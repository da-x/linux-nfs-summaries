NFS Client Bugfixes for 7.0-rc: TLS UAF, RDMA Races, Grace Loop, and VFS Locking RFC

Week ending 2026-03-12

Critical Bugs and Fixes

NFS Client Bugfixes Merged for Linux 7.0-rc2

Anna Schumaker submitted a pull request tagged nfs-for-7.0-2, accepted into Linus Torvalds's tree on March 12. It bundles three fixes: Kconfig typo corrections, an RDMA transport reference-count leak (re_receiving not decremented on early exit paths), and an NFSv3 create error-handling fix returning EISDIR when the target alias is a directory. See the pull request for details.

TLS Use-After-Free in SUNRPC Connect Worker

Henry Martin reported a slab-use-after-free in the TCP-TLS transport layer: xs_connect() assigned transport->clnt from task->tk_client without taking a reference count. If the RPC task completed before the TLS connect worker ran, cl_cred was freed and later dereferenced in rpc_new_client(), corrupting the kernel credential cache. Jeff Layton reviewed and Benjamin Coddington (Hammerspace) confirmed the severity with production crash reports. Read more.

NFSv3 Mount Crash with xprtsec=tls

A companion bug from Henry Martin: mounting an NFSv3 share with xprtsec=tls triggered a kernel BUG() in nfs_init_timeout_values() because the mountd transport setup did not recognize XPRT_TRANSPORT_TCP_TLS. The fix maps TCP_TLS to plain TCP for mountd (which does not support TLS). Read more.

NFSv4 Client Infinite Loop on nfserr_grace

Li Lingfeng (Huawei) reported a denial-of-service condition: during server restart and lease expiration, the client's state manager enters an infinite loop when _nfs4_open_expired receives NFS4ERR_GRACE in the NFS4CLNT_RECLAIM_NOGRACE phase. A patch was submitted alongside the report. Read more.

NFSv3 Atomic Open Oops on Concurrent Dir/File Creation

Roberto Bergantinos Corpas (Red Hat) fixed a kernel oops in nfs_atomic_open_v23: when a directory alias was found during nfs3_proc_create, the original dentry remained negative, causing do_dentry_open to crash. The fix returns EISDIR. Read more.

FS-Cache Warning in nfs_free_request

Mike Owen reported a PG_WB_END stale warning during NFS read completion with FS-Cache enabled, suggesting a race between page-cache writeback tracking and FS-Cache. No fix yet. Read more.

Writeback Loops on ENOSPC Errors

Olga Kornievskaia (Red Hat) posted an RFC to fix writeback retry loops when the server returns ENOSPC during unstable writes, proposing synchronous writeback for error conditions. Read more.

RDMA Transport Hardening

xprtrdma Race Fixes and Refactoring (v3)

Chuck Lever submitted a seven-patch v3 series fixing three critical race conditions exposed by nconnect multi-QP configurations: the sendctx get/put deadlock, a lost-wakeup race in slot allocation, and an unnecessary 250 ms backlog delay. The series also replaces rpcrdma_mr_seg with an xdr_buf cursor (saving ~6 KB per request) and scales receive batch sizing to the credit window. This v3 corrects a regression from v2 that broke NFS/RDMA entirely. Read more.

MR Pool Exhaustion in bvec RDMA READ Path

Chuck Lever also submitted a fix for MR pool exhaustion on systems without IOVA-based DMA mapping, where the bvec path overstated DMA entries, causing rapid connection cycling with 71% retransmissions. A companion optimization uses contiguous pages for RDMA Read sink buffers. Read more.

TLS Architecture Refactoring

Following the UAF fix, Benjamin Coddington (Hammerspace) proposed an RFC to refactor the SUNRPC TLS transport, removing the rpc_clnt dependency from the connection worker. Chuck Lever reviewed positively but flagged concerns about tracepoint data loss, timeout behavior changes, and unnecessary boilerplate. A v2 is planned. Read more.

Major VFS Locking RFC — 53-Patch Series

Neil Brown submitted a massive 53-patch RFC to lift VFS lookup out of the exclusive directory lock, enabling concurrent directory operations. Seven patches directly modify NFS client code: removing d_drop()/d_alloc_parallel() workarounds from nfs_atomic_open(), using enhanced d_splice_alias() in nfs_link() and nfs_add_or_obtain(), switching to d_alloc_noblock() for dcache priming and silly-rename, and introducing d_duplicate(). Linus Torvalds responded that the series "absolutely requires ACKs from Al" and requested a git branch. Read more.

pNFS SCSI Layout Fix

Dai Ngo (Oracle) submitted v3 of a patch serializing SCSI Persistent Reservation registration with a mutex, preventing RESERVATION CONFLICT errors when multiple threads issue I/O before registration completes. Christoph Hellwig confirmed the fix is correctly scoped to top-level block devices. Read more.

NFSD Lock Regression: F_GETLK Misdiagnosis Resolved

The ongoing regression where nfsd_permission() returned -ENOLCK for lock operations on read-only files took a major turn. Neil Brown corrected his earlier diagnosis: QEMU was using F_GETLK (a lock query, not acquisition), which POSIX does not require write access for, but NFSD incorrectly demanded it. A targeted fix to the lockd subsystem was proposed. Read more.

NFSv4 HA Recovery: server_scope Configuration

Matthew Schumacher documented a successful resolution of NFSv4 session resets during HA failover. The root cause was differing hostnames across cluster nodes — the server_scope parameter must be identical on all nodes for clients to recognize them as the same logical server. Read more.

Ongoing Debate: Should NFS Timeout with NFS_CS_NO_RETRANS_TIMEOUT?

Zhangjian (Huawei) asked whether the NFS client should timeout and return errors rather than hanging indefinitely when a server never replies on an established connection. Trond Myklebust maintained that retransmission is forbidden by the NFSv4 spec, and even unilateral timeouts would exhaust server slots since there is no RPC cancellation mechanism. The soft mount option remains the recommended workaround for unreliable servers. Read more.

User-Space: nfs-utils 2.8.6 Released

Steve Dickson announced nfs-utils 2.8.6, headlined by the fix for CVE-2025-12801 (NFSv3 mountd privilege escalation), plus gssd improvements, nfsrahead updates, and nfsdctl fixes. Read more.

nfsrahead Crash Fix

Aaron Tomlin fixed a crash in nfsrahead caused by uninitialised memory when the fast-path rejected non-NFS devices, and quietened misleading error logs. The patches were merged for nfs-utils 2.8.7-rc1. Read more.

Resolved: FS-Cache/Re-export Lockup Was Not a Kernel Bug

Mike Owen closed a months-long investigation into NFS re-export server lockups with fscache. The root cause was environmental — suboptimal EXT4 tuning rather than an NFS or FS-Cache bug. Switching to XFS and adjusting sysctls resolved the issue entirely. Read more.
