Treewide IS_ERR_OR_NULL Refactor: NFS/SUNRPC Cleanup Patch Reviewed

Summary

A Treewide Refactor: IS_ERR_OR_NULL Overhaul Touches NFS/SUNRPC Code

Philipp Hahn submitted a massive 61-patch series titled "treewide: Use IS_ERR_OR_NULL over manual NULL check - refactor" covering the entire kernel. The effort is a code cleanup / refactoring initiative, not a protocol change or bug fix. Hahn wrote:

"While doing some static code analysis I stumbled over a common pattern, where IS_ERR() is combined with a manual NULL check. For that there is IS_ERR_OR_NULL()."

The series includes a Coccinelle semantic patch (PATCH 01/61) to automatically find and convert instances of IS_ERR() plus manual NULL checks into the more concise IS_ERR_OR_NULL().

NFS/SUNRPC Impact

For the NFS subsystem, only one patch is relevant: [PATCH 30/61] net/sunrpc: Prefer IS_ERR_OR_NULL over manual NULL check [id://20260310-b4-is_err_or_null-v1-30-bd63b656022d@avm.de]. This patch modifies net/sunrpc/xprtrdma/svc_rdma_transport.c, replacing six instances of manual IS_ERR() + NULL checks with IS_ERR_OR_NULL().

The NFS maintainers responded positively and promptly:

  • Jeff Layton provided a Reviewed-by tag.
  • Chuck Lever also added his Reviewed-by.

Layton additionally reviewed PATCH 61/61, which drops redundant unlikely() wrappers around IS_ERR_OR_NULL() in the file subsystem, noting that the macro already uses likely(!ptr) internally.

Semantic Caveats Noted by the Author

Hahn flagged a potential semantic change in patches 55–58, where existing code used WARN_ON() or WARN_ON_ONCE() only on the IS_ERR() path but not for NULL:

"Patches 55-58 may be dropped as they have a (minor?) semantic change: They use WARN_ON() or WARN_ON_ONCE(), but only in the IS_ERR() path, not for the NULL check. Iff it is okay to print the warning also for NULL, then the patches can be applied."

This concern does not affect the NFS/sunrpc patch, which involves straightforward error-pointer checks without warnings.

Broader Thread Activity

The 61-patch series attracted responses from maintainers across many subsystems (btrfs, ext4, ceph, sound, trace, net, drm, vfio, media, etc.). Most reviews were positive, with several maintainers providing Reviewed-by tags or acknowledging the cleanup. The discussion remained technical and focused on code style consistency rather than functional changes.

Conclusion

This week's NFS-relevant activity in this thread was minimal but clean: a single refactoring patch to net/sunrpc/xprtrdma/svc_rdma_transport.c that modernizes error-checking idioms, receiving dual Reviewed-by tags from key NFS maintainers Jeff Layton and Chuck Lever. No bug fixes or protocol changes were discussed; the work is purely cosmetic, aiming for code consistency across the kernel tree.
