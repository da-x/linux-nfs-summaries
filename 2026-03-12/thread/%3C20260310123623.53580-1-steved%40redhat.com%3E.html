Revert nfsrahead event-driven mountinfo monitoring due to crash

Summary

nfsrahead: Reverting Event-Driven mountinfo Monitoring After Crash Report

Type: Bug fix (revert of a recent feature)

On March 10, Steve Dickson submitted a patch to revert a recent change to nfsrahead, the NFS read-ahead daemon. The original commit (0f5fe65d83f7455112aea82bf96f99523cb03ca7) had enabled event-driven /proc/mounts monitoring and added logic to skip non-NFS devices. However, this change introduced a critical stability issue.

The Problem: Core Dump in nfsrahead

Steve Dickson opened the thread with a crash report from Fedora 43, where nfsrahead (process 869) dumped core as reported. The stack trace revealed the failure originated in malloc_printerr, indicating a memory allocation error — likely heap corruption or a double-free:

#3  0x00007f1a866f373b __libc_message_impl.cold (libc.so.6 + 0x273b)
#4  0x00007f1a8676f665 malloc_printerr (libc.so.6 + 0x7e665)
#5  0x00007f1a8676f684 malloc_printerr_tail (libc.so.6 + 0x7e684)
#6  0x00005624543b1d32 main (/usr/libexec/nfsrahead + 0xd32)

The crash was linked to a Fedora Bodhi update, underscoring its impact on production systems.

The Fix: Revert the Offending Commit

The submitted patch reverted the entire event-driven mountinfo monitoring feature, removing 54 lines from tools/nfsrahead/main.c. This restores the previous polling-based behavior, which was stable but less efficient.

Discussion and Resolution

Aaron Tomlin responded to the patch in a brief reply, though the substance of his feedback was not fully captured in the available message body.

Steve Dickson concluded the thread by confirming acceptance of a revised version:

"Okay... v2 does apply so I'll go with those...." Steve Dickson

This indicates that a second version of the revert patch was prepared and accepted, likely addressing minor issues raised during review.

Key Takeaways

  • The event-driven mountinfo monitoring feature in nfsrahead proved unstable, causing crashes due to memory allocation errors.
  • The NFS client tools maintainers opted for a full revert rather than attempting an incremental fix, prioritizing stability over the optimization benefits of event-driven monitoring.
  • This revert affects users of Fedora 43 and potentially other distributions that adopted the nfs-utils-2.8.6 package with the problematic commit.
