kthread Exit Cleanup v2: Removing kthread_exit() Alias and Renaming do_exit() to task_exit()

Kernel Thread Exit Cleanup: v2 Series Removes kthread_exit() Alias, Renames do_exit() to task_exit()

Summary

This week, Christian Brauner submitted [PATCH v2 0/2] kthread, exit: clean up kernel thread exit paths Cover, a two-patch series that concludes the cleanup of kernel thread exit infrastructure. The work directly impacts NFS client and server development through changes to include/linux/sunrpc/svc.h, ensuring RPC tasks use a consistent and safe exit mechanism.

Classification: Bug fix follow-up and API renaming — not a new feature or protocol change. This series removes the now-redundant kthread_exit() alias (leftover from a prior use-after-free fix) and renames do_exit() to task_exit() for clarity.

Bridge from Prior Week

Last week, a heated debate unfolded regarding the removal of kthread_exit(). Christoph Hellwig argued against exporting do_exit() to modules, while Linus Torvalds forcefully rebutted that do_exit() is inherently safe because it only exits the current task prior summary. Brauner agreed with Torvalds, stating:

"And no, we should definitely not keep kthread_exit() as a separate thing around. That just seems weird and clearly that has led to bugs before." Brauner

Brauner promised a follow-up series to rename the unified exit function. This week's v2 series fulfills that promise.

This Week's Activity

Patch 1/2: Removing kthread_exit() Completely

In [PATCH v2 1/2] Patch, Brauner removes the kthread_exit() alias entirely. The function had been folded into do_exit() in commit 28aaa9c39945 to fix a "nasty UAF bug" reported by Christian Loehle, but was left as an alias for compatibility. The patch updates seven files, including:

  • include/linux/kthread.h — removes the kthread_exit() declaration
  • include/linux/sunrpc/svc.h — changes module_put_and_kthread_exit() to call do_exit() directly
  • kernel/module/main.c — updates module exit paths
  • lib/kunit/try-catch.c — updates KUnit test infrastructure

Frederic Weisbecker provided a review tag:

"Thanks for fixing that UAF! I unfortunately missed it." Weisbecker

Patch 2/2: Renaming do_exit() to task_exit()

In [PATCH v2 2/2] Patch, Brauner renames do_exit() to task_exit() across 36 files. The rationale is clarity:

"Rename do_exit() to task_exit() so it's clear that this is an api and not a hidden internal helper." Brauner

The rename touches broad subsystems including:

  • fs/cachefiles/namei.c
  • include/linux/sunrpc/svc.h (NFS server RPC infrastructure)
  • io_uring/io-wq.c, io_uring/sqpoll.c
  • kernel/exit.c, kernel/kthread.c, kernel/signal.c
  • Various selftests and documentation

Weisbecker acknowledged the rename:

"Acked-by: Frederic Weisbecker frederic@kernel.org" Weisbecker

Steven Rostedt's Selftest Compatibility Concern

Steven Rostedt raised an important concern regarding the selftests in patch 2/2. He noted that ftrace-based tests need to remain compatible with older kernels:

"These tests need to pass on old kernels too. So we can't just do a 's/do_exit/task_exit/' conversion. It needs to test for task_exit first, and if not found, fallback to do_exit." Rostedt

He pointed to an existing precedent for handling such renames:

"See how we handled the _do_fork() > kernel_clone() rename." Rostedt

This is a practical concern for maintainability: selftests that hardcode function names will break when run against older kernels, and the fix requires conditional logic to handle both naming conventions.

David Laight's Question on Module Reference Counting

David Laight raised an intriguing question about the mechanics of module_put_and_kthread_exit() (now module_put_and_do_exit()):

"I'm intrigued... How does that actually know to do the module_put()? (I know it does one - otherwise my driver wouldn't unload.)" Laight

He noted that while try_module_get(THIS_MODULE) is called explicitly before kthread_run(), the corresponding module_put() happens implicitly through the exit path. Laight suggested this implicit behavior might be confusing:

"It actually makes me think that module_put_and_exit() ought to have a 'module' parameter. Or, perhaps, kthread_create() should have the module parameter and hold a reference to that module until it exits." Laight

This observation highlights a design question about whether module reference counting for kernel threads should be more explicit, though it does not block the current cleanup series.

NFS Client and Server Relevance

Direct Impact on sunrpc Infrastructure

The patch modifies include/linux/sunrpc/svc.h, which is part of the RPC server infrastructure used by NFSv3 and NFSv4 servers. The change replaces kthread_exit() with do_exit() (soon to be task_exit()) in the module_put_and_kthread_exit() macro:

-#define module_put_and_kthread_exit(code) kthread_exit(code)
+#define module_put_and_kthread_exit(code) do_exit(code)

This ensures that RPC service threads use the same exit path as other kernel tasks, eliminating the divergence that previously caused use-after-free bugs.

Indirect Benefit to NFS Client

While the NFS client does not directly call kthread_exit(), the underlying bug fix (commit 28aaa9c39945) addressed a use-after-free in kernel thread exit paths. Any NFS client code that spawns or interacts with kernel threads benefits from the consolidated, correct exit path. The cleanup removes potential confusion for future developers working on NFS-related kernel threads.

Cachefiles Interaction

The rename touches fs/cachefiles/namei.c, which is relevant to FUSE-based caching solutions that may interact with NFS workloads. The cachefiles fixup applied earlier this week prior summary ensures that transient errors no longer cause permanent cache disabling — a reliability improvement for any caching layer alongside NFS.

Key Technical Arguments and Evolution

  1. From debate to consensus: Last week's heated discussion between Hellwig, Torvalds, and Brauner resolved in favor of unification. This week's v2 series implements the agreed-upon direction without further controversy.
  2. Naming for clarity: The rename from do_exit() to task_exit() addresses legitimate concerns about API discoverability. As David Gow noted last week: "That being said, I agree that do_exit() isn't as nice a name."
  3. Selftest compatibility: Rostedt's concern highlights the need for backward-compatible selftests when renaming kernel functions. This is a practical issue that Brauner will need to address in v3 or via a follow-up patch.
  4. Implicit module reference counting: Laight's question about module_put_and_kthread_exit() raises a design question about explicitness, though it does not block the current cleanup.

Final Conclusions

  • Series status: v2 submitted with positive reviews from Weisbecker. Rostedt's selftest compatibility concern needs to be addressed before merge.
  • NFS impact: Direct changes to sunrpc/svc.h ensure RPC server threads use the safe, unified exit path. Indirect benefits to NFS client through elimination of UAF-prone divergence in kernel thread exit paths.
  • Next steps: Brauner will likely submit v3 addressing Rostedt's selftest concern (adding fallback logic for do_exit/task_exit detection) and potentially clarifying the module reference counting behavior raised by Laight.
  • Bug fix lineage: This series is the final cleanup step following the UAF fix in commit 28aaa9c39945, which was itself prompted by a report from Christian Loehle prior thread. The full chain — bug report → UAF fix → alias removal → API rename — demonstrates a thorough approach to kernel infrastructure cleanup.
