Revert of event-driven mountinfo monitoring in nfsrahead due to blktest failures

Summary

Revert of event-driven mountinfo monitoring in nfsrahead

Classification

Bug fix / Regression revert. This thread addresses a regression introduced by a recent feature addition to the nfsrahead utility, part of the NFS client tools (nfs-utils).

Summary

Steve Dickson submitted and immediately committed **[PATCH v2] Revert "nfsrahead: enable event-driven mountinfo monitoring"](https://lore.kernel.org/linux-nfs/20260306215254.18764-1-steved@redhat.com/) to undo a previous commit (2b62ac4c273a647df07400dc1126fceb76ad96c0). The revert was necessitated by widespread test failures in the blktests suite, specifically within the block/ tests.

Technical Arguments and Evolution

The original commit attempted to enable event-driven monitoring of /proc/self/mountinfo for the nfsrahead tool, likely aiming to improve responsiveness or accuracy in tracking NFS mount points. However, this change triggered a systemic issue during testing:

"Most blktests block/ failed with 'Timed out while waiting for udev queue to empty.'"

Steve Dickson cited an external discussion on the linux-block mailing list 1 to corroborate that the issue was not isolated to NFS testing but affected broader block layer tests. The interaction between the event-driven monitoring mechanism and udev caused queue backlogs, leading to timeouts.

The discussion was brief, as the regression was clear-cut. In a follow-up message just 18 minutes later, Steve confirmed the resolution:

"Committed... (tag: nfs-utils-2-8-6-rc4)"

Final Conclusions

The patch reverted 35 lines of code from tools/nfsrahead/main.c, effectively disabling the event-driven mountinfo monitoring feature. The fix was tagged in nfs-utils-2-8-6-rc4, indicating it is part of the release candidate cycle for nfs-utils 2.8.6. This revert highlights the importance of validating NFS client tool changes against broader kernel subsystem tests, as interactions with udev and block layer utilities can have unintended side effects.

Key Technical Details

  • Affected Component: nfsrahead (NFS read-ahead daemon), part of nfs-utils.
  • Root Cause: Event-driven monitoring of mountinfo interfered with udev queue processing, causing timeouts in blktests.
  • Resolution: Revert to the previous implementation that did not use event-driven monitoring for this purpose.
