NFS Server: Simplify nfsd4_interssc_connect() with Stack Allocation

This week, Dmitry Antipov submitted a small but clean-up patch targeting the NFS server (nfsd) codebase. The discussion is focused on code simplification and optimization rather than a new feature or critical bug fix, though it touches on resource management best practices in kernel networking code.

Key Technical Arguments

The patch targets the function nfsd4_interssc_connect() in fs/nfsd/nfs4proc.c. Dmitry Antipov argued that the variable ipaddr, which has a size of RPC_MAX_ADDRBUFLEN + 1 (64 bytes), is sufficiently small to be allocated on the stack. This eliminates the need for explicit dynamic memory allocation via kzalloc() and subsequent deallocation with kfree().

Additionally, Antipov noted that since the function rpc_ntop() returns the length of the resulting string, an extra call to strlen() is redundant and can be removed.

"In 'nfsd4_interssc_connect()', 'ipaddr' of size RPC_MAX_ADDRBUFLEN + 1 (64) is small enough to allocate it on the stack and so avoid explicit 'kzalloc()' and 'kfree()'. And, since 'rpc_ntop()' returns the length of the result, an extra call to 'strlen()' may be avoided as well." Dmitry Antipov

The patch results in a net reduction of 10 lines, with only 4 insertions, simplifying the control flow and reducing heap pressure for this specific code path.

Final Conclusions

The patch represents a minor refactoring effort aimed at improving code clarity and efficiency in the NFS server's inter-server session connection logic. By moving a small buffer to the stack, it avoids the overhead and potential failure points of dynamic allocation. This type of cleanup is typical of ongoing maintenance efforts in the NFS subsystem to ensure robustness and simplicity in critical paths.
