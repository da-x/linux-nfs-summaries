CVE-2025-12801 Fix Committed in nfs-utils 2.8.6-rc5

Summary

rpc.mountd CVE-2025-12801: Fix Committed in nfs-utils 2.8.6-rc5

Overview

This thread, which began last week with a critical security announcement, concluded this week with confirmation that the fix for CVE-2025-12801 has been merged into nfs-utils. This is a security-critical bug fix, not a new feature or protocol change.

Prior Context (Brief)

Last week (see prior summary), Steve Dickson announced a vulnerability in the rpc.mountd daemon that allowed NFSv3 clients to escalate privileges at mount time, bypassing /etc/exports restrictions including root_squash and all_squash. A four-patch series authored by Trond Myklebust was posted to address the issue by splitting directory lookups so that exported directories are resolved with mountd's privileged credentials while subdirectory lookups use the RPC caller's credentials.

This Week's Activity

On March 7, Steve Dickson followed up on his initial announcement with a brief confirmation:

"Committed... (tag: nfs-utils-2-8-6-rc5)"

As noted in his follow-up, the patch series has been merged and is available under the nfs-utils-2-8-6-rc5 release tag.

Significance for NFS Client Development

While this fix resides in the server-side rpc.mountd daemon, it has direct implications for NFS clients:

  • NFSv3 clients could previously exploit this flaw to gain unauthorized access to subdirectories of exported paths, effectively bypassing export restrictions and privilege-squashing rules.
  • The fix restores the intended security model of /etc/exports, ensuring that mount-time privilege escalation is no longer possible.
  • NFSv4 users remain unaffected, as the vulnerability does not apply to NFSv4-only exports.

Conclusion

The CVE-2025-12801 remediation has been completed and committed to nfs-utils version 2.8.6-rc5. All administrators running NFSv2 or NFSv3 exports on Linux are advised to upgrade promptly to mitigate this privilege escalation vulnerability.
