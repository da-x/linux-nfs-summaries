NFS: Fix writeback loops on ENOSPC errors

Summary

NFS Writeback Stuck in Loops When Encountering ENOSPC

This week, Red Hat's Olga Kornievskaia posted an RFC patch addressing a subtle but serious bug in the NFS client's writeback behavior: under certain error conditions, writeback I/O can become stuck in an infinite retry loop. The issue was discovered while running xfstest generic/751.

The Bug: Two Failure Patterns

Kornievskaia identified two distinct patterns that trigger the problem as described in her RFC patch:

Pattern #1: Writeback I/O experiences ENOSPC on an offset smaller than the file size. For example:

"write offset=0 len=4096 how=unstable OK write offset=8192 len=4096 how=unstable OK write offset=12288 len=4096 how=unstable ENOSPC write offset=4096 len=4096 how=unstable ENOSPC"

The client then sends a commit and receives a verifier different from the last successful write. It marks pages dirty and retries writeback — but again sends writes as unstable, hitting the same ENOSPC error and sending another commit because writes were sent at unstable mode. This creates a loop.

Pattern #2: An unstable write followed by a short write and then ENOSPC:

"write offset=0 len=4096 how=unstable OK write offset=4096 len=4096 how=unstable returns OK but count=100 write offset=4197 len=3996 how=stable returns ENOSPC"

Again, the client sends a commit and receives a verifier different from the last unstable write, and the same behavior is retried in a loop.

The Fix: Synchronous Writeback for Error Conditions

Rather than allowing the asynchronous writeback path to retry indefinitely in these scenarios, Kornievskaia's patch proposes to detect these conditions and mark requests to be done synchronously instead:

"Instead, this patch proposes to identify those conditions and mark requests to be done synchronously instead."

The patch touches three files — fs/nfs/pagelist.c, fs/nfs/write.c, and include/linux/nfs_page.h — adding a small number of lines (5 insertions total) to implement the detection logic.

Status

This is an RFC (Request for Comments) patch, meaning it is being presented for community review rather than as a finalized submission. As of the end of this week, no replies or reviews had been posted to the thread. The discussion remains open for feedback from NFS maintainers and developers.

This fix targets a bug in NFS client development, specifically addressing data integrity and reliability concerns when the server reports out-of-space conditions during writeback operations.
