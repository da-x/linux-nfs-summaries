mountstats nconnect percentage fix committed to nfs-utils

Summary

mountstats: Fix per-operation percentages with nconnect — Committed

Summary

This thread, which began last week with a patch submission by Chuck Lever, concluded this week with the fix being accepted and merged into the nfs-utils userspace toolkit. The change addresses a significant bug in the mountstats reporting utility that skewed per-operation RPC percentage calculations for NFS mounts using nconnect (multiple concurrent TCP connections).

Evolution of the Discussion

Last week, Chuck Lever submitted a patch to correct how tools/mountstats/mountstats.py parses /proc/self/mountstats output. As detailed in the prior summary here, the bug caused percentage metrics to be inflated (e.g., three times too large for nconnect=3) because the parser overwrote cumulative transport counters on each xprt: line instead of aggregating them.

This week, the discussion reached its conclusion with a single message from nfs-utils maintainer Steve Dickson.

Final Conclusion: Patch Committed

On 2026-03-06, Steve Dickson confirmed the integration of the fix:

"Committed... (tag: nfs-utils-2-8-6-rc4)" Steve Dickson

The patch is now part of the nfs-utils release candidate 4 for version 2.8.6. This marks the successful resolution of the issue.

Technical Significance

This bug fix is important for NFS client development and operational debugging. The mountstats utility is a primary diagnostic tool for administrators analyzing NFS performance. When using nconnect—a feature designed to improve throughput by leveraging multiple TCP connections—the previous implementation of mountstats provided misleading data:

  • Before the fix: Per-operation percentages were calculated against only the last transport's rpcsends counter, while operation counts (READ, WRITE, etc.) reflected the total across all transports. This resulted in mathematically impossible or wildly inflated percentages.
  • After the fix: Cumulative counters (rpcsends, rpcreceives, badxids, backlogutil, sendutil, pendutil) are now correctly summed across all transport lines, yielding accurate aggregate statistics.

As Chuck Lever noted in his original submission:

"With nconnect=3 and balanced round-robin, rpcsends holds roughly one third of total RPCs while per-op counts hold the full total. display_rpc_op_stats() computes (op_count * 100) / rpcsends, yielding percentages roughly three times too large." Chuck Lever

With this fix committed, administrators can once again rely on mountstats --rpc output for accurate performance analysis of nconnect-enabled NFS mounts.
