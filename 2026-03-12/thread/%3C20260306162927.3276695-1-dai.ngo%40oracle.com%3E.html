pNFS: Serialize SCSI PR Registration to Avoid Reservation Conflicts

Summary

pNFS: Serializing SCSI Persistent Reservation Registration to Prevent Conflicts

This week, Dai Ngo submitted v3 of a patch addressing a critical race condition in the NFS client's parallel NFS (pNFS) block layout driver. The discussion focused on ensuring that SCSI Persistent Reservation (PR) registration completes before any I/O is issued to data servers, thereby preventing RESERVATION CONFLICT errors that force fallback to the Metadata Server (MDS).

The Bug: Race Condition in PR Registration

The core issue lies in how the NFS client handles concurrent I/O requests for SCSI layouts. As Dai Ngo explained in the patch description:

"With SCSI layouts, the NFS client must not submit I/O to the data server until the Persistent Reservation (PR) registration has completed."

Previously, the function bl_register_scsi() set the PNFS_BDEV_REGISTERED flag before actually performing the PR operation. This created a window where multiple threads could observe the flag as set, skip their own registration logic, and proceed to issue I/O concurrently. The result was that unregistered I/O would hit reservation conflicts on the storage side.

The Fix: Mutex-Based Serialization

The proposed solution introduces a new mutex, pbd_registration_mutex, to serialize the registration path. Only one thread performs the PR registration at a time; other threads wait for completion and then re-check the registration status before issuing I/O.

Key changes in v3 included:

  • Replacing the PNFS_BDEV_REGISTERED flag with a cleaner blkdev_registered boolean.
  • Protecting both registration and unregistration operations with the mutex.
  • Renaming the mutex from pbd_mutex to pbd_registration_mutex for clarity.

Discussion: Scope of Mutex Initialization

After posting the patch, Dai Ngo raised a question regarding the initialization scope of the new mutex in a follow-up:

"The new mutex, pbd_registration_mutex, is initialized only for the top-level pnfs_block_dev in this patch. The mutexes for child pnfs_block_dev instances allocated by bl_parse_concat() and bl_parse_stripe() are not initialized. Should we initialize these child mutexes as well, in case we later want to support concatenated and striped SCSI devices for pNFS?"

Christoph Hellwig responded on March 9, clarifying that this was unnecessary:

"I don't think we need to, as the registration would happen on the actual SCSI devices, not the meta devices."

Dai Ngo acknowledged this explanation in his final reply: "ok, thanks!"

Conclusion

This patch represents an important bug fix for NFS client stability in pNFS environments using SCSI layouts. By serializing PR registration, it eliminates a race condition that caused I/O failures and fallbacks to the MDS. The discussion confirmed that the fix is correctly scoped to top-level block devices, as meta-devices (concatenated/striped) do not require individual registration handling.

The patch appears ready for integration pending final review, with no outstanding technical objections raised in this thread.
