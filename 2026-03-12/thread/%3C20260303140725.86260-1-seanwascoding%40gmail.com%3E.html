sunrpc: dprintk macro simplification and Sparse warning fix

Overview

This week, the discussion around Sean Chang's [PATCH v2] to simplify dprintk() macros in the SunRPC subsystem progressed from initial review to concrete plans for a revised v3 series. The thread focused on addressing a newly discovered Sparse warning regarding type mismatches and determining the merge path for the patches.

Context from Prior Week

Last week, Sean Chang submitted PATCH v2, which simplified debug macro definitions by removing the explicit fmt argument and using no_printk(__VA_ARGS__) directly, following David Laight's suggestion. The patch also removed redundant #ifdef guards in NFS server and lockd code, relying on compiler dead-code elimination under -O2.

Key Technical Arguments This Week

Sparse Warning Discovery

Andy Shevchenko raised a critical issue regarding a Sparse warning reported by the kernel test robot (LKP):

"Does this patch fixes also 202603110038.P6d14oxa-lkp@intel.com?" — Andy Shevchenko

Sean Chang confirmed he had reproduced the issue locally and identified it as a void vs int type mismatch:

"I have reproduced the Sparse warning (void vs int mismatch) locally. To resolve this, I'll use the do-while(0) form in v3 to ensure the macro always evaluates to void" — Sean Chang

The proposed fix wraps no_printk() in a do { ... } while (0) construct:

-# define dfprintk(fac, ...)            no_printk(__VA_ARGS__)
+# define dfprintk(fac, ...)            do { no_printk(__VA_ARGS__); } while (0)

Andy Shevchenko further suggested simplifying related macros:

"Wouldn't be better to drop ({}) in nfs_error*() macros?" — Andy Shevchenko

Merge Path Resolution

Chuck Lever inquired about the merge strategy for the patches:

"Has a subsystem tree been chosen through which to merge these two patches?" — Chuck Lever

Sean Chang responded that he would restructure the work into a 3-patch series for v3 to facilitate review across subsystems:

"To make the review and merging process easier across different subsystems, I will send v3 as a 3-patch series" — Sean Chang

The planned structure:

  1. [PATCH v3 1/3] sunrpc: Fix dprintk type mismatch using do-while(0) (include/linux/sunrpc/debug.h)
  2. [PATCH v3 2/3] nfsd/lockd: Remove redundant debug checks (fs/nfsd/nfsfh.c, fs/lockd/svclock.c)
  3. [PATCH v3 3/3] sunrpc/xprtrdma: Simplify variable declarations and debug checks (net/sunrpc/xprtrdma/svc_rdma_transport.c)

Chuck Lever offered to take all three patches through his tree:

"I can take all three of those, if that's what you'd like. Just let me know when the review is complete." — Chuck Lever

Classification

This discussion concerns a bug fix (addressing Sparse warnings about type mismatches) combined with code cleanup (simplifying debug macros and removing redundant conditional compilation guards). The changes improve build robustness for the NFS client/server infrastructure by ensuring proper type checking while maintaining zero-cost debug stubs in non-debug builds.

Conclusion

The thread concluded with a clear path forward: Sean Chang will submit v3 as a 3-patch series addressing the Sparse warning via do-while(0) wrapping, and Chuck Lever has agreed to merge the patches through his tree once review is complete. The core technical achievement remains the simplification of SunRPC debug macros that eliminates compiler warnings while preserving type safety and leveraging compiler dead-code elimination.
