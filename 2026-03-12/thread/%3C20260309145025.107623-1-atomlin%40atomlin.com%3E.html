nfsrahead: Fix uninitialised memory crash and refine logging

Summary

This week, Aaron Tomlin submitted a two-patch series to address critical stability issues in nfsrahead, the NFS read-ahead tool. The patches resolve a crash caused by uninitialised memory and reduce misleading error logging, both stemming from a recent fast-path optimisation introduced to prevent udev worker thread exhaustion.

Technical Context: The Fast-Path Regression

A previous commit (0f5fe65d) added a mechanism to quickly reject non-NFS block devices. However, this optimisation exposed a bug in the main() function's error handling path.

"When the fast-path is triggered (e.g., for a physical block device like 8:16), get_device_info() instantly returns -ENODEV. Because this early exit occurs before get_mountinfo() is invoked, init_device_info() is never called." — Aaron Tomlin

Consequently, the device_info struct remained populated with uninitialised stack memory. When the cleanup path executed, free_device_info() attempted to free garbage pointers, resulting in a glibc abort(3).

Patch 1: Zero-Initialise device_info

The first patch fixes the crash by explicitly zero-initialising the device_info struct at declaration. This ensures that even if an early exit occurs before initialisation, the cleanup routine safely frees NULL pointers rather than random stack data.

"Fix this by explicitly zero-initialising the device_info struct at declaration, preventing the cleanup path from freeing uninitialised memory during an early exit." — Aaron Tomlin

Patch 2: Quieten Misleading Error Logs

The second patch addresses user experience and log hygiene. Previously, when nfsrahead intentionally skipped a non-NFS device via the fast-path, it logged a generic D_GENERAL error ("unable to find device"). Since udev invokes nfsrahead for all block devices, this created significant journal spam.

The patch updates the logic to catch the -ENODEV return code specifically and log a descriptive debug message ("skipping non-NFS device") at the D_ALL level instead, while still returning the correct errno exit status.

"Verified the issue was fixed now with your patch, thanks." — Yi Zhang

"Committed... (tag: nfs-utils-2-8-7-rc1)" — Steve Dickson

Conclusion

This discussion represents a bug fix for the NFS client utilities (nfs-utils). It highlights the importance of robust error handling and initialisation in tools that interact with the broader system device manager (udev), ensuring that performance optimisations do not introduce stability regressions or log noise.
