NFS Client Infinite Loop on nfserr_grace During Reclaim

Summary

NFS Client Infinite Loop During Open Reclaim When Server Returns nfserr_grace

Type: Bug fix (NFS client state manager)
Participants: Li Lingfeng (Huawei)
Week ending: 2026-03-12

Overview

This week, Huawei engineer Li Lingfeng reported a critical bug in the NFSv4 client state manager: under certain server restart and lease expiration timing conditions, the client enters an infinite loop, rendering it completely unresponsive to user operations. The issue was introduced with a patch submitted alongside the bug report on 2026-03-11.

The Bug

The problem manifests when the NFS server returns NFS4ERR_GRACE during open state reclaim. Li Lingfeng described the scenario:

"We recently encountered an issue where the NFS client's state manager gets stuck in an infinite loop, making the client unresponsive to user operations. The problem occurs when the server returns nfserr_grace during open reclaim."

The root cause lies in a race condition between three conditions on the server side:

  1. The session exists
  2. The NFSD4_CLIENT_RECLAIM_COMPLETE flag is not set
  3. The op_claim_type is not NFS4_OPEN_CLAIM_PREVIOUS

When all three hold, nfsd4_open returns nfserr_grace. On the client side, the function _nfs4_open_expired receives this error and retries indefinitely, trapping the state manager in a loop. The stack trace provided shows the call path:

nfs4_state_manager
  nfs4_do_reclaim // NFS4CLNT_RECLAIM_NOGRACE
   nfs4_reclaim_open_state
    __nfs4_reclaim_open_state
     nfs41_open_expired // ops->recover_open
      nfs4_open_expired
       nfs4_do_open_expired
        _nfs4_open_expired // gets NFS4ERR_GRACE and retries

Reproduction Steps

Li Lingfeng provided a detailed 12-step reproduction procedure involving precise timing manipulation via rpcdebug delays on both client and server. The key steps involve:

  1. Establishing a normal NFS mount with an open file handle
  2. Restarting the NFS server (after changing its hostname to force state changes)
  3. Carefully manipulating debug delays to create a window where the client has flags NFS4CLNT_LEASE_EXPIRED, NFS4CLNT_RECLAIM_NOGRACE, and NFS4CLNT_MANAGER_RUNNING set simultaneously
  4. Releasing the delays, which triggers the infinite loop in the NFS4CLNT_RECLAIM_NOGRACE branch

The resulting kernel stack trace confirms the hang:

[<0>] nfs4_handle_exception+0x245/0x600
[<0>] nfs4_do_open_expired+0x2c8/0x4e0
...
[<0>] nfs4_state_manager+0x1644/0x17f0

The Fix

A patch was submitted alongside the bug report (diff omitted from ingest but referenced in the message). The fix targets the NFS client's handling of NFS4ERR_GRACE during open reclaim operations, ensuring that the state manager does not retry indefinitely when this error is encountered in the NFS4CLNT_RECLAIM_NOGRACE phase.

Significance

This bug represents a denial-of-service condition for NFSv4 clients: once triggered, the affected mount becomes completely unresponsive, requiring either a client reboot or manual intervention to kill the stuck kernel thread. The detailed reproduction steps provided by Li Lingfeng demonstrate a sophisticated understanding of the NFS state machine and will be valuable for regression testing.

As of the end of this reporting window, no replies or reviews from the NFS maintainer community have been recorded. The patch awaits review and integration.
