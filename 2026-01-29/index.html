NFS client delegation fixes, pNFS hang fix, lockd race condition patch, and container mount regression addressed this week

Week ending 2026-01-29

Critical Bug Fixes

NFS Client Delegation Return Handling Fixed

Christoph Hellwig submitted a 7-patch series fixing broken delayed delegation return handling in the NFS client (thread). The core bug — originally reported by Chris Mason — involved a missing spin_unlock and delegations being lost or cluttering incorrect lists. The series includes six preparatory cleanups (simplifying return types, folding functions) before the actual fix, which introduces a separate list for delayed delegations. Chris Mason tested the fix and confirmed no new issues were introduced.

pNFS Layout Drain Wake-Up Fix

Olga Kornievskaia submitted a fix for a subtle race condition in pNFS that could cause tasks to hang indefinitely (thread). Under specific concurrent I/O failure conditions (multiple ESTALE errors on parallel writes), a waiter on NFS_LAYOUT_DRAIN could miss its wake-up and sleep forever. The one-line fix adds a guard to prevent redundant re-setting of the drain flag when NFS_LAYOUT_INVALID_STID is already set.

NFS Client Mount Option Regression Re-appears

Li Lingfeng reported that a previously fixed mount option regression has resurfaced after Trond Myklebust's 6-patch fix series was merged (thread). Alternating ro/rw remounts on the same NFS export now create stacked mounts instead of reusing superblocks. Trond is investigating with diagnostic requests targeting /proc/fs/nfsfs/volumes.

Containerized NFS Mount Regression Fix

Jeff Layton introduced a new VFS flag FS_USERNS_DELEGATABLE to fix a regression breaking NFS mounts inside containers that use privileged mount daemons (thread). A prior VFS security hardening commit blocked filesystems without FS_USERNS_MOUNT from being mounted in user namespaces, which broke the delegation pattern where a container passes an fsopen() context to a vetted daemon in init_ns. The new flag provides a middle ground — allowing delegated mounts without permitting unprivileged containers to mount arbitrary NFS servers directly.

lockd API Boundary Cleanup with Race Fix

Chuck Lever submitted v4 of his 14-patch series clarifying lockd's module API boundaries (thread). The most significant NFS client fix is patch 06/14, which resolves a use-after-free/null pointer dereference race in the sysfs "shutdown" path by introducing nlmclnt_shutdown_rpc_clnt() with proper mutex serialization. The series also adds input validation for malformed NLMv4 lock requests and moves internal headers from include/linux/lockd/ to fs/lockd/. All patches carry Jeff Layton's Reviewed-by tags.

NFS Server Cred Refcount Leak Fixed

Kuniyuki Iwashima fixed credential reference count leaks in nfsd netlink handlers discovered by syzbot (thread). Both nfsd_nl_threads_set_doit() and nfsd_nl_listener_set_doit() called get_current_cred() without a matching put_cred(), leaking credential structures on each invocation. The fix replaces get_current_cred() with current_cred() since these run in process context. Patches were quickly reviewed by Jeff Layton and applied to nfsd-testing by Chuck Lever.

NFS Server: Prevent Exporting Special Kernel Filesystems

Amir Goldstein submitted v3 of a series preventing nfsd from exporting special kernel filesystems like pidfs and nsfs (thread). These filesystems have custom ->open() and ->permission() export methods that nfsd does not respect. The fix blocks exporting any filesystem with these custom methods set. Chuck Lever raised minor documentation concerns; v4 is expected shortly.

Major Trends and Architectural Work

NFS v4.0 Made KConfig-urable

Anna Schumaker submitted v2 of a 14-patch series to make NFS v4.0 support optional via Kconfig (thread). The series extracts v4.0-specific code into dedicated nfs40* files, promotes NFS v4.1 as the default baseline, and introduces NFS4_MIN_MINOR_VERSION. This lays groundwork for eventual deprecation of the oldest NFSv4 minor version. The v2 submission extends KConfig gating into the XDR layer and fixes a kernel test robot build warning.

Delegated Timestamps Move to Runtime Control

Jeff Layton's series transitions NFSv4 delegated timestamps from a compile-time Kconfig option to a runtime debugfs toggle (thread). This signals the feature has matured enough for default inclusion. Chuck Lever requested improved documentation around the migration path; a v3 is planned.

NFS Dummy Root Dentry Cleanup RFC

Al Viro posted an RFC to eliminate a 13-year-old workaround in NFS client dentry management (thread). The "dummy root dentry" hack — where the NFS client manually created an alias for the root directory detached from its inode's alias list — has been unnecessary since 2013. The patch simplifies to using the real dentry as ->s_root. No replies yet.

Ongoing Debates

pNFS Layout Recall Timeout and Fencing Safety

Dai Ngo submitted v4 of a patch enforcing timeouts on NFSv4.1/pNFS layout recalls with SCSI PR fencing integration (thread). This sparked an intense debate about data safety. Chuck Lever highlighted the fundamental challenge: timeout-based fencing risks leaving server and client in inconsistent states ("one believes the fence succeeded, one believes it still has full device access"). Jeff Layton proposed simplifying the architecture by having the workqueue job drive retries rather than NFSD. Dai agreed to shift toward infinite retries with pr_warn admin alerts instead of a fixed retry limit. No consensus reached; significant rework needed.

NFS Delegation Control Mechanism

The ongoing discussion about how to give administrators control over NFS delegations continued (thread). Jeff Layton clarified that the userspace lease export mechanism (via fcntl(F_SETDELEG)) operates at a different lifecycle stage than an O_NODELEGATION open flag, making them complementary rather than competing approaches. He endorsed per-mount delegation control as a pragmatic middle ground.

EOF Page Pollution Design Rationale

MM developer Lorenzo Stoakes engaged Trond Myklebust in a cross-subsystem discussion about why the NFS eof page pollution fix diverges from the generic pagecache_isize_extend() helper (thread). Trond explained that NFS's byte-aligned nature (vs block-aligned) and its concern with read correctness (uptodate state, not dirty state) necessitate the custom approach. Lorenzo is exploring ways to abstract folio_mkclean() while preserving NFS's semantics.

Other Notable Activity

  • SUNRPC dead-loop fix NACKed: Trond Myklebust rejected a proposed fix for a potential infinite loop in xs_read_discard, explaining that resetting transport->recv.len prematurely would cause protocol desynchronization — a worse bug than the original issue (thread).
  • SUNRPC GSS-proxy resource leak under review: Haoxiang Li submitted a fix for a resource leak in gss_proxy_save_rsc(), but Chuck Lever raised concerns about potential double-free issues (thread).
  • pNFS ghost write scenario: Roi Azarzar of VastData opened a discussion about handling duplicate writes when a pNFS client falls back from Data Server to Metadata Server after a Transfer Error (thread). No replies yet.
  • nfs-utils: A 10-patch series fixing typos in man pages was submitted, and a patch adding min-threads parameter support to nfsdctl was posted.
