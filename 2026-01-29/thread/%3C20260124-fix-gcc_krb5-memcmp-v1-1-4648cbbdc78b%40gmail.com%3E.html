SUNRPC: Improve krb5 KUnit test diagnostics with KUNIT_EXPECT_MEMEQ_MSG()

Summary

Improving KUnit Test Diagnostics in SUNRPC krb5 Tests

Type: Bug fix / Test infrastructure improvement

Ryota Sakamoto submitted a patch to enhance the debugging capabilities of the SUNRPC KUnit test suite for GSS-Kerberos 5 (gss_krb5_test.c). The change replaces manual memcmp() assertions with the more expressive KUNIT_EXPECT_MEMEQ_MSG() macro.

Key Technical Arguments

The core motivation, as stated by Sakamoto in the patch description:

"Replace KUnit tests for memcmp() with KUNIT_EXPECT_MEMEQ_MSG() to improve debugging that prints the hex dump of the buffers when the assertion fails, whereas memcmp() only returns an integer difference." Ryota Sakamoto

This is a meaningful improvement for test maintainability. When a memcmp()-based test fails, developers only see a non-zero return value, making it difficult to diagnose where and how two buffers differ. In contrast, KUNIT_EXPECT_MEMEQ_MSG() automatically prints a hex dump of both the expected and actual buffers upon failure, dramatically reducing the time needed to debug subtle memory comparison issues in cryptographic or authentication test vectors.

The patch modified 93 lines in net/sunrpc/auth_gss/gss_krb5_test.c, replacing scattered memcmp() calls with structured KUnit assertions throughout the krb5 test suite.

Evolution and Conclusion

The review was swift. NFS maintainer Chuck Lever applied the patch to the nfsd-testing tree the following day:

"Applied to nfsd-testing, thanks!" Chuck Lever

The patch was merged as commit 63c04545fa09 in the nfsd-testing repository. This change represents a small but valuable contribution to the NFS client's test infrastructure, making future debugging of GSS-Kerberos authentication issues more straightforward for developers.
