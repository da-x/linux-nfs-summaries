NFS: Fix Delayed Delegation Return Handling

Summary

Type: Bug fix (with preparatory cleanups)

Christoph Hellwig submitted a 7-patch series titled "delayed delegation return handling fix" to address issues identified by Chris Mason in a recently resent patch series that added an LRU for delegations As described in the cover letter. The core problem involved improper handling of delayed delegation returns, including missing spinlock unlocks and delegations being lost or cluttering incorrect lists.

Preparatory Cleanups (Patches 1–6)

The first six patches in the series are preparatory refactoring steps designed to simplify the codebase before applying the actual fix:

  1. Return void from nfs4_inode_make_writeable: The return value was never checked by callers, so it was dropped As stated in Patch 1/7.
  2. Return void from ->return_delegation: Similarly, the caller did not check the return value As noted in Patch 2/7.
  3. Use bool for issync argument: Replaced an integer used as a boolean with the proper bool type in nfs_end_delegation_return As described in Patch 3/7.
  4. Remove NULL delegation check: All callers now pass a non-NULL delegation, making the null check redundant As explained in Patch 4/7.
  5. Fold nfs_abort_delegation_return into nfs_end_delegation_return: This consolidation was done to simplify the error handling flow As noted in Patch 5/7.
  6. Simplify error handling: The patch dropped a "pointless delegation->lock held over setting multiple atomic bits in different structures" and used separate labels for delay vs. abort cases As described in Patch 6/7.

The Core Fix (Patch 7/7)

The final patch addresses the actual bug. Hellwig noted:

"Rework this code that was totally busted at least as of my most recent changes." From Patch 7/7

The fix introduces two key improvements:

  • A separate list for delayed delegations, ensuring they "can't get lost and don't clutter up the returns list."
  • A missing spin_unlock in the helper that marks a delegation as a regular pending return.

The patch includes a Fixes: tag referencing commit 0ebe655bd033 ("NFS: add a separate delegation return list") and credits Chris Mason for reporting the issue.

Hellwig also acknowledged the difficulty of reproducing the bug naturally:

"Note that I could not trigger the delayed delegation handling naturally and had to add crude error injection to force it." From cover letter

Feedback from Chris Mason

Chris Mason, who originally reported the issue, tested the fix series and provided positive feedback:

"Thanks Christoph, I reran this through the prompts and didn't find any new issues." From Chris Mason

Conclusion

This thread represents a focused bug-fix effort in NFS client development. The series cleans up delegation return handling code and resolves a critical issue where delayed delegations could be mishandled due to missing unlocks and improper list management. With Chris Mason confirming no new issues were introduced, the fix appears ready for integration.
