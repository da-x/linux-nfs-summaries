nfsdctl: IPv6 listener error fix committed to nfs-utils-2.8.5-rc2

Summary

nfsdctl IPv6 Listener Error Handling Fix Committed

Type: Bug fix (regression repair in nfs-utils)

Background

The thread originated on December 4, 2025, when Olga Kornievskaia submitted a patch to address a regression introduced by commit 8b02f0d5590e ("nfsdctl: cleanup listeners if some failed"). That prior commit changed the behavior of nfsdctl such that if any listener creation failed during NFS server startup, all listeners would be cleaned up and the service would fail to start. This was problematic for systems where IPv6 is not supported by the kernel: the attempt to create an IPv6 listener would fail, causing the entire nfsd service to refuse to start, even though IPv4 operation should have been possible.

Olga's patch restored the previous behavior, where the failure to create an IPv6 listener is ignored, allowing nfsd to start successfully with only IPv4 listeners when IPv6 is unavailable.

This Week's Activity

On January 26, 2026, Steve Dickson confirmed that the patch had been merged into the nfs-utils codebase:

"Committed... (tag: nfs-utils-2-8-5-rc2)" Steve Dickson

Conclusion

The fix is now included in the nfs-utils-2.8.5-rc2 release candidate. This resolves a regression that prevented NFS server startup on systems without IPv6 kernel support, ensuring that nfsdctl gracefully handles the absence of IPv6 rather than failing entirely.
