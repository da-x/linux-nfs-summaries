nfsd: Fix cred refcount leak in netlink handlers

Summary

NFS Server Credential Reference Count Leak Fix

Overview

This week, Kuniyuki Iwashima submitted a two-patch series addressing credential reference count leaks in the NFS server (nfsd) netlink control interface. This is a bug fix targeting memory leaks of struct cred objects discovered by syzbot's fuzzing infrastructure. The patches were quickly reviewed and applied to the nfsd-testing tree by maintainer Chuck Lever.

Background

The Linux NFS server uses the kernel's credential management subsystem to track security contexts for operations. Functions like get_current_cred() increment a reference count on the current task's credentials, while current_cred() simply returns a pointer without bumping the refcount. Misusing these functions — specifically calling get_current_cred() when no corresponding put_cred() exists — leads to memory leaks of credential structures.

The Bug

Patch 1: nfsd_nl_threads_set_doit()

In PATCH 1/2, Iwashima explains the root cause:

"nfsd_nl_threads_set_doit() passes get_current_cred() to nfsd_svc(), but put_cred() is not called after that."

The credential obtained via get_current_cred() flows down to _svc_xprt_create(), which calls get_cred() on it for its own internal use. However, the original reference from get_current_cred() is never released — it is "just leaked," as Iwashima puts it.

Iwashima contrasts this with another caller of nfsd_svc():

"nfsd_svc() is also called from write_threads(), but it does not bump file->f_cred there."

Since nfsd_nl_threads_set_doit() runs in process context via sendmsg() and current->cred does not disappear, the fix is straightforward: use current_cred() instead of get_current_cred().

The bug was originally introduced by commit 924f4fb003ba ("NFSD: convert write_threads to netlink command") and was reported by syzbot with a detailed memory leak backtrace showing allocation in prepare_creds → copy_creds → copy_process → kernel_clone.

Patch 2: nfsd_nl_listener_set_doit()

PATCH 2/2 addresses a similar issue in the listener netlink command handler:

"nfsd_nl_listener_set_doit() uses get_current_cred() without put_cred()."

Iwashima notes that other callers of svc_xprt_create_from_sa() do not require an extra reference count, and since this function also runs in process context via sendmsg(), the same fix applies: replace get_current_cred() with current_cred().

This bug traces back to commit 16a471177496 ("NFSD: add listener-{set,get} netlink command").

Significance

While these are small one-line changes (two insertions, two deletions in fs/nfsd/nfsctl.c), they address genuine memory leaks that can accumulate over time in production NFS server deployments. Each invocation of the affected netlink commands — used to adjust NFS thread counts and listener configurations — would leak a credential structure. Over repeated administrative operations or automated management cycles, this could lead to significant memory consumption.

The fix demonstrates the value of kernel fuzzing tools like syzbot in uncovering subtle resource management bugs that might otherwise go unnoticed in code paths exercised infrequently.
