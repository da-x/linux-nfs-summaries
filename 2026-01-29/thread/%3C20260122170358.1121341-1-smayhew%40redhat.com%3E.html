nfsiostat trailing-slash fix committed to nfs-utils-2.8.5-rc2

Summary

nfsiostat: normalize mountpoints — patch committed to nfs-utils-2.8.5-rc2

Classification: Bug Fix (nfs-utils userspace tooling)

Summary

This thread concerns a minor but user-facing bug fix in nfsiostat, the NFS I/O statistics reporting tool shipped with nfs-utils. The discussion originated last week when Scott Mayhew submitted a patch, and concluded this week when NFS maintainer Steve Dickson confirmed the commit.

Background (from prior week)

Last week, Scott Mayhew of Red Hat submitted a patch to address an issue where passing a mountpoint with a trailing slash on the command line caused nfsiostat to print statistics for all mounts instead of the specific requested mount. As Scott explained:

"If the mountpoint passed in from the command line contains a trailing '/' character, then nfsiostat winds up printing statistics for all mounts instead of printing statistics for the specific mount that was requested."

The fix was a minimal two-line change in tools/nfs-iostat/nfs-iostat.py, normalizing the mountpoint argument by stripping trailing slashes before processing.

This Week's Activity

On January 26, NFS maintainer Steve Dickson confirmed the patch had been accepted:

"Committed... (tag: nfs-utils-2-8-5-rc2)" Steve Dickson

The fix was incorporated into the nfs-utils-2.8.5-rc2 release candidate, making it available for users seeking more reliable NFS I/O statistics reporting.

Significance

While small in scope, this fix improves the usability of a key NFS diagnostic tool. Administrators relying on nfsiostat for monitoring specific NFS mounts will no longer encounter confusing output when they inadvertently include a trailing slash — a common habit among Linux users accustomed to path conventions where trailing slashes are typically insignificant.
