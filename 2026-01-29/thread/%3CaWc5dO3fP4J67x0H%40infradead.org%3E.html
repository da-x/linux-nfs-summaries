nfs-utils: CONFIG_NFSV41→BLKMAPD patch committed for 2.8.5-rc2

Summary

nfs-utils: CONFIG_NFSV41 → CONFIG_BLKMAPD Patch Committed (nfs-utils-2.8.5-rc2)

Classification

Configuration cleanup / deprecation milestone — not a new feature, protocol change, or bug fix per se, but a build-system alignment reflecting the broader deprecation of pNFS block layout in favor of pNFS SCSI layout.

Prior Context (Week of 2026-01-15)

Last week, Scott Mayhew submitted a patch to nfs-utils renaming the misleadingly named CONFIG_NFSV41 configure option to CONFIG_BLKMAPD and disabling it by default. The rationale was that pNFS block layout is deprecated in favor of pNFS SCSI layout:

"pNFS block layout is deprecated in favor of pNFS SCSI layout, which doesn't require the use of blkmapd."

The patch received a Reviewed-by from Christoph Hellwig ("Looks good") and a Tested-by from Salvatore Bonaccorso for Debian.

This Week's Activity

This week, nfs-utils maintainer Steve Dickson confirmed that the patch has been merged upstream:

"Committed... (tag: nfs-utils-2-8-5-rc2)"

Steve's confirmation on January 26 marks the conclusion of this thread. The change is now part of the nfs-utils 2.8.5 release candidate cycle.

Significance for NFS Client Development

While not a kernel-side client change, this nfs-utils update reflects an important ecosystem shift:

  • pNFS block layout deprecation: The blkmapd daemon, previously needed to support pNFS block layout, is now opt-in rather than built by default. Distributions that still require legacy pNFS block layout support must explicitly enable it via --enable-blkmapd.
  • Cleaner defaults for modern deployments: Most NFSv4.1+ deployments using pNFS SCSI layout will no longer carry the unnecessary blkmapd dependency, reducing attack surface and maintenance burden.

Conclusion

This thread has reached its natural conclusion with the patch committed to nfs-utils 2.8.5-rc2. The rename from CONFIG_NFSV41 to CONFIG_BLKMAPD resolves a longstanding naming confusion in the build system and aligns default behavior with current NFS best practices.
