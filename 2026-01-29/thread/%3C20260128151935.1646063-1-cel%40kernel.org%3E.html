lockd API Boundary Cleanup v4: Race Fix and Header Refactoring Submitted

Summary

lockd API Boundary Cleanup v4: Final Polish Before Merge

Overview

Chuck Lever submitted version 4 of his series to clarify the lockd (NFS Lock Manager Daemon) module's API boundaries (PATCH v4 00/14 through PATCH v4 14/14). This is a refactoring and bug-fix series (not a new feature or protocol change), aimed at separating lockd's public API from internal implementation details, with the dual goals of improving code maintainability and enabling future NLMv4 XDR modernization using xdrgen.

As Chuck explained in the cover letter:

"The lockd subsystem currently exposes internal implementation headers through include/linux/lockd/, creating implicit API contracts that complicate maintenance. External consumers such as NFSD and the NFS client have developed dependencies on internal structures like struct nlm_host, and wire protocol constants leak into high-level module interfaces."

He further noted:

"These changes enable subsequent work to modernize the NLMv4 XDR layer using xdrgen without risk of breaking external consumers."

Context from Prior Weeks

This v4 series is the latest iteration of an ongoing effort that began with a 42-patch v1 submission, was refined to a 42-patch v2 (prior summary), and then split into a focused 14-patch v3 series (prior summary). Key developments from prior weeks:

  • Jeff Layton identified a pre-existing race condition in the NFS client's sysfs shutdown path during v2 review, noting: "I don't see any locking here. Soon after this thing goes NULL, the nlm_clnt can be freed."
  • Build failures on alpha and hexagon architectures were reported by the kernel test robot against v2 patch 10/42, exposing hidden header dependencies in fs/nfs/nfs3proc.c.
  • Build warnings on parisc and s390 were reported against v3 patch 11/14, revealing a missing forward declaration for struct file_lock in the public bind.h header.

Changes Since v3

Chuck documented the incremental change:

"Changes since v3: Address a build failure due to header reorganization"

This addresses the parisc/s390 warnings by adding the necessary forward declarations to bind.h.

Key Technical Arguments and Patches

Critical NFS Client Bug Fix: Race Condition in Sysfs Shutdown (Patch 06/14)

The most significant change for NFS client developers is PATCH v4 06/14, which fixes a use-after-free and null pointer dereference race condition in the NFS client's sysfs "shutdown" file path:

"A race condition exists in shutdown_store() when writing to the sysfs 'shutdown' file concurrently with nlm_shutdown_hosts_net(). Without synchronization, the following sequence can occur:

  1. shutdown_store() reads server->nlm_host (non-NULL)
  2. nlm_shutdown_hosts_net() acquires nlm_host_mutex, calls rpc_shutdown_client(), sets h_rpcclnt to NULL, and potentially frees the host via nlm_gc_hosts()
  3. shutdown_store() dereferences the now-stale or freed host"

The fix introduces nlmclnt_shutdown_rpc_clnt(), a new public API helper that acquires nlm_host_mutex before accessing h_rpcclnt. This carries Jeff Layton's Reviewed-by tag from the v2 review cycle. The patch also improves API layering: NFS client code no longer needs to include internal lockd headers to access nlm_host fields.

Input Validation Hardening (Patch 13/14)

PATCH v4 13/14 adds defensive input validation to prevent malformed lock requests from violating kernel invariants:

"While relocating the function, add input validation: clamp the starting offset to OFFSET_MAX before use. Without this, a malformed lock request with off > OFFSET_MAX results in fl_start > fl_end, violating file_lock invariants and potentially causing incorrect lock conflict detection."

The function is also renamed from nlm4svc_set_file_lock_range() to lockd_set_file_lock_range4(), correcting the misleading "svc" prefix and making it accessible to both client and server code without including server-internal headers.

API Boundary Enforcement (Patches 01–05, 07–12, 14)

The series systematically reduces lockd's public API surface:

  • PATCH v4 01/14: Removes dead NLMv4 code from the NLMv1/v3 handler in cast_status().
  • PATCH v4 02/14: Relocates and renames nlm_drop_reply to nlm__int__drop_reply, making its internal-only nature explicit (per Jeff Layton's naming suggestion from v2 review).
  • PATCH v4 03/14: Introduces nlm__int__deadlock as an internal status code, establishing a translation boundary between generic lockd code and version-specific wire protocol handlers.
  • PATCH v4 04/14: Changes nlm_fopen() to return standard errno values instead of on-the-wire NLM status codes, removing NFSD's dependency on NLM wire protocol definitions and eliminating a CONFIG_LOCKD_V4 check from NFSD source.
  • PATCH v4 05/14: Relocates nlmsvc_unlock_all_by_sb() and nlmsvc_unlock_all_by_ip() declarations to bind.h, grouping them with other external API functions.
  • PATCH v4 07–12/14: Moves internal headers (xdr4.h, share.h, lockd.h, debug.h, xdr.h, nlm.h) from include/linux/lockd/ to fs/lockd/. The public API is reduced to just bind.h.
  • PATCH v4 14/14: Relocates svc_version definitions to the XDR layer, preventing internal implementation details from leaking into public RPC server interfaces.

Build Fix: NFS Client Header Dependency (Patch 11/14)

PATCH v4 11/14 addresses the build failures and warnings from prior versions:

"Forward declarations for struct nfs_fh and struct file_lock are added to bind.h because their definitions were previously pulled in transitively through xdr.h. Additionally, nfs3proc.c needs an explicit include of filelock.h for FL_CLOSE."

This corrects a layering violation where NFS client code depended on internal lockd headers, fixing build failures on alpha/hexagon (v2) and warnings on parisc/s390 (v3).

Summary for NFS Client Development

The most directly relevant changes for NFS client developers are:

  1. Race condition fix (PATCH v4 06/14): A pre-existing use-after-free/null pointer dereference in the sysfs "shutdown" path is resolved by introducing nlmclnt_shutdown_rpc_clnt(), which properly serializes access to h_rpcclnt via nlm_host_mutex.

  2. Layering corrections (PATCH v4 11/14): fs/nfs/nfs3proc.c now explicitly includes filelock.h rather than relying on transitive inclusion through lockd headers, fixing build failures across multiple architectures.

  3. Input validation hardening (PATCH v4 13/14): Malformed NLMv4 lock requests with offsets exceeding OFFSET_MAX are now clamped, preventing violations of file_lock invariants that could cause incorrect lock conflict detection.

  4. API surface reduction: Going forward, NFS client code should only depend on include/linux/lockd/bind.h for lockd interactions. All other lockd headers have been moved to fs/lockd/ as internal implementation details.
