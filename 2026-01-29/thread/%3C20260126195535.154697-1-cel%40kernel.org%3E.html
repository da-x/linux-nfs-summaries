lockd API Boundary Cleanup v3: Race Fix and Header Refactoring Submitted

Summary

lockd API Boundary Cleanup: v3 Series (14 patches) Submitted

Type: Refactoring / Bug fix (race condition fix in NFS client shutdown path, plus input validation hardening)

Overview

Chuck Lever submitted version 3 of his series to clarify the lockd module's API boundaries (PATCH v3 00/14 through PATCH v3 14/14). This is a significant reduction from the previous 42-patch v2 submission, as Chuck separated the API cleanup work (patches 01–14 in v3) from the NLMv4 XDR modernization using xdrgen (which will be posted separately).

As Chuck explained in the cover letter:

"The patches in this series refactor the lockd code base to clearly separate its public API from internal implementation and NLM protocol details."

He further noted that these changes are prerequisites for future XDR work:

"These changes enable subsequent work to modernize the NLMv4 XDR layer using xdrgen without risk of breaking external consumers."

Context from Prior Week

Last week, Chuck posted a 42-patch v2 series (prior summary) that received review from Jeff Layton, who identified a pre-existing race condition in the NFS client's sysfs shutdown path and provided a Reviewed-by tag for the series. The kernel test robot also reported build failures on alpha and hexagon architectures caused by hidden header dependencies in fs/nfs/nfs3proc.c (prior summary).

The v3 series addresses all feedback from v2, incorporating the race condition fix and build failure resolution directly into the patches.

Key Technical Changes (v3 vs. v2)

Chuck documented the changes between versions in the cover letter:

"Changes since v2:

  • Serialize client-side NLM shutdown to avoid UAF and NPD
  • Address a build failure due to header reorganization
  • Rename internal status code nlm_drop_reply"

"Changes since v1:

  • Refine the pre-requisite header adjustments
  • Reduce stack consumption by moving large structures to wrappers
  • Additional extensive clean up"

Critical NFS Client Bug Fix: Race Condition in Sysfs Shutdown

The most important change for NFS client developers is PATCH v3 06/14, which fixes a use-after-free and null pointer dereference race condition in the NFS client's sysfs "shutdown" file path:

"A race condition exists in shutdown_store() when writing to the sysfs 'shutdown' file concurrently with nlm_shutdown_hosts_net(). Without synchronization, the following sequence can occur:

  1. shutdown_store() reads server->nlm_host (non-NULL)
  2. nlm_shutdown_hosts_net() acquires nlm_host_mutex, calls rpc_shutdown_client(), sets h_rpcclnt to NULL, and potentially frees the host via nlm_gc_hosts()
  3. shutdown_store() dereferences the now-stale or freed host"

The fix introduces a new public API helper nlmclnt_shutdown_rpc_clnt() that acquires nlm_host_mutex before accessing h_rpcclnt, synchronizing with nlm_shutdown_hosts_net(). This was originally identified by Jeff Layton during review of v2:

"I don't see any locking here. Soon after this thing goes NULL, the nlm_clnt can be freed. ISTM that this ought to take a reference to nlm_clnt and put it afterward." Jeff Layton

Chuck confirmed the issue during v2 review:

"I asked Claude specifically to look for races, and he agrees there is a pre-existing synchronization issue in here. Certainly could be addressed via a pre-requisite patch to 05/42." Chuck Lever

The fix also improves API layering: NFS client code no longer needs to include the internal lockd header to access nlm_host fields. The new helper resides in bind.h alongside other public lockd interfaces.

Input Validation Hardening: Lock Range Clamping

PATCH v3 13/14 adds input validation to prevent malformed lock requests from violating kernel invariants:

"While relocating the function, add input validation: clamp the starting offset to OFFSET_MAX before use. Without this, a malformed lock request with off > OFFSET_MAX results in fl_start > fl_end, violating file_lock invariants and potentially causing incorrect lock conflict detection."

This is a defensive hardening measure that prevents potential issues from malicious or corrupted NLMv4 lock requests on both client and server sides.

Build Fix: NFS Client Header Dependency

PATCH v3 11/14 addresses the build failure reported by the kernel test robot on alpha and hexagon architectures. The patch adds an explicit #include of filelock.h in fs/nfs/nfs3proc.c for struct file_lock and FL_CLOSE, which were previously pulled in transitively through include/linux/lockd/xdr.h:

"Additionally, nfs3proc.c needs an explicit include of filelock.h for struct file_lock and FL_CLOSE, which xdr.h previously provided."

This corrects a layering violation where NFS client code depended on internal lockd headers.

API Boundary Enforcement (Patches 01–14)

The series systematically reduces the public API surface of lockd:

  • PATCH v3 01/14: Simplifies cast_status() by removing dead NLMv4 code from the NLMv1/v3 handler.
  • PATCH v3 02/14: Relocates and renames nlm_drop_reply to nlm__int__drop_reply, making its internal-only nature explicit (per Jeff Layton's naming suggestion from v2 review).
  • PATCH v3 03/14: Introduces nlm__int__deadlock as an internal status code, establishing a translation boundary between generic lockd code and version-specific wire protocol handlers.
  • PATCH v3 04/14: Changes nlm_fopen() to return standard errno values instead of on-the-wire NLM status codes, removing NFSD's dependency on NLM wire protocol definitions.
  • PATCH v3 05/14: Relocates nlmsvc_unlock API declarations to bind.h, grouping them with other external API functions.
  • PATCH v3 07–12/14: Moves internal headers (xdr4.h, share.h, lockd.h, debug.h, xdr.h, nlm.h) from include/linux/lockd/ to fs/lockd/, reducing the public API to just bind.h.
  • PATCH v3 14/14: Relocates svc_version definitions to the XDR layer, preventing internal implementation details from leaking into public RPC server interfaces.

Discussion Status

As of this week's window close, no replies have been posted to the v3 series. The series carries Jeff Layton's Reviewed-by tags from the v2 review cycle on several patches (notably patches 01, 03, 04, and 06), suggesting that the core technical content has already received positive review, with v3 incorporating the requested changes.

Summary for NFS Client Development

The most directly relevant changes for NFS client developers are:

  1. Race condition fix (PATCH v3 06/14): A pre-existing use-after-free/null pointer dereference in the sysfs "shutdown" path is fixed by introducing nlmclnt_shutdown_rpc_clnt(), which properly serializes access to h_rpcclnt via nlm_host_mutex.

  2. Layering correction (PATCH v3 11/14): fs/nfs/nfs3proc.c now explicitly includes filelock.h rather than relying on transitive inclusion through lockd headers, fixing build failures on alpha and hexagon architectures.

  3. Input validation hardening (PATCH v3 13/14): Malformed NLMv4 lock requests with offsets exceeding OFFSET_MAX are now clamped, preventing violations of file_lock invariants that could cause incorrect lock conflict detection.

  4. API surface reduction: Going forward, NFS client code should only depend on include/linux/lockd/bind.h for lockd interactions. All other lockd headers have been moved to fs/lockd/ as internal implementation details.
