NFSv4 Delegated Timestamps: Runtime Switch Replaces Compile-Time Kconfig Option

NFSv4 Delegated Timestamps: Runtime Switch Replaces Compile-Time Kconfig Option

Summary

Type: Configuration simplification / Feature maturation (transitioning from compile-time to runtime control)

Overview

Jeff Layton submitted a 2-patch v2 series (PATCH v2 0/2) to transition NFSv4 delegated timestamps from a compile-time Kconfig option (CONFIG_NFSD_V4_DELEG_TIMESTAMPS) to a runtime-controlled feature via debugfs. This change reflects the maturation of the delegated timestamp feature, which has proven stable enough to be enabled by default while retaining the ability to disable it for debugging purposes.

As Jeff explained in the cover letter:

"The delegated timestamp code seems to be working well enough now that we want to make it always be built in. In the event that there are problems though, we still want to be able to disable them for debugging purposes." Jeff Layton

Context from Prior Week

The v1 version of this series was posted earlier (January 22, 2026) but received a build failure report from the kernel test robot when CONFIG_NFSD_V4 was disabled. The v2 submission addresses that issue by conditionally compiling out the new debugfs file when NFSv4 support is not enabled.

Key Technical Arguments

Patch 1/2: Adding the Runtime Switch

The first patch (PATCH v2 1/2) introduces a debugfs entry at /sys/kernel/debug/nfsd/delegated_timestamps that allows administrators to enable or disable delegated timestamps at runtime. The implementation adds:

  • A nfsd_delegts_enabled flag in the NFS server state
  • A debugfs file creation guarded by CONFIG_NFSD_V4 (the v2 fix)
  • Integration with the existing delegation timestamp logic in nfs4state.c

Patch 2/2: Removing the Kconfig Option

The second patch (PATCH v2 2/2) removes the NFSD_V4_DELEG_TIMESTAMPS Kconfig option entirely, making delegated timestamp support always compiled in. This eliminates 10 lines from fs/nfsd/Kconfig and 7 lines of conditional compilation from fs/nfsd/nfs4state.c.

Chuck Lever's Review Feedback

Chuck Lever reviewed the patches and passed along LLM-assisted review comments, focusing on documentation concerns:

"Key Concerns: 1. Behavioral change: Systems that previously disabled this experimental feature at compile-time will now have it enabled by default after upgrade. While the runtime switch allows disabling, administrators are not informed of this change. 2. Documentation gap: The commit message is minimal and doesn't explain the transition rationale, migration path, or the loss of the RFC specification reference that was in the Kconfig help text." Chuck Lever

Chuck recommended three specific improvements:

"Recommendations: 1. Consider whether nfsd_delegts_enabled should default to false to preserve the conservative default of the removed Kconfig option, or document the intentional policy shift. 2. Expand commit message to include migration guidance. 3. Add a brief comment above nfsd4_want_deleg_timestamps() documenting the debugfs control and RFC reference." Chuck Lever

He acknowledged that the debugfs switch is intentionally undocumented and temporary, but suggested:

"As the new debugfs switch is intended to be undocumented and temporary, I think adding some code comments and a little more beef to the commit message (sorry vegans) would be helpful. You don't need to go crazy with it." Chuck Lever

Jeff Layton's Response

Jeff agreed with the feedback and committed to preparing a v3:

"Sounds good. I'll plan to send a v3." Jeff Layton

Evolution of the Discussion

The discussion followed a straightforward progression:

  1. v1 submission (Jan 22): Initial proposal to replace Kconfig with runtime control
  2. Build failure report: Kernel test robot identified a build issue when CONFIG_NFSD_V4 is disabled
  3. v2 submission (Jan 25): Fixed the build issue by guarding debugfs file creation behind CONFIG_NFSD_V4
  4. Review feedback (Jan 25): Chuck Lever provided documentation-focused review comments via LLM-assisted analysis
  5. Agreement on v3 (Jan 25): Jeff Layton agreed to improve the commit message and code comments

Final Conclusions

The series received positive technical review, with the only requested changes being improvements to documentation and commit messages. The key conclusions are:

  1. Delegated timestamps are considered stable: The transition from compile-time to runtime control signals that the feature has matured sufficiently for default inclusion in the kernel.

  2. Runtime disable remains available: Administrators can still disable delegated timestamps via debugfs (echo 0 > /sys/kernel/debug/nfsd/delegated_timestamps) for debugging purposes.

  3. Documentation improvements needed: The v3 submission will include expanded commit messages explaining the migration path and code comments documenting the debugfs control mechanism.

Significance for NFS Client Development

While this series primarily affects NFSD (the server side), it has implications for NFS client testing and interoperability:

  • Clients interacting with servers that have upgraded to this change will encounter delegated timestamps by default, rather than only when the server was compiled with CONFIG_NFSD_V4_DELEG_TIMESTAMPS=y.
  • The runtime switch provides a mechanism for server administrators to temporarily disable delegated timestamps during debugging sessions without requiring kernel recompilation.
