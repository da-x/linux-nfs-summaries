nfsd: Delegated Timestamps Moved to Runtime Control

Summary

nfsd: Delegated Timestamps Moved from Compile-Time to Runtime Control

Type: Kernel configuration / feature hardening (NFS server, not client-facing bug fix).

Jeff Layton submitted a two-patch series (PATCH v3 0/2) to transition NFSv4 delegated timestamps from a compile-time Kconfig option to a runtime-tunable feature via debugfs. This change reflects growing confidence in the delegated timestamp implementation and simplifies kernel configuration for distributions.

Background

Delegated timestamps are an optimization in the NFS server that allow clients holding delegations to update file timestamps without contacting the server, improving performance under certain workloads. The feature was previously gated behind CONFIG_NFSD_V4_DELEG_TIMESTAMPS, requiring a kernel rebuild to enable or disable it.

Patch Series Overview

Patch 1/2: Add a runtime switch for disabling delegated timestamps [id://20260126-delegts-v3-1-079f29927b83@kernel.org]

Layton introduced a debugfs toggle at /sys/kernel/debug/nfsd/delegated_timestamps that allows administrators to disable delegated timestamps at runtime. As Layton explained in the commit message:

"The delegated timestamp code seems to be working well enough now that we want to make it always be built in. In the event that there are problems though, we still want to be able to disable them for debugging purposes."

This patch adds a helper function nfsd4_want_deleg_timestamps() and exposes the debugfs file only when CONFIG_NFSD_V4 is enabled (a refinement from v2).

Patch 2/2: Remove NFSD_V4_DELEG_TIMESTAMPS Kconfig option [id://20260126-delegts-v3-2-079f29927b83@kernel.org]

With the runtime switch in place, this patch eliminates the compile-time configuration option entirely. Administrators who previously disabled the feature at build time can now do so via:

echo 0 > /sys/kernel/debug/nfsd/delegated_timestamps

Review and Acceptance

Chuck Lever applied the series to the nfsd-testing tree on the same day it was posted [id://176945201300.108780.3424496378222094323.b4-ty@oracle.com]:

"Applied to nfsd-testing, thanks!"

The v3 iteration incorporated minor documentation improvements (comments and changelog updates) based on feedback from prior review rounds, with no substantive code changes.

Significance for NFS Client Development

While this series targets the NFS server (nfsd), it has indirect implications for NFS client testing and debugging. By making delegated timestamps always enabled by default but runtime-disablable, kernel developers and distribution maintainers can ship kernels with the optimization active while retaining the ability to quickly toggle it off when investigating client-server interoperability issues or timestamp-related bugs. This eliminates the need for custom kernel builds during diagnostic workflows.
