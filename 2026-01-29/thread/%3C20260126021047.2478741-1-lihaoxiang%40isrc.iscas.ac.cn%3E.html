sunrpc: Resource Leak Fix in gss_proxy_save_rsc() Under Review

sunrpc: Resource Leak Fix in gss_proxy_save_rsc()

Classification

Bug fix — A resource leak in the SUNRPC GSS-proxy server-side authentication path, specifically in gss_proxy_save_rsc().

Summary

Haoxiang Li submitted a patch on January 26 to address a resource leak in the NFS/SUNRPC subsystem's GSS-proxy integration. The issue lies in gss_proxy_save_rsc() in net/sunrpc/auth_gss/svcauth_gss.c: when gss_import_sec_context() fails, the mechanism reference acquired earlier by gss_mech_get_by_OID() was not being released, leading to a resource leak.

Patch Details

The patch adds a call to gss_mech_put() on the error path of gss_import_sec_context(). As Haoxiang Li explained in the commit message:

"In gss_proxy_save_rsc(), if gss_import_sec_context() fails, call gss_mech_put() to release the reources acquired by gss_mech_get_by_OID()." Patch submission

The patch is marked with:

  • Fixes: 030d794bf498 ("SUNRPC: Use gssproxy upcall for server RPCGSS authentication.")
  • Cc: stable@vger.kernel.org (indicating the bug is considered significant enough to warrant backporting)

Review Concerns

NFS maintainer Chuck Lever raised a critical concern about potential double-free issues in his review. He questioned whether the mechanism reference might already be released through another code path:

"Is the reference already released via free_svc_cred() ? This change might introduce a double-free bug." Chuck Lever

This is an important question because free_svc_cred() is the function responsible for cleaning up server-side GSS credentials. If that function already calls gss_mech_put() on the same reference, then adding another call in the error path of gss_proxy_save_rsc() would result in a double-free — a serious memory corruption bug.

Current Status

As of this week's cutoff, the discussion remains unresolved. Chuck Lever's concern about the potential double-free has not yet received a response from the patch author. The thread contains only two messages (the initial patch and Chuck's review question), with no follow-up from Haoxiang Li within the week.

Significance for NFS Client Development

While this fix targets server-side GSS-proxy authentication code (svcauth_gss.c), it is relevant to NFS client-server interactions because:

  • The gssproxy upcall mechanism is used for RPCGSS authentication, which underpins secure NFS mounts (e.g., Kerberos-based security)
  • Resource leaks in the server-side authentication path can lead to memory exhaustion over time, degrading NFS server reliability
  • The fix targets a bug introduced by commit 030d794bf498, which added gssproxy upcall support for server RPCGSS authentication

The discussion highlights the careful review process applied even to seemingly straightforward resource leak fixes, particularly in complex reference-counted subsystems like GSS-API integration.
