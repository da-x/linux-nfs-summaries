Client TLS handshake UAF and CMSG v3 await review; Trond tightens NFSv3 ENXIO-on-symlink

Week ending 2026-08-13

A quiet week on linux-nfs still put two NFS client TLS lifetime bugs on the table, plus the only human review of the window: Trond Myklebust tightening the NFSv3 atomic_open type check that currently returns ENXIO on an existing symlink. Nothing merged. Client maintainers spoke on fs/nfs/dir.c and stayed silent on both xprtsock.c postings.

Critical client bugs: handshake UAF, then Alert misclassification

The most urgent client fix is Jérémy Jean’s one-commit SUNRPC patch for a use-after-free on the lower TCP-with-TLS transport. xs_tls_handshake_sync() already pins that rpc_xprt for xs_tls_handshake_done(), but on timeout or signal it drops the pin after tls_handshake_cancel() returns false. False means completion already won — the callback may still be storing xprt_err. An ordinary Ctrl-C during an xprtsec=tls mount, racing tlshd, is enough. Jean drains the callback on the cancel-loser path and leaves the timeout/-ERESTARTSYS return unchanged, matching Chuck Lever’s May server-side handshake wait. Tagged Fixes: 75eb6af7acdf with Cc: stable. No replies.

The same file, a different race: Lever’s v3 CMSG series (7 patches, down from 8) hardens how in-kernel SUNRPC consumes kTLS control records after read_sock_rectype died on netdev. The three client patches (xprtsock.c, now 5–7) are the ones that still need an Acked-by:

  • reject a TLS Alert that is not exactly two octets (-EACCES, so pending RPC tasks see it);
  • classify fatality from the Alert description, not the retired AlertLevel octet — a peer that aborts with unexpected_message but leaves the level set to warning currently leaves in-flight RPCs sitting on a dead session until timeout;
  • fold xs_sock_process_cmsg() into its only caller.

v3’s only delta from v2 is dropping the server helper fold that follow-on work would re-split. Accounting and “resume after control record” remain server-only (svcsock.c); the client still returns -EAGAIN for KeyUpdate, and nobody implements a rekey path. Lever is explicit that the octet-accounting bugs have no trigger today — no RPC-with-TLS stack sends post-handshake control records — and wants independently backportable commits rather than a net/handshake helper. Third posting, still zero review.

The two series share a file and a transport class, not a race: Jean is handshake lifetime; Lever is post-handshake receive policy.

NFSv3 client: ENXIO-on-symlink moves toward v3

The week’s only review thread is Michael Nemanov’s v2 for nfs_atomic_open_v23(). Cold-dcache open(O_CREAT) of an existing symlink over NFSv3 still hits no_open() and returns ENXIO instead of letting the VFS follow the link. v2 already used finish_no_open(file, NULL) after Trond caught a dentry-refcount underflow in v1.

This week Trond accepted that shape, then revised the type check twice in twenty minutes: first !d_inode(dentry) || !S_ISREG(...) so an NFSv2 CREATE that races a server-side directory rename does not dereference a negative dentry, then !d_is_reg(dentry) which already encodes both cases. Nemanov agreed and offered a v3. That v3 did not appear in-window; no Ack, no merge.

The exchange is a reminder of how thin the shared v2/v3 atomic_open path still is. 7c6c5249f061 put O_TRUNC on CREATE UNCHECKED; symlink ENXIO and the NFSv2 negative-dentry rename race are siblings of the same rule: do not call finish_open() unless the dentry is a regular file.

Server-side: two-year-old nfsd netlink hangs now reproduce

syzbot, not a human, supplied the rest of the traffic. On 7 August it posted C reproducers for two June 2024 hung-task reports, both in the nfsd Generic Netlink control plane, both the same lock:

  • nfsd_nl_version_get_doit blocked on nfsd_mutex while nfsd_nl_listener_set_doit holds it;
  • nfsd_nl_threads_get_doit the same, with five getter tasks piled up behind the listener-set holder.

Despite the [nfs?] tag, there is no fs/nfs/ frame on either stack. Client developers can ignore these as mount/RPC regressions; nfsd still serializes version, thread, and listener netlink doits on one process-wide mutex, and listener_set can occupy it long enough to trip khungtaskd. No #syz test, no patch, no maintainer reply.

Trends and what is still open

RPC-with-TLS hardening is the through-line: handshake callback lifetime on the client (Jean), Alert length and severity on both sides (Lever v3), LTS-shaped Fixes: tags, and a deferred net/handshake helper so net/sunrpc/ can drop <net/tls_prot.h>. The client half of that work is blocked on review that has not arrived across three CMSG revisions plus Jean’s new UAF.

Meanwhile the client maintainer is iterating dir.c in public and the nfsd netlink mutex remains a fuzzing magnet. Outstanding at week close: Jean’s handshake wait, Lever’s three xprtsock.c patches (and the four server CMSG fixes), Nemanov’s promised d_is_reg() v3, and two reproducible nfsd hung-task reports with no owner.
