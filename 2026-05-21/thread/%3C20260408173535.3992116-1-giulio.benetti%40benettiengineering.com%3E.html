nfs-utils build-fix series merged for nfs-utils-2.9.2-rc3

Summary

nfs-utils: Build-Fix Series Accepted and Merged into nfs-utils-2.9.2-rc3

Type: Bug fixes (build compatibility / portability)
Status this week: All three patches committed by the maintainer; series closed.

Overview

The thread that began in early April with Giulio Benetti's v2 submission of a three-patch build-compatibility series for nfs-utils reached its natural conclusion this week. On 2026-05-15, Red Hat's NFS maintainer Steve Dickson acknowledged and committed all three patches, tagging them under the release candidate nfs-utils-2-9-2-rc3. This is a routine but important maintenance milestone: the fixes ensure that the user-space NFS tooling continues to compile on older Linux distributions and glibc versions.

What Was Committed

All three commits landed in rapid succession (within ~25 seconds of each other), each accompanied by Dickson's terse confirmation "Committed (tag: nfs-utils-2-9-2-rc3)":

  1. fh_key_file: fix missing string.h inclusion — confirmed by Steve Dickson. The original rationale from Benetti:

    "Add #include <string.h> to fix build failure."

  2. Introduce compat.h for NETLINK_EXT_ACK — confirmed by Steve Dickson. This central patch creates a small compatibility header that conditionally defines NETLINK_EXT_ACK when older kernel headers lack it, and replaces direct <linux/netlink.h> includes with "compat.h" in the affected source files (support/export/cache.c, support/export/cache_flush.c, utils/nfsdctl/nfsdctl.c).

    "In 'compat.h' check if NETLINK_EXT_ACK exists, otherwise define it to fix build failure and where at the moment <linux/netlink.h> is included let's include 'compat.h'"

  3. support/backend_sqlite.c: fix getrandom() fallback — confirmed by Steve Dickson. On older glibc/Linux combinations the syscall number lives in <sys/random.h> rather than being visible through the usual paths, so the include was added.

    "In old Linux/Glibc versions __NR_getrandom is defined in <sys/random.h> so let's add it to fix build failure."

Evolution of the Discussion

The thread itself saw no new technical debate this week — the three messages are purely maintainer acknowledgments closing out the series. The substantive design discussion (introduction of compat.h vs. inline #ifdefs, the v1→v2 refinement that swapped direct netlink header includes for the compat shim, and the addition of the SQLite getrandom fix as a new patch in v2) all took place during the initial submission window covered in the prior week's summary.

The ~five-week gap between submission (April 8) and commit (May 15) is consistent with the cadence of nfs-utils release-candidate preparation: patches are typically batched into an RC tag rather than merged individually.

Significance for NFS Client / User-Space Development

While these changes do not alter NFS protocol behavior or client-side runtime logic, they matter in practice:

  • Distribution and LTS maintainers can now build nfs-utils against older kernel headers without patching upstream sources.
  • The compat.h pattern establishes a small, reusable shim that future netlink-related compatibility issues can extend rather than scattering #ifdefs across multiple files.
  • The SQLite re-export backend fix removes a latent build failure on systems where <sys/random.h> is the sole provider of __NR_getrandom, which affects the export-cache code path used by NFS server tooling (nfsdctl).

Conclusion

The series is fully merged and tagged for nfs-utils-2.9.2-rc3. No further action is expected on this thread. The fixes are low-risk, well-scoped portability improvements that broaden the build matrix for the NFS user-space stack.
