swap_activate interface: MM maintainer reviews complete, merge order clarified

Summary

swap_activate Interface Rework: Full Acked-by from MM Maintainer and Merge-Order Clarification

Overview

This week brought a significant milestone to Christoph Hellwig's 12-patch series reworking the swap_activate interface. The primary event was Chris Li, the memory management subsystem maintainer, reviewing and providing Acked-by tags on all twelve patches in a rapid-fire sequence on May 15. This effectively clears the main gatekeeping hurdle for the series to land upstream.

The thread also saw Hellwig clarify the merge-order priority relative to other in-flight swap work, and follow up on an unresolved boot regression reported by Steve French last week.

Background (from prior week)

Last week, Hellwig posted the full series motivated by Darrick Wong's iomap support for fuse-iomap: > "Darrick recently posted iomap support for fuse-iomap, which was trivial but a bit ugly, which triggered me into looking how this could be done in a cleaner way." The series moves swap operations from address_space_operations to file_operations, consolidates boilerplate into core MM code, and encapsulates internal structures. The NFS client was among the filesystems mechanically updated (changes in fs/nfs/file.c, fs/nfs/direct.c, fs/nfs/nfs4file.c, and include/linux/nfs_fs.h). Steve French reported a boot OOM failure on 7.1-rc3 with the patches applied.

This Week's Activity

MM Maintainer Acked-by on All Patches

On May 15, Chris Li went through each patch in the series and provided his endorsement. His overall first impression was positive:

"My first impression it looks very promising. I will need more time to take a closer look." — Chris Li

He then proceeded to Ack all twelve patches, with particular praise for the boilerplate consolidation:

"Very nice cleanup." — on Patch 02/12

For the core architectural change (moving swapfile operations to struct file_operations):

"That makes sense to me. I ack for the core swap part of the code." — on Patch 03/12

On the sis->bdev pushdown, he noted a slightly narrower review scope:

"The core swap part of the code looks fine to me, I did not look much deeper into the fs side." — on Patch 09/12

He also offered a minor optimization nitpick on Patch 01/12:

"Nitpick: I couldn't hlep but notice the si->max does not change between setup bad slots, so in theory you can cache the si->max value to a local variable for the loop. In real life, it will make no difference, so feel free to keep it as is." — on Patch 01/12

Merge-Order Conflict with Swap Table Work

A critical practical concern was raised by Chris Li:

"BTW, I just tried it, this series conflicts with Kairui's swap table phase IV series. Might need to coordinate the merge order with Kairui." — Chris Li

Hellwig responded on May 18 with a clear priority ordering:

"Yes. I think the swap table should be a priority. Next would be swap_ops (see my take on that from Friday) and then this series. The iomap-fuse work from Darrick seems to be a bit stalled on the fuse side, so I hope he can wait a bit on this as well. Especially as swapfile support might not be the highest priority feature for that." — Christoph Hellwig

This establishes a three-tier merge order: (1) Kairui's swap table phase IV, (2) Hellwig's swap_ops proposal, and (3) this 12-patch interface rework. The iomap-fuse consumer can wait since the FUSE side is stalled.

Follow-up on Boot OOM Regression

Hellwig followed up on Steve French's reported boot failure:

"Is that a failure with the patches or also with the baseline?" — Christoph Hellwig

No reply from French was received within this week's window, so the regression remains unresolved.

NFS Client Relevance

While this series is primarily an MM/filesystem-interface refactoring rather than an NFS-specific feature or bug fix, it directly affects the NFS client codebase. The NFS swap implementation in fs/nfs/file.c had 21 lines removed as swap operations were relocated to the file_operations structure. The mechanical nature of the changes means no behavioral change is expected for NFS swap file support, but the interface contract has shifted — future NFS swap development must use the new ->swap_activate / ->swap_deactivate file_operations callbacks rather than address_space_operations.

Classification

This is a refactoring / API cleanup series, not a bug fix or protocol change. It reorganizes how filesystems integrate with the MM swap subsystem, reducing boilerplate and improving encapsulation. The only functional addition is a sanity check limiting swap file size to device size on block devices (Patch 07/12).

Status and Outlook

With full Acked-by from the MM maintainer, Reviewed-by tags from Damien Le Moal and others in the prior week, and a clear merge-order plan, the series appears well-positioned for inclusion in a future merge window — contingent on Kairui's swap table work landing first. The unresolved boot OOM report remains an open question that could delay or require fixes before final integration.
