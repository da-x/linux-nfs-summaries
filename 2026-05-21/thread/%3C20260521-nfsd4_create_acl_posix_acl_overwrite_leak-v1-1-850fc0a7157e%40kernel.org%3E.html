nfsd: Fix dead ACL conflict guard leaking posix_acl slabs in nfsd4_create

Summary

Bug fix: Dead ACL conflict guard in nfsd4_create leaks two posix_acl objects per request

This week's thread is short but consequential — a one-line bug fix on the NFS server (nfsd) side that plugs an unbounded slab leak triggered by a specific client encoding pattern. It landed quickly, with Chuck Lever applying it to nfsd-testing within hours of submission.

The bug

Jeff Layton submitted a patch on May 21 fixing a subtle but nasty memory leak in nfsd4_create(). The function "steals" the POSIX ACL pointers (create->cr_dpacl / create->cr_pacl) into a local nfsd_attrs struct via a designated initializer, then immediately NULLs out the source fields. The problem:

"The subsequent conflict guard tests the already-nilled source fields, making it permanently dead code:

if (create->cr_acl) {
    if (create->cr_dpacl || create->cr_pacl)  /* always false */
```"

Because the guard could never fire, a client that encoded both FATTR4_WORD0_ACL and FATTR4_WORD2_POSIX_{DEFAULT,ACCESS}_ACL in the same CREATE fattr bitmap would cause nfsd4_acl_to_attr() to overwrite attrs.na_pacl/na_dpacl without releasing the originals. As Layton put it:

"leaking two posix_acl slab objects per request. Repeated requests cause unbounded slab exhaustion."

The fix is a one-line change: check attrs.na_dpacl/attrs.na_pacl (the stolen values) instead of the already-nilled create->cr_dpacl/create->cr_pacl, matching the pattern already used correctly in nfsd4_setattr().

Context and provenance

  • Reported-by: Chris Mason (clm@meta.com) — suggesting this was found during Meta's internal NFS testing.
  • Fixes tag: points to commit d2ca50606f5f ("NFSD: Add support for POSIX draft ACLs for file creation"), meaning the bug has been present since that feature landed.
  • The patch is a single-line change in fs/nfsd/nfs4proc.c.

Resolution

Chuck Lever applied the patch to nfsd-testing the same day, confirming:

"Applied to nfsd-testing, thanks!"

The commit landed as e18fa5137111b7d2ab7002d041c05ee7c52694ef.

Assessment

This is a textbook bug fix (not a new feature or protocol change) with real operational impact: any NFSv4 client that sends both the XDR-encoded ACL attribute and the POSIX draft ACL attributes in a single CREATE would trigger the leak. The unbounded nature of the slab exhaustion makes this a stability concern for long-running servers under such workloads. The quick turnaround — same-day review and application — reflects the straightforwardness of the fix once the dead-code path was identified.
