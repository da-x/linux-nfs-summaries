nfsd: posix_acl leak and ignored error in nfsd4_create_file fixed

Summary

nfsd: posix_acl leak and ignored error in nfsd4_create_file fixed

Type: Bug fix (two distinct bugs in NFSv4 server-side file creation ACL handling)

A concise, self-contained thread landed this week on linux-nfs: Jeff Layton posted a patch fixing two bugs in nfsd4_create_file(), and Chuck Lever applied it to the nfsd-testing tree the same day.

The Patch

Jeff Layton identified two bugs in the NFSv4 server's file creation path:

  1. Silently discarded error from nfsd4_acl_to_attr():

    "The return value of nfsd4_acl_to_attr() is silently discarded. When the NFSv4-to-POSIX ACL conversion fails (e.g., -EINVAL for unsupported ACE types), the file is created without any ACL and the client receives NFS4_OK. This violates RFC 7530/8881 which require the server to reject unsupported attributes on CREATE."

  2. posix_acl memory leak on early error path:

    "When start_creating() fails after ACL attributes have been populated in attrs (either via nfsd4_acl_to_attr or via ownership transfer from open->op_dpacl/op_pacl), the function jumps to out_write which skips nfsd_attrs_free(). The posix_acl allocations are leaked."

Layton noted the leak is triggerable by a client:

"A client can trigger this repeatedly with OPEN(CREATE), ACL attributes, and an invalid filename (e.g., longer than NAME_MAX)."

The fix captures the return value of nfsd4_acl_to_attr(), redirects early error paths to jump to out instead of out_write (so nfsd_attrs_free() is called), and initializes child to ERR_PTR(-EINVAL) so that end_creating() is safe even if start_creating() was never reached.

The patch carries a Fixes: tag pointing to commit 7ab96df840e6 ("VFS/nfsd/cachefiles/ovl: add start_creating() and end_creating()") and credits Chris Mason (Meta) as the reporter. It touches only fs/nfsd/nfs4proc.c with 9 insertions and 6 deletions.

Response and Outcome

Chuck Lever applied the patch to the nfsd-testing tree within hours:

"Applied to nfsd-testing, thanks!"

The commit landed as 15906201636c0850eff0e2e86791f24e007d4160.

Significance

This is a server-side (nfsd) fix rather than a client change, but it directly affects NFSv4 client-visible behavior: clients sending unsupported ACE types on CREATE will now correctly receive an error instead of a silent success with no ACL applied. The memory leak fix also closes a resource-exhaustion vector that could be triggered repeatedly by a malicious or buggy client.
