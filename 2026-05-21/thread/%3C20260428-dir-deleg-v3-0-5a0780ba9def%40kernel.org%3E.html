CB_NOTIFY directory delegation VFS patches merged into vfs.git; NFSD merge timing discussed

Summary

CB_NOTIFY Directory Delegations: VFS Half Merged, NFSD Awaiting Merge Window

This week brought a meaningful milestone for Jeff Layton's 28-patch series adding CB_NOTIFY callback support to NFSv4 directory delegations. The VFS-side changes have been merged into the vfs.git tree, and Chuck Lever has begun coordinating the merge timing for the remaining NFSD patches.

VFS Patches Merged by Christian Brauner

On May 15, Christian Brauner announced that he had merged the VFS-specific portions of the series into a dedicated branch:

"I've only merged the vfs specific changes into a stable branch. You can pull it I won't touch it again. You can pull the nfsd work in in whatever form you like. Same procedure I use with io_uring et al."

The patches landed on the vfs-7.2.directory.delegations branch of vfs/vfs.git, and Brauner noted they "should appear in linux-next soon." The merged VFS changes (patches 01–07 of the series) include:

  • filelock: Passing the current blocking lease to trace_break_lease_block(), adding support for ignoring delegation breaks for directory change events, a new tracepoint at the start of break_lease(), and an inode_lease_ignore_mask helper.
  • fsnotify: A new tracepoint in fsnotify(), the fsnotify_modify_mark_mask() helper, and the FSNOTIFY_EVENT_RENAME data type for carrying rename target information.

Brauner also included his standard post-merge guidance:

"Please report any outstanding bugs that were missed during review in a new review to the original patch series allowing us to drop it."

Chuck Lever Confirms NFSD Merge Prerequisites

Three days later, on May 18, Chuck Lever responded with a brief but important coordination note:

"Looks good. To make the NFSD pieces apply, I need v7.1-rc4 and vfs-7.2.directory.delegations merged into vfs.all. Given your regular merge cadence over the past few weeks, I expect that will happen end of this week? Early next?"

This confirms that the remaining 21 patches (08–28) — covering the NFSD protocol implementation for CB_NOTIFY per RFC8881bis, callback encoding/decoding, fsnotify watch setup on delegated directories, RCU protection of fi_deleg_file, and attribute marshaling in notifications — are ready to proceed but gated on the VFS branch being pulled into vfs.all.

Context from Prior Week

As covered last week, Layton posted v3 of the series with a single change from v2: a crash fix in alloc_init_dir_deleg() where "release_pages() can't handle an array with NULL pointers in it." Chuck Lever had already provided his Acked-by for the full series. The series is fundamentally a new feature (protocol extension enabling clients to receive directory-change notifications without losing their delegation lease), though it included that important crash fix during its development cycle.

Significance for NFS Client Development

While this week's activity is server-side, the CB_NOTIFY infrastructure is the foundation for a significant client-side improvement: NFSv4.2+ clients will be able to register interest in directory changes (creates, unlinks, renames) and receive asynchronous notifications with updated attributes, eliminating the need for full delegation recalls on every directory modification. Layton had noted in the cover letter that testing was done with pynfs and that "we won't want to merge these until we have a complete client-side implementation to test against" — a caveat that remains relevant as the NFSD patches move toward merging.

Status

  • VFS patches (01–07): Merged into vfs-7.2.directory.delegations, expected in linux-next.
  • NFSD patches (08–28): Acked by Chuck Lever, awaiting VFS branch merge into vfs.all (expected end of this week or early next).
  • Client-side implementation: Still pending; full integration testing will follow.
