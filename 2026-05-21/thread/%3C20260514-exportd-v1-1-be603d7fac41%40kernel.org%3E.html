exportfs: is_export cleanup committed to nfs-utils 2.9.2-rc3

Summary

exportfs: Unused is_export Parameter Cleanup — Committed

Classification

Code Cleanup / Dead Code Removal — This is not a new feature, protocol change, or bug fix in the traditional sense. It is a straightforward source-code simplification in the NFS user-space export utilities (nfs-utils).

Context from Prior Week (2026-05-14)

Last week, Jeff Layton submitted a patch to support/export/xtab.c removing the vestigial is_export parameter from xtab_read() and xtab_write(), noting that it was "always passed as 1" and that the is_export == 0 code paths were dead. He also acknowledged the patch had been misdirected to the kernel NFS list rather than the nfs-utils list:

"Oops, I meant to make this '[nfs-utils PATCH]'. Ahh well, anyway, it's just a bit of cleanup..." — Jeff Layton

This Week's Activity (2026-05-15)

The thread concluded this week with a brief confirmation from Steve Dickson, the nfs-utils maintainer:

"Committed (tag: nfs-utils-2-9-2-rc3)" — Steve Dickson

Dickson quoted Layton's original patch description in full before the one-line commit notice, providing a clean record of what was merged. The patch reduced support/export/xtab.c by removing 26 lines and adding 13, netting a 13-line reduction in the export table read/write logic.

Significance for NFS Client Development

While this change lives in the server-side export utilities rather than the kernel NFS client, it is relevant to the broader NFS ecosystem: xtab.c underpins how exportd parses and writes /etc/exports, which directly affects what clients see when they mount shares. Removing dead conditional branches reduces the surface area for future regressions in export table handling and simplifies the code path that every NFSv3/v4 client interacts with at mount time.

Conclusion

The discussion closed without controversy. The patch was accepted as-is, committed to the nfs-utils release candidate (2.9.2-rc3), and no further discussion was needed. It stands as a small but welcome reduction in code complexity for the NFS export subsystem.
