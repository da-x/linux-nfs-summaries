Week in NFS (ending 2026-05-21)

A busy week for the Linux NFS client, dominated by memory-safety fixes in the writeback and pNFS paths, an architectural rework of the xprtrdma transport that hit build errors and is awaiting a v2, and a new RFC on per-client fairness in knfsd. On the server side, a flurry of same-day bug fixes landed in nfsd-testing, including a SUNRPC double-free hardening, several posix_acl leak fixes, and an async-copy TTL inversion. The netfslib bvecq refactoring (v2) continues to shape the client I/O path for the next merge window.

NFS Client: Critical Bug Fixes

Writeback use-after-free in nfs_write_completion()

Dave Jones posted a one-line fix for a slab-use-after-free caught by KASAN under heavy NFSv3 writeback (an rsync workload on 7.1-rc4). The regression came from commit 5d3869a41f36, which dereferenced hdr->req->wb_lock_context inside the per-request loop; when a single pgio header spans multiple page groups, a parallel COMMIT can free hdr->req while the outer loop is still iterating. The fix swaps in the loop-local req, which is pinned by its writeback kref for the duration of that iteration. Jeff Layton has already issued a Reviewed-by. See thread.

pNFS layout-update UAF (tracepoint ordering)

Wentao Liang (ISCAS) posted a one-line reorder in pnfs_update_layout() moving trace_pnfs_update_layout() before pnfs_put_layout_hdr(lo) on the NFS_LAYOUT_RETURN branch. The original ordering — introduced by 2c8d5fc37fe2 — let the tracepoint read from an already-freed layout header. Marked for stable backport; no in-window review yet, but a follow-up from Markus Elfring landed just after the window. See thread.

Don't trust server inode size under a write delegation (v2)

Dai Ngo posted v2 of a small fs/nfs/inode.c fix to nfs_wcc_update_inode(): while the client holds a write delegation, the server's GETATTR size may legitimately lag the locally-buffered size, so it must not be treated as authoritative. The patch gates the WCC size update on either "no write delegation" or "NFS_INO_INVALID_SIZE set." Awaiting review. See thread.

nfs_access_calc_mask() corner cases for special files

Ondrej Mosnacek (Red Hat) fixed two inconsistencies in the NFS client's access-permission calculation that caused access(2, X_OK) on FIFOs/char/block devices to always fail regardless of UNIX permissions — a clear divergence from local-filesystem behavior. The fix unifies regular and special-file handling and corrects a bare bitwise AND into the proper equality pattern used elsewhere. Regression from ecbb903c5674. See thread.

NFSv4.1 client hang in nfs4_drain_slot_tbl (ongoing)

The long-running bug report from 郭玲兴 advanced this week: Rick Macklem flagged the reporter's soft mount option as the likely culprit ("Whenever an RPC times out and doesn't wait for a reply from the server, it will leave a session slot messed up"), and the reporter followed up with full environment details (Windows Server 2022, AUTH_SYS, x86_64) plus lease-expiry evidence showing lease_expired ≈ age - lease_time on both hung clients — strong signal that session state was corrupted well before the visible hang. The reporter is now retesting with a hard mount and has explicitly reframed the question toward client-side robustness: should a single timed-out RPC on a soft mount be able to leave the slot table permanently stuck? This will likely drive the next phase of the thread, potentially toward a concrete nfs4_drain_slot_tbl hardening patch. See thread and follow-up.

NFS Client: Major Infrastructure & Security

xprtrdma: Decouple RPC completion from Send completion (v2 expected)

Chuck Lever posted a significant architectural rework of the RDMA transport's reference-counting model to fix a DMA-lifetime bug: when a reply arrives before an unsignaled Send completes, rpcrdma_reply_handler() could drop the last kref and recycle the request while the HCA is still DMA-reading from its send buffer — silently corrupting RPC data on the wire. The fix decouples RPC completion (Receive path) from request recycling (kref), introduces two explicit owners, adds a teardown drain, and removes a cache-cold atomic from the hot reply path. However, the kernel test robot flagged build errors on nios2/riscv referencing removed backchannel preallocation fields, and Chuck confirmed "Bots and LLM review have found issues with this patch, so expect a v2." See thread.

netfslib: bvecq refactoring (v2)

David Howells posted v2 of his 21-patch series replacing netfslib's folio_queue/rolling_buffer with segmented bio_vec[] chains (bvecq). The goals are consolidation (one buffering scheme for buffered and DIO), performance (single kernel_sendmsg() per RPC, no corking), and simplification (merged prepare/issue ops). For NFS clients the key wins are unified buffer management, a cachefiles optimization that avoids per-read SEEK_DATA/SEEK_HOLE on contiguous files, and reduced TCP overhead. Feedback was minor: David Laight questioned bitfield usage and suggested a tail queue; Stefan Metzmacher acked the CIFS/SMBDirect patches with commit-message nits. See thread.

rpcsec_gss_krb5 → crypto/krb5 migration: client ack received

Anna Schumaker (NFS client maintainer) tested Chuck Lever's 18-patch series migrating rpcsec_gss_krb5 to the common crypto/krb5 library and provided her Acked-by. Combined with Jeff Layton's earlier Reviewed-by, the series now has full maintainer approval for upstream integration. This removes over 4,000 lines of duplicated crypto code from the NFS client and reduces the audit surface for Kerberos operations. See thread.

rxrpc/RxGK pre-decrypt length check (v4)

David Howells posted v4 of the crypto/krb5 + rxrpc fix adding a pre-decrypt/pre-verify length-check facility. The patch is marked for stable backport and CC'd to linux-nfs, signaling its relevance to any NFS client path that shares the Kerberos crypto API. The series has stabilized after three weeks of revisions. See thread.

NFS Server: Bug Fixes & Merges

NFSD fixes merged into v7.1-rc

Chuck Lever's GIT PULL landed in mainline within hours, bringing six commits: an infinite-loop fix in pNFS layout state revocation (Lever), three delegated-attribute correctness fixes for CLONE/COPY/GET_DIR_DELEGATION (Kornievskaia), a CB_GETATTR change-detection fix (Mayhew), and a sunrpc cache netlink seqno off-by-one (Layton). Three are flagged for expedient stable backports.

SUNRPC rq_procinfo double-free hardening (v1 → v2 merged)

The week saw the full lifecycle of this fix: Ren Wei posted v1 on May 20, Chuck Lever requested a broader hardening (clear rq_procinfo at all entry points), and v2 landed on May 21 with those refinements. Jeff Layton reviewed; Lever applied to nfsd-testing the same day (commit 2739a03). The four-line change closes a stale-hook double-free/UAF reachable via malformed or early-failing RPCs. See v1 thread and v2 thread.

SUNRPC xdr_buf_to_bvec() bio_vec array overflow

Chuck Lever posted a two-patch hardening series fixing a latent OOB write in the XDR-to-bio_vec conversion helper on the NFS server's WRITE-decode and send hot paths. Patch 1 (backportable) reorders bound-checks before stores; patch 2 changes the return type to propagate -ESERVERFAULT on overflow. Jeff Layton reviewed both within hours. Reported by Chris Mason (Meta). See thread.

nfsd: drain backchannel callbacks before freeing a session

Chris Mason (Meta) posted a two-patch UAF fix for the race between DESTROY_SESSION and in-flight CB RPCs on rpciod. Jeff Layton validated both problems but flagged a busy-spin in nfsd41_cb_get_slot() when the session is NULL (the new early-return path doesn't sleep or set an error, causing __rpc_execute() to loop). Bruce Fields questioned whether the explicit drain is redundant with rpc_shutdown_client(). Layton granted a conditional Reviewed-by pending reordering and the spin fix. Both patches carry Assisted-by: kres (claude-opus-4-7). See thread.

nfsd: release layout stid on setlease failure

Chris Mason fixed a dangling IDR pointer in the pNFS layout stateid teardown path: a failed nfsd4_layout_setlease() freed the stateid without calling idr_remove(), leaving any subsequent IDR walker to dereference freed slab. The fix hoists INIT_DELAYED_WORK above the setlease call and replaces manual cleanup with nfs4_put_stid(). Applied to nfsd-testing within an hour; Layton reviewed. See thread.

Batch of same-day nfsd fixes (May 21)

A cluster of small, surgical fixes landed on the final day of the week, all applied to nfsd-testing within hours:

  • posix_acl leak on SETACL decode failure — Layton wired proper pc_release handlers for NFSv2/v3 SETACL so orphaned ACLs are freed even when decode fails. Thread
  • Dead ACL conflict guard in nfsd4_create — a one-line fix for an unbounded slab leak when a client encodes both XDR ACL and POSIX draft ACL attributes. Thread
  • posix_acl leak + ignored error in nfsd4_create_file — fixes a silently discarded nfsd4_acl_to_attr() return and an early-error path that skipped nfsd_attrs_free(). Thread
  • Inverted cp_ttl check in async copy reaper — a one-character negation fixing spurious NFS4ERR_BAD_STATEID on OFFLOAD_STATUS. Thread
  • Unchecked get_user() of princhashlen — a missing return-value check in the v2 upcall path that could drive memdup_user() with garbage. Thread

Rejected / dropped patches

  • nfsd UAF in nfsd4_lock() — Wentao Liang's proposed fix was rejected by Layton within an hour: the stateid already holds two references at that point, so the UAF cannot occur. Thread
  • sunrpc kref_get_unless_zero in auth_domain_lookup — Layton's own patch was dropped after sashiko (automated review) correctly identified that the described race window doesn't exist under the current locking. Thread

NFSD export cleanup revert: tested and queued

The multi-week saga of reverting "Defer sub-object cleanup in export put callbacks" reached its final step: Calum Mackay (Oracle) confirmed all three regression symptoms are resolved ("no crashes, sosreport no longer hangs, no seq_file warnings"), and Chuck Lever marked it for the next nfsd-testing push. See thread.

Ongoing Debates & RFCs

knfsd: per-client fair scheduling (new RFC)

Benjamin Coddington (Hammerspace) opened a new RFC proposing a per-client fair-queueing scheduler to prevent one aggressive client (e.g., 8 connections × 128 slots ≈ 1000 concurrent ops) from starving others. Chuck Lever acknowledged the problem as "a well-known shortcoming" but pushed back on making the client the unit of fairness, noting the deeper buffer-to-thread coupling issue. Lever proposed managing per-session slot tables for NFSv4.1+; Coddington's open question — "What about v3?" — remains unanswered. Daire Byrne (brahma.io) corroborated with production evidence of using svc_rpc_per_connection_limit = 4 as a crude stopgap. See thread.

CB_NOTIFY directory delegations: VFS half merged

Christian Brauner merged the VFS-specific patches (01–07) of Layton's 28-patch CB_NOTIFY series into vfs-7.2.directory.delegations. Chuck Lever confirmed the remaining NFSD patches (08–28) are ready but gated on the VFS branch landing in vfs.all (expected end of this week or early next). The client-side implementation is still pending; full integration testing will follow. See thread.

Case folding v14: post-merge triage

The case-folding series is confirmed for Linux 7.2. This week's activity centered on an LTP statx04 regression on vfat: the new fileattr_get implementation makes FS_IOC_GETFLAGS succeed on directories, converting previously-skipped test cases into failures for attributes FAT doesn't support (COMPRESSED, NODUMP). Lever proposed the narrowest fix (generic_fill_statx_attr in fat_getattr()) and is awaiting vfat maintainer sign-off. See thread.

try_break_deleg() and atomic_open(): closed

The design discussion between Neil Brown and Jeff Layton reached a natural conclusion: no current filesystem (NFSv4, CIFS) combines directory leases with ->atomic_open, so the theoretical race is not exploitable today. The NFSv4 client's local lease handling appears correct for intra-client conflicts; empirical testing is recommended but not blocking. See thread.

XFS pNFS Server Fixes (client-impacting)

Dai Ngo's two-patch series correcting XFS pNFS layout mappings was reviewed and approved by Christoph Hellwig the same day. Patch 1 fixes use of an uninitialized imap in the error path of xfs_fs_map_blocks(); patch 2 removes XFS_BMAPI_ENTIRE to eliminate overlapping extents in LAYOUTGET replies — a server-side source of malformed layout data that could cause client-side data corruption or protocol violations. A broader nfsd race condition (layout insertion after ->proc_layoutget) remains an open item. See thread.
