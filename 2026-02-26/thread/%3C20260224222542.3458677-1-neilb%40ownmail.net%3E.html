VFS Directory Locking Centralization: v3 Patch Series Submitted, NFS Server Impact Minimal

Overview

On February 24, Neil Brown submitted version 3 of his 15-patch series titled "Further centralising of directory locking for name ops" 00/15. This is a VFS refactoring effort — not a new feature, protocol change, or bug fix — aimed at consolidating all directory locking for name operations into unified interfaces (start_creating(), start_removing(), start_renaming(), and related functions). The ultimate goal is to transition from whole-directory locking to per-name locking, a prerequisite for improved VFS scalability.

No replies or reviews were posted this week; the series was submitted fresh with fixes addressing prior feedback from Chris Mason's tool-based review.

Bridge from Prior Weeks

This series is a continuation of Neil Brown's long-running directory locking refactor, previously summarized in related threads:

  • The v2 iteration (submitted earlier this month as a 13-patch series) generated significant discussion around overlayfs lock reacquisition semantics and SELinux integration coordination. Paul Moore agreed to take the SELinux patch into the SELinux tree independently prior summary.
  • A parallel discussion on d_splice_alias() and hashed dentries — directly relevant to NFS client atomic_open handling — remains open after Neil Brown's February 26 analysis prior summary.

v3 Changes and Fixes

Neil Brown noted in the cover letter that v3 addressed specific bugs found during automated review:

"Following Chris Mason's tool-based review, here is v3 with some fixes. Particularly 06/15 mistakenly tested the result of start_creating for NULL and 09/15 had some really messed up flow in error handling. Also human-language typos fixed." Cover letter

The series expanded from 13 to 15 patches, with additional VFS documentation and cleanup patches added at the beginning and end.

Patch-by-Patch Breakdown

VFS Documentation and Cleanup (Patches 01–04)

  • PATCH 01/15: Updates documentation for try_lookup_noperm() and related functions to correctly note that they can return error pointers, not just NULL. This was prompted by Darrick J. Wong's observation.
  • PATCH 02/15: Removes unnecessary root inode locking in proc_setup_self() and proc_setup_thread_self(), which are called before the filesystem is live.
  • PATCH 03/15: Moves a misplaced kerneldoc comment to its correct location for start_dirop().
  • PATCH 04/15: Eliminates code duplication by having simple_done_creating() call end_creating().

Security Module Conversions (Patches 05–06)

  • PATCH 05/15: Converts AppArmor to use simple_start_creating() / simple_done_creating(), removing explicit parent locking and lookup. Jeff Layton reviewed this patch.
  • PATCH 06/15: Converts SELinux similarly. Paul Moore provided his Acked-by. Neil Brown notes: "The lookup uses simple_lookup() and so always succeeds. Thus when d_make_persistent() is called the dentry will already be hashed."

NFS Server Impact (Patch 07/15)

  • PATCH 07/15: Converts nfsd's purge_old() in fs/nfsd/nfs4recover.c to use start_removing_noperm() and end_removing() wrappers instead of explicit locking. Jeff Layton reviewed this patch. Neil Brown explains: "This was not done with other start_removing changes due to conflicting in-flight patches."

NFS client relevance: This patch touches only the NFS server (nfsd) recovery code, not the NFS client. The change is a straightforward API migration with no behavioral impact on NFS client operations.

VFS Internal Cleanup (Patch 08/15)

  • PATCH 08/15: Makes lookup_one_qstr_excl() static since it is no longer used outside namei.c.

Overlayfs Refactoring (Patches 09–14) — The Bulk of Changes

Neil Brown emphasized: "The biggest changes are in overlayfs." Cover letter

  • PATCH 09/15: Simplifies ovl_lookup_real_one() by removing explicit locking and using lookup_noperm_unlocked(). Both Jeff Layton and Amir Goldstein reviewed this patch.

  • PATCH 10/15: Converts cachefiles_bury_object to use start_renaming_dentry(), reducing the patch by 62 lines of code.

  • PATCH 11/15: Passes a name buffer to ovl_start_creating_temp() in preparation for the next patch.

  • PATCH 12/15: The most technically significant patch. It changes ovl_create_real() to drop the directory lock and reacquire a new lock when re-opening a created file. Neil Brown explains the motivation:

    "Proposed changes to locking will make this not possible — as the name, rather than the directory, will be locked. The new APIs provided for lookup and locking do not and cannot support this pattern."

    He further notes: "The lock isn't needed. ovl_create_real() can drop the lock and then get a new lock for the lookup — then check that the lookup returned the correct inode." Amir Goldstein reviewed this patch.

  • PATCH 13/15: Replaces lock_rename() with is_subdir() for a point-in-time sanity check in overlayfs mount validation.

  • PATCH 14/15: Removes the now-unused ovl_lock_rename_workdir() function.

VFS API Consolidation (Patch 15/15)

  • PATCH 15/15: Unexports lock_rename(), lock_rename_child(), and unlock_rename() since they are now only used internally within namei.c. This is a symbolic milestone indicating that all external callers have been converted to the new centralized APIs.

Testing Status

Neil Brown reported initial testing progress in the cover letter:

"I'm running the --overlay tests in xfstests and nothing has popped yet. I'll continue with this and run some NFS tests too." Cover letter

Key Technical Arguments and Evolution

This v3 series represents a maturation phase of the locking centralization effort:

  1. Bug fixes from automated review: The NULL-check error in patch 06/15 and the messed-up error handling flow in patch 09/15 were corrected, showing the value of tool-assisted review.
  2. Expanded scope: The series grew from 13 to 15 patches, adding documentation fixes (patch 01) and final API unexporting (patch 15).
  3. Overlayfs as the critical path: The overlayfs changes remain the most complex and risky part of the series, particularly patch 12/15's lock-dropping-and-reacquiring pattern in ovl_create_real().
  4. NFS server integration: The nfsd conversion (patch 07/15) was deferred in earlier versions due to conflicting patches and is now included cleanly.

Final Conclusions

  • No discussion this week: The series was submitted on February 24 with no replies within the reporting window. Review and feedback are expected in subsequent weeks.
  • NFS client impact: indirect. While this series does not directly modify NFS client code, it is part of the broader VFS locking refactor that will eventually require NFS client adaptations — particularly around d_drop() usage and dentry hashing semantics, as discussed in the parallel d_splice_alias() thread.
  • NFS server impact: minimal. Patch 07/15 converts one nfsd function to the new API with no behavioral change.
  • The series is a prerequisite for the follow-up batch (available in Neil Brown's pdirops-next branch) that will implement the actual per-name locking model.
