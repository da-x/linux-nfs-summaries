nfsd: Convert global state_lock to per-net deleg_lock for reduced container contention

Summary

nfsd: Converting the Global state_lock to a Per-Namespace deleg_lock

This week, NFS server (nfsd) development saw a targeted improvement aimed at reducing lock contention in containerized environments. Jeff Layton introduced and had accepted a patch that refactors how delegation state is protected within the kernel NFS server.

Technical Argument: Reducing Contention Between Containers

The core issue addressed by this change is unnecessary serialization of NFS operations across different network namespaces (containers). Previously, a single global spinlock, state_lock, was used to protect delegation lifecycle operations—specifically the del_recall_lru list and the delegation hash/unhash mechanisms.

In his patch submission, Jeff Layton explained the rationale:

"The state_lock was only used to protect delegation lifecycle operations (the del_recall_lru list and delegation hash/unhash), all of which are scoped to a single network namespace. Making the lock per-net removes a source of unnecessary contention between containers."

By converting this global lock into a per-nfsd_net deleg_lock, the patch ensures that NFS servers running in different containers no longer compete for the same CPU spinlock when managing delegations. This is a significant scalability improvement for systems hosting multiple NFS services in isolated network namespaces.

Conclusion and Acceptance

The change was reviewed and accepted by NFS maintainer Chuck Lever. In his response, Lever confirmed the patch was applied to the nfsd-testing tree with minor adjustments:

"Applied to nfsd-testing with minor changes, thanks!"

The commit 87d8659010fe5ba78759ad7b8780656f1c3d350a now resides in the testing branch, pending merge into the mainline kernel.

Classification
