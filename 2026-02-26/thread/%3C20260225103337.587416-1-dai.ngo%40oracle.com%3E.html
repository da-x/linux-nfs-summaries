NFSD: Per-Net Namespace Callback Ops and Critical nrvers Bug Fix

Summary

NFSD: Per-Net Namespace Callback Ops and a Critical Bug Fix

This week, Dai Ngo submitted version 2 of a patch to move accumulated NFSv4 callback operations from global static structures into per-network namespace data (struct nfsd_net). The goal is to ensure proper isolation when running nfsd inside containers. However, the review process uncovered a significant bug in the v2 implementation that would have caused out-of-bounds memory access.

Patch Overview and Intent

Dai Ngo introduced the change with the following description:

"Track accumulated callback operations on a per-network-namespace basis instead of globally, ensuring proper isolation and behavior when running nfsd in containers." PATCH v2 1/1

The patch modifies fs/nfsd/netns.h, fs/nfsd/nfs4callback.c, fs/nfsd/nfsctl.c, and fs/nfsd/state.h to allocate callback counters and program definitions within the network namespace context. The v2 update also included a minor fix:

"free memory allocated for nn->nfsd_cb_version4.counts in nfsd_net_cb_stats_init() on error in nfsd_net_init()." PATCH v2 1/1

Critical Bug Identification by Jeff Layton

Jeff Layton reviewed the patch and highlighted a serious error in how the nrvers field of the RPC program structure was calculated. In the original global code, this field used ARRAY_SIZE(nfs_cb_version), which correctly evaluated to 2 (the number of supported versions). In Dai's v2 patch, the calculation was changed incorrectly:

nn->nfsd_cb_program.nrvers = sizeof(struct rpc_version *) * 2;

Jeff Layton explained the severity of this mistake:

"sizeof(struct rpc_version *) is 8 on 64-bit, making nrvers 16 here while the nfsd_cb_versions array only has 2 elements. The version bounds check in rpc_new_client() compares args->version against program->nrvers, and rpc_proc_show() iterates from 0 to nrvers - 1 accessing program->version[i]." Review

This bug would have allowed the kernel to treat 16 versions as valid when only 2 existed, leading to out-of-bounds array accesses during RPC client creation or debugging output generation. Jeff suggested using ARRAY_SIZE(nn->nfsd_cb_versions) instead.

Resolution and Acknowledgement

Dai Ngo acknowledged the error immediately and confirmed it would be fixed in version 3 of the patch:

"Yes, it's a bug. Fix in v3." Response

Dai also humorously noted Jeff's use of AI-assisted review:

"Clause describes it much more precise than I did, pretty soon I'll be out a job :)." Response

Conclusion

This discussion centers on a bug fix and feature refinement for NFS server (NFSD) development. The primary contribution is moving callback statistics to per-net namespace storage, which is essential for containerized NFS deployments. However, the review process caught a critical implementation bug that would have introduced memory safety issues. The fix for this bug is expected in v3 of the patch series.
