sunrpc: Fix missing XPT flags in tracing macro

Summary

This week saw a brief but important maintenance patch from NFS subsystem maintainer Chuck Lever addressing an oversight in the SUNRPC tracing infrastructure. The discussion is strictly a bug fix rather than a new feature or protocol change, focusing on ensuring that diagnostic tracing for NFS server transports remains accurate and complete.

Key Technical Arguments and Context

The patch addresses a discrepancy introduced by two prior commits:

  1. eccbbc7c00a5 ("nfsd: don't use sv_nrthreads in connection limiting calculations.")
  2. 898374fdd7f0 ("nfsd: unregister with rpcbind when deleting a transport")

Both of these earlier changes added new transport flags (XPT flags) to the SUNRPC subsystem but failed to update the show_svc_xprt_flags() macro, which is used for tracing and debugging purposes. This meant that when developers or administrators inspected NFS server transport states via tracepoints, the newly introduced flags would not be displayed, potentially hindering diagnostics.

As Chuck Lever noted in the commit message:

"Commit eccbbc7c00a5 ("nfsd: don't use sv_nrthreads in connection limiting calculations.") and commit 898374fdd7f0 ("nfsd: unregister with rpcbind when deleting a transport") added new XPT flags but neglected to update the show_svc_xprt_flags() macro."

Evolution of the Discussion

This thread consisted of a single message this week:

  • [PATCH] sunrpc: Add XPT flags missing from SVC_XPRT_FLAG_LIST](https://lore.kernel.org/linux-nfs/20260221183959.7672-1-cel@kernel.org/) by Chuck Lever on February 21, 2026.

There was no further discussion or review feedback within the current week's window. The patch is a straightforward one-file change to include/trace/events/sunrpc.h, adding three lines and removing one, to ensure the tracing macro reflects all currently defined transport flags.

Final Conclusions

The patch represents a minor but necessary correction to maintain the integrity of NFS server debugging tools. By updating SVC_XPRT_FLAG_LIST, future trace outputs will correctly display all active transport flags, including those related to connection limiting and rpcbind unregistration. This ensures that developers troubleshooting NFS server behavior will have complete visibility into transport states.

Given the simplicity and correctness of the fix, and its origin from the subsystem maintainer, it is expected to be merged without controversy. The lack of additional discussion this week suggests the patch was either queued for immediate inclusion or awaited standard review cycles outside the current window.
