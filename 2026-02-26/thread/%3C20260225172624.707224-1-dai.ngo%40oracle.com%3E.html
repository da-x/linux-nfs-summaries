NFSD: Per-Net Namespace Callback Ops – v3 Fixes Critical nrvers Bug

Summary

NFSD: Per-Net Namespace Callback Operations – v3 Patch Addresses Critical Bug

Overview

This thread represents version 3 of Dai Ngo's patch series to move accumulated NFSv4 callback operations from global static structures into per-network namespace storage (struct nfsd_net). The change is a bug fix and container isolation improvement for the NFS server (NFSD) subsystem, ensuring that each network namespace maintains its own callback counters and RPC program definition.

Evolution of the Discussion

This v3 submission follows two earlier iterations within the same week:

  • v1 (submitted Feb 25): Initial proposal to track callback operations per-network namespace for container isolation.
  • v2 (submitted Feb 25): Added an error-path memory free fix but introduced a critical bug in the nrvers field initialization.

The v2 patch was reviewed by Jeff Layton, who identified a severe out-of-bounds memory access vulnerability:

"sizeof(struct rpc_version *) is 8 on 64-bit, making nrvers 16 here while the nfsd_cb_versions array only has 2 elements. The version bounds check in rpc_new_client() compares args->version against program->nrvers, and rpc_proc_show() iterates from 0 to nrvers - 1 accessing program->version[i]."

Dai Ngo acknowledged the error promptly:

"Yes, it's a bug. Fix in v3."

This Week's Activity (v3)

On February 25, Dai Ngo submitted PATCH v3 1/1, which addresses the issues raised during review:

"v3: . reword commit message. . fix initialization of nn->nfsd_cb_program.nrvers."

The patch modifies four files in the NFSD subsystem:

  • fs/nfsd/netns.h (+4 lines): Adds per-namespace callback state structures.
  • fs/nfsd/nfs4callback.c (75 lines changed): Core refactoring of callback operation tracking.
  • fs/nfsd/nfsctl.c (+5 lines): Initialization and cleanup for per-namespace data.
  • fs/nfsd/state.h (+2 lines): State structure updates.

The net change is 51 insertions and 35 deletions, reflecting a moderate but impactful refactoring effort.

Context: Broader NFSD Containerization Effort

This patch is part of an ongoing initiative to improve NFSD's compatibility with containerized environments. Earlier this week, the mailing list also discussed exposing callback statistics via /proc vs. netlink interfaces (related discussion, summarized separately). Neil Brown had advised:

"So I change my comment to: please don't do that. I don't think it is appropriate to export global statistics. We should only export per-net-namespace statistics. So place convert the statistics collect to per-net-namespace, then export them."

This v3 patch directly implements Neil's recommendation by converting callback statistics collection to a per-net-namespace basis — a prerequisite for any future statistics export work.

Current Status

As of the end of this reporting period, there have been no replies to the v3 submission within the week window. A response from the kernel test robot arrived on February 27 (outside the reporting window). The patch appears ready for maintainer review and potential inclusion in the next merge window.

Conclusion

This thread highlights a well-executed iterative development process: Dai Ngo submitted a container-isolation improvement, reviewers caught a critical memory safety bug that would have caused out-of-bounds accesses, and the author promptly corrected it in v3. The patch represents an important step toward full NFSD container support, ensuring callback operations are properly isolated per network namespace.
