Cleanup: Remove stray pagevec references and unused includes from NFS and other filesystems

Summary

mm/folio_batch Cleanup: Removing Stray pagevec References

This thread covers a four-patch series by Tal Zussman to clean up residual references to struct pagevec following its removal from the kernel. While primarily a memory management and filesystem infrastructure update, it includes minor cleanup changes to NFS client source files.

Overview

The series aims to modernize headers and macros after struct pagevec was removed in commit 1e0877d58b1e. The changes involve:

  1. Removing stray forward declarations of struct pagevec.
  2. Removing unnecessary #include <linux/pagevec.h> directives from .c files that do not use the header's contents.
  3. Renaming include/linux/pagevec.h to include/linux/folio_batch.h.
  4. Renaming the macro PAGEVEC_SIZE to FOLIO_BATCH_SIZE.

NFS Client Impact

The only impact on NFS client development is cosmetic and maintenance-related. Patch 2/4 removes unused header includes from two NFS files:

  • fs/nfs/blocklayout/blocklayout.c
  • fs/nfs/dir.c

As noted by Tal Zussman in the cover letter PATCH v2 0/4:

"While at it, remove unnecessary #includes of pagevec.h (now folio_batch.h) in .c files. There are probably more of these that could be removed in .h files, but those are more complex to verify."

There were no technical arguments or debates regarding NFS functionality. The changes do not alter NFS protocol handling, performance, or bug fixes; they simply reduce header dependency clutter.

Review and Acceptance

The series was quickly reviewed and accepted by key maintainers:

  • Andrew Morton (mm maintainer) confirmed acceptance: "Thanks, I'll add this series to mm.git's mm-new branch." Re: PATCH v2 0/4
  • Jan Kara provided Reviewed-by tags for patches 2/4, 3/4, and 4/4, stating: "If it compiles than it's nice to get rid of." Re: PATCH v2 2/4
  • David Hildenbrand, Zi Yan, and Chris Li provided Acked-by tags for the various patches.

Conclusion

This thread represents a successful infrastructure cleanup with negligible impact on NFS client logic. The removal of unused headers from fs/nfs/ files is a minor maintenance improvement, ensuring that NFS code does not depend on obsolete or unnecessary memory management headers. No new features or bug fixes were introduced for the NFS subsystem in this discussion.
