NFS: Suppress misleading "Server wrote zero bytes" error during pNFS fallback

Summary

NFS: Suppress Misleading "Server wrote zero bytes" Error During pNFS Fallback

Overview

This week, Olga Kornievskaia submitted a targeted bug fix to improve error reporting in the NFS client when dealing with Parallel NFS (pNFS) I/O failures. The patch addresses a specific scenario where the kernel logs a misleading error message that can confuse system administrators into believing there is a systemic issue, when in fact the NFS client's fallback mechanism is working as intended.

Technical Context

The discussion centers on the interaction between pNFS data server writes and the Metadata Server (MDS) fallback path. When a pNFS I/O operation fails against a data server, the NFS client retries the operation against the MDS. This is standard behavior and not indicative of a failure condition. However, during this transition, the kernel was logging an error message that suggested something had gone wrong.

The Problem

As described by Olga Kornievskaia in her patch submission:

"When a pnfs error occurs, the IO is retried against the MDS. However, the initial IO leads to the kernel logging 'Server wrote zero bytes' when in fact the MDS IO will not fail and thus the error misleads administrators that the system is experiencing issues."

The root cause lies in the function nfs_writeback_result(). When a pNFS I/O fails and triggers pnfs_write_done_resent_to_mds(), the original page structure in the nfs_pgio_header is cleared (with content copied into a new structure for the retry RPC to the MDS). At this point, when nfs_writeback_result() checks for pages to process, it finds none and logs the "Server wrote zero bytes" message — even though no actual error has occurred.

The Fix

The patch makes a minimal one-line change in fs/nfs/write.c:

"Thus, in nfs_writeback_result() when we have no pages to work with no need to try and also therefore skip logging the message about 0bytes."

By skipping the error log when there are no pages to process (a condition that occurs during legitimate pNFS-to-MDS fallback), the patch eliminates the false-positive error reporting.

Classification

  • Type: Bug fix (error reporting improvement)
  • Component: NFS client, specifically pNFS write path and MDS fallback handling
  • Impact: Reduces noise in kernel logs for administrators managing NFS mounts with pNFS enabled

Conclusion

This is a small but meaningful quality-of-life improvement for NFS administrators. By silencing a misleading error message during normal pNFS fallback operations, the patch helps ensure that log messages accurately reflect actual system issues rather than routine operational behavior. The change was proposed by Olga Kornievskaia of Red Hat and suggested by Trond Myklebust, reflecting ongoing efforts to refine the NFS client's robustness and observability.
