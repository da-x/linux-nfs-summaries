pNFS: "Server wrote zero bytes" Fix Adopted, v2 Patch Promised

Summary

pNFS: Suppress Misleading "Server wrote zero bytes" Warning on MDS Retry — Resolution

Classification: Bug Fix (NFS Client / pNFS File Layout Driver)

This thread continues from last week, where Red Hat's Olga Kornievskaia submitted a patch to suppress a misleading "Server wrote zero bytes" kernel warning that appears during pNFS I/O error recovery. The issue is not a data integrity problem — the actual I/O succeeds via Metadata Server (MDS) retry — but rather a noisy log message that can alarm administrators.

Prior Week Recap

Last week, Olga's initial patch was reviewed by NFS client maintainer Trond Myklebust, who questioned whether the fix was necessary given existing safeguards in nfs_pgio_result(). After Olga clarified that task->tk_status is reset to 0 by filelayout_reset_write() during MDS retry preparation, Trond proposed a cleaner, more generic alternative:

"IOW: Why not just change that test at the top of nfs_writeback_result() to read something like: if (resp->count < argp->count && !list_empty(hdr->pages))" 00f3d1fe8b61410ad2296d76f0603a51e8e9991b.camel@kernel.org

This approach would prevent the warning from firing when no pages remain to be written — a condition that naturally occurs during pNFS MDS retry scenarios.

This Week's Activity: Agreement and v2 Commitment

This week, Olga Kornievskaia responded positively to Trond's suggestion, confirming that she tested his proposed generic approach and found it effective:

"Thank you for the suggestion. A generic approach like you are suggesting is definitely better. I have tested it and it solves the problem. I can send a v2 tomorrow." CAN-5tyEoVHxS4aJYHjSYAhJF1OyuGKOStFcLQf9eqaPMue8tmw@mail.gmail.com

Final Conclusions

The discussion has reached a clear resolution:

  1. Trond's suggested fix is accepted: Rather than Olga's original approach of explicitly checking for a retry-against-MDS error, the maintainer's more generic guard — adding !list_empty(hdr->pages) to the short-write condition in nfs_writeback_result() — was endorsed by both parties.
  2. A v2 patch is forthcoming: Olga committed to sending an updated patch incorporating Trond's suggestion, expected shortly after this week's window.
  3. Impact: The fix improves NFS client logging hygiene for pNFS deployments, eliminating false-positive warnings that could mislead system administrators during normal error recovery flows.

Key Technical Takeaway

The root cause was that filelayout_reset_write() resets task->tk_status to 0 when preparing for an MDS retry, which allowed the writeback completion path to proceed and emit the "Server wrote zero bytes" warning despite no actual short write having occurred. The refined fix addresses this at a more fundamental level by ensuring the short-write condition is only entered when there are actually pages pending — a logically sound guard that prevents the spurious warning without requiring special-case handling for MDS retries.
