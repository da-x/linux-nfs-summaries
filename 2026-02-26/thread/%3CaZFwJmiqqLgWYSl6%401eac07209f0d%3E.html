nfs-utils: mount.nfs const-correctness fix committed

Summary

This thread, initiated last week by Rudi Heitbaum with a patch to address -Wdiscarded-qualifiers compiler warnings in nfs-utils, concluded this week when maintainer Steve Dickson confirmed the patch was accepted and merged.

Classification

Bug Fix: Const-correctness fix in nfs-utils mount.nfs device parser.

Evolution of the Discussion

Last week, Rudi Heitbaum submitted PATCH 1/2 to fix compiler warnings in utils/mount/parse_dev.c. The issue stemmed from the dev variable being passed as a const pointer to parsing functions that destructively modified the string. Heitbaum explained:

"dev is passed by nfs_parse_devname to nfs_parse_... as a copy of the device name, the parser destructively modifies dev, so pass as non const so that it can be modified without warning."

This week, NFS maintainer Steve Dickson closed the loop with a brief confirmation:

"Committed... (tag: nfs-utils-2-8-6-rc2)" bed68038-34eb-4b08-92d0-06c2a1f817fa@redhat.com

Technical Details

The patch modifies utils/mount/parse_dev.c (6 lines changed: 3 additions, 3 deletions), removing the const qualifier from pointer targets in functions such as nfs_parse_simple_hostname and nfs_parse_square_bracket. This aligns the type signatures with the actual behavior of these parsers, which modify the string in-place using operations like strchr. The fix silences -Wdiscarded-qualifiers warnings without altering any runtime logic.

Conclusion

The fix has been merged into the nfs-utils tree and is tagged for release in nfs-utils-2.8.6-rc2. This maintenance patch ensures clean compilation under stricter warning flags, contributing to the overall code quality of the NFS client userspace utilities.
