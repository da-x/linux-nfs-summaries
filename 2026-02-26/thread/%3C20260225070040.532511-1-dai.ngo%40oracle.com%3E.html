NFSD: Per-Network Namespace Callback Operations for Container Isolation

Summary

Overview

This thread contains a single patch submission from Dai Ngo of Oracle, proposing a change to the NFS server (NFSD) subsystem to improve container isolation. The patch moves accumulated callback operations tracking from a global scope to a per-network-namespace basis.

Technical Details

Type: Bug fix / Container support improvement

Patch: [PATCH 1/1] NFSD: move accumulated callback ops to per-net namespace](https://lore.kernel.org/linux-nfs/20260225070040.532511-1-dai.ngo@oracle.com/)

Dai Ngo submitted a patch addressing an isolation issue in the NFSD subsystem when running inside containers. The core problem is that accumulated callback operations were being tracked globally rather than per network namespace. This global tracking can lead to incorrect behavior when multiple NFS servers run in separate containers, each with their own network namespace.

As stated in the commit message:

"Track accumulated callback operations on a per-network-namespace basis instead of globally, ensuring proper isolation and behavior when running nfsd in containers."

The patch modifies four files:

  • fs/nfsd/netns.h – Adds 4 lines (likely new per-namespace state structures)
  • fs/nfsd/nfs4callback.c – 75 lines changed (major refactoring of callback operation tracking)
  • fs/nfsd/nfsctl.c – Adds 4 lines (likely initialization/cleanup for per-namespace data)
  • fs/nfsd/state.h – Adds 2 lines (state structure updates)

The net result is 50 insertions and 35 deletions, indicating a moderate refactoring effort.

Context and Significance

This change is part of the ongoing effort to improve NFSD's compatibility with containerized environments. Proper network namespace isolation is critical for running NFS servers in containers, as it ensures that callback operations (used by the NFS server to communicate with clients) are correctly scoped to each container instance.

The thread ordering notes from the summary system indicate this topic has been under development: "callback ops per-net (v1→v5 sequentially)," suggesting this may be a later iteration of the patch series, though only this single submission appeared in the current week's window.

Current Status

As of the end of this reporting period (2026-02-26), there have been no replies or reviews to this patch submission. The discussion is in its initial stage, awaiting feedback from NFSD maintainers and the community.

Key Participants

Conclusion

This patch represents a targeted fix to improve NFSD's behavior in containerized environments by ensuring callback operation statistics are properly isolated per network namespace. With no reviews yet, the technical merit of the approach remains to be validated by the community.
