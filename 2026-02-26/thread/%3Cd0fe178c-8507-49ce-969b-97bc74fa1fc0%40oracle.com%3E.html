LTP inotify04 Test Fails Due to NFSv4 Delegation Regression in v6.19

Summary

LTP inotify04 Test Failure Due to NFSv4 Delegation Regression

Overview

This thread captures a bug report filed by Dai Ngo from Oracle, identifying a regression in kernel v6.19 that causes the LTP inotify04 test to fail when unlinking NFSv4 files with active delegations. This is a bug fix discussion concerning NFS client development and filesystem notification semantics.

The Bug Report

On 2026-02-20, Dai Ngo reported that commit bd4928ec799b3 ("NFS: Avoid changing nlink when file removes and attribute updates race") introduced a regression affecting inotify notifications during file removal on NFSv4 mounts.

"After commit bd4928ec799b3, unlinking an NFSv4 file that has a delegation can leave inode->i_nlink incorrectly unchanged (stays 1). As a result, dentry_unlink_inode() may skip fsnotify_inoderemove(), and FS_DELETE_SELF is not delivered."

Technical Analysis

Dai Ngo provided a detailed breakdown of the failure sequence:

  1. vfs_unlink() is called on an NFS inode holding an NFSv4 delegation
  2. The delegation return triggers an attribute refresh that advances the inode's attribute generation counter (nfsi->attr_gencount)
  3. When nfs_drop_nlink() later executes as part of the unlink path, it uses an older gencount value
  4. Due to the gencount mismatch, nfs_drop_nlink() skips calling drop_nlink()
  5. With inode->i_nlink remaining at 1, dentry_unlink_inode() skips fsnotify_inoderemove(), suppressing the FS_DELETE_SELF notification

The root cause is a race condition between:

  • The attribute generation counter update during delegation return (via nfs4_delegreturn_release())
  • The gencount check in nfs_drop_nlink() that was introduced to prevent races with inflight RPCs

Significance

This bug affects the reliability of filesystem notifications for NFSv4 clients. Applications relying on inotify to detect file deletions (such as build systems, file watchers, or security monitoring tools) may miss deletion events when files are removed while holding delegations.

Status

As of this week's window, only the initial bug report has been posted. No responses or patches have appeared in the thread yet.

Note: In subsequent weeks (outside this summary's scope), Roberto Bergantinos Corpas from Red Hat submitted a patch to address this issue by reordering gencount capture relative to delegation returns in the NFSv4 remove path, with review and feedback from Trond Myklebust.
