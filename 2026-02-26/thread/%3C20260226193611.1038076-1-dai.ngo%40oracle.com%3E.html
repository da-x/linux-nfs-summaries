NFSD Per-Net Callback Ops: v5 Restores Original Commit Message After Maintainer Critique

Overview

This thread captures the fifth and likely final iteration of Dai Ngo's (Oracle) patch to move accumulated NFSv4 callback operations from global statics into struct nfsd_net, giving each network namespace its own callback counters and RPC program definition. The change is a bug fix / container-isolation improvement for the NFS server (NFSD) subsystem — it ensures that when multiple NFS servers run in separate containers, their callback statistics are properly isolated rather than shared globally.

This Week's Activity

On February 26, Dai Ngo submitted PATCH v5 1/1, which carries the following changelog:

"v2: . free memory allocated for nn->nfsd_cb_version4.counts in nfsd_net_cb_stats_init() on error in nfsd_net_init(). v3: . reword commit message. . fix initialization of nn->nfsd_cb_program.nrvers. v4: . fix merge conflict in nfsd_net_exit in nfsd-testing branch. v5: . restore commit message to the original in v1"

The patch modifies four files in the NFSD subsystem:

  • fs/nfsd/netns.h (+5 lines): Adds per-namespace callback state structures.
  • fs/nfsd/nfs4callback.c (75 lines changed): Core refactoring of callback operation tracking.
  • fs/nfsd/nfsctl.c (+5 lines): Initialization/cleanup for per-namespace data.
  • fs/nfsd/state.h (+2 lines): State structure updates.

Net result: 52 insertions, 35 deletions — a moderate but impactful refactoring.

The v5 change is purely cosmetic: it restores the original commit message from v1, which had been reworded (and degraded) in v3. The substantive technical work — moving callback RPC program, version, and stats structures into struct nfsd_net for proper container isolation — was already completed by v3 after Jeff Layton's review caught a memory safety bug.

Bridge to Prior Context

The v5 resubmission follows an unusually rapid same-day iteration cycle on February 25 (v1 through v4), as documented in the prior week's summary of the v4 thread:

  • v1 (Feb 25, 07:00 UTC): Initial proposal with the rationale: "Track accumulated callback operations on a per-network-namespace basis instead of globally, ensuring proper isolation and behavior when running nfsd in containers."
  • v2 (Feb 25, 10:33 UTC): Added error-path memory free; introduced the nrvers bug.
  • v3 (Feb 25, 17:26 UTC): Fixed the nrvers initialization and reworded the commit message.
  • v4 (Feb 25, 19:50 UTC): Fixed a merge conflict in nfsd_net_exit() against the nfsd-testing branch.

Jeff Layton's critical review of v2 had identified a severe memory safety issue:

"sizeof(struct rpc_version *) is 8 on 64-bit, making nrvers 16 here while the nfsd_cb_versions array only has 2 elements. The version bounds check in rpc_new_client() compares args->version against program->nrvers, and rpc_proc_show() iterates from 0 to nrvers - 1 accessing program->version[i]."

Dai acknowledged promptly: "Yes, it's a bug. Fix in v3."

The immediate trigger for v5 was NFSD maintainer Chuck Lever's pointed critique of the v4 commit message:

"The new patch description is rather inferior to the original. Most importantly, it doesn't explain why this change is necessary, but instead simply repeats the content of the diff."

Dai Ngo responded by restoring the original v1 commit message in v5 — a direct and pragmatic fix to Chuck's concern.

Broader Context: NFSD Containerization Effort

This patch is part of a broader initiative to make NFSD fully compatible with containerized environments. Earlier in the week, Neil Brown had advised on related statistics export work:

"So I change my comment to: please don't do that. I don't think it is appropriate to export global statistics. We should only export per-net-namespace statistics. So place convert the statistics collect to per-net-namespace, then export them."

This patch directly implements Neil's recommendation by converting callback statistics collection to a per-net-namespace basis — a prerequisite for any future statistics export via netlink or other interfaces.
