sunrpc: Cache Infrastructure Scalability Improvements and Bug Fix

Summary

sunrpc: Cache Infrastructure Scalability Improvements and Bug Fix

Jeff Layton submitted a four-patch series, version 2, aimed at improving the scalability of the Sun RPC cache infrastructure. The series targets contention issues in the NFS client/server caching mechanisms by replacing global synchronization primitives with per-cache-detail equivalents and refactoring the internal data structures. Additionally, it addresses a memory leak bug identified during the review of the previous version.

Key Technical Arguments and Evolution

Bug Fix: Cache Request Leak

The first patch in the series addresses a pre-existing bug reported by NeilBrown. The issue involved a cache_request leak when a reader's file descriptor was closed while actively reading a request (i.e., rp->offset != 0).

"When a reader's file descriptor is closed while in the middle of reading a cache_request... cache_release() decrements the request's readers count but never checks whether it should free the request." As detailed by Jeff Layton

The fix adds cleanup logic to cache_release() mirroring that in cache_read(): if the reader count drops to zero and the CACHE_PENDING flag is clear, the request is dequeued and freed. This prevents memory leaks in scenarios where cache_dequeue() had previously skipped the request because the pending transition occurred while readers were still active.

Scalability Improvements: Per-Cache-Detail Locking

Patches 2 and 3 convert global synchronization primitives to per-cache-detail instances:

  1. Spinlock Conversion: The global queue_lock was serializing upcall queue operations across all cache_detail instances (e.g., auth.unix.ip vs. nfsd.fh). Converting this to a per-cache-detail spinlock eliminates unnecessary contention between unrelated caches.
  2. Waitqueue Conversion: Similarly, the global queue_wait waitqueue meant that a wake-up for one cache_detail would unnecessarily wake pollers on all caches. Moving this to a per-cache-detail field ensures only relevant pollers are woken.

Data Structure Refactoring

The final patch splits the single interleaved cache_detail->queue into two dedicated lists: cd->requests for upcall requests and cd->readers for open file handles.

"This eliminates the cache_queue wrapper struct entirely, simplifies the reader-skipping loops in cache_read/cache_poll/cache_ioctl/cache_release, and makes the data flow easier to reason about." As stated by Jeff Layton

Readers now track their position using a monotonically increasing sequence number (next_seqno) rather than their position in a shared list. Layton noted that this change "may help with implementing netlink upcalls," suggesting future-proofing for newer communication mechanisms.

Final Conclusions

Chuck Lever applied the entire v2 series to the nfsd-testing tree, replacing the previous version.

"Applied to nfsd-testing, replacing v1. Thanks!" Confirmed by Chuck Lever

The series is targeted for inclusion in kernel v7.1, providing both immediate stability improvements via the leak fix and long-term scalability benefits through reduced lock contention and cleaner data structures.
