NFS: Avoid False OOO Tagging in nfs_setattr()

Summary

NFS Client Bug Fix: Avoiding False Out-of-Order Write Tagging in nfs_setattr()

Classification

Bug fix targeting NFS client performance during attribute-setting operations.

Overview

Michael Stoler of Vast Data submitted a patch addressing a performance regression observed when extracting archives via untar over NFS. The issue stems from false out-of-order (OOO) write tagging, which causes valid page cache entries to be dropped unnecessarily on subsequent file opens.

Technical Details

The Problem

As described by Stoler in his initial patch submission:

"I’m seeing a performance issue with an NFS driver based on Linux 6.6. When untar extracts an archive, it sets file attributes and timestamps after each file is created. As a result, the inodes of these files are marked as OOO (out-of-order write), which causes valid page cache to be dropped on subsequent opens."

The root cause lies in nfs_setattr(), where inode attributes are updated twice:

  1. First, in the protocol-version-specific method (nfs*_proc_setattr()), which calls nfs_update_inode().
  2. Second, in nfs_setattr() itself via nfs_refresh_inode().

Because the inode state has already been updated by the first call, nfs_refresh_inode() falsely interprets the second update as an out-of-order operation and marks the inode with an OOO range:

"As a result, nfs_refresh_inode() falsely detects the second attempt to apply the same file attributes as an out-of-order operation and marks the inode with an OOO range."

The Proposed Fix

Stoler's patch modifies five files (fs/nfs/inode.c, fs/nfs/nfs3proc.c, fs/nfs/nfs4proc.c, fs/nfs/proc.c, and include/linux/nfs_fs.h) to eliminate the redundant inode attribute update in nfs_refresh_inode() when the inode has already been updated.

Discussion Evolution

Anna Schumaker's Review

NFS maintainer Anna Schumaker responded the following day with two key points:

  1. Kernel version concern: She noted that the patch was based on Linux 6.6, which dates to late 2023:

    "Linux 6.6 was from late 2023. Have you checked if this problem is still there on a more recent upstream Linux kernel?"

  2. Code changes since 6.6: She pointed out that the relevant code area has evolved significantly:

    "The code in this area has changed in the last 6 months and does an extra ATTR_SIZE check in this if statement that you're removing."

Schumaker requested that Stoler rebase his patch against current upstream and resubmit, indicating that the fix may need adjustment given recent changes to the ATTR_SIZE handling logic.

Status

The thread remains open pending a rebased submission from Michael Stoler. No final conclusions have been reached this week. The discussion highlights an important NFS client-side performance issue related to page cache invalidation due to false OOO tagging — a concern particularly relevant for workloads involving bulk file operations such as archive extraction.

Key Takeaway

This bug fix targets a subtle but impactful performance issue in the NFS client where redundant attribute updates during setattr operations trigger false out-of-order write detection, leading to unnecessary page cache drops. The maintainer's feedback underscores the importance of validating patches against current upstream code, especially when significant changes have occurred in the affected subsystem.
