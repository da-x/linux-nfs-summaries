NFS Client: Fixing Unused Variable Warnings via no_printk()

Summary

NFS Client: Addressing Unused Variable Warnings in Debug Code

This week, Sean Chang submitted a patch series aimed at resolving compiler warnings encountered during RISC-V kernel builds. The series contained two patches; the first addressed unused variable warnings in the NFS client subsystem, while the second targeted a format-truncation warning in the MACB ethernet driver. This summary focuses on the NFS-related discussion, which evolved from a simple workaround to a more robust architectural fix for debug macros.

Initial Proposal: __maybe_unused Workaround

Sean Chang initially proposed adding the __maybe_unused attribute to variables that were only used within dprintk() calls in the NFS client code (fs/nfs/nfs4proc.c, fs/nfs/flexfilelayout/flexfilelayout.c, and fs/nfs/flexfilelayout/flexfilelayoutdev.c). The issue arises because when CONFIG_SUNRPC_DEBUG is disabled, the dprintk() macro expands to an empty do-while loop, leaving the variables unused from the compiler's perspective.

As Sean explained:

"When CONFIG_SUNRPC_DEBUG is disabled, the dprintk() macro expands to an empty do-while loop. This causes variables used solely within dprintk() calls to appear unused to the compiler, triggering -Wunused-variable warnings."

Review: Criticism of Code Style

Andrew Lunn reviewed the NFS patch and expressed strong dissatisfaction with the proposed solution, citing code aesthetics and maintainability.

Andrew Lunn stated:

"Sorry, but this is ugly. There must be a better way to fix this. Maybe look at no_printk()."

He suggested using the no_printk() mechanism, which allows the compiler to perform type checking on arguments without generating code or triggering unused variable warnings, pointing to an example in the framebuffer driver.

Resolution: Adopting no_printk()

Sean Chang accepted Andrew Lunn’s feedback and proposed a more elegant solution. Instead of annotating every affected variable with __maybe_unused, he suggested modifying the debug macros in include/linux/sunrpc/debug.h to use no_printk() when debugging is disabled. This approach silences the warnings at the source while preserving type safety.

Sean Chang concluded:

"You are absolutely right, adding __maybe_unused to every variable is indeed ugly and repetitive. I investigated the suggestion of using no_printk(). It provides the same dummy-function behavior while allowing the compiler to perform type checking on the arguments. This effectively silences the -Wunused-variable warnings without generating any machine code."

Conclusion

The discussion highlights a shift from a localized, repetitive fix to a systemic improvement in how the NFS client handles debug macros. The proposed change to use no_printk() in include/linux/sunrpc/debug.h represents a cleaner, more maintainable solution for suppressing compiler warnings in non-debug builds. This bug fix ensures that the NFS client code compiles cleanly across various architectures, including RISC-V, ARM, and ARM64, without compromising code quality or type safety.
