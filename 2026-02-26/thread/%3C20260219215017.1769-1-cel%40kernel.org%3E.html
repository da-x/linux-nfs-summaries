NFSD UAF Fix Validated: Deferred Cleanup and Net Reference for Proc FDs

Summary

NFSD UAF Fix: Deferred Cleanup and Net Reference Held for Proc FDs

Classification: Critical Bug Fix (NFS Server / SUNRPC)

This week's activity on this thread concluded the review and validation cycle for Chuck Lever's two-patch series addressing use-after-free (UAF) vulnerabilities in the NFS server (nfsd) subsystem. The patches, originally submitted last week 2026-02-19/thread/..., received reviews from Jeff Layton and NeilBrown, and crucially, real-world testing confirmation from Olga Kornievskaia on PowerPC hardware — the platform where the crashes were originally reported.

Recap: The Bug

Last week, Misbah Anjum N reported 100% reproducible kernel panics on ppc64le systems when diagnostic tools (e.g., sosreport) read /proc/fs/nfsd/* files. Chuck Lever identified the root cause as a class of UAF bugs introduced by optimizations that removed explicit cache reference counting under the assumption that RCU protection was sufficient. Two distinct races were identified:

  1. Sub-object cleanup race: svc_export_put() freed sub-objects (paths, auth domains) before the RCU grace period expired, while readers in e_show() and c_show() still accessed them.
  2. Network namespace lifetime race: /proc/fs/nfs/exports file descriptors could outlive their originating network namespace, leading to cache destruction while reads were in progress.

Technical Summary of the Fixes

Patch 1/2: Defer Sub-Object Cleanup in Export Put Callbacks

The core fix replaces call_rcu/kfree_rcu with queue_rcu_work(), which defers cleanup until after the RCU grace period and executes it in process context where sleeping operations (path_put(), auth_domain_put()) are permitted. This ensures all RCU readers have completed before sub-objects are freed.

Patch 2/2: Hold Net Reference for Lifetime of /proc/fs/nfs/exports fd

The second fix holds a reference on struct net for the lifetime of an open file descriptor to /proc/fs/nfs/exports. This prevents nfsd_net_exit() from freeing the cache while reads are in progress, even if the originating network namespace is torn down (e.g., during container destruction).

Conclusions

This thread represents a successful resolution of a critical NFS server stability issue:

  1. The bug was severe and reproducible: Kernel panics occurred 100% of the time on ppc64le when diagnostic tools accessed /proc/fs/nfsd/*.
  2. The fix is architecturally sound: By using queue_rcu_work() for deferred cleanup and tying net lifetime to fd lifetime, the patches address the root cause rather than applying workarounds.
  3. Community validation was thorough: Reviews from Jeff Layton and NeilBrown, combined with Olga Kornievskaia's real-world testing on the affected platform, provide strong confidence in the correctness of the fix.
  4. The patches are ready for merge: With two Reviewed-by tags and a Tested-by tag from the reporter's platform, this series is well-positioned for inclusion in the mainline kernel.

This fix highlights the importance of careful reference counting in RCU-protected data structures and demonstrates the value of cross-platform testing in the Linux kernel development process.
