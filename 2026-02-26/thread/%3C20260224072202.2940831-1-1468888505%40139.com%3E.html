pNFS: Fix deadlock when returning delegation during open()

Summary

pNFS: Fix a Deadlock When Returning a Delegation During open()

Overview

This week, the Linux NFS mailing list received a backport patch addressing a critical deadlock in the Parallel NFS (pNFS) client code. The issue, originally identified by Benjamin Coddington and resolved by Trond Myklebust, involves a circular dependency between delegation returns and layout returns during file open operations.

The Bug: A Deadlock in pNFS Delegation Handling

The discussion centers on a hang reported by Benjamin Coddington (bcodding@hammerspace.com), manifested as a kernel stack trace showing the system stuck in pnfs_roc() while attempting to return a delegation during an open() operation.

The problematic call chain was:

nfs4_file_open -> nfs4_atomic_open -> _nfs4_do_open -> ... 
-> nfs_inode_set_delegation -> nfs_do_return_delegation 
-> nfs4_proc_delegreturn -> _nfs4_proc_delegreturn -> pnfs_roc [HANG]

As explained in the patch description:

"The issue is that the delegreturn is being asked to wait for a layout return that cannot complete because a state recovery was initiated. The state recovery cannot complete until the open() finishes processing the delegations it was given."

This creates a classic deadlock scenario:

  1. An open() operation receives a delegation from the server.
  2. To process this new delegation, the client must return any existing delegation via nfs_do_return_delegation.
  3. The delegation return path calls pnfs_roc() (Return On Close), which attempts to wait for outstanding layout returns to complete.
  4. However, a state recovery is in progress, blocking the layout return.
  5. The state recovery itself cannot complete until the open() finishes processing its delegations — but the open() is blocked waiting on the delegation return, which is blocked on the layout return.

The Fix

Trond Myklebust's solution, originally committed upstream as 857bf9056291a16785ae3be1d291026b2437fc48, propagates existing flags that indicate a non-blocking call context down to pnfs_roc(). This allows the function to recognize when it should not block, breaking the circular wait.

"The solution is to propagate the existing flags that indicate a non-blocking call to the function pnfs_roc(), so that it knows not to wait in this situation."

The patch modifies three files:

  • fs/nfs/nfs4proc.c: Adjusts how delegation return calls are made.
  • fs/nfs/pnfs.c: Refactors pnfs_roc() and related functions to accept and respect non-blocking flags.
  • fs/nfs/pnfs.h: Updates function signatures accordingly.

Backport Context

Li hongliang submitted this as a backport to the 6.6.y stable tree, noting:

"[ Upstream commit 857bf9056291a16785ae3be1d291026b2437fc48 ]"

"[ Minor conflict resolved. ]"

The original bug was introduced by commit 29ade5db1293 ("pNFS: Wait on outstanding layoutreturns to complete in pnfs_roc()"), which added the waiting behavior that ultimately caused the deadlock under certain conditions.

Significance

This fix is important for NFS client stability, particularly in environments using pNFS where delegation and layout management are active. Deadlocks in the NFS client can lead to hung processes or even system-wide hangs if critical filesystem operations are blocked. The fix ensures that delegation returns during open operations do not inadvertently block on layout returns when state recovery is in progress, maintaining forward progress in the NFS client state machine.
