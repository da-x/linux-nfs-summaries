NFS Week 2026-02-26: Critical heap overflow fix in nfsd, multiple client deadlocks resolved, SUNRPC cache scalability improvements, and massive VFS inode widening series

Week ending 2026-02-26

NFS Mailing List Overview — Week Ending 2026-02-26

This week saw an unusually high volume of critical bug fixes for both the NFS client and server, alongside major architectural refactoring in the VFS and SUNRPC layers that directly impact NFS. Highlights include a security-critical heap overflow fix in the NFSv4.0 LOCK replay cache, three deadlock fixes backported to stable kernels, and a sweeping 61-patch series to widen inode->i_ino to 64 bits — eliminating decades-old inode truncation hacks in the NFS client.

Critical Bugs and Security Fixes

nfsd: Heap Overflow in NFSv4.0 LOCK Replay Cache

Jeff Layton identified and fixed a slab-out-of-bounds write vulnerability in the NFS server's replay cache for NFSv4.0 LOCK operations. The 112-byte inline buffer (NFSD4_REPLAY_ISIZE) was undersized for denied LOCK responses containing large lock owner strings (up to 1024 bytes), allowing a remote attacker to corrupt adjacent heap memory using two cooperating clients. The fix adds bounds checking before copying into the replay buffer, skipping the payload if too large while still caching the status code. This patch was applied to nfsd-testing and recommended for all stable kernels.

Chuck Lever followed up with a companion patch to restore full protocol compliance via dynamic allocation for oversized responses, preventing malformed XDR replies on retransmitted LOCK operations. See: thread/%3C20260224-v4-0-lock-overflow-v1-1-22beeaf5cf6b%40kernel.org%3E.md and thread/%3C20260224193354.57849-1-cel%40kernel.org%3E.md.

Regression: nfsd_permission() Breaks File Locking (-ENOLCK)

Tj reported a production regression in the NFS server where a recent refactoring of NFSD_MAY_LOCK removed critical permission checks from nfsd_permission(), causing all file locking operations (flock()/fcntl()) to fail with -ENOLCK for NFSv3 clients. The issue was discovered on the Debian openQA infrastructure and affected both NFSv3 and NFSv4 paths through the shared nfsd_access() function. See: thread/%3Cc0f15088-3fc0-487a-9f24-cf89c158420d%40proton.me%3E.md.

NFS Client Deadlock Fixes (Stable Backports)

Three critical deadlock fixes were submitted for the 6.6.y stable tree this week, all authored by Trond Myklebust and submitted by Li hongliang:

  1. Deadlock in nfs_release_folio() during state recovery: Memory reclaim via kthreadd could block on NFSv4.1 state recovery, which itself was blocked waiting for memory. The fix introduces asynchronous folio release to break the circular dependency. See: thread/%3C20260224070237.2933965-1-1468888505%40139.com%3E.md.

  2. pNFS deadlock when returning delegation during open(): A delegation return during file open could hang waiting for layout returns blocked by concurrent state recovery. The fix propagates non-blocking flags down to pnfs_roc(). See: thread/%3C20260224072202.2940831-1-1468888505%40139.com%3E.md.

  3. Unsafe folio length access in trace events: NFS trace events calling nfs_folio_length() without proper locking could crash under xfstest workloads. The fix follows the XFS model of passing explicit offset/count parameters to tracepoints. See: thread/%3C20260224070058.2933695-1-1468888505%40139.com%3E.md.

NFS Client Development

xprtrdma: Fix Receive Queue Drain Hang

Eric Badger (Pure Storage) fixed a kernel hang in the RPC-over-RDMA client where rpcrdma_xprt_drain() could block indefinitely under memory pressure. When rpcrdma_post_recvs() exited early due to allocation failure, the re_receiving counter was not decremented, preventing drain completion. Chuck Lever reviewed and approved the fix. See: thread/%3C20260223182858.1158739-1-ebadger%40purestorage.com%3E.md.

Suppress Misleading "Server wrote zero bytes" Error in pNFS

Olga Kornievskaia submitted a fix to eliminate a false-positive error message logged during legitimate pNFS-to-MDS fallback. When a pNFS data server write fails and the client retries against the MDS, the original page structure is cleared, causing nfs_writeback_result() to log "Server wrote zero bytes" despite no actual failure. Trond Myklebust suggested a more generic guard (!list_empty(hdr->pages)) that was accepted. See: thread/%3C20260220214218.78581-1-okorniev%40redhat.com%3E.md and thread/%3C20260219192327.34732-1-okorniev%40redhat.com%3E.md.

Avoid False Out-of-Order Write Tagging in nfs_setattr()

Michael Stoler (Vast Data) reported a performance regression where archive extraction via untar over NFS caused unnecessary page cache drops due to false OOO (out-of-order write) tagging during redundant attribute updates in nfs_setattr(). Anna Schumaker requested a rebase against current upstream, as the relevant code has evolved since the 6.6 base. See: thread/%3C20260222134019.21516-1-michael.stoler%40vastdata.com%3E.md.

RFC: Protect File Lock List Traversal with nfsi->rwsem

Yang Erkun (Huawei) submitted an RFC addressing a long-standing use-after-free hazard in NFS client file-lock list traversal. The proposal switches protection from flc_lock to the inode-level nfsi->rwsem, aligning delegation claim and lock-done paths with the existing reclaim discipline. See: thread/%3C20260226012203.3962997-1-yangerkun%40huawei.com%3E.md.

Major Architectural Changes

vfs: Widen inode->i_ino from unsigned long to u64 (61-patch series)

Jeff Layton posted a massive 61-patch series touching 195 files to widen the VFS inode number field to 64 bits universally. For NFS, this eliminates:

  • The XOR-folding hack in nfs_compat_user_ino64() for 32-bit userspace
  • The enable_ino64 module parameter
  • Helper functions nfs_fattr_to_ino_t() and nfs_fileid_to_ino_t()

The VFS stat path now handles narrowing to 32-bit st_ino with -EOVERFLOW natively. The series received rapid positive reviews from filesystem maintainers, with minor feedback on trace event field ordering and format string consistency. See: thread/%3C20260226-iino-u64-v1-0-ccceff366db9%40kernel.org%3E.md.

SUNRPC Cache Infrastructure Scalability Improvements

Jeff Layton submitted a v2 four-patch series converting global SUNRPC cache synchronization primitives to per-cache-detail equivalents:

  • Global queue_lock spinlock → per-cache-detail lock
  • Global queue_wait waitqueue → per-cache-detail waitqueue
  • Single interleaved queue → separate request and reader lists with sequence-number tracking

The v2 also fixes a pre-existing memory leak in cache_release() identified by Neil Brown during v1 review. The series was applied to nfsd-testing, replacing v1. See: thread/%3C20260223-sunrpc-cache-v2-0-91fc827c4d33%40kernel.org%3E.md.

VFS Directory Locking Centralization (v3, 15-patch series)

Neil Brown submitted v3 of his directory locking refactoring series, consolidating all explicit directory locking into centralized start_creating()/start_removing() interfaces. This is a prerequisite for future per-name (rather than per-directory) locking. The NFS server's purge_old() function was converted to the new API. See: thread/%3C20260224222542.3458677-1-neilb%40ownmail.net%3E.md.

NFSD Server Development

Automatic NFSv4 State Revocation on Unmount — Pivot to fsnotify

Chuck Lever's v3 series for automatic state revocation on filesystem unmount faced pushback from VFS maintainers (Al Viro, Christian Brauner) regarding namespace isolation and ad-hoc notifier proliferation. The consensus shifted toward using existing fsnotify infrastructure with FS_UNMOUNT events on the export root inode rather than a new SRCU-based umount notifier chain. See: thread/%3C20260224163908.44060-1-cel%40kernel.org%3E.md.

NFSD Buffer Page Management Optimization (v2)

Chuck Lever posted v2 of his six-patch series to optimize NFSD buffer page handling for large NFSv4 COMPOUNDs. The series allocates a separate reply page array and tracks consumed entries to avoid full-array scans on every RPC. Neil Brown raised concerns about doubled memory overhead for NFSv3-only servers; Lever defended the trade-off as necessary for high-throughput NFSv4 performance. See: thread/%3C20260226144739.193129-1-cel%40kernel.org%3E.md.

Per-Namespace Callback Operations and Statistics

Dai Ngo (Oracle) iterated rapidly through four versions of a patch moving NFSD callback operations and statistics into struct nfsd_net for proper container isolation. Jeff Layton caught a critical nrvers initialization bug in v2 that would have caused out-of-bounds memory access. Chuck Lever requested commit message improvements. See: thread/%3C20260225182418.723304-1-dai.ngo%40oracle.com%3E.md.

Jeff Layton also submitted a standalone patch converting the global state_lock to a per-net deleg_lock, reducing delegation contention between containers. See: thread/%3C20260224-nfsd-deleg-lock-v1-1-1df17c1daa47%40kernel.org%3E.md.

Ongoing Debates

nfs4_acl Passthru for NFSv4 Reexport (RFC v2)

Mike Snitzer's RFC series to enable NFSv4 ACL passthrough during re-export faced strong architectural objections from Chuck Lever. Lever NACKed the addition of .setacl/.getacl operations to export_operations, arguing that raw byte pass-through creates technical debt and that NFSD should first implement proper native DACL/SACL support. Snitzer defended the design as necessary for his specific re-export use case where intermediate decoding is counterproductive. No consensus reached. See: thread/%3C20260224192438.25351-1-snitzer%40kernel.org%3E.md.

NFS 7.0 KConfig Bisect-ability Regression

Mike Snitzer reported that the CONFIG_NFS_V4_0 restructuring in Linux 7.0 breaks kernel bisect workflows: using a 7.0 .config against older kernels silently drops NFS v4.1/v4.2 support because the old CONFIG_NFS_V4_1 symbol no longer exists. See: thread/%3C20260212220625.358550-1-anna%40kernel.org%3E.md.

KCSAN Data Race in VFS atime Handling

The kernel test robot reported new data races between atime_needs_update and touch_atime introduced by a recent VFS refactoring commit. While not NFS-specific, the race affects all filesystems' atime update paths. See: thread/%3C202602262015.d00ee0c9-lkp%40intel.com%3E.md.
