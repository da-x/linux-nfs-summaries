Week ending 2026-02-05

NFS Client Bug Fixes and Semantics

This week's most significant NFS client activity centered on clarifying mount behavior, fixing a page cache performance regression, and revisiting a thorny locking race.

Mount Stacking Is Intended Behavior

A bug report from last week about NFS client mount option "regressions" was resolved this week. Li Lingfeng (Huawei) had observed that alternating ro/rw remounts produced stacked mount entries rather than replacing the existing mount. Diagnostics confirmed only two superblocks were created — one per option set — and the stacking is a VFS-level behavior, not an NFS bug. Trond Myklebust clarified that NFS correctly deduplicates superblocks by mount options but does not prevent mount point stacking, which differs from block filesystems like ext4. No code change warranted. (thread)

Unnecessary Page Cache Invalidation During setattr

Michael Stoler (VastData) reported a performance regression where untar operations caused valid page cache to be dropped due to false out-of-order (OOO) tagging in nfs_setattr(). The root cause: inode attributes are updated twice — once in the protocol-specific nfs*_proc_setattr() and again in nfs_refresh_inode() — causing the second update to falsely trigger OOO range marking. A fix eliminating the redundant refresh is proposed; Jeff Layton gave a positive initial review ("the patch looks sane overall") pending proper resubmission with Signed-off-by. (thread)

Lock/Unlock vs Open Race: Revised Approach After Deadlock Discovery

Li Lingfeng returned with a revised strategy for the long-standing use-after-free bug in NFS client file locking. The previously proposed rwsem-based fix was found to introduce a deadlock between unlock paths and the state manager. The new approach separates the local VFS lock update from the RPC completion path, using nfsi->rwsem more narrowly to protect against UAF without holding it across the full RPC wait cycle. No review feedback yet this week. (thread)

sysfs Memory Leak Fix Rejected — No Bug Found

Salah Triki submitted a patch to replace kfree() with kobject_put() in the NFS client's nfs_sysfs_init() error path. Trond Myklebust and Benjamin Coddington determined the existing code is correct: kset_register() already frees kobj->name on failure, and the kobject is not yet initialized at that point. The patch was withdrawn. (thread)

Containerized NFS Mounts Restored via FS_USERNS_DELEGATABLE

Jeff Layton's patch introducing the FS_USERNS_DELEGATABLE VFS flag — restoring NFS mount functionality inside containers using delegated mount daemons — was applied by Christian Brauner to the VFS tree. Anna Schumaker provided an Acked-by. A follow-up to apply the same flag to BPFFS is expected. (thread)

NFSD Server: Signed Filehandles, TCP Scalability, and Bug Fixes

Signed Filehandles v3: Endianness Bug Caught

Benjamin Coddington posted v3 of the kNFSD signed filehandle series, which appends a siphash MAC to NFS filehandles to prevent guessing attacks. The v3 series removed the controversial FH_AT_MAC flag per Chuck Lever's earlier concerns, relying solely on the server-side sign_fh export option. Eric Biggers caught an endianness bug in the MAC computation — the siphash u64 result is copied directly into a byte array without explicit endianness handling, which would break filehandles across architectures of different endianness. Coddington confirmed the issue and plans a v4 fix. (thread)

RFC: Reduce Lock Contention for NFSD TCP Sockets

Chuck Lever submitted a 7-patch RFC series addressing the ~300-400K IOPS ceiling observed on NFS servers. The redesign includes: (1) dedicated per-connection TCP receiver threads to eliminate socket lock contention, (2) flat combining for TCP sends to amortize xpt_mutex acquisition, (3) a lock-free page recycling pool, and (4) explicit TCP buffer sizing. This directly targets the xpt_mutex bottleneck identified in last week's profiling. No replies yet within this window. (thread)

nfsd_file Reference Leak Fix Applied

Dai Ngo fixed an nfs4_file reference count leak in the write delegation path where a race condition caused double-incrementing of the access counter, preventing nfsd_file objects from being freed and triggering a kmem_cache_destroy() BUG on server shutdown. Applied to nfsd-testing the same day. (thread)

pNFS Layout Recall Timeout v5

Dai Ngo posted v5 of the layout recall timeout and lease manager fencing patch, incorporating feedback from Chuck Lever and Jeff Layton on reference counting, retry counts (increased to 20), and worker cancellation. (thread)

VFS Refactoring Affecting NFS

Neil Brown's 13-patch series centralizing directory locking for name operations was posted, with nfsd impact limited to migrating purge_old() to use start_removing_noperm(). Jeff Layton provided Reviewed-by tags across the series; Amir Goldstein raised concerns about overlayfs lock reacquisition patterns. (thread)

nfs-utils 2.8.5 Released and Follow-Up Fixes

Steve Dickson announced nfs-utils 2.8.5, featuring the min-threads parameter for nfsdctl, systemd updates, and man page corrections. Jeff Layton followed up with a compatibility fix series so newer nfsdctl gracefully handles older kernels lacking min-threads support by querying netlink policy at startup. (release announcement, compatibility fix)
