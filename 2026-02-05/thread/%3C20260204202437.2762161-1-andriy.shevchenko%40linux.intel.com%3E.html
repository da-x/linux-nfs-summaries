sunrpc/NFS: Fix make W=1 build warnings in blocklayout and sunrpc debug infrastructure

Summary

sunrpc/NFS Blocklayout: Fix make W=1 Build Issues

Andy Shevchenko submitted a three-patch series addressing compiler warnings that surface when building with make W=1 (warnings-as-errors mode). The issues stem from unused variables — particularly in code paths where the debugging macro dprintk() is compiled out as a no-op. This is a bug fix series focused on build hygiene and cleanup rather than runtime behavior changes.

Patch 1/3: NFS Blocklayout Unused Variable Fix

The first patch targets the NFS block layout driver. Clang flagged an unused-but-set variable in bl_write_pagelist():

"Clang compiler is not happy about set but unused variable (when dprintk() is no-op): ... error: variable 'count' set but not used [-Werror,-Wunused-but-set-variable]" As described by Andy Shevchenko

The variable count was a leftover from a prior cleanup commit (3a6fd1f004fc, which removed read-modify-write handling in bl_write_pagelist). The fix simply removes the dead code. This patch received an Acked-by from Anna Schumaker and a Reviewed-by from Jeff Layton.

Patch 2/3: Kill the RPC_IFDEBUG() Macro

The second patch eliminates the RPC_IFDEBUG() macro, which was only used in two places across the codebase — once guarded by ifdeffery and once implied through dprintk() usage. Shevchenko's approach moves the conditional logic inline, simplifying the debug infrastructure:

"Kill the macro and move the ifdeffery to the regular condition with the variable defined inside, while in the second case add the same conditional and move the respective code there." As explained by Andy Shevchenko

This patch touches fs/nfsd/nfsfh.c, include/linux/sunrpc/debug.h, and net/sunrpc/xprtrdma/svc_rdma_transport.c. Jeff Layton provided a Reviewed-by tag.

Patch 3/3: Fix Unused Variables When dprintk() Is No-Op

The final patch addresses the root cause of several unused-variable warnings across multiple NFS and sunrpc files. When dprintk() is compiled as a no-op, variables assigned solely for debug printing become dead stores. Clang flagged three specific instances:

"Clang compiler is not happy about set but unused variables: ... flexfilelayoutdev.c:56:9: error: variable 'ret' set but not used ... flexfilelayout.c:1505:6: error: variable 'err' set but not used ... nfs4proc.c:9244:12: error: variable 'ptr' set but not used" As detailed by Andy Shevchenko

The fix forwards dprintk() parameters to no_printk(), which consumes them harmlessly. Shevchenko noted an additional benefit:

"The positive side-effect is a format-string checker enabled even for the cases when dprintk() is no-op." As noted by Andy Shevchenko

This patch received an Acked-by from Geert Uytterhoeven and a Reviewed-by from Jeff Layton. It fixes issues dating back to the initial FlexFile Layout Driver introduction (d67ae825a59d) and the create_session operation (fc931582c260).

Series Evolution

The series evolved through three versions:

  • v1: Initial submission with separate patches.
  • v2: Added the RPC_IFDEBUG() removal patch, unified separate patches, and collected tags from Geert Uytterhoeven.
  • v3: Removed ifdeffery to keep struct rpc_task::tk_pid available (per LKP feedback) and collected additional tags from Anna Schumaker and Jeff Layton.

"Applied to nfsd-testing, thanks!" As confirmed by Chuck Lever

  • 5ea3d8c52742 — nfs/blocklayout: Fix compilation error (make W=1) in bl_write_pagelist()
  • 69998e1a90d7 — sunrpc: Kill RPC_IFDEBUG()
  • d5a621346246 — sunrpc: Fix compilation error (make W=1) when dprintk() is no-op

Significance for NFS Client Development

While this series does not introduce new NFS protocol features or fix runtime bugs, it is important for maintaining build robustness. The make W=1 configuration is a critical gate for catching latent issues early. By cleaning up unused variables in the blocklayout driver and sunrpc debug infrastructure, this work ensures that future code changes won't be blocked by stale compiler warnings — particularly relevant as Clang's warning-as-error policies grow stricter. The format-string checker side-effect from patch 3/3 adds an extra layer of safety for debug logging across the NFS client and server codebase.
