statd: Typo Fix Committed (PATCH 10/10)

Summary

statd: Typo Fix in Debug Message (PATCH 10/10) — Committed

Overview

This thread covers the resolution of [PATCH 10/10] statd: fix a typo in a debug message, submitted by Seiichi Ikarashi of Fujitsu as part of a 10-patch series targeting typo corrections across the nfs-utils user-space tools suite. The patch is an editorial bug fix — specifically, a correction to a debug message string in C source code — rather than a new feature or protocol change.

Patch Details

The original patch was submitted on January 29, 2026 (prior week), modifying utils/statd/simulate.c with a single-line correction (1 insertion, 1 deletion). The patch carries the standard sign-off:

"Signed-off-by: Seiichi Ikarashi s.ikarashi@fujitsu.com"

This is the tenth and final patch in a cohesive series of typo fixes across nfs-utils. The preceding nine patches corrected typos in man pages for nfs.conf, mountstats, nfsiostat, rpcctl, exports, gssd, nfs, mountd, and nfsd. Patch 10/10 is notable as the only patch in the series that targets a runtime debug message string in C source code (simulate.c) rather than documentation files.

Maintainer Acknowledgment

On February 1, 2026, nfs-utils maintainer Steve Dickson confirmed the patch was accepted and merged:

"Committed... (tag: nfs-utils-2-8-5-rc3)" Steve Dickson

This acknowledgment, arriving in the current week's window, brings closure to the 10-patch typo-fix series. The patch is included in the nfs-utils-2-8-5-rc3 release candidate tag.

Relevance to NFS Client Development

This change is a minor editorial correction and does not introduce new features, protocol changes, or functional bug fixes affecting NFS client behavior. The statd daemon plays a role in NFSv4 lock recovery via the Network Lock Manager (NLM) protocol, but this modification only affects a debug message string — it has no impact on runtime functionality, network protocol handling, or client-server interoperability.
