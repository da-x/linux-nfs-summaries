overlayfs: SteamOS Testing Validates uuid=off, but Merge Deferred to 7.1

Summary

This week saw a single but consequential message in this long-running thread, as André Almeida returned from time off to report on his testing of Amir Goldstein's patch that extends the uuid=off mount option for cross-filesystem overlayfs setups — specifically targeting the SteamOS A/B partitioning use case. While initial tests were promising, a remaining issue with reboot scenarios led Almeida to recommend deferring the patch until kernel 7.1.

Background (Brief)

This thread originated from Almeida's rejected 3-patch series proposing to repurpose export_operations::get_uuid() for overlayfs origin file handles. Christoph Hellwig firmly opposed that approach, arguing it served pNFS block layout exclusively and should not be spread further. The discussion pivoted toward overlayfs's existing uuid=off mount option — originally created for Virtuozzo container disk copying — as a more pragmatic solution. Over the prior three weeks, Goldstein developed and tested a patch lifting uuid=off's same-filesystem restriction, clarified its semantics (it must be enabled from the first mount), and offered to queue it for kernel 7.0.

Key Technical Arguments This Week

André Almeida: Initial Success Followed by Reboot Failure

After returning from a week away, Almeida provided his long-awaited feedback on Goldstein's patch [id://05c37282-715e-4334-82e6-aea3241f15eb@igalia.com]:

"Our initial test case worked great! We managed to mount both images and use overlayfs without a problem after your clarification of where to use uuid=off, which should be on the first mount."

This confirmed that Goldstein's earlier clarification — that uuid=off must be declared from the very first mount rather than retroactively applied — resolved the initial confusion. However, Almeida then reported a remaining issue:

"However, when rebooting to the other partition, the mount failed with 'failed to verify upper root origin' again, but I believe that I forgot to add uuid=off somewhere in the mount scripts. I'm still debugging this."

The failure mode — "failed to verify upper root origin" — is the same error that originally motivated this entire discussion. Almeida suspected a configuration oversight in his mount scripts rather than a fundamental flaw in the patch, but had not yet completed debugging.

Decision to Defer Until 7.1

Given the proximity to the merge window and the incomplete testing, Almeida made a pragmatic call:

"Anyhow, I see that we are now too close to the merge window, and from my side we can delay this for 7.1 and merge it when it gets 100% clear that this is the solution that we are looking for."

This deferral acknowledges both the promise of the uuid=off approach and the need for more thorough validation before inclusion in the mainline kernel.

Evolution of the Discussion

The thread's trajectory over its full lifespan can be summarized as follows:

  • Weeks 1–2 (Jan 14–22): Almeida's original 3-patch series was rejected; discussion pivoted to uuid=off as an existing mechanism suited to the SteamOS use case. Goldstein identified and tested a patch lifting the same-filesystem restriction.
  • Week 3 (Jan 23–29): Almeida initially reported the patch did not work due to a UUID comparison mismatch in ovl_verify_fh(). Goldstein clarified that uuid=off must be enabled from the first mount, not retroactively applied, and provided documentation improvements. Goldstein followed up seeking confirmation to queue for 7.0.
  • Week 4 (Feb 5): Almeida returned with positive initial results but reported a remaining reboot-related issue. He recommended deferring the patch until 7.1 pending full validation.

Final Conclusions

  1. The uuid=off approach is validated in principle. Almeida confirmed that, after applying Goldstein's clarification about enabling uuid=off from the first mount, "Our initial test case worked great" [id://05c37282-715e-4334-82e6-aea3241f15eb@igalia.com]. This represents significant progress toward solving the SteamOS cloned-image problem.

  2. A reboot scenario remains untested. The "failed to verify upper root origin" error persists when switching between A/B partitions, though Almeida suspects a configuration issue rather than a patch bug [id://05c37282-715e-4334-82e6-aea3241f15eb@igalia.com].

  3. Merge deferred to kernel 7.1. With the merge window imminent and testing incomplete, Almeida recommended waiting until the solution is "100% clear" before inclusion [id://05c37282-715e-4334-82e6-aea3241f15eb@igalia.com].

  4. Stable backport remains a possibility. Goldstein previously indicated that the change "could be backported to stable kernels" but would not mark it for automatic selection, preferring manual backporting based on demand [id://CAOQ4uxhHFvYNAgES9wpM_C-7GvfwXC2xet1ensfeQOyPJRAuNQ@mail.gmail.com].

Classification

Type: Feature extension / Bug fix (overlayfs uuid=off support for cross-filesystem setups)

NFS Client Relevance: Indirect. While this is fundamentally an overlayfs discussion, it touches on file handle encoding semantics that are foundational to NFS exports and the exportfs subsystem. The original get_uuid() infrastructure served pNFS block layout, and Hellwig noted earlier that "encoding the uuid into the file handle in the kernel is the right thing for NFS as well."
