nfsdctl: Fix Compatibility with Older Kernels That Lack min-threads Support

Summary

This week, Jeff Layton submitted a three-patch series to nfs-utils addressing a compatibility bug that arose after the recent addition of min-threads support. The issue was reported by Benjamin Coddington, who encountered errors when running newer versions of nfsdctl against older kernels that do not yet support the min-threads netlink attribute.

Bridge from Prior Weeks

Last week (and earlier in this week's window), the community saw the successful merge of the original min-threads feature into nfs-utils 2.8.5-rc3. That feature allows administrators to configure a minimum NFS server thread count, enabling dynamic scaling between a configured minimum and maximum based on workload demand as summarized previously. However, this new capability introduced a backward-compatibility problem: older kernels reject the unknown min-threads netlink attribute with -EINVAL.

This Week's Activity

The Problem

On February 4, Jeff Layton submitted a three-patch series to resolve the compatibility issue. In his cover letter, he explained:

"Ben reported a problem with using new userland with old kernel. If he tried to send down a setting that the kernel doesn't support, it returns -EINVAL to the call."

The series introduces a mechanism for nfsdctl to query the kernel's netlink policy and determine which attributes are supported before attempting to use them.

Patch 1/3: Optimize Netlink Family Name Resolution

The first patch is a preparatory optimization. Layton noted that the existing code resolved string names to IDs for every netlink call, and this change resolves them once at startup:

"The current code resolves the string name to an id for every netlink call. Just resolve the family names once and keep them."

Patch 2/3: Query Netlink Policy Before Sending min-threads

The core fix addresses the compatibility bug directly. Layton explained the technical rationale:

"While netlink is an extensible format, genetlink (which we are using) will reject unknown attributes by default with -EINVAL."

He considered alternative approaches but ruled them out:

"We could fix this in the kernel by having it ignore unknown attributes, but there is no way to fix old kernels and silently ignoring it is less than ideal. By handling this in userland, we can properly error out when the kernel doesn't support this attribute."

The patch implements the following behavior:

  • At startup, nfsdctl queries the kernel for the "policy" of the threads operation to determine the highest supported attribute index.
  • For the explicit threads command, if --min-threads is passed but the kernel does not support it, the command fails with an error.
  • For autostart, a warning is logged and the setting is silently ignored.

The patch includes a Fixes: tag referencing the original commit that introduced the feature:

"Fixes: 00e2e62b8998 ("nfsdctl: add support for min-threads parameter")"

Patch 3/3: Cleanup of xlog() Format Strings

The final patch removes unnecessary newlines from xlog() format strings — a minor code-quality improvement.

Review and Testing

On February 5, Benjamin Coddington, who originally reported the bug, reviewed and tested all three patches:

"Thanks for these Jeff!

For all three:

Classification

This discussion centers on a bug fix in the NFS server user-space tooling (nfs-utils). Specifically, it resolves a backward-compatibility regression introduced by the recent min-threads feature, ensuring that newer versions of nfsdctl can operate correctly against older kernels that lack support for the new netlink attribute.

Significance for NFS Development

This fix is important for several reasons:

  1. User-space/kernel compatibility: It demonstrates a robust pattern for handling extensible netlink interfaces — querying kernel capabilities at runtime rather than assuming feature availability.
  2. Graceful degradation: The approach allows newer tools to work with older kernels by either erroring out (for explicit commands) or warning and continuing (for autostart scenarios).
  3. Continued maturation of dynamic threading: The min-threads feature, merged just last week, is already receiving follow-up fixes, underscoring the active development cycle around NFS server scalability improvements.

Conclusion

Jeff Layton's three-patch series successfully resolves the compatibility issue between newer nfsdctl versions and older kernels lacking min-threads support. The approach of querying netlink policy at startup provides a clean, extensible mechanism for feature detection. With Benjamin Coddington's review and testing confirmation, the patches are ready for integration into nfs-utils, ensuring that administrators can safely upgrade user-space tools without requiring immediate kernel upgrades.
