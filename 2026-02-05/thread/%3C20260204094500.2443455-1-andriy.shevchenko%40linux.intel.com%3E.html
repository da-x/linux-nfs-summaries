sunrpc: Fix make W=1 build issues — bug fix series applied with v3 respin

Summary

sunrpc: Fix make W=1 Build Issues — Bug Fix Series Applied (with v3 Respin)

Classification: Bug fix series targeting compiler warnings under make W=1 builds in the NFS client and SUNRPC subsystems.

Overview

Andy Shevchenko submitted a three-patch series (PATCH v2 0/3) to address make W=1 compilation errors caused by unused-but-set variables, particularly when the dprintk() debug macro is compiled as a no-op. The series touched both NFS client code (blocklayout) and core SUNRPC debugging infrastructure.

"Compiler is not happy about unused variables (especially when dprintk() call is defined as no-op). Here is the series to address the issues."

Patch Breakdown

Patch 1/3 — nfs/blocklayout: Fix compilation error in bl_write_pagelist()

This patch removes a leftover variable (count) from fs/nfs/blocklayout/blocklayout.c that was set but never used when dprintk() is compiled as a no-op, triggering the Clang error:

"variable 'count' set but not used [-Werror,-Wunused-but-set-variable]"

The issue traces back to commit 3a6fd1f004fc which removed read-modify-write handling in bl_write_pagelist but left behind this unused variable. NFS client maintainer Anna Schumaker provided an ack:

"Acked-by: Anna Schumaker anna.schumkaer@oracle.com"

Patch 2/3 — sunrpc: Kill RPC_IFDEBUG()

This patch removes the RPC_IFDEBUG() macro, which was used in only two places. The macro's functionality is replaced with explicit conditional guards around the relevant code blocks. This cleanup simplifies the debug infrastructure and eliminates a source of build warnings.

Patch 3/3 — sunrpc: Fix compilation error when dprintk() is no-op

This patch addresses unused-but-set variable errors in multiple NFS client files (flexfilelayoutdev.c, flexfilelayout.c, nfs4proc.c) by forwarding dprintk() parameters to no_printk(). As a bonus, this enables format-string checking even when debug printing is disabled:

"The positive side-effect is a format-string checker enabled even for the cases when dprintk() is no-op."

Discussion and Submission Path

Jeff Layton reviewed the series positively:

"These all look like good changes to me. The first patch should go to Trond/Anna and Chuck will probably pick up the other two?"

Chuck Lever concurred, noting:

"That's what I was thinking, as long as there aren't any dependencies between 1/3 and the others."

However, Andy Shevchenko argued for submitting all three patches through a single tree to avoid potential ordering issues:

"As I explained in v1, the error in the first patch may be shadowed if the third one (and hence second) is taken first. That's why I prefer them to go via single place."

Chuck Lever ultimately applied the entire series to nfsd-testing:

"Applied to nfsd-testing, thanks! Acks from the NFS client maintainers on 1/3 are welcome."

Post-Application Issue and v3 Respin

After initial application, Shevchenko discovered a remaining build issue — a missing tk_pid field due to conditional inclusion in struct rpc_task. He proposed an inline fix:

"I'm afraid this is not end of story... I received a dozen of minutes ago a new report and now I'm investigating."

Chuck Lever requested a full respin rather than folding the fix:

"Please send a full series respin, thanks."

Shevchenko confirmed that v3 had been sent by end of day.

Key Takeaways for NFS Client Development

  • The blocklayout driver (fs/nfs/blocklayout/) had a stale variable from a prior cleanup — a reminder to audit debug-code paths during refactoring.
  • The dprintk() / no_printk() infrastructure in SUNRPC needed hardening to suppress false-positive unused-variable warnings when debug output is disabled, affecting multiple NFS client components including flexfilelayout and NFSv4 session management code.
  • Format-string validation is now preserved even in non-debug builds thanks to the no_printk() forwarding approach — a subtle but valuable improvement for code quality.
