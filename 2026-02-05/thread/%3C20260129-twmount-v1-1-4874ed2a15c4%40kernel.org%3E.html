FS_USERNS_DELEGATABLE Applied; BPFFS Follow-Up Proposed

Summary

FS_USERNS_DELEGATABLE: Containerized NFS Mount Fix Applied, Follow-Up for BPFFS

Classification

Type: Bug fix (regression in containerized NFS mounting) with follow-up discussion about extending the new VFS mechanism to other filesystems.

Summary

This week's activity on this thread centers around the application of Jeff Layton's patch introducing FS_USERNS_DELEGATABLE, a new VFS filesystem flag that restores NFS mount functionality inside Linux containers using delegated mount daemons. The discussion also spawned a proposal to apply the same mechanism to BPFFS, with Christian Brauner requesting Alexander Mikhalitsyn to submit a formal patch.

Background (from prior week)

Last week, Jeff Layton submitted a single-patch series addressing a regression caused by commit e1c5ae59c0f2 ("fs: don't allow non-init s_user_ns for filesystems without FS_USERNS_MOUNT"). That VFS security hardening inadvertently broke NFS mounts in containerized environments that use a privileged mount daemon architecture — where a process inside a container calls fsopen() and passes the filesystem context to a vetted daemon in the init namespace via Unix socket.

As Jeff explained:

"This broke NFS mounts in our containerized environment. We have a daemon somewhat like systemd-mountfsd running in the init_ns. A process does a fsopen() inside the container and passes it to the daemon via unix socket." Jeff Layton

The fix introduces FS_USERNS_DELEGATABLE — a middle ground between FS_USERNS_MOUNT (fully unprivileged mounting, which would allow containers to mount arbitrary NFS servers) and no flag at all. This preserves the security boundary while restoring functionality for delegation-based architectures.

On February 3rd, VFS maintainer Christian Brauner confirmed the patch was applied:

"Applied to the vfs-7.0.misc branch of the vfs/vfs.git tree. Patches in the vfs-7.0.misc branch should appear in linux-next soon." Christian Brauner

Proposal to Extend to BPFFS

Alexander Mikhalitsyn drew a parallel to the BPF subsystem, noting that BPFFS uses a similar token-based delegation model:

"Great idea, very similar to what we have with BPFFS/BPF Tokens. Taking into account this patch, shouldn't we drop FS_USERNS_MOUNT and replace it with FS_USERNS_DELEGATABLE for bpffs too?" Alexander Mikhalitsyn

He proposed replacing FS_USERNS_MOUNT with FS_USERNS_DELEGATABLE for BPFFS, arguing it would have the same effect while using the more semantically appropriate flag.

Jeff Layton's Review and Christian Brauner's Request

Key Technical Arguments

  1. Security-preserving delegation model: The FS_USERNS_DELEGATABLE flag allows filesystems to be mounted from non-init user namespaces only when a privileged daemon acts on behalf of the container — preserving the security boundary that containers cannot independently mount arbitrary servers.

  2. Generic VFS mechanism: The new flag is filesystem-agnostic and could benefit other network or special-purpose filesystems with similar delegation requirements (e.g., BPFFS, potentially CIFS or 9P).

  3. Semantic improvement for BPFFS: Alexander's proposal suggests that FS_USERNS_DELEGATABLE is a more accurate description of BPFFS's security model than FS_USERNS_MOUNT, since BPFFS also relies on token-based delegation rather than truly unprivileged mounting.

Final Conclusions

  • The NFS fix has been applied to the VFS tree (branch vfs-7.0.misc) and will appear in linux-next.
  • Anna Schumaker provided an Acked-by, confirming NFS maintainer support.
  • A follow-up patch for BPFFS is expected from Alexander Mikhalitsyn, with Jeff Layton's Reviewed-by already on record.

Significance for NFS Client Development

This fix is critical for organizations deploying containerized workloads that rely on privileged mount daemons to perform NFS mounts. It restores functionality without compromising the VFS security hardening introduced in commit e1c5ae59c0f2. The new flag also establishes a reusable pattern for other filesystems requiring similar delegation semantics.
