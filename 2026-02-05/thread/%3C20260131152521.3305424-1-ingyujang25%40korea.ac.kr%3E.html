Question on Dead Error-Handling Code in rpcauth_wrap_req_encode()

Summary

Overview

This week, Ingyu Jang raised a code quality question about potential dead error-handling code in the NFS/RPC authentication layer. The thread remains open with no replies as of this summary's cutoff.

Technical Question: Dead Code in rpcauth_wrap_req_encode() Error Handling?

Ingyu Jang posted a question regarding what appears to be unreachable error-handling code in the RPC authentication subsystem.

The observation centers on rpcauth_wrap_req_encode() in net/sunrpc/auth.c, which always returns 0 unconditionally:

"I noticed that in net/sunrpc/auth.c, the function rpcauth_wrap_req_encode() always returns 0."

The function simply calls encode(task->tk_rqstp, xdr, task->tk_msg.rpc_argp) and then return 0, with no conditional error path.

However, multiple callers in net/sunrpc/auth_gss/auth_gss.c check the return value and implement error-handling branches:

  1. gss_wrap_req_integ() (line 1759):

    if (rpcauth_wrap_req_encode(task, xdr))
    goto wrap_failed;

  2. gss_wrap_req_priv() (line 1856):

    if (rpcauth_wrap_req_encode(task, xdr))
    goto wrap_failed;

  3. gss_wrap_req() (lines 1926 and 1931):

    status = rpcauth_wrap_req_encode(task, xdr);
// checked in switch statement

Jang posed the question:

"Since rpcauth_wrap_req_encode() never fails, these error paths appear to be dead code. Is this intentional defensive coding for potential future changes, or could this be cleaned up by making the function return void?"

Classification

This is a code cleanup / maintainability question, not a new feature, protocol change, or bug fix. It touches on NFS client development in the RPC authentication layer, specifically the GSS (Generic Security Services) authentication mechanism used for Kerberos-based NFS security.

Status

No replies were received during this week. The question remains open for discussion by maintainers and developers regarding whether the error-handling code should be retained as defensive programming or cleaned up.
