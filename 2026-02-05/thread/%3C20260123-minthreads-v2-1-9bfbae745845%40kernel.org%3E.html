nfsdctl min-threads Support Committed to nfs-utils

Summary

This week, the discussion around Jeff Layton's patch series to add dynamic threading support to nfsdctl concluded with the patch being merged into the mainline nfs-utils tree. Steve Dickson confirmed the commit in a brief message:

"Committed... (tag: nfs-utils-2-8-5-rc3)"

This marks the completion of a new feature that enables administrators to configure minimum NFS server thread counts, allowing the kernel's nfsd service to dynamically scale threads between a configured minimum and maximum based on workload demand.

Bridge from Prior Week

Last week (ending 2026-01-29), Jeff Layton submitted the revised v2 patch series PATCH nfs-utils v2 and engaged in a technical discussion with Mike Owen about the load-heuristic used for dynamic thread scaling. Key takeaways from that prior exchange:

  • The current kernel heuristic is simple: when an incoming RPC request arrives and no idle threads are available, a new thread is spawned (up to the configured maximum). Threads eligible to exit if idle for 5 seconds.
  • Jeff Layton noted room for future sophistication: "It would be nice to make this a bit more sophisticated. In particular, we probably don't want to start new threads when memory pressure is high (and maybe shut some down in that case too). We'd welcome some advice here (or even better, patches)."
  • Layton also pushed back on the common "one thread per CPU" sizing rule: "On a typical server, at busy times you probably want more threads than CPUs, simply because a lot of them end up blocked doing I/O."

This Week's Activity

The sole message this week was Steve Dickson's confirmation that the v2 patch series has been accepted and merged. The feature is now available in nfs-utils starting with release candidate nfs-utils-2-8-5-rc3.

Classification

This discussion centers on a new feature (not a bug fix or protocol change): user-space tooling support for the kernel's dynamic nfsd threading capability, introduced via the min-threads parameter in nfs.conf and the nfsdctl command-line interface.

Significance for NFS Server Administration

With this commit, NFS server administrators can now:

  • Set a minimum thread count via min-threads in nfs.conf, ensuring baseline capacity even under light loads.
  • Use the existing threads parameter as the maximum, allowing the kernel to scale dynamically between min and max.
  • Leave min-threads unset (defaulting to 0) to preserve traditional static threading behavior for backward compatibility.

The feature is conditionally compiled based on kernel header support (NFSD_A_SERVER_MIN_THREADS), ensuring graceful degradation on older kernels.

Conclusion

The min-threads feature has been successfully merged into nfs-utils, providing a practical user-space interface for the kernel's dynamic nfsd threading. While the current load heuristic is intentionally simple (RPC-driven), the community has expressed interest in future enhancements—particularly around memory-pressure-aware scaling. As Jeff Layton invited last week, contributions to refine the algorithm are welcome.
