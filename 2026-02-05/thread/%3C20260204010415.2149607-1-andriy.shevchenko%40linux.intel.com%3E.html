sunrpc: Fix dprintk() no-op compilation errors for W=1 builds

Summary

sunrpc: Fix compilation error (make W=1) when dprintk() is no-op

Type: Bug fix — compilation warning/error in the SUNRPC debug infrastructure affecting NFS client and server code.

Overview

Andy Shevchenko submitted a patch to address Clang compiler errors triggered by make W=1 builds when the dprintk() macro expands to a no-op. The core issue was that variables set only for use inside dprintk() calls were flagged as "set but not used" when debugging was disabled, since dprintk() was previously mapped to an empty statement rather than to no_printk().

The Problem

When RPC_DEBUG is disabled, the dprintk() macro in include/linux/sunrpc/debug.h was defined as a no-op that silently discarded its arguments. This meant that any variables assigned solely for formatting within dprintk() calls became unused from the compiler's perspective. Clang with -Werror,-Wunused-but-set-variable flagged three specific locations:

"variable 'ret' set but not used" — in flexfilelayoutdev.c:56 "variable 'err' set but not used" — in flexfilelayout.c:1505 "variable 'ptr' set but not used" — in nfs4proc.c:9244

As described by Andy Shevchenko, the fix forwards dprintk() parameters to no_printk(), which properly consumes them while still enabling format-string checking even when debugging is disabled.

Build Robot Feedback: A New Class of Errors

The kernel test robot (LKP) quickly identified a significant problem with v1. The change from an empty no-op to no_printk() exposed a pre-existing issue in fs/nfsd/nfsfh.c. That file uses RPC_IFDEBUG(char buf[...]) to conditionally declare a buffer — the variable only exists when debugging is enabled. When dprintk() was a true no-op, the arguments (including references to buf) were discarded at the preprocessor level. Once dprintk() forwarded to no_printk(), the compiler attempted to evaluate all arguments, and buf became an undeclared identifier:

"error: 'buf' undeclared (first use in this function)" — in fs/nfsd/nfsfh.c:110

This error was reported across multiple configurations: m68k-defconfig with GCC 15.2, x86_64-kexec with Clang 20.1.8, and x86_64-rhel-9.4 with GCC 14.2. Additionally, sparse analysis on powerpc exposed type-incompatibility warnings in several NFS client files (getroot.c, namespace.c, nfs4super.c, super.c, fs_context.c) where conditional expressions mixed void (from the no-op path) with int.

Community Response

Geert Uytterhoeven, who had attempted a similar fix years earlier, endorsed the approach in principle:

"Definitely. I tried something similar a few years ago, but ran into build errors from the robots, and gave up due to lack of time."

He provided an Acked-by tag for the principle and shared his own unsent local fix that addressed the same nfsfh.c issue — confirming this was a known obstacle. Andy acknowledged the feedback:

"For the matter of fact, I also get into errors from LKP (I compiled only part of this, need to enable more to cover these cases)."

Andy confirmed he would perform additional testing and fixes before resubmitting, noting that Geert's local fix addressed the same call site flagged by the robots.

Resolution

By end of day on February 4th, Andy Shevchenko announced that a v2 series had been submitted:

"v2 just has been sent. You Cc'ed only on patch 3, but it should be available in full here https://lore.kernel.org/r/20260204094500.2443455-1-andriy.shevchenko@linux.intel.com"

The v2 series (outside this thread's scope) was structured as a multi-patch set, with patch 3 specifically addressing the nfsfh.c issue flagged by the build robots. The v1 thread itself concluded without a final resolution within its own messages; the discussion effectively transitioned to the v2 submission.

Significance for NFS Client Development

This fix touches core SUNRPC debug infrastructure used extensively throughout the NFS client and server codebase. While primarily a build-system improvement, it has two important side effects:

  1. Format-string validation at all build levels: By routing dprintk() through no_printk() rather than discarding arguments entirely, format strings are validated even when debugging is disabled — catching potential bugs earlier.
  2. Clean W=1 builds for NFS code: The fix resolves compilation errors in key NFS client files including the FlexFile Layout Driver (flexfilelayoutdev.c, flexfilelayout.c) and NFSv4 procedure handling (nfs4proc.c), enabling stricter warning-level builds across the NFS subsystem.
