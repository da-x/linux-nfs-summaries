Unnecessary page cache invalidation due to false OOO tagging in nfs_setattr()

Summary

Unnecessary Page Cache Invalidation in NFS Client

Overview

This week saw the introduction of a bug report and proposed fix addressing unnecessary page cache invalidation in the Linux NFS client, specifically related to false "out-of-order" (OOO) tagging during attribute setting operations. This is a bug fix discussion focused on NFS client performance optimization.

Key Technical Problem

Michael Stoler from VastData reported a performance regression observed with an NFS driver based on Linux 6.6. The issue manifests when extracting archives via untar, which sets file attributes and timestamps after each file creation:

"I'm seeing a performance issue with an NFS driver based on Linux 6.6. When untar extracts an archive, it sets file attributes and timestamps after each file is created. As a result, the inodes of these files are marked as OOO (out-of-order write), which causes valid page cache to be dropped on subsequent opens." Michael Stoler

Root Cause Analysis

The false OOO tagging occurs in the nfs_setattr() inode method. Stoler explained the double-update problem:

"This flase OOO tagging occurs during the nfs_setattr() inode method. The reason is that inode attributes are updated twice: first in the protocol-version-specific method nfs*_proc_setattr(), and then again in nfs_setattr() itself via nfs_refresh_inode(), even though the inode state has already been updated by nfs_update_inode() in protocol-version-specific method." Michael Stoler

The consequence is that nfs_refresh_inode() falsely detects the second attribute update as an out-of-order operation, marking the inode with an OOO range and triggering unnecessary page cache invalidation.

Proposed Fix

Stoler's patch aims to resolve this by:

"eliminating the second inode attribute update in nfs_refresh_inode() when the inode has already been updated." Michael Stoler

Review Feedback

Jeff Layton reviewed the patch and found it technically sound but requested procedural improvements:

"The patch looks sane overall, but you'll need to resubmit it with a proper Signed-off-by: line. You should also send it inline so that people can more easily inline review comments." Jeff Layton

Layton directed Stoler to the kernel patch submission guidelines and recommended using the b4 tool for easier inline patch review workflows.

Conclusion

This thread is in its early stages. The bug fix addresses a real performance issue where valid page cache entries are unnecessarily dropped due to false OOO tagging during setattr operations. Jeff Layton has given a positive initial assessment of the technical approach ("the patch looks sane overall") but requested resubmission with proper formatting (Signed-off-by line and inline patch). The discussion awaits Stoler's revised submission before proceeding to deeper code review.
