nfsdctl: v2 Patch Series to Handle Older Kernels Lacking min-threads Support

Summary

This week, Jeff Layton submitted a revised v2 four-patch series to nfs-utils addressing a backward-compatibility bug in the recently merged min-threads feature. The issue was reported by Benjamin Coddington: when newer versions of nfsdctl attempt to communicate with older kernels that do not support the NFSD_A_SERVER_MIN_THREADS netlink attribute, the kernel rejects the request with -EINVAL.

"Ben reported a problem with using new userland with old kernel. If he tried to send down a setting that the kernel doesn't support, it returns -EINVAL to the call." — Jeff Layton

The series introduces a runtime mechanism for nfsdctl to query the kernel's netlink policy and determine which attributes are supported before attempting to use them. This is classified as a bug fix (not a new feature), correcting a regression introduced by the original min-threads commit.

Bridge from Prior Weeks

In recent weeks, the NFS community has been actively developing dynamic threading support for nfsd:

  • The kernel-side dynamic threading feature was merged into Chuck Lever's tree, allowing threads to scale between a minimum and maximum based on workload.
  • The user-space min-threads parameter was committed to nfs-utils 2.8.5-rc3 last week.
  • A v1 three-patch series was submitted earlier this week to address the same compatibility problem, and received review from Benjamin Coddington as summarized previously.

This v2 series refines that approach with two key improvements: unconditional compilation of min-threads support (removing the UAPI header dependency) and a corrected getpolicy_handler() implementation.

This Week's Activity

Patch 1/4: Unconditionally Enable min-threads Support

The first patch removes the conditional compilation of min-threads support that previously depended on system UAPI headers. Layton explained:

"I originally had this depend on the system header, but if we maintain our copy of nfsd_netlink.h in tree, then we can unconditionally compile in support for the MIN_THREADS option."

This change adds NFSD_A_SERVER_MIN_THREADS to the private nfsd_netlink.h header maintained within nfs-utils, ensuring the feature is always available at compile time regardless of the kernel headers present on the build system. The runtime policy query (patch 3/4) handles actual kernel compatibility.

Patch 2/4: Optimize Netlink Family Name Resolution

The second patch is a preparatory optimization that resolves netlink family names once at startup rather than on every call:

"The current code resolves the string name to an id for every netlink call. Just resolve the family names once and keep them."

Patch 3/4: Query Netlink Policy Before Sending min-threads

The core fix implements runtime feature detection by querying the kernel's netlink policy for the "threads" operation. Layton explained the rationale:

"While netlink is an extensible format, genetlink (which we are using) will reject unknown attributes by default with -EINVAL."

He considered alternatives but ruled them out:

"We could fix this in the kernel by having it ignore unknown attributes, but there is no way to fix old kernels and silently ignoring it is less than ideal. By handling this in userland, we can properly error out when the kernel doesn't support this attribute."

The patch implements differentiated behavior depending on the command:

  • For explicit threads commands with --min-threads: fail with an error if the kernel lacks support.
  • For autostart: log a warning and silently ignore the setting, allowing the server to start normally.

The patch carries a Fixes: tag referencing the original commit:

"Fixes: 00e2e62b8998 ("nfsdctl: add support for min-threads parameter")" "Reported-by: Ben Coddington bcodding@hammerspace.com"

Patch 4/4: Cleanup of xlog() Format Strings

The final patch removes unnecessary newlines from xlog() format strings — a minor code-quality improvement.

Changes from v1 to v2

The cover letter documents the key changes:

  • Addition of patch 1/4 to unconditionally compile in min-threads support (eliminating the UAPI header dependency)
  • Correction to make getpolicy_handler() return NL_SKIP

Post-Week Resolution (Brief Note)

Although falling outside this week's window, the series received subsequent review and was merged:

  • Benjamin Coddington provided both Reviewed-by and Tested-by tags on February 18.
  • Steve Dickson committed the series to nfs-utils 2.8.6-rc1 on February 23.

Significance for NFS Client/Server Development

This fix is significant for several reasons:

  1. Robust user-space/kernel compatibility pattern: The approach of querying netlink policy at startup provides a clean, extensible mechanism for feature detection that can be reused for future nfsdctl enhancements.

  2. Graceful degradation strategy: By differentiating between explicit commands (hard error) and autostart scenarios (warning + continue), the fix ensures administrators are informed while preventing service disruption on mixed-version deployments.

  3. Build system independence: Removing the UAPI header dependency means nfs-utils can be built on any system without requiring specific kernel headers, simplifying distribution packaging.

  4. Continued maturation of dynamic threading: The min-threads feature, merged just last week, is already receiving follow-up fixes — underscoring the active development cycle around NFS server scalability improvements.

Conclusion

Jeff Layton's v2 four-patch series successfully resolves the backward-compatibility regression in nfs-utils introduced by the min-threads feature. The solution — querying netlink policy at runtime rather than depending on compile-time header checks — provides a robust, extensible approach to handling kernel version differences. With the series subsequently merged into nfs-utils 2.8.6-rc1, administrators can now safely upgrade user-space tools without requiring immediate kernel upgrades.
