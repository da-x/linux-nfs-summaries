NFS Blocklayout: Fix Clang W=1 unused variable error in bl_write_pagelist()

Summary

NFS Blocklayout: Fixing a Clang W=1 Compilation Error

This brief thread addresses a bug fix in the NFS client's block layout driver (fs/nfs/blocklayout/). Specifically, it resolves a compilation error triggered when building with make W=1 (extra warnings enabled) using the Clang compiler.

The Issue

Andy Shevchenko identified that the variable count in bl_write_pagelist() was being set but never used, resulting in a hard error under -Werror,-Wunused-but-set-variable. This issue arose because dprintk(), which previously consumed the variable, becomes a no-op when debugging is disabled.

"Clang compiler is not happy about set but unused variable (when dprintk() is no-op)... Remove a leftover from the previous cleanup." Andy Shevchenko

The patch traces the root cause to a prior cleanup commit:

"Fixes: 3a6fd1f004fc ("pnfs/blocklayout: remove read-modify-write handling in bl_write_pagelist")" Andy Shevchenko

Evolution of the Discussion

Initially, Shevchenko submitted this as a standalone one-patch series. He noted an interaction with another concurrent patch he was sending:

"Note, if https://lore.kernel.org/r/20260204010415.2149607-1-andriy.shevchenko@linux.intel.com is applied first, it will shadow the error here, this patch is needed anyway." Andy Shevchenko

However, he quickly revised his approach to streamline the submission process:

"Nevermind, I will send a v2 where it will be part of the series." Andy Shevchenko

Conclusion

The discussion concluded with the decision to fold this fix into a larger patch series (v2) rather than maintaining it as an independent patch. This ensures that the compilation error is resolved cohesively with related changes in the blocklayout driver, preventing potential shadowing issues and simplifying the review process for maintainers.
