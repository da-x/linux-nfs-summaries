svcrdma: Build errors block contiguous-page RDMA Read optimization

Summary

svcrdma: Build errors block contiguous-page RDMA Read optimization

This thread concerns patch [PATCH v2 2/2] svcrdma: Use contiguous pages for RDMA Read sink buffers submitted by Chuck Lever, part of a two-patch series titled "RDMA/rw: Fix MR pool exhaustion in bvec RDMA READ path" cover letter. The series targets NFS server-side (svcrdma) performance improvements and a bug fix for memory region (MR) pool exhaustion in the RDMA READ path.

Context: What the Patch Does

The second patch introduces an optimization where svc_rdma_build_read_segment() constructs RDMA Read sink buffers using physically contiguous pages via higher-order allocations, rather than consuming pages one-at-a-time from rq_pages[]. As Chuck Lever explained in the patch description:

"A single higher-order allocation followed by split_page() yields physically contiguous memory while preserving per-page refcounts. A single bvec spanning the contiguous range causes rdma_rw_ctx_init_bvec() to take the rdma_rw_init_single_wr_bvec() fast path: one DMA mapping, one SGE, one WR."

This reduces overhead for large NFS READ payloads (e.g., a 64KB payload would produce just one bvec and one RDMA Read Work Request instead of 16 separate ones).

This Week's Activity: Build Failures Across Multiple Architectures

All four messages this week are automated build failure reports from the kernel test robot, with one response from Chuck Lever. The robot reported identical compilation errors on three different architectures/configurations:

  1. x86_64-rhel-9.4 with gcc-14 report
  2. m68k-allmodconfig with GCC 15.2.0 report
  3. riscv-allyesconfig with clang 16.0.6 report

The error is consistent across all configurations:

"implicit declaration of function 'svc_rqst_page_release'; did you mean 'svc_rdma_cc_release'?"

The function svc_rqst_page_release() is called at line 813 in net/sunrpc/xprtrdma/svc_rdma_rw.c within the new helper svc_rdma_fill_contig_bvec(), but it is not declared or defined anywhere in the current patch series.

Chuck Lever's Response

Chuck Lever acknowledged the issue promptly:

"The current version of the series is missing a patch that provides this helper function. Next version (if one is needed) will include it." response

Classification and Status

  • Type: This is a bug fix (patch 1/2 fixing MR pool exhaustion) paired with a performance optimization (patch 2/2 introducing contiguous page allocations for RDMA Read sink buffers).
  • Status: The series is blocked by build failures. The missing helper function svc_rqst_page_release() must be provided in a subsequent version. No resolution was reached this week; the kernel test robot's repeated reports confirm the issue persists across multiple architectures and compilers.

Key Takeaway for NFS Client/Server Developers

While this series primarily targets the NFS server-side (svcrdma) RDMA implementation, the MR pool exhaustion fix in patch 1/2 has implications for NFS clients using RDMA transport, as server-side resource exhaustion can degrade client performance. The contiguous-page optimization aims to reduce DMA mapping overhead and improve throughput for large NFS READ operations over RDMA. A corrected v3 of the series is expected once the missing helper function is included.
