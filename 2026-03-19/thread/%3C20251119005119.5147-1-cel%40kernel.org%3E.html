pynfs ACL-on-Creation Tests: Repository Availability and Pending Push

Summary

This week's activity in this long-running thread centered on the availability of Calum Mackay's pynfs repository and the pending submission of regression tests for the NFSv4 ACL-on-file-creation bug fix. The kernel-side patch, originally submitted by Chuck Lever in November 2025, corrected a defect where the NFSD server neglected to set POSIX ACLs during file creation operations. This week's discussion confirmed that the corresponding pynfs test patches are still pending submission but are expected imminently.

Background (Prior Weeks)

The thread originated with Chuck Lever's patch in November 2025, which fixed a bug where the NFSv4 server failed to apply POSIX ACLs during file creation. As Chuck explained at the time:

"An NFSv4 client that sets an ACL with a named principal during file creation retrieves the ACL afterwards, and finds that it is only a default ACL (based on the mode bits) and not the ACL that was requested during file creation. This violates RFC 8881 section 6.4.1.3: 'the ACL attribute is set as given'."

In prior weeks, Aurélien Couderc had followed up on the status of pynfs regression tests for this fix, noting that Calum Mackay's repository had not been updated in months. Last week, Calum Mackay responded, stating:

"Apologies; I have a number of patches queued up that I need to push out. Will do that asap."

This Week's Activity

On March 13, Aurélien Couderc followed up again, reporting that the pynfs gitweb site appeared to be down:

"https://git.linux-nfs.org/?p=cdmackay/pynfs.git;a=summary appears to be down at the moment. Could you please post the URL of the commits once the site is up again?"

Calum Mackay replied that the site was operational, albeit slow:

"The site seems to be up at the moment, albeit rather slow to respond. I don't look after the site itself, so I'm not sure if there are ongoing issues."

Two days later, on March 15, Aurélien Couderc checked again and found the site working, but noted no new changes:

"It works again for me, but there are no new changes for 2026. Did you push your patches?"

Calum Mackay confirmed that the patches had not yet been pushed but were expected soon:

"Not yet, but I will soon, hopefully this week."

Classification

  • Type: Bug fix validation (test infrastructure)
  • Component: NFSD (NFSv4 server), pynfs test suite
  • Status: Pending — patches queued for imminent submission by Calum Mackay

Conclusion

This week's exchange confirms that the pynfs regression tests for the ACL-on-file-creation bug fix are not lost or abandoned. The delay appears to be due to competing priorities rather than technical blockers. With Calum Mackay indicating that the patches will be pushed "hopefully this week," the NFS community can expect test coverage for this defect in the near future, helping to prevent regressions in NFSD's ACL handling during file creation operations.
