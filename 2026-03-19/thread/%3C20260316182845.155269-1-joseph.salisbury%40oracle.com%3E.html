nfsd: Minor Comment Typo Fix in nfsxdr

This week, a trivial but welcome cleanup patch was submitted and applied to the NFS server (nfsd) subsystem. The discussion centered on correcting a spelling error in a source code comment within fs/nfsd/nfsxdr.c.

Discussion Overview

Joseph Salisbury initiated the thread with a patch titled "[PATCH] nfsd: fix comment typo in nfsxdr" submitted here. The patch addressed a misspelling of the word "occurred" (originally written as "occured") in a comment related to the NFSv2 READDIR entry encoder.

Salisbury justified the change by noting:

"Typos in comments reduce readability and make text searches less reliable for developers and maintainers."

He initially included Fixes: and Cc: stable@vger.kernel.org tags, suggesting the typo originated from commit f5dcccd647da.

Review and Application

Chuck Lever, the NFS maintainer, reviewed the patch and applied it to the nfsd-testing tree. However, he made a significant editorial decision regarding the metadata tags:

"Removed Fixes: and Cc: stable -- not appropriate for fixes to misspellings in code comments."

This highlights a key maintenance policy: while comment cleanups are appreciated for code quality, they do not warrant backporting to stable kernels via the stable tree, as they introduce no functional risk or behavioral change.

Conclusion

The patch was accepted and merged as commit f5d9cf47c90f. This thread serves as a brief example of routine code hygiene in the NFS subsystem, emphasizing that while minor cosmetic fixes are welcome, they are treated distinctly from bug fixes or feature additions in terms of version control metadata and stable kernel inclusion.

Key Takeaways:

  • Type: Documentation/Comment Cleanup (Non-functional).
  • Outcome: Applied to nfsd-testing.
  • Policy Note: Maintainers explicitly strip Fixes: and Cc: stable tags from pure typo fixes to prevent unnecessary noise in stable kernel releases.
