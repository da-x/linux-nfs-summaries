pnfs/flexfiles: Fix OOB Read from Zero version_count

Summary

pnfs/flexfiles: Validate ds_versions_cnt to Prevent OOB Read

Classification

Bug Fix / Security Hardening

This thread consists of a single patch submission addressing a critical out-of-bounds (OOB) read vulnerability in the NFS client's pNFS FlexFiles layout driver. The fix validates input from potentially malicious servers to prevent kernel memory corruption or information leakage.

Technical Summary

Jenny Guanni Qu submitted a patch to validate that ds_versions_cnt is non-zero during the parsing of pNFS LAYOUTGET responses. The vulnerability arises in nfs4_ff_alloc_deviceid_node(), which reads a version_count field from XDR data without verifying it is greater than zero.

The Vulnerability

When a malicious NFS server sends a LAYOUTGET response with version_count=0:

  1. The kernel calls kcalloc(0, ...), which returns ZERO_SIZE_PTR (address 0x10).
  2. Subsequent code in nfs4_ff_layout_ds_version() and other callers attempts to access ds_versions[0].
  3. This results in an out-of-bounds read from the invalid pointer range [0x0000000000000010-0x0000000000000017].

The issue was confirmed using KASAN (Kernel Address Sanitizer), which flagged a null-ptr-deref in the specified range.

The Fix

The patch adds a simple validation check immediately after parsing version_count from XDR, before any allocation occurs:

"Add a check for version_count == 0 after parsing it from XDR, before the allocation."

This prevents the zero-size allocation and subsequent invalid memory access.

Attribution and History

  • Reported-by: Klaudia Kloc and Dawid Moczadło from Vidoc Security.
  • Fixes: Commit d67ae825a59d ("pnfs/flexfiles: Add the FlexFile Layout Driver"), indicating this is a long-standing issue since the driver's introduction.
  • Tested-by: Jenny Guanni Qu.

Significance for NFS Client Development

This fix highlights the importance of rigorous input validation in network-facing kernel code, particularly in pNFS layouts where server-provided data directly influences memory allocation. The FlexFiles layout driver is a critical component for high-performance NFS clients, and ensuring its robustness against malformed or malicious server responses is essential for system stability and security.
