NFS Client: Delegated Attribute Fixes Reviewed and Tested for v7.1

Summary

This week, the discussion around Jeff Layton's two-patch series to fix delegated attribute handling in the Linux NFS client progressed from submission (last week) to testing confirmation and review feedback. The patches address critical bugs where inode change times (ctime) were not being updated correctly when delegated timestamps were active, causing failures in xfstests.

Context (Bridged from Prior Week)

Last week, Jeff Layton submitted the series targeting kernel v7.1 to resolve two specific xfstest failures:

  1. generic/221: Failed because utimensat() updating only atime did not trigger a ctime update via RPC when cached locally under delegation.
  2. generic/728: Failed because removexattr did not fetch updated attributes post-operation, leaving stale ctime in the client cache.

This Week's Activity

Testing Confirmation

Olga Kornievskaia provided crucial validation of the patch series, confirming that the reported test failures were resolved:

"I can confirm that generic/221 and generic/728 no longer fail with this patch series applied." Tested-by confirmation

Review Feedback: Fixes Tags

Anna Schumaker, reviewing the series for inclusion, requested that proper Fixes: tags be added to the commits to ensure correct backporting and changelog tracking:

"Can you add fixes tags to the patches?" Review request

She also asked to include Olga's testing endorsement:

"Thanks for checking that. Can we add your 'Tested-by' to the commits?" Tested-by request

Author Response and Tag Identification

Jeff Layton agreed to add the tags and proposed specific commits to cite:

For the first patch (utimensat fix), he identified:

"Fixes: 40f45ab3814f ("NFS: Further fixes to attribute delegation a/mtime changes")" Proposed tag 1

For the second patch (removexattr fix), he noted it was technically a latent bug exposed by delegated timestamps, but traced the root cause to the initial implementation of extended attribute handling:

"Technically, this worked until delegated timestamps were introduced, but ISTM that omitting the GETATTR in the first place was a mistake" Proposed tag 2

He proposed citing:

"Fixes: 3e1f02123fba ("NFSv4.2: add client side XDR handling for extended attributes")" Proposed tag 2

Layton concluded by asking if he needed to resend the patches with these tags or if Anna could apply them:

"Can you tack those onto the patches or do you need me to resend?" Resend inquiry

Conclusion

The thread concluded with the patches validated by testing and ready for inclusion in v7.1, pending the addition of Fixes: tags and a Tested-by: line. The discussion highlights the importance of rigorous metadata consistency checks in NFS client development, particularly as optimizations like delegated timestamps introduce edge cases where local caching can violate POSIX semantics regarding ctime updates.
