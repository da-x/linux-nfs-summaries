NFSD: Per-Namespace Callback Statistics Cleanup

Summary

NFSD: Moving Callback RPC Statistics to Per-Network Namespace Storage

This thread covers the final resolution of a six-patch-cycle effort by Dai Ngo to refactor how the NFS server (NFSD) tracks backchannel callback statistics, ensuring they are isolated per network namespace rather than maintained globally.

The Problem and Proposed Solution

The core issue addressed in this patch is a statistical inconsistency in containerized environments. As Dai Ngo explained in the patch description:

"The RPC statistics for the NFSD fore channel are tracked per network namespace, but the backchannel (callback) RPC statistics are currently maintained globally. This causes statistics to be shared across network namespaces and can produce misleading results when nfsd is run in containers."

The proposed fix relocates the accumulated backchannel/callback RPC statistics into per-network-namespace storage. Notably, this patch was designed as a preparatory step; it only handles the internal accounting relocation. User-facing retrieval mechanisms were deferred to a subsequent patch.

Review History and Final Resolution

This submission represents version 6 of the patch series. The changelog highlights several iterative fixes:

  • v2: Addressed memory freeing errors in nfsd_net_cb_stats_init().
  • v3: Reworded the commit message and fixed initialization of nn->nfsd_cb_program.nrvers.
  • v4: Resolved a merge conflict in nfsd_net_exit within the nfsd-testing branch.
  • v5 & v6: Restored original messaging clarity and placed specific initialization/shutdown calls under CONFIG_NFSD_V4.

Despite these iterations, NFSD maintainer Chuck Lever noted that the patch still contained unresolved feedback from earlier review cycles. Rather than continuing the back-and-forth, Lever decided to intervene directly:

"There are at least five unaddressed previous review comments here in v6. Since this is a simple clean-up that seems to have stalled out, I'll fix those up and apply it."

Conclusion

The discussion concluded with Chuck Lever taking ownership of the final cleanup. This intervention ensures that the NFSD codebase will gain proper network namespace isolation for callback statistics, improving accuracy for administrators running NFS servers in containerized environments. The patch was accepted as a bug fix/cleanup rather than a new feature or protocol change.
