This Week's Activity

Pull Request Overview

Chuck Lever's pull request 2026-03-18 targets the Git repository at https://git.kernel.org/pub/scm/linux/kernel/git/cel/linux.git under tag nfsd-7.0-2, with changes available up to commit 5133b61aaf437e5f25b1b396b14242a6bb0508e2.

The request highlights four issues requiring expedient stable backports:

"Issues that need expedient stable backports:

  • Fix cache_request leak in cache_release()
  • Fix heap overflow in the NFSv4.0 LOCK replay cache
  • Hold net reference for the lifetime of /proc/fs/nfs/exports fd
  • Defer sub-object cleanup in export "put" callbacks" Chuck Lever

Fix Details

1. SunRPC Cache Request Leak (Jeff Layton)

File: net/sunrpc/cache.c

Jeff Layton fixed a memory leak in the SunRPC cache layer where cache_request objects were not being properly freed during cache_release(). This fix affects both NFS client and server operations that rely on SunRPC caching mechanisms. The patch adds 26 lines while removing 5, indicating a substantial rework of the release logic.

2. NFSv4.0 LOCK Replay Cache Heap Overflow (Jeff Layton)

File: fs/nfsd/nfs4xdr.c

Layton also addressed a heap overflow vulnerability in the NFSv4.0 LOCK replay cache. This is a security-critical fix, as heap overflows can lead to privilege escalation or denial of service. The patch modifies 9 lines (adding 6, removing 2) in nfs4xdr.c.

3. Network Reference Lifetime Management (Chuck Lever)

File: fs/nfsd/nfsctl.c

Lever fixed an issue where the network namespace reference was not held for the full lifetime of /proc/fs/nfs/exports file descriptors. This could lead to use-after-free conditions when a network namespace is destroyed while export files are still open. The patch adds 22 lines and removes 3 in nfsctl.c.

4. Export Sub-Object Cleanup Deferral (Chuck Lever)

Files: fs/nfsd/export.c, fs/nfsd/export.h, fs/nfsd/state.h

The final fix defers sub-object cleanup in export "put" callbacks to prevent premature deallocation issues. This is the largest patch in the set, modifying 63 lines in export.c (adding 51, removing 8), with supporting changes in export.h (7 lines) and state.h (17 lines).

Key Technical Arguments and Evolution

This thread represents a straightforward bug-fix pull request with no extended discussion or debate. The key technical points are:

  1. Security Priority: The heap overflow in the NFSv4.0 LOCK replay cache is explicitly flagged as requiring expedient stable backports, indicating its severity. This vulnerability could allow malicious clients to exploit the server through crafted LOCK operations.

  2. Memory Management Correctness: Both the cache_request leak and the export cleanup deferral address resource management issues that could lead to memory exhaustion or use-after-free bugs under sustained load.

  3. Namespace Safety: The network reference fix ensures proper lifecycle management of network namespaces in relation to NFS exports, preventing potential crashes when containers or network namespaces are torn down while NFS exports remain active.

  4. Impact on NFS Client Development: While these are server-side fixes, the SunRPC cache leak fix directly impacts NFS client operations since both client and server share the net/sunrpc/cache.c infrastructure. Additionally, the heap overflow fix in LOCK replay could affect clients that rely on lock state consistency during failover scenarios.

Final Conclusions

  • Status: Merged into mainline Linux kernel v7.0-rc cycle.
  • Stable Backport Priority: All four fixes are marked for expedient stable backports, indicating they address critical stability and security issues.
  • NFS Client Relevance: The SunRPC cache leak fix has direct implications for NFS client development, as the cache layer is shared infrastructure. The other fixes are server-side but contribute to overall NFS ecosystem stability.
  • No Further Discussion: This was a clean pull request with no objections or review comments, reflecting the maturity of the NFSD maintenance process and the clear need for these fixes.
