NFSD: Per-net namespace callback statistics and per-operation accounting

Summary

This week, Chuck Lever and Dai Ngo submitted version 7 of a two-patch series to refactor the NFSv4 server's callback (backchannel) statistics infrastructure. The work addresses two distinct issues: the lack of granularity in callback operation counting and the exposure of cross-namespace data through global static variables.

Patch 1/2: Per-operation Statistics Indexing

The first patch, "[PATCH v7 1/2] NFSD: use per-operation statidx for callback procedures" [id://20260313163148.281676-2-cel@kernel.org], resolves a long-standing limitation in how the NFS server tracks callback activity. Previously, all compound-based callbacks (such as CB_RECALL, CB_LAYOUT, and CB_OFFLOAD) shared a single statistics counter because they were mapped to index 1 via NFSPROC4_CB_##call. This made it impossible to distinguish between different callback operations in performance monitoring or debugging scenarios.

Chuck Lever explained the issue:

"All compound callback operations therefore share a single statistics counter, making per-operation accounting impossible."

The fix assigns p_statidx from the client-side enum NFSPROC4_CLNT_##proc, giving each callback operation its own unique counter slot. Since the counts array was already sized by ARRAY_SIZE(nfs4_cb_procedures), no memory allocation changes were required. Jeff Layton reviewed and approved this change:

"Reviewed-by: Jeff Layton jlayton@kernel.org" [id://e5f05ba48418df7ee0af18286a24d700a3f1b623.camel@kernel.org]

Patch 2/2: Per-net namespace Callback Program

The second patch, "[PATCH v7 2/2] NFSD: convert callback RPC program to per-net namespace" [id://20260313163148.281676-3-cel@kernel.org], originally authored by Dai Ngo with significant updates by Chuck Lever, moves the callback channel's rpc_program, rpc_version, rpc_stat, and per-procedure counts from file-scope statics to per-network namespace structures.

The motivation was security and isolation:

"When backchannel statistics are eventually surfaced to userspace, the global counters would expose cross-namespace data." [id://20260313163148.281676-3-cel@kernel.org]

The implementation introduces a new opaque struct nfsd_net_cb, managed by initialization and shutdown functions, with only a pointer stored in struct nfsd_net. This keeps the internal details of the NFSv4 callback program hidden from the network namespace header.

Discussion on Implementation Details

Jeff Layton raised a concern about the memory layout, suggesting that since there is only one nfsd_cb per network namespace, it might be more efficient to embed the structure directly inside nfsd_net rather than performing a separate allocation:

"Given that there will only ever be one nfsd_cb per net, why not just embed this struct inside the nfsd_net instead of doing a separate allocation?" [id://5df3076a22438f5be6b070e62c0d3fc567341b20.camel@kernel.org]

Chuck Lever defended the pointer-based approach as a deliberate design choice to maintain clean layering:

"The reason I did this is because otherwise netns.h would need to have knowledge of the details of the NFSv4 callback program. Things like the NFSv4 callback program's RPC program number are implementation-defined... I'm avoiding a weak layering violation by hiding those details behind a pointer." [id://e4a646d0-a916-419d-a78e-1a89977141a1@app.fastmail.com]

Jeff Layton acknowledged the trade-off, conceding that while he might have prioritized avoiding the extra allocation, the architectural benefit of hiding implementation details was valid:

"Meh. I'd probably have prioritized avoiding the extra allocation, but that's a minor thing." [id://48c2f680d4645070c2899e1fb83398ce405c8339.camel@kernel.org]

He subsequently provided his Reviewed-by tag for the second patch as well.

Conclusion

This series represents a significant improvement in the NFS server's internal accounting and isolation capabilities. It enables finer-grained performance monitoring of callback operations and ensures that network namespace isolation is maintained for backchannel statistics, preventing potential information leakage between containers or virtual environments. The patches have been reviewed and approved by Jeff Layton after a brief discussion on memory layout versus code layering.
