Summary

nfsd: Minor Comment Typo Fix in NFSv3 XDR Code

This week saw a brief, low-stakes interaction regarding a cosmetic cleanup in the NFS server (nfsd) subsystem. The discussion centered on a patch submitted by Joseph Salisbury to correct a spelling error in a source code comment within fs/nfsd/nfs3xdr.c.

Discussion Overview

Type: Bug fix (cosmetic/comment-only).

Joseph Salisbury initiated the thread with a patch titled "[PATCH] nfsd: fix comment typo in nfs3xdr" submitted here. The patch addressed a misspelling of the word "occurred" (originally written as "occured") in a comment related to NFSv3 READDIR entry encoders.

Salisbury justified the change by noting:

"Typos in comments reduce readability and make text searches less reliable for developers and maintainers."

He initially included Fixes: and Cc: stable@vger.kernel.org tags, treating the typo correction with the same formal rigor as functional bug fixes.

Resolution

NFS maintainer Chuck Lever reviewed and applied the patch to the nfsd-testing tree but adjusted the metadata. In his response here, Lever stated:

"Removed Fixes: and Cc: stable -- not appropriate for fixes to misspellings in code comments."

The patch was merged with commit d62daf7b8995e05cca3465a21139f619db860ccb.

Conclusion

This thread highlights the ongoing housekeeping efforts within the NFS subsystem. While the change has no impact on runtime behavior or protocol semantics, it reinforces code maintainability standards. The maintainer's decision to strip stable tags underscores the policy that cosmetic comment fixes do not warrant backporting to stable kernel branches.
