Handling Whitespace in User/Group Names for NFSv4 and Samba

Summary

Overview

This thread consists of a single question posted by Aurélien Couderc regarding the handling of user and group names containing whitespace characters — a common scenario when integrating Linux systems with Windows/macOS environments via NFSv4 or Samba. No replies were received during this week's window.

The Question

Aurélien Couderc opened the discussion on March 15, asking how to create Linux users and groups that contain spaces in their names, specifically for interoperability with NFSv4 and Samba:

"Both SAMBA and NFSv4 have to deal with user and group names with <space> in their strings. Common example is the Windows/OSX 'Domain Users'."

He noted that standard Linux tools like groupadd do not appear to support such names directly, citing an unsuccessful attempt:

"Because e.g. groupadd group -n 'Domain_Users' -g 2016029 does not work."

Context

This is a configuration/administration question rather than a discussion of a new feature, protocol change, or bug fix in the NFS client codebase. The issue touches on a well-known interoperability challenge: Windows and macOS Active Directory environments frequently use group names with spaces (e.g., "Domain Users"), while traditional Unix/Linux user management tools have historically been more restrictive about special characters in usernames and group names.

For NFSv4, this matters because the protocol maps user/group identities to numeric IDs (UIDs/GIDs) for access control, and mismatches or unsupported name formats can lead to permission issues when sharing files between Linux NFS servers and Windows/Samba clients.

Status

As of the end of this week's window, no responses were recorded in this thread. The question remains open, with no technical arguments, conclusions, or proposed solutions documented in the mailing list archive for this discussion.
