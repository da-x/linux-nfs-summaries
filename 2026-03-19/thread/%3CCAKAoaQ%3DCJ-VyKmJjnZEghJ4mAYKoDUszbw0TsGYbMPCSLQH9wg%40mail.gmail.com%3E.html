Windows NFS Client Testing Announcement: Interoperability with Linux nfsd

Summary

NFSv4.2/4.1 Windows Client Driver: Testing Announcement for Linux Interoperability

This thread consists of a single message this week, in which Martin Wege forwarded an announcement from Roland Mainz regarding new test binaries for the ms-nfs41-client, an open-source NFSv4.2/NFSv4.1 filesystem client driver for Windows. The primary focus of this posting is to solicit interoperability feedback with Linux NFS servers.

Classification

Topic: New feature release and interoperability testing announcement (Windows NFS client). Relevance to Linux NFS: This discussion concerns a third-party Windows NFS client that interacts with Linux NFS servers. It does not involve changes to the Linux kernel NFS client or server code, but rather highlights features in the Linux NFS server (nfsd) that are being exercised by this Windows client.

Key Technical Arguments and Features

Martin Wege explicitly requested feedback from the Linux community:

"Interoperability feedback with NFSv4.1/NFSv4.2 servers based on Linux 6.6+ LTS and 6.19+/7.0 would be great."

He highlighted several features as particularly noteworthy for their interaction with Linux servers:

"Support for Linux 7.1 case-insensitive NFS filesystems was added, Windows Alternate Streams (Win32 streams) support was added, xcopy.exe/cmd.exe copy/MS Explorer file copy acceleration via NFS server side copies and copy-by-block-cloning are IMO the most interesting new features... because it's 'on' by default for all Windows 11 applications which copy files"

Notable Features Affecting Linux NFS Server Interoperability

The announcement details several capabilities in the Windows client that rely on specific NFSv4.2 server features, many of which are implemented in the Linux kernel nfsd:

  • Server-Side Copy and Block Cloning: The client now implements FSCTL_OFFLOAD_READ/FSCTL_OFFLOAD_WRITE for NFSv4.2 COPY, and FSCTL_DUPLICATE_EXTENTS_TO_FILE for block cloning. Martin Wege noted:

    "cloning now works with FreeBSD 14.3/15.0/16.0 nfsd and Linux nfsd exporting btrfs&xfs filesystems, server side copy with FreeBSD+Linux with all filesystems"

  • Case-Insensitive Filesystems: Support was added for case-insensitive NFS filesystems, which requires:

    "FreeBSD n>= 16.0 NFS server, Linux >= 7.1 NFS server or Windows Server NFS server with a case-insensitive filesystem"

  • Sparse Files: The client supports sparse file operations (hole punching, range enumeration) requiring NFSv4.2 SEEK, ALLOCATE, and DEALLOCATE operations, along with the FATTR4_WORD1_SPACE_USED attribute—features present in modern Linux nfsd.

  • Named Attributes / Alternate Data Streams: Support for Win32 named streams (ADS) is provided if the NFS server supports NFS named attributes. The announcement notes compatibility with FreeBSD >= 15.0, Solaris >= 11.4, and Illumos, but does not explicitly claim Linux nfsd support for named attributes in this release.

  • Bug Fixes: Several bug fixes were mentioned, including fixes for FileRenameInformation/FileLinkInformation SRVOpen collapsing, issues probing sparse files with nfs-ganesha, and general FreeBSD NFS server compatibility improvements.

Evolution of the Discussion

There is no evolution or debate in this thread; it is a straightforward announcement forwarded to the Linux NFS mailing list to encourage testing. The sole message serves as a call for interoperability reports between the Windows client and Linux NFS servers running kernel versions 6.6 LTS through 7.1+.

Final Conclusions

The primary conclusion is an invitation to the Linux NFS community to test the new Windows client binaries against their Linux NFS servers. Martin Wege emphasized that server-side copy and block cloning are now enabled by default for Windows 11 applications, making interoperability with Linux nfsd (particularly on btrfs and xfs exports) a high priority for validation.

"Please test the binaries... Interoperability feedback with NFSv4.1/NFSv4.2 servers based on Linux 6.6+ LTS and 6.19+/7.0 would be great."

While this thread does not involve changes to the Linux kernel itself, it underscores the growing maturity of cross-platform NFS interoperability, particularly around NFSv4.2 features like server-side copy, block cloning, and sparse file support in the Linux NFS server implementation.
