svcrdma: Contiguous Pages for RDMA Read Sink Buffers (v4)

Summary

svcrdma: Use contiguous pages for RDMA Read sink buffers (PATCH v4)

Classification: Performance optimization / new feature in NFS server-side RDMA (svcrdma) subsystem.

Overview

This week, Chuck Lever posted [PATCH v4] svcrdma: Use contiguous pages for RDMA Read sink buffers [id://20260319133610.2556826-1-cel@kernel.org], the latest iteration of a proposal to improve RDMA Read performance in the NFS server's RPC-over-RDMA transport layer. The patch aims to reduce DMA mapping overhead and simplify Work Request (WR) construction for large NFS READ payloads by using physically contiguous memory allocations instead of per-page scatter-gather entries.

Technical Background

The core problem, as described by Lever:

"svc_rdma_build_read_segment() constructs RDMA Read sink buffers by consuming pages one-at-a-time from rq_pages[] and building one bvec per page. A 64KB NFS READ payload produces 16 separate bvecs, 16 DMA mappings, and potentially multiple RDMA Read WRs (on platforms with 4KB pages)."

The proposed solution uses a single higher-order page allocation followed by split_page() to yield physically contiguous memory while preserving per-page reference counts. This allows the RDMA core's rdma_rw_ctx_init_bvec() to take a fast path:

"A single bvec spanning the contiguous range causes rdma_rw_ctx_init_bvec() to take the rdma_rw_init_single_wr_bvec() fast path: one DMA mapping, one SGE, one WR."

Key Design Details

The patch includes several safety mechanisms:

  1. Fallback behavior: Allocation uses __GFP_NORETRY | __GFP_NOWARN and falls back through decreasing orders. If even order-1 fails, the existing per-page path handles the segment.
  2. Array bounds protection: The rq_maxpages guard prevents array overrun, falling back to the per-page path if necessary.
  3. Memory pressure handling: __GFP_NORETRY ensures higher-order allocation failures do not stall the system under memory pressure.
  4. Page consumption neutrality: Extra pages from rounded-up allocations replace existing entries (freed via put_page() first), so there is "no net increase in per-request page consumption."

The contiguous path is attempted only when the segment starts page-aligned (rc_pageoff == 0) and spans at least two pages.

Conclusion

This v4 patch represents a performance optimization for NFS-over-RDMA server-side READ operations, reducing DMA mapping and Work Request overhead by using physically contiguous memory buffers. The related MR pool exhaustion fixes have been accepted into the RDMA subsystem tree, while this contiguous allocation optimization is slated for inclusion in the NFS server tree (nfsd-testing) pending final review.
