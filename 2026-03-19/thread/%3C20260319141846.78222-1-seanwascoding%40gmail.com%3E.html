NFS/SunRPC: Cleanup Redundant Debug Checks and Refactor Macros

Summary

This week, Sean Chang submitted a three-patch series aimed at cleaning up redundant debug checks and refactoring macros within the NFS client, server (nfsd), lockd, and SunRPC subsystems. The series focuses on code maintainability and kernel style compliance rather than introducing new features or fixing runtime bugs.

Series Overview

The patch set addresses two main areas:

  1. Redundant Debug Guards: Patches 1/3 and 2/3 remove explicit IS_ENABLED(CONFIG_SUNRPC_DEBUG) checks in nfsd, lockd, and svcrdma. Chang argues these are unnecessary because the underlying dprintk() macros already evaluate to no-ops when debugging is disabled.
  2. Macro Refactoring: Patch 3/3 refactors nfs_errorf() and nfs_ferrorf() into the standard do-while(0) pattern for safer macro expansion and removes unused nfs_warnf() macros.

Chang emphasized that the removal of explicit guards does not impact performance or binary size, citing compiler optimizations:

"Verification with .lst files under -O2 confirms that the compiler successfully performs 'dead code elimination'. Even when variables... are declared without #ifdef, they are completely optimized out (no stack allocation, no symbol references in the final executable) as they are only referenced within no_printk()." As stated by Sean Chang.

Discussion on Macro Refactoring

The primary technical discussion centered on Patch 3/3, specifically regarding the consistency of macro refactoring. Andy Shevchenko reviewed the changes and questioned why not all related macros were updated to the do-while(0) pattern:

"Why not all of them?" Asked by Andy Shevchenko.

Chang clarified that nfs_errorf was refactored because it does not return a value, whereas macros like nfs_invalf do (returning -EINVAL). He proposed an alternative using statement expressions:

"I initially only refactored nfs_errorf because it doesn't return a value. For nfs_invalf, it will always return -EINVAL. Would you prefer me to refactor it using the ({ ... }) statement expression pattern to keep the return value, or is it better to leave it as is?" Sean Chang replied.

Shevchenko concluded that the proposed change for nfs_invalf did not significantly improve the situation and accepted the original approach, while noting a long-term ideal:

"I don't think in this case it improves the situation. Yeah, it's unfortunate... Okay, let's go with your original approach (ideally these all probably should be replaced by static inline:s)." Andy Shevchenko concluded.

Conclusion

The series received Reviewed-by and Tested-by tags from Andy Shevchenko. While the patches are accepted, Shevchenko also pointed out several unrelated warnings in nfs/super.c regarding incorrect type initializers for rpc_xprt and errors in trace headers (nfstrace.h, nfs4trace.h) that could be addressed separately.

This cleanup effort enhances code clarity and adheres to kernel coding standards, ensuring that debug infrastructure is both minimal and robust.
