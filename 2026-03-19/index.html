NFS Client Regressions and Fixes: EIO with Large rsize, Infinite Writeback Loop, Delegation Bugs, and NFSD Netlink Modernization

Week ending 2026-03-19

Critical NFS Client Bugs

Regression: Large rsize/wsize (1 MB) Causes EIO on Dell EMC OneFS

A significant regression was reported by Debian affecting the Linux NFS client against Dell EMC Isilion/OneFS servers. Commit 2b092175f5e3 ("NFS: Fix inheritance of the block sizes when automounting") exposed a semantic mismatch: the Linux client uses maxread/maxwrite to size WRITE payloads, but OneFS interprets these as total compound packet limits rather than payload-only. When 1 MB writes are issued, the full SEQUENCE+PUTFH+WRITE+GETATTR compound exceeds the server's max_request_size, resulting in NFS4ERR_REQ_TOO_BIG and EIO on the client.

Jeff Layton argued the client should defensively clamp write sizes or at least warn about mismatches, while Trond Myklebust maintained that servers are responsible for advertising consistent limits and adding client-side sanity checks for every vendor would be an undue burden. No fix was agreed upon this week; the issue is tracked via Debian bug #1128834. (thread)

Infinite Loop in nfs_writepages After State Recovery Failure

Huawei's Li Lingfeng reported a critical bug where nfs_writepages enters an infinite loop after a server restart and state recovery failure. When the server returns ESTALE, EROFS, or EIO during open-state reclamation, the file's open context is marked bad (NFS_CONTEXT_BAD). Subsequently, nfs_page_create returns -EBADF, but nfs_writepages does not treat this as a fatal error and retries forever, preventing the superblock lock from being released and causing mount operations to hang. A proposed workaround treats -EBADF as fatal; the report awaits maintainer review. (thread)

Soft Mount Ineffective with NFS_CS_NO_RETRANS_TIMEOUT

Zhangjian from Huawei demonstrated that the soft mount option is ineffective when the TCP connection remains in ESTABLISHED state but the server never responds. The NFS_CS_NO_RETRANS_TIMEOUT flag suppresses retransmission timeouts regardless of mount options, causing operations like OPEN to hang indefinitely while waiting for a sequence ID. Trond Myklebust refused client-side workarounds: "We do not ever 'fix' broken servers by hacking the client." (thread)

Important NFS Client Bug Fixes

Delegated Attribute Fixes for v7.1

Jeff Layton's two-patch series fixing delegated attribute handling was validated by Olga Kornievskaia (xfstests generic/221 and generic/728 now pass). The patches address: (1) utimensat() not triggering ctime updates via RPC when cached locally under delegation, and (2) removexattr not fetching updated attributes post-operation. Anna Schumaker requested Fixes: tags before merging. (thread)

Fix drop_nlink During REMOVE with Delegations

Roberto Bergantinos Corpas submitted a fix for a regression in commit bd4928ec799b. When a file with nlink=1 and an active delegation is removed, the delegation return advances gencount, which the previous logic misinterpreted as evidence that an inflight RPC had already reflected the removal — causing it to skip the link-count drop. This broke inotify FS_DELETE_SELF notifications (LTP/inotify04 failure). The patch forces drop_nlink when a delegation exists before REMOVE. (thread)

pNFS FlexFiles: OOB Read Fix

Jenny Guanni Qu submitted a security hardening patch validating that ds_versions_cnt is non-zero during LAYOUTGET response parsing. A zero value from a malicious server causes kcalloc(0, ...) to return ZERO_SIZE_PTR, leading to an out-of-bounds read at address 0x10. Reported by Vidoc Security; confirmed via KASAN. (thread)

SUNRPC Sysfs Race Fix Backported to 5.15.y

Robert Garcia backported NeilBrown's fix for a race condition where ->sock can be set to NULL asynchronously during sysfs reads, causing kernel oopses. The fix ensures ->recv_mutex is held during transport attribute reads. (thread)

NFSD and Server-Side Activity

Second Round of NFSD Fixes Merged for v7.0-rc

Chuck Lever's pull request merged four critical fixes: a SunRPC cache_request leak, a heap overflow in the NFSv4.0 LOCK replay cache (security-critical), a network namespace reference lifetime fix for /proc/fs/nfs/exports, and deferred sub-object cleanup in export "put" callbacks. All marked for expedient stable backports. (thread)

NFSD Lock Regression: F_GETLK Fix Direction Agreed

After weeks of debate, Jeff Layton endorsed Neil Brown's reframed analysis: the -ENOLCK regression on read-only files was caused by NFSD incorrectly requiring write access for F_GETLK (a lock query), not F_SETLK (lock acquisition). Local filesystems already permit F_GETLK without write access. Layton traced the issue potentially back to a 2021 commit, suggesting it had been latent for years. (thread)

Netlink Modernization: Upcalls and State Revocation

Two major netlink initiatives advanced this week:

  • Netlink upcalls for mountd/exportd (Jeff Layton, 14 patches): Replaces /proc-based cache upcalls with generic netlink for auth.unix.ip, auth.unix.gid, svc_export, and nfsd.fh caches. Chuck Lever reviewed concurrency semantics around snapshotting pending requests. (thread)

  • Automatic NFSv4 state revocation on unmount (Chuck Lever, v4 6 patches): Introduces NFSD_CMD_UNLOCK netlink command with IP, filesystem, and export scopes. Jeff Layton raised concerns about hardlinked files across exports and API design (single vs. multiple commands). Chuck committed to linking NFSv4 state to exports in v5. (thread)

RDMA: MR Pool Exhaustion Fix for NFS over RDMA

Chuck Lever's series fixed Memory Region pool exhaustion under write-intensive workloads causing connection resets. Patches 1–2 (fallback to direct SGE posting and bvec path fix) were accepted into the RDMA tree for -rc. Patches 3–4 (folio batch release helper and contiguous page optimization) are pending for the next merge window. (thread)

Major Trends and Ongoing Debates

Increasing Default max_block_size to 4 MB

Cedric Blancher proposed raising the NFSv4 server default from 1 MB to 4 MB. Chuck Lever called for data-driven validation. Roland Mainz (ms-nfs41-client/Windows) confirmed 4 MB works with performance gains; Rick Macklem (FreeBSD) noted limited support; Anna Schumaker reported Linux client testing passed with code changes needed for >1 MB sizes. (thread)

VFS Directory Locking RFC (Neil Brown, 53 patches)

The second week of Neil Brown's RFC to lift lookup out of exclusive directory locks saw filesystem adaptations for AFS, SMB/CIFS, cephfs, ext4, and others. Amir Goldstein identified overlayfs-specific issues with readdir cache protection; Jan Kara flagged ext4 fast-commit tracking concerns. Al Viro's ACK remains the critical path. (thread)

nfs-utils 2.8.7 Released

Steve Dickson announced nfs-utils 2.8.7, fixing the nfsrahead regression from 2.8.6 that caused 10-second delays for non-NFS devices and cascading blktests failures. He also noted an upcoming 2.9.1 release will disable NFSv4.0 by default on the server, aligning with kernel client defaults in 7.0 kernels. (thread)

Code Cleanup

Sean Chang's series removed redundant IS_ENABLED(CONFIG_SUNRPC_DEBUG) guards and refactored nfs_errorf macros to the standard do-while(0) pattern, receiving Reviewed-by from Andy Shevchenko. (thread)
