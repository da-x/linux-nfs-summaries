nfs-utils netlink upcall series committed to 2.9.1-rc3

Summary

nfs-utils Netlink Series: Committed to 2.9.1-rc3

Classification

New feature / infrastructure change — completion of a 16-patch series introducing netlink-based upcall/downcall support for mountd, exportd, and exportfs in nfs-utils. This week's activity represents the final merge confirmation.

Summary

This thread concludes with the successful integration of Jeff Layton's major refactoring of NFS server-side userspace daemons. Last week, Layton submitted v2 of a 16-patch series adding netlink support as the primary communication channel between the kernel and mountd/exportd, replacing the legacy /proc-based pipe interface. The series also included two bug fixes (removal of stale static variables in nfsd_fh expkey lookup and cleanup of obsolete "legacy mode" documentation) alongside extensive netlink handler implementations for all four cache types (svc_export, expkey, auth.unix.ip, auth.unix.gid).

This week, nfs-utils maintainer Steve Dickson confirmed the series was accepted:

"Committed... (tag: nfs-utils-2.9.1-rc3)" — Steve Dickson

The 16-patch series touched 20 files with approximately 2,350 insertions and 411 deletions. The bulk of the changes (1,892 lines added to support/export/cache.c) implement the netlink cache handlers, while bundled UAPI headers (nfsd_netlink.h and sunrpc_netlink.h) ensure compatibility with kernels that may not yet carry the latest system headers.

Key Technical Highlights

Architecture: Netlink Primary, /proc Fallback

The series establishes a dual-mode architecture where netlink is preferred but /proc remains as a fallback for older kernels. As described in patch 11/16:

"Now that all of the exportd upcalls are converted to use netlink, don't bother opening /proc channel files if that succeeds."

Bug Fixes Included in the Series

Two notable bug fixes were embedded within the feature series:

  1. Static variable removal (patch 02/16): Unnecessary static variables in the nfsd_fh expkey lookup were converted to local variables scoped to the inner loop, preventing state leakage across function calls during CROSSMOUNT submount iteration.

  2. Obsolete documentation removal (patch 03/16): Legacy "mode" documentation referencing 2.4-era kernels was removed from the exportfs manpage, noting that the nfsservctl() syscall was eliminated in Linux 3.1.

Startup Race Condition Fix

patch 12/16 addressed a race condition where requests could queue before the daemon came online:

"It's possible for there to be requests queued before mountd comes online. Always check for already-pending requests after opening netlink sockets."

Significance

This merge marks a major architectural milestone for NFS server infrastructure:

  • Container compatibility: mountd and exportd are no longer dependent on /proc, enabling deployment in containers with restricted filesystem access.
  • Extensibility: Future export options need only be added to netlink headers, simplifying synchronization between kernel and userspace.
  • Performance: Targeted cache scanning eliminates unnecessary polling overhead in high-load deployments.

The series is the userspace counterpart to the corresponding kernel-side netlink upcall series applied to nfsd-testing earlier this week by Chuck Lever.
