OPENAT2_REGULAR flag: post-review status and VFS merge path

Context from Prior Week

In the week ending April 2, Dorjoy Chowdhury submitted Patch v6 of a series introducing the OPENAT2_REGULAR flag for the openat2() system call. This new UAPI feature allows applications to explicitly request opening only regular files, returning -EFTYPE if a non-regular file (e.g., directory, device node) is encountered. The patch series includes support across the VFS layer and several filesystems, including NFS, Ceph, GFS2, and SMB.

Jeff Layton reviewed the core implementation, initially raising concerns about Ceph symlink handling and GFS2 flag masking. After clarification from Chowdhury, Layton acknowledged the correctness of the implementation and provided a Reviewed-by tag on April 1. The NFS client implementation was part of this accepted patch set, benefiting from VFS-level validation and filesystem-specific atomic open updates.

This Week's Activity (April 4–6)

With the technical review concluded, this week's discussion focused on the procedural next steps for merging the patch series into the kernel tree.

Inquiry About Merge Path

On April 4, Dorjoy Chowdhury thanked Jeff Layton for his patience and reviewed-by, then asked about the future trajectory of the patches:

"Thanks for patiently reviewing this! I am planning on sending patches for man-pages and looking into some xfs-tests for this. But I am not sure if this patch series will get more reviews from others or if it will be picked up in the vfs branch?" Dorjoy Chowdhury

Chowdhury indicated plans to expand documentation (man-pages) and testing coverage (xfs-tests), while seeking clarity on whether additional reviews were expected or if the patches would proceed directly to the VFS maintainers.

Layton's Guidance on Review Expectations

Jeff Layton responded on April 5, clarifying that due to the nature of the change, further scrutiny was warranted:

"This is a change to rather core VFS infrastructure so yes, you should expect some more review. Assuming no major issues are found, then yes, this should eventually get picked up by the VFS maintainers." Jeff Layton

Layton emphasized that because openat2() touches core VFS infrastructure, the patch series would likely undergo additional review beyond his own before being accepted by the VFS maintainers.

Follow-up Ping

On April 6, Chowdhury sent a gentle ping to encourage further engagement from other maintainers and reviewers:

"Ping.... This patch series got a 'Reviewed-by' from Jeff Layton but it probably requires more reviews from other maintainers/reviewers as well. So requesting for review on this patch series. Thanks!" Dorjoy Chowdhury

Conclusion

This week marked a transition from technical review to procedural follow-up for the OPENAT2_REGULAR patch series. The key takeaways are:

  1. Technical Review Complete: Jeff Layton's Reviewed-by tag confirms that the core implementation, including NFS client support, is technically sound.
  2. Additional Review Expected: Due to the VFS-level nature of the change, Layton indicated that further reviews from other maintainers are anticipated before merge.
  3. Next Steps: Chowdhury plans to submit man-pages documentation and xfs-tests to broaden coverage, while awaiting additional review and eventual pickup by the VFS maintainers.

For NFS client development, this patch represents a security-enhancing feature that ensures openat2() with OPENAT2_REGULAR correctly rejects non-regular files on NFS mounts. No bug fixes were discussed this week; the focus remained entirely on the merge path for this new feature.
