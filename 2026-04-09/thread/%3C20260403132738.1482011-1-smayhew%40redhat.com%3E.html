pynfs: Test Infrastructure Fixes and New CB_GETATTR Delegation Test

Summary

This week, Scott Mayhew submitted a five-patch series to the pynfs test suite, focusing on bug fixes in delegation tests and introducing a new regression test for CB_GETATTR behavior after synchronous writes. The series addresses several longstanding issues in the NFSv4.1 delegation test infrastructure, including resource leaks, incorrect attribute checks, and faulty assumptions about delegation types.

Discussion Classification

This thread is primarily about bug fixes to the pynfs test suite, with one patch introducing a new test case (DELEG27) that validates correct server behavior per RFC 8881 regarding delegated timestamps.

Key Technical Arguments and Evolution

Patch 1: Test Cleanup After Execution

Mayhew observed that his NFS server was taking an extended time to exit grace mode after running pynfs tests. The root cause was that multiple test clients failed to properly close their open files, causing DESTROY_CLIENTID to return NFS4ERR_CLIENTID_BUSY. As Mayhew explained:

"These tests were all failing to close some of their open files, causing DESTROY_CLIENTID at the end of the test to return NFS4ERR_CLIENTID_BUSY."

He noted that while older servers would eventually time out these stale client IDs after one lease period, the newer courteous server implementation may retain them indefinitely:

"With the newer courteous server they may stick around indefinitely, so it's important for the tests to clean up after themselves." PATCH 1/5

This patch adds proper file close operations in st_courtesy.py, st_delegation.py, and st_sparse.py to ensure clean teardown.

Patch 2: Fix Delegated Attribute Support Check

Mayhew corrected a bitmap check in the DELEG24 and DELEG25 tests. The issue was that fattr4_supported_attrs is a bitmap4, requiring proper bit shifting when checking for FATTR4_OPEN_ARGUMENTS support:

"The DELEG24 and DELEG25 tests should work regardless of whether the server supports delegated attributes or not." PATCH 2/5

This fix removes an unnecessary check added in a prior commit and ensures tests function correctly on servers with varying attribute support.

Patch 3: Remove Erroneous Attribute Test

Mayhew identified a logic error in DELEG24 and DELEG25 where the test incorrectly checked for fattr4_time_deleg_modify in attrs2, which contains GETATTR reply attributes that would never include this field:

"fattr4_time_deleg_modify is valid in CB_GETATTR and SETATTR. attrs2 contains the attributes from a GETATTR reply, and will never contain the fattr4_time_deleg_modify attribute." PATCH 3/5

Jeff Layton acknowledged the error in his review:

"Doh! I don't know what I was thinking there. That should compare FATTR4_TIME_MODIFY on both sides since they're both GETATTR results. Nice catch!" Re: PATCH 3/5

Mayhew noted that a replacement comparison could be implemented by returning the cbattrs dictionary from _testCbGetattr(), but deferred this refinement.

Patch 4: Verify Received Delegation Type

The test helper _testCbGetattr() previously assumed that requesting an attribute delegation guaranteed receiving one. Mayhew added explicit verification:

"It currently assumes that if it requested an attribute delegation, then that's what it received. Better to actually check it instead." PATCH 4/5

This defensive improvement prevents false test results when servers grant different delegation types than requested.

Patch 5: New Test for CB_GETATTR After Synchronous WRITE

The final patch introduces DELEG27, a new regression test simulating a real-world application issue where an application experiences unexpected modification time updates for files it is tracking. The test scenario involves:

"DELEG27 tests the scenario where a client has written data to the server while holding a write delegation, but is not currently holding modified data in its cache." PATCH 5/5

The test validates that CB_GETATTR should not trigger an mtime update when the client has flushed its data:

"In this case, the CB_GETATTR should not trigger an mtime update (the time_modify that client1 gets in the GETATTR after the WRITE should match the time_modify it gets in the GETATTR in the DELEGRETURN compound)." PATCH 5/5

Mayhew noted that this test currently passes only when nfsd has delegated timestamps enabled, and referenced a companion kernel patch (nfsd: fix file change detection in CB_GETATTR) that fixes the underlying server behavior to comply with RFC 8881.

Conclusion

This patch series strengthens the pynfs test infrastructure by eliminating resource leaks, correcting attribute validation logic, and adding a new regression test for delegated timestamp behavior. The fixes ensure that tests accurately reflect NFSv4.1 protocol semantics and properly validate server compliance with RFC 8881. Jeff Layton's quick review and acknowledgment of his own prior error demonstrate the collaborative nature of the NFS development community in maintaining high-quality test coverage.
