exportfs: Release NFSv4 state on last client unexport

Summary

This week, Chuck Lever submitted version 2 of a patch to enhance exportfs behavior when removing NFS exports, specifically addressing a resource cleanup issue related to NFSv4 state.

Problem Statement

The core issue addressed is that when an administrator removes the last client for a given export path using exportfs -u, associated NFSv4 state (opens, locks, and delegations) may persist. This lingering state can keep the underlying filesystem busy, thereby preventing unmount operations.

As described in the patch submission:

"When exportfs -u removes the last client for a given export path, NFSv4 state (opens, locks, delegations) acquired through that export may still hold the underlying filesystem busy, preventing unmount."

Proposed Solution

The patch introduces logic to check whether any active exports remain for the same path across all client types after an export entry is removed. If no exports remain, the tool sends an NFSD_CMD_UNLOCK_EXPORT command to the kernel via generic netlink. This action revokes the associated NFSv4 state and closes cached file handles, allowing the filesystem to be unmounted cleanly.

Key technical components of this update include:

  • A new shared helper function, nfsd_nl_cmd_str(), located in support/nfs/nfsdnl.c, which manages netlink socket setup, message construction, and ACK handling for simple nfsd commands.
  • Updates to the local nfsd_netlink.h copy to include definitions for NFSD_CMD_UNLOCK_IP, NFSD_CMD_UNLOCK_FILESYSTEM, and NFSD_CMD_UNLOCK_EXPORT.
  • Conditional compilation of the helper when libnl3 is available, gated by the existing nfsdctl configure option.

Review Feedback

Jeff Layton reviewed the patch and provided a minor suggestion regarding the conditional compilation guards. He noted that netlink support has become effectively mandatory for building exportfs in recent versions.

As stated by Jeff Layton:

"I don't think you need this #ifdef. With the latest exportfs changes, netlink support is pretty much required to build."

Despite this minor observation, Layton concluded that the rest of the implementation was sound:

"The rest looks good."

He provided his review approval:

"Reviewed-by: Jeff Layton jlayton@kernel.org"

Conclusion

This patch represents a bug fix and usability improvement for NFS server administration. By ensuring that NFSv4 state is properly released when the last client is unexported, it prevents filesystems from being held busy unnecessarily, facilitating cleaner maintenance operations such as unmounting. The discussion concluded with a positive review, indicating readiness for integration pending any minor adjustments to the conditional compilation logic.
