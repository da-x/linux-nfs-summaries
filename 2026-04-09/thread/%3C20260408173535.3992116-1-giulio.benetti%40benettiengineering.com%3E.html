nfs-utils: Build Fixes for Older Linux APIs and Missing Headers

Summary

nfs-utils: Build Fixes for Older Linux APIs and Missing Headers

Type: Bug fixes (build compatibility)
Status: Patch series v2 submitted; no review feedback received within the reporting window.

Overview

Giulio Benetti submitted a three-patch series (v2) addressing build failures in the nfs-utils user-space tools when compiled against older Linux kernel headers or glibc versions. The patches target compatibility gaps that prevent successful compilation on systems with legacy API definitions, particularly around netlink extensions and random number generation interfaces.

While these changes do not alter NFS protocol behavior or client-side runtime logic, they are essential for maintaining the build integrity of NFS server utilities (including nfsdctl and export cache backends) across a wider range of Linux distributions and kernel versions.

Patch Breakdown

1. Fix Missing string.h Inclusion in fh_key_file.c

The first patch adds #include &lt;string.h&gt; to support/nfs/fh_key_file.c to resolve a build failure caused by an implicit declaration of string manipulation functions.

"Add #include <string.h> to fix build failure."

This is a straightforward, low-risk fix with no changes between v1 and v2.

2. Introduce compat.h for NETLINK_EXT_ACK Compatibility

The central patch introduces a new support/include/compat.h header to handle the absence of NETLINK_EXT_ACK in older kernel headers. This macro is used in netlink communication for extended acknowledgment messages, and its absence causes compilation errors on systems with pre-4.12-era kernel headers.

The patch defines NETLINK_EXT_ACK conditionally if it is not already present:

"In 'compat.h' check if NETLINK_EXT_ACK exists, otherwise define it to fix build failure and where at the moment <linux/netlink.h> is included let's include 'compat.h'"

The header is included in four locations:

  • support/export/cache.c
  • support/export/cache_flush.c
  • utils/nfsdctl/nfsdctl.c
  • The new support/include/compat.h itself (10 lines added)

In v2, Benetti refined the approach by replacing direct inclusion of &lt;linux/netlink.h&gt; with "compat.h" where appropriate, ensuring the compatibility shim is applied consistently.

3. Fix getrandom() Fallback in SQLite Backend

The third patch addresses a build failure in support/reexport/backend_sqlite.c related to the getrandom() system call. On older Linux/glibc combinations, the syscall number __NR_getrandom is defined in &lt;sys/random.h&gt;, which was not being included.

"In old Linux/Glibc versions __NR_getrandom is defined in <sys/random.h> so let's add it to fix build failure."

This patch was added new in v2, indicating that the issue was identified during the review cycle of the initial submission.

Significance for NFS Development

These patches are purely infrastructure-level fixes ensuring that nfs-utils remains compilable on older systems. They do not introduce new features or modify NFS protocol semantics. However, they are important for:

  • Distribution maintainers who must support a wide range of kernel versions.
  • Embedded and long-term support (LTS) environments where newer kernel headers may not be available.
  • CI/CD pipelines that test builds against multiple kernel header versions.

Conclusion

No review comments or acknowledgments were received during this week's window. The patch series represents a maintenance effort to broaden the compatibility footprint of NFS user-space tools. If accepted, these changes will eliminate build barriers for users on older Linux systems without impacting runtime behavior or protocol compliance.
