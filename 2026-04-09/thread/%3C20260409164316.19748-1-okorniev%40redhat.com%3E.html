NFSd: Fix mtime/ctime updates for CLONE/COPY with Delegated Attributes

Summary

This week, Olga Kornievskaia submitted version 3 of a two-patch series to address a bug in the NFS server (nfsd) where modification times (mtime) and change times (ctime) were not being updated correctly for CLONE and COPY operations when delegated attributes were present.

The Problem

When a client holds a WRITE_ATTRS delegation, the server opens the file with NOCMTIME to prevent race conditions between the client's cached view and the server's state. However, this mechanism inadvertently prevented the server from updating timestamps for CLONE and COPY operations, which modify the destination file on the server side. This inconsistency caused failures in the generic/407 xfstest suite.

"generic/407 is failing in presence of delegated attributes and this patch series explores the solution where the CLONE compound returns updated mtime/ctime in the GETATTR op in the compound." Olga Kornievskaia

The Solution

The series introduces logic to explicitly update mtime and ctime on the destination file for both CLONE and COPY operations, even when a delegation is active.

  • Patch 1/2: Updates mtime/ctime for CLONE. It extracts shared code from nfsd4_finalize_deleg_timestamps to handle notify_change() errors consistently.
  • Patch 2/2: Updates mtime/ctime for COPY. This patch consolidates synchronous and asynchronous copy paths into a single implementation, simplifying the logic by pulling the dentry directly from the file handle path.

"Both CLONE and COPY need to update destination file mtime/ctime (in presence of delegated timestamp) when file was modified." Olga Kornievskaia

Review and Feedback

Jeff Layton provided a Reviewed-by for the series, noting: "Nice work." Jeff Layton

Chuck Lever provided detailed code review comments for both patches:

For the COPY patch (2/2):

  • He requested that the rationale in the commit message match the detail provided in the CLONE patch.
  • He pointed out a potentially stale comment regarding dget/dput since the new code no longer uses them.
  • He questioned whether an FMODE_NOCTIME guard was necessary for the update logic, suggesting that if the flag is cleared later, the update might be skipped. Olga responded by discussing alternatives:

"Yeah I realized that now checking for the flag might mean that if the flag gets cleared we won't do the update... Alternatively, I thought it would not be harmful to always update the c/mtime upon completion regardless of the delegation? Do you want me to add the do-the-update flag instead?" Olga Kornievskaia

  • He suggested moving the struct iattr definition into a helper function to reduce duplication.

For the CLONE patch (1/2):

  • He suggested a code style improvement for the conditional check:

"Let's write this: if (!status && ((READ_ONCE(dst->nf_file->f_mode) & FMODE_NOCMTIME) != 0))" Chuck Lever

  • He recommended moving the new nfsd_update_cmtime_attr function from a static inline in state.h to fs/nfsd/nfs4state.c with proper kernel-doc comments, stating: "This is a little much for a static inline function." Chuck Lever

Conclusion

The patch series represents an important bug fix for NFSv4.1/4.2 clients and servers using delegations with CLONE and COPY. The technical approach is sound, but minor code organization and logic clarifications are requested by the maintainer before final integration.
