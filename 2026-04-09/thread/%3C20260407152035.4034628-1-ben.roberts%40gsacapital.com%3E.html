pNFS: Deadlock Fix in pnfs_send_layoutreturn (Build Error Reported)

Summary

This week, a patch addressing a critical deadlock in the Parallel NFS (pNFS) client subsystem was submitted and immediately flagged for a syntax error by automated testing.

Issue Classification: Bug Fix

The discussion centers on [PATCH] pNFS: deadlock in pnfs_send_layoutreturn submitted by Ben Roberts, aimed at resolving a production-issue causing system hangs on HPC clusters.

Technical Arguments and Context

Ben Roberts reported that on an HPC cluster running kernel 5.14.0-611.9.1.el9.x86_64, regular deadlocks occurred within pnfs_send_layoutreturn. These deadlocks left userspace processes stuck in uninterruptible sleep (D-state), often requiring reboots to resolve. The issue manifested frequently under heavy load.

Roberts identified a recursive deadlock condition triggered by memory allocation failures:

  1. pnfs_send_layoutreturn() calls kzalloc(), which fails.
  2. The error path invokes pnfs_put_layout_hdr(lo).
  3. This triggers pnfs_layoutreturn_before_put_layout_hdr().
  4. If the NFS_LAYOUT_RETURN_REQUESTED flag remains set, the system attempts another layout return, creating a recursive loop or deadlock.

"The fix ensures that NFS_LAYOUT_RETURN_REQUESTED is cleared in the allocation failure path before calling pnfs_put_layout_hdr(). This prevents pnfs_layoutreturn_before_put_layout_hdr() from attempting another layout return, breaking the recursion cycle."

Roberts noted that this one-line patch had been running in production on top of the EL9 kernel for over three months without recurrence. The patch was assisted by AI ("Assisted-by: Claude:claude-sonnet-4-5").

Evolution of the Discussion

The thread saw immediate feedback from the kernel test robot in this automated reply. The automated build system detected a compilation error when applying the patch to multiple trees, including trondmy-nfs/linux-next and linus/master.

The error was a simple syntax mistake: a missing semicolon after the function call pnfs_clear_layoutreturn_info(lo).

">> fs/nfs/pnfs.c:1364:35: error: expected ';' after expression 1364 | pnfs_clear_layoutreturn_info(lo) | ^ | ;"

Final Conclusions

As of the end of this week's window, the patch has been identified as logically sound for resolving a severe production deadlock but contains a trivial syntax error that prevents it from compiling. The maintainer or author will need to issue a v2 of the patch with the missing semicolon added to proceed with integration into the mainline NFS tree.

This highlights the importance of local compilation testing before submission, even for small patches addressing critical runtime issues in the NFS client infrastructure.
