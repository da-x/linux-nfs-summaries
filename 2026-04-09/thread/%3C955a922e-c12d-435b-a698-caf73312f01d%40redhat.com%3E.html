Summary

nfs-utils 2.9.1 Released: NFSv4.0 Disabled by Default, netlink Upcalls, and Signed Filehandles

This week, Steve Dickson announced the release of nfs-utils 2.9.1, a minor version update that introduces significant changes to the NFS server-side behavior and infrastructure ANNOUNCE: nfs-utils-2.9.1 released.

Release Classification

This thread is a release announcement encompassing both feature additions and bug fixes, with implications for NFS client-server compatibility and server administration.

Key Changes in nfs-utils 2.9.1

Steve Dickson outlined four primary changes in the release:

"This release contains a minor version being disabled (which is why the minor release was bumped), new features and a bug fix"

The specific changes are:

1. NFSv4.0 Disabled by Default on the Server

A notable protocol-level change is that NFSv4.0 is turned off on the server by default. This decision reflects the industry's ongoing shift toward newer NFSv4 minor versions (such as NFSv4.1 and NFSv4.2), which offer improved performance, security, and feature sets—including pNFS support, server-side copy, and space reservation. By disabling v4.0 by default, administrators are encouraged to migrate clients to more modern protocol versions.

2. netlink for Upcalls in exportfs, exportd, and mountd

The release introduces netlink as the mechanism for upcalls in key NFS server utilities: exportfs, exportd, and mountd. This modernization replaces older IPC mechanisms with netlink sockets, offering improved reliability, performance, and integration with the Linux kernel's networking subsystem.

3. Signed Filehandle Support

Signed filehandle support was added, enhancing security by ensuring that file handles cannot be forged or tampered with by clients. This is an important hardening measure for NFS deployments, particularly in multi-tenant or cloud environments where trust boundaries are critical.

4. nfsdctl Listener Check Before Starting

A bug fix ensures that nfsdctl now checks for listeners before starting, preventing potential issues where the NFS daemon might start without proper network listeners configured. This improves operational robustness and reduces misconfiguration-related outages.

Availability

The release tarballs are available at:

  • https://www.kernel.org/pub/linux/utils/nfs-utils/2.9.1/
  • http://sourceforge.net/projects/nfs/files/nfs-utils/2.9.1

The changelog and git tree were also provided for reference.

Significance for NFS Client Development

While this announcement is server-focused, the changes have direct implications for NFS client developers and administrators:

  • NFSv4.0 deprecation by default means clients must ensure they are running at least NFSv4.1 or later to maintain compatibility with updated servers.
  • Signed filehandles may require client-side support for validating signed handles, particularly in security-sensitive deployments.
  • The netlink upcall infrastructure improves server responsiveness and reliability, indirectly benefiting client performance.

This release represents a continued effort to modernize the NFS ecosystem, pushing both clients and servers toward more secure, performant, and maintainable configurations.
