nfs: use memcpy_and_pad in decode_fh

Summary

A Minor Code Simplification in NFS Callback XDR Decoding

This week saw a small but clean patch submitted by Thorsten Blum targeting the NFS client's callback XDR decoding logic. The discussion is best classified as a code cleanup / minor bug-prevention improvement rather than a new feature or protocol change.

The Patch

Thorsten Blum submitted a one-patch series titled:

"Use memcpy_and_pad() instead of memcpy() followed by memset() to simplify decode_fh()."

The patch targets fs/nfs/callback_xdr.c, replacing a two-step operation (memcpy followed by memset) with the kernel helper memcpy_and_pad(). This is part of an ongoing effort across the kernel to consolidate copy-and-pad patterns into a single, safer helper function. The change touches only 1 insertion and 2 deletions, making it a minimal but meaningful improvement.

Technical Context

The decode_fh() function is responsible for decoding NFS file handles in callback XDR (External Data Representation) operations. Callbacks are used by the NFS server to communicate with the client — for example, to recall delegations or notify of layout changes in NFSv4/pNFS. Properly handling variable-length file handles requires copying the handle data and zero-padding any remaining bytes to maintain alignment and prevent information leaks.

Using memcpy_and_pad() instead of a manual memcpy + memset sequence:

  • Simplifies the code, reducing it from two operations to one.
  • Reduces the risk of bugs such as incorrect padding lengths or missing zero-initialization, which could lead to information leaks or undefined behavior.
  • Improves consistency with other parts of the kernel that have already adopted this helper.

Discussion and Outcome

There were no replies or further discussion on this patch during the week ending 2026-04-09. The patch stands alone as a straightforward cleanup submission, awaiting review and potential merge by the NFS maintainers.

Given its small scope and clear intent, this change represents the kind of incremental improvement that strengthens the NFS client codebase over time — eliminating redundant code paths and reducing surface area for future bugs in critical XDR decoding routines.
