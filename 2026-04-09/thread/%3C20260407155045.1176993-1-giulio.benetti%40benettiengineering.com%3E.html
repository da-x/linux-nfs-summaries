Introduce compat.h to fix NETLINK_EXT_ACK build failure on older kernels

Summary

Build Compatibility Fix: Introducing compat.h for Older Linux APIs

Overview

This thread contains a single patch submission from Giulio Benetti addressing a build failure in the NFS utils codebase when compiled against older Linux kernels. The issue is classified as a bug fix, specifically targeting compatibility with legacy kernel APIs that lack the NETLINK_EXT_ACK definition.

The Problem

The NFS utils source tree encountered compilation errors on systems with older Linux kernel headers where the NETLINK_EXT_ACK constant was not defined. This breakage affected multiple components of the NFS server-side tooling, including:

  • support/export/cache.c
  • support/export/cache_flush.c
  • utils/nfsdctl/nfsdctl.c

The Fix

Giulio Benetti proposed a clean solution by introducing a new compatibility header file, compat.h, located at support/include/compat.h. This header checks whether NETLINK_EXT_ACK is already defined by the system headers; if not, it provides a fallback definition. As described in the patch:

"Check if NETLINK_EXT_ACK exists, otherwise define it to fix build failure."

The patch modifies four files with a total of 15 insertions, including the creation of the new compat.h header. This approach centralizes compatibility logic into a single, maintainable location rather than scattering #ifdef guards across multiple source files.

Significance for NFS Client/Server Development

While this fix primarily impacts NFS server-side utilities (nfsdctl and export cache management), it is important for overall NFS ecosystem stability. Build failures on older kernel configurations can prevent users from deploying or maintaining NFS services, particularly in enterprise environments where long-term support kernels are common. By introducing a dedicated compatibility layer, this patch sets a precedent for handling future API discrepancies in the NFS utils codebase.

Conclusion

The patch was submitted without any replies during this week's window. As a straightforward build fix with minimal risk, it represents a maintenance-level improvement to ensure broader kernel compatibility across the NFS toolchain.
