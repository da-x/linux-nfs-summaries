nfsd: Fix file change detection in CB_GETATTR per RFC 8881

Summary

nfsd: Fix File Change Detection in CB_GETATTR

This thread concerns a bug fix for the NFS server's handling of delegation callbacks, specifically regarding how it detects whether a delegated file has been modified. The patch addresses a deviation from RFC 8881 that could lead to incorrect metadata updates and unnecessary delegation recalls.

The Problem

Scott Mayhew identified that the existing implementation incorrectly cached the file size in the delegation record and compared this cached size against the size reported by the client in the CB_GETATTR reply. This approach violated RFC 8881, Section 10.4.3, which mandates a different behavior.

Mayhew explained the protocol requirement:

"RFC 8881, section 10.4.3 doesn't say anything about caching the file size in the delegation record, nor does it say anything about comparing a cached file size with the size reported by the client in the CB_GETATTR reply for the purpose of determining if the client holds modified data for the file."

Instead, the RFC requires the server to compare the current file size (as seen by the server) with the size reported by the client. Mayhew highlighted the negative consequences of the previous logic:

"Doing otherwise would cause the server to believe the client holding the delegation has a modified version of the file, even if the client flushed the modifications to the server prior to the CB_GETATTR."

This bug had a significant side effect: it caused subsequent CB_GETATTR callbacks to trigger updates to the mtime, ctime, and change attributes even when the client had made no further changes to the file.

The Fix

The patch modifies nfsd4_deleg_getattr_conflict() to obtain the current file size via i_size_read() rather than relying on a cached value stored in the delegation record. While the ncf_cur_fsize field is retained for encoding attributes, it is no longer used for change detection logic. Additionally, the patch removes unnecessary initialization of this field in nfs4_open_delegation() and skips certain checks if the delegation is recalled due to a client timeout.

Mayhew noted that the fix applies cleanly to several LTS kernels:

"Chuck - if you want this to go to stable, it applies cleanly against 6.17.y, 6.18.y, and 6.19.y."

Conclusion

Chuck Lever accepted the patch into the nfsd-testing tree, acknowledging the importance of the fix for long-term support kernels:

"Applied to nfsd-testing, thanks! And, thanks for confirming applicability to LTS kernels. Cc: stable@ added."

The commit 17a5b972dbf1 ensures that the NFS server correctly adheres to RFC 8881, preventing spurious metadata updates and improving delegation stability.
