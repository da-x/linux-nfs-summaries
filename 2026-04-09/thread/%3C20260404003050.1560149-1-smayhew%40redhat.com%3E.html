pynfs: Fixes and new CB_GETATTR delegation test

Summary

Scott Mayhew submitted a five-patch series to the pynfs NFS testing framework, comprising both bug fixes for existing delegation tests and a new test case designed to validate server behavior regarding callback attribute updates. The series addresses issues in how the test suite handles cleanup, attribute support checks, and timestamp comparisons, culminating in a new test (DELEG27) that simulates a real-world application scenario.

Cleanup and Robustness Fixes

The series begins with an emphasis on ensuring tests leave the server in a clean state. Mayhew noted that his NFS server was taking longer to exit grace mode after running pynfs because several client IDs were stuck waiting for reclaim. He observed:

"I noticed my server was taking longer to exit grace on restart after running pynfs. The server was waiting for several clients (which have already gone away) to finish reclaim."

These stale client IDs resulted from tests failing to close open files, causing DESTROY_CLIENTID to return NFS4ERR_CLIENTID_BUSY. While older servers would eventually expire these leases, Mayhew warned that "with the newer courteous server they may stick around indefinitely, so it's important for the tests to clean up after themselves" PATCH v2 1/5.

Correcting Attribute Support Checks

Patch 2 fixes a bitwise check in the DELEG24 and DELEG25 tests. The code was incorrectly checking for FATTR4_OPEN_ARGUMENTS support without shifting the bit, as fattr4_supported_attrs is a bitmap. Mayhew explained:

"The DELEG24 and DELEG25 tests should work regardless of whether the server supports delegated attributes or not. fattr4_supported_attrs is a bitmap4, so FATTR4_OPEN_ARGUMENTS needs to be shifted when checking to see if that bit is set" PATCH v2 2/5.

Validating Delegation Types and Timestamps

Patch 3 improves the _testCbGetattr() helper by verifying that the delegation type received matches the one requested, rather than assuming an attribute delegation was granted if one was asked for PATCH v2 3/5.

Patch 4 addresses a more subtle bug in DELEG24 and DELEG25. The tests were erroneously checking for fattr4_time_deleg_modify in a GETATTR reply, where it does not appear. Mayhew clarified:

"fattr4_time_deleg_modify is valid in CB_GETATTR and SETATTR. attrs2 contains the attributes from a GETATTR reply, and will never contain the fattr4_time_deleg_modify attribute. Instead, we want to compare fattr4_time_modify from attrs1 and attrs2" PATCH v2 4/5.

This fix also required careful handling of nfstime4 objects to avoid inadvertently modifying source data during initialization, and the use of the existing compareTimes() function for accurate timestamp comparison.

New Test: CB_GETATTR after Sync WRITE

The final patch introduces DELEG27, a new test case motivated by a practical application issue. Mayhew described the scenario:

"Patch 5 simulates an actual application issue where the application is failing because it's getting a unexpected/surprise mtime update for a file that it's tracking" PATCH v2 0/5.

The test verifies that when a client writes data while holding a write delegation but has no modified data in its cache, the server's CB_GETATTR callback should not trigger an mtime update. Specifically, the time_modify received after the WRITE should match the time_modify received during the DELEGRETURN compound PATCH v2 5/5.

Mayhew later sent a minor correction to the subject line of the final patch, noting: "My bad, the subject should say [PATCH v2 5/5]..." Re: PATCH v2.

Conclusion

This series represents significant maintenance for the pynfs test suite, fixing several bugs that could lead to false negatives or server state corruption during testing. The addition of DELEG27 enhances coverage for delegation callback behavior, ensuring servers correctly handle mtime updates in scenarios relevant to application performance and correctness.
