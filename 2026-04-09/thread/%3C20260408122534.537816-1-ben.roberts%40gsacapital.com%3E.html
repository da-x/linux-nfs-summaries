pNFS: Deadlock fix in pnfs_send_layoutreturn withdrawn after review

Summary

pNFS: Deadlock in pnfs_send_layoutreturn — Patch Withdrawn After Review

Overview

This thread concerns a bug fix proposed by Ben Roberts of GSA Capital to address a recurring deadlock in the Parallel NFS (pNFS) client's layout return path. The patch, submitted as v2 on April 8, was ultimately withdrawn after maintainer review raised concerns about its correctness against upstream code.

The Reported Problem

Ben Roberts reported that his HPC cluster, running Red Hat Enterprise Linux 9 kernel 5.14.0-611.9.1.el9.x86_64, experienced regular deadlocks within pnfs_send_layoutreturn(), causing userspace processes to become stuck in uninterruptible sleep and requiring reboots:

"On a HPC cluster running 5.14.0-611.9.1.el9.x86_64, regular deadlocks were seen within pnfs_send_layoutreturn leading to userspace processes stuck in uninterruptible sleep, ultimately requiring reboots to clear."

The proposed fix was a single-line change: clearing the NFS_LAYOUT_RETURN_REQUESTED flag in the memory allocation failure path of pnfs_send_layoutreturn() before calling pnfs_put_layout_hdr(). Roberts noted that this patch had been running in production for over three months without recurrence.

Maintainer Pushback

Benjamin Coddington, responding on April 10 (just outside the weekly window), questioned whether the issue was reproduced on a recent upstream kernel:

"Did you reproduce and diagnose this problem on a recent upstream kernel version? If not, you probably want to report the issue to your Red Hat support channel directly instead of sending fixes upstream because the maintainers will want to see patches and fixes against the upstream code."

Revised Analysis and Race Condition Theory

Unable to reproduce the issue on newer kernels without risking production systems, Roberts refined his theory. He ruled out a single-process recursive deadlock and instead proposed an inter-process race condition:

"Revised theory for why this patch helps is that the deadlock is subject to an inter-process race, where one process suffers a memory allocation failure, causing a second process to become a victim of bad state, leading to an unserviceable RPC request. The timing appears to be very sensitive and hard to reproduce on demand."

He provided a detailed LLM-assisted analysis describing how Thread A's allocation failure would wake Thread B via pnfs_clear_layoutreturn_waitbit(), but fail to clear the NFS_LAYOUT_RETURN_REQUESTED flag, causing Thread B to initiate an RPC on corrupted layout state. Roberts included a stack trace showing processes deadlocked in rpc_wait_bit_killable() during NFS superblock teardown.

Technical Rebuttal

Coddington countered that the analysis did not hold for upstream code:

"The kzalloc failure is definitely a rarely-used/tested path, so its possible there's an issue there no one has seen yet, but from what I can see it looks like every call to pnfs_send_layoutreturn() first calls pnfs_prepare_layoutreturn(), which already clears NFS_LAYOUT_RETURN_REQUESTED. I don't see how you can end up with another process seeing the flag."

Coddington also noted that Roberts' systems lacked a significant body of upstream pNFS work from June 2024, and again recommended engaging Red Hat support.

Patch Withdrawn

Roberts accepted the feedback and withdrew the patch:

"Understood, thank you for the feedback here. I withdraw the patch request and will take this back to the drawing board. Likely removing the patch from local systems and looking to capture more useful diagnostics if/when the problem reoccurs."

He also noted that most of the referenced upstream changes were already present in the EL9 kernel source, with only partial application of one patch.

Final Word from Trond Myklebust

NFS maintainer Trond Myklebust added a technical note, revealing he had initially applied the patch but then reconsidered:

"I had first applied this patch, however when looking more closely, it seems that it will also be defeated by the loop in pnfs_clear_layoutreturn_info() that checks if there are any layouts that need returning, and resets NFS_LAYOUT_RETURN_REQUESTED."

Conclusion

The patch was not accepted. The discussion highlights the challenges of diagnosing race conditions in production environments running older kernel versions, and underscores the importance of validating fixes against upstream code. The root cause of Roberts' deadlocks remains unresolved, with plans to gather more diagnostics on the affected systems.
