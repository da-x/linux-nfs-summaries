NFS Week: Directory Delegation CB_NOTIFY, CLONE/COPY Timestamp Fixes, pNFS Deadlock Patch, and close() Semantics Debate

Week ending 2026-04-09

Overview

This week saw intense activity around NFS delegation infrastructure, with major feature development for directory delegation notifications, a flurry of critical bug fixes for delegated attribute handling in CLONE/COPY operations, and important client-side stability patches. The nfs-utils 2.9.1 release also marked a milestone in server-side modernization.

Critical Bug Fixes

pNFS Deadlock in pnfs_send_layoutreturn

Ben Roberts submitted a patch fixing a production deadlock in the Parallel NFS (pNFS) client that caused system hangs on HPC clusters (thread). The issue arose when memory allocation failures in pnfs_send_layoutreturn() triggered a recursive layout return loop, leaving processes stuck in uninterruptible sleep (D-state). A v2 was issued to fix a missing semicolon flagged by the kernel test robot. This is a critical stability fix for pNFS deployments.

NFS Client: RENAME Attribute Staleness with Directory Delegations

Olga Kornievskaia fixed a regression where mtime/ctime were not updated after RENAME operations when directory delegations were active, causing xfstest generic/309 failures (thread). Benjamin Coddington reviewed and the patch is ready for integration.

NFS Client: RCU and Tracing Pointer Safety

Sean Chang submitted a two-patch series addressing Sparse static analysis warnings in the NFS client (thread). The fixes ensure proper RCU protection when accessing cl_xprt pointers and correct tracepoint field types to prevent potential use-after-free bugs during concurrent transport updates.

NFS Client: Session Size Limits on Clone Path

Tushar Sariya addressed a regression where the NFSv4.1 automount clone path skipped session size clamping, causing EIO errors on Dell EMC Isilon/OneFS servers (thread). The fix applies the same rsize/wsize limits to cloned servers as top-level mounts.

nfsd: GET_DIR_DELEGATION Error Handling

Olga Kornievskaia fixed incorrect error codes returned by GET_DIR_DELEGATION when VFS leases are disabled, ensuring all failure modes return NFS4ERR_GDD4_UNAVAIL (thread). Applied to nfsd-testing by Chuck Lever.

nfsd: CB_GETATTR File Change Detection

Scott Mayhew corrected the server's file modification detection logic during CB_GETATTR callbacks to comply with RFC 8881, preventing false positives that caused unnecessary metadata updates (thread).

Major Feature: CB_NOTIFY for Directory Delegations

Jeff Layton submitted a 24-patch series implementing server-side support for CB_NOTIFY callbacks in directory delegations (thread). This feature, per RFC 8881bis, allows NFS clients to receive asynchronous notifications about directory changes (creates, unlinks, renames) without losing their delegation. The series touches VFS file locking, fsnotify, and nfsd callback infrastructure.

Chuck Lever's thorough review uncovered four issues:

  1. Spurious blocking in __break_lease() due to unfiltered ignored leases
  2. Stale fsnotify mask bits on delegation removal
  3. Missing handling of FS_RENAME_FROM/FS_RENAME_TO for cross-directory renames
  4. Queued events not being flushed after callback completion

Layton acknowledged all issues and plans a follow-up version after the testing window. The series won't merge until a complete client-side implementation exists for testing.

Ongoing Debate: CLONE/COPY Timestamp Handling with Delegated Attributes

A significant multi-thread effort this week focused on fixing mtime/ctime updates for NFSv4.2 CLONE and COPY operations when delegated attributes are present. The root cause is that files opened with write attribute delegations use the NOCMTIME flag, which inadvertently suppressed timestamp updates for server-side copy operations, breaking xfstest generic/407.

Server-side fix (nfsd): Olga Kornievskaia submitted three iterations of a patch series (v1, v2, v3). Chuck Lever identified race conditions in the initial approach and a dentry refcount underflow in the async COPY path. Jeff Layton provided Reviewed-by on v3, with minor code organization feedback remaining.

Client-side fix (NFS): Parallel patches for NFSv4.2 client CLONE (thread) and COPY (thread) attribute handling were discussed, with Jeff Layton advocating for server-side fixes as the primary solution and GETATTR in compounds as a secondary measure.

NFSD State Revocation Infrastructure

Chuck Lever posted v8 of a 9-patch series introducing netlink-based NFSv4 state revocation commands (thread). The series provides three netlink commands (NFSD_CMD_UNLOCK_IP, NFSD_CMD_UNLOCK_FILESYSTEM, NFSD_CMD_UNLOCK_EXPORT) for fine-grained state revocation, replacing legacy procfs interfaces. It also fixes two pre-existing bugs: an infinite loop in layout state revocation and missing cleanup of revoked layout stateids. Jeff Layton reviewed all patches positively.

A companion patch for exportfs (thread) adds logic to release NFSv4 state when the last client is unexported, preventing filesystems from being held busy.

Ongoing Debates

NFS close() Semantics During Server Unavailability

Jon Curley (Pure Storage) raised concerns that close() returns success while writes are in a failure loop, potentially causing operation reordering bugs (thread). Trond Myklebust clarified that close() intentionally uses lighter-weight flushing than fsync() to avoid live locks, but Curley demonstrated real application failures due to write/truncate reordering. No resolution reached this week.

Al Viro Reviews Directory Delegation Verifier Code

VFS maintainer Al Viro re-engaged with the long-running directory delegation verifier thread (thread), raising concerns about potential use-after-free on inode iteration, questioning cursor semantics in NFS directories, and providing detailed dentry lifetime analysis. He urged NFS developers to consult the broader fsdevel community for VFS-related subtleties.

RWF_DONTCACHE Write Performance

Jeff Layton submitted v2 of a series to improve RWF_DONTCACHE write performance by offloading flusher work from the writer's hot path (thread). Christoph Hellwig and Jan Kara raised concerns that waking the entire BDI flusher is too coarse-grained, proposing targeted DONTCACHE folio tracking instead. The architectural debate remains unresolved.

Releases and Tooling

nfs-utils 2.9.1 was released (thread), featuring NFSv4.0 disabled by default on the server, netlink upcalls for exportfs/exportd/mountd, and signed filehandle support.

pynfs test framework updates were submitted by Scott Mayhew to ensure tests clean up after themselves and fix delegated attribute support checks (thread).

Other Notable Activity

  • NFSD XDR padding: Hiroyuki Sato identified uninitialized memory in COMPOUND reply tag padding; Chuck Lever encouraged a formal patch submission (thread).
  • Code cleanup: Thorsten Blum simplified decode_fh() using memcpy_and_pad() (thread).
  • Block layout exports cleanup: Christoph Hellwig's series to clean up block-style layout exports continued under review (thread).
