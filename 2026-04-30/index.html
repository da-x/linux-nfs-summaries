NFS client 7.1 pull merged; critical mkdir regression fixed; pNFS, SUNRPC, and Kerberos hardening continue

Week ending 2026-04-30

NFS Client Pull for Linux 7.1 Merged

Trond Myklebust's GIT PULL request for NFS client updates targeting Linux 7.1 was merged this week. The pull covers 25 files with 443 insertions and 215 deletions, focusing on bug fixes across delegation handling, write error recovery, pNFS layout management, and RDMA transport (xprtrdma) reliability. Notable highlights include synchronous write fallback for ENOSPC conditions, fixes for delegated timestamp handling in CLONE/COPY operations, and seven xprtrdma patches from Chuck Lever addressing sendctx races and backlog wakeup delays.

Critical Bug Fixes

NFSv4 mkdir Regression: Spurious -EEXIST After DELAY Retry

A significant regression was reported by Igor Raits where mkdir(2) returned -EEXIST even though the directory was successfully created on the server. The issue occurred when the server returned NFS4ERR_DELAY followed by success — the client would then send a third CREATE RPC and surface the resulting NFS4ERR_EXIST to userspace. Root cause analysis traced the bug to commit dd862da61e91, which added a conditional guard around nfs4_handle_exception(), preventing exception-state cleanup on successful retries. Igor submitted a targeted fix restoring the unconditional call, reviewed and endorsed by NeilBrown with a Cc: stable tag.

pNFS LAYOUTCOMMIT Infinite Retry Loop on OLD_STATEID

Lei Yin reported that the NFSv4.1/pNFS client could enter an unbounded retry loop during LAYOUTCOMMIT when the server returned -NFS4ERR_OLD_STATEID. The fix ensures the layout state ID is refreshed before retrying, preventing I/O hangs on affected files under high-concurrency workloads.

pNFS/filelayout Striped Layout Detection

Sagi Grimberg submitted a one-line fix correcting how the client determines whether a pNFS file layout is striped. The previous check used num_fh > 1, which fails for deployments where MDS and DSs share a single filehandle (e.g., "vast" storage backends). The fix uses stripe_count > 1 as the correct indicator.

SUNRPC Cache Slab-Out-of-Bounds Read

Alessandro Zanni reported a slab-out-of-bounds read in cache_seq_start_rcu() triggered when the hash index exceeded hash_size. Chuck Lever confirmed an equivalent fix was already in his testing tree.

NFS Server Use-After-Free in cache_check_rcu() Persists

Misbah Anjum N confirmed that the use-after-free bug in cache_check_rcu() originally reported in February has propagated into mainline (kernel v7.0), affecting both ppc64le and ARM64. Chuck Lever indicated a patch series addressing all remaining instances of this UAF class is nearly complete.

AUTOSEL Stable Backports: NLM Shutdown Race and Writeback Livelock

Two important fixes were backported to stable kernels (7.0/6.6):

  • NLM shutdown race: A use-after-free in the sysfs NLM shutdown path, fixed by introducing nlmclnt_shutdown_rpc_clnt() with proper mutex synchronization.
  • Writeback livelock: An infinite retry loop when servers return ENOSPC or commit verifier mismatches, resolved by forcing synchronous writes under error conditions via a new NFS_CONTEXT_WRITE_SYNC flag.

See AUTOSEL backports for details.

Major Development Efforts

VFS/NFS: Lifting Lookup Out of Exclusive Directory Lock

Neil Brown posted v3 of a 19-patch series preparing to move d_alloc_parallel() and related lookup operations outside the directory's exclusive i_rwsem lock. This major concurrency improvement introduces new VFS primitives (d_alloc_noblock(), d_duplicate(), enhanced d_splice_alias()) and updates NFS client paths for atomic open, link, silly-rename, and dcache priming. The series attracted extensive review from Al Viro, Amir Goldstein, and Linus Torvalds. A critical bug in the OverlayFS patch was identified and fixed. However, Neil reported a deadlock during NFS client testing against an XFS server, putting the series on hold pending further investigation.

NFSd CB_NOTIFY for Directory Delegations

Jeff Layton posted v3 of a 28-patch series adding CB_NOTIFY callback support for directory delegations to nfsd. This enables clients to receive notifications about creates, unlinks, and renames without losing their lease. Chuck Lever provided an Ack; the series awaits client-side implementation for full integration testing.

Kerberos Security Hardening: Migrate rpcsec_gss_krb5 to crypto/krb5

Chuck Lever submitted an 18-patch series migrating the NFS client's rpcsec_gss_krb5 module from its private Kerberos 5 crypto implementation to the common kernel crypto/krb5 library. This reduces the audit surface by ~3,450 lines and enables automatic propagation of new encryption types and hardware offload capabilities. Jeff Layton provided a Reviewed-by tag; patches were applied to nfsd-testing.

lockd TEST Lock Fix for Read-Only File Descriptors

Chuck Lever submitted v3 of a fix (originally by Neil Brown) correcting lockd's handling of F_GETLK on read-only file descriptors. The bug, exposed by recent NFSD permission refinements, caused applications like QEMU to fail when testing write locks on read-only NFS images.

Field Issues and Troubleshooting

NFS4ERR_SEQ_MISORDERED Causing Severe Client Slowdown

Rik Theys reported extreme slowness on a Rocky 8 client against a RHEL10 server, with packet captures showing frequent NFS4ERR_SEQ_MISORDERED errors. Expert diagnosis by Olga Kornievskaia traced the issue to a server-side bug in SEQUENCE replay handling that sent an incorrect maxslots value, causing the client to discard slot sequence state. The fix is available in RHEL10.2 and CentOS 6.12.0-201+ kernels.

NFS Client Processes Stuck in D State

Rik Theys also reported processes stuck in uninterruptible sleep (D state) under memory pressure on the same RHEL10 server infrastructure. Blocked tasks were observed in writeback waits, inode lookup waits, and RPC execution hangs. No community response was received this week.

ktls-utils Breakage with NFS Keyring

Sagi Grimberg reported a regression in ktls-utils when using the .nfs keyring for client certificate management, bisected to a commit adding dual-certificate support. Chuck Lever escalated triage to the ktls-utils maintainers.

Other Notable Activity

  • NFS mount option redaction: Sagi Grimberg proposed redacting cert_serial and privkey_serial from mount output to prevent credential metadata leakage.
  • Delegation optimization RFC: Sagi Grimberg proposed keeping delegations post-REMOVE when the server supports NFS4_OPEN_RESULT_PRESERVE_UNLINKED.
  • Case folding exposure: Two versions (v11 and v12) of a 15-patch series for exposing case-folding behavior were posted.
  • pynfs 0.5 was tagged and released, advancing NFS testing infrastructure.
