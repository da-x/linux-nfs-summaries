NFSD Block Layout Cleanup v3: Resend Logistics Follow-Up

Summary

This week's activity on the NFSD block layout export cleanup thread was minimal, consisting solely of administrative correspondence regarding a patch series resend. The substantive technical discussion and patch submission occurred in the prior week (ending 2026-04-23), when Chuck Lever posted v3 of Christoph Hellwig's four-patch series to refactor NFSD's block-style layout export infrastructure.

Bridge to Prior Week

Last week, Lever submitted Hellwig's v3 series under the subject "[PATCH v3 0/4] cleanup block-style layouts exports." The series comprises:

  1. Patch 1/4: Always ignore loca_time_modify — a protocol-compliance correction ensuring NFSD explicitly ignores client-provided timestamps during layout commits, per RFC 8881 Section 18.42.
  2. Patch 2/4: Split out operations for layout-based block device access — introducing include/linux/exportfs_block.h to separate block layout-specific operations from general export machinery.
  3. Patch 3/4: Don't pass struct iattr to ->commit_blocks — simplifying the callback interface to pass only the new file size.
  4. Patch 4/4: Rework checking for layout-based block device access support — lifting hard-coded checks into filesystem-level helpers, preparing for multi-device block layout exports.

The series was submitted with the understanding that it would flow through Christian Brauner's VFS tree via a dedicated vfs.nfsd subtree, following a procedural agreement reached earlier in April. As Lever explained in the cover letter:

"Christian prefers to see them taken through the VFS tree. Once the patches are applied there, I will rebase nfsd-next and nfsd-testing on that tree and drop these."

This Week's Activity

The only activity this week was a brief exchange between Hellwig and Lever concerning duplicate resends of the patch series:

  • Christoph Hellwig inquired:

"I got two resends of my series without cover letters in my inbox. Was this just an accident in sending out some internal tree?"

  • Chuck Lever responded:

"The first resend picked up the wrong patch set, and was a mistake. The purpose of the second resend was to transfer ownership of this series to Christian, including fixes and forward porting changes. The cover letter was not included in the repost because it is not committed to the new branch."

Classification

This thread concerns an infrastructure refactoring with a minor protocol-compliance correction component. No new features or traditional bug fixes are introduced; rather, the series reorganizes code structure and ensures correct handling of NFSv4.2 block layout commit semantics.

Significance for NFS Client Development

For NFS client developers, this refactoring has several implications:

  1. Timestamp handling: The explicit ignoring of loca_time_modify ensures that client-provided timestamps during PNFS block layout commits do not conflict with server-side multi-grain timestamp semantics (particularly on XFS), preventing potential data integrity issues or unexpected attribute changes.

  2. Layout support gating: The reworked support checks ensure that clients receive accurate information about filesystem-level block layout capabilities, preventing failed LAYOUTGET operations or incorrect assumptions about server support.

  3. Future multi-device support: The infrastructure changes prepare for future multi-device block layout exports, which may affect how clients handle layout segments spanning multiple devices.

Final Conclusions

The v3 cleanup series remains pending integration through the VFS tree. No further technical discussion occurred this week; the exchange was purely logistical. The series is expected to be merged via Brauner's vfs.nfsd subtree, after which Lever will rebase the NFS trees accordingly. For client developers, the changes ensure continued correctness of PNFS block layout interactions while laying groundwork for expanded server-side capabilities.
