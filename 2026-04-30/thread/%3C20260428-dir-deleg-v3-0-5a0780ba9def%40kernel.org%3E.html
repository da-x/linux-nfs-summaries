NFSd CB_NOTIFY Support for Directory Delegations (v3)

Summary

NFSd Gains CB_NOTIFY Callbacks for Directory Delegations

This week, Jeff Layton posted version 3 of a significant 28-patch series adding support for CB_NOTIFY callbacks in directory delegations to the Linux NFS server (nfsd) and VFS layer. The series enables NFS clients to register interest in directory changes (creates, unlinks, renames) and receive notifications without losing their lease, improving performance by avoiding unnecessary delegation recalls.

Key Technical Arguments and Evolution

The series builds on previous directory delegation work. In the cover letter PATCH v3 00/28, Layton notes:

"This patchset builds on the directory delegation work we did a few months ago, to add support for CB_NOTIFY callbacks for some events. In particular, creates, unlinks and renames. The server also sends updated directory attributes in the notifications. With this support, the client can register interest in a directory and get notifications about changes within it without losing its lease."

Changes from v2 to v3: The only change in v3 was a critical bug fix:

"The only difference in this version is a small error handling fix in alloc_init_dir_deleg(). The old version could crash since release_pages() can't handle an array with NULL pointers in it."

Changes from v1 to v2 included:

  • Fixing __break_lease handling for different lease types.
  • Adding FSNOTIFY_EVENT_RENAME data type for cross-directory renames.
  • Ensuring the client making changes is not notified.
  • Requeuing notifications if new events arrive during processing.

Implementation Details

The series modifies several subsystems:

  1. VFS/filelock: Adds support for ignoring delegation breaks for specific directory change events via an "ignore mask." This allows nfsd to request leases that don't break on certain operations, relying instead on notifications.
  2. fsnotify: Introduces new tracepoints and a FSNOTIFY_EVENT_RENAME data type to carry information about overwritten inodes during renames, allowing atomic observation of rename targets.
  3. nfsd:
    • Adds protocol support for CB_NOTIFY as defined in RFC8881bis.
    • Implements callback encoding/decoding linkages.
    • Uses RCU to protect fi_deleg_file against races with delegation teardown.
    • Sets up fsnotify watches on directories with delegations to trigger CB_NOTIFY events.
    • Sends basic file attributes and filehandles in the notifications.

Layton notes that testing has been done with pynfs:

"This has mainly been tested with pynfs, with some new testcases that I'll be posting soon. They seem to work fine with those tests, but I don't think we'll want to merge these until we have a complete client-side implementation to test against."

Conclusion

Chuck Lever provided an Ack for the series:

"For the series: Acked-by: Chuck Lever chuck.lever@oracle.com"

The discussion is focused on a new feature (protocol extension and server-side implementation) rather than a bug fix, although it includes a crash fix from v2. The series awaits client-side implementation for full integration testing before merging.
