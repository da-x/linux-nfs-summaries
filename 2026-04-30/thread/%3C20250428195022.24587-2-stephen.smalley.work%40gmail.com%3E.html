NFS Client Adaptation to Updated security_inode_listsecurity() Interface

Summary

This week, Paul Moore posted a forward-ported version of Stephen Smalley's patch updating the security_inode_listsecurity() interface, bringing it up to date for the Linux v7.1 merge window Patch repost by Paul Moore. The discussion was brief, with Moore following up to indicate his intent to merge the patch into the lsm/dev tree pending no objections Merge announcement by Paul Moore.

Classification: Interface Cleanup Affecting NFS Client

This discussion centers on an interface cleanup rather than a new feature, protocol change, or bug fix. The patch updates the security_inode_listsecurity() LSM hook interface to allow use of the xattr_list_one() helper, simplifying the implementation across security modules. The NFS client code in fs/nfs/nfs4proc.c was among the consumers updated to adapt to the new interface signature.

Technical Details

The patch touches seven files across the security subsystem and filesystem layers:

  • fs/nfs/nfs4proc.c — NFS client adaptation (7 lines changed: 2 insertions, 5 deletions)
  • fs/xattr.c — Core xattr helper updates
  • include/linux/lsm_hook_defs.h and include/linux/security.h — Interface definition changes
  • security/security.c, security/selinux/hooks.c, security/smack/smack_lsm.c — LSM hook implementation updates

The original work was authored by Stephen Smalley, with Paul Moore performing the forward port to v7.1-rc1+:

"[PM: forward porting to bring this patch up to v7.1-rc1+]"

Evolution of the Discussion

The thread this week consisted solely of two messages from Paul Moore on April 28, 2026:

  1. Patch submission: Moore posted the ported v2 patch, noting that the original security_inode_listsecurity() cleanup had shipped in Linux v7.0 and that this version was prepared for the next merge window.

  2. Follow-up on merge plans: In his reply to his own submission, Moore stated:

"With the security_inode_listsecurity() cleanup shipping in Linux v7.0, I wanted to get this patch ready for the next merge window. As expected, some borderline non-trivial porting was needed, so I'm posting the ported version in case anyone wants to review the patch again."

He further indicated his timeline:

"If I don't hear anything over the next few days, I'll plan to merge this into lsm/dev later this week."

NFS Client Impact and Testing

While the primary focus of the patch is on the security subsystem, the NFS client component (fs/nfs/nfs4proc.c) required adaptation to the updated interface. Moore confirmed that the changes do not introduce regressions in NFS-related testing:

"The SELinux test suite runs clean for both local and NFS test runs."

This assurance is notable for NFS developers, as LSM interactions with extended attributes are critical for security-aware NFS deployments, particularly when dealing with label-based access controls over networked filesystems.

Conclusion

This thread represents a routine but important maintenance update: the NFS client's interaction with the LSM security_inode_listsecurity() hook was updated to match a cleaned-up interface. No objections were raised during the week, and Moore planned to merge the patch into the lsm/dev tree. The change is a cleanup rather than a bug fix, but it ensures the NFS client remains compatible with ongoing security subsystem refactoring in the v7.1 development cycle.
