NFS Client Updates for Linux 7.1: Bugfixes and RDMA Transport Improvements

Summary

NFS Client Pull Request for Linux 7.1

On April 24, 2026, Trond Myklebust submitted a GIT PULL request for NFS client updates targeting the Linux 7.1 kernel release As announced by Trond Myklebust. The pull request was promptly merged into torvalds/linux.git later that same day, as confirmed by the pr-tracker-bot Confirmation of merge.

Classification: Bug Fixes and Cleanups

This pull request is primarily a bug fix release, with no new features or protocol changes introduced. The updates span 25 files across the NFS client (fs/nfs/) and SUNRPC/RDMA transport layers (net/sunrpc/xprtrdma/), comprising 443 insertions and 215 deletions.

Key Bug Fixes in the NFS Client

The highlights from Trond's announcement cover several important areas of NFS client development:

Write Handling and Error Recovery

  • ENOSPC handling: Writes that must be resent due to out-of-space conditions are now written synchronously, preventing potential data loss or inconsistency.
  • Writeback under error conditions: A fix ensures writeback behaves correctly in the presence of errors, as contributed by Olga Kornievskaia.

NFSv4 Delegation and Timestamp Fixes

A significant portion of the fixes address issues with delegated timestamps and directory delegations:

  • NFSv4.2 delegated timestamps: Multiple fixes for CLONE/COPY attributes in the presence of delegated attributes.
  • utimensat() with atime: Jeff Layton fixed utimensat() behavior when dealing with atime under delegated timestamps.
  • Directory delegation and stat(): Failure to obtain a directory delegation should no longer cause stat() to fail — a notable reliability improvement.
  • Rename timestamp updates: NFSv4 rename operations were failing to update timestamps when a directory delegation was held; this has been corrected.
  • ctime after removexattr: The inode ctime is now properly updated after removexattr operations.

pNFS (Parallel NFS) Fixes

  • Layout return retry on reboot: If the server is down, layout returns are now retried on reboot, improving resilience in distributed storage environments.
  • MDS fallback short write logging: A bug where fallback to the Metadata Server (MDS) could result in a short write being incorrectly logged has been fixed.
  • Flexfiles validation: Jenny Guanni Qu added validation that ds_versions_cnt is non-zero, preventing potential issues with flexfile layouts.

NFSv4 Cross-Boundary and Session Fixes

  • rsize/wsize across filesystem boundaries: The client now properly checks read/write size parameters after crossing an NFSv4 filesystem boundary.
  • Session size limits on clone path: Tushar Sariya applied session size limits to the clone operation path for NFSv4.1.

RCU and Memory Safety

  • RCU dereference fix: Sean Chang fixed an RCU dereference of cl_xprt in nfs_compare_super_address, addressing a potential use-after-free or race condition.

RDMA Transport Improvements (xprtrdma)

Chuck Lever contributed seven patches targeting the RDMA transport layer:

  • Closing a sendctx get/put race that could block a transport
  • Avoiding a 250 ms delay on backlog wakeup
  • Closing a lost-wakeup race in xprt_rdma_alloc_slot
  • Decoupling frwr_wp_create from frwr_map
  • Replacing rpcrdma_mr_seg with an XDR buffer cursor
  • Scaling receive batch size with the credit window
  • Posting receive buffers after RPC completion

These changes collectively improve the reliability and performance of NFS over RDMA, addressing race conditions and latency issues.

Cleanups

  • memcpy_and_pad in decode_fh: Thorsten Blum introduced a cleanup using memcpy_and_pad in the file handle decode path, likely improving safety against buffer overruns.
  • Redundant attribute removal: Sean Chang removed a redundant __private attribute from nfs_page_class.

Conclusion

This pull request represents a solid maintenance release focused on stability and correctness rather than new functionality. The fixes address real-world issues with delegation handling, error recovery in write paths, and RDMA transport reliability — all critical for production NFS deployments. The rapid merge into the mainline tree underscores the importance of these corrections for the Linux 7.1 release cycle.
