NFS Server UAF in cache_check_rcu(): Mainline Persistence and Bisect Results

Summary

NFS Server Use-After-Free in cache_check_rcu(): Bug Persists in Mainline, Bisect Results Reported

Classification: Critical Bug Fix (NFS Server / SUNRPC)

This week, IBM's Misbah Anjum N provided a significant follow-up to the use-after-free (UAF) bug originally reported on February 19, confirming that the crash has propagated into mainline and sharing the results of an exhaustive git bisect. The discussion continued briefly into early May with responses from Jeff Layton and Chuck Lever, who contextualized the findings and outlined ongoing remediation efforts.

Background (Prior Weeks)

The thread originated on 2026-02-19 when Misbah Anjum N reported a 100% reproducible use-after-free in cache_check_rcu() within the SUNRPC cache layer, triggered by the sosreport diagnostic tool reading /proc/fs/nfsd/* files on ppc64le systems. The crash manifested as kernel panics with corrupted pointers containing ASCII strings such as "export_cap" and "libz.so.", classic indicators of freed memory being reallocated. A fix was applied in February for one instance of this UAF class, but additional instances remained unfixed.

This Week's Activity

Git Bisect Results and Mainline Confirmation

On 2026-04-30, Misbah Anjum N posted a detailed follow-up completing the git bisect and confirming the bug's presence in mainline:

"The use-after-free bug in cache_check_rcu() that I originally reported in linux-next (6.19.0-next-20260216/17) has now propagated into mainline and is confirmed present in: mainline (Tested on Latest kernel as of 2026-04-30 - commit 08d0d3466664), linux-next (Tested on Latest kernel as of 2026-04-30)."

The reporter emphasized the operational impact:

"This bug is causing failures on ppc64le systems: 1. Kernel panics: 100% reproducible crashes when sosreport runs 2. CI/Testing failures: All automated Avocado-vt KVM testing on ppc64le is failing"

The bisect identified merge commit da6b5aae84beb0917ecb0c9fbc71169d145397ff ("Merge tag 'platform-drivers-x86-v7.1-1'") as the first bad commit. However, this was a merge of x86 platform driver updates — an unlikely causal agent for a ppc64le-specific crash, suggesting the bisect landed on a coincidental boundary rather than the true root cause.

Community Response (Early May)

Jeff Layton responded on 2026-05-01, noting the bisect result was not actionable as-is and recommending further diagnostics:

"The commit you landed on is a merge commit and is not likely to be the cause, particularly since that merge was for x86 drivers and you're seeing this on PPC."

"What might be best is to run this test with KASAN enabled. That might give us a clearer picture of what object is being freed and when."

Chuck Lever then provided crucial context, clarifying the relationship between the February fix and the current report:

"That fix addressed one instance of this problem; there are actually several more, all in the same UAF class. I have a patch series nearly complete to address these issues."

"The issue Misbah reports here is not the same as the February issue, though it is very similar."

Lever also confirmed the bug was not architecture-specific:

"We have an internal bug reporting the same stack trace on ARM64. Now that we have both a reproducer and a platform that is easily accessible it will be straightforward to confirm these issues are fully addressed before we merge the new fixes."

Key Technical Arguments and Evolution

  1. Bug Persistence: Despite a February fix for one instance of this UAF class, the bug survived into mainline (kernel v7.0), affecting both ppc64le and ARM64 architectures.

  2. Bisect Limitations: The git bisect landed on an x86 platform driver merge commit, which Jeff Layton correctly identified as unlikely to be the true cause. This highlights the challenge of bisecting across large merge commits where the actual regression may have been introduced earlier but only manifested after other changes.

  3. Remediation Path: Chuck Lever confirmed that a patch series addressing all remaining instances of this UAF class was nearly complete, with testing facilitated by Misbah's reliable reproducer on ppc64le and ARM64.

Conclusions

This thread documents the ongoing battle against a class of use-after-free bugs in the NFS server's SUNRPC cache layer. Key takeaways:

  • The bug is confirmed present in mainline (kernel v7.0) and affects multiple architectures (ppc64le, ARM64).
  • A reliable reproducer exists (modprobe nfsd followed by sosreport), enabling thorough testing of fixes.
  • A patch series is nearly complete to address all remaining instances of this UAF class, with Chuck Lever leading the effort.
  • The git bisect result, while not directly identifying the root cause, confirmed the bug's persistence and helped establish its presence in mainline.

The discussion underscores the importance of comprehensive testing across architectures and the value of community-reported bugs with reliable reproducers in driving kernel stability improvements.
