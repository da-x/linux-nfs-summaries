NFS: Redact cert_serial and privkey_serial from mount output

Summary

Overview

This week saw a single-message thread from Sagi Grimberg proposing a targeted fix to prevent sensitive cryptographic material from being exposed via mount option output in the NFS client. The patch addresses a privacy and security concern rather than introducing new functionality or fixing a runtime bug.

Classification

Bug fix / Security hardening: The change prevents inadvertent leakage of certificate serial numbers and private key serials through mount command output, which is typically visible to all local users on the system.

Technical Details

Sagi Grimberg submitted a one-patch series titled "[PATCH] NFS: show redacted cert_serial and privkey_serial in mount options" on April 28. The patch modifies fs/nfs/super.c (4 lines added) to ensure that when NFS mounts using Kerberos or TLS-related options are displayed via tools like mount or /proc/mounts, the actual values of cert_serial and privkey_serial are not revealed in plaintext. Instead, the output should indicate only that these options were provided — effectively redacting the sensitive serial number data.

As Sagi stated in the commit message:

"mount output should not reveal the contents of the serials, but indicate they were provided."

This is a straightforward information disclosure fix. Mount option strings are world-readable on most Linux systems, and exposing cryptographic serial numbers could aid attackers in fingerprinting or correlating mounted NFS shares with specific certificates or keys.

Discussion Evolution

The thread contained only the initial patch submission this week, with no replies, reviews, or objections recorded within the reporting window. The patch appears to be a standalone fix without prior discussion in this thread.

Conclusion

No final resolution was reached this week, as the patch received no responses during the reporting period. However, the change is minimal, well-motivated, and addresses a clear security concern in NFS client development — preventing sensitive credential metadata from leaking through mount option display. The community's response (or lack thereof) will determine whether this patch proceeds to merge in subsequent weeks.
