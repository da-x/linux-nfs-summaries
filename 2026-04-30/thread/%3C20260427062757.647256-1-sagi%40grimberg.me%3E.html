pNFS/filelayout: Fix striped layout detection bug

Summary

pNFS/filelayout: Fix Striped Layout Detection

Classification

Bug fix in the NFS client's pNFS filelayout code.

Overview

Sagi Grimberg submitted a one-line patch correcting how the NFS client determines whether a Parallel NFS (pNFS) file layout is "striped." The bug had been introduced by a previous commit (a6b9d2fa0024, titled "pNFS/filelayout: Fix coalescing test for single DS") and affected the logic used to decide if data should be distributed across multiple Data Servers (DSs).

Key Technical Argument

The core issue was that the client incorrectly relied on num_fh (the number of filehandles) to determine striping. As Sagi Grimberg explained in the initial patch submission on April 27:

"A layout can be striped with num_fh = 1. It is perfectly possible that both MDS and DSs can handle the same filehandle, which is exactly the case in vast pnfs layouts."

In certain pNFS deployments—specifically those using "vast" storage backends—the Metadata Server (MDS) and Data Servers (DSs) may share a single filehandle. In such cases, num_fh equals 1 even though the layout is genuinely striped across multiple DSs. The correct indicator of striping, therefore, is stripe_count > 1, not num_fh > 1.

The patch updates the check to use stripe_count > 1 as the primary condition. As a defensive fallback, if flseg->dsaddr is unexpectedly NULL, the code returns its "best guess" based on flseg->num_fh > 1:

"We should not be called with flseg->dsaddr = NULL, but if for some reason we do, return our best guess with is flseg->num_fh > 1."

Discussion Evolution

The thread was brief. Sagi Grimberg posted the patch on April 27 and followed up on April 28 with a reply adding Olga (likely Olga Kornievskaia, a known NFS maintainer/contributor) to the CC list:

"CC Olga"

No further discussion or review comments appeared within this week's window. The patch remains pending review as of the end of the reporting period.

Significance for NFS Client Development

This fix is important for correctness in pNFS filelayout clients interacting with modern storage backends that share filehandles across MDS and DS roles. An incorrect striping detection could lead to suboptimal I/O scheduling, improper layout coalescing, or degraded performance on affected deployments. The patch directly addresses a regression from a prior fix, underscoring the complexity of pNFS layout semantics.
