Fix slab-out-of-bounds read in SUNRPC cache RCU lookup

Summary

SUNRPC Cache: Fixing a Slab-Out-of-Bounds Read in RCU Path

This thread addresses a critical memory safety bug in the SunRPC cache subsystem, specifically within the RCU-protected lookup path. The discussion is centered on a bug fix for a slab-out-of-bounds read reported by Syzbot.

Key Technical Arguments and Evolution

The Bug Report

Alessandro Zanni submitted a patch to address a slab-out-of-bounds read in cache_seq_start_rcu(). He explained the root cause:

"The issue happens in function __cache_seq_start() when is invoked hlist_for_each_entry_rcu() and the hash value is greater than the hash_size."

The proposed fix adds a bounds check before dereferencing the hash table:

"This fix verifies that the hash index is within the hash_size value before dereferencing the hash table: if the hash index is out of bounds return NULL, otherwise access the value."

The patch references commit ae74136b4bb6 ("SUNRPC: Allow cache lookups to use RCU protection rather than the r/w spinlock") as the origin of the vulnerability and cites a specific Syzbot report.

Maintainer Response

Chuck Lever, the NFS/SunRPC maintainer, responded promptly on the same day. He acknowledged the patch but noted that the issue had already been resolved in his testing tree:

"Thank you for the patch! We have this fixed in the nfsd-testing tree already:"

He provided a link to commit 72fe9e528c68 in the nfsd-testing branch, indicating that the fix was already integrated and would likely be merged into the mainline kernel through his tree rather than requiring this specific patch submission.

Final Conclusions

  • Issue Type: Bug fix (memory safety/correctness).
  • Status: The issue was already fixed in the maintainer's testing tree. Alessandro Zanni's patch aligns with the existing fix, confirming the correctness of the approach.
  • Impact: Prevents potential kernel crashes or security vulnerabilities due to out-of-bounds memory access in the SunRPC cache lookup path when using RCU protection.

This discussion highlights the effectiveness of automated fuzzing (Syzbot) in identifying subtle race-condition-adjacent bugs in kernel subsystems like SunRPC, which underpins NFS client and server operations.
