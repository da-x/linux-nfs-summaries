AUTOSEL Backports: NFS NLM Shutdown Race Fix and Writeback Livelock Repair

Overview

This thread consists of two AUTOSEL backport messages from Sasha Levin, delivering important bug fixes for the NFS client subsystem to stable kernel trees (7.0/6.6). Both patches address longstanding correctness issues in the NFS client: one resolves a use-after-free race in the Network Lock Manager (NLM) shutdown path, and the other eliminates a writeback livelock triggered by server-side errors such as ENOSPC or commit verifier mismatches.

Patch 1: Safely Shut Down NLM Client RPC State

Classification: Bug fix (race condition / use-after-free)

Chuck Lever introduced a new helper, nlmclnt_shutdown_rpc_clnt(), to safely shut down the NLM client's RPC state from the sysfs shutdown handler. The patch was reported and reviewed by Jeff Layton, a long-time NFS/lockd developer.

The Bug

A race condition existed between shutdown_store() (triggered when root writes to /sys/fs/nfs/server-N/shutdown) and nlm_shutdown_hosts_net() or the host release path during NFS unmount. Without synchronization, the following sequence could occur:

"1. shutdown_store() reads server->nlm_host (non-NULL) 2. nlm_shutdown_hosts_net() acquires nlm_host_mutex, calls rpc_shutdown_client(), sets h_rpcclnt to NULL, and potentially frees the host via nlm_gc_hosts() 3. shutdown_store() dereferences the now-stale or freed host"

This race was introduced in kernel v6.5 when the sysfs shutdown knob was enhanced to cancel existing RPC tasks. The failure mode is a use-after-free or NULL-pointer dereference, leading to a kernel oops.

The Fix

The patch introduces nlmclnt_shutdown_rpc_clnt() in fs/lockd/host.c, which acquires nlm_host_mutex before accessing h_rpcclnt. This synchronizes with both nlm_shutdown_hosts_net() and nlmclnt_release_host(), ensuring the RPC client pointer remains valid. The NFS sysfs code was updated to call this helper instead of directly dereferencing server->nlm_host->h_rpcclnt, and the include was switched from the internal lockd.h to the public bind.h header, improving API layering.

"This change also improves API layering: NFS client code no longer needs to include the internal lockd header to access nlm_host fields."

The fix is small (+32/-2 across 3 files), uses an existing mutex consistent with the rest of the lockd subsystem, and was reviewed by the domain expert. The bug has been latent since v6.5 (~2 years).

Patch 2: Fix Writeback Livelock in Presence of Errors

Classification: Bug fix (livelock / infinite retry loop)

Olga Kornievskaia submitted a fix for a writeback livelock that can occur when the NFS server returns ENOSPC or when a commit receives a verifier different from the last successful write. The patch was signed off by NFS maintainer Trond Myklebust.

The Bug

Kornievskaia identified two failure patterns, both reproducible via xfstest generic/751:

"Pattern#1: writeback IO experiences ENOSPC on an offset smaller than the filesize... client sends a commit and receives a verifier which is different from the last successful write. It marks pages dirty and writeback retries. But it again send writes unstable and gets into the same pattern, running into the ENOSPC error and sending a commit because writes were sent at unstable."

"Pattern#2: an unstable write followed by a short write and ENOSPC... client send a commit and receives a verifier different from the last unstable write. The same behaviour is retried in a loop."

In both cases, the NFS client enters an infinite retry loop: unstable writes fail, commits return mismatched verifiers, pages are re-marked dirty, and the cycle repeats indefinitely. This causes writeback to hang, fsync() to block forever, and eventually leads to system-wide writer throttling or OOM-class behavior.

The Fix

The patch introduces a new flag, NFS_CONTEXT_WRITE_SYNC, on the nfs_open_context structure. When certain error conditions are detected — short writes, ENOSPC during writeback, or commit verifier mismatches — this flag is set to force subsequent writes to use stable (NFS_FILE_SYNC) semantics instead of unstable writes. This breaks the retry loop because stable writes do not require a separate commit RPC, eliminating the verifier mismatch trigger.

"Instead, this patch proposes to identify those conditions and mark requests to be done synchronously instead. Previous solution tried to mark it in the nfs_page, however that's not persistent thus instead mark it in the nfs_open_context."

The fix also extends the same logic to the LocalIO code path (for loopback NFS-on-same-host scenarios), ensuring consistent behavior across both transport paths. The change touches 4 files with +27/-1 lines and affects hot write/commit completion paths, but only activates under error conditions.

Evolution of the Discussion

Both patches were delivered as AUTOSEL backports from upstream mainline commits, meaning they had already been merged into the development tree. No additional discussion occurred within this week's window — these are stable-tree nominations via Sasha Levin's automated backport tooling.

The NLM shutdown fix evolved through four public revisions of Chuck Lever's "Clarify module API boundaries" series (v1–v4). Notably, v2 used a simpler NULL-check approach, but the author upgraded to full mutex serialization in v3 after recognizing a TOCTOU race window:

"Serialize client-side NLM shutdown to avoid UAF and NPD."

The writeback livelock fix also underwent significant redesign between v1 (which used a per-page PG_SYNC bit) and v2/v3 (which moved to the persistent per-open-context flag), demonstrating that the design space required careful consideration.

Final Conclusions

Both patches are important bug fixes for the NFS client:

  1. NLM Shutdown Race Fix: Closes a real use-after-free/NULL-pointer dereference in a root-gated sysfs path. The fix is small, well-reviewed by Jeff Layton (subsystem expert), and uses consistent locking semantics. The bug has existed since v6.5.

  2. Writeback Livelock Fix: Eliminates an infinite retry loop that causes writeback to hang when servers return ENOSPC or commit verifier mismatches. Reproducible via standard xfstests, affects all current stable kernels (bug logic dates to 2012), and comes from the NFS maintainer directly.

Both fixes are appropriate for stable kernel trees and address real-world failure scenarios that can cause kernel crashes or system hangs for NFS users.
