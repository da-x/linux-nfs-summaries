Linux NFS Weekly Overview — Week ending 2026-07-16

Critical Bugs & Fixes

NFS Client Bugfixes Merged for Linux 7.2-rc3

Anna Schumaker's pull request landed in mainline within hours, delivering four fixes: two SUNRPC transport reference-counting bugs (killed-waiter leak and TLS connect_worker UAF from Chuck Lever), a MAY_WRITE permission-mask fix for O_TRUNC opens, and a memory-accounting correction so unstable writes are charged by request size rather than folio size. All four are now in 7.2-rc3.

FREE_STATEID Use-After-Free (Client)

Anna Schumaker posted a two-patch series fixing a use-after-free in the NFSv4.1 client when a FREE_STATEID RPC is delayed past server teardown. Dan Aloni (Vast Data) reported and tested the fix. Jia Zhu (ByteDance) replied noting a related but distinct nfs_server UAF his team hit in production, pointing to his own superblock-pinning series still awaiting review.

delegation_hash_table Slab Leak (Client)

Nate Prodromou's one-line fix for an unbounded slab leak on failed NFSv4 mounts received a same-day Reviewed-by from Christoph Hellwig. The production impact was dramatic: a backup poller retrying against an NFSv3-only server leaked ~3.4 GiB/day of unreclaimable slab. Flagged for stable backport.

NFSD Post-Shutdown UAF Merged

Chuck Lever's single-commit pull fixing a use-after-free in NFSD_CMD_UNLOCK_FILESYSTEM was merged into mainline the same day — the first NFSD fix for the 7.2-rc cycle.

NFSv4.2 listxattr / SELinux Netlink Detour

Paul Moore's bisect of a mount regression pointed at the nfsd.fh netlink upcall commit, but the follow-up thread revealed the "connection refused" symptom was a red herring — Scott Mayhew's "is your server running?" question turned out to be correct. The real issue is a SELinux policy gap (CAP_NET_ADMIN for nfsd_t) blocking the mountd netlink upcall on Fedora Rawhide; Paul confirmed a local policy allow-rule fixes it.

Major Trends

NFS Direct I/O Modernization (v3)

Pranjal Shrivastava (Google) posted v3 of his 5-patch series migrating NFS O_DIRECT to iov_iter_extract_pages() — the key enabler for PCI Peer-to-Peer DMA (P2PDMA). The series includes a real bug fix (pages were being unpinned immediately after request creation) and was slimmed from v2 by splitting out the contentious folio work after Matthew Wilcox's pushback. No reviewer replies yet as of week's end.

netfslib bvecq Overhaul (v6)

David Howells posted a 24-patch series replacing folio_queue/rolling_buffer with a new segmented bio_vec[] chain (bvecq) across netfslib (NFS, CIFS, AFS, 9p, Ceph). Goals: single-sendmsg() RPC transmission, unified buffered/DIO buffering, and a simpler writeback model. Carries ~24 bug fixes from automated review, including a stable-tagged AFS fix and deadlock-prone writethrough removal. Addressed to Christian Brauner's VFS tree; no replies yet.

NFSD Copy Offload Hardening (v3 Applied)

Jeff Layton's 10-patch series fixing multiple UAFs, a publish race, and an ownership-check bypass in NFSv4.2 inter-server copy offload was applied to nfsd-testing same-day. Notably, the bugs were found via LLM-assisted inspection ("kres" and agentic review), and patch 05 closes a security gap where any authenticated client could cancel another client's copy-notify stateid.

NFSD Create/Open Refactor (v3, Active Review)

NeilBrown's 17-patch series refactoring nfs4_create_file() is in active review. It includes two real bugfixes (honouring client attributes on EXCLUSIVE4_1 creates; correct filehandle for mounted-on files). Chuck Lever and Jeff Layton identified several regressions (FIFO open stall, read-only OPEN returning ROFS, a __be32 vs host-enum comparison bug) — v4 expected within days.

xdrgen Hardening (Two 5-Patch Series)

Chuck Lever posted two companion series for the XDR code generator: one fixing generated-code defects (void-handler symbol collisions, unbounded opaque/string encoders rejecting all non-empty values), and another adding RFC 4506/5531 semantic checks (duplicate names, out-of-range procedure numbers). Both are preparatory work for the NFSv2/v3 server-side xdrgen conversion.

nfsd.h Header Reorganization

Lever's 9-patch series slimming the "kitchen sink" nfsd.h header (net −202 lines, new attr4.h) received a Reviewed-by from Jeff Layton on July 16.

Ongoing Debates

pNFS blocklayout: "Malicious Server" Threat Model NACKed

The week's most heated exchange: Michael Bommarito's patch to reject zero chunk_size/volumes_count in GETDEVICEINFO (preventing a division-by-zero panic) was outright NACKed by Trond Myklebust, who called it "worthless AI slop" and argued that in storage, a malicious server already has your data — the correct mitigation is transport security (krb5i/p, TLS), not client-side input validation. Bommarito countered with ARP-spoofing / man-in-the-middle scenarios on flat networks; Myklebust closed by pointing to secure VLANs. The patch was not merged.

wdeleg_getattr: Keep or Drop?

In the nfsd netlink stats v6 thread, Layton and Lever re-litigated whether the legacy wdeleg_getattr procfs counter should be exposed over netlink. Layton argues it's an oddity with no public consumer and that CB_GETATTR counts approximate it; Lever wants API equivalence between procfs and netlink. The decision is deferred to Dai (original author), who had not yet replied.

syzbot: nfsd Netlink Lock Contention

A fresh syzbot report filed July 16 shows a task hung >143 s in nfsd_nl_cache_flush_doit, blocked on nfsd_mutex held by nfsd_nl_listener_set_doit. This is the first concrete evidence that the coarse-grained global mutex serializing all nfsd netlink operations can wedge the control plane under concurrent traffic. No maintainer has acknowledged it yet.

nfs-utils 2.9.2-rc5 Activity

A productive week for userspace tooling (all committed by Steve Dickson):

  • mountd netlink fixes — including a fix for mount hangs when SELinux blocks CAP_NET_ADMIN and the code falls back to /proc.
  • rpc.gssd resource leak fixes — two AI-assisted (Claude Sonnet 4.5) leak fixes in the Kerberos upcall daemon.
  • nfsstat callback-ops display — new netlink-gated section showing per-opcode NFSv4 callback counts.
  • ignore_hosts passthrough — one-line fix preventing DNS queries (and boot-time stalls) in nfs-server-generator.
  • gssd memory leak and nfsd haddr overflow — two Huawei submissions; Chuck Lever flagged a DKIM misconfiguration that may block future intake.

Other Notable Items

  • NFSD NFSv2 ACL GETACL wire-format fix — error replies were appending junk attributes data after the status word; unreviewed as of week's end.
  • mm: page_alloc API cleanups and CONFIG_IPV4 decoupling RFC — broader kernel changes with NFS touchpoints.
