NFSD: Fix junk data in NFSv2 ACL GETACL error replies

Summary

NFSD: Encode only the status in NFS-ACL v2 GETACL error replies

Overview

This week, Chuck Lever posted a single-message bug-fix patch to the linux-nfs list addressing a wire-format corruption bug in the NFSv2 ACL GETACL result encoder. The thread contains no replies yet — it stands as an unreviewed patch submission as of the end of this window.

The Bug

The NFSv2 ACL GETACL reply is defined as an XDR union: file attributes and ACL data are present only when the status is NFS_OK. All error cases should be void results (just a status word on the wire). However, the current encoder decides whether to append the "OK" body by testing whether the file handle resolved to a positive dentry — not by checking the actual reply status.

As Lever explains in the patch cover letter:

"A GETACL request that resolves its file handle but then fails for another reason (an unsupported mask value, a getattr failure, or an ACL retrieval error) therefore appends file attributes and ACL data after the error status on the wire."

He goes further, noting the most insidious case:

"Worse, when the mask is rejected, fh_getattr() hasn't been called at all, so those attributes are serialized from a zero-filled kstat and are junk."

This means a client receiving an error reply would see garbage bytes trailing the status word — violating the protocol's wire format and potentially causing clients to misparse subsequent data or crash.

Root Cause and Fix

The bug was introduced by commit f8cba47344f7 ("NFSD: Update the NFSv2 GETACL result encoder to use struct xdr_stream"), which converted the encoder to the modern xdr_stream API but inadvertently changed the branch condition from a status check to a dentry-validity check.

Lever's fix reverts the decision logic to use the reply status (as it was before the conversion) while keeping the xdr_stream infrastructure in place:

"The logic before the xdr_stream conversion used the reply status. Revert to that approach (but keep the xdr_stream conversion in place)."

The patch touches fs/nfsd/nfs2acl.c with 15 insertions and 16 deletions — a small, surgical change.

Classification

  • Type: Bug fix (regression from an API-conversion commit)
  • Component: NFS server (NFSD), specifically the NFSv2 ACL GETACL result encoder
  • Impact: Wire-format corruption on error paths; clients could receive junk attributes data after an error status

Status

The patch was posted on 2026-07-12 with no replies in this window. It carries a Fixes: tag pointing to the offending commit, making it a candidate for stable backports once merged. No prior-week history exists for this thread (it is a fresh, single-message submission).
