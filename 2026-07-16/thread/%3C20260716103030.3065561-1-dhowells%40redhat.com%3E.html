netfs: bvecq replaces folio_queue/rolling_buffer (PATCH v6 posted)

Summary

netfslib's buffer overhaul lands in v6: a segmented bio_vec[] chain replaces folio_queue

Status this week: On Thursday, 16 July, David Howells posted the sixth revision of a large 24-patch series, "[PATCH v6 00/24] netfs: Keep track of folios in a segmented bio_vec[] chain" posted to the list, addressed directly to Christian Brauner asking him to take it through the VFS tree for the next merge window. As of this week's close, no replies or review discussion had landed — the thread consists entirely of David's 25-message posting (cover letter plus the individual patches). There is no prior-week summary file for this thread; the v6 posting itself carries a full changelog bridging versions 2 through 6.

What kind of change this is

This is primarily a major internal refactor / new infrastructure in netfslib (the shared library behind NFS, CIFS, AFS, 9p and Ceph), with an important bug-fix component woven in. It is not a wire-protocol change — the RPC messages on the wire are unchanged — but it does reshape how network filesystems stage their I/O buffers, which has direct performance consequences for the NFS client's buffered and DIO paths.

The cover letter lays out three stated goals:

"The kernel file I/O subsystem seems to be moving towards consolidating on the use of bio_vec arrays, so embrace this by moving netfslib to keep track of its buffers for buffered I/O in bio_vec[] form."

"Netfslib already uses a bio_vec[] to handle unbuffered/DIO, so the number of different buffering schemes used can be reduced to just a single one."

And the performance motivation:

"Always send an entire filesystem RPC request message to a TCP socket with single kernel_sendmsg() call as this is faster, more efficient and doesn't require the use of corking as it puts the entire transmission loop inside of a single tcp_sendmsg()."

The new data structure: bvecq

The centrepiece is a new type, struct bvecq, described in the cover letter as "a segmented chain of bio_vec arrays rather than a single monolithic array." Each segment tracks a file position (fpos), a refcount, slot counts, and a memory-type flag (BVECQ_MEM_EXTERNAL, _PAGECACHE, _GUP, or _ALLOCED) that governs how the underlying pages are released. A key design point is contiguity semantics:

"all the segments pointed to by a single bvecq must represent contiguous data, but adjacent bvecqs within a chain need not be contiguous. This allows a bvecq chain to be used to provide bufferage for a sparse read or write RPC such as can be done with Ceph."

A new iov_iter iterator type, ITER_BVECQ, is added so the construct can be passed straight to sendmsg() or block-based DIO. The series ultimately deletes include/linux/folio_queue.h, include/linux/rolling_buffer.h, and Documentation/core-api/folio_queue.rst, and adds fs/netfs/bvecq.c (~761 lines) and include/linux/bvecq.h.

Netfslib changes (NFS-relevant)

The final patch, "[PATCH v6 24/24] netfs: Combine prepare and issue ops and grab the buffers on request" posted, restructures how subrequests are generated, motivated by writeback complexity:

"the code has to create multiple streams of write requests to disparate targets with different properties (e.g. server and fscache), where not every folio needs to go to every target."

The change collapses ->prepare_xxx(), buffer selection, and ->issue_xxx() into a single issue call; netfslib now hands the filesystem a bvecq slice rather than an iov_iter, and pushes iov_iter handling down into the filesystem. Buffer tracking is managed with three cursors (load, dispatch, collect), and readahead folios are bulk-loaded up front in a single xarray pass. NFS itself is touched in fs/nfs/fscache.c and fs/nfs/Kconfig, and an earlier changelog entry notes fixes to nfs_netfs_issue_read() — "to set -ENOMEM, not 0, on alloc failure" and "to only terminate the subrequest once."

Bug fixes riding along

The series is notable for how many correctness fixes it carries, largely attributed to automated review by "Sashiko." A few stand out:

  • AFS directory-edit fix (stable-tagged): "[PATCH v6 08/24] afs: Fix afs_edit_dir_remove() to get, not find, block 0" posted switches afs_edit_dir_remove() from afs_dir_find_block() to afs_dir_get_block(), because the latter "caches the found block in the afs_dir_iter and may switch out the page it's on if another afs_dir_find_block() is done." It carries a Fixes: tag for a5b5beebcf96 and is cc'd to stable.

  • Writethrough removal (deadlock fix): "[PATCH v6 12/24] netfs: Remove the writethrough code" posted deletes the O_DIRECT-style writethrough path because "it's very tricky to get the locking right and it will probably deadlock if used in conjunction with Ceph snapshots because it excludes writeback for the duration, but to flush out old snapshots, it does a synchronous flush that invokes writeback." The fallback is simpler: "O_SYNC writes do a flush after performing the write - which is already there as the callers of netfs_perform_write() all call generic_write_sync()."

The v6 changelog alone lists roughly two dozen fixes from Sashiko's review, including bvecq_extract() switching to GFP_NOFS, an off-by-one in bvecq_pos_step(), a "transfer-too-long" read path that now "avoid[s] retrying and just end[s] with EIO (in case data further along in the buffer got corrupted)," and several -ENOMEM handling fixes in netfs_writepages() to avoid double unlocks.

Cachefiles / ondemand sunset

The series also removes cachefiles' on-demand mode (a one-patch contribution from Gao Xiang, "[PATCH v6 13/24] cachefiles,netfs: sunset ondemand mode") and stops relying on the backing filesystem's storage map for typical contiguous files, which are now marked CACHEFILES_CONTENT_ALL rather than a sparse backfs-mapped object.

Outlook

David flags two follow-ups he has "working for cifs" but is not including here: letting a filesystem take a copy of a subchain to tack on protocol headers/trailers (and join copies into compounds), and splicing the TCP receive queue directly into a bvecq chain so "the socket lock can be dropped much more quickly." He also lists future ideas, including using bvecq to eventually replace scatterlist.

Bottom line for NFS readers: this is the long-gestating consolidation of netfslib's buffering onto a single bio_vec[]-based mechanism, aimed at faster single-sendmsg() RPC transmission and a simpler writeback model. It arrived as v6 with a heavy bug-fix tail but had not yet attracted reviewer commentary by the end of this week — expect discussion to develop in the coming days as it heads toward Christian Brauner's VFS tree.
