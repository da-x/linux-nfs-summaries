NFS Direct I/O modernization: v3 posted, folio work split out

Summary

NFS Direct I/O Modernization — v3 Posted (No Replies Yet)

This week's activity in this thread consists of a single event: Pranjal Shrivastava (Google) posted v3 of his "Modernize Direct I/O path" series on 2026-07-15, covering five patches. As of the close of this reporting window, no reviewer has replied to v3 — the discussion is at its opening stage.

What kind of change is this?

This is primarily a refactoring / preparatory feature for NFS client development, with an embedded bug fix. The stated goal is to lay groundwork for PCI Peer-to-Peer DMA (P2PDMA) support in the NFS client:

"Modernize the NFS Direct I/O path as a preparatory step to enable PCI Peer-to-Peer DMA (P2PDMA) support." — cover letter

The core technical move is migrating NFS O_DIRECT off the legacy iov_iter_get_pages_alloc2() API onto the modern iov_iter_extract_pages() API, which supports the page-pinning (GUP) semantics that P2P memory requires.

The five patches

  1. make nfs_page pin-aware — introduces a PG_PINNED flag to struct nfs_page. Because pages extracted via iov_iter_extract_pages() carry pins rather than plain references, the creation path now takes a pinned bool and skips the redundant get_page()/folio_get(), while cleanup uses unpin_user_page()/unpin_user_folio() instead of put_page() when the flag is set. Patch 1/5

  2. Track number of pinned pages — adds wb_nr_pinned so only primary requests perform the final unpin, preventing subrequests from prematurely releasing pins owned by their parent. Patch 2/5

  3. nfs_release_request_list helper — a centralized bulk-release helper, framed as prep for both pin-aware cleanup and future folio support ("similar to the pattern in bio_release_pages"). Patch 3/5

  4. migrate direct I/O to iov_iter_extract_pages — this is where the bug fix lives:

    "The migration fixes a bug in the Direct I/O loop where pages were being unpinned immediately after request creation. With the new extraction model, pins are held until the I/O is complete." — Patch 4/5

  5. nfs_direct_extract_pages helper — centralizes page extraction and request creation, unifying the read and write schedule_iovec paths. Patch 5/5

How v3 differs from earlier versions (the evolution)

The series has now gone through an RFC, v1, and v2 before landing here as a slimmer v3. Two decisions shaped this revision:

  • Folio work was split out. The v2 discussion over the "Optimize direct I/O to use folios" patch surfaced a real design impasse. Matthew Wilcox pushed back on treating every struct page as a valid folio:

    "It's not true, eg, for slab... You'll get into a lot of trouble trying to treat slabs as folios (and that will include assertions tripping)." — Wilcox

    Christoph Hellwig then advised splitting the work:

    "In doubt if you think you can get a series merged quicker without a later part I'd split it." — Hellwig

    Accordingly, v3 drops the folio patches (v2 was 0/7; v3 is 0/5) and folds requested_bytes accounting into patch 5. The roadmap now lists two follow-up series: migrating NFS Direct I/O to folios, and enabling ITER_ALLOW_P2PDMA.

  • Earlier fixes carried forward. The v2 changelog notes a data-corruption fix in nfs_direct_extract_pages() (correct intra-page offsets via offset_in_page()) and a requested_bytes accounting fix (increment only after successful RPC scheduling).

Testing

Shrivastava reports running the xfstests quick suite across RDMA and TCP, NFSv3–4.2, before and after applying the series with no regressions, and tabulates that tests which failed in v1 now pass:

"The tests were run before & after applying the series. No regressions were observed." — cover letter

Open threads to watch

Two v2-era review items may resurface in the (not-yet-started) v3 discussion:

  • Chuck Lever asked for linux-rdma@vger.kernel.org and linux-pci@vger.kernel.org to be added on repost. Lever
  • Hellwig questioned whether the full xfstests suite (not just the previously-failing tests) had been run for broader coverage. Hellwig

Bottom line: v3 is a cleaner, more focused refactor that isolates the P2PDMA-enabling infrastructure (pin-aware nfs_page, modern extraction API, and a real unpinning-lifetime bug fix) from the contentious folio migration. The ball is now in the reviewers' court.
