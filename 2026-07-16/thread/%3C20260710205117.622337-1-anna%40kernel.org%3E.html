NFS Client Bugfixes for Linux 7.2-rc3 Merged

Overview

This week, Anna Schumaker submitted a GIT pull request to Linus Torvalds for four NFS client bugfixes targeted at Linux 7.2-rc3, and the changes were promptly merged into mainline by the PR tracker bot.

The Pull Request

Anna's message, dated July 10, outlined a compact set of fixes spanning both the NFS filesystem layer and the underlying SUNRPC transport:

"NFS Client Bugfixes for Linux 7.2-rc3 Bugfixes:

  • SUNRPC: Release lower rpc_clnt if killed waiting for XPRT_LOCKED
  • SUNRPC: Pin upper rpc_clnt across the TLS connect_worker
  • NFS: Include MAY_WRITE in open permission mask for O_TRUNC
  • NFS: Charge unstable writes by request size, not folio size"

The changes touched seven files with 50 insertions and 16 deletions, a modest but impactful patchset.

Key Technical Fixes

SUNRPC Transport Fixes (Chuck Lever)

Two fixes from Chuck Lever addressed subtle reference-counting and locking issues in the RPC transport layer:

  1. Release lower rpc_clnt if killed waiting for XPRT_LOCKED – This fix ensures that if a client is killed while waiting for the transport lock, the lower rpc_clnt reference is properly released, preventing a resource leak.

  2. Pin upper rpc_clnt across the TLS connect_worker – This addresses a potential use-after-free or premature release of the upper RPC client during the asynchronous TLS connection establishment path in xprtsock.c.

NFS Filesystem Fixes (Benjamin Coddington)

Two fixes from Benjamin Coddington addressed correctness issues in the NFS client:

  1. Include MAY_WRITE in open permission mask for O_TRUNC – When a file is opened with O_TRUNC, the open permission mask now correctly includes MAY_WRITE. This ensures that the server-side access check properly validates write permissions when truncation is requested, fixing a potential security/correctness gap in fs/nfs/dir.c.

  2. Charge unstable writes by request size, not folio size – A memory accounting fix in fs/nfs/write.c that corrects how unstable (uncommitted) writes are charged against the process's memory limits. Previously, the charge was based on the full folio size rather than the actual request size, which could over-charge and unnecessarily throttle writers.

Resolution

The pull request was merged into torvalds/linux.git within hours of submission. The PR tracker bot confirmed the merge:

"The pull request you sent on Fri, 10 Jul 2026 16:51:17 -0400 ... has been merged into torvalds/linux.git"

Conclusion

This was a straightforward bugfix pull with no discussion or objections. The four fixes address real-world correctness issues in the NFS client stack—two in the RPC transport layer (reference counting under error paths and TLS connection setup) and two in the filesystem layer (permission checking for O_TRUNC and memory accounting for unstable writes). All changes are now part of Linux 7.2-rc3.
