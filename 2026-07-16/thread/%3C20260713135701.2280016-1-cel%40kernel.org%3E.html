Summary

NFSD v7.2-rc fix: post-shutdown UAF in NFSD_CMD_UNLOCK_FILESYSTEM merged

This week's activity on this thread was brief but consequential: a single-commit bug-fix pull request from NFS server maintainer Chuck Lever landed cleanly in Linus's tree, closing out the first round of fixes for the v7.2-rc release cycle.

The fix

On July 13, Chuck Lever sent a git pull request containing one commit:

"NFSD: Prevent post-shutdown use-after-free in NFSD_CMD_UNLOCK_FILESYSTEM"

The change is small — 4 insertions and 3 deletions in fs/nfsd/nfsctl.c — but it addresses a memory-safety bug that could be triggered after the NFS daemon has shut down. The issue: when the NFSD_CMD_UNLOCK_FILESYSTEM control command was issued post-shutdown, the code path could dereference memory that had already been freed during teardown. This is classified as a bug fix (use-after-free), not a new feature or protocol change.

Lever's pull message framed it succinctly:

"Issues reported with v7.2-rc:

  • Fix a UAF when unlocking a filesystem"

The tag nfsd-7.2-1 was cut from his cel/linux repository, building on top of the prior NFSD work that included the svcrdma transport-close fix (commit e5248a742603).

Merged same day

Within hours, the pr-tracker-bot confirmed that the pull had been merged into torvalds/linux.git:

"has been merged into torvalds/linux.git: https://git.kernel.org/torvalds/c/0f26556c5eeea62cc934fa8938b148aa5844a6b6"

Context and significance

This is the first NFSD fix pull for the v7.2 cycle, indicating that the UAF was caught during early-rc testing. The NFSD_CMD_UNLOCK_FILESYSTEM command is part of the NFS daemon's control interface (used by tools like nfsdctl or legacy /proc/fs/nfsd interactions), so the bug would have been reachable from userspace administration paths — a non-trivial attack surface if left unfixed.

Notably, this thread sits alongside several other NFSD-related pull requests and discussions in the same week (including additional fix pulls from Lever on July 12–13 and an exportd netlink series), suggesting an active stabilization push for v7.2-rc. The quick turnaround — reported, fixed, and merged within a single day of the pull request — reflects the typical kernel release-cycle rhythm for rc-phase bug fixes.

Conclusion

No further discussion or review debate occurred on this thread; it was a straightforward fix-and-merge cycle. The use-after-free in the filesystem unlock path is now resolved upstream for v7.2-rc, and no follow-up patches or regressions were reported within this week's window.
