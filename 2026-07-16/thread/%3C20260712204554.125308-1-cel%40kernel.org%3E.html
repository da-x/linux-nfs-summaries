NFSD: Reorganizing the nfsd.h "kitchen sink" header

Summary

NFSD: Chuck Lever begins untangling the nfsd.h kitchen-sink header

Overview

This week, NFS server maintainer Chuck Lever posted a nine-patch series titled Start reorganizing fs/nfsd/nfsd.h, continuing his ongoing effort to clean up the NFSD codebase's header structure. The series is a refactoring / cleanup effort rather than a new feature or protocol change, though it touches on an important architectural concern: reducing coupling between NFSD's internal modules and speeding up compilation of nfsd.ko.

Lever framed the problem in the cover letter:

"fs/nfsd/nfsd.h has become a kitchen sink of unrelated declarations and definitions, including a broad swathe of headers and other detritus in NFSD source files. This organization introduces brittleness that makes it difficult to execute changes that cut across layers and internal modules that might otherwise be cleanly siloed."

He also highlighted the practical cost:

"It also pulls in unused items into each TU, making compilation of nfsd.ko needlessly slower and more computationally-expensive."

The Patch Series (9 patches)

The series makes targeted moves to decouple nfsd.h from headers and definitions that don't belong there:

  1. Make "stats.h" self-contained — The inline helpers in stats.h dereference struct nfsd_net and struct svc_export, but the header included neither netns.h nor export.h. Lever noted this created "a hidden ordering requirement that has to be honored at every include site." The fix includes both headers directly so stats.h stands on its own.

  2. Explicitly include "stats.h" — With stats.h now self-contained, the blanket include from nfsd.h is dropped and the six translation units that actually need it (nfs4state.c, nfscache.c, nfsctl.c, nfsfh.c, stats.c, vfs.c) include it directly.

  3. include "netns.h" — Nothing in nfsd.h needs the full contents of netns.h; a forward declaration of struct nfsd_net suffices for its prototypes. The include is dropped from nfsd.h and added to the TUs that actually operate on struct nfsd_net. A side benefit: "netns.h" had been the transitive path by which <linux/filelock.h> reached nfsxdr.c and state.h; both now include it themselves.

  4. Remove '#include "nfsd.h"' from fs/nfsd/cache.h — A simple cleanup: cache.h doesn't need the full definition of struct nfsd_net, just a forward declaration.

  5. Move the export.h include from nfsd.h to auth.c — Of the twenty source files that include nfsd.h, only auth.c actually relies on the transitive inclusion of export.h (for struct svc_export and NFSEXP_* flags). The include is moved to its sole consumer.

  6. Move struct readdir_cd — This patch addresses a layering inversion: struct readdir_cd is part of the VFS readdir API but lived in nfsd.h, forcing the lower-level vfs.h to include nfsd.h. Lever relocated it to vfs.h "just below the nfsd_filldir_t callback typedef," so that vfs.h defines the struct itself and no longer includes nfsd.h.

  7. Relocate nfsd_user_namespace() — The auth-related function is moved from nfsd.h to auth.c/auth.h, so callers no longer need to pull in the full NFS protocol definitions "even when the caller uses nothing else from nfsd.h."

  8. Relocate nfsd4_set_netaddr() — Following kernel convention of avoiding static inline functions with a single call site, this 30-line helper is moved from the header (pulled into ~25 .c files) into nfs4proc.c, removing <linux/sunrpc/addr.h> from the header's transitive include surface.

  9. Relocate NFSv4 "supported attributes" to new header — The NFSv4 attribute bitmask definitions (used only by nfs4proc.c and nfs4xdr.c) are moved to a new dedicated header attr4.h. Lever also took the opportunity to fix a stale comment:

    "While moving the block, correct the stale QUOTA_* annotation: the promised support never materialized, so these attributes are unlikely to be supported any time soon rather than forthcoming."

Net Impact

The series touches 22 files with 253 insertions and 203 deletions, creating one new header (attr4.h) and significantly slimming down nfsd.h (net −202 lines). The changes are purely mechanical relocations — no behavioral changes to the NFS protocol or server functionality.

Review and Conclusion

The review was swift and positive. On July 16, Jeff Layton replied with a brief but decisive endorsement:

"This all looks sane."

"Reviewed-by: Jeff Layton jlayton@kernel.org"

With the Reviewed-by tag from the other NFSD maintainer, the series is in good shape for merging. This work fits within Lever's broader campaign to modularize the NFS server codebase, making it easier to maintain and faster to build — a theme that has run through multiple patch series this week (see related threads on nfsd.h cleanup and other NFSD refactoring efforts).
