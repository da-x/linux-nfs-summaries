Aaron Tomlin signs off kmod.h slimming patch (Reviewed-by)

Summary

Aaron Tomlin signs off Petr Pavlu's linux/kmod.h slimming patch

What happened this week

Activity in the current window (2026-07-10 → 2026-07-16) is a single message, but it is the one that matters: Aaron Tomlin posted a Reviewed-by tag on Patch 2/2, closing out the review cycle that opened last week.

"LGTM. Thank you.

Reviewed-by: Aaron Tomlin atomlin@atomlin.com"

Tomlin's sign-off is aimed squarely at the second patch of the series — "module: Bring includes in linux/kmod.h up to date" — which he quoted back to frame his approval, echoing Pavlu's headline number:

"Including linux/kmod.h alone results in 1.5 MB of preprocessed output, even though it provides only a few functions and macros."

Bridging prior weeks (brief)

Last week's summary covers the substance of the series, so this is kept to context only. On 2026-07-08, SUSE's Petr Pavlu posted a two-patch header-hygiene / build-system cleanup — explicitly not a protocol change and not a runtime bug fix. Patch 1/2 adds explicit #include <linux/umh.h> to files that use usermode helpers (including the NFS client's fs/nfs/cache_lib.c and server-side fs/nfsd/nfs4layouts.c / nfs4recover.c); Patch 2/2 trims linux/kmod.h down to its three real dependencies (compiler_attributes.h, errno.h, types.h), cutting preprocessed output from ~1.5 MB to ~10 kB. Michal Koutný flagged one over-eager hunk in kernel/cgroup/cgroup-v1.c, and Pavlu promised a v2 dropping it.

NFS-client angle

For readers tracking the client, nothing new landed this week on the code side: the only NFS-client hunk (fs/nfs/cache_lib.c swapping linux/kmod.h for the correct linux/umh.h) was already posted and uncontroversial last week. This week's contribution is purely a review milestone — an independent Reviewed-by from Tomlin (a long-time module-loader / kmod maintainer, well placed to judge this patch) on the core of the series. That sign-off strengthens Pavlu's hand with maintainers ahead of merge and confirms Patch 2/2 is in good shape; it does not by itself change any client behaviour.

Bottom line

  • Type: build-system / header cleanup (no protocol change, no runtime bug fix).
  • This week: one message — Aaron Tomlin's Reviewed-by on Patch 2/2.
  • Status: the cgroup-v1.c hunk is slated for a v2 (per last week), and the kmod.h slimming now carries an external sign-off. No new objections; the series is converging toward merge.
