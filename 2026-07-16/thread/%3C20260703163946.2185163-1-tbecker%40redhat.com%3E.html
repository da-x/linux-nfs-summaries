rpc.gssd leak fixes committed to nfs-utils 2.9.2-rc5

Summary

rpc.gssd: Two resource leaks — merged into nfs-utils 2.9.2-rc5

This week's development

The thread that began on July 3 with Thiago Becker's two-patch series fixing resource leaks in rpc.gssd reached its conclusion this week when nfs-utils maintainer Steve Dickson confirmed the patches were merged. In a brief reply posted on July 11, Dickson simply stated:

"Committed... (tag: nfs-utils-2-9-2-rc5)"

This closes the loop on a quiet, uncontested bug-fix submission that had received no discussion or review comments in the intervening days. The two patches — one decrementing a clnt_info reference count on an error path in alloc_upcall_info, and the other adding a missing pthread_attr_destroy() call before start_upcall_thread returns — are now part of the nfs-utils 2.9.2 release cycle.

Context from prior week

As covered last week, Becker's series was notable for its provenance: both leaks were identified by an AI assistant (Claude Sonnet 4.5), with the human developer filtering false positives before submission. Each patch carried an Assisted-by: Claude:claude-sonnet-4-5 trailer alongside the standard sign-off. The fixes are minimal — four added lines total in utils/gssd/gssd_proc.c — and address slow resource accumulation in long-running gssd processes that broker Kerberos upcalls for NFS clients.

Significance

The commit to nfs-utils-2-9-2-rc5 means these fixes will ship with the next stable nfs-utils release, benefiting any deployment running Kerberos-authenticated NFS clients where leaked references and thread attributes could degrade the gssd daemon over time. The series is a low-risk, well-scoped bug fix suitable for backporting to stable branches.
