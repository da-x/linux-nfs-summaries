kmod.h include cleanup touches NFS cache upcalls

Summary

Petr Pavlu posted a treewide header-hygiene series this week that is not an NFS protocol change and not a functional bug fix. It is a compile-time include cleanup whose only NFS client impact is making the cache-upcall path include the header that actually declares usermode helpers.

What landed this week

On 21 July, Pavlu posted v2 of a three-patch series titled “Bring includes in linux/kmod.h up to date.” The cover letter is explicit about both the historical debt and the limited near-term payoff:

"The usermode helper declarations were previously provided by linux/kmod.h but commit c1f3fa2a4fde ("kmod: split off umh headers into its own file") moved them to linux/umh.h in 2017."

"This cleanup is motivated by trying to reduce the preprocessed size of linux/module.h, which includes linux/kmod.h. The linux/module.h header is included by every *.mod.c file to provide struct module and other related definitions, so it should avoid pulling in unnecessary dependencies."

He immediately caveats that this series is preparatory rather than a win by itself:

"Note that this series doesn't immediately improve the situation, since most of the files included by linux/kmod.h are, for now, also included by linux/module.h through other paths."

Because the change is treewide, he asked for acks rather than a single-subsystem merge:

"Apologies for the wide distribution. Acked-bys are appreciated."

No replies landed inside this week’s window. Later comments from Thomas Gleixner (25 July) sit outside the period and are left for next week.

NFS client change: fs/nfs/cache_lib.c

The NFS-relevant work is entirely in patch 1/3, “umh, treewide: Explicitly include linux/umh.h where needed.” Pavlu’s rationale is that callers of call_usermodehelper() and friends have been getting those prototypes only because linux/kmod.h still pulled in linux/umh.h as a compatibility include. Once that compatibility include goes away, every real user must name linux/umh.h itself.

On the client side that means fs/nfs/cache_lib.c: a one-line swap of #include <linux/kmod.h> for #include <linux/umh.h>. That file is the NFS client’s cache-upcall helper — the path that launches user-space cache helpers for things such as idmap and DNS resolution via call_usermodehelper(). There is no change to the upcall protocol, argument vector, timeout, or error handling. The client still talks to the same helpers; it simply includes the header that has actually owned those declarations since 2017.

The same patch also touches two nfsd files that use usermode helpers for pNFS layout recall and client-tracking recovery (fs/nfsd/nfs4layouts.c swaps kmod.h for umh.h; fs/nfsd/nfs4recover.c gains an explicit umh.h). Those are server-side and do not alter client behavior.

The rest of the series

Patch 2/3 is a one-line include of linux/sysctl.h in kernel/time/jiffies.c, needed because that file currently gets proc_int_u2k_conv_uop() and related converters only through linux/module.h → linux/kmod.h. It is listed so the later kmod.h shrink does not break the time code; it has no NFS content.

Patch 3/3 is the actual header shrink. Pavlu’s numbers are blunt:

"Including linux/kmod.h alone results in 1.5 MB of preprocessed output, even though it provides only a few functions and macros."

After dropping the compatibility umh.h include and keeping only compiler_attributes.h (__printf()), errno.h (ENOSYS), and types.h (bool), he reports:

"Include only these files, reducing the preprocessed output to 10 kB."

Aaron Tomlin’s Reviewed-by from v1 is carried on this patch. That is the piece that will eventually make linux/module.h cheaper for every *.mod.c, including the NFS client and server modules, but Pavlu is careful not to claim that win yet.

Brief bridge from v1

v1 went out on 8 July as a two-patch series. Michal Koutný noted that kernel/cgroup/cgroup-v1.c did not actually need kmod.h. Pavlu agreed — “You're right. I'll remove the kmod.h include from kernel/cgroup/cgroup-v1.c. I went through all the files again and it seems this was the only place I missed.” — and Tomlin reviewed the header shrink with “LGTM. Thank you.” v2 therefore drops that stray cgroup include and adds the jiffies sysctl.h include as a third patch. The NFS hunks are unchanged from v1.

Status

This is include hygiene, not a client bug fix and not a protocol change. The only NFS client development interest is that cache_lib.c will compile against the real UMH API instead of a nine-year-old compatibility include, which is a prerequisite for slimming linux/kmod.h / linux/module.h. No linux-nfs maintainer has acked or objected in-window; the series is waiting on the wide Acked-by sweep Pavlu requested.
