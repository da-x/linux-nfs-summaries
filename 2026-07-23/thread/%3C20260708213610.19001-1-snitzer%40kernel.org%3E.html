Maintainer asks for Fixes tag on localio DIO tracepoint patch

Summary

NFS/localio: maintainer asks for a Fixes: tag on the DIO misaligned-tracepoint patch

This week's activity in the localio tracepoint thread is a single, pointed follow-up from NFS client maintainer Anna Schumaker. The underlying change remains a bug fix — an observability defect in the NFS client's local I/O direct-I/O path, not a protocol change or new feature — and the discussion has not yet advanced to an ACK, a v2, or a merge.

Prior week, in brief

On 8 July, Mike Snitzer posted a small patch to fs/nfs/localio.c and fs/nfs/nfstrace.h correcting trace_nfs_local_dio_misaligned(). nfs_local_iters_setup_dio() is supposed to report that the middle segment of a localio DIO write is misaligned, but it was passing local_dio->start_len as @offset — "a cut-n-paste bug from the preceding nfs_local_iter_setup() call," in Snitzer's words. The patch switches that argument to local_dio->middle_offset and computes the start-segment offset instead of assuming it.

Before/after traces made the defect concrete: the buggy event reported offset=329 (the start-segment length), while the fixed event reports offset=1049088 (the true middle-segment start). The surrounding nfs_local_dio_write event was unchanged, so the I/O path itself is not being rewritten. Snitzer Cc:'d stable@vger.kernel.org but did not include a Fixes: tag.

This week's question

On 21 July, Anna Schumaker replied with a one-line procedural request:

"Do you have a fixes tag for this commit?"

That is the entire in-window discussion. Schumaker did not dispute the diagnosis, the traces, or the two-file change; she is asking for the metadata that stable backports require. Snitzer had already flagged the patch for stable, so the missing Fixes: line — pointing at the commit that introduced the cut-and-paste — is the obvious next step before the client tree (or -stable) can take it.

No reply from Snitzer landed before the 23 July close of this reporting window, and no Reviewed-by / Acked-by tags appear on the thread. The patch therefore remains pending: technically uncontroversial, evidence-backed, and still waiting on the Fixes: tag the NFS client maintainer asked for.

Bottom line

A clean NFS-client localio observability fix is sitting in review. This week's only movement is Schumaker's request for a Fixes: tag; until that lands, the patch is not yet queued.
