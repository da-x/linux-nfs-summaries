NFS client DIO modernization v4 wins full review

Summary

Google engineer Pranjal Shrivastava posted v4 of a five-patch series that modernizes the NFS client’s O_DIRECT path, replacing the legacy iov_iter_get_pages_alloc2() extractor with iov_iter_extract_pages(). The work is infrastructure rather than a protocol change: it is the first of three planned series that will eventually enable PCI peer-to-peer DMA for NFS Direct I/O, with folio aggregation and ITER_ALLOW_P2PDMA transport negotiation deferred to follow-ups.

The cover letter is explicit about the split. After RFC and v2 feedback, folio conversion was pulled out so this series can land the pin-aware request lifecycle first:

"Currently, NFS O_DIRECT relies on the legacy iov_iter_get_pages_alloc2() API which does not support the pinning requirements for P2P memory. The implementation moves NFS to the modern iov_iter_extract_pages() API."

Shrivastava also recorded a real client DIO bug that the API migration closes: the old loop unpinned pages immediately after request creation. With extract-pages, pins are now held until I/O completion, and the loop only releases pages that failed to become requests.

Pin-aware nfs_page lifecycle

Patch 1 adds PG_PINNED to struct nfs_page. nfs_page_create_from_page() and nfs_page_create_from_folio() take a pinned boolean; when it is set, the creators skip get_page()/folio_get() because the GUP pin itself is the reference. nfs_clear_request() and nfs_direct_release_pages() then call unpin_user_page()/unpin_user_folio() instead of a plain put_page(), and subrequests inherit the parent’s pin state.

Patch 2 adds wb_nr_pinned so only the primary request performs the final unpin. That is the client-side equivalent of not letting a split write or read subrequest drop pins that still belong to the parent. The count is initialized with nfs_page_array_len() from the request’s offset and length.

Patch 3 introduces nfs_release_request_list() as the bulk cleanup helper, then converts nfs_read_sync_pgio_error() to it. Shrivastava frames the helper as groundwork for both pin-aware cleanup and later folio-sized requests, “similar to the pattern in bio_release_pages.”

Direct I/O extraction rewrite

Patch 4 is the actual API swap in fs/nfs/direct.c. Beyond aligning NFS with the VFS extraction model, the commit message calls out the unpin-too-early bug:

"The migration fixes a bug in the Direct I/O loop where pages were being unpinned immediately after request creation. With the new extraction model, pins are held until the I/O is complete. Manual release in the loop is correspondingly updated to only clean up failed pages."

Patch 5 then centralizes that logic in nfs_direct_extract_pages(), which both nfs_direct_read_schedule_iovec() and nfs_direct_write_schedule_iovec() now share. Extraction, request construction, error unwind, and iov_iter_revert() live in one place instead of two nearly identical DIO loops.

The series is a 135-line net change across direct.c, pagelist.c, the read/write page creators, and include/linux/nfs_page.h. It was rebased on fs-next (070f41f07272).

Testing and the remaining roadmap

Shrivastava ran xfstests -g quick on RDMA and TCP for NFSv3 and v4.0–v4.2, before and after the series, and reported no regressions. A tabulated subset of the tests that failed in v1 now pass on every transport/version combo that actually runs them (several NFSv4.2-only cases remain skipped on older versions; generic/444 is skipped everywhere).

Two follow-up series are still planned:

  1. Folio-based Direct I/O, exporting an iov_iter.c helper so nfs_direct_extract_pages() can aggregate hugepage I/O into fewer RPCs.
  2. P2PDMA enablement: ITER_ALLOW_P2PDMA on the DIO path plus transport-level discovery of P2P-capable RDMA/NVMe devices, built on the PG_PINNED infrastructure landed here.

Review: style nits absorbed, then a clean bill of health

v4 is a same-day respin of v3 after Christoph Hellwig’s style comments. The changelog lists the mechanical fixes: drop superfluous externs from nfs_page.h, scope req locally inside nfs_release_request_list(), wrap >80-column lines in patch 1, and normalize commit-subject capitalization. Reviewed-by tags from Hellwig (patches 4–5, carried from v3) and Shivaji Kant (patches 3–5) were collected on the way.

Two days later Hellwig finished the remaining three patches with identical one-liners. On pin-awareness he wrote, “Looks good”; on wb_nr_pinned, “Looks good”; on the release-list helper, “Looks good” — each with a Reviewed-by: Christoph Hellwig. No further technical objections landed in-window.

Bottom line: this is client DIO infrastructure plus a pin-lifetime bug fix, not a wire-protocol change. With Hellwig’s reviews now covering all five patches and xfstests showing a clean quick-group run on TCP and RDMA, the series looks ready to land as the foundation for folio DIO and P2PDMA follow-ups.
