Netfs v7: folio queues give way to bvecq chains

Summary

David Howells posted [PATCH v7 00/29] of his long-running netfslib buffer rewrite this week, asking Christian Brauner to queue it for the VFS tree. There were no review replies in-window: the thread is the 29-patch drop itself, rebased on v7.2-rc4 and carrying a dense changelog of Sashiko-found bugs plus three front-of-series netfs leak fixes from Yichong Chen.

This is primarily an infrastructure rewrite, not a protocol change. Howells wants netfslib (and therefore the NFS, CIFS, AFS, 9p and Ceph clients that sit on it) to stop tracking buffered I/O in folio_queue / rolling_buffer / ITER_FOLIOQ and instead keep a segmented chain of bio_vec[] arrays (struct bvecq + ITER_BVECQ). The three aims, as he put them in the cover letter, are to follow the kernel I/O stack’s consolidation on bio_vec, to collapse buffered and DIO buffering onto one scheme, and to:

"Always send an entire filesystem RPC request message to a TCP socket with single kernel_sendmsg() call as this is faster, more efficient and doesn't require the use of corking as it puts the entire transmission loop inside of a single tcp_sendmsg()."

That last point is the NFS-client-relevant payoff. A filesystem will eventually be handed a copy of a bvecq subchain, glue protocol headers and trailers onto it, and emit one RPC with one kernel_sendmsg(). Howells says he already has that working for CIFS, plus a companion “splice the TCP receive queue into a bvecq” path so recvmsg() no longer holds the socket lock across the copy into destination buffers. Neither of those two follow-ons is in this branch.

What actually changes for the NFS client

NFS is a netfslib consumer, so the client does not grow a new on-wire feature here, but it does have to speak the new issue API. The final patch, netfs: Combine prepare and issue ops and grab the buffers on request, collapses ->prepare_read() / ->prepare_write(), buffer setup and ->issue_*() into a single ->issue_*() call. The filesystem is given the subrequest at maximum extent, shortens it, then calls back into netfslib to slice a piece of the master bvecq. iov_iter is pushed down into the filesystem; netfslib now hands over a bvecq.

The NFS-side delta is small but load-bearing: fs/nfs/fscache.c and fs/nfs/Kconfig are updated, and the v7 changelog records that nfs_netfs_issue_read() now returns int (it previously did not match the new issue-op contract). Earlier revisions in this series already fixed two NFS-client bugs that would have been easy to miss: nfs_netfs_issue_read() setting 0 rather than -ENOMEM on alloc failure, and terminating the subrequest twice. Those are the kind of “issue path returns the wrong thing and the collector loops or double-completes” defects that show up as hung reads or lost fscache I/O, not as protocol mismatches.

Howells is explicit that the new model is meant to make retry and multi-stream writeback less of a maze:

"The issue, primarily, is in writeback: the code has to create multiple streams of write requests to disparate targets with different properties (e.g. server and fscache), where not every folio needs to go to every target."

For NFS-over-fscache that is exactly the two-stream case (server + cache). Netfslib now accumulates bufferage, asks each stream for an estimate of how much to gather, then loops creating subrequests. -ENOMEM from ->issue_*() aborts further generation; other early errors fail the subrequest after extending it as far as possible.

Bug fixes that actually ship in v7

Three leak/refcounting fixes from Yichong Chen are prepended because they conflict with the rest of the series:

  • netfs: clear PG_private_2 on copy-to-cache append failure — netfs_pgpriv2_copy_to_cache() marks the folio PG_private_2 before the append; if rolling_buffer_append() fails the folio is never queued, so the flag and its reference must be dropped immediately.
  • netfs: handle single writeback rolling buffer allocation failure — netfs_write_folio_single() takes an extra folio ref before append and previously leaked it on folio_queue allocation failure. This is the AFS-directory / “single monolithic object” writeback path.
  • netfs: release readahead folios on iterator preparation failure — netfs_prepare_read_iterator() batches readahead folio refs in put_batch and, on rolling_buffer_load_from_ra() failure, returned without dropping them.

Those three are bug fixes against current netfs, even though the rolling buffer they patch is then deleted later in the same series. They exist so the intermediate patches bisect, and so the failure paths they close are not reintroduced in the bvecq conversion.

AFS directory editing also gets three stable-tagged kunmap/refcount fixes (missing kunmap, get not find block 0, double-unmap) found by Sashiko against the hashtable directory search. They are not NFS, but they are the same class of “iterator holds a kmap, second lookup unmaps the wrong page” bug that network-filesystem directory code is prone to.

Two netfs correctness patches sit at the tail:

  • Check for too much data being read aborts the rest of a read request with -EIO if a subrequest over-reads, on the basis that “some of the read buffer may have been corrupted.” Collection no longer winds subreq->transferred back.
  • Limit the minimum trigger for progress reporting stops the collector being woken for every folio on a huge RPC: the trigger is now max(256KiB, size of the folio at the front of the queue), and the base is the stream collection point rather than “whatever the collector has cleaned up to (which is currently 0).”

That progress-reporting floor is an NFS-shaped performance fix. Large NFS reads already span many folios; waking the collector per folio is exactly the “negative performance impact on the system” Howells is trying to kill.

The bvecq design, in brief

Patch 11 introduces struct bvecq: a refcounted, NULL-terminated (not circular) segment of bio_vec[] with file position, contiguity flag, and a mem_type saying how to dispose of the memory (EXTERNAL, PAGECACHE, GUP, ALLOCED). Adjacent segments may be discontiguous so a chain can describe a sparse Ceph-style RPC; each individual segment must be contiguous. Patch 12 adds the netfs-side tools (alloc/expand/shorten, rolling-buffer view, folio load, slice, clear). Patch 13 extracts any iov_iter into a bvecq.

Patch 21 is the actual netfs switch. Three cursors live on netfs_io_request (load_cursor, dispatch_cursor, collect_cursor); writeback needs a dispatch cursor per stream. Subrequests carry dispatch_pos and content so a bounce/copy can be retired independently of the source. Buffered writeback now records only the dirty portion of a folio in the bvec, then expands a copy of that segment when writing to the cache (rounded to DIO block alignment). Unbuffered/DIO extracts the VFS iterator up front via netfs_extract_iter().

Consumers are converted before the old types die: AFS directories and CIFS crypto bounce buffers move from folioq to bvecq (14, 15); smbdirect learns ITER_BVECQ and then drops ITER_FOLIOQ (16, 22, both with Stefan Metzmacher’s ack). Then the wrecking ball: remove folioq alloc/free, remove netfs_extract_user_iter(), remove ITER_FOLIOQ, remove folio_queue and rolling_buffer including Documentation/core-api/folio_queue.rst.

Two supporting MM/iov_iter patches make the conversion possible: readahead now stores a folio count in readahead_control so netfs can preallocate the queue and bulk-load under RCU (07, 08, the latter already reviewed by Paulo Alcantara), and iov_iter_get_pages*() becomes a wrapper around iov_iter_extract_pages() for kernel iterator types (10).

Writethrough is gone; cachefiles is slimmed

Patch 17 deletes netfs writethrough outright:

"Remove the netfs writethrough code as it's very tricky to get the locking right and it will probably deadlock if used in conjunction with Ceph snapshots because it excludes writeback for the duration, but to flush out old snapshots, it does a synchronous flush that invokes writeback."

O_SYNC writes now just flush after netfs_perform_write(), which the callers already do via generic_write_sync(). NFS does not use the writethrough path today, but the removal simplifies the write-issue code the NFS client does share.

Cachefiles loses EROFS on-demand mode (18, from Gao Xiang: fscache is now “netfslib-oriented” and EROFS was never a network filesystem). More interesting for NFS+fscache is 19: most files no longer query the backing fs with SEEK_DATA/SEEK_HOLE on every cache read. The common { open(O_TRUNC); write(); … close(); } pattern is tagged CACHEFILES_CONTENT_ALL in the xattr; i_size of the backing file tracks how much has actually been stored (always DIO-block aligned) and xattr.object_size holds the netfs file size. Occupancy is now a first-class fscache_occupancy query returning up to two extents (FSCACHE_EXTENT_DATA or FSCACHE_EXTENT_ZERO), and a new ->collect_write() method updates cache metadata when a contiguous write run completes. Howells is blunt that sparse cachefiles still lean on the backing fs map and “needs to be fixed, but in a separate set of patches as it's not trivial.”

Patch 20 adds the cache object debug ID to netfs read/write tracepoints so netfs and cachefiles traces can be cross-referenced — a debugging aid for anyone chasing NFS fscache I/O.

v7 versus v6, and where this sits

The cover letter’s v7 delta is almost entirely bug-fixing from Sashiko’s 20260716 patchset: double page-put in the bvecq kunit destructor, bvecq_alloc_buffer2() mishandling pre_slots>0 && size==0, missing barriers on bvecq::next and nr_slots, cachefiles resize treating expansions as shrinks, netfs_single_dispatch_read() not allowing the cache to round stored data out to DIO size, write collection never retrying cache writes, over-read abandoning the rest of the request, ->issue_read()/->issue_write() failure paths not advancing cursors, CIFS credit double-release, Ceph inline-file retry, and the NFS issue_read return-type fix. Paulo Alcantara has reviewed or acked several of the earlier, more mechanical patches (bulk readahead load, iov_iter_get_pages* wrap, ITER_BVECQ itself, bvec_kmap_partial()).

Howells already has an eye on the next steps: batched folio unlock over a bio_vec[], walking i_pages by the file position stored on the bvecq rather than via bv_page, making iov_iter_revert() reset-and-advance from a stored start (which would drop the prev pointer), and eventually replacing scatterlists so crypto drivers can still glue bits on the front.

Status this week: series posted, no Ack/Review traffic on linux-nfs, requested for the VFS tree via netfs-next. NFS client developers should treat v7 as the API they will have to match: nfs_netfs_issue_read() returns int, buffers arrive as bvecq slices, and over-reads are fatal -EIO rather than a truncated transfer.
