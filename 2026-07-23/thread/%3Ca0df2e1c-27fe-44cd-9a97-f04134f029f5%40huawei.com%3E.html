gssd leak fix lands in nfs-utils-2.9.2-rc6

Summary

gssd: leak fix in gssd_free_client committed to nfs-utils 2.9.2-rc6

Type: Bug fix (userspace NFS client tooling — rpc.gssd in nfs-utils) Week ending: 2026-07-23

Overview

A small but consequential leak fix for the NFS client's GSS helper daemon closed this week. Last week Huawei's zhangjian (CG) posted a one-function patch against utils/gssd/gssd.c after noticing that gssd_free_client() never released its upcall_* allocations. This week, nfs-utils maintainer Steve Dickson applied it as-is and tagged the result for the 2.9.2 release-candidate train.

Prior week, in brief

On 14 July, zhangjian diagnosed a dead branch in the client-context teardown path:

"clp->servername is always not null, so upcall_* is never free."

gssd_free_client() gated the upcall_* free on a null servername that the rest of gssd never actually produces, so every GSS upcall context leaked its associated buffers. The patch restructured that cleanup so the upcall_* allocations are released unconditionally (24 lines in utils/gssd/gssd.c, 14 insertions / 10 deletions, a single Signed-off-by). There was no list review in that window.

This week's development: committed, no further debate

The only in-window message is Dickson's 23 July ack-and-commit. Replying directly to the original patch, he wrote:

"Committed... (tag: nfs-utils-2-9-2-rc6)"

No review comments, no requested respin, no follow-up questions. The maintainer treated the diagnosis as self-evident and the diff as ready to land. That is the entire discussion this week: a one-line confirmation that the leak fix is now in the nfs-utils tree under the nfs-utils-2-9-2-rc6 tag.

Why it matters for NFS client development

rpc.gssd is the long-lived userspace half of Linux NFS Kerberos/GSS. The kernel client upcalls into it for context establishment; the daemon then holds per-server client state (clp) until those mounts go away. A leak on that free path is invisible to kernel kmemleak and shows up as slow RSS growth on hosts that churn GSS-secured mounts — exactly the class of "runs for weeks, then OOM" bugs operators hit on Kerberized NFS clients.

The bug itself was a classic invariant mismatch: cleanup code written for a nullable servername that the rest of the daemon made non-nullable. Dickson's silent commit endorses the cleaner of the two possible fixes — drop the dead conditional rather than invent a null-servername case — and puts the change on a short path into a stable nfs-utils RC.

This is not a protocol change, not a kernel-client change, and not a new feature. It is a maintenance/correctness patch in the client-side GSS helper, now queued for nfs-utils 2.9.2.

Bottom line

Huawei's gssd_free_client() leak fix posted 14 July was committed by Steve Dickson on 23 July with no further discussion, tagged nfs-utils-2-9-2-rc6. Kerberized NFS client hosts running a long-lived rpc.gssd should pick up that RC (or the eventual 2.9.2) to stop leaking upcall_* state on every client-context teardown.
