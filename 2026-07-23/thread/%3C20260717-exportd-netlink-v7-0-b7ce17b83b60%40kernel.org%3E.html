nfsd netlink stats v7 applied: server-side nfsstat moves to netlink, wdeleg_getattr retired

Summary

nfsd netlink stats v7 applied: server-side nfsstat goes netlink, and wdeleg_getattr is finally gone

Context (brief bridge)

This thread carries forward Jeff Layton's series converting the NFS server-side nfsstat interface from procfs scraping to a generic-netlink dump handler. The prior v6 thread (2026-07-23 summary) ended with the last open design question — what to do about the legacy wdeleg_getattr procfs counter — handed off to its original author, Dai Ngo, who had not yet replied.

This week that question is answered and the series lands: v7 was posted on Friday 2026-07-17 and applied to nfsd-testing the same day.

This Week (July 17): v7 posted and merged in one day

Layton posts v7, incorporating Dai's verdict

Layton posted v7 with an unapologetic cover letter:

"I last sent this series about a month ago, and dropped the ball on sending out a newer version afterward. This version fixes some minor issues that Chuck and Sashiko pointed out in review."

The stated motivation for the whole series is unchanged — the procfs interface has "several limitations: the counters are global (not network-namespace-aware), the format is fragile to parse, and it cannot be extended without breaking existing parsers." The v7-specific change relative to v6 is small but reflects the prior thread's conclusion:

"Skip never-called operations in the server-stats netlink dump instead of emitting a zero-count entry for every opcode"

And per his target: "Ideally, I'd like to see this go into v7.3."

The six patches

  1. 1/6 sunrpc: add per-netns per-procedure call counts to svc_stat — adds a vs_count pointer array to struct svc_stat plus svc_stat_alloc_counts() / svc_stat_free_counts() helpers, and increments the per-net counter alongside the global one in svc_generic_init_request().
  2. 2/6 sunrpc: use per-net counts in svc_seq_show() — a one-line change that makes /proc/net/rpc/nfsd itself report per-network-namespace procedure call counts. Layton notes "the only caller is nfsd, which always allocates vs_count via svc_stat_alloc_counts() in nfsd_net_init(), so the per-netns arrays are always available."
  3. 3/6 nfsd: implement server-stats-get netlink handler — the core of the series. The dump streams scalar stats (reply cache, filehandle, IO, network, RPC) followed by per-version procedure counts and NFSv4 per-operation counts. Layton's commit message documents a subtle sizing constraint: "the first dump message is allocated at NLMSG_GOODSIZE (a single page on most architectures) regardless of the client's receive buffer; packing every counter into one message would overflow it and fail the dump with -EMSGSIZE." Sections are therefore paged across messages, with cb->args[0]/cb->args[1] tracking section and entry index.
  4. 4/6 sunrpc: remove unused svc_version vs_count field — now that both svc_seq_show() and the netlink handler read the per-netns arrays, "the global per-version vs_count percpu counters are no longer read by anything." The field and its DEFINE_PER_CPU_ALIGNED initializers are removed across nfsd, lockd, and the NFS client callback service (11 files, 39 deletions).
  5. 5/6 nfsd: count NFSv4 callback operations per netns — adds a per-netns percpu counter array indexed by RFC 8881 callback opcode (OP_CB_GETATTR..OP_CB_OFFLOAD), bumped in nfsd4_run_cb(). This patch also implements the removal of wdeleg_getattr: "Report the procfs 'wdeleg_getattr' line from the CB_GETATTR counter and drop the now-redundant NFSD_STATS_WDELEG_GETATTR counter, its helper, and its increment site." Layton is candid about the semantic shift: "The two are not identical: the old counter incremented on every such conflict, whereas the CB_GETATTR counter only counts callbacks that are actually queued, so concurrent conflicts that coalesce onto an already in-flight CB_GETATTR are now counted once rather than once per conflict."
  6. 6/6 nfsd: export NFSv4 callback op stats via netlink — adds a proc4cb-ops nested attribute to the server-stats dump, reusing the existing op/count layout.

Lever applies it the same day

Chuck Lever replied at 13:30 UTC — roughly two and a half hours after the posting:

"Applied to nfsd-testing, thanks!"

He listed all six commit hashes. The series is now in nfsd-testing heading toward v7.3.

Key Technical Points

  • Namespace-aware server stats: The central win is that both /proc/net/rpc/nfsd and the new netlink handler now report per-network-namespace procedure counts, fixing the "counters are global" limitation Layton called out in the cover letter.
  • Backchannel observability: Patches 5/6 add the first-ever per-operation statistics for NFSv4 callback (backchannel) operations — previously only the forward channel (proc4ops) was tracked. This closes a real observability gap for diagnosing delegation recall and backchannel pressure from the server side.
  • wdeleg_getattr retirement: The counter that dominated the v6 thread is now gone as a first-class stat. Per Dai Ngo's verdict last week ("it would be better to remove it altogether"), patch 5/6 repurposes the procfs wdeleg_getattr line to report from the CB_GETATTR counter and deletes the dedicated counter, helper, and increment site.
  • Dump pagination: The -EMSGSIZE hazard on the first netlink dump message is handled by section-based paging — a design detail that matters for any userspace consumer merging attributes across messages.

Classification and Significance

  • Type: This is a new feature (netlink stats interface) combined with a cleanup/refactor (removal of global per-version counters and the wdeleg_getattr stat). The v6-era bug fixes (use-after-free in nfsd4_run_cb(), CB_SEQUENCE undercount on v4.1+) are already baked into the applied code; no new bug fix was introduced this week.
  • NFS client relevance: While server-side, the series directly affects how NFS client behavior is observable from the admin side. The new per-netns callback op counts (CB_GETATTR, CB_SEQUENCE, etc.) give operators a netlink-based view of delegation recall and backchannel activity — historically only visible via the fragile procfs scrape. The nfs-utils patch to consume this over netlink with a procfs fallback is already merged, so userspace tooling is ready.
  • Cleanup scope: Patch 4/6 touches fs/nfs/callback_xdr.c (the client's callback service) and both lockd service files, removing dead percpu counter initializers — a modest but welcome reduction of duplicated global state.

Where Things Stand

The series is applied to nfsd-testing with all six commits listed by Lever. The only remaining question from the v6 era — the fate of wdeleg_getattr — has been resolved in favor of removal, and patch 5/6 implements it exactly as Dai prescribed. With Layton's stated target of v7.3 and the series already in the testing tree, this thread is effectively done; future activity would be limited to any late review nits before the merge window opens.
