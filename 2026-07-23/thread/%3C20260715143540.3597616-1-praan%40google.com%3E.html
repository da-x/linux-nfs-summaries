NFS DIO pin-aware v3: Hellwig R-b, v4 nits

Summary

Summary

Review of Pranjal Shrivastava's v3 NFS Direct I/O modernization series finally arrived this week, five days after the patches landed. Christoph Hellwig walked the whole five-patch stack on 20 July and tagged the two functional DIO patches with Reviewed-by; Shivaji Kant followed with Reviewed-by on the helper patches. Shrivastava immediately acknowledged the remaining style nits and promised a quick v4. No protocol change is on the table — this remains NFS client infrastructure work (a refactor plus an embedded DIO lifetime bug fix) that prepares nfs_page for pin-based GUP so a later series can enable PCI P2PDMA.

Brief bridge from last week

v3 (cover) dropped the folio conversion that stalled v2 and kept five patches: pin-aware nfs_page, wb_nr_pinned tracking so only the primary request unpins, a bulk nfs_release_request_list helper, the actual switch of O_DIRECT onto iov_iter_extract_pages() (which also stops unpinning pages immediately after request creation), and a shared nfs_direct_extract_pages() helper. Last week's window closed with no replies.

Hellwig's patch-by-patch pass

Hellwig opened on patch 1/5 (nfs: make nfs_page pin-aware) with a style-only reservation:

"It would be nice to avoid the overly long lines, but otherwise this looks good." — Hellwig

On patch 2/5 (Track number of pinned pages in nfs_page) he flagged inconsistent subject-line capitalization across the series — "You probably one to stick to one version or another" — but otherwise signed off: "Otherwise this looks good to me." (Hellwig)

Patch 3/5 (nfs_release_request_list) drew the only real code comments. Hellwig asked that req be a local in the list-walk (or that the loop switch to list_first_or_null), and that the new prototypes drop superfluous extern keywords:

"req could/should be local here. Or you switch to list_first_or_null, which some folks prefer."

"Please drop the superflous externs for new code." — Hellwig

Patches 4 and 5 — the actual DIO migration to iov_iter_extract_pages and the nfs_direct_extract_pages helper that unifies the read and write schedule_iovec paths — received clean Reviewed-by tags with no further notes (4/5, 5/5). That is the important client-side result this week: the pin-lifetime bug fix (pins now held until I/O completion instead of being dropped at request creation) and the extraction refactor both have Hellwig's review.

Kant's second set of eyes

Shivaji Kant, also at Google, piled on two Reviewed-by tags. On patch 3 he asked only that the changelog typo "similat" become "similar", plus Hellwig's locals/extern nits:

"Small nit + fix christoph's comment, else looks ok" — Kant

On patch 5 he endorsed the consolidation explicitly:

"Refactoring looks good. Consolidates extraction, error handling, and iov_iter_revert() into a single helper shared by both read and write paths." — Kant

Author response: v4 incoming

Shrivastava answered every comment the same afternoon. He will trim the long lines in patch 1 and "post a v4 quickly" (ack). Subject lines will stay lower-case "as it seems to be common in the other commits" (ack). On patch 3 he made req local, dropped the externs (ack), and will fix the changelog typo (ack).

Where the series stands

This is not a protocol change. It is NFS client DIO plumbing: PG_PINNED / wb_nr_pinned so nfs_page can own GUP pins, a bulk-release helper patterned on bio_release_pages, and the iov_iter_extract_pages() migration that both modernizes the path and fixes premature unpinning. Folio conversion and ITER_ALLOW_P2PDMA remain follow-ups, as announced in v3.

By the end of this window the functional patches have Hellwig (and, for 3/5 and 5/5, Kant) Reviewed-by, and the remaining comments are mechanical. v4 has been promised but has not yet been posted; maintainers have not yet given an explicit merge ack. Last week's open questions — adding linux-rdma/linux-pci to CC, and whether the full xfstests suite (not just the previously-failing cases) was run — did not resurface in this review round.

Bottom line: v3's pin-aware DIO rewrite is through first review with only style nits outstanding. Watch for v4, then for a maintainer pull of the client-side unpinning fix and P2PDMA groundwork.
