Client DIO pin rewrite lands review; futimens() silently drops SETATTR; NLMv3 grant callback merged

Week ending 2026-07-23

The NFS client’s O_DIRECT path is the week’s biggest development story: Google’s pin-aware rewrite is through full review and ready to land as P2PDMA groundwork. Against that, a 7.0-era futimens() regression still has no patch, two lockd/lease crash fixes sit unreviewed, and Trond Myklebust shut down extra rdirplus= knobs in favor of traces. On the server, NeilBrown’s create-path refactor and Jeff Layton’s netlink stats both hit nfsd-testing in a day, while syzbot hangs exposed rpcbind I/O under nfsd_mutex as a multi-vector DoS.

Client DIO: pin-aware rewrite wins full review

Pranjal Shrivastava’s five-patch v4 DIO modernization is the week’s headline client series. It replaces iov_iter_get_pages_alloc2() with iov_iter_extract_pages(), adds PG_PINNED / wb_nr_pinned so nfs_page owns GUP pins, and centralizes extraction in nfs_direct_extract_pages(). The API swap also fixes premature unpinning: the old loop dropped pins immediately after request creation; pins are now held until I/O completion.

Christoph Hellwig walked v3 on 20 July (style nits plus Reviewed-by on the two functional DIO patches); Shrivastava respun the same day. Two days later Hellwig tagged the remaining three v4 patches “Looks good.” Shivaji Kant’s reviews from v3 carried over. xfstests -g quick on TCP and RDMA for NFSv3 and v4.0–v4.2 showed no regressions. Folio aggregation and ITER_ALLOW_P2PDMA remain follow-ups.

Mike Snitzer’s localio DIO misaligned-tracepoint fix is still pending: Anna Schumaker asked only for a Fixes: tag.

Critical client bugs: silent timestamps, lease crash, lockd oops

The most user-visible client defect this week has no patch. Michael Yang reported that GNU touch -d on NFSv4.2 returns success from fd-based futimens() / utimensat(fd, NULL, …) without sending SETATTR. Client stat briefly shows the new times, the server inode never changes, and revalidation snaps the cache back. Pathname-based utimensat() works. Holger Hoffstätte confirmed on 7.1.x and bisected the onset to the 7.0 window, pointing at nfs: split nfs_update_timestamps and the VFS ->update_time refactor. No maintainer reply landed.

Two crash fixes arrived unreviewed:

  • Zhansong Gao — nfs4_add_lease() races with delegation return and passes a possibly-NULL priv into nfs4_delete_lease(), oopsing in generic_setlease(). Four-line fix against the application-leases-on-delegations work.
  • Shuangpeng Bai — lockd installs NLM fl_ops even when lockowner allocation fails, so VFS teardown NULL-derefs in nlmclnt_locks_release_private(). Ancient (Fixes: 1da177e4c3f4), stable-Cc’d.

The one client-facing lockd bug that did land is Olga Kornievskaia’s NLMv3 GRANTED_MSG repair. Chuck Lever’s nfsd-7.2-2 pull restored nlmsvc_lookup_host() on the grant-callback path so a host without nfsd can accept the callback; Linus merged it 22 July. The xdrgen conversion had wired a client callback through the nfsd-gated server helper, hanging blocked NLM locks on ordinary clients.

Userspace: Steve Dickson committed Huawei’s gssd upcall_* leak and nfsd haddr overflow to nfs-utils-2-9-2-rc6.

Policy debate: no more rdirplus= knobs

Jorge Mora (NetApp) re-pinged for rdirplus=legacy / eager after a Rocky 8.7 → 6.12 GETATTR/LOOKUP storm on a read-only tree walk. Trond Myklebust was blunt: the client already has heuristic / none / force, and he is “violently opposed to adding yet another” slightly different heuristic. Capture the existing readdirplus tracepoints and argue for a default-heuristic fix; for static trees, use statx(..., AT_STATX_DONT_SYNC). The request is rejected pending data.

Swap, netfs, and kTLS: client plumbing in motion

Christoph Hellwig’s swap_ops v2 (acked by Chris Li) lets the NFS client supply struct swap_ops directly from fs/nfs/file.c, dropping the MM → swap_rw → NFS DIO double hop. No wire-protocol change; swap-over-NFS I/O loses one indirect call. A companion zram single-folio write restore is MM-only.

David Howells posted netfs v7 (29 patches): folio_queue / ITER_FOLIOQ give way to bvecq chains so a filesystem can emit one RPC with one kernel_sendmsg(). NFS must match a new ->issue_*() contract (nfs_netfs_issue_read() now returns int); over-reads become fatal -EIO. Three Yichong Chen leak fixes lead the series. No linux-nfs review in-window.

Chuck Lever’s kTLS read_sock_rectype v2 converts NFSD svcsock first; xprtsock is the named next consumer, so a kTLS NFS client can see KeyUpdate and fatal Alerts without a CMSG fallback. Sabrina Dubroca split patch 1 (empty TLS 1.3 data-record lock-pin) out to net; the new API stays on net-next.

Ameer Hamza’s SUNRPC NUMA_NO_NODE restore undoes a 2× READ-throughput collapse on four-node boxes (v6.17→v6.18): a folio-scratch conversion plus kthread auto-affinity pinned every globally pooled nfsd thread — and NFS client callback threads — to the creator’s node. Reviewed by Jeff Layton, applied to nfsd-testing ahead of the pool-mode rewrite, aimed at stable v6.18+.

Chuck also posted a four-patch SSC confinement that deletes the dead client nfs_ssc_client_ops table left by earlier UAFs, pins nfsv4 across sleeping ssc_open with RCU + try_module_get(), and splits the shared header so NFSD stops compiling client types. Preventive architecture after a trail of source-mount lifetime bugs; no replies yet.

Server: create-path and netlink stats land; rpcbind-under-mutex is a DoS

NeilBrown’s 18-patch nfs4_create_file() v5 — exclusive-create attribute drop, mounted-on-file CREATE across v2/v3/v4, groundwork for vfs_lookup_open() — was Reviewed-by Layton and applied to nfsd-testing the same day as the v4 posting.

Jeff Layton’s nfsstat→netlink v7 also applied same-day. Dai Ngo settled the leftover debate: drop wdeleg_getattr; CB_GETATTR counts are good enough. Per-netns procedure counts and the first backchannel op stats are in.

Chuck’s global DRC clean-ups (off-by-one prune limit; percpu_counter_add_local() to kill a global spinlock that fired on every ~144-byte DRC update) got Reviewed-by from NeilBrown and Layton. His flexfile UID mapping fix stops LAYOUTGET from leaking host UIDs into client AUTH_SYS creds in a non-initial user namespace — and uses from_kuid_munged() so an unmapped owner cannot wrap to uid 0. Layton reviewed.

Thorsten Leemhuis asked why the lock-owner UAF was not already on its way to Linus. Chuck’s policy: same CI/review as everything else; it rides the first nfsd-7.3 pull with a stable tag for 7.2.y. Original reporter Wolfgang Walter is fine carrying the patch.

The open server fight is control-plane locking. syzbot hung cache flush, then expkey-set-reqs and expkey-get-reqs, all on nfsd_mutex. Layton: synchronous rpcbind registration (including a ~60s rpc_ping) runs under that mutex; netlink listener_set can batch many sockets. NeilBrown wants a 1s timeout and questions holding the mutex across the whole batch; Layton says even 1s lockups with a few hundred listeners and prefers ordered async registration. No patches posted. Client impact: stalled fh-cache upcalls look like mount.nfs: Connection refused.

Header hygiene continued in parallel: NFSv4 tidying (Layton R-b), linux/nfs_fh.h, write-path vs v3 stable_how. Adjacent VFS: Howells’ foreign-UID inode ops (NFS keeps the default i_uid path); Brauner closed a duplicate fhandle NULL-deref as already fixed.
