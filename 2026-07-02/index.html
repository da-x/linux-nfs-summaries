Week ending 2026-07-02

Week ending 2026-07-02 — linux-nfs overview

A busy week on the NFS list, dominated by client-side protocol work and a wave of server-side stability backports. The headline items: Mike Snitzer's NFSv4.2 UNCACHEABLE_FILE_DATA / UNCACHEABLE_DIRENT_METADATA client feature moved to v3; Chuck Lever's delegation-return livelock fix was confirmed in Anna Schumaker's testing branch for the next bugfix round; and Jeff Layton's sunrpc pool_mode series reached v4 with full Reviewed-by from NeilBrown.

NFS client: new features

NFSv4.2 "uncacheable" attributes — v2 then v3 posted

Mike Snitzer posted both v2 (June 30) and v3 (July 1) of a six-patch series adding client support for two IETF-draft per-object attributes:

  • UNCACHEABLE_FILE_DATA (FATTR4 87): regular files transparently opened O_DIRECT so reads/writes bypass the page cache.
  • UNCACHEABLE_DIRENT_METADATA (FATTR4 88): directories force READDIRPLUS on every readdir to refresh per-entry metadata.

The motivating use case is multi-protocol namespaces (NFSv4.2 + NFSv3 + SMB) where client caches go stale faster than the cache lifetime. v3 over v2 was a build fix for CONFIG_NFS_V4_SECURITY_LABEL=n. No reviewer feedback has landed yet — the series is awaiting maintainer review.

Direct I/O folio migration: Hellwig de-escalates the safety concern

Christoph Hellwig finally replied to the direct-I/O folio debate that had been open for over a week. He confirmed that the slab/vmalloc concern raised by Matthew Wilcox does not apply to NFS direct I/O user pinning (GUP-pinned pages are always valid folios), but flagged a latent fragility in iov_iter_extract_bvecs() for kvec iterators. This effectively clears patch 6/7 of Pranjal Shrivastava's seven-patch "Modernize Direct I/O path" series, which also fixes a data-corruption bug and an early-unpin defect.

pNFS FSINFO layout-type overflow fix — v2

Michael Bommarito posted v2 of his security-relevant hardening for decode_pnfs_layout_types(), now using the canonical xdr_stream_decode_uint32_array() helper per Trond Myklebust's review. A malicious server could previously craft a count that wrapped 32-bit arithmetic and caused an out-of-bounds XDR read (confirmed via KASAN). Cc: stable.

NFS client: important bug fixes

Delegation-return livelock fix confirmed for merge

Chuck Lever's patch to return a delegation the client fails to record in nfs_inode_set_delegation() was confirmed by Anna Schumaker on July 2 as being "in a testing branch" and planned for "the next round of bugfixes." The fix prevents a state-manager livelock where a dropped DELEGRETURN leaves every subsequent SEQUENCE reply carrying SEQ4_STATUS_RECALLABLE_STATE_REVOKED.

TEST_STATEID loop on 6.17 — delegations disabled as workaround

Charles Hedrick (Rutgers) reported in the delegations status thread that upgrading to 6.17 did not resolve his site's delegation issues — it surfaced a TEST_STATEID loop instead. Fixes are believed to exist in mainline 7.0 but were not backported to Ubuntu's 6.17 HWE. Interim mitigation: NFSv4.2 with delegations off.

NULL-deref in nfs_inode_remove_request()

Jiangshan Yi (KylinOS) posted a fix for a dereference-before-NULL-check in the writeback completion path. The bug (also flagged by Baolin Liu in October 2025) crashes the kernel when nfs_page_to_folio() returns NULL. Awaiting review.

ENXIO on O_CREAT open of existing symlink over NFSv3

Michael Nemanov re-posted his fix for a cold-dcache bug where open(O_CREAT) on an existing symlink returns ENXIO instead of following it. The 7-line fix adds a type check and dispatches through finish_no_open(). Awaiting maintainer review.

fhandle: NULL mnt_ns panic via open_by_handle_at()

David Lee (Trail of Bits) posted a one-line fix for a kernel panic when open_by_handle_at() races with mount detachment. Reviewed-by Jeff Layton, applied to vfs.fixes by Christian Brauner the same day. Cc: stable.

NFS server (nfsd/sunrpc): critical fixes and trends

sunrpc pool_mode: starvation fix fully reviewed (v4)

The multi-week sunrpc pool_mode series reached v4 with NeilBrown's Reviewed-by on all four patches. The core fix prevents indefinite connection hangs when nfsd threads < NUMA nodes by routing to a populated pool. The RCU-vs-gate debate was resolved by dropping RCU and gating on sv_is_pooled. The correct Fixes: tag (bfd241600a3b) was identified after both author and reviewer initially had it wrong. A v5 with minor tweaks is expected.

6.18.37 nfsd regression: null-deref Oops in remove_blocked_locks

A production fileserver running 6.18.37 wedged hard (requiring power cycle). The backtrace points at remove_blocked_locks() → __destroy_client() — a list-corruption/UAF in NFSv4 client-state teardown. Chuck Lever suspects the export-cache cleanup revert (95f9eb19d5e6) as the sole nfsd delta between 6.18.36 and 6.18.37. A diagnostic build is pending.

Stable backports: write-verifier rotation, layout stid leak, CB_GETATTR

Chuck Lever posted three stable series on July 2:

  • 6.6.y: write-verifier rotation on deferred writeback errors (silent data-loss fix for UNSTABLE+COMMIT) and layout stid UAF.
  • 6.12.y: CB_GETATTR change-detection fix (RFC 8881 §10.4.3 compliance) and layout stid UAF.
  • 6.18.y: mtime/ctime on COPY/CLONE with delegated attributes and layout stid UAF.

All queued for stable within hours. The write-verifier fix is the most client-impactful: without it, clients silently lose data when backing storage has a deferred writeback error.

lockd: GRANTED_MSG fix reviewed; NLM_SHARE refcount debate

  • The GRANTED_MSG handling fix (client-side NLM callback regression from xdrgen refactoring) received Reviewed-by from NeilBrown and LGTM from Chuck Lever, who will split it for stable.
  • lockd TEST handling fix (ancient bug breaking read-only NFS access, notably qemu on ISO images) queued for 6.18.
  • The NLM_SHARE refcount series hit a wall: Chuck Lever rejected the refcount approach on idempotency grounds (NLM over UDP has no duplicate reply cache) and proposed a 16-bit mask instead. No v3 posted.
  • NLMv4 XDR regeneration (enum value validation hardening) reviewed by Jeff Layton, ready to merge.

SUNRPC sparse-flow dispatch: design in active flux

The RFC for a latency floor for interactive clients hit a critical finding this week: the exact-zero re-arm trigger collapses under load (a flow with even 2 RPCs in flight essentially never crosses depth==0). Chuck Lever argued watermarks merely relocate the cliff and proposed a decaying credit model instead. NeilBrown entered the debate, suggesting time-based batch detection and minimal inter-tier fairness from the start. The design is unresolved; real-workload data is the gating condition.

nfsd4_create_file() refactor + vfs_lookup_open() resubmission

NeilBrown posted a 10-patch nfsd4_create_file() refactor to prepare for the new VFS interface, including a create-race correctness fix (PATCH 05/10). Chuck Lever flagged that Sashiko found issues in 9 of 10 patches. Separately, Christian Brauner green-lit resubmission of the 18-patch vfs_lookup_open() series ("Yes, please resubmit"), deferring ordering against his O_CREAT|O_DIRECTORY work.

Other items

  • PID namespace in machinename/COMPOUND tag: Tigran Mkrtchyan's RFCs for multi-tenant debugging hit compile/scope issues and buffered-write semantics concerns from Trond Myklebust. Still open.
  • Null root/cwd in fs_struct: rejected by Brauner on security grounds ("open invitation for a slew of security bugs"). Dead end.
  • rpcbind nconf leak: one-line fix committed by Steve Dickson.
  • SUNRPC strlcat removal: deprecation cleanup, awaiting review.
  • RDMA ib_device_attr int→u32 v8: final INT_MIN edge case confirmed, v9 promised.
  • nfsd inter-server copy UAF fixes: NeilBrown reviewed all three patches — one approved, two need rework.
  • pnfs.rst doc fix: author pinged for review; still awaiting response.

Key trends this week

  1. Delegation/stateid reliability remains the top client-side concern. The livelock fix, TEST_STATEID loop, and CB_GETATTR change-detection all touch the same fragile state-management boundary. Production sites are running with delegations off as a safety measure.
  2. Server-side stability is getting serious attention from Meta (Chris Mason). Multiple UAF fixes in pNFS layout stateid teardown, the write-verifier data-loss fix, and the inter-server copy concurrency bugs all carry Meta authorship or reporting.
  3. XDR decoder hardening is ongoing. The NLMv4 enum validation regeneration and the pNFS FSINFO layout-type overflow fix both close remote-attackable input validation gaps.
  4. AI-assisted development is now visible in the patch stream. Multiple patches this week carry Assisted-by: Claude or Assisted-by: kres (claude-opus) tags, and the Sashiko automated review tool is actively flagging issues in submitted series.
