lockd GRANTED_MSG fix: Reviewed and queued for stable split

Summary

lockd: fix GRANTED_MSG handling — review and merge decisions

This week's activity (2026-06-26 → 2026-07-02)

The thread that opened last week with Olga Kornievskaia's [PATCH 1/1] lockd: fix GRANTED_MSG handling](https://lore.kernel.org/linux-nfs/20260625211852.31972-1-okorniev@redhat.com/) — a client-side NLM callback regression introduced by the xdrgen XDR refactoring of GRANTED_MSG — closed out this week with two short but consequential replies: a Reviewed-by from NeilBrown and an LGTM plus a process correction from Chuck Lever.

Key technical arguments

NeilBrown's review (2026-06-26, 01:49 UTC)

NeilBrown signed off on the fix and then flagged a naming concern that goes to the root of why this bug was so easy to introduce in the first place:

"Reviewed-by: NeilBrown neil@brown.name"

"That is a subtle difference between nlm4svc_lookup_host() and nlmsvc_lookup_host(). I wonder if making the names more distinct would help..." — NeilBrown

This is a pointed observation: the two helpers differ by only a few characters (nlm4svc_lookup_host vs nlmsvc_lookup_host), and the xdrgen conversion patch picked the wrong one precisely because the names are nearly indistinguishable. NeilBrown's suggestion to rename would be a follow-up hardening measure, not part of this fix itself.

Chuck Lever's LGTM and stable-branch split (2026-06-26, 13:27 UTC)

Chuck Lever confirmed the technical correctness but raised a process issue about how the patch should land in stable:

"The fix LGTM."

"Looking at this now, I see the patch targets two distinct stable kernels. Therefore IMO this does actually need to be two separate patches. I will split the patch when I apply it to nfsd-testing." — Chuck Lever

The original patch carried two Fixes: tags (62721885e861 for NLMv4 and 6c534ad999b6 for NLMv3), each pointing at a different stable kernel. Chuck's decision to split the single combined patch into two separate commits when applying it to nfsd-testing is the standard practice for stable backports: each stable tree gets only the fix relevant to its own Fixes: tag, keeping the bisect history clean and avoiding cross-contamination between NLMv3 and NLMv4 fixes.

Evolution of the discussion

  1. Last week (2026-06-25): Olga posted the patch with a clear explanation of the client/server asymmetry in the host-lookup helpers. No replies landed in that window.
  2. This week (2026-06-26, early): NeilBrown reviewed and approved, adding the naming-distinctness observation.
  3. This week (2026-06-26, midday): Chuck Lever confirmed LGTM and committed to splitting the patch for stable application.

The discussion was short and unanimous — no technical pushback on the fix itself. The only open thread (pun intended) is NeilBrown's suggestion about renaming the helpers for clarity, which would be a separate cleanup patch if anyone picks it up.

Final conclusions

  • Type: Bug fix (client-side NLM callback regression from xdrgen XDR refactoring).
  • Status: Reviewed-by (NeilBrown) + LGTM (Chuck Lever); Chuck will split into two patches for nfsd-testing / stable.
  • Impact on NFS clients: Pure NFS clients (no nfsd running) that were silently failing every incoming GRANTED_MSG callback — breaking asynchronous lock-grant notifications on both NFSv3 and NFSv4 mounts — will be fixed once the backports land.
  • Open item: Potential follow-up to rename nlm4svc_lookup_host() / nlm3svc_lookup_host() vs nlmsvc_lookup_host() to reduce future confusion (NeilBrown's suggestion, no patch yet).
