SUNRPC: drop deprecated strlcat() from rpc_sockaddr2uaddr()

Summary

SUNRPC: Replace strlcat() with snprintf() in rpc_sockaddr2uaddr()

What happened this week

This week's activity in the thread is a single, self-contained patch submission. On 2026-06-27, Ian Bridges posted a one-file cleanup patch to net/sunrpc/addr.c that removes the last use of the deprecated strlcat() helper from the SUNRPC address-formatting path. No maintainer or reviewer has replied within the reporting window, so the thread is still in its "posted, awaiting review" stage; a follow-up message from Bridges landed later (2026-07-29) and falls outside this week's scope.

Classification

This is not a new feature and not a protocol change. It is a bug-fix-adjacent code cleanup / API deprecation patch: it removes a deprecated kernel string helper in preparation for its eventual removal, while preserving existing behavior — including the truncation-safety check.

The technical argument

The motivation is stated up front in the cover message:

"In preparation for removing the deprecated strlcat() API[1], replace the snprintf()/strlcat() pair in rpc_sockaddr2uaddr() with a single snprintf() that appends the port suffix directly to the address buffer."

Bridges links the effort to the broader KSPP (Kernel Self Protection Project) tracking issue for strlcat() removal (https://github.com/KSPP/linux/issues/370), placing this small change inside a kernel-wide campaign to retire the function.

The core of the argument is that the old two-step sequence — format the address into addrbuf with snprintf(), then build a separate port string in portbuf and append it with strlcat() — can be collapsed into one write:

"rpc_ntop4() and rpc_ntop6_noscopeid() leave a NUL-terminated presentation address in addrbuf; the port is then formatted as ".p1.p2" and appended. Writing that suffix at addrbuf + strlen(addrbuf) with snprintf() yields the same universal address string as the separate portbuf/strlcat() step it replaces, so the intermediate portbuf is no longer needed."

Because rpc_ntop4() / rpc_ntop6_noscopeid() guarantee a NUL-terminated result in addrbuf, appending at addrbuf + strlen(addrbuf) is well-defined, and the redundant portbuf scratch buffer can be deleted entirely. The patch touches 11 lines (5 insertions, 6 deletions) in net/sunrpc/addr.c.

The safety property that matters most for a client-side address formatter is preserved explicitly:

"snprintf() returns the length it would have written excluding the NUL, so comparing it against the remaining buffer space preserves the existing truncation check that returns NULL."

That is, if the combined address-plus-port string would not fit, rpc_sockaddr2uaddr() still returns NULL exactly as before — no new truncation or overflow behavior is introduced.

Relevance to NFS client development

rpc_sockaddr2uaddr() lives in net/sunrpc/addr.c, the shared SUNRPC layer that backs both the NFSv3/v4 client and server socket address handling. The function converts a sockaddr into a "universal address" string (presentation-form IP plus port) used for RPC connection bookkeeping, XDR of addresses, and diagnostics. The change is behavior-preserving — same output strings, same NULL-on-truncation contract — so it carries low regression risk for NFS clients, but it does touch a core client-side code path and therefore still warrants normal review before merging. Its significance this week is as one more data point in the ongoing kernel effort to eliminate strlcat() (and its sibling strlcpy()) in favor of explicit length-checked formatting, reducing the surface area for subtle string-handling bugs across the tree.

Bottom line

A clean, minimal deprecation patch: replace a snprintf() + strlcat() pair with a single snprintf() append in rpc_sockaddr2uaddr(), delete the now-unused portbuf, and keep the existing truncation check intact. Posted 2026-06-27, still awaiting maintainer review as of the end of this reporting week.
