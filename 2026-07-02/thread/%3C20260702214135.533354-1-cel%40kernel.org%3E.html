nfsd 6.6.y stable backports: write-verifier rotation and layout-stid teardown

This week's activity (2026-06-26 → 2026-07-03)

This is a compact two-patch series posted by Chuck Lever on 2026-07-02 for the 6.6.y stable tree, both tagged Cc: stable@vger.kernel.org. The thread contains no review discussion within the window — it is a backport submission, with Sasha Levin's standard stable-queue acknowledgement landing just outside the window on 2026-07-04. Both patches fix server-side nfsd bugs that have direct, observable consequences for NFS clients: one silently violates the UNSTABLE+COMMIT durability contract; the other leaves a dangling pointer in the per-client stateid IDR after a pNFS layout setlease failure.

Patch 1/2 — release layout stid on setlease failure

Posted by Chuck Lever, authored by Chris Mason (Meta) and reviewed by Jeff Layton. This is a bug fix for a use-after-free / dangling-IDR-slot in the pNFS layout stateid path, backported from upstream commit 30d55c8aabb2 (Fixes: c5c707f96fc9 "nfsd: implement pNFS layout recalls").

The core defect, as described in the patch body:

"nfs4_alloc_stid() publishes the new stid into cl->cl_stateids via idr_alloc_cyclic() under cl_lock before returning to nfsd4_alloc_layout_stateid(). When nfsd4_layout_setlease() then fails, the error path frees the layout stateid directly with kmem_cache_free() without ever calling idr_remove(), leaving the IDR slot pointing at freed slab memory. Any subsequent IDR walker (states_show, client teardown) dereferences the dangling pointer."

The correct teardown for an IDR-published stid is nfs4_put_stid(), which removes the IDR slot under cl_lock and dispatches sc_free (nfsd4_free_layout_stateid) to release ls->ls_file via nfsd4_close_layout(). A second, subtler issue blocked that switch:

"nfsd4_free_layout_stateid() unconditionally inspects ls->ls_fence_work via delayed_work_pending() under ls_lock, but INIT_DELAYED_WORK(&ls->ls_fence_work, ...) currently runs only after the setlease call. On the setlease-failure path the destructor would touch an uninitialized delayed_work."

The fix hoists the ls_fenced / ls_fence_delay / INIT_DELAYED_WORK initialization above the nfsd4_layout_setlease() call and replaces the manual nfsd_file_put + put_nfs4_file + kmem_cache_free cleanup with a single nfs4_put_stid(stp). Chuck's 6.6.y adaptation note is worth flagging:

"[ cel: no ls_fence_work in 6.6.y; dropped INIT_DELAYED_WORK hunk ]"

so the backport is a minimal 1-line net change in fs/nfsd/nfs4layouts.c (1 insertion, 3 deletions) — just the switch to nfs4_put_stid().

Client impact: pNFS clients that exercise layout recalls / setlease failures against a 6.6.y server would otherwise hit a dangling-pointer dereference in states_show or at client teardown — a potential kernel oops on the server side, but one that can also surface as spurious NFSv4 stateid errors to clients mid-session.

Patch 2/2 — reset write verifier on deferred writeback errors

Posted by Chuck Lever, authored by Jeff Layton and reported by Chris Mason (Meta). This is a bug fix for a silent data-loss path in the NFSv3/v4 UNSTABLE+COMMIT durability contract, backported from upstream commit 2090b05803fa (Fixes: 555dbf1a9aac "nfsd: Replace use of rwsem with errseq_t").

The defect:

"nfsd_vfs_write() and nfsd_commit() both call filemap_check_wb_err() to detect deferred writeback errors, but neither rotates the server's write verifier (nn->writeverf) when this check fails. Every other durable-storage-failure path in these functions calls commit_reset_write_verifier() before returning an error."

The consequence is precisely the kind of silent data corruption that makes NFS durability bugs so serious:

"The missing rotation means clients holding UNSTABLE write data under the current verifier will COMMIT, receive the unchanged verifier back, and conclude their data is durable — silently dropping data that failed writeback. This violates the UNSTABLE+COMMIT durability contract (RFC 1813 §3.3.7, RFC 8881 §18.32)."

The fix adds commit_reset_write_verifier() calls at both filemap_check_wb_err() error sites, matching the pattern already used by adjacent error paths in the same functions. The helper internally filters -EAGAIN and -ESTALE, so the calls are unconditionally safe. Chuck's 6.6.y adaptation note:

"[ cel: 6.6.y predates the commit_reset_write_verifier() helper (v6.7); open-coded nfsd_reset_write_verifier() and the reset tracepoint at both sites, matching the other reset paths in these functions ]"

so the backport is a small open-coded change in fs/nfsd/vfs.c (8 insertions, 1 deletion).

Client impact: This is the more consequential of the two for NFS clients. Any client that issues UNSTABLE writes and then COMMITs — the standard pattern for buffered NFSv3 and NFSv4.0/4.1 data writes — against a 6.6.y server whose backing storage has a deferred writeback error would previously receive an unchanged verifier, treat the data as durable, and silently lose it. After this fix, the verifier rotates on the failure path, so the client's subsequent COMMIT returns a different verifier and the client correctly detects that the data was not durably committed (per RFC 1813 §3.3.7 / RFC 8881 §18.32), allowing it to retry or surface the error to userspace.

Final conclusions

  • Type: Two independent bug fixes for nfsd, backported to 6.6.y.
  • Patch 1 (layout stid): Use-after-free / dangling IDR slot on nfsd4_layout_setlease() failure; fixed by switching the error path to nfs4_put_stid(). Minimal 6.6.y delta because ls_fence_work does not exist in that tree.
  • Patch 2 (write verifier): Silent data loss on deferred writeback errors during UNSTABLE+COMMIT; fixed by rotating nn->writeverf at both filemap_check_wb_err() error sites, matching adjacent error paths. Open-coded for 6.6.y since the v6.7 helper is not present.
  • Status: Posted to stable; Sasha Levin's queue acknowledgement received (just outside this week's window). No in-window review discussion.
  • Client impact: Patch 2 is the higher-severity fix for NFS clients — it closes a silent data-loss path that violates the RFC-mandated UNSTABLE+COMMIT durability contract. Patch 1 prevents server-side crashes / spurious stateid errors on pNFS layout setlease failures.
