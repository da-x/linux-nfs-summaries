nfsd stable backports: delegated-attribute mtime/ctime on COPY/CLONE and layout stid leak fix

Summary

nfsd 6.18.y Stable Backport Series: Delegated-Attribute Timestamps and a pNFS Layout Stateid Leak

Type: Bug fixes (three separate regressions, all targeted for the 6.18.y stable tree) Participants: Chuck Lever (submitter), Olga Kornievskaia (author of patches 1–2), Chris Mason (author of patch 3), Jeff Layton (reviewer), Sasha Levin (stable maintainer)

Overview

On Thursday, July 2, 2026, NFS server maintainer Chuck Lever posted a three-patch series targeting the 6.18.y stable tree to fix two distinct classes of bugs in nfsd. The first two patches address incorrect mtime/ctime handling on the COPY and CLONE operations when delegated attributes are outstanding; the third fixes a use-after-free / dangling-pointer bug in the pNFS layout stateid teardown path. All three were queued for stable within hours.

Patches 1 & 2: mtime/ctime Updates on CLONE and COPY with Delegated Attributes

The first patch and its companion for COPY are authored by Olga Kornievskaia (Red Hat) and backport upstream commits 2863bac7f4 and 4183cf383b respectively.

The bug: When a client opens a file with delegated attributes, the server opens it with the NOCMTIME flag so that modifying operations do not update mtime/ctime — this prevents the server's attribute view from drifting out of sync with the client's delegated copy. However, COPY and CLONE are special: they modify the destination file on the server side without the client holding a delegation on it. As Lever's cover description explains:

"When delegated attributes are given on open, the file is opened with NOCMTIME and modifying operations do not update mtime/ctime as to not get out-of-sync with the client's delegated view. However, for COPY operation, the server should update its view of mtime/ctime and reflect that in any GETATTR queries."

Both patches carry Fixes: e5e9b24ab8fa ("nfsd: freeze c/mtime updates with outstanding WRITE_ATTRS delegation"), identifying the original commit that introduced the over-broad suppression.

Technical detail (patch 1/3, CLONE): The fix touches fs/nfsd/nfs4proc.c, fs/nfsd/nfs4state.c, and state.h (33 insertions, 15 deletions). It ensures the CLONE path explicitly updates mtime/ctime on the destination file's nfsd_file even when the source is opened with NOCMTIME. Lever noted in a bracketed annotation:

"[ cel: 9be4b7e74eb7 and 3daab3112f03 are missing from linux-6.18.y ]"

indicating that two prerequisite commits had not been picked up by the stable tree, requiring this patch to be self-contained for 6.18.y.

Technical detail (patch 2/3, COPY): A smaller change (11 insertions, 1 deletion) in fs/nfsd/nfs4proc.c and fs/nfsd/xdr4.h, applying the same mtime/ctime correction to the NFSv4.2 COPY operation path.

Patch 3: Release Layout stid on setlease Failure (Use-After-Free Fix)

The third patch is authored by Chris Mason (Meta), reviewed by Jeff Layton, and backports upstream commit 30d55c8aab. This is the most technically involved fix in the series.

The bug: A dangling-pointer / use-after-free in the pNFS layout stateid error path. Lever's description walks through the call chain:

"nfs4_alloc_stid() publishes the new stid into cl->cl_stateids via idr_alloc_cyclic() under cl_lock before returning to nfsd4_alloc_layout_stateid(). When nfsd4_layout_setlease() then fails, the error path frees the layout stateid directly with kmem_cache_free() without ever calling idr_remove(), leaving the IDR slot pointing at freed slab memory. Any subsequent IDR walker (states_show, client teardown) dereferences the dangling pointer."

The fix replaces the ad-hoc kmem_cache_free() cleanup with a proper nfs4_put_stid(stp) call, which correctly removes the IDR slot under cl_lock and dispatches the full stateid destructor.

A secondary issue: The standard teardown path (nfsd4_free_layout_stateid) calls delayed_work_pending(&ls->ls_fence_work), but on 6.18.y the INIT_DELAYED_WORK() for that work struct had not yet been hoisted above the setlease call (that hoist was part of a separate upstream commit not present in 6.18.y). Lever noted:

"[ cel: drop fence_work init hoist absent from 6.18.y ]"

so the stable backport is trimmed to just the nfs4_put_stid() replacement (net change: 1 insertion, 3 deletions in fs/nfsd/nfs4layouts.c).

AI-assisted development: Notably, the patch carries an unusual tag — Assisted-by: kres (claude-opus-4-7) — indicating AI tooling was used in developing or verifying the fix. This is one of the first instances of such a tag appearing on a mainline/stable NFS server patch.

Author correction: Twenty minutes after posting, Lever sent a brief follow-up clarifying:

"Please note: The correct Author for this patch is 'Chris Mason clm@meta.com'"

This was a minor metadata fix to ensure proper attribution in the stable tree.

Resolution

Stable maintainer Sasha Levin confirmed acceptance the following morning:

"Queued the series for 6.18.y, with the author of 3/3 fixed up to Chris Mason per your follow-up. Thanks!"

All three patches are now queued for the next 6.18.y stable release.

Significance for NFS Server Development

  • Delegated-attribute correctness: The COPY/CLONE mtime/ctime fixes close a gap where server-side file modifications could leave stale timestamps visible to other clients, violating POSIX expectations around attribute coherence.
  • pNFS robustness: The layout stid leak fix eliminates a potential kernel crash (dangling pointer dereference in states_show or client teardown) that could be triggered by a failed lease acquisition on a pNFS layout — a rare but serious reliability bug.
  • Stable-tree hygiene: Lever's bracketed annotations documenting which upstream commits are missing from 6.18.y exemplify careful backport engineering, ensuring the stable patches remain self-contained and correct in isolation.
