Summary

NFS delegation-return fix: maintainer confirms inclusion in next bugfix round

Overview

This week the long-silent thread on Chuck Lever's delegation-return patch finally moved from "posted and awaiting review" to "on a maintainer's testing branch, queued for the next bugfix submission." Two short messages on July 2 — a bump from Lever and a disposition reply from client maintainer Anna Schumaker — close out what had been a two-week wait. The underlying change remains an NFS client bug fix in fs/nfs/delegation.c, not a new feature or protocol change, and it targets a delegation-state livelock that can leave the client's state manager spinning forever.

Bridge from prior week

As summarized last week, Lever's original patch (June 17) closed a hole in nfs_inode_set_delegation(): three error flows returned without sending DELEGRETURN, so a delegation granted by the server in an OPEN reply could be silently dropped on the client. The protocol consequence, per Lever's RFC 8881 §20.2.4 argument, is that "a delegation can be relinquished only by DELEGRETURN," and dropping one leaves the server believing the client still holds it — cascading into a NFS4ERR_BADHANDLE on CB_RECALL, a phantom entry on the server's cl_revoked list, and a client-side livelock where "every subsequent SEQUENCE reply then carries SEQ4_STATUS_RECALLABLE_STATE_REVOKED." The patch (14 insertions, 4 deletions) hands the delegation back via DELEGRETURN in those error paths and carries a Fixes: tag pointing at ade044647dd56.

No maintainer review or commit landed between June 18 and July 1 — the thread sat idle for two weeks.

This week's activity

Lever's friendly bump

On Thursday, July 2, Chuck Lever re-quoted his original submission and asked:

"Friendly bump! What is the disposition of this submission?"

The message was a clean, low-pressure nudge — no new technical argument, no revised patch, just a request for status on what had been sitting in the maintainer queue since mid-June.

Schumaker's disposition

About 35 minutes later, Anna Schumaker replied with a concrete answer:

"I have it in a testing branch that I haven't pushed out yet. I'm planning to include it in the next round of bugfixes that I send out."

This is the first explicit maintainer disposition on the patch since its original posting. Two points are worth flagging:

  1. It has been tested, not just queued. Schumaker's phrasing — "in a testing branch" — indicates the patch has already gone through her local validation pass rather than merely being parked in a for-linus staging tree. That is a meaningful signal of confidence for a fix that touches the OPEN → DELEGRETURN → CB_RECALL state boundary.
  2. It will ride the next bugfix submission, not a feature pull. By routing it through "the next round of bugfixes," Schumaker is treating this as a correctness fix (consistent with the Fixes: tag) rather than folding it into a larger delegation rework. Given the severity Lever documented — a client-side state-manager livelock that is now routinely reachable because modern servers grant write delegations on any write OPEN — this is the right vehicle.

Technical significance

The fix itself was already well-argued last week; this week's exchange adds no new technical content but does confirm the patch's trajectory. For NFS client developers, the key takeaway is that the delegation-recall livelock class of bug is now being actively addressed: a dropped DELEGRETURN on an OPEN error path can no longer leave both sides out of sync on who holds a stateid. The Fixes: tag against ade04647dd56 also makes this a strong stable-candidate, and Schumaker's "next round of bugfixes" framing is consistent with that expectation.
