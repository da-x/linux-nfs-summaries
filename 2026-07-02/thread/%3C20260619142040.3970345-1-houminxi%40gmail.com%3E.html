Bridging Prior Weeks

For context, the original PATCH was submitted on June 19 (covered in the prior week's summary). It is a one-file documentation fix to Documentation/filesystems/nfs/pnfs.rst that corrects two stale references accumulated in the pNFS client docs:

  1. Layout header list location — the docs still described the layout header list as living in struct nfs_client (field cl_layouts), but it was moved to struct nfs_server (field layouts) in commit 6382a44138e7. As Minxi noted originally:

    "The layout header list was moved from struct nfs_client (cl_layouts) to struct nfs_server (layouts) in commit 6382a44138e7, but the documentation was not updated."

  2. Layout driver count — the docs still listed four layout drivers, including the objects layout driver removed in commit 6d22323b2e9f, leaving three implemented in the kernel client (files, blocks, and flexfiles).

Classification & Significance

This is a documentation bug fix — no code changes, no protocol changes, and no new features. It is low-risk housekeeping that keeps the pNFS client documentation in sync with earlier architectural shifts in the NFS client:

  • The move of cl_layouts to nfs_server->layouts reflects the shift from per-client-connection to per-mount (nfs_server) layout tracking, since layouts are associated with a specific export/mount point rather than the underlying server connection.
  • The objlayout removal simplified the pNFS client codebase, leaving three actively maintained layout drivers: files, blocks, and flexfiles.

Status & Outlook

The thread is quiet but alive. After eleven days without a reply, Minxi's June 30 ping signals continued intent to land the fix and an offer to "respin if any changes are needed." No maintainer acknowledgment has appeared in this window, so the patch is still awaiting review/merge. Given its minimal scope (a few lines of doc text), it is a strong candidate for quick pickup once a maintainer sees it.
