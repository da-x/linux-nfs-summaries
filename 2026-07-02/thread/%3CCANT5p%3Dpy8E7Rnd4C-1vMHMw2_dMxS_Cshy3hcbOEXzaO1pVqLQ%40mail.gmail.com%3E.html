Delegations status: Rutgers' 6.17 delegation upgrade hits a TEST_STATEID loop; fallback to delegations-off

Summary

Delegations in the NFSv4 client: the 6.17 "fix" fails on TEST_STATEID, so Rutgers falls back

This week at a glance

This week (June 26 – July 2) carries exactly one message in this thread, and it is a significant plot twist. Charles Hedrick of Rutgers — who two weeks ago had reported that upgrading to kernel 6.17 resolved the delegation-related vscode hang on his site's home directories — reports that the upgrade did not actually work. The new failure mode is a TEST_STATEID loop, and he is now planning to wait for Ubuntu's 7.0 HWE kernel in August.

This is a bug-fix / deployment-reliability discussion rather than a feature or protocol change. It is the practical tail of the earlier production-readiness inquiry opened by Shyam Prasad N about file and directory delegations in the Linux NFSv4 client.

The key message this week

Hedrick's June 29 update Re: Status of delegations feature in NFSv4 client opens with a blunt reversal of his prior report:

"Ugh. The upgrade to 6.17 failed. TEST_STATEID loops on some clients."

He then lays out the plan and the root-cause analysis he has pieced together:

"Next try: 7.0 when the Ubuntu 7.0 HWE comes out in August. there are known causes of this problem that look like they have been fixed in 7.0 but not 6.17. And it looks like Ubuntu didn't backport."

And finally, the interim mitigation he has settled on:

"So far NFS 4.2 looks OK for Ubuntu's 6.8 and 6.17 except for a very odd problem due to network interruption. But with delegations off."

He also flags a process gap that is relevant to anyone running large NFS deployments:

"I'm not sure where the right place for this is, but it would be useful for sites like mine to know what it's safe to use in what release."

How this bridges from last week

In the prior summary (week ending 2026-06-18), the thread had settled into a tidy three-part picture: Anna Schumaker confirmed file delegations are "stable for production environments" while directory delegations remain newer (recallable as of 6.19, with client-side CB_NOTIFY support still in progress); and Hedrick had offered encouraging field data —

"We have been successful with Ubuntu 24.04 upgraded to kernel 6.17, and a Redhat 9.8 server."

That optimism is what this week's message undercuts. The vscode hang on 6.8 was real and apparently fixed by 6.17, but the delegation machinery surfaced a different defect once exercised at Rutgers scale: TEST_STATEID looping on some clients. Hedrick's framing — that the known causes "look like they have been fixed in 7.0 but not 6.17" and that Ubuntu did not backport them — points to specific delegation/stateid recall-path fixes that landed upstream after the 6.17 branch point.

Why this matters for NFS client development

  • Delegation recall/stateid paths remain a live bug surface. The TEST_STATEID loop is a classic symptom of stateid validation or delegation-recall handling going wrong under real-world concurrent I/O — exactly the kind of long-tail reliability issue that synthetic benchmarks miss. Hedrick's institutional vantage point ("Rare events occur several times a semester. Impossible events occur at least once a year.") is what keeps surfacing these.
  • Distribution backporting is a first-order concern. The fix reportedly exists in mainline 7.0 but was not backported to Ubuntu's 6.17 HWE, leaving production sites stuck. This reinforces the recurring theme that "stable" for delegations is strongly version- and distro-dependent.
  • The practical recommendation this week is conservative: run NFSv4.2 with delegations off until a kernel carrying the TEST_STATEID fixes (7.0 HWE, expected August) is available — accepting the performance cost of disabling delegations in exchange for stability.

Evolution and current state

  1. June 16–18 (prior week): Shyam asks about production readiness; Anna gives the file-vs-directory delegation status; Hedrick reports the vscode-on-NFS-home hang on 6.8 and claims a successful 6.17 upgrade.
  2. June 29 (this week): Hedrick reports the 6.17 upgrade failed with TEST_STATEID loops, plans to retry on Ubuntu 7.0 HWE in August, and is running NFSv4.2 with delegations disabled as the safe interim configuration. He also asks where such release-safety guidance should live for production sites.

The thread is still open: Hedrick's question about a proper venue for "what's safe to use in what release" is unanswered this week, and his August 7.0 HWE retry will be the next data point. No patches or protocol changes were posted; the discussion remains deployment guidance grounded in a real-world delegation bug.

Classification

Bug fix / deployment reliability. Specifically, a regression-adjacent failure (TEST_STATEID looping) in the NFSv4 client's delegation/stateid handling on kernel 6.17, with fixes believed to exist in mainline 7.0 but not backported to Ubuntu — driving an interim fallback to delegations-off.
