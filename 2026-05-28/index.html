CB_NOTIFY dir-delegations land in nfsd-testing; pNFS client panic fix and a wave of memory-safety hardening dominate the week

Week ending 2026-05-28

linux-nfs Week Ending 2026-05-28

A heavy week for both NFS client and server. The headline event is Jeff Layton's CB_NOTIFY directory-delegation series (v4 → v5) landing in nfsd-testing, alongside a four-patch follow-on fix set — the server side of RFC 8881bis's new callback is now functionally complete, with only the Linux client implementation still outstanding. On the client side, Michael Bommarito's pNFS GETDEVICEINFO kernel-panic fix reached v2 after Anna Schumaker's review, and Dai Ngo posted a pNFS "scheduling while atomic" unmount fix. The rest of the week was dominated by a wave of memory-safety hardening: use-after-frees in lockd, sunrpc cache teardown, session-slot shrink, delegation laundromat, and the svcrdma transport lifecycle; plus two large server-side audit series from Chuck Lever (svcrdma PCL validation, RPCSEC GSS decode/backchannel) and a 10-patch "grab bag" of nfsd fixes from Layton. A second NFSD pull request for 7.1-rc was merged into mainline on May 26.

Critical client bugs & fixes

pNFS client: kernel panic from malformed GETDEVICEINFO (v2)

Bommarito's two-patch series fixing a remotely-triggerable NULL-pointer dereference in nfs4_decode_mp_ds_addr() reached v2 on May 27, addressing Anna Schumaker's two cosmetic nits from v1 review. The bug: a malicious pNFS metadata server can panic any flexfile or file-layout client with a 56-byte crafted GETDEVICEINFO body (multipath count ≥ 3, one valid pair). The fix flips < 0 checks to <= 0 and caps the unbounded mp_count loop at NFS4_PNFS_MAX_MULTI_CNT (256) in both layout drivers. Stable backport requested for three Fixes: targets. No new review yet on v2 — a quick apply is expected.

pNFS client: "scheduling while atomic" on unmount

Dai Ngo (Oracle) posted a fix for a sleeping-in-atomic-context bug where the block layout driver's return_range callback issues SCSI PR commands while the inode lock is still held during _pnfs_return_layout(). The patch defers the callbacks until after inode unlock, bumping the layout header refcount first. Affects any pNFS SCSI-block-layout deployment; can trigger a full panic under panic_on_warn.

pNFS client: use-after-free in pnfs_update_layout() (ongoing)

Wentao Liang's one-line tracepoint-reordering fix from last week drew a follow-up from Markus Elfring probing for code duplication in the 250+ line pnfs_update_layout() function. No maintainer response yet; the patch remains a strong stable candidate.

Client: optimize away CB_RECALL for write delegation (new)

Ben Coddington (Hammerspace) posted a client-side patch to preemptively return a write delegation when a SETATTR would strip the holder's own write access, avoiding an expensive CB_RECALL/NFS4ERR_DELAY/DELEGRETURN round trip. The access test is deliberately conservative (mode bits + fsuid/fsgid only), so false positives degrade gracefully. Trond Myklebust and Rick Macklem began reviewing on May 29 (just outside this window).

Major server-side work

CB_NOTIFY directory delegations: v5 applied + follow-on fixes

The 21-patch NFSD series implementing RFC 8881bis CB_NOTIFY callbacks reached v5 on May 22 (addressing Sashiko's review findings: alloc_pages_bulk failure path, NULL fsnotify mark, RCU-protected fi_deleg_file, GFP_NOFS, tracepoint hardening) and was applied to nfsd-testing by Chuck Lever on May 23. A four-patch follow-on series (FILEID_INVALID check, empty ne_file for dir-attr events, delegation-status check in cb_notify_done, tracepoint format fix) was applied within an hour. Layton's caveat stands: final mainline merge awaits a complete client-side implementation.

nfsd: "a pile of fixes for random bugs" (10 patches)

Layton posted a 10-patch grab bag on May 28 covering remotely-triggerable panics, UAFs, DoS vectors, and protocol correctness issues. Key items include: a BUG_ON fix for racing delegation revoke (with NeilBrown questioning the locking approach), session-teardown callback drain, grace-end serialization, reclaim dedup, NFSv3 SETACL mask gating, stable_how return (resubmitted from 2 years ago), append-only TOCTOU fix, partial-write detection off-by-half, POSIX ACL count cap (sparking a Rick Macklem/Chuck Lever debate on whether to reuse NFS_ACL_MAX_ENTRIES for NFSv4), and symlink target length validation. Early discussion active; no merge decision yet.

  • Thread

svcrdma: harden parsed chunk list against malformed wire values (6 patches)

Chuck Lever and Chris Mason (Meta) posted a 6-patch series fixing input-validation defects in the PCL data structure where wire-supplied values cause unsigned underflows — exposing slab memory to the Reply channel, driving multi-MiB allocations, or causing GPFs via zero-segcount chunks. Jeff Layton acked within 24 hours.

  • Thread

svcrdma: resource lifecycle bugs in transport setup/teardown (5 patches)

A follow-on series from Lever fixing cross-transport corruption on failed accept, UAF races in teardown ordering, netns reference leaks, a remotely amplifiable cm_id leak, and an ADDR_CHANGE replacement failure UAF. Introduces the rn_done sentinel for idempotent unregister. Layton acked within 20 minutes.

  • Thread

RPCSEC GSS decode and backchannel teardown hardening (6 patches)

Lever's audit series addressing stale-state bugs in the server-side GSS accept path (non-zeroing kmalloc reuse, NULL derefs, refcount leaks, dangling pointers) plus a genuine UAF in callback-service teardown. The backchannel fix is directly relevant to NFS client robustness. Layton granted Reviewed-by within 2.5 hours.

Trends & observations

  • AI-assisted development is now routine. Multiple patches this week carry Assisted-by: Claude or Assisted-by: kres (claude-opus-4-7) trailers — from Bommarito's pNFS and lockd fixes, to Layton's session-slot and openowner patches, to Mason's svcrdma and GSS patches. The automated review tools (Sashiko, Codex) are also catching issues before human reviewers, as seen in the three-round lockd UAF series.
  • Server-side hardening wave. Lever's two large audit series (svcrdma PCL, RPCSEC GSS) plus Layton's 10-patch grab bag represent a concentrated push to close remotely-triggerable memory-safety and DoS vectors in nfsd/sunrpc/svcrdma.
  • CB_NOTIFY is the gating item for client progress. The server side is functionally complete in nfsd-testing; the Linux NFS client implementation of CB_NOTIFY handling is the next major client-side feature work expected.
  • alloc_pages_bulk() semantics debate. Christoph Hellwig's thread revisiting the bulk allocator API (early-fail, folio, order>0, zeroed-array) pulled in Chuck Lever to explain sunrpc's forward-progress constraint on rq_pages. The xdr_buf → bvec migration is identified as the natural vehicle for eliminating sunrpc's last holdout.
  • nfsstat netlink conversion (v2). Layton posted v2 of his 4-patch series converting nfsd server statistics from procfs scraping to per-netns netlink, completing the user-space tooling migration pattern established by the mountd/exportd work in March. No review yet this week.
