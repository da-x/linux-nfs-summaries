Rick Macklem asks where to find striped flex file pNFS client patches

Summary

Striped flex file client patches — a quick Q&A on the list

This week's activity in this thread is brief but pointed: a single question from long-time NFS contributor Rick Macklem, and a short answer from Anna Schumaker (Anna "Schmastap" Schumaker) confirming where the work landed.

The question

On Friday, May 22, Rick Macklem opened the thread with a self-deprecating but practical query about where to find the client-side support for striped flex files in pNFS:

"Hopefully you mind a dumb ass question.. Are the patches for handling striped flex files pNFS for the client in a kernel on kernel.org now, or where is the best place to grab them from?"

The thread's subject — "striped flex file client patches" — frames this as a question about an existing feature (client support for the NFSv4.1+ striped layout type under pNFS), not a new patch series or protocol change being proposed this week. The discussion is purely about provenance: which kernel tree carries the work, and where a user can pull it from.

The answer

Four days later, on May 26, Anna Schumaker replied with a concise pointer:

"It looks like the patches went into Linux 6.18, so anything after that should have them."

"I hope this helps!"

That's the whole thread for the week — no follow-ups, no further debate, and no additional technical discussion. The conclusion is unambiguous: client-side striped flex file support in pNFS has been merged into mainline Linux as of 6.18, so any kernel at or after that release already includes it. No out-of-tree tree or separate patchset is needed.

Context and significance

This exchange is small in volume but meaningful for the broader picture of NFS client development:

  • Feature, not bug fix. The thread does not discuss a defect, regression, or protocol change. It confirms that a previously developed pNFS client feature — handling of striped flex files (a layout type used by some storage backends to stripe data across multiple devices) — has been accepted upstream.
  • Mainline convergence. For anyone tracking NFS client work, the practical takeaway is that the striped flex file client code is now part of the standard kernel.org tree rather than living in a personal or vendor branch. Anyone wanting to test or deploy it can simply use Linux 6.18 or newer.
  • Low-friction Q&A. The thread illustrates the kind of quick, low-stakes question-and-answer that keeps mailing lists useful as a community resource: a contributor with deep context (Macklem) asks where something landed, and a maintainer with current knowledge (Schumaker) answers in one line.

Bottom line

The discussion is a brief confirmation — not a new feature proposal, protocol change, or bug fix. The key conclusion, stated by Anna Schumaker, is that the striped flex file pNFS client patches are in mainline Linux 6.18 and later, so kernel.org trees at or after that release are the canonical source.
