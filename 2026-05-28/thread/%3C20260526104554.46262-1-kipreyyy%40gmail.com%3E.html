One-line UAF fix in nfsd delegation laundromat lands same-day via Layton review and Lever apply

Summary

nfsd: SC_STATUS_FREED missing on admin-revoked delegation FREE_STATEID — one-line UAF fix applied to nfsd-testing

Overview

A compact, single-patch thread closed the loop in under three hours on Tuesday, May 26. Zhenghang Xiao submitted a one-line patch to fix a use-after-free in the NFSv4 server's delegation laundromat, Jeff Layton reviewed it within an hour (catching an incorrect Fixes: tag on the way), and Chuck Lever applied it to nfsd-testing later that afternoon. It is squarely a bug fix — not a feature or protocol change — in the NFSD state-management code path around admin-revoked delegations, and it lands against the same delegation-lifecycle machinery that has been under heavy work this week (see the CB_NOTIFY directory-delegation series below).

The bug

The patch description lays out the failure mode with surgical precision:

"nfsd4_drop_revoked_stid() handles FREE_STATEID for admin-revoked delegations but does not set SC_STATUS_FREED before releasing cl_lock. revoke_delegation() uses this flag to detect whether FREE_STATEID has already processed the delegation — without it, the freed delegation is added to cl_revoked via list_add(), producing a use-after-free when cl_revoked is later traversed in __release_client()."

The author frames the fix as restoring symmetry with an existing code path:

"The SC_STATUS_REVOKED path in nfsd4_free_stateid() (line 7590) already sets SC_STATUS_FREED correctly. Apply the same pattern to the SC_STATUS_ADMIN_REVOKED path in nfsd4_drop_revoked_stid()."

The diff is a single insertion in fs/nfsd/nfs4state.c — one line changed, zero deletions. The original (incorrect) Fixes: tag pointed at 8be12e0cf211 ("nfsd: convert global state_lock to per-net deleg_lock"), the locking-conversion commit that restructured this area but did not itself introduce the flag-omission bug.

Review and landing

Jeff Layton's reply arrived roughly fifty minutes after the posting. He endorsed the fix but corrected the provenance:

"The Fixes tag doesn't look right. I think it should be: Fixes: 8dd91e8d31fe ("nfsd: fix race between laundromat and free_stateid") The patch looks OK though. Reviewed-by: Jeff Layton jlayton@kernel.org"

That's a meaningful correction — 8dd91e8d31fe is the commit that introduced the laundromat/free_stateid race machinery, i.e., the code path where the missing SC_STATUS_FREED actually bites. The corrected tag will matter for stable backporters when this lands upstream.

Chuck Lever's application note came about two hours after Layton's review:

"Applied to nfsd-testing, thanks! [1/1] nfsd: set SC_STATUS_FREED in nfsd4_drop_revoked_stid for delegations commit: a1da502807b6b63963f2b1064df76e0a58fb3479"

Context within this week's delegation work

This fix is small but lands in the same nfs4state.c neighborhood that has dominated linux-nfs traffic all week. Jeff Layton's 21-patch CB_NOTIFY directory-delegation series (v4) — the server-side counterpart to Christian Brauner's already-merged VFS patches — was posted earlier this week and continues to touch delegation lifecycle, cl_lock semantics, and the laundromat-adjacent state-management code. A UAF in the admin-revoked FREE_STATEID path is exactly the kind of latent hazard that becomes more reachable as new callback-driven delegation flows (CB_NOTIFY) add more workqueue-side traversal of client state. The fix removes one such landmine ahead of that feature's eventual merge, which Layton has noted will await a complete client-side implementation:

"I don't think we'll want to merge these until we have a complete client-side implementation to test against."

Client-side relevance

This is an NFSD (server) fix rather than an NFS client change — the UAF lives in __release_client()'s traversal of cl_revoked on the server. The practical impact for clients is indirect but real: a server hitting this UAF during admin-revoked delegation teardown can corrupt its own state or crash, which from the client's perspective looks like a sudden server-side loss of session/delegation state. Closing the bug reduces one class of spurious client-visible failures on NFSv4 servers that have been administering delegations (e.g., via nfsdctl-style tooling or nfsd_state.sh admin operations).
