ANNOUNCE: rpcbind-1.2.9 released

Overview

This week's activity in this thread is a single announcement message from Red Hat's Steve Dickson, posted on 2026-05-27, declaring the release of rpcbind-1.2.9 — the userspace RPC portmapper that sits underneath the Linux NFS client stack and is essential for mapping RPC service numbers to network addresses. The thread has no prior history in this archive (no earlier messages were found under the same root), so there is no multi-week discussion to bridge; the entire story is contained in one release note.

Classification

This is a bug-fix / maintenance release of an out-of-kernel NFS client component, not a protocol change or new feature. rpcbind is part of the classic RPC plumbing that the Linux NFS client (and server) depends on for service discovery; while it is not the kernel NFS client itself, its correctness directly affects whether mount.nfs and friends can locate their peer services reliably.

Key Technical Content

The release note from Steve Dickson is brief but points to two classes of fixes that matter for any deployment running NFS:

"This release contains: - A number of memory leaks fixes. - A couple buffer overflow fixes."

The memory leak fixes are typical long-running-daemon hygiene — rpcbind persists across reboots and handles many registration/deregistration cycles, so leaked allocations accumulate over time and can show up as slow RAM creep on NFS-heavy hosts. The buffer overflow fixes are the more security-relevant item: rpcbind parses untrusted input from both local callers and (depending on configuration) remote peers, so overflow bugs in its parsing paths have historically been a real attack surface for NFS-adjacent infrastructure.

Dickson also credits the bulk of the work to a colleague at Red Hat:

"Thanks to Scott Mayhew smayhew@redhat.com for doing the majority of the work."

This is worth noting for readers tracking who is actively maintaining the userspace NFS tooling on the Red Hat side — Mayhew has been visible across the linux-nfs list in recent cycles.

Distribution and Maintenance Notes

The announcement also includes two housekeeping items that are useful for anyone patching their distro:

"Both the tarball and change log can be found at http://sourceforge.net/projects/rpcbind"

and a relocation of the upstream git tree:

"The git tree was moved to: git://linux-nfs.org/~steved/rpcbind.git"

The move off SourceForge's git hosting onto linux-nfs.org is consistent with the broader consolidation of NFS development under the kernel.org / linux-nfs.org umbrella. Dickson closes by directing bug reports to both the kernel-side and libtirpc lists:

"Please send comments/bugs to linux-nfs@vger.kernel.org and/or libtirpc-devel@lists.sourceforge.net"

Conclusions

  • What shipped: rpcbind 1.2.9, a maintenance release focused on stability (memory leaks) and security (buffer overflows).
  • Who did the work: Scott Mayhew (Red Hat), with Steve Dickson cutting and announcing the release.
  • Why it matters for NFS client users: rpcbind is on the critical path for any NFSv2/v3 mount and for RPC service registration generally; the buffer overflow fixes in particular reduce a known class of risk in the userspace stack that surrounds the kernel NFS client.
  • Where to get it: SourceForge project page (tarball + changelog) and the new git tree at git://linux-nfs.org/~steved/rpcbind.git.
  • Discussion state: No replies or follow-up technical debate appeared in this thread during the week; the announcement stands as a one-shot release note.

For distro maintainers and NFS operators, the practical takeaway is straightforward: pull 1.2.9 to pick up the leak and overflow fixes, and update any pinned git references from the old SourceForge tree to the new linux-nfs.org location.
