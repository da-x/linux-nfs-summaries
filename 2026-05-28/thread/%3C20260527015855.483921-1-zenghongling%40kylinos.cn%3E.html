sunrpc: one-line fix for IS_ERR_OR_NULL() misuse in xprt sysfs store path

Summary

sunrpc: Fix error handling in rpc_sysfs_xprt_switch_add_xprt_store()

Type: Bug fix (NFS client / SUNRPC transport layer) Status this week: Patch re-posted; no review feedback yet.

What happened this week

The only activity in this thread during the reporting window was a fresh posting of a one-line patch by Hongling Zeng (KylinOS) on 2026-05-27, resending the same fix he had first sent on 2026-05-13 without any visible reply from maintainers in either thread. The current posting is byte-for-byte the same change, suggesting a nudge rather than a revision.

The technical argument

The patch targets rpc_sysfs_xprt_switch_add_xprt_store() in net/sunrpc/sysfs.c, the sysfs write handler that lets userspace add a new transport to an existing xprt switch (the mechanism behind multi-transport / resilient NFS client setups). Zeng's commit message is terse but precise:

"xprt_create_transport() never returns NULL, only valid pointers or error pointers. Using IS_ERR_OR_NULL() is incorrect, and PTR_ERR(NULL) would return 0, which indicates EOF in a sysfs store function."

The fix swaps IS_ERR_OR_NULL() for IS_ERR() on the return value of xprt_create_transport(). The reasoning matters: because the callee contractually never returns NULL, the NULL branch of IS_ERR_OR_NULL() is dead code — and worse, if it were ever taken, PTR_ERR(NULL) evaluates to 0, which a sysfs store callback interprets as "EOF / success", silently swallowing an error. The patch carries a proper Fixes: tag:

"Fixes: df210d9b0951 ("sunrpc: Add a sysfs file for adding a new xprt")"

The diff is minimal — one insertion, one deletion in net/sunrpc/sysfs.c — which is typical of the kind of defensive-coding cleanup that gets flagged by static-analysis or careful code review.

No maintainer (e.g., Trond Myklebust or Anna Schumaker) has weighed in, and there are no related threads in this week's window that cross-reference it. The re-posting pattern is common for small fixes that slip through a merge window — Zeng appears to be trying to get the change picked up before the next pull request.

Bottom line

A clean, low-risk one-line correctness fix in the SUNRPC sysfs transport-management path. It corrects a latent error-handling bug where a NULL return (which should be impossible) would have been misreported as success rather than an error. The patch is trivially reviewable and awaits maintainer ack; no protocol or feature change is involved — this is purely client-side robustness in the transport-switch sysfs interface.
