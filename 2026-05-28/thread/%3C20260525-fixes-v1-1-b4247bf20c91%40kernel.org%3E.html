nfs-utils: silence -Wunused-parameter warnings in netlink handlers

Summary

nfs-utils: mark unused netlink handler arguments with UNUSED()

Classification

This is a bug fix / code-quality cleanup for the nfs-utils userspace tree (specifically the shared support/nfs/nfsdnl.c helper), not a new feature or protocol change. It addresses compiler warnings that surfaced in the netlink callback plumbing recently added to support the kernel's generic-netlink-based NFS server control path.

This week's activity

The thread opened on Monday, May 25 with a single patch from Jeff Layton:

"Use the project's UNUSED() macro from nfslib.h to suppress -Wunused-parameter warnings on the error_handler, finish_handler, and ack_handler callback parameters that are required by the libnl callback signatures but not referenced in the function bodies."

The patch is small — four insertions and three deletions in support/nfs/nfsdnl.c — and carries a Fixes: tag pointing at commit 3ddc8e81240f, which is Chuck Lever's "exportfs: release NFSv4 state when last client is unexported" change. Layton framed it matter-of-factly in the cover note:

"Just some fixes for some new warnings I saw crop up recently."

The connection to that earlier work is meaningful context: the nfsdnl.c helper (and its libnl callback scaffolding) was introduced as part of the broader effort to give exportfs and friends a netlink-based channel into the kernel, replacing the older /proc-pipe interface. As more userspace tools started exercising those callbacks under stricter compiler flags, the unused-parameter warnings became visible noise in build logs — exactly the kind of thing that obscures real regressions.

Evolution and conclusion

Within the week there was no review debate or back-and-forth; the patch sailed through. Steve Dickson picked it up on Sunday, May 30 (just outside this week's window) with the standard maintainer sign-off:

"Committed... (tag: nfs-utils-2-9-2-rc4)" — Steve Dickson

So the discussion is effectively closed: the warning-suppression fix has landed in the nfs-utils-2.9.2-rc4 release tag.

Why it matters for NFS client/server tooling

While this particular change touches server-side userspace (exportfs/nfsdctl plumbing rather than the nfs client itself), it is part of the same netlink migration that underpins the modern admin story for both ends: clean state revocation on unexport/unmount, cache management, and listener control. Keeping the build warning-free in this shared helper layer keeps future patches to nfsdnl.c — which every netlink-using tool depends on — easier to review and less likely to hide real issues behind a wall of -Wunused-parameter noise.

Key takeaways

  • Type: bug fix (compiler-warning cleanup), not a feature or protocol change.
  • Scope: support/nfs/nfsdnl.c in nfs-utils; uses the existing UNUSED() macro from nfslib.h.
  • Provenance: fixes warnings introduced by commit 3ddc8e81240f ("exportfs: release NFSv4 state when last client is unexported").
  • Outcome: committed to nfs-utils at tag nfs-utils-2-9-2-rc4; no review objections raised.
