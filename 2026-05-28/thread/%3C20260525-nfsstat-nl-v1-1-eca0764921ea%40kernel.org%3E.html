nfsstat gains netlink support for NFS server statistics (v1)

Summary

nfsstat: Netlink Support for Fetching Server Statistics

Type: New feature (userspace tooling + kernel API)
Week ending: 2026-05-28
Status: Initial patch posted; no replies within this week's window.

Overview

On May 25, Red Hat's Jeff Layton posted the first version of an nfs-utils patch that adds Generic Netlink support to the nfsstat tool for retrieving NFS server statistics. The patch introduces a modern, structured alternative to the long-standing practice of scraping /proc/net/rpc/nfsd.

"Add Generic Netlink support to nfsstat for retrieving NFS server statistics, with automatic fallback to the existing /proc/net/rpc/nfsd parsing when netlink is unavailable (e.g., older kernels)." — Jeff Layton

Key Technical Details

The userspace patch touches three files in the nfs-utils tree:

FileChange
support/include/nfsd_netlink.h+86 / −31 — extended netlink header with new attribute definitions and helper declarations
utils/nfsstat/Makefile.am+4 / −2 — build-system tweaks to link the new netlink code
utils/nfsstat/nfsstat.c+282 — new netlink fetch path alongside the existing procfs parser

The new code sends an NFSD_CMD_SERVER_STATS_GET dump command over the nfsd generic netlink family and parses the reply to populate the same stat arrays already used by the proc path:

  • Reply cache (rc)
  • Filehandle (fh)
  • IO
  • Network
  • RPC
  • Per-version procedure call counts (proc2, proc3, proc4, proc4ops)

A critical design choice is graceful fallback: if netlink is unavailable (e.g., on older kernels that lack the new handler), nfsstat transparently falls back to parsing /proc/net/rpc/nfsd. This makes the patch safe to merge into nfs-utils without a hard dependency on a specific kernel version.

Kernel-Side Dependency

Layton explicitly notes that this userspace patch is not standalone:

"This patch requires the corresponding kernel patches to add netlink support." — Jeff Layton

The companion kernel series, posted minutes earlier on the same day as [PATCH v2 0/4] nfsd/sunrpc: convert nfsstat server-side interfaces to use netlink](https://lore.kernel.org/linux-nfs/20260525-exportd-netlink-v2-0-40003fed450c@kernel.org/), lays out the motivation and four-part kernel plan:

"The nfsstat tool currently scrapes /proc/net/rpc/nfsd for server statistics. This procfs interface has several limitations: the counters are global (not network-namespace-aware), the format is fragile to parse, and it cannot be extended without breaking existing parsers." — Jeff Layton

The kernel series (v2, 4 patches) covers:

  1. sunrpc: Add per-network-namespace, per-procedure percpu call-count arrays to struct svc_stat.
  2. sunrpc: Switch svc_seq_show() to read from the per-netns counters, making /proc/net/rpc/nfsd namespace-aware (noted as a deliberate behavior change).
  3. nfsd: Implement the server-stats-get netlink dump handler that streams reply-cache, filehandle, IO, network, and RPC statistics plus per-version and per-operation procedure counts.
  4. sunrpc: Remove now-unused global svc_version vs_count percpu arrays from nfsd, lockd, and the NFS client callback service.

The series also adds a netlink spec document (Documentation/netlink/specs/nfsd.yaml, 105 lines) and new UAPI headers (include/uapi/linux/nfsd_netlink.h, 35 lines).

Significance for NFS Development

This work addresses a long-standing maintainability problem in the NFS server tooling stack. The procfs interface has been the de facto way to read nfsd statistics since well before the modern kernel, but its text-based format is brittle and its global (non-namespaced) counters are increasingly inadequate in containerized and multi-tenant environments. Moving to a structured netlink API:

  • Makes statistics network-namespace-aware, which is essential for per-container observability.
  • Provides a stable, binary protocol that can be extended without breaking existing consumers.
  • Enables richer data (per-operation counts) that would be awkward to expose via procfs.

The fallback design ensures backward compatibility: administrators on older kernels see no change in nfsstat behavior.
