CB_NOTIFY Directory Delegation: v5 Applied to nfsd-testing After Sashiko Review Fixes

Overview

The long-running effort to add CB_NOTIFY callback support to NFSv4 directory delegations reached a significant milestone this week. Jeff Layton posted version 5 of the 21-patch NFSD series on May 22, addressing issues flagged by Sashiko during review. Just one day later, Chuck Lever applied the full series to nfsd-testing, confirming:

"Applied to nfsd-testing, thanks!"

This is a new protocol feature implementing RFC8881bis's CB_NOTIFY callback — allowing NFSv4 clients to register interest in directory changes (creates, unlinks, renames) and receive asynchronous notifications with updated attributes without losing their delegation lease.

Bridge from Prior Week

As documented earlier this week, v4 was posted on the same day (May 22) as a clean rebase onto Chuck's nfsd-testing branch sitting atop Christian Brauner's already-merged VFS directory delegation patches. Light review activity included Chuck Lever's nit on patch 20/21 split and Steven Rostedt's question about the show_fsnotify_mask() helper (resolved by pointing to Layton's dir-deleg branch).

v5 Changes: Sashiko's Review Fixes

The v5 cover letter is brief but substantive, listing six specific fixes:

"This version of the patchset fixes up some problems that Sashiko flagged during review."

The changes from v4 to v5:

  • Properly free dir delegation when alloc_pages_bulk() fails — a memory leak fix in the error path of alloc_init_dir_deleg().
  • Handle nfsd_file with no mark in nfsd_fsnotify_recalc_mask() — prevents a NULL dereference when the fsnotify mark hasn't been set yet.
  • nfsd_get_dir_deleg() should use stable nf pointer instead of depending on fi_deleg_file — eliminates a potential race by using the directly-held nfsd_file pointer rather than chasing through the delegation structure.
  • Use GFP_NOFS in alloc_nfsd_notify_event() since it's called with locks held — avoids a potential lockdep warning / deadlock scenario during memory reclaim while holding VFS locks.
  • nfsd_handle_dir_event() tracepoint now handles NULL pointers safely — hardens the tracing path against edge cases where event fields may be NULL.

These are all defensive/robustness fixes rather than functional changes, indicating the series had already stabilized architecturally.

Key Technical Highlights of the Series

The 21-patch series (2,188 insertions across 16 files) covers:

Protocol and XDR plumbing:

  • Patch 02 adds CB_NOTIFY to the XDR grammar and regenerates C code, also removing duplicate NFS4_VERIFIER_SIZE/NFS4_FHSIZE from UAPI headers.
  • Patch 03 adds new NOTIFY4_* flags from RFC8881bis.

Race condition hardening (bug fix):

  • Patch 08 converts fi_deleg_file to RCU protection: "Concurrent accesses from workqueue callbacks -- such as CB_NOTIFY -- can dereference a NULL pointer if they race with this teardown." This is critical for the callback path's safety.

Lease/fsnotify integration:

  • Patches 04–05 wire directory leases with ignore masks and maintain fsnotify marks across delegation add/remove cycles.

Event handling and attribute marshaling:

  • Patches 09–12 set up the notification infrastructure, including the important protocol constraint: "If the client doesn't set NOTIFY4_GFLAG_EXTEND, then don't offer any notifications, as nfsd won't provide directory offset information."
  • Patches 13–20 refactor fattr4 encoding to work without a svc_export/svc_fh context (unavailable in the callback path).
  • Patch 21 completes the feature: "the server will still recall the delegation on a SETATTR, so these are only sent for changes to child dirents."

Significance for NFS Client Development

While this is server-side work, it's a prerequisite for meaningful client-side improvements. Layton's caveat from the cover letter remains the governing constraint:

"I don't think we'll want to merge these until we have a complete client-side implementation to test against."

The server code is now in Chuck Lever's nfsd-testing tree with all 21 commits applied, but final upstream merge awaits the Linux NFS client counterpart that will handle incoming CB_NOTIFY callbacks. Once both sides are in place, clients will be able to maintain directory delegations across creates/unlinks/renames and receive push notifications with up-to-date attributes — reducing round-trips for workloads that monitor directory contents.

Status

  • NFSD patches (v5): Applied to nfsd-testing on May 23. All 21 commits landed.
  • Client-side implementation: Still pending; required before final merge into mainline.
  • Testing: Layton notes the series has "mainly been tested with pynfs, with some new testcases that I'll be posting soon."
