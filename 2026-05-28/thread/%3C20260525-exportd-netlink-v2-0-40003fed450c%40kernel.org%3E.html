nfsd/sunrpc: Convert nfsstat Server-Side Statistics to Netlink (PATCH v2)

Overview

This week's activity in the thread is a single event: on 2026-05-25, Red Hat's Jeff Layton posted the second revision of his four-patch kernel series, "[PATCH v2 0/4] nfsd/sunrpc: convert nfsstat server-side interfaces to use netlink". There were no replies or review comments within this week's window — the thread consists solely of the five messages (cover letter plus four patches) that Layton posted in quick succession. The series is a new feature / interface modernization rather than a bug fix, though it does include a deliberate behavior change to the procfs statistics output.

This kernel-side work is the natural companion to the user-space netlink upcall/downcall series Layton sent to nfs-utils back in March (bridged below), which moved mountd/exportd/exportfs off the legacy /proc cache interfaces. This series extends the same netlink-based philosophy to server statistics collection.

Motivation and Key Technical Arguments

Layton's cover letter lays out three concrete limitations of the current mechanism, in which the nfsstat tool scrapes /proc/net/rpc/nfsd:

"The nfsstat tool currently scrapes /proc/net/rpc/nfsd for server statistics. This procfs interface has several limitations: the counters are global (not network-namespace-aware), the format is fragile to parse, and it cannot be extended without breaking existing parsers."

The proposed solution adds per-network-namespace procedure call counts to the sunrpc layer and exposes them through a new netlink handler in the nfsd generic netlink family, with a procfs fallback retained for older kernels.

The Four Patches

Patch 1/4 — sunrpc: add per-netns per-procedure call counts to svc_stat This is the foundational change. The existing per-procedure counters live in global svc_version->vs_count[] arrays that are not namespace-aware. Layton adds a vs_count pointer array to struct svc_stat, plus svc_stat_alloc_counts() / svc_stat_free_counts() helpers to manage per-version percpu count arrays tied to the nfsd_net lifecycle:

"Add a vs_count pointer array to struct svc_stat, along with svc_stat_alloc_counts() and svc_stat_free_counts() helpers to manage per-version percpu call count arrays. Increment the per-net counter alongside the global one in svc_generic_init_request()."

Patch 2/4 — sunrpc: use per-net counts in svc_seq_show() A small but consequential change that switches svc_seq_show() to read from the per-netns arrays instead of the global ones. Layton flags this as an intentional semantic shift:

"This makes /proc/net/rpc/nfsd report per-network-namespace procedure call counts."

In the cover letter he is candid about the impact:

"Note that this is a behavior change, but I think it's a desirable one."

He notes the only caller is nfsd, which always allocates vs_count via svc_stat_alloc_counts() in nfsd_net_init(), so the per-netns arrays are guaranteed to be present.

Patch 3/4 — nfsd: implement server-stats-get netlink handler The core of the new feature. It implements nfsd_nl_server_stats_get_dumpit(), a dump operation that streams statistics across multiple netlink messages:

"First message: all scalar stats (reply cache, filehandle, IO, network, RPC) plus per-version procedure counts (proc2/3/4-ops) using per-netns vs_count arrays. Subsequent messages: NFSv4 per-operation counts (proc4ops-ops), one entry per message, using cb->args[0] to track the current operation index across dump calls."

This patch also adds a netlink spec (Documentation/netlink/specs/nfsd.yaml) and new UAPI definitions in include/uapi/linux/nfsd_netlink.h.

Patch 4/4 — sunrpc: remove unused svc_version vs_count field A cleanup that removes the now-dead global per-version vs_count percpu counters from nfsd, lockd, and the NFS client callback service. Notably, this touches NFS client code (fs/nfs/callback_xdr.c) — the callback service's unused counter array is dropped as part of the deprecation:

"Now that svc_seq_show() and the nfsd netlink stats handler both use the per-netns svc_stat vs_count arrays, the global per-version vs_count percpu counters are no longer read by anything."

Evolution and Context (Bridging Prior Weeks)

The v2 revision continues a multi-round effort. The March summary covered the user-space side — Layton's 17-patch nfs-utils series that gave mountd/exportd/exportfs netlink upcalls with procfs fallback, including robust graceful degradation ("the netlink setup silently fails and the daemon falls back to procfs-only operation"). This v2 kernel series is the server-side statistics counterpart, applying the same design pattern (netlink primary, procfs fallback) to nfsstat. The change-id in the cover letter (20260316-exportd-netlink-...) confirms this v2 descends from work started in mid-March.

Final Conclusions

As of the end of this week's window, the series has been posted but no review feedback or maintainer response had landed on this thread — it is awaiting discussion. Layton tees up the follow-on user-space work:

"I'll also be sending an nfs-utils patch to convert nfsstat to use the new interfaces."

The net effect, if accepted, would be a namespace-aware, extensible, binary statistics interface for NFS server monitoring — completing the migration of nfsd's user-space tooling off fragile procfs scraping. (Subsequent revisions v3–v7 of this series were posted in later weeks.)
