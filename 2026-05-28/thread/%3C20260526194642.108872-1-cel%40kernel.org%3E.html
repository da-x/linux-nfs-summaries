More NFSD fixes for 7.1-rc merged into mainline

Summary

[GIT PULL] More NFSD fixes for 7.1-rc — merged into torvalds/linux

A short but consequential thread this week: NFS maintainer Chuck Lever sent a second pull request of NFSD-side fixes for the 7.1 release candidate cycle, and it was accepted into Linus's tree within hours. The thread itself contains no technical debate — just the pull message and the automated merge confirmation — so the substance lives in what the three commits address.

The pull request

In the pull request, Lever describes the batch as nfsd-7.1 fixes (tag nfsd-7.1-2, on top of the earlier 7.1-rc work that ended with "NFSD: Fix infinite loop in layout state revocation"). He splits the changes into two buckets:

Issues reported with v7.1-rc:

  • Tighten bounds checking for sunrpc cache hash tables
  • Don't report key material in the ftrace log

Issues that need expedient stable backports:

  • Fix lockd's implementation of the NLM TEST procedure

The three commits are:

  • sunrpc: prevent out-of-bounds read in __cache_seq_start() (Chuck Lever) — a hardening fix in the sunrpc cache layer, tightening bounds checking on the cache hash tables. This is a memory-safety bug fix in shared RPC infrastructure used by both NFS client and server code paths.
  • NFSD: Report whether fh_key was actually updated (Chuck Lever) — a trace-hygiene fix that stops NFSD's ftrace events from leaking key material into the log. A small but meaningful security/hardening improvement for anyone running traced NFS servers.
  • lockd: fix TEST handling when not all permissions are available. (NeilBrown) — a correctness fix in lockd's implementation of the NLM TEST procedure, flagged by Lever as one that "need[s] expedient stable backports." This is the most user-visible bug of the three: NLM TEST is the procedure clients use to check whether a lock can be granted, and a broken TEST response can mislead NFSv3 clients about lock availability.

The diffstat spans 8 files (66 insertions, 32 deletions) across fs/lockd/, fs/nfsd/, and net/sunrpc/cache.c.

Merge confirmation

The pr-tracker-bot reply confirms the tag was merged into torvalds/linux.git at commit eb3f4b7426cfd2b79d65b7d37155480b32259a11, roughly four hours after Lever's request. No pushback or discussion followed in-thread — a clean, uncontested merge.

Context and significance

This is the second NFSD pull for 7.1-rc (the first, referenced as the base commit, fixed an infinite loop in layout state revocation on 2026-05-10). The batch here is squarely bug-fix work rather than new feature or protocol change:

  1. A memory-safety fix in sunrpc's cache hash-table iteration — the kind of latent OOB read that can be triggered by a malformed or adversarial RPC exchange, so it matters for both client and server robustness.
  2. A trace-leak fix in NFSD — important for operators who enable ftrace on production NFS servers; previously key material could appear in trace logs.
  3. An NLM TEST correctness fix by NeilBrown — the only item Lever explicitly earmarked for expedient stable backports, signaling it affects shipped kernels and real NFSv3 lock behavior.

From a client-development angle, the sunrpc cache fix touches shared RPC code that the NFS client also exercises, and the lockd TEST fix directly affects how NFSv3 clients observe lock state — both are relevant to anyone tracking client-visible regressions in 7.1-rc.
