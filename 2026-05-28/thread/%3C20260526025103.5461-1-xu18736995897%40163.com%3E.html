libnfsidmap: fix malloc(0) crash on empty Local-Realms

Summary

libnfsidmap: avoid malloc(0) for empty Local-Realms

Type: Bug fix (memory safety / undefined behavior in user-space NFS client tooling)

Overview

This week saw a small but important bug-fix patch land on the linux-nfs list targeting nfs-utils, specifically the libnfsidmap library that handles ID-mapping configuration for NFSv4 clients. The patch, submitted by xuchenchen of KylinOS, fixes an undefined-behavior bug where a malformed or degenerate Local-Realms entry in /etc/idmapd.conf could trigger a write to the result of malloc(0).

The Patch

xuchenchen posted the patch on 2026-05-26, explaining the root cause:

"conf_get_list() can return an empty list when Local-Realms is present but contains only empty fields, such as ', ,'. In that case the Realms list logging path computes a buffer size of zero and then writes a NUL byte to the result of malloc(0)."

The fix is minimal — two insertions, three deletions in support/nfsidmap/libnfsidmap.c — and does two things:

  1. Reserves space for the terminating NUL byte so the computed buffer size is never zero.
  2. Switches from malloc() to calloc(), ensuring the log buffer is valid (zero-initialized) even when the realm list is empty.

This is a textbook C memory-safety fix: writing a NUL terminator into a zero-length allocation is undefined behavior per the C standard and can manifest as a crash, silent corruption, or — in security-sensitive contexts — exploitable heap overflow depending on allocator behavior.

Resolution

The patch was accepted quickly. nfs-utils maintainer Steve Dickson confirmed on 2026-05-30:

"Committed... (tag: nfs-utils-2-9-2-rc4)"

The fix is now part of the nfs-utils-2.9.2-rc4 release cycle, meaning it will ship in the next stable nfs-utils point release.

Significance for NFS Client Development

While libnfsidmap is user-space rather than kernel code, it sits on the critical path for NFSv4 ID-mapping — the mechanism that translates between local UIDs/GIDs and global numeric or string-based identities across NFSv4 mounts. A crash in this library during configuration parsing (e.g., triggered by a misconfigured idmapd.conf with stray commas) could take down the entire idmapper service, breaking all NFSv4 file access on the affected host. The fix eliminates a class of crashes that would otherwise require users to manually clean up their realm configuration files.

The patch is notable for its surgical scope: it addresses a specific edge case (empty fields in a comma-separated list) without altering the broader parsing logic, making it low-risk for backporting to stable branches.
