NFS client eof page pollution regression resolved; case folding v7, NFSv4.0 deprecation refactoring, and heated export opt-in debate dominate this week

Week ending 2026-01-22

Critical Bug Fixes

NFS Client: EOF Page Pollution Regression Resolved

The multi-week investigation into ext4 checksum corruption caused by the NFS client's "eof page pollution" protection fix reached a positive conclusion. NVIDIA's testing team confirmed that Trond Myklebust's race condition patch — "NFSv4.2: Fix size read races in fallocate and copy offload" — successfully eliminates the issue. The fix has been submitted upstream for inclusion in 6.18.x stable kernels.

The root cause was a separate race condition in NFSv4.2 fallocate and copy offload operations where file size was read before locking the inode, causing nfs_truncate_last_folio() to overwrite valid data. The original eof page pollution safeguard remains intact. (thread)

pNFS Block Layout: SCSI Fencing Bug Fixed

Dai Ngo reported a critical bug in nfsd4_block_get_device_info_scsi where stale XA_MARK_0 marks on xarray entries prevented re-fencing of clients after SCSI reservation conflicts were resolved. Once an entry was marked as fenced, subsequent xa_insert calls would not update it, leaving the mark indefinitely and blocking necessary re-fencing operations. Chuck Lever applied the fix (wrapped in xa_lock for atomicity) to nfsd-testing, with a follow-up improvement to add named constants for the xarray marks planned. (thread)

pNFS SCSI Fencing v7: GETDEVICEINFO Fence Clearing

Chuck Lever posted v7 of the SCSI Persistent Registration Fencing patch, adding a critical enhancement: GETDEVICEINFO now clears existing fences, ensuring stale fencing state from prior operations is reset when clients re-register. Christoph Hellwig reviewed enthusiastically ("much better than before"). (thread)

syzbot: NFS Server Task Hang in expkey_flush

Google's syzkaller reported a task hang involving multiple tasks blocked on the global nfsd_mutex during export cache flush, filesystem unmount, and netlink thread configuration operations. No human response or patch was posted this week. (thread)

nfsiostat: Trailing Slash Mountpoint Fix

Scott Mayhew fixed a user-facing bug in nfsiostat where passing a mountpoint with a trailing slash caused statistics for all mounts to be printed instead of the requested one. Committed into nfs-utils-2.8.5-rc2. (thread)

Major Trends and Feature Development

Case Folding Behavior: v7 Posted, Near Merge Readiness

Chuck Lever posted v7 of the 16-patch "Exposing case folding behavior" series, resolving Jan Kara's initialization bug by removing a memset from vfs_fileattr_get. The series introduces a kernel-wide fileattr_get mechanism enabling filesystems to report case sensitivity/preservation characteristics. Key NFS client impact: the NFS client now implements fileattr_get, enabling accurate re-export of case sensitivity information and proper negative dentry caching behavior on case-insensitive shares. A UAPI collision with fsverity xflags remains, but Darrick Wong indicated it can be resolved at merge time. (thread)

NFS Client: Make NFS v4.0 KConfig-urable (Deprecation Step)

Anna Schumaker submitted a 14-patch series making NFS v4.0 support optional via Kconfig, as the first step toward eventual deprecation of the protocol version. The series extracts v4.0-specific code into new nfs40* files and promotes NFS v4.1 as the default, always-enabled minor version. This enables distributions and embedded systems to reduce code footprint while modernizing NFS client support. (thread)

bio_vec RDMA API v3: SQ Sizing Bug Fix Included

Chuck Lever posted v3 of the bio_vec-based RDMA read/write API series, which includes a critical bug fix for Send Queue exhaustion under heavy NFS WRITE workloads when memory registration is enabled. The fix introduces rdma_rw_max_sge() to correctly compute SQ entries needed. Christoph Hellwig provided Reviewed-by on the core API patch. (thread)

Ongoing Debates

Filesystem Opt-In for NFS Export: Heated Naming and Semantics Dispute

Jeff Layton's 31-patch series requiring filesystems to explicitly opt-in to nfsd export support via EXPORT_OP_STABLE_HANDLES sparked an intense and at times heated debate. The core disagreement centers on:

  • Naming: Christoph Hellwig insists on semantics-based naming (not NFS-specific); NeilBrown argues for explicit NFS export naming; Christian Brauner demands pseudo-filesystems be excluded regardless of flag name.
  • Scope: Is this about file handle stability, uniqueness, or maintainer choice to disallow export? NeilBrown argued "file handle stability was never the real issue, and maintainer choice was."
  • Resolution: Jeff Layton acknowledged the complexity and proposed potentially deferring to LSF for broader consensus. Amir Goldstein's narrower patch blocking special kernel filesystem exports (pidfs, nsfs) is accepted as a short-term path forward. (thread, v2)

Signed Filehandles v2: API Design Debate and Endianness Bug

Benjamin Coddington's v2 of the kNFSD signed filehandles series sparked a contentious debate over procfs vs. netlink API design. Chuck Lever strongly opposed adding new procfs APIs, ultimately persuading Coddington to drop the procfs interface. Eric Biggers identified an endianness bug in key handling that would cause different behavior across CPU architectures. Key rotation strategy was settled on "locked while server running." (thread)

NFS Delegation Control: Sysfs Knobs vs Open Flags Debate Rekindled

Olga Kornievskaia and Trond Myklebust revived the debate over how to provide delegation control. Three paths remain under consideration: sysfs knobs (Mayhew's approach), per-application open() flags (Myklebust's proposal), or userspace lease integration via Jeff Layton's ongoing work exporting NFSv4 delegations through the VFS lease framework. (thread)

Recall Timeout for Layout Conflict: Data Integrity Concerns

Dai Ngo's patch to enforce recall timeouts for pNFS layout conflicts raised serious data integrity concerns from Jeff Layton and Chuck Lever. The core issue: if a lease is removed before the rogue client is fenced, competing access could corrupt data. Reviewers insist on fencing before lease removal. The patch remains under active review with no resolution. (thread)

Other Notable Activity

  • Delegated Timestamps: Jeff Layton moved the feature from compile-time Kconfig gate to always-on with a runtime debugfs switch. Applied by Chuck Lever. (thread)
  • Block Export of Special Kernel Filesystems: Amir Goldstein's v2 patch preventing nfsd from exporting pidfs and nsfs received Reviewed-by from NeilBrown and Jeff Layton. (thread)
  • sunrpc/cache RCU Safety: Neil Brown's long-pending patch improving RCU safety in cache_list walking was finally applied to nfsd-testing. (thread)
  • NULL Pointer Fix Withdrawn: Jeff Layton's patch to fix a NULL pointer dereference in check_export() was self-withdrawn after discovering the kernel already had adequate protection. (thread)
