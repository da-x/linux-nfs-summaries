nfsd: Withdrawn fix for NULL pointer dereference in check_export()

Summary

Thread Overview

This brief thread concerns a bug fix for a NULL pointer dereference in the NFS server (nfsd) export code. The patch was quickly withdrawn by its author after realizing the issue was already handled elsewhere in the kernel.

Initial Patch Submission

Jeff Layton submitted a patch to address a potential NULL pointer dereference in check_export() within fs/nfsd/export.c. The bug could be triggered when mountd sends a path that has no export operations defined for its filesystem. As described in the commit message:

"Given the right export table, it's possible to trigger a NULL pointer dereference when mountd sends a path that has no export operations." As noted by Jeff Layton

The proposed fix added an explicit check for export_ops and returned -EINVAL if they were not set. Layton noted that triggering the bug required a "rather pathological export table" — he reproduced it by exporting the root directory ("/"). He also expressed uncertainty about whether the fix warranted backporting to stable kernels:

"Given that, I'm on the fence as to whether we want to send this to stable." Jeff Layton

Self-Withdrawal of the Patch

Shortly after submission (about 13 minutes later), Jeff Layton withdrew the patch himself. Upon further review, he discovered that the existing function exportfs_can_decode_fh() already performed the necessary NULL check:

"Hrm, actually exportfs_can_decode_fh() already checks this. You can disregard this patch." Jeff Layton

This means the kernel already had protection against the NULL pointer dereference scenario described in the original patch. The existing code path in check_export() calls exportfs_can_decode_fh(export_op) after verifying that export_op is non-NULL, making Layton's additional check redundant.

Automated Build Feedback

Despite the patch being withdrawn, the kernel test robot (0-DAY CI) still processed it and reported two issues:

  1. Build warning on parisc-defconfig with GCC 15.2.0: a const qualifier was being discarded when assigning inode->i_sb->s_export_op to a non-const pointer variable kernel test robot.

  2. Build error on arm64-randconfig with Clang 22.0.0: the same const qualifier issue was treated as an error due to -Wincompatible-pointer-types-discards-qualifiers kernel test robot.

These build issues were incidental to the patch's withdrawal and had no further impact on the discussion.

Conclusion

This thread was short-lived and concluded with the withdrawal of the patch. The key takeaway is that the NFS server already contained adequate safeguards against the NULL pointer dereference in check_export() via the existing exportfs_can_decode_fh() call. No code changes were merged as a result of this discussion.
