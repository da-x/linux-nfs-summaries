nfsiostat: normalize mountpoints with trailing slashes

Summary

nfsiostat: Trailing Slash Mountpoint Bug Fix

Classification: Bug Fix

This brief thread concerns a small but user-facing bug in nfsiostat, the NFS I/O statistics reporting tool included in nfs-utils. The patch addresses an issue where passing a mountpoint with a trailing slash on the command line caused unexpected behavior.

Problem Description

Scott Mayhew of Red Hat reported that when a user specifies a mountpoint with a trailing / character, nfsiostat fails to report statistics for that specific mount. Instead, it prints statistics for all mounts, which is misleading and unhelpful for targeted diagnostics.

As Scott explained in the commit message:

"If the mountpoint passed in from the command line contains a trailing '/' character, then nfsiostat winds up printing statistics for all mounts instead of printing statistics for the specific mount that was requested." Scott Mayhew

The Fix

The patch is a minimal two-line change in tools/nfs-iostat/nfs-iostat.py. It normalizes the mountpoint argument by stripping trailing slashes before processing, ensuring that /mnt/nfs and /mnt/nfs/ are treated identically. This brings the command-line behavior in line with user expectations — most filesystem tools on Linux treat trailing slashes as insignificant.

Resolution

NFS maintainer Steve Dickson promptly reviewed and accepted the patch:

"Committed... (tag: nfs-utils-2-8-5-rc2)" Steve Dickson

The fix was incorporated into the nfs-utils-2.8.5-rc2 release candidate, making it available for users seeking more reliable NFS I/O statistics reporting.

Significance

While small in scope, this fix improves the usability of a key NFS diagnostic tool. Administrators relying on nfsiostat for monitoring specific NFS mounts will no longer encounter confusing output when they inadvertently include a trailing slash — a common habit among Linux users accustomed to path conventions.
