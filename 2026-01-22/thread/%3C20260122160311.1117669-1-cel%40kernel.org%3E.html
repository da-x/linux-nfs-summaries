Case Folding v7: Memset Removal Fixes Initialization Bug; Series Ready for VFS Tree Submission

Summary

Case Folding v7: Final Memset Removal Posted, Series Nears Readiness for VFS Tree

Type: New feature / protocol enhancement (continued from prior weeks)

Prior Weeks Recap

Chuck Lever's 16-patch series "Exposing case folding behavior" has progressed through six versions since early January. The series introduces a kernel-wide fileattr_get mechanism enabling filesystems to report their case sensitivity and case preservation characteristics, allowing NFSD, ksmbd, and NFS clients to accurately convey filename semantics across protocol boundaries. Prior review rounds addressed struct layout optimization (packing flags into FS_XFLAG_* rather than dedicated fields), FAT's nocase mount option edge case, a UAPI collision with fsverity xflags, and an initialization bug flagged by Jan Kara regarding the flags_valid hint in ioctl_getflags(). See v4 summary, v5 summary, and v6 summary for full history.

This Week's Activity: v7 Series Posted

On January 22nd, Chuck Lever posted version 7 of the series [id://20260122160311.1117669-1-cel@kernel.org], based on v6.19-rc6. The sole change since v6 is surgical but significant:

"Changes since v6:

  • Remove the memset from vfs_fileattr_get"

This addresses Jan Kara's earlier concern that relocated struct initialization was inadvertently zeroing out the flags_valid hint before the filesystem's ->fileattr_get() callback could read it. By removing the memset from vfs_fileattr_get(), callers at ioctl/syscall entry points now zero-initialize the struct themselves, preserving hints passed to filesystem callbacks — a refinement that resolves the initialization bug without requiring "a bit more careful surgery" as Kara had suggested.

Key Technical Arguments

1. VFS Infrastructure: Cleaned-up file_kattr Initialization (Patch 01/16)

The foundational patch [id://20260122160311.1117669-2-cel@kernel.org] continues to encode case sensitivity through FS_XFLAG_CASEFOLD and FS_XFLAG_CASENONPRESERVING in fa->fsx_xflags. Lever explains:

"Filesystems report case-insensitive or case-nonpreserving behavior by setting these flags directly in fa->fsx_xflags. The default (flags unset) indicates POSIX semantics: case-sensitive and case-preserving. These flags are read-only; userspace cannot set them via ioctl."

The v7 change relocates struct file_kattr initialization from fileattr_fill_xflags() and fileattr_fill_flags() to the callers at ioctl/syscall entry points, allowing hints (flags_valid, fsx_valid) to be passed through to filesystem callbacks without being zeroed out.

2. NFS Client: fileattr_get for Case Sensitivity (Patch 10/16) — Critical for Re-export

The NFS client patch [id://20260122160311.1117669-11-cel@kernel.org] remains a cornerstone of the series for NFS infrastructure. As Lever explains in the commit message:

"An NFS server re-exporting an NFS mount point needs to report the case sensitivity behavior of the underlying filesystem to its clients. Without this, re-export servers cannot accurately convey case handling semantics, potentially causing client applications to make incorrect assumptions about filename collisions and lookups."

The implementation exposes case sensitivity information the NFS client already retrieves from servers during mount — via PATHCONF for NFSv3 or FATTR4_CASE_INSENSITIVE/FATTR4_CASE_PRESERVING attributes for NFSv4. NFSv2 mounts default to POSIX behavior since that protocol lacks PATHCONF support. The patch touches nine files across the NFS client codebase (client.c, inode.c, internal.h, nfs3proc.c, nfs3xdr.c, nfs4proc.c, proc.c, symlink.c, and include/linux/nfs_xdr.h).

3. NFSD: Dynamic Case Sensitivity Reporting (Patches 14-15/16)

NFSv3 PATHCONF [id://20260122160311.1117669-15-cel@kernel.org]: Replaces the hard-coded MSDOS_SUPER_MAGIC check with a dynamic query through ->fileattr_get. Lever notes:

"The hard-coded MSDOS_SUPER_MAGIC check in nfsd3_proc_pathconf() only recognizes FAT filesystems as case-insensitive. Modern filesystems like F2FS, exFAT, and CIFS support case-insensitive directories, but NFSv3 clients cannot discover this capability."

NFSv4 FATTR4 attributes [id://20260122160311.1117669-16-cel@kernel.org]: Replaces hard-coded responses with actual filesystem queries via nfsd_get_case_info(), supporting per-directory settings for filesystems that allow mixing case-sensitive and case-insensitive directories within an export. A v6 carryover improvement ensures the NFSv4 GETATTR clears the attribute mask bit if nfsd_get_case_info() fails, preventing stale or incorrect defaults from reaching clients.

4. Twelve Filesystem Implementations (Patches 02-13/16)

The series implements fileattr_get callbacks across twelve filesystems: FAT/exFAT, NTFS3, HFS/HFS+, ext4, XFS, CIFS, NFS client, f2fs, vboxsf, and ISO9660. The CIFS implementation is notable for multi-protocol environments where a Linux NFS server may re-export an SMB mount point and needs to accurately report its case handling semantics.

5. ksmbd Integration (Patch 16/16)

The in-kernel SMB server [id://20260122160311.1117669-17-cel@kernel.org] reports filesystem case sensitivity via FS_ATTRIBUTE_INFORMATION, enabling consistent multi-protocol file serving environments.

Significance for NFS Client Development

This series addresses several critical interoperability challenges:

  1. Windows/macOS NFS client support: As Lever emphasized in the cover letter, Windows-based NFS clients such as ms-nfs41-client "explicitly require servers to report FATTR4_WORD0_CASE_INSENSITIVE = TRUE for proper operation, a hard requirement for Windows client interoperability because Windows applications expect case-insensitive behavior."

  2. Linux NFS client caching correctness: Lever noted that "when a client detects a case-insensitive NFS share, negative dentry caching must be disabled (a lookup for 'FILE.TXT' failing shouldn't cache a negative entry when 'file.txt' exists) and directory change invalidation must clear all cached case-folded file name variants."

  3. Re-export accuracy: The NFS client's fileattr_get implementation enables NFSD to accurately report the case sensitivity of re-exported NFS mounts — essential for file service proxies and multi-protocol gateways.

  4. Multi-protocol environments: "Hammerspace servers and several other NFS server implementations operate in multi-protocol environments, where a single file service instance caters to both NFS and SMB clients. In those cases, things work more smoothly for everyone when the NFS client can see and adapt to the case folding behavior that SMB users rely on and expect."

Status and Outlook

The v7 series is posted and represents a refinement of the v6 submission, with the initialization bug resolved through the memset removal. The series remains on track to proceed through Christian Brauner's VFS tree rather than the NFSD subtree, targeting kernel version v6.20 or later (v6.19 is closed to new features). Two items from prior rounds remain noted:

  • UAPI collision: FS_XFLAG_CASEFOLD collides with Andrey's fsverity xflag patch. Darrick J. Wong indicated in the prior round that "whoever decides to merge them [can] fix up the conflicts whenever they merge them."
  • Struct initialization correctness: The v7 change directly addresses Jan Kara's concern about flags_valid being zeroed out prematurely.

The series has broad support across filesystem maintainers from prior rounds and appears well-positioned for eventual merge, representing a significant step forward in NFS client-server interoperability for cross-platform file serving environments.
