Delegated Timestamps: Kconfig Gate Removed in Favor of Runtime Debugfs Switch

Summary

Delegated Timestamps: Moved from Compile-Time Kconfig Gate to Always-On with Runtime Debugfs Switch

Summary

Type: Infrastructure / protocol feature maturation (not a bug fix, but a configuration simplification for an existing experimental NFSv4 extension)

Prior Context

The delegated timestamps feature in NFSD was introduced as an experimental NFSv4 extension based on an unratified IETF draft. It was previously gated behind a compile-time Kconfig option (CONFIG_NFSD_V4_DELEG_TIMESTAMPS), following the same pattern used for other experimental features such as the POSIX ACL support (which uses CONFIG_NFSD_V4_POSIX_ACLS). This approach allowed developers and distributors to opt in without risking production stability while the feature was still maturing.

This Week's Activity

On January 22, Jeff Layton posted a concise two-patch series titled "nfsd: move delegated timestamps to being runtime disabled instead of compile time". The series reflects the growing confidence in the delegated timestamps implementation after extended testing.

Patch 1/2: Runtime Debugfs Switch

The first patch [id://20260122-delegts-v1-1-40fbb180556c@kernel.org] adds a debugfs switch to allow disabling delegated timestamps at runtime. Layton explained the motivation in the cover letter:

"The delegated timestamp code seems to be working well enough that we want to just always enable it. There is a chance though that some clients or workloads could still see problems, so this also adds a debugfs switch to allow disabling them at runtime."

This provides a safety net for administrators who encounter issues with specific clients or workloads, without requiring a kernel rebuild or reconfiguration. The patch touches fs/nfsd/debugfs.c, fs/nfsd/nfs4state.c, and fs/nfsd/nfsd.h.

Patch 2/2: Remove Kconfig Option

The second patch [id://20260122-delegts-v1-2-40fbb180556c@kernel.org] eliminates the compile-time gate entirely. With the runtime debugfs switch in place, there is no longer a need for CONFIG_NFSD_V4_DELEG_TIMESTAMPS. The patch removes 10 lines from fs/nfsd/Kconfig and 7 lines from fs/nfsd/nfs4state.c, simplifying the codebase.

Chuck Lever's Response: Applied

Chuck Lever applied both patches promptly on January 22 [id://176911946777.1143362.852891163114456306.b4-ty@oracle.com]:

"Applied, thanks!"

Key Technical Arguments

The discussion was brief but decisive, reflecting broad consensus on the feature's readiness:

  1. Feature maturity: After extended testing in the kernel tree, the delegated timestamp code has proven stable enough to be enabled by default. The move from compile-time to runtime gating signals confidence in the implementation.

  2. Pragmatic safety net: Rather than removing the ability to disable the feature entirely (which would leave no escape hatch for problematic clients or workloads), a debugfs switch was added. This balances simplicity with operational flexibility.

  3. Code simplification: Removing the Kconfig option reduces maintenance burden and eliminates conditional compilation complexity in nfs4state.c.

Significance for NFS Client Development

While this change is server-side, it has direct implications for NFS clients:

  1. Wider availability of delegated timestamps: With the feature always enabled by default, more NFSv4 servers will support delegated timestamps out of the box. Clients that implement or rely on this extension can expect broader interoperability without requiring special server configuration.

  2. Debugging capability: The debugfs switch allows server administrators to quickly disable delegated timestamps if a specific client exhibits problems, facilitating targeted troubleshooting without kernel recompilation.

  3. Consistency with other experimental features: This follows the same maturation pattern as other NFSD extensions (e.g., POSIX ACLs), where compile-time gates are eventually replaced by runtime controls once stability is demonstrated.

Conclusion

The delegated timestamps feature has graduated from experimental status to always-on, reflecting confidence in its implementation. The addition of a runtime debugfs switch ensures that administrators retain the ability to disable the feature if issues arise with specific clients or workloads. Both patches were applied by Chuck Lever on January 22, completing this configuration simplification effort.
