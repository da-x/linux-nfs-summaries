Inquiry about FATTR4_TIME_METADATA support in Linux NFSv4 server

Summary

Linux NFSv4 Server Support for FATTR4_TIME_METADATA?

Overview

This thread consists of a single inquiry posted on January 20th with no replies during the current week. The discussion centers on a question about whether the Linux NFSv4 server supports the FATTR4_TIME_METADATA attribute and its reliability across various filesystems. This is neither a bug fix nor a new feature proposal, but rather an informational query about existing protocol support.

Key Message

Martin Wege opened the thread with a direct question to the community:

"Does the Linux NFSv4 server support FATTR4_TIME_METADATA? How reliable is this on ext4, xfs, btrfs, fat, tmpfs, ...?" Martin Wege

The FATTR4_TIME_METADATA attribute in NFSv4 is used to indicate whether the server supports reporting metadata change times (ctime). This attribute is relevant for clients that need to track when file metadata has been modified, such as for caching or synchronization purposes.

Status

As of the end of this week, no responses have been recorded in this thread. The question remains unanswered regarding:

  • Whether the Linux NFSv4 server advertises support for FATTR4_TIME_METADATA
  • How reliably different underlying filesystems (ext4, xfs, btrfs, fat, tmpfs) report metadata change times through the NFSv4 interface

This query may be of interest to NFS client developers who are considering whether they can rely on FATTR4_TIME_METADATA support when interacting with Linux-based NFS servers.
