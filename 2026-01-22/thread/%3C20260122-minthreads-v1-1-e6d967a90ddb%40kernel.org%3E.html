Removing min_threads from nfsdfs: Cleaning Up Procfs Interface for Dynamic Threading

Summary

Type: Bug fix / interface cleanup (NFSD server-side)

This thread is a brief but important follow-up to Jeff Layton's dynamic threading patches for NFSD. On January 22nd, Layton submitted a patch [id://20260122-minthreads-v1-1-e6d967a90ddb@kernel.org] to remove the min_threads file from the nfsdfs (procfs) interface, and Chuck Lever promptly squashed it into the original commit that introduced it.

Context: Dynamic Threading in NFSD

The dynamic threading feature allows NFSD to automatically scale the number of service threads per CPU pool based on workload demand, rather than relying solely on a static thread count set at startup via rpc.nfsd or /proc/fs/nfsd/threads. As part of that series, Layton introduced controls to set a minimum number of threads per pool — but inadvertently exposed this setting through the legacy procfs interface (nfsdfs) in addition to the intended netlink interface.

The original commit d086653f3250 ("nfsd: add controls to set the minimum number of threads per pool") added a min_threads file under /proc/fs/nfsd/, which was useful during development but was never intended for production use through the legacy interface.

The Patch: Removing min_threads from nfsdfs

Jeff Layton's patch [id://20260122-minthreads-v1-1-e6d967a90ddb@kernel.org] removes 44 lines from fs/nfsd/nfsctl.c, eliminating the min_threads procfs entry entirely. In his commit message, Layton explains:

"It was handy while I was developing the dynamic threading patches, but we don't have any plans to make this setting available via legacy rpc.nfsd. Remove the min_threads file from nfsdfs since only netlink interfaces were intended to get support for this."

He also references a prior discussion in another thread:

"As we discussed in another thread, this file should never have been added to the procfs interfaces. This patch just removes it, and leaves netlink as the sole way to set min-threads."

The patch carries a Fixes tag pointing to the original commit that introduced the procfs entry:

"Fixes: d086653f3250 ("nfsd: add controls to set the minimum number of threads per pool")"

Chuck Lever's Response: Squashed into Original Commit

Chuck Lever responded promptly [id://176911049554.1126364.18140238216896313921.b4-ty@oracle.com], noting that the dynamic thread series was still in nfsd-testing and squashed this cleanup into the original commit:

"The dynamic thread series is still in nfsd-testing for a few more days, so I squashed this one into 'nfsd: add controls to set the minimum number of threads per pool' and updated the commit message to reflect the change."

He confirmed the update would appear on git.kernel.org shortly.

Significance for NFS Development

This cleanup is significant for several reasons:

  1. Interface consistency: By removing the procfs entry, the NFSD maintainers are reinforcing a clear separation between legacy interfaces (procfs/rpc.nfsd) and modern management interfaces (netlink). The dynamic threading feature — including minimum thread count configuration — is intended to be managed exclusively through netlink going forward.

  2. Avoiding confusion: Leaving a development-era procfs file in place could mislead administrators into believing that min_threads can be configured via the traditional /proc/fs/nfsd/ interface, when in fact only netlink was designed to support this setting.

  3. Clean commit history: By squashing the removal into the original commit rather than creating a separate "remove" commit, the git history will reflect the correct final state of the feature from its inception — avoiding a confusing pattern where a file appears and then disappears in subsequent commits.

Conclusion

This thread represents a quick and clean resolution to an interface inconsistency introduced during the development of NFSD's dynamic threading feature. The min_threads setting remains fully functional through netlink; only the unintended procfs exposure has been removed. With the patch squashed into the original commit, the nfsd-testing tree will carry this correction forward as part of the broader dynamic threading series.
