Summary

pynfs: Allowing NAMETOOLONG Alongside REQ_TOO_BIG in SEQ6 Compound Handling

Overview

This short but focused thread addresses a bug fix in the pynfs NFSv4 test suite — specifically, updating a test to correctly accept NFS4ERR_NAMETOOLONG as an alternative error response alongside NFS4ERR_REQ_TOO_BIG when sending oversized compound requests via the SEQ6 operation.

Background

The pynfs test function testTooManyOps sends a request with more operations than the NFSv4 session can handle, expecting the server to respond with NFS4ERR_REQ_TOO_BIG. However, as noted in Calum Mackay's reply on 2026-01-22, the NFSv4 RFC permits servers to validate component operations (such as checking for NAMETOOLONG) before evaluating the overall compound request size limit. This means a server may legitimately return NFS4ERR_NAMETOOLONG instead of — or in addition to — NFS4ERR_REQ_TOO_BIG.

Key Technical Arguments

Animesh Javali from Red Hat initiated the thread on 2026-01-22 by submitting a patch that modifies the test to accept both error codes:

check(res, (NFS4ERR_REQ_TOO_BIG, NFS4ERR_NAMETOOLONG))

The patch also updates an associated FIXME comment in the test code.

Calum Mackay from Oracle responded later the same day, acknowledging the fix with appreciation:

"Thanks very much indeed."

He provided two pieces of feedback:

  1. Process note: He requested that future patches be sent inline rather than as attachments, noting:

    "in future, please send patches in-line, rather than as an attachment. I've appended it."

  2. Technical nuance regarding the FIXME comment: Calum raised an important distinction about test coverage intent:

    "I suspect that Fred's original intent, with FIXME, was that we want to check specifically the REQ_TOO_BIG handling, even though the RFC allows the server to check for NAMETOOLONG first."

He suggested that a separate, more targeted test should be added to explicitly verify REQ_TOO_BIG behavior on servers like NFS Ganesha — one that avoids triggering the NAMETOOLONG path:

"That probably requires a separate test to be added, which doesn't trigger the latter. i.e. it would be good to have a case that tests REQ_TOO_BIG handling on ganesha, which the current test doesn't."

Calum offered to adjust the FIXME comment slightly when applying Animesh's patch.

Final Conclusions

  • Bug fix accepted: The pynfs test suite will be updated to accept both NFS4ERR_REQ_TOO_BIG and NFS4ERR_NAMETOOLONG as valid responses in the testTooManyOps test, aligning with RFC flexibility regarding error-checking order.
  • Future work identified: A more targeted test case is needed to specifically exercise REQ_TOO_BIG handling without triggering the NAMETOOLONG path, ensuring comprehensive coverage of both error conditions on NFSv4 servers such as Ganesha.

Significance for NFS Client Development

This fix improves the robustness of the pynfs regression test suite, which is widely used to validate NFSv4 server implementations. By acknowledging that servers may return NAMETOOLONG before evaluating compound request size limits, the test better reflects real-world server behavior and avoids false negatives when testing compliant servers. This contributes to more reliable interoperability testing between Linux NFS clients and diverse server implementations.
