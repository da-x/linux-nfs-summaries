sunrpc/cache: RCU Safety Improvements in cache_list Walking

Summary

sunrpc/cache: Improve RCU Safety in cache_list Walking

Classification

This thread concerns a bug fix and code hardening effort in the SunRPC cache subsystem (net/sunrpc/cache.c), which underpins NFS server (nfsd) caching operations. The patch improves RCU (Read-Copy-Update) safety when walking the cache list, addressing both correctness issues and code clarity concerns.

Background (Prior Weeks)

The original patch was submitted by Neil Brown on October 18, 2025 here. Neil Brown outlined three improvements:

  1. Consistently using hlist_add_head_rcu() when adding to the cachelist, for clarity (though hlist_add_head() already provides sufficient barriers).
  2. Calling cache_get() before adding to the list with hlist_add_head_rcu(), incrementing the reference count before publishing a reference — "it look more correct to use this order."
  3. Avoiding possible races between NULL tests and hlist_entry_safe() calls, where "a test will find that .next or .head is not NULL, but hlist_entry_safe() will find that it is NULL," potentially causing list walks to terminate early.

Neil Brown characterized the issue as follows:

I was looking at this code a while back while hunting for a bug that turned out to be somewhere else. I notice point 1 and 2 above and thought that while of little significance, I may as well fix them. While examining the code more closely as part of preparing the patch I noticed point 3 which is a little more significant - clearly a bug but not particularly serious (I think).

Discussion Evolution

I wonder if this patch should be split for better bisectability. Are the changes to the *ppos calculations dependent on the RCU changes?

He also flagged an extraneous blank line in the diff. Neil Brown confirmed there was no dependency between the changes but was not convinced splitting all three items was worthwhile:

There is no dependency between the various changes. Did you just want the *ppos split out, or did you want the 1, 2, 3 also split apart. I considered that but wasn't convinced it was worth it.

Chuck Lever responded with a preference for either three independent patches or at minimum separating the *ppos changes:

Ideally, since you had listed three items in the patch description, there should be three independent patches. But if you think that isn't worth it, I'd be happy with the *ppos changes in a separate patch.

Key Technical Points

  • RCU list walking safety: The patch addresses a subtle race condition where concurrent RCU-based readers of the cache list could encounter inconsistent state between NULL pointer checks and hlist_entry_safe() dereferences, potentially causing premature termination of list iteration.
  • Reference counting discipline: Moving cache_get() before list insertion ensures the reference count is incremented before the object is published to concurrent readers — a defensive best practice even if not strictly required in this specific case.
  • Code clarity: Replacing hlist_add_head() with hlist_add_head_rcu() makes the RCU-safe nature of the operation explicit to future maintainers.

Conclusion

The patch was accepted and merged into the nfsd-testing tree under commit b4e702355adfd46215c52e14dcf661dc857afef0. This fix strengthens the RCU safety guarantees in the SunRPC cache subsystem, reducing the risk of subtle race conditions during concurrent cache list traversal — an important reliability improvement for NFS server operations.
