NFS client hardening: flexfiles panic fix, lockd memory leak patches, and major NLMv3 xdrgen conversion

Week ending 2026-05-14

Critical Bugs and Fixes

NFS Client Hardening

This week saw several important bug fixes targeting the NFS client, with a focus on pNFS layout handling and protocol robustness.

  • Flexfiles kernel panic fix: Michael Bommarito submitted a patch rejecting zero-length filehandle version counts in flexfiles layouts. Without this check, a malformed server response triggers a ZERO_SIZE_PTR allocation that later dereferences as a null pointer, causing a KASAN-reported kernel panic. The fix is marked for stable backport. (thread/NFSv4/flexfiles-reject-zero-filehandle-version-count.md)

  • pNFS filelayout stripe detection: Sagi Grimberg corrected the logic for determining whether a pNFS filelayout is striped, switching from num_fh > 1 to stripe_count > 1. The old check failed when MDS and DSs shared the same filehandle, leading to incorrect layout classification. (thread/pNFS/filelayout-fix-checking-if-a-layout-is-striped.md)

  • XFS pNFS LAYOUTGET overlapping extents: Dai Ngo fixed a regression in XFS's block layout server code where XFS_BMAPI_ENTIRE caused multiple calls within a single LAYOUTGET to return overlapping extent mappings. This could confuse client-side extent selection and lead to incorrect device routing. (thread/xfs-fix-overlapping-extents-returned-for-pNFS-LAYOUTGET.md)

  • NFSv4 mkdir retry regression: Thorsten Leemhuis followed up on an unmerged patch by Igor Raits that fixes spurious -EEXIST errors from mkdir(2) after a successful retry following NFS4ERR_DELAY. The patch, reviewed by NeilBrown and marked for stable, awaits maintainer action. (thread/NFSv4-clear-exception-state-on-successful-mkdir-retry.md)

lockd: Memory Leaks and Hash Corruption

Chuck Lever submitted three critical fixes for the NFS lock manager (thread/three-lockd-fixes.md):

  1. nlm_file leak on fopen failure — A malicious client presenting invalid file handles could trigger unbounded memory consumption.
  2. Refcount leak on cached fopen failure — Stale nlm_file entries became unreclaimable by the garbage collector.
  3. Uninitialized hash bytes in NLMv4 lookup — File handles shorter than 32 bytes hashed inconsistently, causing lock-state lookups to fail.

SUNRPC and NFSD Fixes

  • SUNRPC sysfs error handling: Hongling Zeng fixed incorrect IS_ERR_OR_NULL usage in the transport creation sysfs interface, which could mask errors as success. (thread/sunrpc-fix-error-handling-in-rpc_sysfs_xprt_switch_add_xprt_store.md)

  • SUNRPC cache UAF refinement: After detailed analysis by Yang Erkun, Chuck Lever confirmed that proc_entry_rundown already protects SUNRPC cache files from namespace-teardown races. The actual fix is deferring auth_domain_put() in ip_map release via RCU work. (thread/SUNRPC-Address-remaining-cache_check_rcu-UAF-in-cache-content-files.md)

  • NFSD export cleanup revert: Yang Erkun's revert of deferred sub-object cleanup in export put callbacks was approved by Jeff Layton after clarifying that RCU protects the relevant sub-objects. This resolves an unmount regression while maintaining UAF safety. (thread/Revert-NFSD-Defer-sub-object-cleanup-in-export-put-callbacks.md)

Major Trends

NLMv3 xdrgen Conversion (38 patches)

Chuck Lever submitted a massive 38-patch series converting all NLMv3 server-side procedures from hand-written XDR to xdrgen-generated code, completing the migration begun with NLMv4. The goals are improved memory safety and reduced maintenance burden. Jeff Layton provided a Reviewed-by after an AI-assisted review flagged a file-handle zeroing issue (which Chuck confirmed was a pre-existing regression from the NLMv4 series, not this one). (thread/lockd-Convert-NLMv3-server-side-procedures-to-xdrgen.md)

NFS Client Inode Cleanup

Jeff Layton submitted a four-patch series removing the redundant fileid field from struct nfs_inode, now that VFS supports 64-bit inode->i_ino. This saves 8 bytes per inode and eliminates legacy XOR-folding hashing machinery. The series also fixes two pre-existing tracing bugs where fileid fields were truncated to u32. (thread/nfs-remove-the-fileid-field-from-struct-nfs_inode.md)

Block Layout Export Cleanup Applied

Christian Brauner confirmed that Christoph Hellwig's four-patch NFSD block layout export cleanup series has been applied to the VFS tree (vfs-7.2.exportfs). This ensures correct handling of loca_time_modify per RFC 8881 and prepares for multi-device block layout exports. (thread/cleanup-block-style-layouts-exports.md)

Ongoing Debates

ENOSPC/EDQUOT Writeback Safety

Piyush Sachdeva continued the discussion on preventing silent data loss when servers run out of space during asynchronous writeback. He noted that even NFSv4.2 ALLOCATE may defer space checks until writeback, and performing synchronous pre-write checks would harm performance. Experiments are planned. (thread/Preventing-ENOSPC-EDQUOT-writeback-errors-on-network-filesystems.md)

pNFS Layout Recall Semantics

Sagi Grimberg posted a question on file layout recall behavior, though no replies were received this week. This follows significant prior work by Dai Ngo on layout recall timeouts and lease manager fencing integration. (thread/Question-on-file-layout-recall.md)

Security Hardening: RxGK Length Checks

David Howells submitted a patch adding pre-decrypt/pre-verify length validation to the Kerberos crypto library and applying it in the rxrpc RxGK security class. While primarily targeting AFS, this hardens infrastructure shared by NFS clients using Kerberos-based security. (thread/crypto/krb5-rxrpc-Fix-lack-of-pre-decrypt-pre-verify-length-checks.md)
