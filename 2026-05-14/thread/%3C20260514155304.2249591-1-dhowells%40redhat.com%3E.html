rxrpc/RxGK: v3 Pre-Decrypt Length Check Fix for Kerberos Crypto

Summary

Type: Bug fix (security hardening)

David Howells submitted version 3 of a patch this week as part of a four-patch series targeting the net tree, addressing a security gap in the AF_RXRPC subsystem's handling of Kerberos-secured (RxGK) data packets. This is an evolution of the v2 patch discussed last week.

The Problem

The patch description states:

"Change the krb5 crypto library to provide facilities to precheck the length of the message about to be decrypted or verified."

"Fix AF_RXRPC to make use of this to validate DATA packets secured with RxGK."

The issue traces back to commit 9d1d2b59341f, which introduced the yfs-rxgk security class (GSSAPI) for rxrpc. Without proper length validation before decryption or verification, malformed packets could potentially cause issues in the crypto processing pipeline. The patch also references an external bug tracker entry:

"Closes: https://sashiko.dev/#/patchset/20260511160753.607296-1-dhowells%40redhat.com"

Technical Scope

The fix touches five files across the crypto and rxrpc subsystems:

FileChanges
Documentation/crypto/krb5.rst+17/-3 (updated API documentation)
crypto/krb5/krb5_api.c+54/-4 (core length-checking logic)
include/crypto/krb5.h+9/-2 (API header updates)
include/trace/events/rxrpc.h+1 (tracing enhancement)
net/rxrpc/rxgk.c+15/-2 (rxrpc integration)

The patch marks itself for stable kernel backporting via the cc: stable@vger.kernel.org tag, underscoring its importance as a security-related fix.

Relevance to NFS

While this patch primarily targets the AF_RXRPC socket family and the Kerberos crypto library — infrastructure shared between AFS and NFS over RDMA with Kerberos security — it is CC'd to linux-nfs@vger.kernel.org and Chuck Lever, indicating its relevance to NFS clients that may leverage rxrpc-based transports or share the underlying krb5/crypto infrastructure. The fix hardens pre-decrypt validation, which benefits any consumer of the Kerberos crypto API, including NFS clients using Kerberos-based security mechanisms.

Evolution from v2

This is version 3 of the patch series. The previous week's summary covered v2, which received a brief acknowledgment from Jeffrey Altman. The v3 submission appears to be a refinement of the same fix, with minor adjustments (notably in net/rxrpc/rxgk.c where changes increased from +11/-2 in v2 to +15/-2 in v3).

Conclusion

This is a straightforward bug fix that adds missing input validation to the Kerberos crypto library and applies it in the rxrpc RxGK security class. The patch has been marked for stable backporting, reflecting its significance as a defensive measure against potentially malformed network packets. No substantive technical debate was raised in this window, suggesting the fix is well-received and likely to be merged.
