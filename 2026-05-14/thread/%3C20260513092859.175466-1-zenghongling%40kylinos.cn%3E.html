sunrpc: Fix incorrect IS_ERR_OR_NULL usage in sysfs transport add

Summary

sunrpc: Fix error handling in rpc_sysfs_xprt_switch_add_xprt_store()

This week saw a small but important bug fix in the SUNRPC subsystem, specifically addressing incorrect error handling in the sysfs interface for adding new transports.

The Bug

Hongling Zeng from KylinOS submitted a patch to correct a logic error in rpc_sysfs_xprt_switch_add_xprt_store(). The issue stemmed from a misunderstanding of the return value semantics of xprt_create_transport().

As Zeng explained:

"xprt_create_transport() never returns NULL, only valid pointers or error pointers. Using IS_ERR_OR_NULL() is incorrect, and PTR_ERR(NULL) would return 0, which indicates EOF in a sysfs store function."

The original code used IS_ERR_OR_NULL() to check the result of xprt_create_transport(). Since this function never returns NULL, the OR_NULL part was redundant at best. More critically, if a NULL pointer were somehow passed to PTR_ERR(), it would evaluate to 0. In the context of a sysfs store function, returning 0 signifies success (or EOF), which could mask actual errors and lead to undefined behavior or silent failures in the NFS client's transport layer.

The Fix

The fix is minimal—a one-line change replacing IS_ERR_OR_NULL() with the correct IS_ERR() check:

"Fix this by using IS_ERR() instead of IS_ERR_OR_NULL()."

This ensures that only genuine error pointers (encoded via ERR_PTR) are treated as failures, while valid transport pointers proceed correctly through the sysfs add operation.

Classification

  • Type: Bug fix
  • Subsystem: SUNRPC / NFS client infrastructure
  • Impact: Prevents potential silent failure in sysfs-based transport management, ensuring proper error propagation when transport creation fails.

The patch references commit df210d9b0951 ("sunrpc: Add a sysfs file for adding a new xprt") as the source of the original bug. This is a clean, targeted fix with no controversy or extended discussion this week.
