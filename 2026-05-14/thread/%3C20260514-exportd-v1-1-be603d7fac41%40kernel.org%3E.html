Summary

exportfs: Cleanup of Unused Parameter in xtab Functions

This brief thread consists of a single patch submission and a follow-up clarification from Jeff Layton regarding the nfs-utils export daemon codebase.

Classification

Bug Fix / Code Cleanup: This is not a new feature or protocol change, but rather a source code cleanup removing dead code paths.

Discussion Summary

Jeff Layton submitted a patch to simplify the xtab_read() and xtab_write() functions in the NFS export utilities (support/export/xtab.c). The core technical argument was straightforward: an is_export parameter had become vestigial.

"The is_export parameter is always passed as 1. Remove it and simplify both functions by eliminating the dead is_export == 0 code paths." Jeff Layton

The patch removed 26 lines of code while adding only 13, effectively streamlining the export table handling logic by deleting conditional branches that were never executed in current usage.

In a follow-up message, Layton noted a minor administrative error: the patch was intended for the nfs-utils mailing list rather than the kernel NFS list. He characterized the change as low-risk maintenance work:

"Oops, I meant to make this '[nfs-utils PATCH]'. Ahh well, anyway, it's just a bit of cleanup..." Jeff Layton

Conclusion

No further discussion occurred. The patch represents a minor but positive reduction in code complexity for the NFS export utilities, removing unused parameters and dead code paths from the export table management functions. Given its nature as a simple cleanup with no behavioral changes, it was expected to be accepted without controversy once routed to the correct mailing list.
