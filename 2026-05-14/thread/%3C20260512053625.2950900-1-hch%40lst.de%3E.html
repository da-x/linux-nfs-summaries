Summary

Improve the swap_activate Interface

Overview

Christoph Hellwig posted a 12-patch series to rework how the memory management (MM) subsystem interacts with filesystems when activating swap files. The series was motivated by recent iomap support for fuse-iomap, which exposed ugliness in the existing interface. As Hellwig explained:

"Darrick recently posted iomap support for fuse-iomap, which was trivial but a bit ugly, which triggered me into looking how this could be done in a cleaner way." Cover letter

The series touches 31 files across the kernel, with net deletions of 173 lines (471 insertions, 644 deletions), indicating a significant cleanup effort.

Key Technical Changes

Moving Swap Operations to file_operations

A central theme is moving swap-related operations from address_space_operations to file_operations. Hellwig argued:

"The swap operations have nothing to do with the address_space, which is used for pagecache operations." Patch 03/12

Darrick J. Wong endorsed this architectural shift:

"This sounds like a good idea because the filesystem is effectively giving the kernel a lease on a file's layout, which has little to do with the pagecache." Re: Patch 03/12

NFS Client Impact

The NFS client is among the filesystems affected by this refactoring. Changes include:

  • fs/nfs/file.c: 21 lines removed, swap operations moved to file_operations
  • fs/nfs/direct.c: 1 line added
  • fs/nfs/nfs4file.c: 3 lines added
  • include/linux/nfs_fs.h: 3 lines added

The NFS-specific changes are primarily mechanical updates to align with the new interface, moving swap_activate and related operations into the NFS file_operations structure. No NFS-specific bugs were reported or fixed in this series; rather, the NFS client was updated to conform to the cleaner kernel API.

Boilerplate Reduction and Core Swap Code Consolidation

Patch 02/12 moves calculation of sis->pages, nr_extents, and span into core swap code, removing boilerplate from filesystem callers. This simplifies implementations across btrfs, ext4, f2fs, NFS, XFS, and others.

Block Device Handling

Patches 06/12 and 07/12 move block device swapon code into block/fops.c and add sanity checks to limit swap file size to device size. Hellwig noted:

"Don't blindly pass the value from the swap header to swap_add_extent, but instead the device size rounded down to page granularity." Patch 07/12

iomap Swapfile Simplification

Patch 08/12 simplifies iomap_swapfile_iter by removing duplicate extent coalescing logic, since add_swap_extent already handles this. A technical discussion ensued between Hellwig and Wong about edge cases with contiguous mixed mappings and page alignment. Wong highlighted a real-world use case:

"We do, because mkswap -F uses fallocate nowadays" Re: Patch 08/12

Hellwig questioned whether such edge cases warranted complexity, suggesting a cleaner approach using sector_t values directly.

Private Internal Structures

The final patches move struct swap_extent and swap_info_struct into internal MM headers (mm/swap.h), encapsulating swap internals away from filesystem code. A new helper swap_activate_fs_ops abstracts the low-level details for filesystem implementers.

Reviews and Feedback

  • Damien Le Moal provided Reviewed-by tags for most patches, noting minor nits such as a whitespace change in Patch 09/12 and suggesting renaming ->max to ->maxpages for clarity.
  • Darrick J. Wong reviewed multiple patches, providing constructive feedback on variable naming and edge cases in extent handling.
  • Hannes Reinecke also provided a Reviewed-by for Patch 01/12.

Reported Issue

Steve French reported a boot failure after applying the series:

"I just tried this on 7.1-rc3 with the swap patches (full kernel build, on Ubuntu 25.10) and boot failed with out of memory which I had never seen before." Re: Cover letter

No resolution to this issue was provided within the current week's window.

Conclusions

This series represents a significant cleanup of the swap activation interface, improving code organization and reducing boilerplate across multiple filesystems including NFS. The changes are primarily refactoring rather than bug fixes, though they do add sanity checks for swap file sizes on block devices. The NFS client was updated to conform to the new API without any NFS-specific functionality changes or bug fixes.

Hellwig tested the series with xfstests on btrfs, ext3, ext4, f2fs, and XFS, noting that all passed except f2fs which had pre-existing test infrastructure gaps. The series received positive reviews from filesystem maintainers, though one boot regression was reported without resolution this week.
