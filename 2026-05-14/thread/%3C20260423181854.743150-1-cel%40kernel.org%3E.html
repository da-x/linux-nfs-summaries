NFSD Block Layout Export Cleanup: Applied to VFS Tree

Summary

This week, the long-running discussion around Christoph Hellwig's four-patch series to clean up NFS server (NFSD) block-style layout export infrastructure reached its conclusion. After weeks of procedural negotiation and a v3 submission on April 23, Christian Brauner confirmed that all four patches have been applied to his VFS tree under the vfs-7.2.exportfs branch.

Bridge to Prior Weeks

The series was originally authored by Christoph Hellwig and submitted in v3 form by Chuck Lever on April 23. As Lever explained in the cover letter:

"Christian prefers to see them taken through the VFS tree. Once the patches are applied there, I will rebase nfsd-next and nfsd-testing on that tree and drop these."

The four-patch series addressed:

  1. Patch 1/4: Always ignore loca_time_modify — a protocol-compliance correction per RFC 8881 Section 18.42.
  2. Patch 2/4: Split out operations for layout-based block device access into a dedicated header (exportfs_block.h).
  3. Patch 3/4: Simplify ->commit_blocks by removing the unnecessary struct iattr argument.
  4. Patch 4/4: Rework support checks for layout-based block device access, preparing for multi-device exports.

A brief logistical exchange followed in late April regarding duplicate resends of the series, but no further technical debate occurred.

This Week's Activity: Application Confirmation

The sole message this week was Brauner's application notice on May 11:

"Applied to the vfs-7.2.exportfs branch of the vfs/vfs.git tree. Patches in the vfs-7.2.exportfs branch should appear in linux-next soon." Brauner

He also noted:

"The branch is stable in case anyone wants to rely on it."

Classification

This thread concerns an infrastructure refactoring with a minor protocol-compliance correction. The series is not a new feature or a traditional bug fix; rather, it reorganizes NFSD's export infrastructure and ensures correct handling of NFSv4.2 block layout commit semantics.

Significance for NFS Client Development

Although these changes are server-side, they have direct implications for NFS client developers working with PNFS block layouts:

  1. Timestamp correctness: The explicit ignoring of loca_time_modify ensures that client-provided timestamps during layout commits do not conflict with XFS's multi-grain timestamp semantics. This prevents potential data integrity issues or unexpected attribute changes on the server side, which clients might otherwise observe as inconsistent behavior.

  2. Accurate capability reporting: The reworked support checks (patch 4/4) ensure that clients receive correct information about filesystem-level block layout capabilities via LAYOUTGET operations. This prevents clients from attempting block layouts on filesystems that do not properly support them.

  3. Future multi-device readiness: The infrastructure separation prepares for future multi-device block layout exports, which will affect how clients handle layout segments spanning multiple devices.

Final Conclusions

The NFSD block layout export cleanup series has been successfully merged into the VFS tree via Brauner's vfs-7.2.exportfs branch and is expected to appear in linux-next shortly. Chuck Lever will subsequently rebase nfsd-next and nfsd-testing on this tree, completing the integration. For NFS client developers, these changes ensure continued correctness of PNFS block layout interactions while laying the groundwork for expanded server-side capabilities.
