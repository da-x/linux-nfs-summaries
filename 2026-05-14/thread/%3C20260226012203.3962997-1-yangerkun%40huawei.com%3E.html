NFS file-lock UAF fix: quiet week, another gentle ping

Classification

This is a bug fix on the NFS client side — not a new feature or protocol change. It addresses a use-after-free (UAF) hazard during traversal of the per-inode file-lock list in delegation-claim and lock-reclaim paths. The patch carries a Fixes: tag pointing to commit c69899a17ca4 ("NFSv4: Update of VFS byte range lock must be atomic with the stateid update").

Bridge from prior weeks

This thread has been active since February 2026. In brief:

  • February 2026: Huawei's Yang Erkun opened the thread with an RFC patch to protect NFS file-lock list traversal using nfsi->rwsem instead of flc_lock. The bug — originally identified by Li Lingfeng — stems from the fact that functions like nfs_delegation_claim_locks and nfs4_reclaim_locks must release flc_lock to call blocking RPC code, creating a UAF window.

Key technical arguments (recap)

The fix rests on two pillars:

  1. Per-inode protection via nfsi->rwsem. The previous guard (so_delegreturn_mutex) is per-state-owner, but a single inode can carry multiple nfs4_state objects, allowing races between state owners on the same inode. Switching to nfsi->rwsem aligns with the already-established pattern in nfs4_reclaim_locks.

  2. Relocation of locks_lock_inode_wait. The call was moved out of async RPC callbacks (nfs4_lock_done, nfs4_locku_done) into the synchronous caller _nfs4_proc_setlk, so it can execute under nfsi->rwsem without risking deadlocks. Erkun argued this does not regress the original atomicity bug fixed by commit c69899a17ca4, because later commits (notably 0460253913e5) drain slots before reclaim, and the delegation-claim path sets the stateid only once.

Current status

The patch remains unmerged as of this week's close. The technical discussion is settled — Jeff Layton's Reviewed-by has been on record for over two months, no objections have been raised, and an AI-assisted review corroborated the absence of regressions. The ball rests with NFS subsystem maintainers Anna Schumaker and Trond Myklebust to complete the merge. Erkun's persistent but polite pings reflect the frustration of a well-vetted fix languishing in limbo.
