ktls-utils 1.3.1 Release: Bug Fixes for kTLS NFS Tools

Summary

ktls-utils 1.3.1 Release Announcement

This thread consists of a single announcement message from Chuck Lever regarding the release of ktls-utils version 1.3.1. This is not a discussion thread but rather a formal release notification for userspace tools supporting kernel TLS (kTLS) for NFS.

Nature of the Update

The release is characterized as a "FIXES release" based on ktls-utils 1.3.0, which was originally released in October 2025. The focus is squarely on bug fixes and compatibility improvements rather than new feature development.

Key Technical Fixes

Chuck Lever outlined several critical fixes included in this version:

"Fix dual-certificate regression in keyring-based cert retrieval"

This addresses a regression affecting systems that rely on keyrings for certificate management, a common configuration in enterprise NFS deployments using kTLS.

"Restore QUIC session ticket handling with current GnuTLS releases"

This fix ensures compatibility with newer versions of GnuTLS, maintaining support for NFS over QUIC, which has been an area of active development and integration with the Linux kernel's TLS stack.

"Send fatal alert when server x.509 handshake configuration is invalid"

This improvement enhances security posture by ensuring that misconfigured servers properly terminate handshakes rather than proceeding with potentially insecure connections.

"Detect missing ML-DSA support in GnuTLS at runtime"

This addresses compatibility with post-quantum cryptography algorithms (ML-DSA, or Module-Lattice-based Digital Signature Algorithm), allowing the tools to gracefully handle environments where this support is not available in the underlying GnuTLS library.

"Plug session leak on x.509 server handshake error paths"

A resource leak fix that prevents memory or session state accumulation when handshake errors occur, improving stability for long-running NFS servers.

"Fix systemd unit installation for out-of-tree builds"

This addresses a build system issue affecting users who compile ktls-utils outside of the standard kernel tree workflow.

Context and Significance

The release of ktls-utils 1.3.1 is significant for NFS administrators and developers deploying kTLS-enabled NFS servers and clients. The fixes address both security concerns (proper handshake termination, session leak prevention) and compatibility issues (GnuTLS updates, post-quantum cryptography detection).

The availability of these tools on GitHub (oracle/ktls-utils) continues Oracle's contribution to the NFS ecosystem's TLS infrastructure, supporting both TCP-based kTLS and the newer QUIC transport for NFS.

Conclusion

This announcement serves as a straightforward release notification with no further discussion in the thread. Users running ktls-utils 1.3.0 are encouraged to upgrade to 1.3.1 to benefit from these bug fixes, particularly those involving certificate handling, QUIC session management, and resource leak prevention.
