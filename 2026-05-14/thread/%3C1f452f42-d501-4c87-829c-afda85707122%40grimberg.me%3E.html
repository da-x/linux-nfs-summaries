Context: Prior Layout Recall Work

This question arrives in the context of significant prior work on layout recall handling. Earlier in 2026, Dai Ngo from Oracle submitted a multi-version patch series (v6 through v12) titled "NFSD: Enforce timeout on layout recall and integrate lease manager fencing." That series addressed critical issues where layout conflicts could cause excessive nfsd thread blocking during __break_lease operations.

Key aspects of that prior work included:

  • Introducing a timeout mechanism for layout recalls to prevent server starvation
  • Integrating with the lease manager's fencing capabilities
  • Adding an lm_breaker_timedout callback to handle timeout scenarios
  • Implementing asynchronous fencing operations for SCSI and block layouts when clients fail to release layouts

The v12 iteration, posted in February 2026, refined the approach with exponential backoff for fence retries, proper reference counting on layout stateids, and improved logging.
