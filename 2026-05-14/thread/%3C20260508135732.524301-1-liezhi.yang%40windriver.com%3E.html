Summary

nfs-utils: Fixing musl Build Error in fh_key_file.c

This thread addresses a straightforward bug fix for nfs-utils, specifically resolving a compilation error when building against the musl C library. The discussion highlights a case of duplicate patch submissions and the maintainer's workflow for handling patches that lack proper mailing list tagging.

Technical Context: A Bug Fix for Portability

The issue is a build failure on systems using musl libc, where the function strerror was implicitly declared in support/nfs/fh_key_file.c. This is a common portability issue when code assumes glibc's more permissive headers or implicit declarations.

Robert Yang submitted a patch to resolve this:

"Fixed: error: implicit declaration of function 'strerror'" Patch submission

Discussion Evolution

The discussion was brief and focused on deduplication efforts rather than technical debate over the fix itself.

  1. Duplicate Detection: Benjamin Coddington quickly identified that this issue had already been addressed by a previous submission from Giulio Benetti in April 2026. He noted:

    "Giulio sent a patch for this already... Steve D - did you pick that one up yet?" Response

  2. Maintainer Response: nfs-utils maintainer Steve Dickson explained why the earlier patch had not been merged yet, attributing it to a lack of proper subject tagging which caused it to get lost in the noise of kernel patches:

    "Nope! It was hiding in a bunch of kernel patch w/out a nfs-utils subject tag. It is on todo list now..." Resolution

Conclusion

The thread concludes with the maintainer acknowledging the oversight and adding the fix to his TODO list. While Robert Yang's patch is a valid fix, the community standard practice suggests that Giulio Benetti's earlier submission should take precedence for credit, assuming it contains an equivalent or superior solution. This exchange serves as a reminder for contributors to ensure patches are correctly tagged with [nfs-utils] in the subject line to avoid being overlooked by maintainers filtering their mail.

Key Takeaway: This is a minor but important portability fix for nfs-utils users on Alpine Linux or other musl-based distributions. The resolution highlights the importance of clear patch tagging in the Linux kernel and subsystem mailing lists.
