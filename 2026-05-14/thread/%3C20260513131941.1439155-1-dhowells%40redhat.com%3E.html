rxrpc/RxGK: Pre-decrypt length check fix for Kerberos crypto

Summary

rxrpc/RxGK: Fix Lack of Pre-Decrypt/Pre-Verify Length Checks

Type: Bug fix (security hardening)

David Howells submitted a patch this week as part of a four-patch series targeting the net tree, addressing a security gap in the AF_RXRPC subsystem's handling of Kerberos-secured (RxGK) data packets.

The Problem

The patch description states:

"Change the krb5 crypto library to provide facilities to precheck the length of the message about to be decrypted or verified."

"Fix AF_RXRPC to make use of this to validate DATA packets secured with RxGK."

The issue traces back to commit 9d1d2b59341f, which introduced the yfs-rxgk security class (GSSAPI) for rxrpc. Without proper length validation before decryption or verification, malformed packets could potentially cause issues in the crypto processing pipeline. The patch also references an external bug tracker entry:

"Closes: https://sashiko.dev/#/patchset/20260511160753.607296-1-dhowells@redhat.com"

Technical Scope

The fix touches five files across the crypto and rxrpc subsystems:

include/trace/events/rxrpc.h+1 (tracing enhancement)
net/rxrpc/rxgk.c+11/-2 (rxrpc integration)

The patch marks itself for stable kernel backporting via the cc: stable@vger.kernel.org tag, underscoring its importance as a security-related fix.

Relevance to NFS

While this patch primarily targets the AF_RXRPC socket family and the Kerberos crypto library — infrastructure shared between AFS and NFS over RDMA with Kerberos security — it is CC'd to linux-nfs@vger.kernel.org and Chuck Lever, indicating its relevance to NFS clients that may leverage rxrpc-based transports or share the underlying krb5/crypto infrastructure. The fix hardens pre-decrypt validation, which benefits any consumer of the Kerberos crypto API, including NFS clients using Kerberos-based security mechanisms.
