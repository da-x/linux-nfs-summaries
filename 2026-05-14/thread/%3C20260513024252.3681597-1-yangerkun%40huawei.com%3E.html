NFSD: Revert deferred export cleanup to fix unmount regression (v2)

Summary

This thread covers the submission and acceptance of Patch v2 from Yang Erkun, which reverts commit 48db892356d6 ("NFSD: Defer sub-object cleanup in export put callbacks"). The revert addresses a regression in NFS server (NFSD) unmount operations that was introduced by the original commit. The discussion from the previous day's v1 patch resolved key technical concerns regarding potential Use-After-Free (UAF) bugs, leading to a smooth acceptance of this refined version.

Discussion Overview

The Regression and the Fix

Yang Erkun submitted Patch v2 to revert the deferred cleanup mechanism in svc_export_put. The original commit had attempted to fix UAF errors by deferring the cleanup of sub-objects (ex_path and ex_client->name) via workqueues. However, this approach reintroduced a regression previously fixed by commit 69d803c40ede ("nfsd: Revert "nfsd: release svc_expkey/svc_export with rcu_work"").

"Commit 48db892356d6 ... describes an issue where calling svc_export_put, path_put, and auth_domain_put directly can cause use-after-free (UAF) errors ... But after discussion in [1], it seems cannot happen and either will introduce a gression that was already fixed by commit 69d803c40ede ... Therefore, reverting commit 48db892356d6 ... is necessary to fix this regression."

Safety Validation (Recap from v1)

As established in the prior day's discussion summarized here, Jeff Layton had initially raised concerns about UAFs if sub-objects were freed directly while RCU readers iterated the cache. Yang clarified that sub-objects like dentry, mnt, and auth_domain are themselves freed via RCU mechanisms (e.g., call_rcu). Consequently, the rcu_read_lock() held by readers protects access to these sub-objects, making the revert safe. Jeff Layton provided his Reviewed-by tag for this v2 patch based on that prior resolution.

Acceptance and Integration

Chuck Lever accepted the patch into the nfsd-testing tree, noting that he expanded the commit message to preserve the context of the technical discussions regarding UAF safety and the unmount regression.

"Applied to nfsd-testing with an expanded commit message to preserve the context of our discussions."

Yang Erkun acknowledged the improvement:

"Certainly, this commit message could be more detailed. Thank you for taking the time to do this!"

Key Technical Arguments

  • Bug Fix Type: This is a revert to fix an unmount regression in NFSD.
  • UAF Safety: The revert is safe because sub-objects accessed by RCU readers are freed via RCU, preventing UAFs even when path_put() and auth_domain_put() are called directly.
  • Workqueue Complexity: The revert removes the need for deferred cleanup via workqueues for these specific objects, simplifying the codebase and avoiding conflicts with Chuck Lever's ongoing workqueue refactoring in sunrpc.ko.

Final Conclusions

  • The patch was applied to nfsd-testing as commit ef4e34669aa1.
  • The NFSD export cleanup logic now directly releases sub-objects, relying on RCU protection for safety, which resolves the unmount regression without reintroducing UAF vulnerabilities.
