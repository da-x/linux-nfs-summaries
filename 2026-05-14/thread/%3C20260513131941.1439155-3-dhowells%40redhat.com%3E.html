rxrpc/RxGK: Self-correction on sizeof() in Pre-Decrypt Length Check Fix

Overview

Type: Bug fix (security hardening) — with a minor code correction noted mid-thread.

This thread is a continuation of David Howells's four-patch series targeting the net tree to address missing pre-decrypt/pre-verify length checks in the Kerberos crypto library and its consumption by AF_RXRPC's RxGK security class. The prior summary for this series (rxrpc/RxGK: Pre-decrypt length check fix for Kerberos crypto) covered the initial patch submission and a brief acknowledgment from Jeffrey Altman.

This Week's Activity

The sole message this week is a self-correction from David Howells on 2026-05-13, where he identified a subtle but important bug in his own patch v2:

"This should be sizeof(hdr) here in patch 2 and sizeof(*hdr) in patch 3."

The Correction Explained

In patch 2 of the series, the code uses sizeof(*hdr) when calling crypto_krb5_check_data_len():

if (crypto_krb5_check_data_len(gk->krb5, KRB5_ENCRYPT_MODE,
                               len, sizeof(*hdr)) < 0)

Howells notes that in patch 2, the variable hdr is already a pointer, so sizeof(*hdr) dereferences it to get the size of the struct. However, he clarifies that patch 2 should use sizeof(hdr) (implying hdr may be defined differently in that patch's context — likely as a direct struct rather than a pointer), while patch 3 correctly uses sizeof(*hdr) where hdr is indeed a pointer.

This is a precision fix ensuring the correct header size is passed to the length-checking function, which is critical for the security validation logic to work properly. If the wrong size were used, the pre-decrypt length check could either reject valid packets or fail to catch malformed ones.

Relevance to NFS Client Development

While this patch series primarily targets AF_RXRPC and the Kerberos crypto library — infrastructure shared between AFS and NFS over RDMA with Kerberos security — it is CC'd to linux-nfs@vger.kernel.org. The fix hardens pre-decrypt validation for any consumer of the Kerberos crypto API, including NFS clients that leverage Kerberos-based security mechanisms. Proper length validation before cryptographic operations is a defensive measure against malformed or malicious network packets.

Conclusion

This week's activity consists solely of David Howells identifying and documenting a sizeof() precision issue in his own patch series. The correction ensures the pre-decrypt length checks use the correct header size calculation across patches 2 and 3, maintaining the integrity of the security hardening introduced by the series. No further debate or external review was recorded this week.
