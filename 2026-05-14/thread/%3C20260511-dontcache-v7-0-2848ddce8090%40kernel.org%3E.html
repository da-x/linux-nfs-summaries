mm: RWF_DONTCACHE writeback performance improvements (v7)

Summary

Overview

This week saw the posting and rapid review of Patch Series v7 by Jeff Layton, aimed at significantly improving write performance for RWF_DONTCACHE operations in the Linux memory management subsystem. The series addresses long-standing latency issues where DONTCACHE writes suffered from high tail latencies due to inline writeback submission.

The discussion is focused on bug fixes and performance optimizations within the VM writeback path, with significant implications for NFS clients and other filesystems utilizing RWF_DONTCACHE.

Key Technical Arguments and Evolution

The Problem: Inline Writeback Latency

In previous versions, the IOCB_DONTCACHE path called filemap_flush_range() inline on every write. As Jeff Layton noted in the cover letter PATCH v7 0/3:

"Perf lock contention profiling shows the performance problem is not lock contention but the writeback submission work itself — walking the page tree and submitting I/O blocks the writer for milliseconds, inflating p99.9 latency from 23ms (buffered) to 93ms (dontcache)."

The Solution: Background Flusher Kick with Targeted Tracking

The v7 series introduces three main changes:

  1. Preserve PG_dropbehind during folio split PATCH 1/3: Ensures tail folios retain the drop-behind hint after splitting, preventing silent loss of the flag.
  2. Per-bdi_writeback dirty tracking PATCH 2/3: Adds a WB_DONTCACHE_DIRTY counter to track dirty pages with the dropbehind flag, allowing targeted writeback without flushing unrelated buffered data.
  3. Kick flusher instead of inline writeback PATCH 3/3: Replaces inline filemap_flush_range() with a background flusher kick, moving writeback submission off the writer's hot path.

Review Feedback and Simplifications

Christian Brauner provided critical code simplification suggestions for patch 3/3 Re: PATCH 3/3:

"Doesn't test_and_set_bit() return the old value? IOW, if it sees that WB_start_dontcache was already set it'll return true? So you can remove the test_bit() call, right?"

"That does look much cleaner. Do you want to just make that change or would you rather I resend?" Re: PATCH 3/3

Performance Results

The cover letter PATCH v7 0/3 presented compelling benchmarks:

  • Single-stream sequential write throughput: Increased from 298 MB/s to 897 MB/s (+201%)
  • Tail latency (p99.9): Collapsed from ~8.9 seconds to 28 ms (-99.7%)
  • Multi-writer parity: Dontcache throughput now matches buffered I/O (4,532 vs 4,616 MB/s)
  • Fair sharing: Previously, buffered writers starved dontcache writers 2:1; both now receive equal bandwidth

Final Conclusions

The series received broad approval from key reviewers:

  • David Hildenbrand: "Acked-by" for patch 1/3 Re: PATCH 1/3
  • Jan Kara: "Reviewed-by" for all three patches, noting patch 3/3 with Christian's simplification "looks good" Re: PATCH 3/3
  • Ritesh Harjani: "Reviewed-by" for patches 2/3 and 3/3, praising the use of wb_stat infrastructure Re: PATCH 2/3

Christian Brauner agreed to fold his simplification into patch 3/3 before merging. The series is expected to be merged into v7.2, delivering substantial performance improvements for RWF_DONTCACHE workloads, particularly benefiting NFS clients and other filesystems relying on this writeback mode.
