Hellwig wants nfsd-style Kconfig, not a rewrite

Summary

This week’s linux-nfs traffic on Scott Mayhew’s pNFS client Kconfig split is a build-system / feature-selection change, not a protocol revision and not a runtime bug fix. Last week Mayhew posted [PATCH] nfs/blocklayout: allow pNFS SCSI layout without pNFS block layout, arguing that CONFIG_PNFS_BLOCK had forced SCSI-layout kernels to carry RFC 5663 block layout and device-mapper as well. The patch kept a single blocklayoutdriver module, carved SIMPLE-volume parsing into block.c and SCSI-leaf / PR register paths into scsi.c, and introduced prompted booleans CONFIG_PNFS_BLOCK and CONFIG_PNFS_SCSI_LAYOUT plus an internal tristate CONFIG_PNFS_BLOCK_LAYOUT_DRIVER. SCSI layout would default on and drop the BLK_DEV_DM dependency; block layout would default off. The commit was tagged Assisted-by: Claude:claude-opus-4-8.

The first review arrived this week from Christoph Hellwig, who wrote the original SCSI layout work and the nfsd side of the same split. He agrees with the goal — a SCSI-only client should not have to drag in block layout — but rejects the shape of the patch:

"Supporting SCSI layout with block layout makes totaly sense, but please do it without all the gracious renaming and annoying AI slop commit log."

That is a two-part objection. First, the mechanical churn: Mayhew’s 8-file, +300/−215 refactor extracts block.c/scsi.c from dev.c, promotes bl_map_simple / bl_parse_simple / bl_parse_scsi / bl_register_scsi / bl_unregister_scsi to globals, and wraps the shared core in IS_ENABLED(). Hellwig does not want that renaming as the price of independent Kconfig knobs. Second, the commit log itself: the Claude-assisted changelog is called out as “AI slop,” a rare public rejection of LLM-written patch description on this list.

Hellwig then points at the model he wants the client to copy from the server:

"Take a look at show nfsd handled this with CONFIG_NFSD_BLOCKLAYOUT and CONFIG_NFSD_SCSILAYOUT as that is the model that applies here as well."

On the nfsd side those two symbols are independent prompted options; they do not invent a third internal driver tristate, they do not default SCSI on and block off, and they do not require splitting the shared layout driver into newly named source files. Applied to fs/nfs/, that would mean CONFIG_PNFS_BLOCK and a SCSI counterpart that simply compile the existing type-specific objects in or out of the current blocklayout driver — closer to a Kconfig/Makefile tweak than to Mayhew’s file-level rewrite.

No v2, Ack, or follow-up from Mayhew landed in this window. The thread therefore ends mid-review: the client-side decoupling of RFC 8154 SCSI layout from RFC 5663 block layout is accepted in principle, but the posted implementation — extra CONFIG_PNFS_BLOCK_LAYOUT_DRIVER tristate, boolean-vs-tristate dance to avoid y/m mismatch, default polarity flip, block.c/scsi.c split, and the Claude-authored log — is not. Until a respin that looks like nfsd’s CONFIG_NFSD_BLOCKLAYOUT / CONFIG_NFSD_SCSILAYOUT pair, SCSI-only NFS clients still cannot be configured without device-mapper and SIMPLE-volume blkmapd plumbing.

This remains adjacent to, not overlapping, FAN YE’s bl_resolve_deviceid() lost-wakeup work: that path is the SIMPLE-volume userspace upcall Mayhew’s patch would compile out of SCSI-only kernels. Hellwig’s review does not mention that series.
