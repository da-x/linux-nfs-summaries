nfs-utils getport FTBFS fix lands in 2.9.3-rc2

Summary

This week closed a small but concrete bug fix for the user-space NFS client utilities: the pre-C23 switch/case FTBFS in support/nfs/getport.c is now in the nfs-utils tree. There is no protocol change and no kernel NFS client work here — the discussion is about keeping nfs-utils (mount helpers, portmap/getport, and related client tooling) buildable on conservative embedded toolchains.

Last week, Petr Vorel posted [FTBFS,PATCH,nfs-utils 1/1] getport: Fix switch case on old compilers. A warning-cleanup commit (1a6dcd74, "Removed warnings in nfs_sockaddr2universal()") had put a declaration immediately after a switch case label in nfs_sockaddr2universal(), the helper that turns a sockaddr into a universal address string for NFS port mapping. That is a C23-ism; on C11 and earlier a label must be followed by a statement. Buildroot’s GCC 6.3.0 (Buildroot 2017.05) for aarch64 failed with:

"getport.c:460:3: error: a label can only be part of a statement and a declaration is not a statement"

Vorel’s three-line workaround wrapped the case body in a compound statement so the path_len declaration lives inside a block, and he left the maintainer an equally valid alternative:

"Steve, other option would be to use ';'. Not sure which one you prefer."

This week’s only in-window message is the maintainer ack. On 31 August, Steve Dickson replied to the original patch with a one-line commit notice:

"Committed... (tag: nfs-utils-2-9-3-rc2)"

He did not debate braces versus a null statement after the case label; he took Vorel’s compound-statement version as posted. The patch therefore ships in nfs-utils 2.9.3-rc2, restoring getport builds for old C11-default compilers without changing NFS client runtime behavior.

That is the end of the thread: a lone FTBFS patch from 19 August, unacked last week, accepted this week into the nfs-utils release candidate. Embedded and Buildroot consumers of the Linux NFS client user-space stack can treat the nfs_sockaddr2universal() regression as fixed in 2.9.3-rc2.
