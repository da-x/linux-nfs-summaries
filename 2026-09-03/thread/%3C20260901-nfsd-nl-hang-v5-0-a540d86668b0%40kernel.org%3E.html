NFSD listener_set v5 lands in nfsd-testing

Summary

Jeff Layton posted a 15-patch v5 of the NFSD netlink LISTENER_SET hardening series on 1 September, one day after v4. This is a bug-fix and hardening series against syzbot hung-task reports on the server's listener netlink command, not a protocol change and not a client-facing feature. The work lives in NFSD and the shared SUNRPC local rpcbind client; NFS client code is only a bystander, because the same rpcb_clnt path is what the server uses to talk to loopback/AF_LOCAL rpcbind under nfsd_mutex.

The next day, Chuck Lever applied the entire series to nfsd-testing:

"Applied to nfsd-testing, thanks!"

That is the week's conclusion. After three same-week revisions (v3 on 28 August, v4 on 31 August, v5 on 1 September), the hang bound, the error taxonomy, and the selftest harness are all in the NFSD testing tree, aimed at v7.4.

From v4 to v5: Sashiko review, plus a NULL-deref fix

The cover letter still leads with the v3/v4 errno cleanup, then asks for v7.4:

"This version just fixes up some errno handling confusion that was in v3 that Chuck pointed out. This version also drops ENAVAIL as a special error code -- we can use EIO for that instead."

"Please consider these for v7.4."

The material v5 delta is the Sashiko review of v4, plus a new defensive patch. Layton listed six changes:

  • svc_xprt_clear_rpcb_unreg() now only clears listeners already marked for close, instead of every permsock in the net. That is the unregistration give-up path in patch 09: one silent UNSET still stops the rest of the teardown, but it no longer skips rpcbind cleanup on live sockets that this LISTENER_SET is not destroying.
  • svc_register() stops the version loop as soon as rpcbind goes quiet, even when vs_rpcb_optnl discarded the error. Without that, a v4-only server (where every rpcbind error is optional) would keep walking versions after the first timeout.
  • listener_set only blames rpcbind in the extack for the entry that actually hit it, rather than gluing a silent-rpcbind warning onto whatever later entry happened to fail.
  • rpcb_register_call() no longer treats -ERESTARTSYS as a "never reached the wire" case. The task can be signalled after RPC_TASK_SENT, so a fatal signal during an in-flight SET is not evidence that rpcbind never saw the call.
  • Tests now include linux/nfsd_netlink.h rather than open-coded command ids, skip when the loopback ioctls fail, and add NFSD's Kconfig deps to the fragment.
  • New patch 11: rpcb_register_inet{4,6}() used to store the universal address unchecked. rpc_sockaddr2uaddr() returns NULL when its GFP_KERNEL kstrdup() fails, and encode_rpcb_string() then called strlen() on it. Return -ENOMEM instead. Fixes: ba809130bc26 ("SUNRPC: Remove duplicate universal address generation").

v5 is therefore 15 patches, not 14. The extra one is that NULL-deref, slotted between the NFSD give-up patch and the selftests.

The hang this series is trying to kill

The original bug is a server-side hung-task, not a client I/O stall. nfsd_nl_listener_set_doit() holds nfsd_mutex across listener teardown and rebuild. Each new listener calls svc_register(), which talks to the local rpcbind synchronously. A rpcbind that accepts the connection and never replies used to cost one transport-default timeout per listener, per program, per version. The AF_LOCAL default is 10s; the loopback TCP fallback is 60s. Patch 04 still records the watchdog trip that made this visible:

"INFO: task hung in nfsd_nl_cache_flush_doit"

The holder itself waits killably and escapes the watchdog; other NFSD netlink operations pile up behind nfsd_mutex. With the 1024-entry cap that patch 01 now enforces, patch 10 still spells out the worst case without the give-up rule:

"With the cap of 1024 entries the request can hold nfsd_mutex for about 34 minutes, which is roughly 17 times the hung-task threshold."

Patches 01, 02 and 10 still carry Fixes: 16a471177496 ("NFSD: add listener-{set,get} netlink command"). Patches 02, 04 and 10 still link the syzbot report (extid=c7eae0eb80858a2dba0f). Several patches remain Assisted-by: LLM. Patch 10 still carries Olga Kornievskaia's Suggested-by for the "give up after the first failure" rule.

Input validation and the 1s bound

The first half of the series is still about work that today runs under nfsd_mutex or sv_lock with bottom halves disabled:

  • 01/15 rejects a listener_set with more than NFSD_NL_LISTENER_MAX (1024) entries in nfsd_nl_validate_listeners(), before taking any lock. The nested match loop is O(N×M). The patch still does not cap M (existing sockets); __write_ports_addxprt() can still push M past the cap. Both interfaces require CAP_NET_ADMIN.
  • 02/15 checks the transport name against tcp/udp/rdma before nfsd_create_serv(), so an arbitrary name no longer reaches request_module("svc%s", name) as a TASK_KILLABLE usermode helper under nfsd_mutex. Modular svcrdma autoload is deliberately left in place. The rejection names the offending attribute through extack, because -EPROTONOSUPPORT alone does not say which entry carried the bad name.
  • 03/15 makes svc_register() keep the first error instead of the last, so a later success cannot erase an earlier failure. This is also what makes CONFIG_NFS_LOCALIO=y agree with =n on "a failed registration stays fatal."
  • 04/15 bounds the local rpcbind client to a single 1s attempt. Layton is still explicit that this is a mitigation, not the end state:

"This shortens the stall. It does not remove the stall, and it is not free. Registration stays synchronous and stays fatal. … An rpcbind that is merely slow to be scheduled can therefore now fail server startup, where it succeeded before. The real fix is to make the registration asynchronous."

  • 05/15 reports listener-creation failures through netlink extack, naming both the attribute and the transport so a multi-entry request is not reduced to a bare "Address already in use." NL_SET_BAD_ATTR() is required because several entries can share a transport name.

v2's svc_register() unwind stays dropped, for the reason Chuck found earlier: rpcbind matches an UNSET on [program, version, netid], and the v2 fallback ignored protocol, so the unwind "could therefore clear entries that belong to other live listeners."

Error taxonomy and the give-up rule

Patch 06 is still the Chuck-driven errno cleanup from v4, now with the Sashiko -ERESTARTSYS correction. rpcb_register_call() failures split into three buckets, and silence is -EIO rather than a new -ENAVAIL:

  • answered: a FALSE reply, or an RPC-level rejection that rpc_decode_header() derives from the reply — -EACCES (FALSE reply or AUTH_ERROR), -EPROTONOSUPPORT, -EPFNOSUPPORT, -EOPNOTSUPP.
  • never sent: -ENOMEM, -EMSGSIZE. v5 no longer puts -ERESTARTSYS here.
  • no answer: everything else, i.e. transport errors.

Any no-answer error is represented by -EIO, which is already what the RPC layer reports for a soft timeout without RPC_TASK_TIMEOUT. The serv still keeps a sv_rpcb_failures count; later patches still watch that count and stop further SET/UNSET once it moves. A real reply, a memory failure, or a signal no longer increment that count and no longer get rewritten into a synthetic timeout.

Patches 07–10 still implement Olga's rule, keyed off that count:

  • 07/15 stops the program loop in svc_register() on no-answer, not just the version loop, so an nfsd serv does not pay 2s (nfsd + nfsacl) for a dead rpcbind. v5 also stops the version loop even when vs_rpcb_optnl discarded the error.
  • 08/15 and 09/15 bound the unregistration side the same way: svc_unregister() gives up after the first silent call, and svc_delete_xprt() clears XPT_RPCB_UNREG on remaining transports already marked for close once one UNSET gets no answer. One LISTENER_SET therefore pays one timeout in each direction rather than one per listener/program/version.
  • 10/15 is the NFSD consumer: once svc_rpcb_failure_count() moves, the rest of the request is created with SVC_SOCK_ANONYMOUS. Suggested-by Olga Kornievskaia.

A refused SET (-EACCES) is still an answer, so it stays fatal for that listener and does not trip the give-up path. That distinction is what the selftests in patches 14–15 are written to protect.

Selftests: a per-netns rpcbind stub

The last four patches add tools/testing/selftests/nfsd/nfsd_netlink_listener.c (~1.3k lines) and put the new directory in the NFSD MAINTAINERS entry. That is the only part of the series that a client-side developer might actually reuse: a harness for talking to NFSD netlink without poisoning the host's rpcbind.

12/15 covers the pre-mutex validation: bad/absent transport name, missing address, truncated sockaddr, bad family, a malformed entry behind a well-formed one, more than 1024 entries, and LISTENER_GET on an empty netns. Each kselftest harness test runs in its own net and mount namespace with /run masked, because unix_find_bsd() has no struct net and a connect to /var/run/rpcbind.sock would otherwise hit the host rpcbind — and svc_rpcb_setup() opens with svc_unregister(), which would clear the host's nfsd registrations. The config fragment therefore includes NAMESPACES, NET_NS, SHMEM, TMPFS and UNIX; without them every test skips. v5 also pulls in NFSD's own Kconfig deps and skips when the loopback ioctls fail.

13/15 is the interesting piece: a per-netns rpcbind stub bound to the abstract name "\0/run/rpcbind.sock" (that lookup is netns-local via unix_find_abstract()). The stub never decodes arguments; NULL gets success, SET/UNSET get TRUE, and it speaks RPCBVERS_4 as well as v2 so IPv6 listeners are not left unregistered. Mode and counters live in a shared page so a test can switch the stub to silent without killing the connection the kernel holds — killing it would make the next rpcb_register_call() fail immediately with -ENOTCONN (RPC_TASK_NOCONNECT) instead of waiting out a timeout. Layton is still careful that errno alone is a weak oracle. Several tests exist "to catch a revert, not to describe the interface": val_bad_transport now also requires the stub saw no traffic; sem_register_refused re-reads the listener set because -EACCES can also come from bind; func_empty_destroys uses the connection count to distinguish a destroyed serv from a live serv with no permsocks. FIXTURE_TEARDOWN removes any listener or thread a test left behind, because those pin the netns.

14/15 is where the give-up rule shows up in tests. RPCB_STUB_SILENT reads a call and writes nothing back; RPCB_STUB_REFUSE cannot serve here, because "a refusal is an answer, and the count ignores it on purpose." The NULL procedure still has to be answered: rpcb_create_af_local() builds its client without RPC_CLNT_CREATE_NOPING, so silencing the ping would fail the AF_LOCAL client, send rpcb_create_local() on to the loopback fallback, and leave the stub seeing one call per request no matter how many listeners it carried. The four cases:

  • rpcb_stop_after_failure — one listener, then three; three entries must not cost three times as much.
  • rpcb_silent_set_complete — the entry that finds rpcbind silent is the one that pays the timeout; a three-entry request must still bring up all three, succeed, and warn.
  • rpcb_v4_only_bounded — v4-only, so vs_rpcb_optnl discards every error and every listener comes up; the count, not a failed listener, is what bounds the walk.
  • rpcb_retry_next_request — the stop lasts for one request; after the stub starts answering, the next request must reach rpcbind again.

15/15 covers the teardown side of the same rule: remove one listener, then three, with the stub silent. Three removals must not cost three timeouts. Both measurements also pay the svc_unregister() sweep that nfsd_destroy_serv() runs once the last listener is gone, so that cancels out of the comparison.

Where it stands

v5 is the series that landed. Chuck applied all 15 patches to nfsd-testing on 2 September, with commits ranging from 196e48772ea6 (the 1024-entry cap) through f56be2f4966b (the removal-side selftest). The direction is the same as v3 and v4 — cap the request, validate before taking nfsd_mutex, bound the local rpcbind client, stop walking once rpcbind is silent — with Chuck's errno objection addressed by classifying silence as -EIO, and with Sashiko's review tightening the unregistration scope, the optional-version loop, the extack blame, and the -ERESTARTSYS classification.

The 1s timeout remains a mitigation. Both the cover letter's v3 history and patch 04 still point at asynchronous (and eventually userland) rpcbind registration as the real cure for holding nfsd_mutex across a synchronous RPC. Client developers waiting for a protocol or mount-path change will not find one here; the important bug fix is that a silent local rpcbind can no longer pin the NFSD netlink path for tens of minutes, and that fix is now in the testing tree.
