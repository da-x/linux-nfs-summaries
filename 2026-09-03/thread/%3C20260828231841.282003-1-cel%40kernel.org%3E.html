NFSD maps NFSv2 READ/WRITE of non-regular files to NFSERR_ISDIR

Summary

Hours after maintainers agreed not to restore the illegal NFSv2 NFSERR_INVAL mapping, Chuck Lever posted the promised bug-fix patch: NFSD now returns NFSERR_ISDIR when an NFSv2 READ or WRITE hits a symlink or other non-regular file. That is the historic Sun/Solaris status, and it is the status U-Boot’s NFS client already treats as “follow the symlink.” Jeff Layton and NeilBrown both Reviewed-by the same day. This is not a protocol change and not a Linux nfs.ko change; it is a server-side compatibility fix for a firmware NFSv2 client.

Prior week (brief)

Commit 0ac903d1bfdc (“NFS: NFSERR_INVAL is not defined by NFSv2”) stopped NFSD from returning NFSERR_INVAL for NFSv2 READ/WRITE of a non-regular file, substituting NFSERR_IO because RFC 1094 never defined INVAL. That broke U-Boot netboot through a symlink: the bootloader only follows a symlink when READ fails with NFSERR_ISDIR or NFSERR_INVAL, so the load now completes with zero bytes transferred. In the parent thread, maintainers rejected a revert to the illegal INVAL mapping. Lever’s constructive alternative — map the case to NFSERR_ISDIR, matching Solaris and the first arm of U-Boot’s existing check — is what this patch implements. Reported-by Jörg Sommer; Closes the original report.

The patch

Lever’s v1 is a 19-line change to fs/nfsd/nfsproc.c. The commit message states the client-visible failure plainly:

"U-Boot's NFS client follows a symlink only when READ fails with NFSERR_ISDIR or NFSERR_INVAL. Since that commit it cannot load a boot image through a symlink exported by a Linux NFS server: the load completes with zero bytes transferred."

The intended mapping is explicit and scoped:

"Solaris returns NFSERR_ISDIR when the target of an NFSv2 READ or WRITE is not a regular file. Return the same status from NFSD. Other NFSv2 procedures continue to return NFSERR_IO."

So the special case is only on nfsd_proc_read() and nfsd_proc_write(). SETATTR and the rest of the NFSv2 procedure table keep the post-0ac903d1bfdc NFSERR_IO mapping. That matches the earlier agreement not to widen the exception until someone files a concrete complaint about other procedures.

Reviews

Jeff Layton Reviewed-by with no further comment.

NeilBrown also Reviewed-by and confirmed the Solaris scope, which is the closest thing NFSv2 has to a reference implementation:

"The only places that openSolaris returns NFSERR_ISDIR when the object might not be a directory are in rfs_read(), rfs_write(), and rfs_write_sync(), which is called for rfs_write()."

"So adding this special handling only for nfsd_proc_read() and nfsd_proc_write() makes sense."

That is the technical argument that keeps the patch from becoming a blanket “wrong type → ISDIR” rewrite of NFSv2 status mapping. The exception exists because READ and WRITE are the operations historic clients (U-Boot, and before that NetBSD-derived NFS boot code) use as a type probe for symlink following. Other procedures do not need to lie about the object type.

Client impact

Linux’s in-kernel NFS client is not being modified. The affected client is U-Boot’s decades-old NFSv2 boot path, which already checks NFSERR_ISDIR before NFSERR_INVAL. Returning ISDIR therefore restores symlink-through-NFS boot without a firmware update — the only practical fix, given that most U-Boot deployments are never flashed again. New U-Boot can still grow an NFSERR_IO arm for robustness, but that is not required for this server change to work.

The patch is tagged Fixes: 0ac903d1bfdc and is the candidate for backport to the LTS/stable kernels that shipped the regression (called out in the parent thread as LTS v6.12 and v6.18, plus stables v7.1 and v7.2).

Conclusions

  • Type of change: compatibility bug fix on NFSD, restoring Sun-compatible NFSv2 READ/WRITE status for non-regular files. Not a new feature, not an RFC change, not a Linux NFS client patch.
  • Do not restore NFSERR_INVAL. RFC 1094 never defined it; the previous mapping was already a Linux-ism.
  • Do return NFSERR_ISDIR from nfsd_proc_read() and nfsd_proc_write() when the target is not a regular file. That is what OpenSolaris does in rfs_read() / rfs_write() / rfs_write_sync(), and it is the status U-Boot already treats as “this is a symlink.”
  • Leave other NFSv2 procedures on NFSERR_IO. Brown’s OpenSolaris check is the rationale for keeping the special case that narrow.
  • Two Reviewed-by tags landed the same evening. No objections, no v2 requested in-window.

The discussion is complete for this week: the agreed server-side fix is posted and reviewed. Watch for it hitting nfsd trees and the stable backports that close the U-Boot netboot regression.
