nfs-utils gssd/statd help text catch-up

Summary

This week Dell engineer Prabhakar Pujeri posted a two-patch nfs-utils series to bring rpc.gssd and rpc.statd command help in line with the options those daemons actually accept. The work is a documentation/help-text bug fix, not a protocol change or new feature: it only touches usage strings and the rpc.gssd(8) synopsis so NFS client operators are not steered toward invalid flags or left unaware of existing ones.

The series is based on current nfs-utils master. Pujeri reported a clean autotools rebuild and make check; the statd integration test is skipped when its required service environment is unavailable. The whole delta is tiny — three files, four insertions and two deletions — and there were no replies, reviews, or acks in the window.

Why it matters for the NFS client

rpc.gssd is the userspace helper that obtains GSS/Kerberos contexts for the NFS client, and rpc.statd is the NSM/NLM lock-recovery daemon the client (and server) still depend on for NFSv3 locking. Misleading -h output is a practical client-side footgun: operators copy flags from usage text into unit files and mount scripts, then hit "invalid option" or never discover the NLM port knobs they need for firewall layouts.

Patch 1: rpc.gssd usage and man-page synopsis

Patch 1/2 fixes a two-way drift between getopt and the advertised flags in utils/gssd/gssd.c and utils/gssd/gssd.man.

Pujeri’s diagnosis is blunt:

"The getopt string no longer contains 'l', so the '-l' advertised by usage() and the rpc.gssd(8) synopsis only earns users an "invalid option". Conversely, the -T rpc-timeout option exists but was never added to usage()."

The patch therefore:

  • drops the stale -l from both usage() and the man-page synopsis
  • documents -T (rpc-timeout), which the daemon already implements

That is the client-facing timeout for GSS upcalls, so the missing -T in help text is the more important half of the fix: administrators who only read rpc.gssd -h had no hint that the timeout was tunable.

Patch 2: rpc.statd NLM port options

Patch 2/2 adds two lines to usage() in utils/statd/statd.c. rpc.statd already accepts -T/--nlm-port and -U/--nlm-udp-port, and both are described in rpc.statd(8), but the on-disk help never mentioned them.

"rpc.statd accepts -T/--nlm-port and -U/--nlm-udp-port and both are described in rpc.statd(8), but usage() never mentions them."

Those flags pin the NLM TCP/UDP ports used with lockd, which is exactly the kind of client-side firewall/NAT detail people look up from rpc.statd -h rather than the full man page.

Cover letter and status

In the cover letter, Pujeri framed the series as a straightforward catch-up:

"Bring the command help in line with the options accepted by rpc.gssd and rpc.statd. The first patch removes a stale rpc.gssd option and adds its timeout option. The second adds the existing NLM port options to rpc.statd usage output."

Conclusion this week: the patches are posted, compile-tested, and otherwise unanswered. No maintainer ack, nack, or requested revision appeared on linux-nfs before the window closed. The technical claim — help text must match getopt and the man pages — is uncontroversial; the remaining question is simply whether nfs-utils maintainers pick the series up as-is.
