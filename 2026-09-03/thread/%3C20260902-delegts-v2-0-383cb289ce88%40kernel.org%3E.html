nfsd accepts backdated delegated timestamps without a client RPC

Summary

This week's v2 series from Jeff Layton is a bug fix for NFSv4 attribute-delegation timestamp handling. It is not a protocol change and it deliberately avoids a client-side workaround that would force a SETATTR RPC on every utimensat().

The user-visible failure is on the NFS client: tools that write a file and then backdate it (tar -x, cp -p, rsync -t) lose the restored mtime when the client holds an attribute delegation. The client applies utimensat() locally and only reports the times at DELEGRETURN as TIME_DELEG_MODIFY. nfsd was discarding any timestamp that moved backwards, then nfsd4_finalize_deleg_timestamps() stamped "now", so the file kept the DELEGRETURN time. The SETATTR still returned NFS4_OK, so the client believed the backdate had stuck.

Layton's cover letter frames the client-vs-server choice directly:

"We could fix this on the client by making it always issue an RPC for the SETATTR, but that would harm performance in these common use-cases. This set allows the server to accept some of these backdated mtime updates, by changing how the ctime is handled."

He wants the series in v7.4.

How we got here this week

v1 landed on 1 September as a single nfsd patch (PATCH). Chuck Lever flagged a real correctness hole: vet_deleg_attrs() compared a later SETATTR against grant-time dp->dl_ctime, which is never refreshed. A second backdated SETATTR could then leave mtime at T3 and ctime at T5, contradicting the claim that "an mtime that moves backwards sets the ctime to the current time." He asked whether comparing against the inode's current ctime would be better.

Layton agreed and also called out another race:

"Yes, I think we do want to rework it to do that. Additionally, I noticed another race condition that we ought to fix while we're in here. ... I think we have to push some of this handling into the VFS layer so that it's done under more consistent locking and properly uses the mgtime infrastructure."

v2 is that rework, split into three patches.

Patch 1: VFS stamps "now" for a stale delegated ctime

PATCH v2 1/3 changes inode_set_ctime_deleg() in fs/inode.c. The helper previously dropped any update that did not advance ctime. That is correct when a client reports a timestamp it advanced on its own; it is wrong when the client intentionally moves the timestamp backwards via utimensat(). The new rule stamps the current time instead, so ctime still never moves backwards, but a backdated mtime no longer leaves ctime stranded at an older delegated value.

This is the piece that had to move under VFS locking rather than live in nfsd's comparison against grant-time snapshots. Jan Kara reviewed it:

"Looks good to me. Feel free to add: Reviewed-by: Jan Kara jack@suse.cz"

Patch 2: nfsd treats the delegation holder's SETATTR as fact

PATCH v2 2/3 is the nfsd policy change. Because the delegation makes the client the authority for these times, nfsd now accepts a backwards atime or mtime. A backwards mtime sets ctime to "now" via the VFS helper, so nfsd no longer compares against ctime itself. Future times are still clamped. The CB_GETATTR path keeps the old rule: a backwards time there is treated as a stale report.

Several client-visible edge cases are cleaned up in the same patch:

  • The client reports times at every DELEGRETURN, changed or not. A report that already matches the inode is dropped, so an untouched file does not get a new change attribute (and every other client does not drop cache). Without that, notify_change() ran for nothing and a holder that does not own the file could get -EPERM from setattr_prepare() where it used to get NFS4_OK.
  • dl_setattr is set only on the branch that actually carries a c/mtime update, so a write that follows a no-op SETATTR does not have its timestamps overwritten by nfsd4_finalize_deleg_timestamps().

Layton is explicit that this diverges from one sentence of RFC 9754 ("the server ignores a time before the original time") because the same section also says the server MUST accept the change or MUST reject it with NFS4ERR_DELAY. A silent discard does neither, and a DELAY retry would just resend the same backdated value.

One gap remains, and it is a client-protocol limitation:

"There is still one gap: nfsd cannot tell an explicit utimensat() from a report of a write. An mtime after the ctime and before the current time therefore sets the ctime to that mtime, instead of to 'now'. RFC 9754 requires this. Fixing that would require the client to issue an RPC for the mtime."

So the Linux client keeps the caching win of the attribute delegation; the remaining RFC mismatch is accepted rather than paid for with extra RPCs on the tar/cp/rsync path.

Patch 3: CB_GETATTR vets against the inode, not grant-time snapshots

PATCH v2 3/3 is the follow-through on Chuck's v1 comment, plus the race Layton mentioned. cb_getattr_update_times() used to vet CB_GETATTR times against dl_atime/dl_mtime/dl_ctime, sampled once at grant and never refreshed. An earlier CB_GETATTR or SETATTR could move the inode past those snapshots, so vetting accepted a report it must reject; setattr_copy() then applied atime/mtime with no current-value check and both moved backwards.

v2 compares against the inode instead, takes i_rwsem before the comparison so a concurrent delegation-break setattr cannot land first, and drops the now-unused dl_atime/dl_mtime/dl_ctime fields. That also removes a read of an uninitialized struct kstat on the read-delegation arm (stat.atime was assigned to dl_atime even when nfs4_delegation_stat() had not run).

All three patches carry Fixes: 3952f1cbcbc4 ("nfsd: fix SETATTR updates for delegated timestamps").

Review status

Chuck Lever acked the series and directed the merge path because of the VFS change:

"Since the series modifies fs/inode.c, Christian will want to take it through the VFS tree."

"Acked-by: Chuck Lever cel@kernel.org"

Jan Kara's Reviewed-by covers the VFS ctime helper. There was no further technical objection in-window. The practical conclusion this week is: keep the Linux client's delegated utimensat() caching, teach nfsd (and inode_set_ctime_deleg()) to accept a backdated holder SETATTR, route the series via the VFS tree, and live with the remaining RFC 9754 gap unless the client is willing to issue an extra RPC.
