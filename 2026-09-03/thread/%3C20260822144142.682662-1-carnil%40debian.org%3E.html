rpcctl Python 3.14 SyntaxWarning committed to nfs-utils

rpcctl Python 3.14 finally-block SyntaxWarning (committed)

Summary

This is a userspace bug fix, not a protocol change or a kernel NFS client feature. Last week Debian's Salvatore Bonaccorso posted a five-line rewrite of tools/rpcctl/rpcctl.py so the RPC-pipefs helper would stop emitting a Python 3.14 SyntaxWarning (PEP 765) on return inside a finally block. This week the patch landed: nfs-utils maintainer Steve Dickson committed it to nfs-utils-2-9-3-rc2.

The discussion is closed. There was no technical debate, no alternative patch, and no NAK.

Prior week, briefly

Bonaccorso's original patch credited Trent W. Buck and described the problem as:

"Trent W. Buck reported that when using rpcctl with Python 3.14 version, a SyntaxWarning warning is issued on the use of return in the finally block in the read_info_file function."

The fix replaced finally with except BaseException and moved the return up one indent level, preserving cleanup on any unwind (including KeyboardInterrupt/SystemExit) while silencing the PEP 765 warning. Debian tracked it as bug 1144982. A follow-up the same day widened the To: list to include Anna Schumaker. No maintainer ACK arrived in that window.

This week's development

On 31 August, Steve Dickson replied to the original patch with a one-line merge notice:

"Committed... (tag: nfs-utils-2-9-3-rc2)"

The same text went out twice more within about a minute — a second copy and a third — all quoting Bonaccorso's patch and all tagging nfs-utils-2-9-3-rc2. They add no extra review comments, no requested changes, and no discussion of the except BaseException shape versus a larger restructure of read_info_file. The triple send is almost certainly accidental duplication, not a second commit.

Why it matters for NFS client work

rpcctl is not in-kernel, but it is the userspace counterpart that reads RPC pipefs info files used when diagnosing NFS client transports (Xprt objects and friends). A SyntaxWarning on every invocation would have become noise as distributions pick up Python 3.14. Landing the fix in nfs-utils-2-9-3-rc2 means the helper stays clean on current Python without changing how it inspects the client's RPC stack.

  • Class: userspace compatibility bug fix (PEP 765 / Python 3.14).
  • Scope: tools/rpcctl/rpcctl.py (read_info_file), 3 insertions / 2 deletions.
  • Outcome: committed by Dickson to nfs-utils-2-9-3-rc2; thread complete.

Takeaway

The open item from last week — maintainer ACK — is resolved. No remaining questions on the list. Client-side diagnosis tooling is unblocked for Python 3.14; there is nothing further for kernel NFS client developers to do in this thread.
