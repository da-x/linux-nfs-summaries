netfs v11: bvecq buffering rewrite, NFS fscache hooks

Summary

David Howells posted a 36-patch v11 of his long-running netfslib rewrite on 2 September, asking Paulo Alcantara to review a series that retires folio_queue, rolling_buffer and ITER_FOLIOQ in favour of a segmented bio_vec[] chain (bvecq) and a matching ITER_BVECQ iterator. The posting is a combined feature refactor, API change and a clutch of I/O-path bug fixes; it is the only activity in this thread during the week, aside from a process objection from Christoph Hellwig the next morning. There is no merge conclusion yet.

Why the rewrite, and why NFS should care

Howells’ cover letter sets out three aims: follow the kernel’s consolidation on bio_vec arrays, collapse buffered and DIO buffering onto a single scheme, and send each filesystem RPC with a single kernel_sendmsg() so the entire transmission loop sits inside one tcp_sendmsg() without corking. The replacement object is a NULL-terminated, refcounted struct bvecq that can glue extra segments on the front, carry a disposal type (PAGECACHE / GUP / ALLOCED / EXTERNAL), and be walked by ITER_BVECQ.

That plumbing is not NFS-specific, but the Linux NFS client is a netfslib consumer for fscache, and two patches in this revision touch NFS directly. Patch 18 makes deprecated PG_private_2 support optional and has fs/nfs/Kconfig select it (Ceph does the same), so NFS remains on the old copy-to-cache folio flag while other netfs users can drop it. Patch 34 then rewrites fs/nfs/fscache.c as part of collapsing ->prepare_read() / ->issue_read() into a single issue callback that slices a bvecq rather than an iov_iter. The v11 changelog also records earlier NFS-side issue-path bugs that were folded into previous revisions and remain part of the story: nfs_netfs_issue_read() now returns an int, sets -ENOMEM rather than 0 on allocation failure, and terminates a subrequest only once.

Howells is explicit that the series is still a work in progress for the protocol-facing filesystems. Two follow-ons he already has working for CIFS, but not in this branch, would let a filesystem tack RPC headers and trailers onto a duplicated bvecq slice and splice the TCP receive queue into a bvecq so the socket lock can be dropped before the copy. Those are the pieces that would eventually matter for NFS RPC packing, but they are not in v11.

Core infrastructure and the Hellwig objection

The first third of the series is core code. Patch 01 is a real bug fix: commit 14b007e17881 added iter_iov_addr() / iter_iov_len() checks to iov_iter_extract_bvecs(), which are only valid for ITER_UBUF/ITER_IOVEC and malfunction when cachefiles passes ITER_FOLIOQ. Howells switches the check to iov_iter_alignment(). Patch 02 stores a folio count in readahead_control so a filesystem can size its buffer up front. Patch 03, suggested by Matthew Wilcox, adds a bulk folio_end_writeback() iterator that merges xarray walks and stats updates. Patch 07 introduces bvecq and ITER_BVECQ (Paulo Alcantara already reviewed that one); later patches add netfs helpers, a mempool for writeback (because writeback_iter() cannot fail with ENOMEM under WB_SYNC_ALL), and an extract-from-iter helper.

That core-vs-netfs mixing is exactly what Hellwig objected to. Replying to the cover letter in what he labelled “broken record mode”, he wrote:

"Please split out changes to core infrastructure. Make sure they are also useful and used outside of your little corner. Ensure they can be an are properly tested by either having common test exercise them or adding new easy to run test in common testsuites like xfstests or blktests. And make sure the changes to the core code are relatively self-contained and reviewable."

There is no reply from Howells in-window. The series remains a single 36-patch stack that also deletes ITER_FOLIOQ, folio_queue and rolling_buffer once CIFS encryption buffers, AFS directories and smbdirect SG mapping have been converted.

Netfslib I/O path: writeback, reads, and the NFS fscache hook

The meat of the client-visible change is the I/O engine. Patch 14 removes writethrough entirely:

"Remove the netfs writethrough code as it's very tricky to get the locking right and it will probably deadlock if used in conjunction with Ceph snapshots because it excludes writeback for the duration, but to flush out old snapshots, it does a synchronous flush that invokes writeback."

O_SYNC now relies on the existing generic_write_sync() after netfs_perform_write(). NFS is not a writethrough user, but the removal simplifies the shared write-issue path that NFS fscache still shares.

Patch 21 is the actual switch to bvecq. Buffered I/O still adds folios as it goes; DIO extracts the source iterator up front. Three cursors on netfs_io_request (load_cursor, dispatch_cursor, collect_cursor) plus a per-subrequest dispatch_pos/content pair replace the rolling buffer. Howells notes that holding a ref on every bvecq_pos “is probably overkill as only the hindmost position (that of collection) needs to hold a reference.”

Writeback is then split into smaller, reviewable steps that Howells extracted from earlier megapatches. Patch 27 builds a list of file-position regions under writeback. Patch 28 uses Wilcox’s bulk end-writeback tool and that region list to unmark folios from the pagecache xarray instead of walking the bvecq, so the collector no longer has to stay attached to the producer. Patch 31 adds ->estimate_write() on both the filesystem and cache APIs (AFS, 9p, CIFS and cachefiles get implementations; NFS does not, because it is not driving netfslib writeback). Patch 32 reworks writeback to accumulate buffers and flush a stream when the estimate or a discontiguity is hit, which Howells says is needed before bounce buffering for encryption.

The read side gets two important bug-hardening changes. Patch 29 stops trying to salvage fully-downloaded folios that span mixed-success subrequests:

"Simplify this by just abandoning the rest of a read request once a permanently failed subreq is hit. This is what read_folio, DIO/unbuffered read, gap filling, RMW and write preload all need to do; readahead is the odd one out as it doesn't have any return other than unlocking folios."

Retryable failures still retry inside the request. Patch 30 aborts with -EIO if a subrequest over-reads, on the grounds that the buffer may already be corrupted.

Patch 34 then fuses prepare and issue. Howells’ rationale is resource hold time, which is the piece that maps most directly onto NFS fscache and onto CIFS credits:

"This delay between prepare and issue, however, presents a couple of issues: firstly, it may hold server resources for a significant length of time (e.g. cifs SMB2+ credits), blocking other users; and secondly it holds memory or other local resources that could otherwise be used to perform some other task under low-memory conditions."

Netfslib now accumulates bufferage, calls ->issue_xxx() with the subrequest defined to its maximum extent, and the filesystem or cache shrinks it and callbacks to take a bvecq slice. iov_iter is pushed down into the filesystem. NFS’s fs/nfs/fscache.c is updated for that new issue contract; CIFS, AFS, 9p, Ceph and cachefiles are converted in the same patch. -ENOMEM from issue now aborts further subrequest generation.

Cachefiles, and what this does not yet do for NFS

Two cachefiles patches sit at the edge of NFS cached I/O. Patch 19 stops using SEEK_DATA/SEEK_HOLE for the common contiguous open(O_TRUNC); write…; close() case, tagging those objects CACHEFILES_CONTENT_ALL and tracking how much is stored in the cache i_size separately from the netfs file size. Occupancy is queried two extents at a time via a new ->query_occupancy() method. Patch 36 presets the state xattr when the tmpfile is created so a later ENOSPC from setxattr cannot force a successfully filled cache file to be scrapped.

What the series does not do this week is touch the NFS RPC layer, pNFS, or the non-fscache NFS pagecache path. NFS remains a comparatively thin netfslib client: it opts into PG_private_2, it has its fscache issue hook rewritten, and it inherits the abandoned-read / over-read / all-queued barrier cleanups automatically. There is no in-week comment from Trond Myklebust, Anna Schumaker or other NFS maintainers.

Status at week’s end

v11 is rebased on Christian Brauner’s vfs/vfs.fixes branch. Howells split several previously tangled changes (readahead producer/consumer preload, earlier copy-to-cache marking, writeback region lists, ->estimate_write(), unused-code removal) into their own patches, and he records a long trail of Sashiko-reported fixes from v4–v10. The tree is at git://git.kernel.org/pub/scm/linux/kernel/git/dhowells/linux-fs.git on netfs-next. Review so far is one Ack on the ITER_BVECQ introduction from Alcantara (carried from an earlier revision) and Hellwig’s demand that the mm/iov_iter/block pieces be split, generalised and tested outside netfs. Until that split happens, this remains an RFC-scale netfs rewrite with NFS fscache as a passenger, not an NFS-client series in its own right.
