fsidd: drop assert() on local-socket command parsing

Summary

Scott Mayhew posted a one-file nfs-utils robustness patch that hardens fsidd, the userspace filesystem-ID daemon used by NFS reexport. The change is a bug fix, not a protocol change or a new client feature: malformed command traffic on the local socket could take the daemon down instead of being rejected.

Mayhew’s diagnosis is blunt. fsidd currently leans on assert() while parsing commands received over that socket, specifically to require an argument after the command prefix:

"fsidd relies on assert() to ensure that an argument is present after the command prefix while parsing commands received over the local socket. Malformed input can cause fsidd to abort."

That is a classic assert-as-input-validation failure. Assertions are compile-time debug checks; they are not a contract with untrusted (or even merely buggy) local clients. If NDEBUG is unset, a missing argument becomes an abort. If it is set, the same path can fall through into undefined behavior. Either way, a daemon that exists to keep reexport identity mapping alive should not die because a peer sent a truncated command.

The proposed fix, confined to support/reexport/fsidd.c (19 lines: +15/−4), replaces those assertions with explicit malformed-input handling and returns an error to the client. Mayhew’s intended outcome is equally direct:

"Replace the assertions with explicit malformed-input handling and return an error to the client."

That is the right shape for a local-socket service: treat a missing argument as a protocol error, keep the process up, and let the caller recover. For NFS reexport, that matters more than the diff size suggests. fsidd sits on the path that maps filesystem identities across reexported mounts; an abort there is not a quiet userspace hiccup, it is a service outage that can stall or confuse client-visible reexport operations until the daemon is restarted.

The patch is a late-week drop (3 September 2026) with no review replies in this window. There is no Acked-by, no requested-changes, and no discussion of whether every parse site was converted or whether the new error path is tested. Until that review lands, the technical conclusion is Mayhew’s: assert() is the wrong tool for socket command parsing, and fsidd should answer malformed input with an error rather than disappearing.

NFS client kernel code is not touched here; the relevance to client development is operational. Reexport clients depend on this userspace helper staying alive. Hardening fsidd against garbage on its local socket is a small but important reliability fix on that path.
