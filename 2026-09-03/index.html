NFS client lock splits, pNFS hardening, and a 45 GB/s RDMA regression

Week ending 2026-09-03

The Linux NFS client spent the week under a microscope: Chuck Lever posted two RFCs that split the hottest SUNRPC locks and retune rpciod/nfsiod/xprtiod, then a 96-CPU pNFS/RDMA box showed those same workqueue changes can cut streaming throughput from 45 GB/s to 15 GB/s. Alongside that, Dell expanded pNFS XDR hardening, SUSE reported an unbootable FlexFiles NFS root, and Lever rewrote the pNFS blocklayout rpc_pipefs waiter after a syzkaller KASAN hit. Server-side, Jeff Layton’s netlink listener_set hang series landed in nfsd-testing, NFSD learned to return Sun-compatible NFSERR_ISDIR so U-Boot can boot through a symlink again, and a GSS deferral underflow became a server identity-confusion bug.

Client lock contention: split the 53% lock, do not inline async RPC

Under a 4KB NFSv3 workload on 100GbE RDMA, Lever measured up to 53% of non-idle cycles in native_queued_spin_lock_slowpath. The RFC v1 named three axes: reserve_lock on every XID allocation, queue_lock on every submit and completion, and the unbound pool lock on rpciod/nfsiod/xprtiod. Two days later RFC v2 kept the cheap wins and dropped the aggressive one.

  • XID allocation becomes atomic_t. It never needed the slot-table lock.
  • recv_lock splits out of xprt->queue_lock. Reply matching and transmit drain stop sharing one lock. v2 is the version to take: it waits for a zero pin count under queue_lock before freeing the send bvec (sashiko UAF).
  • Do not inline the first async RPC states. v1 ran call_start through call_allocate in the submitter to skip a rpciod hop. v2 withdrew it: completion callbacks in the submitter re-create the pNFS read-resend vs. layoutreturn deadlock of 54e4a0dfa25d. The hop stays.
  • WQ_AFFN_SMT on rpciod, nfsiod, and xprtiod. Tejun Heo had already rejected a finer global unbound default. On Lever’s 12-core single-LLC box the override cut submission-latency variance 67% and p99.9 completion latency 11%. Tejun nitted the new workqueue_set_affn_scope() helper; Lever says that is already in an unposted v3.

Then Tim Menninger bisected a 45 GB/s → 15–25 GB/s regression on a 96-CPU pNFS FlexFiles/RDMA client (nconnect=16, 1 MiB reads) to v1’s rpciod SMT override. On v1 the live sysfs toggle smt ↔ cache_shard was causal. On v2 the 15 GB/s cliff remains, but it is no longer pinned to affinity scope — dropping the async-inline hop changed the failure mode. Lever has not withdrawn the patch; he wants IRQ maps and rpciod vs. ib-comp-wq locality before anyone merges SMT affinity.

pNFS client bugs: XDR loops, a FlexFiles root hang, 64-bit stripe units

Prabhakar Pujeri’s v2 expands last week’s GETDEVICEINFO address work into seven stable-bound patches. A broken or malicious pNFS server can still provoke unbounded multipath loops (the inner address count can be U32_MAX and nfs4_decode_mp_ds_addr() returns NULL without consuming input), oversized version_count / fh_count allocations, an unchecked sscanf() on data-server port octets, and leaked da_netid strings on cache-hit cleanup. The series bounds every loop by remaining XDR, exports nfs4_pnfs_ds_addr_free(), and grows KUnit coverage from three flexfiles cases to six. No review in-window.

Antonio Alvarez Feijoo reported an unbootable NFSv4 root against knfsd with FlexFiles enabled. First DS I/O does symbol_request(nfs3_set_ds_client) → request_module(), which after pivot_root() tries to exec /sbin/modprobe from the filesystem that is blocked waiting for that same DS connect. The hang stayed latent until 7a375cafc14e honored FF_FLAGS_NO_IO_THRU_MDS — and knfsd sets that flag on every FlexFiles layout. The proposed fix is MODULE_SOFTDEP("pre: nfsv3") on nfs_layout_flexfiles; workaround is rd.driver.pre=nfsv3. Unreviewed.

Benjamin Coddington’s 23-patch FlexFiles series is still in review. Anna Schumaker rejected the v2 plan to -EINVAL a 64-bit stripe_unit that does not fit 32 bits; Coddington agreed to promote DS-selection and page-coalescing to div64_u64() in v3 instead. The ndc_immediate CHANGE path drew only comment nits. The rest of the stack — RCU pins, DELETE recovery, 1024-device cache scaling — is unreviewed.

Christoph Hellwig agreed that a SCSI-only pNFS client should not drag in RFC 5663 block layout and device-mapper, but rejected Scott Mayhew’s file-level rewrite and “AI slop” changelog. Copy nfsd’s independent CONFIG_NFSD_BLOCKLAYOUT / CONFIG_NFSD_SCSILAYOUT pair instead.

rpc_pipefs waiters: KASAN on cld, rewrite on blocklayout

Farhad Alemi’s syzkaller KASAN (rpc_pipe_msg left queued on a stack frame) produced Lever’s five-patch v1 and then an eight-patch v2. The cld downcall matches on xid alone, so a write that arrives before nfsdcld has read the upcall completes the waiter while the message is still queued. gss and idmap already keep rpc_pipe_msg in a heap object; cld and pNFS blocklayout did not.

v2 adds the complementary hang: once the daemon has read the whole upcall, rpc_pipe_read() unlinks the message, so a daemon that exits between read and write leaves the waiter in TASK_UNINTERRUPTIBLE. On the client, bl_resolve_deviceid() holds nn->bl_mutex across that wait, so a dying blkmapd freezes every later blocklayout GETDEVICEINFO in the netns. Patches 5 and 8 rewrite the blocklayout waiter onto the gss pattern (message in struct nfs_net, complete only on its own reply, .release_pipe on close). Lever asked NFS client maintainers for an Acked-by so the mixed series can go through the NFSD tree. None arrived. A late-week syzbot hung-task in nfsd4_cld_tracking_init is the hang face of the same waiter, with a C reproducer.

Other client bug fixes

  • NFSv3/RDMA READ corruption. Rakesh Bhargava retracted his ping after finding Lever’s already-posted rpcrdma_inline_fixup() shrink. A legal READ3resok with attributes_follow = FALSE was smearing 84 bytes of stale head onto a correct RDMA Write payload; FlexFiles DS READs hit it every time because they never learn read_hdrsize. Merge of that v2 is still outstanding.
  • NFSv4.2 fallocate EOF. AUTOSEL is backporting Dai Ngo’s fix (6.18–6.1): ZERO_RANGE/ALLOCATE extends the file on the server, but a write delegation blocks post-op i_size refresh, so generic/075 fails with “Size error.” The client must bump i_size itself on RPC success.
  • xprtrdma request-pool slack. Same AUTOSEL batch, 6.18–5.10: after Send-gated recycling, allocate max_reqs + DIV_ROUND_UP(max_reqs, 8) reqs so pinned sendctxes cannot stall a credit-legal RPC.
  • svcrdma credit grant. Lever’s three-patch series sets sc_fc_credits after the RQ clamp. A client that honors an over-advertised grant overruns the Receive Queue and drops the connection with RNR. Unreviewed; the client is already behaving correctly.
  • SUNRPC timeout diagnostics. Manjunath Patil’s transport-id printk is still waiting on Trond/Anna. Chuck clarified that Patchwork “Not Applicable” just means it is not an NFSD patch (thread).

Server fixes that clients actually see

U-Boot NFSv2 netboot. Commit 0ac903d1bfdc stopped NFSD from returning illegal NFSERR_INVAL for READ of a symlink, substituting NFSERR_IO. U-Boot only follows a symlink on NFSERR_ISDIR or NFSERR_INVAL, so boot through a symlink now transfers zero bytes. Maintainers refused a revert to the illegal INVAL mapping. Lever’s follow-up maps NFSv2 READ/WRITE of a non-regular file to Sun/Solaris NFSERR_ISDIR. Jeff Layton and NeilBrown Reviewed-by the same day. Backport candidate for LTS 6.12/6.18 and stables 7.1/7.2.

Delegated timestamps. cp -p, rsync -t, and tar -x lose mtime against a Linux client that holds an attribute delegation: the client applies utimensat() locally and reports TIME_DELEG_MODIFY at DELEGRETURN, and nfsd was discarding a backwards time then stamping “now.” Layton rejected the “just RPC from the client” workaround as too expensive for untar. v1 compared against grant-time dl_ctime; Chuck flagged a second SETATTR that could leave ctime stranded. v2 moves “stamp now for a stale delegated ctime” into inode_set_ctime_deleg(), accepts the holder’s backdated SETATTR, and vets CB_GETATTR against the inode. Chuck Acked-by; Jan Kara Reviewed-by the VFS helper. Merge path is the VFS tree. One RFC 9754 gap remains: nfsd cannot tell an explicit utimensat() from a write report without an extra client RPC.

RPCSEC_GSS deferral. Yilin Zhang reported that svc_defer() misses the rq_arg.len vs head[0].iov_len check, so a crafted GSS packet can poison the deferred snapshot and skip GSS on replay (thread). Lever’s v1 copies from the head buffer and refuses to defer a Call that spills into pages. Integrity unwrap truncates rq_arg.len by the MIC; privacy unwrap leaves a client-chosen skip. A deferred replay skips GSS verification, so a forged Call in that window can run under another user’s GSS context. Unreviewed; treat as high priority on GSS nfsd.

NFSD listener_set hangs. Layton spun v3 → v4 → v5 in four days. A silent local rpcbind used to cost one timeout per listener/program/version under nfsd_mutex (up to ~34 minutes with the 1024-entry cap). v5 caps the request, validates transport names before taking the mutex, bounds the local rpcbind client to 1s, stops walking once rpcbind is silent (-EIO, not v3’s too-wide -ENAVAIL), and adds a per-netns rpcbind stub selftest. Chuck applied all 15 patches to nfsd-testing. The 1s timeout is still a mitigation; async/userland registration remains the real cure. Twin syzbot reports this week: nfsd_nrthreads (now with a C reproducer naming rpcb_create_local on the holder) and nfsd_nl_unlock_filesystem_doit.

Also applied to nfsd-testing: Cen Zhang’s cl_lock around client_has_state() (KASAN UAF on concurrent EXCHANGE_ID). Ameer Hamza’s session-slot replay fix picked up Layton’s Reviewed-by. A syzbot AI patch to reject a socket already in use in svc_addsock() duplicates Lever’s August check already queued.

Ongoing debates

Is the NFSv3 DRC advisory? Lever’s implied-ACK eviction v2 drops completed TCP/RDMA DRC entries when a later request arrives on the same svc_xprt, cutting nfsd_cache_lookup from 1.53% to 0.76% of CPU on NFSv3/RDMA writes. Layton rejected the “cache is advisory” framing: a pipelined RENAME whose reply is still in flight can be evicted, then a reconnect retransmits and re-executes a non-idempotent op. Lever’s closer: the old DRC has always been best-effort, overrun is more likely on fast networks, and “NFSv4.1 is the only total answer.” No Ack, no v3.

vfs_lookup_open() for NFSD OPEN. NeilBrown’s conversion is blocked by Chuck: VFS-tree routing, missing S_IALLUGO clamp (mode 0040755 can create a socket), GUARDED4 now returning EXIST instead of ISDIR/SYMLINK, and break_deleg_wait() stalling every nfsd thread instead of returning NFS4ERR_DELAY on directory-delegation recall.

netfs bvecq rewrite. David Howells posted v11 (36 patches). NFS is a passenger: it keeps PG_private_2 for fscache and gets its issue hook rewritten. Christoph Hellwig, “broken record mode,” wants the mm/iov_iter/block pieces split, generalised, and tested outside netfs.

Userspace: rpcbind, gssd, junctions, nfsdctl

Scott Mayhew dropped a pile of nfs-utils/rpcbind hardening on 3 September: rpcbind rmtcalls actually disabled when --enable-rmtcalls is unset (today they still fork loggers and grow stats lists before failing), GETSTAT restricted to loopback, spoofed-XID forward-slot free closed; gssd shutdown-join and upcall leaks; junction XML over-read and multi-location UAF. Pujeri validates gssd/idmapd names (uninitialized heap log, NAMETOID strnlen, overlong hostname → ENAMETOOLONG instead of a truncated keytab lookup). Krzesimir Nowak posted an rpcinfo stack overflow in rpcbdump(). None of these have review yet.

On the admin ABI, Pujeri’s nfsd Netlink client dump reached v3; Layton still wants the confirmed/unconfirmed walk called twice rather than incremented through an enum. Companion nfsdctl clients v2 is unreviewed. Grace reporting stays deferred so it can later represent per-export grace.

Also this week

  • xdrgen pragma pages / pragma aggregate — generator feature so forthcoming NFSv2/v3/ACL conversions can splice page-cache payloads and stream aclent<> / READDIR without copying. No in-tree .x file uses either directive yet; client READDIR decode is still a stub.
  • NFS3ERR import — Layton Reviewed-by both patches. Shared linux/nfs3.h is now the canonical home for NFSv3 status names.
  • PG_private removal v2 — NFS writeback already owns folio->private with its own refcount; the client only loses two no-op helpers and a comment. No linux-nfs review.
  • Windows ms-nfs41-client binaries seeking interop against Linux 6.6+ / 7.2 nfsd (COPY/CLONE, case-insensitive exports, named attributes).

Watch next week: Lever RFC v3 of the lock-contention series (and Tim’s perf of rpciod vs. ib-comp-wq); client Ack on the rpc_pipefs v2; review of Pujeri’s pNFS XDR series and Feijoo’s flexfiles softdep; Coddington v3 with 64-bit stripe_unit; merge of the xprtrdma READ-corruption fix; stable backports of the U-Boot NFSERR_ISDIR mapping.
