Summary

Case Folding v14: Series Applied to f2fs Development Tree

Bridge from Prior Weeks

The "[PATCH v14 00/15] Exposing case folding behavior" series was posted by Chuck Lever on May 7, merged into the VFS tree by Christian Brauner on May 11 (week of 2026-05-14), and confirmed targeted for Linux 7.2 (week of 2026-05-21). The series is a new feature that exposes filesystem case-folding behavior across the VFS, with critical implications for NFS client caching correctness and NFSD attribute reporting to non-POSIX clients. Post-merge bug triage on vfat's fileattr_get was underway as of late May.

This Week: Application to jaegeuk/f2fs.git (dev)

The sole message this week is a patchwork notification from patchwork-bot+f2fs@kernel.org, confirming that the full 15-patch series was applied to jaegeuk/f2fs.git (dev) by Christian Brauner on June 24:

"This series was applied to jaegeuk/f2fs.git (dev) by Christian Brauner brauner@kernel.org"

The bot echoes Lever's original merge request from May 7:

"Christian, let's lock this one in. I will post subsequent changes as delta patches."

NFS-Relevant Patches in the Applied Series

Of particular importance to NFS client and server development, the applied commits include:

  • Patch 10/15 — nfs: Implement fileattr_get for case sensitivity (commit 92d67628a1a9): The NFS client now reports its own case-handling capabilities via the VFS fileattr_get interface. This is critical for re-export scenarios where an NFS-mounted filesystem is itself exported by NFSD — the client's cached capability bits (NFS_CAP_CASE_INSENSITIVE, NFS_CAP_CASE_NONPRESERVING) are surfaced to upper layers so that correct semantics propagate through the stack.

  • Patch 13/15 — nfsd: Report export case-folding via NFSv3 PATHCONF (commit 211cb2ba4877): NFSD now answers NFSv3 PATHCONF queries with the underlying filesystem's case-folding state, enabling v3 clients to learn whether an export is case-insensitive.

  • Patch 14/15 — nfsd: Implement NFSv4 FATTR4_CASE_INSENSITIVE and FATTR4_CASE_PRESERVING (commit 01ee7c3d2e23): The core protocol change for NFSv4, advertising the two new attribute bits defined in the case-folding extension. This is what Windows-based NFS clients explicitly require to avoid redundant LOOKUP/READDIR round-trips for case variants.

Significance

This application to the f2fs development tree represents a downstream integration milestone: the case-folding infrastructure is now available in a filesystem maintainer's active development branch, where it can be tested alongside f2fs-specific behavior and picked up by distro integrators tracking linux-next. The fact that Brauner applied it (rather than Lever or an f2fs maintainer) underscores the cross-subsystem nature of this feature — it spans VFS core, ten filesystems, NFSD, and ksmbd.

For NFS client developers specifically, the key takeaway is that patch 10/15's fileattr_get implementation is now live in a testable tree. The prior week's vfat LTP regression (where wiring fileattr_get converted "skipped" test outcomes into "executed but failed") serves as a reminder that similar edge cases may surface in other filesystems' interactions with the NFS client's case-handling logic.

Conclusion

A quiet but consequential week: no new technical debate, just the mechanical confirmation that the long-gestating case-folding series has landed in yet another development tree. The stage is set for broader testing and for Lever's promised "subsequent changes as delta patches."
