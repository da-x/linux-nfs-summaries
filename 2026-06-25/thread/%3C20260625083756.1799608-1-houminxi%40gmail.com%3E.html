Flexfiles: New FFFL1 Test for LAYOUTGET ffl_flags Validation

Overview

This week, the Linux NFS mailing list saw a single-message thread in which Minxi Hou posted a patch adding test coverage for the ffl_flags field in Flexfiles LAYOUTGET responses. The thread is purely about test infrastructure for the NFSv4.1 server (Flexfiles) — it is not a new feature, protocol change, or bug fix in the kernel itself, but rather a gap-filling addition to the nfs4.1 self-test suite.

The Patch

Minxi Hou's patch adds a new test case, FFFL1, to nfs4.1/server41tests/st_flex.py (48 lines of insertions). The test verifies that the ffl_flags field returned in a LAYOUTGET response contains only bits defined in RFC 8435 Section 5.1:

  • NO_LAYOUTCOMMIT
  • NO_IO_THRU_MDS
  • NO_READ_IO

As Hou noted in the commit message:

"The three flag constants were already defined in nfs4_const.py but had no test coverage."

This makes clear the motivation: the kernel's Flexfiles server code and the test harness both recognized these flags, but nothing actually exercised them. The new FFFL1 test closes that gap by asserting that a compliant server only ever returns valid flag combinations.
