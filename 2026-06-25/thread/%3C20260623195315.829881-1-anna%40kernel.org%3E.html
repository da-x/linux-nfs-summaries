Summary

NFS Client Updates for Linux 7.2 Merged into Mainline

Overview

This week's activity in this thread is brief but consequential: Anna Schumaker sent the GIT PULL request to Linus Torvalds on June 23, and the pr-tracker-bot confirmed the merge into torvalds/linux.git just six hours later on June 24. The pull request, tagged nfs-for-7.2-1, represents the culmination of weeks of patch development and review across the linux-nfs list — a mix of new features, bug fixes, and cleanups that collectively strengthen the NFS client for the 7.2 release cycle.

"The following changes since commit 4549871118cf616eecdd2d939f78e3b9e1dddc48: Linux 7.1-rc7 (2026-06-07 15:37:58 -0700) are available in the Git repository at: git://git.linux-nfs.org/projects/anna/linux-nfs.git tags/nfs-for-7.2-1" Anna Schumaker

The diffstat is substantial: 35 files changed, 703 insertions(+), 326 deletions(-), with the heaviest concentration in net/sunrpc/xprtrdma/ (the NFS-over-RDMA transport) and fs/nfs/ (the core client).

Classification

This is a mixed pull request combining:

  • New features: XPRTRDMA request recycling decoupling, FMODE_NOWAIT for read-only files
  • Bug fixes: 16 distinct fixes spanning SUNRPC, XPRTRDMA, NFS core, NFSv4, pNFS, and flexfiles
  • Cleanups/improvements: fileid field removal, workqueue migration, llist conversion, mount option redaction

Key Technical Content

New Features

1. XPRTRDMA: Decouple req recycling from RPC completion (Chuck Lever, 13 patches)

This is the largest single contributor to this pull. Lever's series — which evolved through v2 in May and v3 on May 26 — addresses a use-after-free where an rpcrdma_req could be recycled back to its free pool while the HCA was still DMA-reading from its send buffer. The merged version includes:

  • Use of sendctx DMA state for Send signaling
  • Request-pool slack for delayed recycling
  • Clear receive-side ownership pointers on release
  • Documentation and assertions of reply-handler invariants
  • Conversion of the send buffer free list to an llist (lockless)
  • Check of frwr_wp_create() during connect
  • Resize of reply buffers before reposting receives
  • Sanitization of the reply credit grant after parsing
  • Repost of Receive buffers for malformed replies
  • Return of sendctx slot after Send preparation failure

2. NFS: Expose FMODE_NOWAIT for read-only files (Dylan Yudaken, 2 patches)

This feature — which first appeared as a one-liner from Arik Rinberg in April and was later expanded by Yudaken into a two-patch series for O_DIRECT reads — allows io_uring to complete NFS I/O requests inline rather than punting to background worker threads. The merged version adds a non-blocking variant of nfs_start_io_direct that returns -EAGAIN instead of blocking on the inode lock, and exposes FMODE_NOWAIT for read-only files.

Bug Fixes (16 total)

SUNRPC (2 fixes by Hongling Zeng):

  • Fix sunrpc sysfs error handling in rpc_sysfs_xprt_switch_add_xprt_store()
  • Fix uninitialized xprt_create_args structure — "critical fields like srcaddr, bc_xps, and flags contain uninitialized stack garbage"

XPRTRDMA (3 fixes by Chris Mason):

  • Fix ep kref imbalance on ADDR_CHANGE: an RDMA_CM_EVENT_ADDR_CHANGE arriving before ESTABLISHED caused a reference count underflow during teardown
  • Initialize re_id before removal registration
  • Fix bcall rep leak and unbounded peek: "five subsequent __be32 reads ... walk up to 20 bytes past the wire payload into stale regbuf contents"

NFS Core (5 fixes):

  • Fix EOF updates after fallocate/zero-range (Dai Ngo): NFSv4.2 fallocate/zero-range operations extended files on the server but left the local inode's i_size stale under a write delegation, causing xfstest generic/075 failures
  • Keep PG_UPTODATE clear after read errors in page groups (Clark Wang): introduces a sticky page-group read-failed flag to prevent serving stale data
  • Use nfsi->rwsem to protect traversal of the file lock list (Yang Erkun): fixes a use-after-free where nfs_delegation_claim_locks released flctx->flc_lock during iteration and relied on so_delegreturn_mutex — but that mutex is per-state-owner, not per-inode
  • Prevent resource leak in nfs_alloc_server() (Markus Elfring): missing ida_free() in error path
  • Use common error handling code in nfs_alloc_server() (Markus Elfring): Coccinelle-driven cleanup

NFSv4 (2 fixes):

  • Clear exception state on successful mkdir retry (Igor Raits): fixes spurious -EEXIST errors from mkdir(2) after a successful retry following NFS4ERR_DELAY
  • Don't skip revalidate when holding a dir delegation and attrs are stale (Tom Haynes): the client's early-exit optimization in __nfs_revalidate_inode() was bypassing GETATTR RPCs even when attributes were flagged stale

pNFS (3 fixes):

  • Fix use-after-free in pnfs_update_layout() (Wentao Liang): tracepoint ordering issue where the layout segment could be freed before the tracepoint fired
  • Defer return_range callbacks until after inode unlock (Dai Ngo): fixes a sleeping-in-atomic-context bug where the block layout driver's return_range callback issues SCSI PR commands while the inode lock is still held — "can trigger a full panic under panic_on_warn"
  • Fix LAYOUTCOMMIT retry loop on OLD_STATEID (Lei Yin): unbounded retry loop in nfs4_layoutcommit_done() when the server returns NFS4ERR_OLD_STATEID; the fix refreshes the layout stateid before retrying

pNFS/flexfiles (3 fixes):

  • Reject zero-length r_addr in nfs4_decode_mp_ds_addr (Michael Bommarito): malformed server response could trigger a NULL pointer dereference
  • Reject zero-length filehandle version arrays (Michael Bommarito): without this check, a malformed server response triggers a ZERO_SIZE_PTR allocation that later dereferences as a null pointer, causing a KASAN-reported kernel panic
  • Fix checking if a layout is striped (Sagi Grimberg): switched from num_fh > 1 to stripe_count > 1; the old check failed when MDS and DSs shared the same filehandle

NFS/flexfiles (2 fixes by Mike Snitzer):

  • Honor FF_FLAGS_NO_IO_THRU_MDS on fatal DS connect errors: "If FF_FLAGS_NO_IO_THRU_MDS flag is set then NFSv4 flexfiles should never fallback to trying to issue IO directly to the MDS" — the out_failed: path's && !ds_fatal_error clause was overriding the flag's short-circuit
  • Honor FF_FLAGS_NO_IO_THRU_MDS in pg_get_mirror_count_write: introduces a sticky header-level flag (NFS4_FF_HDR_NO_IO_THRU_MDS) for lseg-less windows (e.g., between LAYOUTRETURN and the next LAYOUTGET)

Cleanups and Improvements

1. Remove the fileid field from struct nfs_inode (Jeff Layton, 4 patches)

This is the follow-on to Layton's treewide inode->i_ino widening series that merged in 7.1. As Layton noted at v2 submission: "With this change, we may be able to shrink some inode structures. For instance, struct nfs_inode has a fileid field that holds the 64-bit inode number." The four patches:

  • Store the full NFS fileid in inode->i_ino
  • Remove nfs_compat_user_ino64() and deprecate enable_ino64
  • Replace NFS_FILEID() and nfsi->fileid with inode->i_ino
  • Remove the fileid field from struct nfs_inode

This is a significant simplification: the XOR-folding hack that truncated 64-bit inode numbers for 32-bit userspace is gone, replaced by the VFS stat path's native -EOVERFLOW handling.

2. Move long-delayed xprtrdma work onto system_dfl_long_wq (Marco Crivellari)

A one-patch optimization that uses the dedicated "long" workqueue for delayed RDMA operations, reducing interference with short-latency tasks.

3. Convert xprtrdma send buffer free list to an llist (Chuck Lever)

Lockless conversion of the send buffer free list, improving scalability under concurrent access.

4. Show "<redacted>" for cert_serial and privkey_serial mount options (Sagi Grimberg)

Prevents credential metadata leakage when NFS mounts using Kerberos or TLS-related options are displayed via mount or /proc/mounts. The actual serial number values are replaced with the string <redacted>.

Bridge from Prior Weeks

This pull request represents the culmination of several weeks of patch development and review:

  • xprtrdma hardening: Chris Mason's three patches (ep kref, re_id init, bcall rep leak) were part of Chuck Lever's eight-patch series posted June 4 that "hardens connect and reply handling" — the result of an LLM-assisted audit. The series had no review or discussion by the close of that week, but all eight patches (including Lever's own five) are now merged.
  • FMODE_NOWAIT: The feature traces back to Arik Rinberg's one-line patch in April and Dylan Yudaken's two-patch series for O_DIRECT reads posted May 30, which "awaits maintainer sign-off on the locking-safety argument" as of early June.
  • pNFS fixes: Several of the pNFS bug fixes have been in flight for weeks:
    • The LAYOUTCOMMIT retry loop fix was first submitted by Lei Yin in April, with a v2 posted April 24 and a follow-up question about "Not Applicable" status on April 27.
    • The use-after-free in pnfs_update_layout() was submitted by Wentao Liang on May 18 and received review from Markus Elfring on May 23.
    • The return_range callback deferral was posted by Dai Ngo on May 26 with no replies by end of that week.
  • Flexfiles NO_IO_THRU_MDS: Mike Snitzer's two-patch fix was posted June 4 after a Hammerspace test exposed the bug by "widening the window between LAYOUTRETURN and LAYOUTGET."
  • Fileid cleanup: Jeff Layton's four-patch series is the promised follow-on to the treewide i_ino widening that merged in 7.1. As of this week's Coddington review notes, the NFS_FILEID() macro removal is already affecting new patches: "The NFS_FILEID() macro has been removed, and you should use inode->i_ino instead."

Significance for NFS Client Development

This pull request is a milestone for the NFS client in several ways:

  1. Memory safety: The xprtrdma hardening (both Lever's 13-patch recycling series and Mason's 3 fixes) addresses multiple use-after-free and reference-count bugs that could be triggered by malformed server responses or race conditions during teardown. These are exactly the kind of issues that syzbot and other fuzzers target, and their resolution strengthens the client's robustness against both accidental and malicious inputs.

  2. Protocol compliance: The pNFS and flexfiles fixes address subtle protocol-correctness issues:

    • The LAYOUTCOMMIT retry loop fix aligns the client with RFC 5661 §8.3.4 (retry on OLD_STATEID)
    • The FF_FLAGS_NO_IO_THRU_MDS fixes ensure the client honors an explicit layout flag that appliance vendors rely on for correctness
    • The return_range deferral fixes a locking violation that could panic the kernel

  3. Performance: The FMODE_NOWAIT feature enables io_uring to complete NFS I/O inline, eliminating an unnecessary worker-thread indirection for asynchronous workloads. The xprtrdma llist conversion and workqueue migration are smaller but meaningful scalability improvements.

  4. Code simplification: The fileid field removal eliminates a 32-bit compatibility hack that has been in the codebase for over a decade. As Layton noted, this is "a significant simplification of the NFS client codebase" that makes the inode number handling consistent with the rest of the VFS.

  5. Security: The mount option redaction prevents credential metadata leakage, addressing a real (if low-severity) information disclosure vector.

Final Conclusion

The thread has reached its natural conclusion: the pull request was sent on June 23 and merged into mainline on June 24, with no further discussion or objections. The pr-tracker-bot's confirmation — "has been merged into torvalds/linux.git: https://git.kernel.org/torvalds/c/840ef6c78e6a2f694b578ecb9063241c992aaa9e" — marks the end of this particular merge window for NFS client changes.

The 7.2 release will now carry these improvements, and the next cycle (7.3) is already taking shape with in-flight work on directory delegations (CB_NOTIFY), netlink stats, and other features as seen in the same-week predecessor threads.
