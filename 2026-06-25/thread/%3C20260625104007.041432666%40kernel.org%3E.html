Summary

tracing v4: split trace_controls.h out of trace_printk.h, remove it from kernel.h

Classification: Core-kernel header-cleanup / build-time patch series (v4), not an NFS feature or protocol change. Its only touch point with the NFS tree is a one-line include fix in include/linux/sunrpc/debug.h, which lands as part of PATCH v4 2/2.

What happened this week (2026-06-25)

The whole thread activity for the window is a single day: Steven Rostedt posted v4 of his two-patch series in the morning, Jani Nikula acked the i915 hunks shortly after, and Nathan Chancellor reported a build break at the end of the day. No prior-week summary file exists for this thread root (GlobOutputs found none), so there is no earlier history to bridge — v3 was simply linked from the cover letter.

The patches

In the cover letter, Rostedt frames the goal: "Remove trace_printk.h by creating a trace_controls.h for those places that need access to tracing prototypes like tracing_off() and for the places that need trace_printk() directly, to have it included directly."

  • PATCH v4 1/2 creates include/linux/trace_controls.h and moves the non-trace_printk() prototypes (the tracing control functions, ftrace_dump(), trace_dump_stack()) out of trace_printk.h. Rostedt draws a deliberate line between the two use cases:

    "These control functions as well as ftrace_dump() and trace_dump_stack() are used in cases where things go wrong. The main use case is to do a trace_dump_stack(); tracing_off(); ftrace_dump(); in a place that detected that something went wrong, whereas, trace_printk() is added to normal code during debugging and removed before committing upstream. The dump code is fine to keep in production."

    v4's delta over v3 (linked as 20260624081948...) was forced by automated testing: "Move include out of #if statement in rcu.h — kernel test robot found other configs that could require the control functions in rcu.h. Just always include it in that file."

  • PATCH v4 2/2 removes trace_printk.h from include/linux/kernel.h, motivated by build-time complaints ("There have been complaints about trace_printk.h causing more build time for being in kernel.h if it changes") and the broader effort to slim down kernel.h. The NFS-relevant hunk is a single added include in include/linux/sunrpc/debug.h — i.e., the SUNRPC/NFS debug header now pulls in trace_printk.h explicitly rather than transitively via kernel.h. (The series also touches drivers/infiniband/hw/hfi1/trace_dbg.h, but that is RDMA, not NFS.)

Discussion and reactions

  • Jani Nikula replied within ~25 minutes, acking only the i915 hunks: "For the i915 parts, Acked-by: Jani Nikula ... for merging via whichever tree." No NFS-specific discussion followed from the subsystem side; sunrpc/debug.h is a debug-only header, so the include addition is mechanically safe.

  • Nathan Chancellor reported at 23:42 UTC that patch 2/2 "breaks lib/test_context-analysis.c for me in several configurations," with three error: use of undeclared identifier '_THIS_IP_' failures coming through include/linux/local_lock_internal.h → lockdep.h. His proposed fix (diff omitted at ingest) restores the missing definition, and he asked: "should I send it as a separate patch or do you want to just fold it in with a note?"

    This is the key open item of the week: a build regression in lib/test_context-analysis.c caused by removing trace_printk.h from kernel.h, with a fix offered but not yet merged into the series. (Rostedt's reply, <20260626045119.659d1e6b@fedora>, and Nathan's follow-up land on 2026-06-26, just outside this window.)

Bottom line for NFS readers

No NFS client behavior changes: the only NFS-tree impact is include/linux/sunrpc/debug.h gaining an explicit #include <linux/trace_printk.h> so that SUNRPC debug code keeps compiling once kernel.h no longer drags in the header. The series itself is a tracing-infrastructure cleanup, and as of end-of-week it still carries one outstanding build fix from Nathan Chancellor awaiting Rostedt's decision on folding it into v5.
