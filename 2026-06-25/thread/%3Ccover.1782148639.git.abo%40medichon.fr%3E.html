Arnaud Bonnet submits pNFS bitop cleanup using clear_and_wake_up_bit

Summary

NFS client: pNFS bit-operation refactor via clear_and_wake_up_bit()

This week, Arnaud Bonnet posted a small two-patch series to the Linux NFS mailing list refactoring flag-handling code in the NFS and pNFS clients. The work is a cleanup/refactor rather than a new feature or protocol change — it consolidates a hand-rolled atomic bitops idiom onto an existing kernel helper, with no behavioral change intended.

The submission

The series was posted on 2026-06-22 as [PATCH 0/2] (cover letter), [PATCH 1/2], and [PATCH 2/2]. In the cover letter, Bonnet explains that several NFS functions perform the same three-step sequence when manipulating flags:

"clear_bit_unlock(); smp_mb__after_atomic(); wake_up_bit();"

He notes that this exact pattern now has a dedicated helper, clear_and_wake_up_bit(), introduced by commit 8236b0ae31c8 ("bdi: wake up concurrent wb_shutdown() callers.") and since adopted by several subsystems including VFS. The series aims to bring the NFS client into line with that effort:

"This function is already used in files such as nfs4state.c and pnfs_nfs.c and this serie aims to continue this effort, which also allows to remove some no longer used code."

Patch 1/2 — nfs_clear_invalid_mapping

PATCH 1/2 replaces the manual atomic bitops sequence in nfs_clear_invalid_mapping (in fs/nfs/inode.c) with the helper, a net change of 1 insertion and 3 deletions. Bonnet justifies it on the grounds that "inode.c already relies on functions from <linux/wait_bit.h>" and that this "homogenizes with other subsystems."

Patch 2/2 — pNFS helpers in pnfs.c

PATCH 2/2 targets fs/nfs/pnfs.c, where several local helpers contain identical clear-barrier-wake bodies. The patch substitutes the global helper, which "describes accurately its effects at the call and still specifies the cleared bit," and then deletes the now-unused local helpers — a net change of 10 insertions and 25 deletions across the file.

Testing

Bonnet reports validation on real hardware:

"Tested on x86 hardware using a loopback pNFS SCSI layout: doing image compression/decompression using xz and recompiling tinyconfig kernels on the remounted partition. No error reported under sanitizers."

Attribution and context

The work is credited as a beginner-oriented cleanup task, with Suggested-by: Agatha Isabelle Moreira <code@agatha.dev> and a link to the KernelNewbies "Beginner Cleanup and Refactor Tasks" list (task_007) on every patch. This places the series in the broader community effort of mentoring newcomers through low-risk refactoring that modernizes subsystem code against newly introduced core-kernel helpers.

Status at end of window

As of the close of this week's window, the thread contained only Bonnet's three-message submission — no reviewer or maintainer reply had yet landed on-list.
