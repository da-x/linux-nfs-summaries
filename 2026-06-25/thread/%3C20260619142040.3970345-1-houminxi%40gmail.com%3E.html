NFS pnfs Documentation Cleanup: Fixing Stale Layout Driver References

This week, a small but tidy documentation patch landed on the linux-nfs list, addressing long-standing staleness in the pNFS (parallel NFS) client documentation. The thread is quiet — just a single patch submission this week, with no replies yet within the reporting window.

The Patch

Minxi Hou submitted a one-file documentation fix to Documentation/filesystems/nfs/pnfs.rst on June 19. The patch addresses two specific stale references that had accumulated in the pNFS client documentation:

  1. Layout header list location: The docs still described the layout header list as living in struct nfs_client (field cl_layouts), but this was moved to struct nfs_server (field layouts) in commit 6382a44138e7 ("NFS: move pnfs layouts to nfs_server structure"). As Minxi noted:

    "The layout header list was moved from struct nfs_client (cl_layouts) to struct nfs_server (layouts) in commit 6382a44138e7, but the documentation was not updated."

  2. Layout driver count: The docs still listed four layout drivers, including the objects layout driver that was removed in commit 6d22323b2e9f ("nfs: remove the objlayout driver"). Minxi clarified the current state:

    "Also update the layout driver description to reflect that the objects layout driver was removed in commit 6d22323b2e9f, leaving 3 layout types implemented in the kernel client: files, blocks, and flexfiles."

Classification

This is a documentation bug fix — no code changes, no protocol changes, no new features. It corrects the pNFS client documentation to match the current state of the kernel source. The change is minimal (3 insertions, 3 deletions in one file) but important for anyone trying to understand the pNFS client architecture from the in-tree docs.

Context for NFS Client Development

The patch touches on two notable historical changes in the NFS/pNFS client:

  • Per-server vs. per-client layout tracking: The move of cl_layouts to nfs_server->layouts reflects an architectural shift where pNFS layout state is now tracked per mount (per nfs_server) rather than per client connection. This makes sense because layouts are associated with a specific export/mount point, not just the underlying server connection.

  • objlayout removal: The objects layout driver was one of the earliest pNFS layout types but saw limited real-world deployment. Its removal simplified the pNFS client codebase, leaving three actively maintained layout drivers: files (for object-based storage), blocks (for block devices), and flexfiles (the most feature-rich, supporting multiple data servers).
