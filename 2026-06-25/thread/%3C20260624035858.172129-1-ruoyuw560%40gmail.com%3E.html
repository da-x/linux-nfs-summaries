NFSv4: remove callback IDR entry on client allocation failure

This week's activity in this thread is limited to a single patch submission — there were no replies, reviews, or follow-ups within the reporting window. The thread therefore stands as a fresh bug-fix proposal awaiting maintainer attention.

Classification

This is a bug fix (not a new feature or protocol change). It addresses a lifetime/use-after-free hazard in the NFSv4 client's callback identifier bookkeeping, traced back to the original commit that introduced callback_ident support.

The submission

Ruoyu Wang posted a small, focused patch (3 files changed, 15 insertions, 1 deletion across fs/nfs/client.c, fs/nfs/internal.h, and fs/nfs/nfs4client.c) on Wednesday, June 24. The change makes the callback IDR removal helper callable from the allocation failure path so that a partially-initialized client does not leak a stale identifier entry.

Key technical argument

The patch's cover letter lays out a precise publish-before-free lifetime bug in nfs4_alloc_client():

"nfs4_alloc_client() allocates an NFSv4.0 callback identifier before it finishes setting up the client. If any later initialization step fails, the error path frees the nfs_client directly with nfs_free_client(). That bypasses nfs_put_client(), which is where the callback IDR entry is removed during normal teardown."

The consequence is a dangling pointer in the global cb_ident_idr map:

"A failed allocation can therefore leave cb_ident_idr pointing at a freed nfs_client. A later NFSv4.0 callback lookup by cb_ident would find the stale pointer and take a reference to it."

The proposed remedy is straightforward — route the failure path through the same IDR removal that normal teardown performs:

"Make the callback IDR removal helper callable by the allocation failure path, and remove the callback identifier before freeing the client."

Provenance and verification

Wang credits an automated tool for surfacing the issue, then confirms it manually — a combination worth noting for the credibility of the report:

"This was found by a local static-analysis checker for publish-before-free lifetime bugs and confirmed by manual inspection."

The patch carries a Fixes: tag pointing at the originating commit:

"Fixes: f4eecd5da342 ("NFS implement v4.0 callback_ident")"

Evolution and conclusions

Because no other messages landed in the window, there is no discussion evolution to track this week — the thread has just opened. The technical position is well-argued on its own terms: a classic asymmetric teardown bug where one error path skips a cleanup step that every other path performs, leaving a global ID map pointing at freed memory. The fix is minimal and surgical, consistent with how such lifetime bugs are typically resolved in the NFS client.

The outstanding question for the coming days is whether maintainers (Trond Myklebust / Anna Schumaker) will pick it up and merge it; as of this week's close, no acknowledgment has appeared on the list.
