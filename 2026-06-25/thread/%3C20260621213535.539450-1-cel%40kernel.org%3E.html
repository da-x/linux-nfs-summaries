NFSD: Replace isdotent() macro with VFS name_is_dot_dotdot() helper

Summary

NFSD: Replace isdotent() macro with VFS name_is_dot_dotdot() helper

Type: Code cleanup / minor robustness fix (not a new feature or protocol change) Status this week: Patch posted and quickly reviewed; ready for merge.

Overview

This week's activity in the thread was brief but clean: Chuck Lever posted a patch on Sunday, June 21 to retire nfsd's home-grown isdotent() macro in favor of the VFS's canonical name_is_dot_dotdot() helper, and Jeff Layton signed off with a Reviewed-by the following morning. No objections or design debate emerged — this is a straightforward deduplication patch that also tightens up an edge case.

Key technical arguments

Chuck Lever's cover message frames the change as both a de-duplication and a small safety improvement:

"The VFS provides name_is_dot_dotdot() as the canonical helper for recognizing the '.' and '..' directory entries, and fs/ already uses it widely. nfsd has instead carried its own open-coded isdotent() macro that computes the same predicate for non-empty names, a needless duplicate of shared functionality."

He then highlights the subtle robustness gain over the old macro:

"The macro reads the first name byte without first confirming the name is non-empty; name_is_dot_dotdot() tests the length first, so it never touches a zero-length buffer."

So while the patch is nominally a cleanup, it also removes a latent out-of-bounds read on a zero-length name by switching to a helper that length-checks before dereferencing.

Scope of the change

The patch touches seven files across the NFS server (fs/nfsd/), converting every isdotent() call site and deleting the macro definition:

  • nfs3proc.c, nfs3xdr.c — NFSv3 procedure and XDR paths
  • nfs4proc.c, nfs4xdr.c — NFSv4 procedure and XDR paths
  • nfsd.h — removal of the macro (3 lines)
  • nfsproc.c — NFSv2/legacy procedure path
  • vfs.c — VFS glue, with the most call sites (13 lines touched)

Net diff: 13 insertions, 15 deletions across 7 files.

Final conclusion

The change is a low-risk, mechanical refactor that aligns nfsd with the rest of fs/ on dot-entry detection and incidentally hardens the zero-length-name path. With Jeff Layton's Reviewed-by in hand, the patch is positioned for inclusion in the next merge window. No further discussion was needed this week.
