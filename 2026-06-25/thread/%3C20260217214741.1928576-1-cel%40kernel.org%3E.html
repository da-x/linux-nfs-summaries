Case Folding Exposure Series (v8) Applied to f2fs dev Tree

Summary

This week's single event in the long-running "Exposing case folding behavior" thread is a patchwork bot notification confirming that Chuck Lever's 17-patch v8 series was applied to jaegeuk/f2fs.git (dev branch) by Christian Brauner, VFS maintainer. The message, posted on June 24, marks the culmination of months of review and iteration on a feature that lets Linux filesystems report their case-sensitivity semantics to network file servers — a critical enabler for NFS client interoperability with Windows and macOS.

"This series was applied to jaegeuk/f2fs.git (dev) by Christian Brauner brauner@kernel.org" 178229157577.2577930.354083176752004996.git-patchwork-notify@kernel.org

Classification: New Feature / Protocol Enhancement (Now Merged)

This is a new feature that adds VFS-level case-folding introspection (fileattr_get with FS_XFLAG_CASEFOLD and FS_XFLAG_CASENONPRESERVING) and uses it to fix long-standing inaccuracies in how NFSD reports filesystem semantics to NFSv3 and NFSv4 clients. It is not a bug fix per se, though it corrects hard-coded assumptions that were effectively bugs for case-insensitive exports.

Background (Brief Bridge from Prior Weeks)

The series was submitted as v8 on February 17 by Chuck Lever 20260217214741.1928576-1-cel@kernel.org. Its motivation, as Lever explained at submission:

"The Linux NFS community has a growing interest in supporting NFS clients on Windows and MacOS platforms, where file name behavior does not align with traditional POSIX semantics."

Key NFS-relevant patches in the series:

  • Patch 11/17 — NFS client fileattr_get implementation, enabling re-export servers to propagate upstream case semantics.
  • Patches 15–16/17 — NFSD fixes: replacing a hard-coded MSDOS_SUPER_MAGIC check in NFSv3 PATHCONF and correcting NFSv4 responses that previously "hard-coded all exports as case-sensitive and case-preserving."

NFS Client Development Focus

The most significant patch for NFS client development is Patch 11/17: "nfs: Implement fileattr_get for case sensitivity." As Lever described at submission:

"An NFS server re-exporting an NFS mount point needs to report the case sensitivity behavior of the underlying filesystem to its clients. Without this, re-export servers cannot accurately convey case handling semantics, potentially causing client applications to make incorrect assumptions about filename collisions and lookups."

This patch exposes the case-sensitivity information that the NFS client already retrieves via PATHCONF (NFSv3) or FATTR4_CASE_INSENSITIVE/FATTR4_CASE_PRESERVING attributes (NFSv4) through the VFS fileattr_get interface. The practical impact:

  1. Re-export correctness: A Linux NFS server that re-exports an upstream NFS mount can now faithfully propagate the source filesystem's case semantics to its own clients, rather than defaulting to POSIX assumptions.
  2. Windows/macOS client interop: As Lever noted, "This client implementation explicitly requires servers to report FATTR4_WORD0_CASE_INSENSITIVE = TRUE for proper operation." With NFSD patches 15–16 now in the tree, that requirement can be met dynamically.
  3. Linux client optimization: Trond Myklebust's earlier work (merged ~4 years prior) already lets the Linux NFS client disable negative dentry caching and clear case-folded variants on directory change when it detects a case-insensitive share. Accurate server-side reporting makes those optimizations reliable.
