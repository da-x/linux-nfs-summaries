NFSD Per-Net Callback Ops – 0-DAY CI Reports Undefined Symbol Build Errors

Summary

NFSD Per-Net Namespace Callback Ops – Build Failure Reported by 0-DAY CI

Bridge to Prior Week

Last week, Dai Ngo submitted PATCH v3 1/1 to move accumulated NFSv4 callback operations from global static structures into per-network namespace storage (struct nfsd_net). This bug fix and container isolation improvement followed two earlier iterations, with v2 having been caught for a critical nrvers field initialization bug by Jeff Layton:

"sizeof(struct rpc_version *) is 8 on 64-bit, making nrvers 16 here while the nfsd_cb_versions array only has 2 elements."

Dai Ngo acknowledged and corrected the issue in v3. The patch was also aligned with Neil Brown's earlier recommendation to export per-net-namespace statistics rather than global ones:

"So I change my comment to: please don't do that. I don't think it is appropriate to export global statistics. We should only export per-net-namespace statistics."

This Week's Activity

This week saw a single message in the thread: an automated build failure report from the kernel test robot on February 27.

The 0-DAY CI report flagged two modpost undefined symbol errors when building against multiple trees (brauner-vfs/vfs.all, linus/master v7.0-rc1, and next-20260226) on a parisc-randconfig-002-20260227 configuration with hppa-linux-gcc (GCC) 8.5.0:

ERROR: modpost: "nfsd_net_cb_stats_shutdown" [fs/nfsd/nfsd.ko] undefined! ERROR: modpost: "nfsd_net_cb_stats_init" [fs/nfsd/nfsd.ko] undefined!

These errors indicate that the functions nfsd_net_cb_stats_init and nfsd_net_cb_stats_shutdown — which are referenced by the NFSD module (fs/nfsd/nfsd.ko) — are not being exported or defined in a way visible to the module build system. This is likely an issue with symbol visibility (e.g., missing EXPORT_SYMBOL_GPL or the functions being defined as static when they need to be accessible from another compilation unit).

The robot noted:

"If your patch is applied to the wrong git tree, kindly drop us a note."

However, since the failure also appeared on linus/master v7.0-rc1 and next-20260226, this appears to be a genuine build issue with the patch itself rather than a tree mismatch problem.

Technical Assessment

This is a build-time linkage bug introduced by the per-net namespace refactoring. The patch moves callback-related initialization and cleanup into per-network namespace operations, but the symbols for these functions are apparently not properly exported or visible to the module build system on certain architectures (at minimum, parisc). This would prevent the nfsd.ko kernel module from loading on affected configurations.

Current Status

As of the end of this reporting period (March 5, 2026), no response from Dai Ngo or any maintainer has been recorded in the thread. The patch requires a v4 to address the undefined symbol errors before it can be considered for inclusion.

Conclusion

The per-net namespace callback refactoring for NFSD — an important step toward full container isolation of NFS server state — encountered a build failure during automated testing. The fix will likely involve ensuring proper symbol export or visibility for nfsd_net_cb_stats_init and nfsd_net_cb_stats_shutdown. Once resolved, the patch should be ready for maintainer review.
