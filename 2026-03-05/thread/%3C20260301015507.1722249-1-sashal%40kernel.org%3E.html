SUNRPC gss_auth kref leak fix failed to apply to 5.15-stable

SUNRPC gss_auth kref Leak Fix Failed to Apply to 5.15-stable

Classification

Bug fix backport failure. This thread concerns a memory/resource leak in the NFS/SUNRPC client's GSS authentication subsystem, specifically within net/sunrpc/auth_gss/auth_gss.c. The discussion is limited to a notification from the stable tree maintainers that an upstream fix could not be automatically applied to the 5.15 long-term support (LTS) kernel.

Summary

On March 1st, Sasha Levin notified the community that a critical bug fix for a reference count leak in the SUNRPC GSS authentication code failed to apply cleanly to the 5.15-stable tree.

The original patch, authored by Daniel Hodges and merged into Linus Torvalds's mainline tree, addressed a resource leak introduced by a previous commit (5940d1cf9f42, "SUNRPC: Rebalance a kref in auth_gss.c"). That prior commit added a kref_get(&gss_auth->kref) call to balance a reference release in gss_release_msg(), but inadvertently omitted the corresponding kref_put() on an error path.

As described in the patch details:

"If service_name is non-NULL and kstrdup_const() fails, the function jumps to err_put_pipe_version which calls put_pipe_version() and kfree(gss_msg), but never releases the gss_auth reference. This leads to a kref leak where the gss_auth structure is never freed."

The fix adds a forward declaration for gss_free_callback() and invokes kref_put() in the err_put_pipe_version error path to properly release the reference.

Evolution of Discussion

This thread consists of a single message from Sasha Levin announcing the failure. There were no replies, discussions, or alternative patches submitted within this week's window.

Sasha Levin explicitly requested community assistance for manual backporting:

"If someone wants it applied there, or to any other stable or longterm tree, then please email the backport, including the original git commit id to stable@vger.kernel.org."

Final Conclusions

  • Status: The patch has not been applied to the 5.15-stable tree as of this week.
  • Action Required: A developer (likely from the NFS/SUNRPC client team or a maintainer of the 5.15 LTS tree) needs to manually backport the fix and submit it to the stable mailing list.
  • Impact: Systems running 5.15-stable with GSS authentication enabled are potentially subject to a gss_auth structure leak if the specific error condition (failure of kstrdup_const() when service_name is non-NULL) is triggered.

This highlights an ongoing maintenance challenge for LTS kernels, where upstream fixes may require manual intervention due to code divergence over time.
