pNFS: Fix race condition in SCSI PR registration causing reservation conflicts

Summary

pNFS: Serializing SCSI PR Registration to Eliminate Reservation Conflicts

This week, a critical bug fix for the Parallel NFS (pNFS) block layout driver was discussed and reviewed. The patch addresses a race condition in SCSI Persistent Reservation (PR) registration that could lead to I/O failures when multiple threads access the same storage device concurrently.

The Problem: A Race Condition in Registration

Dai Ngo from Oracle submitted PATCH v2 1/1, which identifies a subtle but impactful concurrency bug in the NFS client's handling of SCSI layouts.

The core issue lies in the timing of flag updates versus actual hardware operations:

"Currently, bl_register_scsi() sets PNFS_BDEV_REGISTERED before performing the PR operation. If multiple threads concurrently start I/O to the same SCSI device, the first thread sets the flag and begins registration, while other threads observe the flag, skip registration, and proceed to issue I/O."

When these premature I/O requests reach the data server, they encounter RESERVATION CONFLICT errors because the Persistent Reservation has not yet been established. This forces the client to fall back to the Metadata Server (MDS), degrading performance and potentially causing application-level timeouts.

The Solution: Mutex-Protected Serialization

The proposed fix introduces a mutex (pbd_registration_mutex) to serialize both registration and unregistration operations:

"Protect the registration/unregistration operation path with a mutex so only one thread performs the op at a time. Other threads wait for the operation to finish and only then and only then re-check PNFS_BDEV_REGISTERED flag."

This ensures that:

  1. Only one thread initiates the PR registration at any given time.
  2. All other threads block until the operation completes.
  3. Threads re-verify the PNFS_BDEV_REGISTERED flag after waking, ensuring they do not proceed with I/O until the reservation is truly active.

Review Feedback: Simplification Suggestion

Christoph Hellwig reviewed the patch and provided a minor code quality suggestion:

"dev->flags can now become a simple unsigned int, and you can define PNFS_BDEV_REGISTERED as an actual value instead of using BIT everywhere."

Hellwig noted that with the mutex protecting access to the flag, atomic bit operations are no longer strictly necessary. This simplification would improve code readability without affecting correctness. He concluded:

"Otherwise this looks good."

Classification and Impact

  • Type: Bug fix (concurrency/race condition)
  • Subsystem: NFS client, specifically the pNFS block layout driver (fs/nfs/blocklayout/)
  • Impact: Prevents RESERVATION CONFLICT errors during concurrent I/O initialization on SCSI-backed pNFS storage, improving reliability and reducing unnecessary fallbacks to the MDS.

The patch is in its second version, with changes from v1 including renaming the mutex for clarity, adding documentation, and extending protection to unregistration operations as well.
