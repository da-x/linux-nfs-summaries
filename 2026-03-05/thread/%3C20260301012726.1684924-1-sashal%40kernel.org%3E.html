SUNRPC GSS Auth kref Leak Patch Failed to Apply to 6.12-Stable

Summary

SUNRPC GSS Auth kref Leak Backport Failure

Classification

Bug Fix / Stable Tree Maintenance

This thread is not a technical discussion but an automated notification from the stable kernel tree maintainers regarding a failed patch application. The underlying issue concerns a bug fix for a reference count leak in the NFS/SUNRPC client's GSS authentication subsystem.

Summary of Activity

On March 1, Sasha Levin reported that a critical bug fix patch, originally authored by Daniel Hodges and merged into Linus Torvalds's mainline tree, failed to apply cleanly to the 6.12-stable tree.

The original commit (dd2fdc350459) addressed a resource leak in net/sunrpc/auth_gss/auth_gss.c. As described in the patch notes:

"Commit 5940d1cf9f42 ("SUNRPC: Rebalance a kref in auth_gss.c") added a kref_get(&gss_auth->kref) call to balance the gss_put_auth() done in gss_release_msg(), but forgot to add a corresponding kref_put() on the error path when kstrdup_const() fails."

The bug manifested when service_name was non-NULL and kstrdup_const() failed. The code would jump to an error label (err_put_pipe_version) that freed local memory but neglected to release the gss_auth reference, leading to a memory leak where the structure was never freed.

Sasha Levin's notification served as a call for action:

"If someone wants it applied there, or to any other stable or longterm tree, then please email the backport, including the original git commit id to stable@vger.kernel.org."

Evolution and Conclusions

There were no replies to this message within the reporting window. The thread remains open in the sense that the patch has not yet been successfully backported to the 6.12-stable tree.

Key Takeaway for NFS Client Development: This highlights the ongoing maintenance burden of the SUNRPC subsystem, particularly around reference counting in error paths—a common source of subtle memory leaks. The fix itself is straightforward (adding a kref_put() and a forward declaration for gss_free_callback()), but its failure to apply automatically suggests that the 6.12-stable tree has diverged sufficiently from mainline that manual intervention by a maintainer or contributor is required to create a clean backport.

No further technical debate occurred this week; the resolution depends on a developer submitting a manually adjusted patch to the stable mailing list.
