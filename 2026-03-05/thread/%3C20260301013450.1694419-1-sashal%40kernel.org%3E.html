nfsd: Stable Backport Failure for ID Mapping Error Code Fix

Overview

This week, the Linux NFS mailing list received a notification from stable tree maintainer Sasha Levin regarding a failed backport attempt of an important NFS server (nfsd) bug fix to the 6.6-stable kernel tree. The discussion centers on a patch that corrects error handling in NFSv4 ID mapping operations, specifically addressing how timeout errors during userspace upcalls are propagated to clients.

Technical Context: The Bug Fix

The original patch, authored by Anthony Iliopoulos and merged into Linus Torvalds' mainline tree, addresses a subtle but impactful bug in the NFS server's identity mapping subsystem. As described in the commit message:

"idmap lookups can time out while the cache is waiting for a userspace upcall reply. In that case cache_check() returns -ETIMEDOUT to callers."

The problem was that nfsd_map_name_to_[ug]id functions would continue processing—attempting to map IDs to kernel user/group IDs (kuids)—even after receiving a temporary -ETIMEDOUT failure from the ID mapping cache. This resulted in the server returning NFSERR_BADOWNER to clients, causing operations to fail permanently rather than allowing for retry.

The fix ensures that when an ID mapping lookup times out, the server returns NFSERR_JUKEBOX instead:

"This will return NFSERR_JUKEBOX on idmap lookup timeout so that clients can retry the operation instead of aborting it."

This is a significant improvement for NFS client reliability, as NFSERR_JUKEBOX signals a transient condition that clients should handle by retrying, whereas NFSERR_BADOWNER indicates a permanent error. The patch fixes an issue introduced in commit 65e10f6d0ab0 ("nfsd: Convert idmap to use kuids and kgids").

Stable Tree Backport Failure

On March 1st, Sasha Levin notified the community that the patch failed to apply cleanly to the 6.6-stable tree:

"The patch below does not apply to the 6.6-stable tree. If someone wants it applied there, or to any other stable or longterm tree, then please email the backport, including the original git commit id to stable@vger.kernel.org."

This is a common occurrence in kernel development, where patches that apply cleanly to mainline may conflict with code changes already present in older stable branches. The 6.6-stable tree represents a long-term support (LTS) kernel version widely deployed in production environments, making successful backports critical for security and stability.

Conclusion

As of the end of this week's window, no backport patch had been submitted to resolve the application failure. The ball is now in the court of the original author or maintainers to prepare a rebased version of the fix suitable for the 6.6-stable tree. Given the importance of proper error handling in NFS ID mapping—particularly for environments relying on userspace name-to-ID translation services like NSSwitch or LDAP—this fix warrants attention from stable tree maintainers and system administrators awaiting its inclusion in LTS kernels.

This thread represents a bug fix rather than a new feature or protocol change, focusing on correcting error code propagation in the NFS server's identity mapping subsystem to improve client-side retry behavior during transient failures.
