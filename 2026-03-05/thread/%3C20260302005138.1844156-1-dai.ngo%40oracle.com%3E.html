pNFS: Serializing SCSI PR Registration to Prevent Reservation Conflicts

Summary

This week, a critical bug fix for the pNFS block layout client was proposed and reviewed. The patch addresses a race condition in SCSI Persistent Reservation (PR) registration that could lead to I/O failures under concurrent load.

The Bug: Race Condition in PR Registration

Dai Ngo from Oracle identified an issue where multiple threads initiating I/O to the same SCSI device via pNFS could trigger reservation conflicts. Currently, the function bl_register_scsi() sets the PNFS_BDEV_REGISTERED flag before completing the actual PR operation. If multiple threads start concurrently:

  1. The first thread sets the flag and begins registration.
  2. Other threads see the flag is set, skip registration, and immediately proceed to issue I/O.
  3. Since the PR registration isn't complete, these early I/Os hit RESERVATION CONFLICT, forcing a fallback to the Metadata Server (MDS).

As Dai explained in the patch submission:

"Protect the registration path with a mutex so only one thread performs PR registration at a time. Other threads wait for registration to finish and only then re-check PNFS_BDEV_REGISTERED, ensuring no I/O is issued until PR registration is complete."

He provided a specific fio workload capable of reproducing the issue, involving multiple jobs with high I/O depth to saturate bandwidth and trigger parallel Data Server connections.

Review and Refinement

Christoph Hellwig reviewed the patch and suggested improvements for code consistency and clarity:

  1. Naming and Placement: He requested moving the new mutex field up in the structure definition (away from function pointers) and renaming it to pbd_registration_mutex with a descriptive comment.
  2. Symmetry and Locking Scheme: Christoph pointed out that the patch only protected registration, not unregistration. He argued for fully protecting both paths:

    "This seems to only lock the registration side, and not the unregistration side, which is a bit odd. If you fully protect register/unregister we also don't need atomic bitops for PNFS_BDEV_REGISTERED and have a more consistent locking scheme."

Dai initially resisted adding the mutex to unregistration, arguing that it occurs during unmount where races are unlikely and harmless:

"The reason I did not use the mutex on unregistration is because unregistration happens when the export is unmounted and I don't see any race condition can happen at that time. Besides, even if there is race condition on the unregistration the consequence is a duplicate SCSI PR unregistration which is harmless."

However, he acknowledged that adding it would make the code symmetric. Dai also questioned whether the PNFS_BDEV_REGISTERED bit was still necessary if both paths were mutex-protected:

"Even we fully protect register/unregister don't we still need the PNFS_BDEV_REGISTERED bit so the others thread can check and skip the register/unregister op?"

Christoph clarified that while the bit is still needed for threads to quickly determine if registration has occurred, it no longer requires atomic bit operations if the mutex protects the state changes:

"Yes, but it doesn't need to use the atomic bit ops."

Testing Infrastructure Discussion

The inclusion of a fio test case sparked a brief discussion on integrating such tests into the NFS development workflow. Christoph expressed interest in wiring up such tests:

"I wish we could wire this up somewhere. Not sure what the right place for these kinds of nfs tests are, though."

Chuck Lever noted that he had previously added pNFS with iSCSI testing workflows to kdevops, including fstests and other suites, but has struggled to find resources to integrate them into the main NFSD test matrix.

Conclusion

The discussion concluded with Dai agreeing to prepare a v2 of the patch incorporating Christoph's suggestions:

  • Renaming the mutex to pbd_registration_mutex.
  • Adding a descriptive comment.
  • Moving the mutex field in the structure.
  • Extending the mutex protection to cover unregistration for symmetry and consistent locking, thereby allowing the removal of atomic bit operations for PNFS_BDEV_REGISTERED.

This fix is crucial for NFS client stability in high-concurrency pNFS environments using SCSI layouts, preventing unnecessary fallbacks to the MDS and potential performance degradation.
