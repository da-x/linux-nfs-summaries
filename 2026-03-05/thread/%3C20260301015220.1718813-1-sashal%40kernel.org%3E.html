nfsd: Stable Backport Failure for ID Mapping Timeout Fix

Overview

This thread consists of a single automated notification from the stable kernel maintainers indicating that an important bug fix for the NFS server (nfsd) failed to apply cleanly to the 5.15-stable tree. The discussion is centered on a bug fix related to how nfsd handles timeouts during ID mapping lookups, rather than a new feature or protocol change.

Technical Context

The patch in question, originally authored by Anthony Iliopoulos and merged into Linus Torvalds's mainline tree, addresses a subtle but impactful bug in the NFS server's identity mapping subsystem. As described in the original commit message:

"idmap lookups can time out while the cache is waiting for a userspace upcall reply. In that case cache_check() returns -ETIMEDOUT to callers."

The problem was that when such timeouts occurred, the nfsd_map_name_to_[ug]id functions would continue attempting to map the ID to a kuid despite the temporary failure, ultimately returning NFSERR_BADOWNER to clients. This caused client operations to fail outright rather than being retried.

The fix ensures that the timeout error is returned early, resulting in:

"This will return NFSERR_JUKEBOX on idmap lookup timeout so that clients can retry the operation instead of aborting it."

This is significant for NFS client development because NFSERR_JUKEBOX is a transient error code that signals to clients that the operation may succeed upon retry, whereas NFSERR_BADOWNER is treated as a hard failure. The patch fixes commit 65e10f6d0ab0 ("nfsd: Convert idmap to use kuids and kgids") and was reviewed by NeilBrown before being signed off by Chuck Lever.

Stable Tree Backport Status

Sasha Levin, the stable tree maintainer, reported on March 1st:

"The patch below does not apply to the 5.15-stable tree. If someone wants it applied there, or to any other stable or longterm tree, then please email the backport, including the original git commit id to stable@vger.kernel.org."

This indicates that while the fix is deemed important enough for stable consideration (it carries a Cc: stable@vger.kernel.org tag), it requires manual intervention to backport due to API or code structure differences in the 5.15 long-term support branch. No further discussion occurred within this week's window; the ball is effectively in the court of the patch author or maintainers to provide a rebased version for the stable tree.

Conclusion

This thread highlights an important bug fix in nfsd's error handling path for ID mapping timeouts. The fix improves client experience by ensuring retryable errors are properly signaled rather than causing hard failures. However, the backport to the widely-used 5.15-stable tree remains pending manual resolution.
