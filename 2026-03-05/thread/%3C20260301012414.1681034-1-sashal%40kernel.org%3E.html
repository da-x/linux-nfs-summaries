SUNRPC auth_gss Memory Leak Fix Backport Failure Notification

Summary

SUNRPC: auth_gss Memory Leak Fix Failed to Apply to 6.12-stable

Classification

Bug fix backport notification. This thread is a procedural notice from the stable tree maintainers regarding a failed patch application, rather than a technical discussion. The underlying issue addresses critical memory leaks in the NFS client's RPC security (RPCSEC_GSS) subsystem.

Summary of Activity

This week, Sasha Levin notified the community that a significant bug fix for the SUNRPC subsystem failed to automatically apply to the 6.12-stable tree.

The patch in question, originally authored by Chuck Lever and merged into Linus Torvalds' mainline tree, addresses memory leaks in the XDR (External Data Representation) decoding error paths within auth_gss. Specifically, it targets functions gssx_dec_ctx(), gssx_dec_status(), and gssx_dec_name().

The Underlying Bug

The original commit 3e6397b05633 highlights a critical resource management flaw:

"The gssx_dec_ctx(), gssx_dec_status(), and gssx_dec_name() functions allocate memory via gssx_dec_buffer(), which calls kmemdup(). When a subsequent decode operation fails, these functions return immediately without freeing previously allocated buffers, causing memory leaks."

The leak is particularly severe in gssx_dec_ctx() because the caller initializes buffer length fields to non-zero values before decoding. If a partial failure occurs (e.g., source name decodes successfully but target name fails), the memory for the successful parts remains unreferenced and cannot be reclaimed.

Current Status

Sasha Levin's notification indicates that manual intervention is required:

"If someone wants it applied there, or to any other stable or longterm tree, then please email the backport, including the original git commit id to stable@vger.kernel.org."

As of this week's window, no backport patch has been submitted or discussed in this thread. The resolution depends on a maintainer or developer providing a manually adjusted patch that applies cleanly to the 6.12-stable codebase.

Key Technical Context

  • Subsystem: SUNRPC / NFS Client Security (RPCSEC_GSS)
  • Issue Type: Memory Leak (Resource Exhaustion potential)
  • Root Cause: Missing cleanup in error paths of XDR decoding functions.
  • Fix Strategy: Implementation of goto-based cleanup to free allocated buffers before returning errors.
  • Stability Impact: High, as memory leaks in kernel space can lead to denial-of-service conditions over time, especially under high-load NFS security contexts.

Conclusion

The thread serves as a call for action rather than a concluded discussion. The critical bug fix for auth_gss memory leaks has been identified and merged upstream, but its propagation to the 6.12-stable tree is currently stalled due to application conflicts. Developers interested in this fix for stable kernels are urged to provide a backported patch.
