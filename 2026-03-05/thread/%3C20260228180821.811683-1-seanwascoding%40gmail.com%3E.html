SUNRPC Debug Macro Cleanup and NFSd Build Fixes

Summary

This week's thread continues the ongoing effort to stabilize NFS and SUNRPC builds by fixing compiler warnings and errors. Sean Chang submitted PATCH v5 0/2, following up on previous discussions about replacing empty debug stubs with no_printk() to silence -Wunused-variable warnings while preserving type checking.

SUNRPC Macro Refactoring and NFSd Build Fix

The first patch simplifies the dfprintk macros by removing redundant format arguments and using no_printk(__VA_ARGS__) directly, as previously suggested by David Laight. This change ensures variables used for debugging are type-checked even when CONFIG_SUNRPC_DEBUG is disabled. Additionally, the patch addresses a build error in fs/nfsd/nfsfh.c reported by syzbot, where a conditionally defined variable was referenced in an unguarded debug print.

Geert Uytterhoeven noted that similar issues had been addressed in prior attempts:

"This should have been fixed alteady, cfr. 'Re: [PATCH v3 0/3] sunrpc: Fix make W=1 build issues'?"

Sean Chang responded by highlighting the improvements in his subsequent v6 series, which further refines the approach by relying on compiler optimization (-O2) to eliminate unreachable branches rather than using explicit IS_ENABLED() checks or #if guards. This aligns with Andrew Lunn's earlier advice to minimize conditional compilation:

"In v6, we don't need explicit IS_ENABLED(CONFIG_SUNRPC_DEBUG) checks... With -O2, the compiler already proves these branches are unreachable and optimizes them away automatically."

Andy Shevchenko, brought into the discussion, directed Sean to synchronize with recent upstream changes:

"Recently Chuck updated his nfsd-next, so please rebase and resend, Cc'ing me."

MACB Driver Warning Fix

The second patch addresses a stringop-truncation warning in the MACB ethernet driver on RISC-V toolchains by adopting the modern ethtool_sprintf() API. Andy Shevchenko reviewed this patch positively but suggested decoupling it from the SUNRPC fixes:

"This can go separately from patch 1. Dunno why this is a series... And this one LGTM"

Conclusion

The discussion concludes with actionable feedback for the maintainer: rebase the SUNRPC fixes against the latest nfsd-next tree and consider submitting the MACB fix as an independent patch. The core technical achievement is the stabilization of NFS-related build configurations by modernizing debug macros to prevent both warnings and fatal errors in non-debug builds, leveraging compiler optimizations to reduce code complexity.
