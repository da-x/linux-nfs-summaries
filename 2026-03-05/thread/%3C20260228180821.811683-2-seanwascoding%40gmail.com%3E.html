Summary

lockd Build Errors Exposed by SUNRPC Debug Macro Cleanup

This week's activity on the thread concerning Sean Chang's [PATCH v5 1/2] sunrpc: simplify dfprintk macros and fix nfsd build error consists entirely of automated build failure reports from the kernel test robot. The patch series, which aims to modernize SUNRPC debug macros using no_printk() for type checking while disabling CONFIG_SUNRPC_DEBUG, has triggered latent build errors in the NFS lock manager (lockd) subsystem.

Build Failures in fs/lockd/svclock.c

The kernel test robot reported consistent build failures across multiple configurations, highlighting an implicit declaration of nlmdbg_cookie2a and associated format string mismatches in fs/lockd/svclock.c. The issue manifests in two functions: nlmsvc_lookup_block() and nlmsvc_find_block().

In the first report using gcc-14 on i386-randconfig, the robot noted:

"fs/lockd/svclock.c:163:33: error: implicit declaration of function 'nlmdbg_cookie2a' [-Wimplicit-function-declaration]"

A subsequent report with the same configuration reiterated the error, emphasizing that nlmdbg_cookie2a returns an int but is used in a format string expecting char *:

"warning: format '%s' expects argument of type 'char *', but argument 7 has type 'int' [-Wformat=]"

A third report using clang version 20.1.8 confirmed the issue with stricter C99 compliance:

"fs/lockd/svclock.c:163:5: error: call to undeclared function 'nlmdbg_cookie2a'; ISO C99 and later do not support implicit function declarations [-Wimplicit-function-declaration]"

Technical Analysis

The errors originate from the following code pattern in fs/lockd/svclock.c:

dprintk("lockd: check f=%p pd=%d %Ld-%Ld ty=%d cookie=%s\n",
        block->b_file, fl->c.flc_pid,
        (long long)fl->fl_start,
        (long long)fl->fl_end, fl->c.flc_type,
        nlmdbg_cookie2a(&block->b_call->a_args.cookie));

The function nlmdbg_cookie2a appears to be either missing from the current build configuration or not properly declared when CONFIG_SUNRPC_DEBUG is disabled. Sean Chang's patch simplifies the dfprintk macros, but this change has exposed pre-existing issues in lockd where debug helper functions are not guarded appropriately.

Status

As of this week's window, no human responses have been recorded in this thread. The kernel test robot's reports serve as a critical signal that Sean Chang's patch series requires additional fixes to address the lockd build errors before merging. The maintainer will need to either:

  1. Ensure nlmdbg_cookie2a is properly declared or stubbed when debugging is disabled, or
  2. Guard the affected dprintk() calls in fs/lockd/svclock.c appropriately.

This bug fix thread underscores the importance of comprehensive build testing across multiple configurations, as changes to shared debug infrastructure can expose latent issues in disparate subsystems like NFS lock management.
