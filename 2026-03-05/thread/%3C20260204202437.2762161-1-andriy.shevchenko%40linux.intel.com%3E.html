sunrpc: make W=1 build fixes promoted to nfsd-next and linux-next

Summary

sunrpc/NFS: make W=1 Build Fixes Promoted to Integration Trees

Classification

This thread concerns bug fixes focused on build hygiene — specifically, resolving compiler warnings that surface when building the kernel with make W=1 (warnings-as-errors mode). The changes affect the sunrpc debug infrastructure and the NFS blocklayout driver, impacting both NFS client and server codepaths.

Background (Prior Weeks)

In early February, Andy Shevchenko submitted a three-patch series to address Clang compiler errors triggered by unused variables in the NFS blocklayout driver and sunrpc debug macros when dprintk() is compiled as a no-op. The series was applied to nfsd-testing on February 4th, and LKP automated testing confirmed no regressions. See prior summaries for details on the patch content.

This Week's Activity: Promotion to Integration Trees

This week's discussion centered on the promotion of these build fixes from the short-lived nfsd-testing tree to the longer-lived integration trees (nfsd-next and subsequently linux-next).

Inquiry About Timeline

On February 28th, Andy Shevchenko followed up on the status of the patches after receiving positive LKP results:

Promotion to nfsd-next

Chuck Lever responded promptly, confirming that the patches had been applied to the nfsd-next tree:

"Applied to nfsd-next just now. Should appear in linux-next the next time nfsd-next is pulled (Sunday night US/Eastern, maybe?)" As confirmed by Chuck Lever

Confirmation of linux-next Inclusion

On March 2nd, Shevchenko verified that the patches had indeed appeared in linux-next:

"Yep, I think it will be in today's Linux Next, thank you!" As confirmed by Andy Shevchenko

Significance for NFS Client Development

While this series does not introduce new NFS protocol features or fix runtime bugs, it is important for maintaining build robustness. The three patches address:

  1. NFS Blocklayout: Removal of an unused-but-set variable count in bl_write_pagelist(), which Clang flagged as an error under -Werror,-Wunused-but-set-variable.
  2. sunrpc Debug Infrastructure: Elimination of the RPC_IFDEBUG() macro, simplifying debug code paths.
  3. Debug Logging Safety: Forwarding dprintk() parameters to no_printk() when debugging is disabled, which also enables format-string checking even in non-debug builds — a side-effect Shevchenko noted as beneficial for catching latent logging bugs.

The successful promotion through the integration pipeline (nfsd-testing → nfsd-next → linux-next) demonstrates the standard workflow for NFS subsystem patches and ensures these build hygiene improvements will be available for wider kernel testing before entering the mainline tree.
