SUNRPC GSS Auth kref Leak Fix Backport Failure on 5.10-Stable

Summary

SUNRPC GSS Auth kref Leak Fix Failed to Apply to 5.10-Stable Tree

Classification

Bug fix backport notification. This thread concerns the failure of an important memory leak fix in the SUNRPC subsystem to automatically apply to the Linux 5.10 stable tree.

Summary

This week, Sasha Levin notified the community that a critical bug fix for the SUNRPC Generic Security Services (GSS) authentication module failed to apply cleanly to the 5.10-stable kernel tree. The patch in question addresses a reference counting leak in gss_alloc_msg(), which could lead to memory exhaustion in systems using Kerberos or other GSS-based NFS authentication.

The Original Bug Fix

The underlying fix was authored by Daniel Hodges and merged into Linus Torvalds's mainline tree. As described in the original commit:

"Commit 5940d1cf9f42 ("SUNRPC: Rebalance a kref in auth_gss.c") added a kref_get(&gss_auth->kref) call to balance the gss_put_auth() done in gss_release_msg(), but forgot to add a corresponding kref_put() on the error path when kstrdup_const() fails."

The bug manifests when service_name is non-NULL and kstrdup_const() fails during message allocation. In this error scenario, the code jumps to err_put_pipe_version, which calls put_pipe_version() and kfree(gss_msg), but never releases the gss_auth reference. This results in a kref leak where the gss_auth structure is never freed, potentially causing memory exhaustion over time for NFS clients using GSS authentication.

Backport Failure Notification

Sasha Levin's notification on March 1 states:

"The patch below does not apply to the 5.10-stable tree. If someone wants it applied there, or to any other stable or longterm tree, then please email the backport, including the original git commit id to stable@vger.kernel.org."

This is a routine but important notification in the stable kernel maintenance process. The 5.10 series is a long-term support (LTS) kernel widely deployed in production environments, making it essential that security and stability fixes reach these trees.

Significance for NFS Client Development

This fix is particularly relevant to NFS client deployments using Kerberos-based authentication (RPCSEC_GSS). The leak occurs in the error path of message allocation, meaning it would only trigger under memory pressure conditions — precisely when system stability is most critical. For enterprise NFS deployments relying on GSS authentication, this represents a latent reliability issue that could manifest as gradual memory consumption over extended operation periods.

Conclusion

No backport was submitted during this week's window. The patch remains pending manual backporting to the 5.10-stable tree (and potentially other LTS trees). Maintainers or developers interested in seeing this fix applied to stable kernels are encouraged to prepare and submit a rebased patch to stable@vger.kernel.org, as requested by Sasha Levin.

The original commit (dd2fdc350459) is available in mainline, and the fix itself is straightforward: adding a kref_put() call in the error path to properly release the reference taken earlier in gss_alloc_msg().
