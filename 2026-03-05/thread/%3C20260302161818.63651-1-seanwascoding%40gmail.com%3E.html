sunrpc: Simplify dprintk macros and clean up redundant debug guards

Summary

This week saw a cleanup effort in the SunRPC subsystem aimed at simplifying debug printing macros and removing redundant configuration guards. The discussion was brief, consisting of an initial patch submission and a single review response.

Technical Overview: Macro Simplification and Dead Code Elimination

Sean Chang submitted a patch to simplify the dprintk macro definitions within the SunRPC debug infrastructure. The primary goal was to remove unnecessary arguments and consolidate the macro definition to be "more idiomatic."

The core technical argument relied on the compiler's ability to perform dead code elimination. Chang explained that by using no_printk(__VA_ARGS__) directly, the compiler could still perform type checking and "see" the variables, thereby silencing warnings without emitting any executable code. He noted:

"Verification with .lst files under -O2 confirms that the compiler successfully performs 'dead code elimination'. Even when variables (like char buf[] in nfsfh.c) or static helper functions (like nlmdbg_cookie2a in svclock.c) are declared without #ifdef, they are completely optimized out (no stack allocation, no symbol references in the final executable) as they are only referenced within no_printk()."

This approach allowed for the removal of several #if IS_ENABLED(CONFIG_SUNRPC_DEBUG) guards in files such as fs/nfsd/nfsfh.c, net/sunrpc/xprtrdma/svc_rdma_transport.c, and fs/lockd/svclock.c.

Review Feedback: Redundancy and Style

Andy Shevchenko reviewed the patch, questioning some of the premises in the commit message. He pointed out that type checking was already occurring with the existing code structure:

"This is already the case with the current code."

He further questioned whether the variable visibility issue was truly a new problem:

"Also, isn't it the current state of affairs?"

Shevchenko also critiqued the verbosity of the commit message, suggesting that the list of changes was redundant since they were visible in the diff:

"Isn't this list redundant in the commit message? We can see this from the code without much brain used."

Additionally, he provided a style correction regarding variable declaration order in svc_rdma_transport.c, requesting adherence to the "reversed xmas tree order" for local variables.

Conclusion and Status

The discussion concluded with Shevchenko noting that while squashing this cleanup into his previous patch would have been ideal, it was likely not feasible given the patch's inclusion in nfsd-next. He offered his feedback as "just my 2c," leaving the final decision to the maintainers.

This thread represents a minor code quality improvement rather than a functional bug fix or new feature, focusing on reducing code complexity and leveraging compiler optimizations for debug code paths.
