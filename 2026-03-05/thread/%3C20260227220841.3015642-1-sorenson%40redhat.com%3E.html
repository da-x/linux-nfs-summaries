Summary

nfsdclnts: Fix crash when kernel omits superblock in stateid display

Overview

This week saw a single-message patch submission addressing a bug fix in nfsdclnts, the userspace tool used to inspect NFS server client state. The patch resolves a crash that occurs when the kernel does not provide superblock information for certain stateids.

Technical Details

The issue was reported and fixed by Frank Sorenson of Red Hat in a single patch submission on February 27, 2026.

The Bug

When nfsdclnts reads the /proc/fs/nfsd/clients/<client>/states procfile, it parses stateid entries that may include superblock and filename information. However, as Sorenson explains:

"If the stateid's file can't be found, the kernel will skip printing the superblock and filename in the 'states' procfile."

When this occurs — i.e., when the kernel cannot locate the file associated with a stateid — it omits the superblock key from the output. The existing nfsdclnts code did not handle this absence gracefully, leading to a crash:

"nfsdclnts crashes trying to reference the non-existent superblock key while getting the inode."

The Fix

The patch applies a straightforward defensive fix consistent with how other optional fields are handled in the tool. Sorenson's solution sets the inode field to 'N/A' when the superblock is not present:

"Fix this by setting the inode field to 'N/A' when the superblock isn't present, as is done with other fields which may be missing."

The change touches a single file (tools/nfsdclnts/nfsdclnts.py) with 4 insertions and 1 deletion, making it a minimal, targeted correction.

Classification

  • Type: Bug fix
  • Component: NFS server userspace tools (nfsdclnts)
  • Impact: Prevents a crash when inspecting client state on systems where some stateids reference files the kernel cannot resolve (e.g., deleted or inaccessible files).

Conclusion

This is a clean, well-scoped bug fix that improves the robustness of nfsdclnts as a diagnostic tool. By handling missing superblock data gracefully — mirroring the treatment of other optional fields — the patch ensures that administrators can inspect NFS client state without encountering crashes due to edge-case kernel behavior. No further discussion occurred within this week's window; the patch stands as a standalone fix.
