sunrpc: Fix unused variable warnings with no_printk and cleanup RPC_IFDEBUG

Summary

This thread discusses a patch series by Sean Chang aimed at fixing compiler warnings for RISC-V builds, specifically focusing on the NFS client and SunRPC subsystems. The discussion centers on [PATCH v4 1/2], which addresses -Wunused-variable warnings in sunrpc when CONFIG_SUNRPC_DEBUG is disabled.

Technical Arguments and Evolution

Initial Proposal: Sean Chang proposed replacing empty do {} while (0) stubs for dfprintk() macros with no_printk(). This allows the compiler to perform type checking on arguments without generating code, thereby silencing unused variable warnings globally rather than marking individual variables as __maybe_unused.

"Instead of marking every affected variable with __maybe_unused, update the dfprintk and dfprintk_rcu stubs to use no_printk(). This allows the compiler to see the variables and perform type checking without emitting any code, thus silencing the warnings globally for these macros." — Sean Chang

The patch received immediate positive feedback:

"Seems obviously good to me." — Chuck Lever

Macro Simplification Debate: David Laight suggested simplifying the macro definition by removing the explicit fmt argument and the ## token pasting operator, arguing that since __VA_ARGS__ expands to include the format string, the extra layer was redundant:

"You can omit fmt, then you don't need the ## ... By the time the compiler looks at it the pre-processor has expanded VA_ARGS. So it doesn't matter that the format string is in the VA_ARGS list rather than preceding it." — David Laight

Andrew Lunn initially expressed concern that removing fmt might break GCC's format checking, but Sean Chang confirmed that the simplified approach works correctly because no_printk itself handles the internal logic. Sean agreed to adopt the simpler macro in v5:

"I agree that since VA_ARGS will always contain the format string in this context, the ## and explicit fmt are indeed redundant... I'll switch to the simpler in v5." — Sean Chang

Bug Fix and Cleanup: Sean also identified a build error in fs/nfsd/nfsfh.c reported by syzbot, where a buffer variable declared inside RPC_IFDEBUG was undeclared when debug was disabled. He initially proposed wrapping the code in #if IS_ENABLED(CONFIG_SUNRPC_DEBUG).

Andrew Lunn advised against adding more #if guards, emphasizing that compile testing is hindered by complex conditional compilation blocks:

"Please try to avoid adding such #if code. Compile testing does not work as well if there are millions of #if def combinations. Ideally we want the stub functions to allow as much as possible to be compiled, and then let the optimizer throw it out because it is unreachable." — Andrew Lunn

Sean verified that with no_printk, the compiler optimizes away the unused buffer and code under -O2 even without #if guards. Consequently, he decided to remove the RPC_IFDEBUG macro entirely in v6, as it is now redundant:

"Even after dropping the #ifdef and always declaring the char buf[], the compiler successfully optimizes everything out when CONFIG_SUNRPC_DEBUG is disabled... I agree it is the perfect time to also remove the RPC_IFDEBUG(x) macro entirely." — Sean Chang

Conclusion

The discussion concluded with a consensus on:

  1. Using no_printk for dfprintk stubs to fix unused variable warnings while preserving type checking.
  2. Simplifying the macro definition as suggested by David Laight.
  3. Removing the RPC_IFDEBUG macro and relying on compiler optimization instead of conditional compilation guards, improving code maintainability and compile-test coverage.

This is a bug fix and code cleanup effort for the NFS client/SunRPC subsystems, ensuring cleaner builds across architectures like RISC-V.
