SUNRPC GSS Auth kref Leak Backport Failure to 6.6-stable

Summary

SUNRPC GSS Auth kref Leak Backport Failure to 6.6-stable

Classification

Bug Fix / Stable Tree Maintenance

This thread addresses a failed backport of an important memory leak fix in the SUNRPC subsystem, specifically within the GSS authentication (auth_gss) code. The issue is not a new feature or protocol change, but rather a critical resource management bug fix that was rejected by the stable tree automation due to application conflicts.

Key Technical Arguments and Context

The discussion centers on a single notification from Sasha Levin regarding a patch that failed to apply cleanly to the Linux 6.6 longterm/stable tree.

The Underlying Bug

The original commit, authored by Daniel Hodges and merged into Linus's mainline tree, addressed a reference counting leak in net/sunrpc/auth_gss/auth_gss.c.

As described in the patch metadata:

"Commit 5940d1cf9f42 ("SUNRPC: Rebalance a kref in auth_gss.c") added a kref_get(&gss_auth->kref) call to balance the gss_put_auth() done in gss_release_msg(), but forgot to add a corresponding kref_put() on the error path when kstrdup_const() fails."

The bug manifests when service_name is non-NULL and kstrdup_const() fails. The execution flow jumps to the err_put_pipe_version label, which correctly cleans up the pipe version and frees the message structure (kfree(gss_msg)), but neglects to release the gss_auth reference taken earlier via kref_get. This results in a memory leak where the gss_auth structure is never freed.

The Fix

The proposed fix adds a forward declaration for gss_free_callback() and inserts a kref_put() call within the err_put_pipe_version error path to properly balance the reference count:

"Add a forward declaration for gss_free_callback() and call kref_put() in the err_put_pipe_version error path to properly release the reference taken earlier."

Backport Failure

Sasha Levin reported that this patch, while accepted into mainline, did not apply cleanly to the 6.6-stable tree. The notification states:

"The patch below does not apply to the 6.6-stable tree. If someone wants it applied there, or to any other stable or longterm tree, then please email the backport, including the original git commit id to stable@vger.kernel.org."

Evolution of the Discussion

This thread consists of a single message this week: a notification from the stable tree maintainer. There is no further discussion, debate, or technical argumentation within this specific thread window. The "evolution" is purely administrative:

  1. A bug was identified and fixed in mainline (prior to this week).
  2. The fix was tagged for stable inclusion (Cc: stable@vger.kernel.org).
  3. Automated backporting to 6.6 failed.
  4. Sasha Levin notified the community that manual intervention is required if the fix is desired in the 6.6 longterm tree.

Final Conclusions

The thread concludes with an open request for action. The NFS/SUNRPC community, specifically developers maintaining or interested in the 6.6 stable tree (such as Anna Schumaker, who signed off on the original patch), are implicitly asked to provide a manually rebased backport of the fix if it is critical for that kernel version.

"If someone wants it applied there, or to any other stable or longterm tree, then please email the backport, including the original git commit id to stable@vger.kernel.org."

Without a subsequent reply in this window providing the rebased patch, the fix remains absent from the 6.6-stable tree as of the end of this reporting period. This highlights the ongoing maintenance burden of ensuring critical NFS client bug fixes propagate correctly to longterm kernels used in production environments.
