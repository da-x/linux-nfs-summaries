NFS Client: xfstest Failures with Delegated Attributes — Bug Report and Fix Series

Summary

NFS Client: xfstest Failures with Delegated Attributes — Bug Report and Fix Series

Classification: Bug Fix (NFS Client / Attribute Delegation)

This thread captures Jeff Layton's introduction of client-side xfstest failures that arise when the delegated_attributes mount option is enabled, along with the subsequent two-patch fix series submitted later in the week.

Prior Context (Brief)

In the prior week (ending 2026-02-26), Olga Kornievskaia reported xfstest failures that manifested differently depending on whether delegated_attributes was enabled or disabled. Jeff Layton investigated and identified a root cause in xfstest generic/751: the NFS client's REMOVEXATTR compound RPC did not include a trailing GETATTR, leaving cached timestamps stale when delegated attributes were active — whereas the SETXATTR compound already included one. This asymmetry was flagged as a client-side bug requiring a fix as summarized previously.

This Week's Activity

Bug Report Thread Initiation

On March 2, Jeff Layton posted a message titled "client-side xfstest failures with delegated attributes" c4dcc644fa65036f9bcae63e64b66509db85efc1.camel@kernel.org, bringing wider visibility to the issue. The thread itself contained only this single message, serving as an introductory note to frame the problem for the community.

Fix Series Submitted (Related Thread)

Later in the week, Layton followed up with a concrete two-patch series ([PATCH 0/2] nfs: delegated attribute fixes, <20260305-nfs-7-1-v1-0-e2200f69e543@kernel.org>) targeting Linux kernel v7.1. He introduced the series with:

"This patchset fixes a couple of test failures in xfstests when delegated timestamps are enabled. Please consider for v7.1!" PATCH 0/2

The series addressed two distinct bugs:

Patch 1: Fix utimensat() for atime with delegated timestamps (xfstest generic/221)

When a client holds a WRITE_ATTRS_DELEG delegation and a userspace process performs a utimensat() call updating only the access time (atime), the change time (ctime) was not being updated correctly. Layton explained:

"The problem is that the client tries to cache the atime update, but there is no mtime update, so the delegated attribute update never updates the ctime." PATCH 1/2

He further noted a protocol limitation:

"Delegated timestamps don't have a mechanism to update the ctime in accordance with atime-only changes due to utimensat() and the like." PATCH 1/2

Fix: The patch modifies the client to issue an RPC in this specific case, ensuring the server updates ctime alongside atime, rather than relying on the insufficient local caching mechanism.

Patch 2: Update inode ctime after removexattr operation (xfstest generic/728)

This patch resolves the bug identified in last week's analysis. After a removexattr operation, the client's cached ctime remained stale because the subsequent stat() call did not trigger a GETATTR due to the active delegation. Layton described the issue:

"The client does a removexattr and then a stat to test the ctime, which doesn't change. The stat() doesn't trigger a GETATTR because of the delegated timestamps, so it relies on the cached ctime, which is wrong." PATCH 2/2

Fix: Following the strategy used by setxattr (which includes a trailing GETATTR), this patch adds a similar mechanism to the removexattr compound operation, ensuring the client retrieves and caches the updated ctime immediately after removing an extended attribute.

Final Conclusions

Status: Two patches submitted for v7.1, addressing concrete correctness bugs in the NFS client's delegated attribute handling:

  • Patch 1 forces an RPC during utimensat() atime-only updates to ensure ctime is correctly refreshed on the server.
  • Patch 2 adds a trailing GETATTR to the removexattr compound, mirroring the setxattr behavior and resolving stale ctime caching.

Both patches resolve xfstest failures (generic/221 and generic/728) that surfaced when delegated attributes are enabled, improving the robustness of the NFS client's attribute delegation implementation.

Significance for NFS Client Development

These fixes highlight subtle correctness issues in the NFS client's handling of delegated timestamps — a feature designed to reduce RPC overhead by allowing clients to cache attribute updates locally. The bugs demonstrate that edge cases (atime-only updates, extended attribute removal) can leave metadata stale when local caching is relied upon without proper server-side coordination. Resolving these issues ensures POSIX-compliant ctime semantics are maintained even under delegation, which is critical for filesystem correctness testing and real-world workloads that depend on accurate timestamp information.
