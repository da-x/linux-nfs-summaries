rpc.mountd CVE-2025-12801: Privilege Escalation Fix in NFSv3 Mounts

Summary

rpc.mountd CVE-2025-12801: Privilege Escalation in NFSv3 Mounts

Overview

On March 5, 2026, Steve Dickson posted a critical security announcement and patch series addressing CVE-2025-12801, a vulnerability in the rpc.mountd daemon within the nfs-utils package. This is a bug fix — specifically a security-critical bug fix — rather than a new feature or protocol change.

The Vulnerability

As described in the cover letter PATCH 0/4:

"A vulnerability was recently discovered in the rpc.mountd daemon in the nfs-utils package for Linux, that allows a NFSv3 client to escalate the privileges assigned to it in the /etc/exports file at mount time."

The flaw permits an NFSv3 client to access any subdirectory or subtree of an exported directory, bypassing both standard file permissions and root_squash or all_squash attributes that should restrict such access. The vulnerability affects all Linux kernel NFS servers exporting NFSv2 and/or NFSv3 protocols, but does not affect servers exporting only NFSv4.

"This issue has been fixed in nfs-utils 2.8.6 and later, with an upgrade advised for all users."

Patch Series Breakdown

The four-patch series, authored by Trond Myklebust with reviews from Jeff Layton and sign-offs from Scott Mayhew and Steve Dickson, systematically addresses the root cause:

1. Minor refactor of get_rootfh() PATCH 1/4

This patch reorders operations to perform mountpoint checks before checking the user path, laying groundwork for the subsequent fixes.

2. Separate lookup of exported directory and mount path PATCH 2/4

The core architectural change: when a client requests a path that does not terminate with an exported directory, the lookups are split so that:

  • The exported directory is looked up using mountd's privileged credential
  • Remaining subdirectory lookups use the RPC caller's credential

"When the caller asks to mount a path that does not terminate with an exported directory, we want to split up the lookups so that we can look up the exported directory using the mountd privileged credential, and the remaining subdirectory lookups using the RPC caller's credential."

3. Mini-library for RPC credentials PATCH 3/4

Adds server-side functionality to extract credentials from client RPC calls and apply them, enabling proper access checking within mountd.

"Add server functionality to extract the credentials from the client RPC call, and apply them. This is needed in order to perform access checking on the requested path in the mountd daemon."

4. Fix access checks for NFSv3 subdirectory mounts PATCH 4/4

The final patch applies RPC credentials together with any root or all-squash rules when an NFSv3 client requests a subdirectory of an exported directory.

"If a NFSv3 client asks to mount a subdirectory of one of the exported directories, then apply the RPC credential together with any root or all squash rules that would apply to the client in question."

Significance for NFS Client Development

While this fix resides in the server-side rpc.mountd daemon, it has direct implications for NFS clients:

  • NFSv3 clients could previously exploit this flaw to gain unauthorized access to subdirectories, effectively bypassing export restrictions.
  • The fix ensures that privilege escalation at mount time is no longer possible, restoring the intended security model of /etc/exports.
  • NFSv4 users are unaffected, as noted in the announcement.

Conclusion

This thread represents a timely and critical security remediation for the NFS ecosystem. The patch series was reviewed by Jeff Layton and accepted into nfs-utils 2.8.6. All administrators running NFSv2/NFSv3 exports on Linux are urged to upgrade promptly.
