sunrpc: Simplify dprintk() macros and remove redundant debug guards

Summary

This week, Sean Chang submitted PATCH v2 to simplify the dprintk() macro definitions in the sunrpc subsystem and clean up redundant debug guards across multiple NFS-related files. This patch represents the culmination of discussions from prior weeks regarding compiler warnings, build errors, and code maintainability in the NFS client/server infrastructure.

Context from Prior Weeks

In previous weeks (PATCH v4 and PATCH v5), the community discussed:

  1. Replacing empty do {} while (0) stubs for debug macros with no_printk() to fix -Wunused-variable warnings while preserving type checking.
  2. David Laight's suggestion to simplify macro definitions by removing the explicit fmt argument and the ## token pasting operator.
  3. Andrew Lunn's advice to minimize conditional compilation guards (#if blocks) to improve compile-test coverage, relying instead on compiler optimization to eliminate unreachable code.

Technical Arguments

The current patch implements these conclusions:

Macro Simplification:

"Following David Laight's suggestion, simplify the macro definitions by removing the unnecessary 'fmt' argument and using no_printk(VA_ARGS) directly." — Sean Chang

Compiler Optimization Verification: Sean verified that the compiler successfully performs dead code elimination under -O2:

"Verification with .lst files under -O2 confirms that the compiler successfully performs 'dead code elimination'. Even when variables (like char buf[] in nfsfh.c) or static helper functions (like nlmdbg_cookie2a() in svclock.c) are declared without #ifdef, they are completely optimized out (no stack allocation, no symbol references in the final executable) as they are only referenced within no_printk()." — Sean Chang

v2 Changes: The patch addresses feedback from Andy Shevchenko and refines the commit message:

"v2:

  • Follow reversed xmas tree order for variables in svc_rdma_transport.c as requested by Andy Shevchenko.
  • Polish commit message: use dprintk() and remove redundant file list.
  • Correct the technical claim about dprintk() type checking." — Sean Chang

Files Modified

The patch touches four files:

  • fs/lockd/svclock.c: Removed redundant debug guards (7 lines deleted)
  • fs/nfsd/nfsfh.c: Cleaned up conditional variable declarations (8 lines changed)
  • include/linux/sunrpc/debug.h: Simplified macro definitions (8 lines changed)
  • net/sunrpc/xprtrdma/svc_rdma_transport.c: Refactored debug code with proper variable ordering (25 lines changed)

Classification

This is a code cleanup and bug fix effort for the NFS client/SunRPC subsystems. The changes:

  1. Fix compiler warnings on architectures like RISC-V by using no_printk() for type checking without code generation.
  2. Improve code maintainability by reducing conditional compilation complexity.
  3. Enhance compile-test coverage by removing unnecessary #ifdef guards, allowing more code paths to be tested during build verification.

Conclusion

As of the end of this week, no replies have been received to this patch submission. The discussion continues in subsequent weeks with feedback from Andy Shevchenko and Chuck Lever. The core achievement is the stabilization of NFS-related build configurations through modernized debug macros that prevent both warnings and fatal errors in non-debug builds, while leveraging compiler optimizations to reduce code complexity.
