xprtrdma: Fix sendctx get/put Race That Can Block a Transport

Summary

xprtrdma: Fix sendctx get/put Race That Can Block a Transport

Classification: Bug fix (NFS client, RDMA transport)

Overview

On March 2nd, Chuck Lever submitted a critical bug fix for the NFS/RDMA (xprtrdma) transport layer, addressing a race condition between rpcrdma_sendctx_get_locked() and rpcrdma_sendctx_put_locked() that can permanently block all further sends on an RDMA transport. The patch was submitted as a standalone message with no replies in the current week.

Technical Analysis

The bug manifests when the sender and a Send completion handler race on the send context ring buffer. Lever detailed the interleaving:

"rpcrdma_sendctx_get_locked() and rpcrdma_sendctx_put_locked() can race in a way that leaves XPRT_WRITE_SPACE set permanently, blocking all further sends on the transport"

The specific sequence is as follows:

  1. The sender (get_locked) reads rb_sc_tail and determines the ring is full.
  2. Concurrently, a Send completion (put_locked) advances rb_sc_tail, calls xprt_write_space(), but finds XPRT_WRITE_SPACE not set, so it returns without action.
  3. The sender then sets XPRT_WRITE_SPACE and returns NULL (with -EAGAIN).

After the sender releases the lock, the release path refuses to wake the next task because XPRT_WRITE_SPACE is already set. The sender retries, finds the flag still set, and sleeps on xprt_sending. Critically:

"No further Send completions arrive to clear the flag because no new Sends can be posted."

Impact on nconnect

The bug has amplified consequences when using NFS/RDMA with nconnect (multiple transports per session). Lever noted:

"With nconnect, the stalled transport's share of congestion credits are never returned, starving the remaining transports as well."

This means a single race on one transport can degrade performance across all parallel connections in an nconnect session.

Resolution

The patch modifies net/sunrpc/xprtrdma/verbs.c (16 insertions, 1 deletion) to close this race window. It is marked as fixing commit 05eb06d86685 ("xprtrdma: Fix occasional transport deadlock"), indicating this is a regression or incomplete fix from prior work on transport deadlocks.

Conclusion

This is an important stability fix for NFS/RDMA clients, particularly those using nconnect. The race condition could lead to permanent transport stalls and cascading congestion credit starvation. With no objections in the current window, this patch appears poised for inclusion in the upcoming kernel merge cycle.
