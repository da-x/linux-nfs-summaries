NFSD v7.0 Fixes: Cred Leaks and Thread Reporting Merged

Summary

First Round of NFSD Fixes for v7.0 Merged

This brief thread documents the successful merge of the first round of NFS server (NFSD) fixes for the Linux v7.0 kernel cycle. The pull request, initiated by Chuck Lever and accepted by Linus Torvalds, addresses critical bug fixes related to credential reference leaks and incorrect thread count reporting in the NFSD subsystem.

Nature of Discussion: Bug Fixes

The discussion is strictly focused on bug fixes, specifically targeting issues that arose after the v7.0 merge window or required expedient stable backports. No new features or protocol changes were introduced in this set.

Key Technical Arguments and Changes

Chuck Lever submitted the pull request on March 2, 2026, highlighting two primary categories of fixes:

1. Credential Reference Leaks in Netlink Admin Protocol

Two significant bug fixes by Kuniyuki Iwashima addressed credential reference leaks within the NFSD netlink administration interface. These are critical stability and security issues, as reference leaks can lead to resource exhaustion or denial of service.

  • nfsd: Fix cred ref leak in nfsd_nl_threads_set_doit().
  • nfsd: Fix cred ref leak in nfsd_nl_listener_set_doit().

Lever noted these are "Issues that need expedient stable backports," indicating their severity for production kernels.

2. Thread Count Reporting Restoration

A fix by Jeff Layton addressed a regression in how NFSD reports its thread count:

  • nfsd: report the requested maximum number of threads instead of number running

Lever described this as restoring "previous nfsd thread count reporting behavior," implying that recent changes had inadvertently altered the metric exposed to administrators, potentially causing confusion in monitoring and tuning.

Evolution and Conclusion

The thread was short-lived, consisting only of the initial pull request and the automated confirmation of its merge.

"The pull request you sent on Mon, 2 Mar 2026 09:11:29 -0500... has been merged into torvalds/linux.git" confirmed by pr-tracker-bot.

The merge commit is 1b37ac211a22d4c65aad1ae2da07f078197e7394 in the mainline repository.

Impact on NFS Client Development

While this thread focuses on NFSD (server-side) fixes, the resolution of credential leaks and accurate thread reporting contributes to overall NFS subsystem stability. Reliable server behavior is a prerequisite for robust client development, as clients depend on consistent server responses and resource management. The netlink fixes ensure that administrative operations do not degrade server performance over time, indirectly benefiting client interactions by maintaining server health.
