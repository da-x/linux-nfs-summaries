Jan Kara Reviews VFS and FAT Patches for Case Folding Series (v8)

Summary

This week, VFS maintainer Jan Kara provided formal review approvals for the first three patches of Chuck Lever's [PATCH v8] Exposing case folding behavior series. These reviews advance the series toward integration by validating the foundational VFS infrastructure changes and the initial filesystem implementation (FAT).

Classification: New Feature / Protocol Enhancement

This discussion concerns a new feature: a VFS-level mechanism for filesystems to report their case sensitivity and case preservation behavior. The feature enables NFS server (NFSD), SMB server (ksmbd), and user-space file servers to accurately advertise these attributes to clients, improving interoperability with Windows and macOS NFS clients.

Background (Brief)

As summarized in the prior week's report, Chuck Lever submitted version 8 of a 17-patch series on February 17. The series introduces FS_XFLAG_CASEFOLD and FS_XFLAG_CASENONPRESERVING flags exposed via fileattr_get, enabling network file servers to query the underlying filesystem's case semantics dynamically rather than relying on hard-coded assumptions.

Key NFS-relevant patches include:

  • Patch 11/17: NFS client fileattr_get implementation for re-export scenarios.
  • Patches 15-16/17: NFSD enhancements to report accurate case sensitivity via NFSv3 PATHCONF and NFSv4 attributes.

Theodore Ts'o (ext4 maintainer) had already acknowledged Patch 08/17 in the prior week.

This Week's Activity: Jan Kara's Reviews

On February 27, Jan Kara reviewed three foundational patches from the series, providing Reviewed-by tags for each.

Patch 01/17: Move file_kattr initialization to callers

Jan Kara approved this patch without reservation:

"Looks good. Feel free to add: Reviewed-by: Jan Kara jack@suse.cz" ih3mvucoroudud5l4pndgjxbxfxgcizu2mpli4fhkbnxwufrlm@cyoqgtmvlvpq

This patch refactors file_kattr initialization from helper functions to callers, preventing the zeroing of pre-set flags — a necessary prerequisite for adding new flag fields.

Patch 02/17: Add case sensitivity flags to file_kattr

Kara similarly approved the addition of FS_XFLAG_CASEFOLD and FS_XFLAG_CASENONPRESERVING to the file_kattr structure:

"Looks good. Feel free to add: Reviewed-by: Jan Kara jack@suse.cz" 6fw3nxspwmbkyyobefnxe6piza4nmpfqx5pg5btjh6zisuqie3@i22cjwsgobtj

These flags form the core of the VFS interface that filesystems will populate to report their case behavior.

Patch 03/17: fat — Implement fileattr_get for case sensitivity

For the FAT filesystem implementation, Kara provided a conditional approval, noting the need for confirmation from the FAT maintainer regarding corner cases:

"Looks good to me from general POV. It would be good to get confirmation from FAT maintainer you've got all the corner cases of FAT configuration right :) Anyway, feel free to add: Reviewed-by: Jan Kara jack@suse.cz" ua7rmlnvbfiadpxeynekbabwqebhcop3rhaxji7s3mgnwzhhtd@frz77j6wm2eg

The FAT implementation respects the nocase mount option, reporting case-insensitive behavior when that option is active. Kara's comment highlights the importance of filesystem-specific maintainer validation for correct handling of configuration-dependent behavior.

Evolution of the Discussion

With Jan Kara's reviews, the series now holds approval from two key VFS-level stakeholders:

  • Theodore Ts'o (ext4) acknowledged Patch 08/17 last week.
  • Jan Kara (VFS/FAT) reviewed Patches 01-03/17 this week.

The remaining patches (exfat, ntfs3, hfs, hfsplus, xfs, cifs, nfs, f2fs, vboxsf, isofs, nfsd, ksmbd) still require maintainer attention. The NFS-specific patches (11/17 for the client and 15-16/17 for NFSD) are critical for the series' primary goal of improving NFS interoperability with case-insensitive clients.

Conclusions

This week's activity represents steady progress toward merging the case folding exposure series:

  1. VFS infrastructure is approved: Jan Kara's reviews validate the foundational changes to file_kattr, clearing the path for filesystem-specific implementations.
  2. FAT implementation is conditionally approved: Pending FAT maintainer confirmation on corner cases, the FAT patch is ready for integration.
  3. NFS client and server patches remain under review: The patches most directly impacting NFS development — the NFS client fileattr_get implementation and NFSD's dynamic case sensitivity reporting — have not yet received explicit maintainer feedback in this window.

The series continues to build momentum toward resolving a long-standing gap in Linux's ability to accurately report filesystem case semantics to network file clients, particularly benefiting Windows and macOS NFS interoperability.
