SUNRPC auth_gss memory leak fix fails 5.10-stable auto-apply

Summary

SUNRPC auth_gss Memory Leak Fix Fails to Apply to 5.10-stable

This week, the stable tree maintainers reported that a critical memory leak fix for the NFS/RPC GSS authentication subsystem failed to apply automatically to the 5.10-stable long-term kernel tree.

The Bug: Memory Leaks in XDR Decoding Error Paths

The underlying issue, originally fixed in Linus Torvalds' mainline tree by Chuck Lever, involves memory leaks in net/sunrpc/auth_gss/gss_rpc_xdr.c.

As detailed in the original commit 3e6397b05633, the functions gssx_dec_ctx(), gssx_dec_status(), and gssx_dec_name() allocate memory via kmemdup() during XDR decoding. When subsequent decode operations fail, these functions returned immediately without freeing previously allocated buffers.

"The leak in gssx_dec_ctx() is particularly relevant because the caller (gssp_accept_sec_context_upcall) initializes several buffer length fields to non-zero values, resulting in memory allocation."

For example, if gssx_dec_name() succeeds for src_name but fails for targ_name, the memory allocated for exported_context_token, mech, and src_name.display_name remains unreferenced and cannot be reclaimed. The fix introduces goto-based cleanup logic to free any previously allocated buffers before returning an error.

Status: Manual Backport Required

On March 1, Sasha Levin notified the community that the patch did not apply cleanly to the 5.10-stable tree:

"The patch below does not apply to the 5.10-stable tree. If someone wants it applied there, or to any other stable or longterm tree, then please email the backport, including the original git commit id to stable@vger.kernel.org."

This is a bug fix related to NFS client development, specifically addressing resource management in the RPC GSS authentication mechanism. The fix was originally reported by Xingjing Deng and reviewed by Jeff Layton.

Conclusion

As of this week's window, no manual backport has been submitted or discussed in this thread. Developers maintaining 5.10-based systems with RPC GSS authentication may need to manually apply the fix or wait for a community member to provide a rebased patch for the stable tree. The issue affects error handling paths during XDR decoding, meaning it would primarily impact scenarios where GSS context establishment fails after partial success.
