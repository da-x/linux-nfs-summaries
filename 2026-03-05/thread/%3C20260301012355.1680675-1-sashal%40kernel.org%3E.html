nfsd: Stable Backport Failure for ID Mapping Timeout Fix

Classification

Bug fix backport issue. This thread concerns the failure to automatically apply an important NFS server (nfsd) bug fix to the 6.12-stable kernel tree.

Summary

Sasha Levin, the stable kernel maintainer, reported that a patch fixing error handling in NFS server identity mapping failed to apply cleanly to the 6.12-stable tree. The original commit addresses a critical issue where NFS clients could receive incorrect error codes when ID mapping lookups timed out.

The Underlying Bug Fix

The original patch by Anthony Iliopoulos fixes a problem in nfsd_map_name_to_[ug]id functions within the NFS server's identity mapping subsystem. As described in the commit message:

"idmap lookups can time out while the cache is waiting for a userspace upcall reply. In that case cache_check() returns -ETIMEDOUT to callers."

The bug manifested when these timeout conditions occurred:

"The nfsd_map_name_to_[ug]id functions currently proceed with attempting to map the id to a kuid despite a potentially temporary failure to perform the idmap lookup. This results in the code returning the error NFSERR_BADOWNER which can cause client operations to return to userspace with failure."

Impact on NFS Clients

This fix is particularly relevant for NFS client development and operation because it changes the error semantics returned to clients:

"Fix this by returning the failure status before attempting kuid mapping. This will return NFSERR_JUKEBOX on idmap lookup timeout so that clients can retry the operation instead of aborting it."

The distinction is significant: NFSERR_BADOWNER causes client operations to fail permanently, while NFSERR_JUKEBOX signals a transient condition that allows clients to retry—improving robustness when userspace name-to-ID mapping services (such as NSS or LDAP lookups) are slow or temporarily unavailable.

Backport Status

Sasha Levin's notification indicates the patch did not apply automatically to the 6.12-stable tree:

"The patch below does not apply to the 6.12-stable tree. If someone wants it applied there, or to any other stable or longterm tree, then please email the backport, including the original git commit id to stable@vger.kernel.org."

The original commit (404d77946664) was signed off by Chuck Lever and reviewed by NeilBrown, indicating it went through proper review channels in the mainline tree. However, no backport was submitted during this week's window.

Conclusion

This thread represents an administrative notification rather than a technical discussion. The key takeaway for NFS developers is that an important bug fix—correcting error handling in identity mapping timeouts to improve client retry behavior—requires manual backporting to the 6.12-stable tree. As of this week's end, no such backport has been provided by the community or maintainers.
