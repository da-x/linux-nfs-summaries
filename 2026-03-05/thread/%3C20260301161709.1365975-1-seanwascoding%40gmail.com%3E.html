SUNRPC Debug Macro Cleanup and MACB Ethtool Fix

Summary

This thread covers the sixth iteration of a patch series by Sean Chang aimed at resolving compiler warnings and build errors in the SUNRPC subsystem and the MACB ethernet driver. The discussion highlights a collaborative effort to simplify debug macros while ensuring no performance penalty when debugging is disabled.

Technical Arguments and Evolution

The primary technical focus was Patch 1/2, which refactored the dfprintk macros in the SUNRPC subsystem. Previously, these macros expanded to empty loops when CONFIG_SUNRPC_DEBUG was disabled, causing -Wunused-variable warnings for variables used only within debug contexts. Sean Chang proposed using no_printk(__VA_ARGS__) directly, a suggestion originally made by David Laight and Andrew Lunn. This approach allows the compiler to perform type checking while optimizing out the unused code entirely.

Sean Chang provided rigorous verification of this optimization:

"Verification with .lst files under -O2 confirms that the compiler successfully performs 'dead code elimination'. Even when variables... or static helper functions... are declared without #ifdef, they are completely optimized out"

Andrew Lunn validated this approach, noting:

"Thanks for doing this bit. It was needed to show my guess was correct."

He subsequently provided a Reviewed-by tag for the series.

Patch 2/2 addressed a separate issue in the MACB driver, where the RISC-V toolchain triggered a stringop-truncation warning due to manual snprintf usage with fixed-length buffers. The fix adopted the modern ethtool_sprintf() API, which handles padding automatically. Andrew Lunn had previously reviewed and suggested this change.

Process Discussion: Series vs. Standalone Patches

A significant portion of the discussion involved Andy Shevchenko, who questioned the structure of the submission. He noted that the two patches addressed unrelated subsystems (SUNRPC/NFSD and MACB) and should not be bundled together:

"My Q in v5 still stands: Why is this a series and not standalone changes? Also I just gave a tag, please split these two and send individually."

Shevchenko further advised that if the SUNRPC fix was urgent for the nfsd-next tree, it should be sent as a standalone patch after rebasing.

Conclusion

Sean Chang accepted the feedback and confirmed that he had split the work into two independent submissions:

"I have split these into two standalone patches as you requested... I've also verified the optimization again via .lst files to ensure everything is clean."

The thread concludes with the successful decoupling of the SUNRPC debug macro cleanup from the MACB ethtool fix, allowing each to be processed through its respective subsystem maintainer. The SUNRPC changes are particularly relevant for NFS client/server development as they resolve build errors reported by syzbot and improve code maintainability in fs/nfsd/nfsfh.c and related files.
