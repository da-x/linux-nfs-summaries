NFS: Fix W=1 build errors in flexfilelayout and nfs4proc

Summary

NFS: Address build errors when built with W=1

A three-patch series from Peng Fan (NXP) addressed compiler warnings that escalate to errors when the Linux kernel is built with W=1 (treat warnings as errors). The patches target the NFS client subsystem, specifically the flexfile layout driver and NFSv4 procedure implementations. This is a bug fix series focused on build hygiene and minor error-reporting improvements, rather than a new feature or protocol change.

Overview

Peng Fan reported that building x86_64_defconfig with COMPILE_TEST=y and W=1 revealed three "variable set but not used" errors in fs/nfs. The series resolves these issues through two distinct approaches: improving error propagation patterns and marking debug-only variables as intentionally unused.

"I built x86_64_defconfig with COMPILE_TEST=y and W=1, then saw three build errors from fs/nfs: 'error: variable set but not used'"
— Peng Fan

Patch 1/3: Improve error reporting in flexfilelayout device ID allocation

The first patch addresses a flaw in nfs4_ff_alloc_deviceid_node() where the function initialized a return variable ret but never returned it, instead returning NULL on error. This dropped specific error codes and triggered a compiler warning.

"The function also returned NULL on error, dropping the specific errno stored in 'ret'. Convert it to return ERR_PTR(ret) instead, and update ff_layout_alloc_deviceid_node() to detect errors using IS_ERR()."
— Peng Fan

The fix aligns the helper with common kernel allocation patterns by returning ERR_PTR(ret) on failure and updating the caller to use IS_ERR() for error detection. Peng Fan noted:

"No functional change for success paths; improves error reporting."
— Peng Fan

Patch 2/3: Mark err as __maybe_unused in flexfilelayout

The second patch resolves a warning in ff_layout_io_track_ds_error(), where the variable err captures the return value of ff_layout_track_ds_error() but is only consumed by a dprintk() debug statement. When debug output is disabled, the compiler flags the variable as unused.

"Variable 'err' is assigned the return value of ff_layout_track_ds_error() but is only used in the dprintk() debug statement at the end of the function. When debug output is disabled, the variable appears unused to the compiler."
— Peng Fan

The solution marks err with __maybe_unused to indicate this is intentional behavior.

Patch 3/3: Mark ptr as __maybe_unused in nfs4proc

Similarly, the third patch addresses a warning in nfs4_proc_create_session(), where the variable ptr is assigned but only referenced in debug print statements.

"The variable 'ptr' is assigned but only used in dprintk() debug statements. When debug output is disabled, the variable appears unused to the compiler."
— Peng Fan

Again, __maybe_unused resolves the warning without altering runtime behavior.

Conclusion

This series ensures that the NFS client builds cleanly under strict compiler warning settings (W=1). While two patches are purely cosmetic (suppressing warnings for debug-only variables), the first patch provides a tangible improvement to error reporting in the flexfile layout subsystem by preserving errno values through ERR_PTR conventions. The thread concluded without further discussion, as these are straightforward fixes with clear technical merit.
