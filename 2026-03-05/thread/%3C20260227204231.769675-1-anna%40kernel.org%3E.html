NFS KConfig Typo Fixes and Default Corrections

Summary

NFS: Fix KConfig Typos and Defaults

This week, Anna Schumaker submitted a corrective patch addressing two issues discovered after recent NFS v4.0 Kconfig changes were merged upstream. The discussion is classified as a bug fix, specifically targeting configuration defaults and documentation clarity in the kernel build system.

Context and Issues Identified

The patch addresses problems reported by Niklas Cassel and Geert Uytterhoeven following two previous commits:

  1. 4e0269352534 ("NFS: Add a way to disable NFS v4.0 via KConfig")
  2. 7537db24806f ("NFS: Merge CONFIG_NFS_V4_1 with CONFIG_NFS_V4")

As described by Anna Schumaker:

"Two issues were noticed after the NFS v4.0 KConfig changes were merged upstream. First, the text of CONFIG_NFS_V4 should not encourage people to select it if they are unsure. Second, the new CONFIG_NFS_V4_0 option should default to 'on' instead of 'off' to avoid breaking people's setups if they are using NFS v4.0."

Technical Details

The fix involves two specific changes to fs/nfs/Kconfig:

  1. Documentation Correction: The help text for CONFIG_NFS_V4 was revised to remove language that might inappropriately encourage users to enable the option when uncertain about their needs.

  2. Default Value Adjustment: The CONFIG_NFS_V4_0 option was changed to default to "on" rather than "off". This is critical for maintaining backward compatibility, as disabling NFS v4.0 by default could break existing user setups that depend on this protocol version.

Significance for NFS Client Development

This patch highlights the importance of careful consideration when modifying kernel configuration defaults, particularly for widely-used subsystems like NFS. A change that inadvertently disables a feature by default can have significant impact on users who rely on that functionality without explicitly configuring it.

The fix ensures that:

  • Existing NFS v4.0 deployments continue to work out-of-the-box after kernel updates
  • Users are not misled by configuration help text
  • The recent refactoring of NFS v4 configuration options does not introduce regressions

Conclusion

This straightforward but important fix demonstrates the ongoing maintenance efforts in the NFS client codebase, where even post-merge issues are promptly addressed to ensure stability and user experience. The patch was submitted with proper Fixes: tags referencing the original commits that introduced the issues, following kernel development best practices for tracking bug resolutions.
