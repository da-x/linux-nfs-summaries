rpc.gssd Encryption Type Rework Committed to nfs-utils

Summary

Resolution: Encryption Type Handling Patches Committed

Last week, Scott Mayhew from Red Hat submitted a four-patch RFC series to address a critical bug causing input/output errors (-EIO / -5) during readdir() operations on NFSv4 clients using Kerberos with SHA-2 encryption types. The root cause was an encryption type (enctype) mismatch between machine and user credentials when constrained delegation via gssproxy was in use, leading to XDR decoding failures in the kernel.

The series included:

  1. Removal of deprecated single-DES encryption support.
  2. A helper function for converting enctype lists to human-readable strings.
  3. Functionality to query the krb5 library for permitted enctypes at startup.
  4. The key fix: a helper to compute the correct intersection and ordering of enctypes from nfs.conf, kernel upcalls, and the krb5 library's preferences.

This week, Steve Dickson confirmed the series has been merged into the mainline tree:

"Committed... (tag: nfs-utils-2-8-6-rc3)" Steve Dickson

Significance for NFS Client Development

This fix resolves a long-standing issue tracked as Debian Bug #1120598, which affected users relying on Kerberos-authenticated NFS mounts with modern encryption types. By ensuring that rpc.gssd aligns its enctype selection with the krb5 library's internal preferences, the patches prevent the credential mismatch that caused filesystem access failures.

The inclusion in nfs-utils-2-8-6-rc3 means distributions can now integrate this fix into their upcoming releases, improving stability for NFS clients using constrained delegation and SHA-2-based encryption.
