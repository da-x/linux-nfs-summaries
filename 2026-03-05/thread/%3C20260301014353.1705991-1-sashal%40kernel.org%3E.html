nfsd: Stable Backport Failure for ID Mapping Error Code Fix

Overview

This week, Sasha Levin notified the community that a critical bug fix for the NFS server (nfsd) failed to automatically apply to the 6.1-stable tree. The patch in question addresses an issue where improper error handling during identity mapping (idmap) timeouts could cause client operations to fail permanently rather than allowing for retry.

Technical Context: The Bug

The underlying issue, originally fixed in Linus's mainline tree by Anthony Iliopoulos, concerns the nfsd_map_name_to_[ug]id functions. As described in the original commit:

"idmap lookups can time out while the cache is waiting for a userspace upcall reply. In that case cache_check() returns -ETIMEDOUT to callers."

Previously, when such a timeout occurred, the code would proceed to attempt mapping the ID to a kuid despite the temporary failure. This resulted in returning NFSERR_BADOWNER, which caused client operations to fail outright in userspace. The fix ensures that the function returns early with NFSERR_JUKEBOX on timeout, allowing clients to retry the operation instead of aborting it.

Status This Week

On March 1st, Sasha Levin reported:

"The patch below does not apply to the 6.1-stable tree. If someone wants it applied there, or to any other stable or longterm tree, then please email the backport, including the original git commit id to stable@vger.kernel.org."

This is a procedural notification rather than a technical debate. The fix itself has already been merged into mainline (commit 404d77946664) and was reviewed by NeilBrown and signed off by Chuck Lever. However, the 6.1-stable tree requires manual backporting due to code divergence.

Conclusion

This thread highlights an important bug fix for NFS server reliability, particularly in environments where userspace name-to-ID mapping services may experience latency or temporary unavailability. The change ensures that transient failures result in retryable errors (NFSERR_JUKEBOX) rather than permanent failures (NFSERR_BADOWNER).

No further discussion occurred this week regarding the technical merits of the patch; the focus is on the mechanical task of backporting to stable trees. Developers maintaining 6.1-based systems should monitor for a manually prepared backport or prepare one themselves if needed.
