pynfs Test Coverage for NFSv4 ACL-on-Creation Bug Fix

Summary

This week, a single message was posted to this long-running thread concerning a bug fix in the NFSD server: NFSv4 file creation was neglecting to set POSIX ACLs when clients requested them during CREATE operations. The original patch from Chuck Lever (November 2025) addressed the kernel-side defect; this week's activity focused on the corresponding test infrastructure needed to validate the fix via the pynfs test suite.

Background (Prior Weeks)

The thread originated in November 2025 when Chuck Lever submitted a patch fixing a bug where the NFSv4 server failed to apply POSIX ACLs during file creation. As Chuck explained:

"An NFSv4 client that sets an ACL with a named principal during file creation retrieves the ACL afterwards, and finds that it is only a default ACL (based on the mode bits) and not the ACL that was requested during file creation. This violates RFC 8881 section 6.4.1.3: 'the ACL attribute is set as given'."

The root cause was in nfsd_create_setattr(), which relied on nfsd_attrs_valid() to decide whether to call nfsd_setattr(). That function checked for iattr changes and security labels but not POSIX ACLs, causing the ACL to be silently dropped.

During the prior discussion, Chuck mentioned he had developed new pynfs tests while troubleshooting this issue and pointed to Calum Mackay's pynfs repository:

"I developed several new pynfs [1] tests while troubleshooting this issue. I'll post them soon." Chuck Lever

The referenced repository (git://git.linux-nfs.org/projects/cdmackay/pynfs.git) had not seen updates in months, leaving the status of those tests unclear.

This Week's Activity

On March 1, Aurélien Couderc followed up on Chuck's earlier promise to post pynfs tests, noting the apparent inactivity of the upstream repository:

"https://git.linux-nfs.org/?p=cdmackay/pynfs.git;a=summary was not updated since 10 months. Are the patches stuck, or something else happened"

This message serves as a gentle nudge to clarify the status of test coverage for this bug fix. The discussion is categorized as bug fix validation — specifically, ensuring that regression tests exist in the pynfs framework to verify that ACLs set during file creation are correctly applied by the NFSD server.

Classification

  • Type: Bug fix (with associated test infrastructure discussion)
  • Component: NFSD (NFSv4 server), pynfs test suite
  • Status: Open — awaiting clarification on pynfs patch status from Calum Mackay or Chuck Lever

Conclusion

The kernel-side fix for the ACL-on-creation bug was submitted months ago, but this week's message highlights an open question about whether corresponding pynfs regression tests have been integrated. Without such tests, there is a risk that future changes could reintroduce the defect unnoticed. Aurélien Couderc's inquiry underscores the importance of closing the loop between kernel fixes and their test coverage in the NFS community's testing infrastructure.
