mountstats: Fix per-operation percentages with nconnect

Summary

mountstats: Fix per-operation percentages with nconnect

Type: Bug fix (userspace tooling)
Author: Chuck Lever cel@kernel.org
Message: PATCH submission

Overview

This week, a targeted bug fix was submitted to address inaccuracies in the mountstats userspace utility when analyzing NFS mounts configured with nconnect (multiple concurrent TCP connections). The patch corrects how per-operation RPC percentages are calculated, ensuring that statistics reflect the aggregate activity across all transport connections rather than just the last one parsed.

Technical Argument and Bug Description

The core issue lies in the interaction between the kernel's /proc/self/mountstats output format and the Python-based mountstats parser.

As explained by Chuck Lever in the patch cover letter:

"Per-operation percentages reported by 'mountstats --rpc' are inaccurate when an NFS mount uses nconnect."

The kernel emits multiple xprt: (transport) lines for a single NFS client when nconnect=N is set, with each line tracking counters specific to that individual transport connection. However, per-operation counts (such as READ, WRITE, COMMIT) are maintained in a single array per RPC client, reflecting the total across all transports.

The previous implementation of the parser had a flaw:

"The parser overwrites rpcsends on each 'xprt:' line, keeping only the last transport's value."

This led to significant mathematical errors in reporting. Lever illustrates the impact with a concrete example:

"With nconnect=3 and balanced round-robin, rpcsends holds roughly one third of total RPCs while per-op counts hold the full total. display_rpc_op_stats() computes (op_count * 100) / rpcsends, yielding percentages roughly three times too large."

The Fix

The patch modifies tools/mountstats/mountstats.py to correctly aggregate cumulative counters across all transport lines. Specifically, the following fields are now summed rather than overwritten:

  • rpcsends
  • rpcreceives
  • badxids
  • backlogutil
  • sendutil
  • pendutil

Conversely, per-connection properties that do not aggregate (such as port, bind_count, connect_count, connect_time, idle_time, maxslots, and inflightsends) retain their previous behavior of keeping the value from the last transport seen.

Conclusion

This is a critical fix for NFS client development and debugging, particularly for high-performance environments utilizing nconnect to improve throughput. Without this correction, administrators relying on mountstats for performance analysis would have been misled by inflated percentage metrics, potentially obscuring real bottlenecks or misrepresenting the distribution of RPC operations.

The patch is a standalone fix with no further discussion recorded in this window, suggesting it is ready for integration into the tools repository.
