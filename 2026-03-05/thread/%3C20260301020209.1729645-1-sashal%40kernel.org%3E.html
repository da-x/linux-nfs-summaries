nfsd: ID Mapping Timeout Error Fix Fails 5.10-Stable Backport

Summary

nfsd: Stable Backport Failure for ID Mapping Error Fix

Overview

This thread consists of a single automated notification from stable tree maintainer Sasha Levin regarding a failed backport attempt to the 5.10-stable kernel tree. The patch in question addresses a bug fix in the NFS server (nfsd) subsystem related to identity mapping error handling — specifically, how timeout errors during idmap lookups are propagated to NFS clients.

Technical Context: The Bug Fix

The original commit (404d77946664) by Anthony Iliopoulos fixes an issue in the nfsd_map_name_to_[ug]id functions within fs/nfsd/nfs4idmap.c.

The Problem

When idmap lookups time out while waiting for a userspace upcall reply, cache_check() returns -ETIMEDOUT. However, the existing code proceeded to attempt mapping the ID to a kuid despite this temporary failure. This resulted in returning NFSERR_BADOWNER to clients, causing operations to fail permanently rather than allowing for retry.

The Fix

The patch ensures that the failure status is returned before attempting kuid mapping. As described in the commit message:

"This will return NFSERR_JUKEBOX on idmap lookup timeout so that clients can retry the operation instead of aborting it."

Returning NFSERR_JUKEBOX (a transient error) allows NFS clients to retry the operation, which is the correct behavior for temporary failures such as idmap lookup timeouts. This is a significant improvement for NFS client resilience, particularly in environments where userspace name-to-UID/GID mapping services may experience delays.

The fix references an earlier commit: 65e10f6d0ab0 ("nfsd: Convert idmap to use kuids and kgids"), which introduced the regression.

Stable Tree Backport Status

Sasha Levin's notification on 2026-03-01 indicates that this patch could not be automatically applied to the 5.10-stable tree:

"The patch below does not apply to the 5.10-stable tree. If someone wants it applied there, or to any other stable or longterm tree, then please email the backport, including the original git commit id to stable@vger.kernel.org."

This is a common occurrence when kernel APIs or code structures have diverged significantly between mainline and older stable trees. The 5.10 LTS branch, being quite old, likely has structural differences in fs/nfsd/nfs4idmap.c that prevent a clean cherry-pick of the fix.

Conclusion

  • Classification: Bug fix (nfsd server-side error handling improvement with direct NFS client impact).
  • Key Impact: Clients no longer receive permanent NFSERR_BADOWNER errors on temporary idmap timeouts; instead, they receive NFSERR_JUKEBOX, enabling proper retry semantics.
  • Status: The fix is merged in mainline but requires manual backporting to the 5.10-stable tree (and potentially other longterm trees). No further discussion occurred in this thread during the reporting window.

This fix is particularly relevant for NFS client development and operations, as it improves robustness when relying on userspace idmap services that may experience latency or temporary unavailability.
