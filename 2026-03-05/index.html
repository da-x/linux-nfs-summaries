NFS Client: Delegated Attribute Fixes, xprtrdma Race Conditions, pNFS SCSI PR Serialization, and CVE-2025-12801 in rpc.mountd

Week ending 2026-03-05

NFS Mailing List Overview — Week of 2026-03-05

Critical Security: CVE-2025-12801 in rpc.mountd

The most urgent item this week is a privilege escalation vulnerability in the rpc.mountd daemon. Steve Dickson announced CVE-2025-12801, which allows an NFSv3 client to bypass root_squash/all_squash restrictions and access any subdirectory of an exported path at mount time. The four-patch fix, authored by Trond Myklebust, separates the lookup of the exported directory (using mountd's privileged credentials) from subdirectory lookups (using the RPC caller's credentials). All administrators running NFSv2/NFSv3 exports on Linux are urged to upgrade to nfs-utils 2.8.6 or later immediately.

NFS Client Bug Fixes

Delegated Attribute ctime Corrections

Jeff Layton submitted a two-patch series fixing xfstest failures that surfaced when the delegated_attributes mount option is enabled. The bugs were originally reported by Olga Kornievskaia and tracked in a separate bug report thread.

  • Patch 1: utimensat() atime-only updates failed to refresh ctime because the delegated attribute cache had no mechanism for this edge case. The fix forces an RPC to the server in this scenario.
  • Patch 2: removexattr left stale ctime values cached because its compound RPC lacked a trailing GETATTR (unlike setxattr). The patch adds one, ensuring the client retrieves fresh timestamps.

Both patches target Linux v7.1 and resolve xfstests generic/221 and generic/728.

pNFS Block Layout: SCSI PR Registration Race

Dai Ngo submitted a critical fix for the pNFS block layout driver. A race condition in bl_register_scsi() allowed multiple threads to observe a "registered" flag before SCSI Persistent Reservation was actually complete, causing RESERVATION CONFLICT errors and fallback to the MDS. The v2 patch introduces a mutex (pbd_registration_mutex) serializing both registration and unregistration, reviewed positively by Christoph Hellwig.

xprtrdma: Race Conditions and nconnect Stability

Chuck Lever submitted an eight-patch series fixing races in the RDMA transport layer (xprtrdma), surfaced by testing nconnect with NFS/RDMA:

  • Receive counter hang: Fixed a regression where early exits from rpcrdma_post_recvs() failed to decrement re_receiving, causing permanent hangs in rpcrdma_xprt_drain().
  • Send context race: A race between sendctx_get_locked() and sendctx_put_locked() could permanently block all sends on a transport (this fix was also posted standalone earlier in the week).
  • Lost-wakeup in slot allocation: Fixed a race where freed slots went unnoticed by waiting tasks.
  • Unnecessary 250 ms delay: Removed an artificial rpc_delay on backlog wakeup when a slot was already available.

The series also includes substantial refactoring: replacing rpcrdma_mr_seg[] with a lightweight cursor, scaling receive batch size to the credit window, and deferring receive buffer posting until after RPC completion. Anna Schumaker reported regressions on Patch 6/8 (cursor-based MR registration) during cthon testing, indicating a v3 will be needed.

Build Fixes and Tooling

  • W=1 build errors: Peng Fan submitted a three-patch series fixing "variable set but not used" errors in flexfilelayout and nfs4proc, including an improvement to error propagation via ERR_PTR.
  • mountstats nconnect percentages: Chuck Lever fixed per-operation RPC percentage calculations in mountstats, which previously overcounted by a factor of N with nconnect=N.
  • NFS KConfig defaults: Anna Schumaker corrected CONFIG_NFS_V4_0 to default to "on" and fixed misleading help text, preventing regressions for NFSv4.0 users.
  • nfsdclnts crash fix: Frank Sorenson fixed a crash in nfsdclnts when the kernel omits superblock information for certain stateids.
  • nfsrahead revert: Steve Dickson reverted a recent event-driven mountinfo monitoring patch due to concerns raised on linux-block about the libmount API usage.

NFSD and Server-Side Activity

v7.0 Fixes Merged

Chuck Lever's first round of NFSD fixes for v7.0 was merged by Linus, including credential reference leak fixes in the netlink admin protocol and restored thread count reporting.

NLM Lock Regression Debate

An ongoing regression discussion continues regarding -ENOLCK errors on read-only files when using NLM. NeilBrown argues the new behavior is semantically correct (mapping flock to fcntl), while users seek workarounds for tools like QEMU that expect exclusive locks on read-only images.

svcrdma Scalability Series

Chuck Lever submitted v2 of an 18-patch svcrdma performance series, introducing lock-free completion queues, deferred send context release, WR chaining, fair queuing for SQ access, and elimination of spurious transport enqueue attempts. No review comments yet this week.

VFS: inode->i_ino Widened to u64

Jeff Layton posted v3 of the treewide inode->i_ino widening series, condensed to 12 patches after abandoning the controversial kino_t/PRIino scaffolding from v2. Christoph Hellwig and Jan Kara provided Reviewed-by tags. This change will eventually allow NFS client cleanups including removal of nfs_inode.fileid, the enable_ino64 module parameter, and XOR-folding helpers.

SUNRPC Cleanup

Sean Chang submitted v2 of a dprintk macro simplification patch, removing redundant debug guards and leveraging compiler dead-code elimination, following feedback from Andy Shevchenko and David Laight.
