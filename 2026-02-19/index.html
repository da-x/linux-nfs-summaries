NFS Week 2026-02-19: Critical UAF Fix in NFSD Cache, Client KConfig Regression Patched, NLMv4 xdrgen Conversion Submitted

Week ending 2026-02-19

Critical Bugs and Fixes

NFSD Use-After-Free in SUNRPC Cache Show Callbacks

The most significant event this week was a critical use-after-free (UAF) bug reported by IBM's Misbah Anjum N, causing 100% reproducible kernel panics on ppc64le systems when diagnostic tools like sosreport read /proc/fs/nfsd/* files. The crash occurred in cache_check_rcu() within the SUNRPC cache layer, with faulting addresses decoding to ASCII strings such as "export_cap" and "libz.so." — classic signs of freed memory being reallocated. See thread/%3Cdcd371d3a95815a84ba7de52cef447b8%40linux.ibm.com%3E.md.

Chuck Lever responded the same day with a two-patch fix series addressing the root cause. The first patch replaces call_rcu/kfree_rcu with queue_rcu_work() to defer sub-object cleanup (path_put(), auth_domain_put()) until after the RCU grace period in process context, where sleeping is permitted. The second patch holds a network namespace reference for the lifetime of /proc/fs/nfs/exports file descriptors, preventing premature cache destruction during container teardown. See thread/%3C20260219215017.1769-1-cel%40kernel.org%3E.md.

NFS Client KConfig Regression: CONFIG_NFS_V4_0 Missing Default

Following the merge of Anna Schumaker's NFS client updates for Linux 7.0, Niklas Cassel reported a boot failure caused by a missing default y in the new CONFIG_NFS_V4_0 option. Users with nfsvers=4 on their kernel command line experienced root filesystem mount failures because make olddefconfig silently disabled NFS v4.0. Anna acknowledged the oversight and committed to issuing a fix. See thread/%3C20260212220625.358550-1-anna%40kernel.org%3E.md.

NFSv3 Client: Fix Oops on Directory Collision During Create

Roberto Bergantinos Corpas submitted a targeted fix for a kernel oops in the NFSv3 client's atomic open path. When concurrent create/remove operations caused d_splice_alias to return a directory alias, the original code silently discarded it and passed a negative dentry to do_dentry_open, triggering an oops. The patch adds an explicit d_is_dir() check returning -EISDIR. See thread/%3C20260219120440.766178-1-rbergant%40redhat.com%3E.md.

pNFS: Suppress Misleading "Server wrote zero bytes" Warning

Olga Kornievskaia submitted a patch to suppress a spurious "Server wrote zero bytes" kernel warning during pNFS I/O error recovery. When an I/O fails on a data server and is retried against the MDS, filelayout_reset_write() resets task->tk_status to 0, allowing the writeback completion path to fire the misleading warning despite no actual short write. Trond Myklebust suggested a refined guard checking !list_empty(hdr->pages). See thread/%3C20260219192327.34732-1-okorniev%40redhat.com%3E.md.

Kernel Panic on Repeated Failed NFSv4 mTLS Mounts

Debian maintainer Salvatore Bonaccorso forwarded a critical report of a kernel NULL pointer dereference in rcu_do_batch when repeatedly attempting to mount an NFSv4 share with mismatched mTLS certificates. A reproducer was provided, but no fix has been proposed yet. See thread/%3Cfdf293f1-ad7c-42c7-87b8-a2b4d338907a%40unibas.ch%3E.md.

Major Trends and Feature Development

NLMv4 XDR Modernization: 29-Patch xdrgen Conversion (v3)

Chuck Lever submitted version 3 of a massive 29-patch series converting the NFS Lock Manager (NLM) v4 XDR layer from hand-written code to xdrgen-generated functions. This refactoring improves memory safety, guarantees protocol compliance by construction, and paves the way for future Rust code generation. The series touches all NLMv4 procedures (TEST, LOCK, CANCEL, UNLOCK, GRANTED, MSG/RES variants, SM_NOTIFY, SHARE, UNSHARE, NM_LOCK, FREE_ALL). Jeff Layton had previously reviewed v2 positively. See thread/%3C20260217220721.1928847-1-cel%40kernel.org%3E.md.

Exposing Case Folding Behavior (v8)

Chuck Lever submitted version 8 of a 17-patch series introducing VFS-level case sensitivity introspection via file_kattr flags (FS_XFLAG_CASEFOLD, FS_XFLAG_CASENONPRESERVING). This enables NFSD and ksmbd to accurately report filesystem case semantics to clients — critical for Windows NFS client interoperability (the ms-nfs41-client project requires FATTR4_WORD0_CASE_INSENSITIVE = TRUE). The series covers FAT, exFAT, NTFS, HFS/HFS+, ext4, XFS, f2fs, CIFS, VBoxSF, ISO9660, and adds NFS client support for re-export scenarios. Theodore Ts'o provided an Acked-by for the ext4 patch. See thread/%3C20260217214741.1928576-1-cel%40kernel.org%3E.md.

NFSv4 ACL Passthru for Reexport (RFC)

Mike Snitzer submitted an 11-patch RFC enabling full NFS v4.1 ACL (DACL and SACL) passthrough in reexport scenarios where NFSD v4.1 serves over an NFS v4.2 mount. The patchset adds EXPORT_OP_NFSV4_ACL_PASSTHRU to bypass knfsd's lossy ACL mapping when the backend supports it. Chuck Lever and Trond Myklebust provided early feedback on patch structure and POSIX ACL considerations. See thread/%3C20260219221352.40554-1-snitzer%40kernel.org%3E.md.

NFSD Layout Recall Timeout and Lease Fencing (v11/v12)

Dai Ngo submitted v11 of a patch enforcing timeouts on pNFS layout recalls and integrating lease manager fencing to prevent nfsd thread exhaustion. Chuck Lever identified two critical bugs: a jiffies calculation error (absolute vs. relative timeout passed to wait_event_interruptible_timeout()) and a reference counting race condition in the fence worker. Both were acknowledged for v12. See thread/%3C20260213083101.3692692-1-dai.ngo%40oracle.com%3E.md.

NFS Client and nfs-utils Activity

Writeback Internal Cleanup Applied to vfs.git

Kundan Kumar's four-patch series converting the NFS client (along with f2fs and gfs2) away from direct writeback internals access was applied to vfs.git by Christian Brauner. The NFS-specific patch replaces WB_WRITEBACK accounting with new helper APIs, preparing for upcoming parallel writeback infrastructure. See thread/%3C20260213054634.79785-1-kundan.kumar%40samsung.com%3E.md.

rpc.gssd Enctype Handling Rework (RFC)

Scott Mayhew submitted a four-patch RFC addressing XDR decoding failures (-EIO during readdir()) on NFSv4 clients using SHA-2 encryption types with Kerberos constrained delegation. The root cause is an enctype mismatch between machine and user credentials when the krb5 library's referral processing selects different encryption type priorities. The fix computes the intersection of allowed enctypes from three sources (nfs.conf, kernel upcall, krb5 library) and orders them per krb5 preferences. See thread/%3C20260213224012.2608126-1-smayhew%40redhat.com%3E.md.

nfs-utils 2.8.5 Git Tag Pushed

Steve Dickson pushed the missing git tag for nfs-utils 2.8.5 after a downstream inquiry from Debian's Salvatore Bonaccorso, resolving packaging concerns. See thread/%3Cfdf3631f-e924-4e4c-bd9f-db5b40a90bfe%40redhat.com%3E.md.

nfs-utils Const-Correctness Fix

Rudi Heitbaum submitted a fix for -Wdiscarded-qualifiers warnings in mount.nfs's device name parser, where destructively modified strings were declared const. See thread/%3CaZFwJmiqqLgWYSl6%401eac07209f0d%3E.md.

Ongoing Debates and LSF/MM Topics

Several LSF/MM/BPF topic submissions were posted this week, including VFS idmappings support in NFS, namespace-aware upcalls from kernel filesystems, support to split superblocks during remount, and distributed file locking. A user inquiry about mount options to reject non-case-insensitive NFS shares also appeared. These discussions set the agenda for upcoming conference sessions.
