NFSD Layout Recall Timeout: v11 Withdrawn, Replacement Pending

Bridge from Prior Week

Last week (ending 2026-02-12), Dai Ngo posted [PATCH v11 1/1] NFSD: Enforce timeout on layout recall and integrate lease manager fencing [id://20260212222403.3305141-1-dai.ngo@oracle.com], the eleventh iteration of a patch addressing critical server-side reliability issues in NFSD's pNFS block layout recall handling. v11 incorporated fixes for a severe __break_lease timestamp wrap-around bug identified by Chuck Lever, improved per-client logging, and documentation updates. The patch had been under extensive review with Jeff Layton and Chuck Lever since early January.

This Week's Activity (Feb 13–19)

This week's activity in this thread was minimal. On February 13, Dai Ngo issued a brief withdrawal of v11:

"Please ignore this version. I'll send out a replacement." [id://3f466f3f-71c3-4581-98cb-08502712216c@oracle.com]

No replacement patch has appeared in the thread within this week's window, and no further discussion or review commentary was posted.

Discussion Type

Bug fix / reliability enhancement for NFS server (NFSD) pNFS layout recall handling — specifically preventing nfsd thread starvation during layout conflicts and integrating SCSI Persistent Reservation fencing to prevent data corruption.

Key Technical Context (from v11, carried forward)

The patch series addresses a fundamental problem: when a pNFS block layout conflict triggers a recall, unresponsive or malicious clients can cause nfsd threads to block indefinitely in __break_lease. Dai Ngo explained the motivation:

"When a layout conflict triggers a recall, enforcing a timeout is necessary to prevent excessive nfsd threads from being blocked in __break_lease ensuring the server continues servicing incoming requests efficiently." [id://20260212222403.3305141-1-dai.ngo@oracle.com]

The v11 patch introduced a lm_breaker_timedout callback in the VFS lease_manager_operations, triggering asynchronous SCSI PR PREEMPT fencing when layout recalls time out, while keeping the conflicting lease on the list until fencing completes. It also fixed a critical latent bug in __break_lease where an expired fl_break_time could cause unsigned wrap-around and a tight spin loop — potentially hanging uniprocessor systems.

Status and Outlook

  • v11 has been withdrawn by its author on February 13 [id://3f466f3f-71c3-4581-98cb-08502712216c@oracle.com].
  • A replacement version (presumably v12) has been promised but not yet posted within this week's window.
  • The thread is awaiting the next patch submission and subsequent review from Jeff Layton, Chuck Lever, and the broader NFS community.
