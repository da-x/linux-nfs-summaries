nfs-utils: Fix const qualifier warnings in conffile parsing

Overview

This thread consists of a single patch submission addressing compiler warnings in the nfs-utils configuration file parser. The discussion is categorized as a bug fix, specifically targeting code quality and compiler warning suppression rather than functional behavior changes.

Technical Details

Rudi Heitbaum submitted a two-part patch series (this being the second part) to resolve -Wdiscarded-qualifiers warnings in support/nfs/conffile.c. The issue arose because a variable named end was being reused for two different purposes:

  1. As the return value from strchr(line, '='), where line is a const char *
  2. As the return value from strchr(name, ':'), where name is a non-const char * (from strdup)

The compiler flagged this at two locations:

"conffile.c:1711:13: warning: assignment discards 'const' qualifier from pointer target type [-Wdiscarded-qualifiers]"

"conffile.c:1825:13: warning: assignment discards 'const' qualifier from pointer target type [-Wdiscarded-qualifiers]"

The Fix

The solution introduced a separate const char * pointer for the first case (operations on the const line variable), thereby preserving type correctness and eliminating the warnings. As Heitbaum explained:

"Declare a const char * pointer for use in the first case, addressing the warning."

This is a minimal, surgical fix affecting only 10 lines in one file (support/nfs/conffile.c), with 6 insertions and 4 deletions.

Significance

While not altering runtime behavior, this fix improves code hygiene and ensures cleaner builds when compiling with strict warning flags. Such fixes are important for NFS client development as they:

  • Prevent potential future bugs related to const-correctness violations
  • Maintain build cleanliness across different compiler configurations
  • Demonstrate attention to detail in the nfs-utils user-space tooling

No further discussion or review comments were recorded in this window, suggesting either quick acceptance or that this patch was part of a series where broader context was discussed elsewhere.
