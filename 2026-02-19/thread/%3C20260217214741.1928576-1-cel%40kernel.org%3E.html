Exposing Case Folding Behavior: V8 Patch Series Submitted

Summary

This thread captures the submission of version 8 of Chuck Lever's patch series titled [PATCH v8 00/17] Subject: Exposing case folding behavior 20260217214741.1928576-1-cel@kernel.org. The series introduces a VFS-level mechanism for filesystems to report their case sensitivity and case preservation behavior, enabling NFS server (NFSD), SMB server (ksmbd), and user-space file servers to accurately advertise these attributes to clients.

Classification: New Feature / Protocol Enhancement

This is primarily a new feature that enhances the Linux VFS with case-folding introspection capabilities. It also includes important improvements for NFS client interoperability with non-POSIX systems (Windows, macOS) and corrects long-standing inaccuracies in NFSD's reporting of filesystem semantics.

Background and Motivation

Chuck Lever explains that the Linux NFS community has a growing interest in supporting NFS clients on Windows and macOS platforms, where filename behavior does not align with traditional POSIX semantics:

"The Linux NFS community has a growing interest in supporting NFS clients on Windows and MacOS platforms, where file name behavior does not align with traditional POSIX semantics."

A key driver is interoperability with Windows-based NFS clients. Lever cites the ms-nfs41-client project, which explicitly requires servers to report FATTR4_WORD0_CASE_INSENSITIVE = TRUE:

"This client implementation explicitly requires servers to report FATTR4_WORD0_CASE_INSENSITIVE = TRUE for proper operation, a hard requirement for Windows client interoperability because Windows applications expect case-insensitive behavior."

When an NFS client knows the server is case-insensitive, it can optimize operations by avoiding multiple LOOKUP/READDIR requests to search for case variants. Additionally, Lever notes that even the Linux client benefits from this information:

"Even the Linux client can take advantage of this information. Trond merged patches 4 years ago that introduce support for case insensitivity... In particular, when a client detects a case-insensitive NFS share, negative dentry caching must be disabled (a lookup for 'FILE.TXT' failing shouldn't cache a negative entry when 'file.txt' exists) and directory change invalidation must clear all cached case-folded file name variants."

The series also addresses multi-protocol environments where NFSD and ksmbd coexist:

"Hammerspace servers and several other NFS server implementations operate in multi-protocol environments, where a single file service instance caters to both NFS and SMB clients. In those cases, things work more smoothly for everyone when the NFS client can see and adapt to the case folding behavior that SMB users rely on and expect."

Technical Overview of the Patch Series

The 17-patch series touches 42 files with 346 insertions and 37 deletions. The key components are:

VFS Infrastructure (Patches 01-02)

  • Patch 01/17 20260217214741.1928576-2-cel@kernel.org: Moves file_kattr initialization from helper functions to callers, preventing zeroing of pre-set flags.
  • Patch 02/17 20260217214741.1928576-3-cel@kernel.org: Adds FS_XFLAG_CASEFOLD and FS_XFLAG_CASENONPRESERVING flags to file_kattr, exposed via FS_IOC_FSGETXATTR ioctl and file_getattr() syscall.

Filesystem Implementations (Patches 03-14)

Each supported filesystem implements fileattr_get to report its case behavior:

  • FAT/exFAT/NTFS/HFS/HFS+/ext4/XFS/f2fs/CIFS/VBoxSF/ISO9660: All implement reporting of case sensitivity and preservation.
  • Notable details: ext4 and f2fs support per-directory case folding; FAT respects the nocase mount option; NTFS is case-sensitive by default but supports nocase.

NFS Client Support (Patch 11/17)

Patch 11/17 20260217214741.1928576-12-cel@kernel.org is particularly relevant for NFS client development:

"An NFS server re-exporting an NFS mount point needs to report the case sensitivity behavior of the underlying filesystem to its clients. Without this, re-export servers cannot accurately convey case handling semantics, potentially causing client applications to make incorrect assumptions about filename collisions and lookups."

The NFS client already retrieves case sensitivity information via PATHCONF (NFSv3) or FATTR4_CASE_INSENSITIVE/FATTR4_CASE_PRESERVING attributes (NFSv4). This patch exposes that information through the VFS fileattr_get interface, enabling re-export scenarios. NFSv2 mounts default to POSIX behavior (case-sensitive, case-preserving) due to lack of PATHCONF support.

NFSD Enhancements (Patches 15-16)

  • Patch 15/17 20260217214741.1928576-16-cel@kernel.org: Replaces the hard-coded MSDOS_SUPER_MAGIC check in NFSv3 PATHCONF with a query to ->fileattr_get, allowing accurate reporting for any filesystem that implements the interface.
  • Patch 16/17 20260217214741.1928576-17-cel@kernel.org: Fixes NFSD's NFSv4 responses, which previously hard-coded all exports as case-sensitive and case-preserving:

"NFSD currently provides NFSv4 clients with hard-coded responses indicating all exported filesystems are case-sensitive and case-preserving. This is incorrect for case-insensitive filesystems and ext4 directories with casefold enabled."

ksmbd Support (Patch 17/17)

Patch 17/17 20260217214741.1928576-18-cel@kernel.org adds case sensitivity reporting to the in-kernel SMB server via FS_ATTRIBUTE_INFORMATION.

Discussion and Feedback This Week

The only response within this week's window came from Theodore Ts'o, maintainer of ext4, who reviewed Patch 08/17:

"Acked-by: Theodore Ts'o tytso@mit.edu" 20260219131441.GA69183@macsyma-wired.lan

Evolution of the Series

Chuck Lever documented significant changes across eight versions:

  • v8: Split file_attr initialization into a separate patch.
  • v7: Removed memset from vfs_fileattr_get.
  • v6: Converted to FS_XFLAGs; NFSv4 GETATTR clears attr mask bit on failure.
  • v5: Observed MSDOS nocase mount option; defined new FS_XFLAGs for user API.
  • v4: Renamed fa->case_preserving to fa_case_nonpreserving; confirmed VFAT is case-preserving; exposed fields to user space.
  • v3: Removed unicode labels; replaced vfs_get_case_info; added more filesystems and ksmbd support.
  • v2/RFC: Switched from statx to file_getattr; postponed Unicode version exposure; added NTFS, ext4, NFSv4 support.

Conclusions

This thread marks the submission of a mature, well-tested patch series that addresses a fundamental gap in Linux's ability to expose filesystem case semantics to network file servers and user-space applications. Key takeaways:

  1. NFS client interoperability is improved: Windows and macOS NFS clients can now rely on accurate case sensitivity reporting from NFSD, enabling correct operation without workarounds.
  2. Re-export scenarios are supported: The NFS client's fileattr_get implementation allows re-export servers to propagate case behavior from upstream NFS mounts.
  3. NFSD correctness is enhanced: Hard-coded assumptions about filesystem case behavior are replaced with dynamic queries, supporting per-directory case folding in ext4 and f2fs.
  4. Broad filesystem coverage: The series supports FAT, exFAT, NTFS, HFS, HFS+, ext4, XFS, CIFS, f2fs, VBoxSF, and ISO9660, with default POSIX semantics for unsupported filesystems.

The series is poised for integration pending final reviews from VFS and filesystem maintainers.
