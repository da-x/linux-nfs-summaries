Treewide warning fixes in NFS flexfile and nfs4proc

Summary

Overview

This thread comprises a single unsolicited patch submission by Sean Chang aimed at resolving compiler warnings in the NFS client codebase. The discussion is focused on bug fixes (specifically, warning cleanups) rather than new features or protocol changes. No replies were received during this week's window.

Key Technical Details

Sean Chang submitted a treewide patch addressing two categories of compiler warnings: unused variable and format-truncation warnings. The NFS-related changes target three files within the NFS client subsystem:

  1. fs/nfs/flexfilelayout/flexfilelayout.c: Added __maybe_unused to the variable err.
  2. fs/nfs/flexfilelayout/flexfilelayoutdev.c: Added __maybe_unused to the variable ret.
  3. fs/nfs/nfs4proc.c: Added __maybe_unused to the variable ptr.

The patch also includes a fix for the MACB network driver (drivers/net/ethernet/cadence/macb_main.c) to use a precision specifier in snprintf, ensuring strings fit within ETH_GSTRING_LEN (32 bytes).

As described by the author:

"Address several compiler warnings across NFS and MACB drivers to enable a cleaner build"

Conclusion

The thread highlights a routine maintenance effort to silence compiler warnings in the NFS flexfile layout and NFSv4 procedure handling code.
