NFS Server UAF Fix: Deferred Cleanup in Cache Show Callbacks

Summary

Addressing Use-After-Free in NFS Server Cache Show Callbacks

Classification: Critical Bug Fix (NFS Server / SUNRPC)

This thread presents a two-patch series from Chuck Lever addressing a critical use-after-free (UAF) bug in the NFS server (nfsd) subsystem. The patches are a direct response to a crash report filed earlier this week by Misbah Anjum N, who documented 100% reproducible kernel panics on ppc64le systems when diagnostic tools read /proc/fs/nfsd/* files.

Background: The Crash Report

Earlier this week, Misbah Anjum N reported a severe regression in the SUNRPC cache layer:

"I'm reporting a critical use-after-free bug in linux-next NFS server code that causes kernel crashes when sosreport reads /proc/fs/nfsd/* files. This appears to be a recent regression affecting ppc64le systems." dcd371d3a95815a84ba7de52cef447b8@linux.ibm.com

The crashes manifested as NULL pointer dereferences in d_path() and corrupted pointer accesses in cache_check_rcu(), with faulting addresses decoding to ASCII strings like "export_cap" and "libz.so." — classic indicators of freed memory being reallocated.

Chuck Lever noted that a prior fix had addressed one instance of this UAF class, but additional instances remained:

"That fix addressed one instance of this problem; there are actually several more, all in the same UAF class. I have a patch series nearly complete to address these issues."

The Patch Series

Chuck Lever submitted a two-patch series titled [PATCH v1 0/2] Address UAF in sunrpc cache show callbacks 20260219215017.1769-1-cel@kernel.org, describing the effort as follows:

"Attempt to address three crashes reported here."

He noted the patches were compile-tested and regression-tested, but required validation on PowerPC hardware:

"as I do not have a PowerPC system handy, I will need someone who has one to test whether they actually address the crashes."

Patch 1/2: Defer Sub-Object Cleanup in Export Put Callbacks

Subject: NFSD: Defer sub-object cleanup in export put callbacks

This patch addresses the core race condition. The problem lies in svc_export_put(), which calls path_put() and auth_domain_put() immediately when the last reference drops — before the RCU grace period expires. Meanwhile, RCU readers in e_show() and c_show() access ex_path (via seq_path/d_path) and ex_client->name (via seq_escape) without holding a reference. If cache_clean removes the entry and drops the last reference concurrently, sub-objects are freed while still in use:

"RCU readers in e_show() and c_show() access both ex_path (via seq_path/d_path) and ex_client->name (via seq_escape) without holding a reference. If cache_clean removes the entry and drops the last reference concurrently, the sub-objects are freed while still in use, producing a NULL pointer dereference in d_path."

A previous fix (commit 2530766492ec) had moved kfree of ex_uuid and ex_stats into the call_rcu callback, but left path_put() and auth_domain_put() running before the grace period because those operations may sleep and call_rcu callbacks execute in softirq context.

The Solution: Replace call_rcu/kfree_rcu with queue_rcu_work(), which defers the callback until after the RCU grace period and executes it in process context where sleeping is permitted:

"Replace call_rcu/kfree_rcu with queue_rcu_work(), which defers the callback until after the RCU grace period and executes it in process context where sleeping is permitted. This allows path_put() and auth_domain_put() to be moved into the deferred callback alongside the other resource releases."

The patch also applies the same fix to expkey_put(), which exhibits the identical pattern with ek_path and ek_client. A dedicated workqueue scopes the shutdown drain to only NFSD export release work items, avoiding stalls on unrelated subsystem work.

Fixes cited:

  • c224edca7af0 ("nfsd: no need get cache ref when protected by rcu")
  • 1b10f0b603c0 ("SUNRPC: no need get cache ref when protected by rcu")

Patch 2/2: Hold Net Reference for Lifetime of /proc/fs/nfs/exports fd

Subject: NFSD: Hold net reference for the lifetime of /proc/fs/nfs/exports fd

This patch addresses a second, related UAF scenario involving network namespace teardown. The /proc/fs/nfs/exports proc entry is created at module init and persists for the module's lifetime. However, exports_proc_open() captures the caller's current network namespace without taking a reference on it:

"If the namespace is subsequently torn down (e.g. container destruction after the opener does setns() to a different namespace), nfsd_net_exit() calls nfsd_export_shutdown() which frees the cache. Subsequent reads on the still-open fd dereference the freed cache_detail, walking a freed hash table."

The Solution: Hold a reference on struct net for the lifetime of the open file descriptor:

"Hold a reference on the struct net for the lifetime of the open file descriptor. This prevents nfsd_net_exit() from running -- and thus prevents nfsd_export_shutdown() from freeing the cache -- while any exports fd is open."

The patch leverages the fact that cache_detail already stores its net pointer (cd->net, set by cache_create_net()), so exports_release() can retrieve it without additional per-file storage.

Fixes cited:

  • 96d851c4d28d ("nfsd: use proper net while reading "exports" file")

Technical Evolution and Key Arguments

The Root Cause Class

Both patches address bugs introduced by an optimization that removed explicit cache reference counting under the assumption that RCU protection was sufficient. As Chuck Lever's commit messages indicate, commits c224edca7af0 and 1b10f0b603c0 eliminated reference-taking in certain code paths with the rationale "no need get cache ref when protected by rcu." However, this reasoning overlooked cases where:

  1. Sub-objects (paths, auth domains) require sleeping operations for cleanup, which cannot be performed in RCU callback context.
  2. File descriptors outlive their originating network namespace.

The Deferred Cleanup Pattern

The introduction of queue_rcu_work() represents a significant architectural refinement. By deferring cleanup to process context after the RCU grace period, the patch ensures that:

  • All RCU readers have completed before any sub-object is freed.
  • Sleeping operations (path_put(), auth_domain_put()) can be safely performed.
  • A dedicated workqueue prevents shutdown stalls on unrelated subsystems.

Conclusions

This thread documents a targeted, high-severity bug fix for use-after-free vulnerabilities in the NFS server's SUNRPC cache layer. The key takeaways are:

  1. The bug is critical and reproducible: Kernel panics occur 100% of the time when diagnostic tools access /proc/fs/nfsd/* on affected systems (ppc64le confirmed, ARM64 also reported internally).

  2. The root cause is a class of RCU-related UAF bugs: Optimizations that removed reference counting under the assumption of RCU protection introduced races between cache cleanup and proc file reads.

  3. The fix employs deferred workqueue-based cleanup: By using queue_rcu_work() instead of call_rcu, Chuck Lever ensures sub-object cleanup occurs safely in process context after the RCU grace period.

  4. Network namespace lifetime must be tied to fd lifetime: Holding a net reference for the duration of an open /proc/fs/nfs/exports file descriptor prevents premature cache destruction during container teardown.

  5. Validation on PowerPC hardware is pending: Chuck Lever explicitly requested testing from PowerPC maintainers, as he lacks access to such systems.

The patches modify three files (fs/nfsd/export.c, fs/nfsd/export.h, fs/nfsd/nfsctl.c) with 78 insertions and 14 deletions, representing a focused but impactful correction to NFS server stability.
