NFS Server Performance Regression: Delegated Timestamps Removal Causes 15.2% Postmark Drop

NFS Server Performance Regression: Delegated Timestamps Removal Causes 15.2% Postmark Drop

Classification: Performance Regression Report (NFS Server)

This thread consists of a single automated report from Intel's 0-DAY CI kernel test service, flagging a significant performance regression in the NFS server (nfsd) subsystem triggered by recent changes to delegated timestamp handling. No developer responses were recorded during this week's window.

The Report

On February 13, the kernel test robot (Oliver Sang) filed an automated alert titled:

"[cel:nfsd-testing] [nfsd] e491b8e430: postmark.transactions 15.2% regression" 202602130940.4cf74a62-lkp@intel.com

The report identifies a 15.2% regression in postmark.transactions — a standard filesystem microbenchmark measuring file creation, reading, appending, and deletion throughput — on NFSv4 mounts. The regression was attributed to two commits in Chuck Lever's nfsd-testing branch:

  1. 49b14981e9 ("nfsd: add a runtime switch for disabling delegated timestamps")
  2. e491b8e430 ("nfsd: remove NFSD_V4_DELEG_TIMESTAMPS Kconfig option")

The test was run on a 224-thread, 4-socket Intel Xeon Platinum 8380H system with ext4-backed NFSv4 exports, using gcc-14 and the x86_64-rhel-9.4 kernel configuration.

NFS Statistics — Notable Shifts

Several NFSv4 operation counters show striking changes that point to the root cause:

  • nfsstat.Server.nfs.v4.operations.setattr: Increased from 1.00 to 3,381 (+340,000%)
  • nfsstat.Server.nfs.v4.operations.setattr.percent: From 0.00% to 3.09% (+180,000%)
  • nfsstat.Client.nfs.v4.open_noat: Increased from 1,417 to 1,714 (+21.0%)
  • nfsstat.Client.nfs.v4.delegreturn: Increased from 3,655 to 4,058 (+11.0%)
  • nfsstat.Server.nfs.v4.operations.getattr: Increased from 11,939 to 12,607 (+5.6%)

The massive spike in setattr operations is particularly telling: it suggests that the removal of delegated timestamps forced the NFS server to process far more attribute-update operations that were previously handled via delegation mechanisms. The increase in delegation returns (delegreturn) further indicates that clients are being recalled more frequently, adding round-trip overhead.

System-Level Impact

The regression also manifested at the system level:

  • perf-stat.total.instructions: +16.6% (more CPU work)
  • turbostat.IRQ: +17.2% (higher interrupt load)
  • numa-meminfo.node0.FilePages: +2,523% (significant memory pressure shift)

Context: What Changed?

The two commits under scrutiny represent a refactoring of the NFS server's delegated timestamp feature:

  1. Commit 49b14981e9 introduced a runtime switch for disabling delegated timestamps, replacing compile-time control with a dynamic knob.
  2. Commit e491b8e430 removed the NFSD_V4_DELEG_TIMESTAMPS Kconfig option entirely, making the feature always available but governed by the new runtime switch.

The intent was to simplify configuration and allow administrators to toggle delegated timestamp behavior without rebuilding the kernel. However, the automated benchmarking reveals that the default behavior after this change incurs a substantial performance penalty on the postmark workload — likely because the runtime switch defaults to a state where delegated timestamps are less aggressively utilized, or because the implementation of the runtime control introduces overhead.

Conclusions

This thread documents an automated performance regression report with no developer discussion during this week's window. Key takeaways:

  1. The regression is significant: A 15.2% drop in postmark transactions, with elapsed time increasing by 17.3%, represents a meaningful performance loss for NFSv4 file operations.

  2. The root cause appears to be increased setattr overhead: The 340,000% increase in server-side setattr operations strongly suggests that delegated timestamps — which previously allowed clients to update timestamps locally without server round-trips — are no longer being utilized as effectively after the Kconfig removal and runtime switch introduction.

  3. Delegation recall pressure increased: The 11% rise in delegation returns indicates more frequent client recalls, adding network overhead.

  4. No developer response yet: As of this week's close, no NFS maintainers have responded to the report. The regression was flagged for tracking with:
