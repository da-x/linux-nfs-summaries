nfs-utils: Fix const-correctness in mount.nfs parser

Summary

nfs-utils: Fix const-correctness warnings in mount.nfs device parser

This week, Rudi Heitbaum submitted a targeted bug fix for the NFS userspace utilities, specifically addressing compiler warnings in the mount.nfs device name parsing logic.

Classification

Bug Fix: Const-correctness and warning suppression in nfs-utils.

Technical Summary

The patch addresses -Wdiscarded-qualifiers warnings generated during the compilation of utils/mount/parse_dev.c. The core issue was that the dev variable, representing the device name, was passed as a const pointer to parsing functions (nfs_parse_simple_hostname, nfs_parse_square_bracket, etc.), but these parsers destructively modified the string (e.g., using strchr and subsequent manipulation).

As explained by Rudi Heitbaum in the commit message:

"dev is passed by nfs_parse_devname to nfs_parse_... as a copy of the device name, the parser destructively modifies dev, so pass as non const so that it can be modified without warning." aZFwJmiqqLgWYSl6@1eac07209f0d

The warnings cited included:

  • parse_dev.c:89:15: assignment discards 'const' qualifier in nfs_parse_simple_hostname
  • parse_dev.c:100:15: assignment discards 'const' qualifier in nfs_parse_simple_hostname
  • parse_dev.c:146:16: assignment discards 'const' qualifier in nfs_parse_square_bracket

Evolution and Conclusion

This was a standalone patch submission (part 1 of 2, though only this message appears in the current window). There were no replies or further discussion recorded in this week's window. The fix is straightforward: removing the const qualifier from the pointer target where destructive modification occurs, thereby aligning the code with its actual behavior and silencing compiler warnings without altering logic.

This type of maintenance ensures that nfs-utils compiles cleanly under stricter warning flags, improving code quality and maintainability for NFS client development.
