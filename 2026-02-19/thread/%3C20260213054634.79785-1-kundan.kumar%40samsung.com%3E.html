NFS Client Writeback Internal Cleanup Applied to vfs.git

Summary

NFS Client Writeback Internal Cleanup: Patch Series Applied to vfs.git

Classification: Code Refactoring / API Cleanup (NFS Client)

This thread covers the submission and subsequent application of a four-patch series by Kundan Kumar (Samsung) that introduces new writeback helper APIs and converts several filesystems — including NFS, f2fs, and gfs2 — to stop accessing kernel writeback internals directly. For the NFS client, this represents a targeted architectural cleanup rather than a functional change or bug fix.

The Patch Series

On 2026-02-13, Kundan Kumar submitted [PATCH v2 0/4] Avoid filesystem references to writeback internals 20260213054634.79785-1-kundan.kumar@samsung.com, describing the motivation:

"The series introduces writeback helper APIs and converts f2fs, gfs2 and nfs to stop accessing writeback internals directly."

Kundan noted that this work follows earlier guidance from Christoph Hellwig:

"As suggested by Christoph [1], filesystem code that directly accesses writeback internals is split out"

He emphasized that the changes are purely structural:

"No functional changes intended."

The series consists of four patches, submitted on 2026-02-13:

  1. [PATCH v2 1/4] writeback: prep helpers for dirty-limit and writeback accounting 20260213054634.79785-2-kundan.kumar@samsung.com — Adds helper APIs needed by filesystems to avoid poking into writeback internals. This patch received Reviewed-by tags from Jan Kara, Jeff Layton, and Andreas Gruenbacher.

  2. [PATCH v2 2/4] f2fs: stop using writeback internals for dirty_exceeded checks 20260213054634.79785-3-kundan.kumar@samsung.com — Replaces direct dereferences of dirty_exceeded with the core helper bdi_wb_dirty_exceeded().

  3. [PATCH v2 3/4] gfs2: stop using writeback internals for dirty_exceeded check 20260213054634.79785-4-kundan.kumar@samsung.com — Converts gfs2 dirty_exceeded handling to use the writeback core helper.

  4. [PATCH v2 4/4] nfs: stop using writeback internals for WB_WRITEBACK accounting 20260213054634.79785-5-kundan.kumar@samsung.com — The NFS-specific patch, which converts NFS WB_WRITEBACK accounting to use the writeback helper, eliminating direct access to writeback internals.

NFS-Specific Changes

The fourth patch modifies two files within the NFS client:

  • fs/nfs/internal.h (2 lines changed)
  • fs/nfs/write.c (3 lines changed, net -1 line)

As described in the prior week's summary for this series, the design choice to pass an inode instead of a backing device info (bdi) pointer when modifying writeback accounting stats was intentional:

"Pass inode instead of bdi for modifying writeback accounting stats, will make it easier to select proper wb context for the upcoming parallel writeback patches."

This prepares the NFS client for future parallel writeback infrastructure changes.

Significance for NFS Client Development

While this thread does not address a bug or introduce new NFS functionality, it is part of an important kernel-wide architectural cleanup with implications for NFS client maintainability:

  1. Encapsulation: By removing direct references to writeback internals from filesystem code, the kernel reduces coupling between the VFS/writeback layer and individual filesystem implementations.
  2. Future-proofing: The inode-based API design explicitly prepares for upcoming parallel writeback patches, ensuring the NFS client will be compatible with those changes without further refactoring.
  3. Consistency: Aligning NFS with f2fs and gfs2 on this pattern establishes a uniform approach across multiple filesystems.

The series touches six files total (19 insertions, 7 deletions), with the NFS-specific changes being minimal but meaningful in terms of long-term code health.
