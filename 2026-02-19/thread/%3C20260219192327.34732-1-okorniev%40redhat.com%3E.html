pNFS: Suppress Misleading "Server wrote zero bytes" Warning on MDS Retry

Summary

pNFS: Improve Misleading "Server wrote zero bytes" Error on MDS Retry

Classification: Bug Fix (NFS Client / pNFS File Layout Driver)

This thread, initiated by Red Hat's Olga Kornievskaia on 2026-02-19, addresses a misleading kernel warning that surfaces during Parallel NFS (pNFS) I/O error recovery. The fix targets the NFS client's file layout driver and writeback path to suppress a spurious "Server wrote zero bytes" log message when an I/O operation is destined to be retried successfully against the Metadata Server (MDS).

The Problem

When a pNFS I/O error occurs, the Linux NFS client retries the operation against the MDS as a fallback. However, before this retry takes place, the kernel logs a warning:

"Server wrote zero bytes"

This message is misleading because the subsequent MDS retry will succeed, meaning there is no actual data loss or persistent failure. Administrators monitoring system logs may interpret this warning as evidence of ongoing storage issues when none exist.

Olga Kornievskaia explained the core issue in her patch submission:

"When a pnfs error occurs, the IO is retried against the MDS. However, the initial IO leads to the kernel logging 'Serer wrote zero bytes' when in fact the MDS IO will not fail and thus the error misleads administrators that the system is experiencing issues." 20260219192327.34732-1-okorniev@redhat.com

Her proposed fix recognizes that a "retry-against-MDS" type of error has occurred and suppresses the warning accordingly. The patch touches two files: fs/nfs/filelayout/filelayout.c and fs/nfs/write.c.

Review Discussion with Trond Myklebust

NFS client maintainer Trond Myklebust engaged promptly, questioning whether the fix was necessary given existing safeguards in the code. He pointed to a status check in nfs_pgio_result():

"Hmm... Is this needed? Shouldn't the test for task->tk_status < 0 in nfs_pgio_result() ensure that we can't call nfs_writeback_result() in the above case?" c6be70378ce90b3316c997bfc9443172eaa145c5.camel@hammerspace.com

Olga clarified the mechanism: the task->tk_status is reset to 0 by filelayout_reset_write() in the file layout driver, which calls pnfs_write_done_resend_to_mds(hdr). This means the error status is cleared before reaching nfs_writeback_result(), allowing the misleading warning to fire:

"task_status is 0 when it gets to nfs_writeback_done because in filelayout/filelayout.c in filelayout_reset_write() is doing this: task->tk_status = pnfs_write_done_resend_to_mds(hdr);" CAN-5tyFec2nw1=1-wsGYj4TnXmSbw4p+qW_1v9sPD+nPKiP1Gg@mail.gmail.com

Evolving the Fix

Trond then proposed a potentially cleaner approach. He questioned whether the short-write condition should even be entered when the page list is empty, suggesting a more targeted guard:

"Oh... So isn't the hdr->pages list actually empty? Should we even bother entering the short write condition when that happens?" 00f3d1fe8b61410ad2296d76f0603a51e8e9991b.camel@kernel.org

"IOW: Why not just change that test at the top of nfs_writeback_result() to read something like: if (resp->count < argp->count && !list_empty(hdr->pages))" 00f3d1fe8b61410ad2296d76f0603a51e8e9991b.camel@kernel.org

This alternative approach would prevent the warning from firing when no pages remain to be written — a condition that naturally occurs during pNFS MDS retry scenarios.

Key Technical Takeaways

  • Bug type: Misleading log message (not a data integrity or functional bug). The actual I/O succeeds via MDS retry; the issue is purely about noisy/incorrect kernel logging that could alarm administrators.
  • Root cause: The filelayout_reset_write() function resets task->tk_status to 0 when preparing for an MDS retry, which allows the writeback completion path to proceed and emit the "Server wrote zero bytes" warning despite no actual short write having occurred.
  • Proposed solutions: (1) Olga's original patch: explicitly check for a retry-against-MDS error before printing the warning. (2) Trond's suggested refinement: add a !list_empty(hdr->pages) guard to the short-write condition in nfs_writeback_result(), which would more directly address the underlying logic gap.
  • Status: The thread concluded with Trond's suggestion for an improved fix. No final resolution or patch acceptance was recorded within this week's window.
