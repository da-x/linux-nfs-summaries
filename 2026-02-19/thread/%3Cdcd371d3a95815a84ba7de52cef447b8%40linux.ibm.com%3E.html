NFS Server Use-After-Free in cache_check_rcu() on ppc64le

Summary

NFS Server Use-After-Free in cache_check_rcu() on ppc64le

Classification: Critical Bug Fix (NFS Server / SUNRPC)

This thread opens with a critical bug report from IBM's Misbah Anjum N, documenting a 100% reproducible use-after-free in the NFS server (nfsd) subsystem that triggers kernel panics on ppc64le systems when diagnostic tools read /proc/fs/nfsd/* files.

The Bug Report

On 2026-02-19, Misbah Anjum N filed a detailed bug report titled:

"[BUG] [powerpc] [next-20260216/17] nfsd: use-after-free in cache_check_rcu() triggered by sosreport on ppc64le" dcd371d3a95815a84ba7de52cef447b8@linux.ibm.com

The crash manifests in the SUNRPC cache layer function cache_check_rcu() when the sosreport diagnostic tool reads NFS export information from /proc. The reporter emphasized the severity and reproducibility:

"I'm reporting a critical use-after-free bug in linux-next NFS server code that causes kernel crashes when sosreport reads /proc/fs/nfsd/* files. This appears to be a recent regression affecting ppc64le systems."

"The bug is 100% reproducible and shows corrupted pointers containing ASCII strings (library names, export cache names) instead of valid kernel addresses, indicating freed memory has been reallocated."

Key Technical Details

  • Affected kernels: 6.19.0-next-20260216 and 6.19.0-next-20260217
  • Architecture: ppc64le (IBM Power11, 9080-HEX)
  • Trigger: Loading the nfsd module (modprobe nfsd) followed by running sosreport — no active NFS exports required.
  • Reproduction rate: 100%, typically crashing within 30–60 seconds.

The reporter provided three distinct crash traces:

  1. Crash #1 (kernel 6.19.0-next-20260216): Use-after-free in cache_check_rcu+0x44/0x2c0 [sunrpc], called from e_show+0x40/0x260 [nfsd]. The faulting address 0x657079745f70618b decodes to ASCII characters resembling "export_cap" — a telltale sign of freed memory being reallocated with user-space strings.

  2. Crash #2 (kernel 6.19.0-next-20260217): A NULL pointer dereference in d_path+0x44/0x210, called from seq_path → svc_export_show+0x1d4/0x5a0 [nfsd] → c_show+0xa4/0x1c0 [sunrpc].

  3. Crash #3 (kernel 6.19.0-next-20260217): Another cache_check_rcu() crash, this time with a faulting address 0x2e6o732e7a62696c that decodes to "libz.so." — again, freed memory containing library name strings.

The call traces consistently show the crash path flowing through:

sosreport → proc_reg_read → vfs_read → seq_read → seq_read_iter → e_show/c_show [nfsd/sunrpc] → cache_check_rcu [sunrpc]

Important Observations from the Reporter

  1. Direct cat /proc/fs/nfsd/exports does NOT trigger the crash
  2. The crash is triggered by sosreport's specific access pattern to /proc/fs/nfsd/* files
  3. No NFS exports or active NFS server configuration needed
  4. Reproducible 100% of the time with sosreport

The reporter noted they were pursuing two next steps: crash dump analysis and a git bisect to identify the offending commit.

Summary of Conclusions

This thread documents a critical use-after-free regression in the NFS server's SUNRPC cache layer, specifically in cache_check_rcu(). The bug:

  1. Causes kernel panics when diagnostic tools (like sosreport) read /proc/fs/nfsd/* files.
  2. Is 100% reproducible on ppc64le and also affects ARM64.
  3. Represents a class of UAF bugs in cache content file handlers — one instance was fixed in February, but additional instances remained unfixed at the time of this report.
  4. Was being actively addressed by Chuck Lever with a patch series to resolve all remaining instances of this UAF class.

The corrupted pointers containing ASCII strings (e.g., "export_cap", "libz.so.") provide strong evidence that freed kernel memory is being accessed after reallocation, a classic use-after-free pattern with serious security implications.
