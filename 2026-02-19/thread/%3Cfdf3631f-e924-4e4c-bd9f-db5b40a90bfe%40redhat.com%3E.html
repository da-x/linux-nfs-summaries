nfs-utils 2.8.5 Git Tag Pushed After Downstream Inquiry

Summary

This thread, initiated by Steve Dickson's nfs-utils 2.8.5 release announcement, concluded this week with a resolution to a downstream packaging concern raised by Debian maintainer Salvatore Bonaccorso. The discussion is purely administrative, concerning the availability of release artifacts in the nfs-utils git repository.

Bridge from Prior Weeks

  • Week ending 2026-02-05: Steve Dickson announced the release of nfs-utils 2.8.5, a maintenance and feature release headlined by the min-threads parameter for nfsdctl, systemd updates for rpc-statd-notify, and various bug fixes.
  • Week ending 2026-02-12: Debian maintainer Salvatore Bonaccorso raised a practical concern regarding the absence of a release tag in the git repository:

"While 2.8.5 was released, I do not see yet a release commit and tag in the git repository, is this correct?"

This Week's Activity

On February 14th, Steve Dickson responded to Salvatore's inquiry, acknowledging the oversight and confirming that the missing artifact had been pushed:

"Sorry I was traveling and forgot do the push... It is there now."

This brief exchange resolves the issue, ensuring that downstream packagers can now locate the proper release tag in the nfs-utils git repository for Debian and other distribution packaging workflows.

Classification

This is an administrative discussion regarding release process artifacts — not a new feature, protocol change, or bug fix. It touches on the intersection of upstream development practices and downstream distribution packaging needs.

Significance for NFS Development

While brief, this exchange underscores the importance of proper release hygiene in open-source projects. For distributions like Debian that package nfs-utils, having clear, tagged release commits is essential for reproducible builds and version tracking. The prompt resolution demonstrates the maintainers' responsiveness to downstream concerns.
