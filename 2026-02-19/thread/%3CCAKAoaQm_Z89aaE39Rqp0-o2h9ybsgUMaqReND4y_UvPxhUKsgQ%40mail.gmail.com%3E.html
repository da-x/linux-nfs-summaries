Windows NFSv4.1/4.2 Client Test Binaries and Interoperability Request

Summary

Windows NFSv4.1/4.2 Client Driver Binaries Released for Testing

This week, the Linux NFS mailing list saw a forwarded announcement regarding new test binaries for the ms-nfs41-client, an open-source NFSv4.1/NFSv4.2 filesystem client driver for Windows. The message, forwarded by Martin Wege to the linux-nfs list on February 15, originated from Roland Mainz on the ms-nfs41-client-devel SourceForge mailing list.

Nature of the Discussion

This thread is not a technical debate or bug-fix discussion within the Linux kernel community itself. Rather, it is an announcement and interoperability request for a third-party Windows NFS client driver. The primary goal was to solicit testing feedback, specifically regarding interoperability with modern Linux NFS servers.

"Please test the binaries... Interoperability feedback with NFSv4.1/NFSv4.2 servers based on Linux 6.6+ LTS and 6.19+/7.0 would be great."

Key Features in the New Release

The released binaries (based on git commit #7fb7932) support Windows 10/11 (x86, x86-64, ARM64) and Windows Server 2019/2022/2025. Martin Wege highlighted several new features as particularly significant for users interacting with Linux NFS servers:

"Windows Alternate Streams (Win32 streams) support, including winstreamsutil.exe, was added, xcopy.exe/cmd.exe copy/MS Explorer file copy acceleration via NFS server side copies and copy-by-block-cloning are IMO the most interesting new features... because it's 'on' by default for all Windows 11 applications which copy files."

Notable Technical Additions Relevant to Linux NFS Servers:

  • Server-Side Copy & Block Cloning: The client now implements FSCTL_OFFLOAD_READ and FSCTL_OFFLOAD_WRITE for server-side NFSv4.2 COPY operations. Additionally, it supports FSCTL_DUPLICATE_EXTENTS_TO_FILE for block cloning via the NFSv4.2 CLONE operation.
    • Compatibility note: Cloning works with "FreeBSD 14.3/15.0 nfsd and Linux nfsd exporting btrfs&xfs filesystems."
  • Sparse File Support: Requires NFSv4.2 server support for SEEK, ALLOCATE, and DEALLOCATE operations. The release notes mention fixing "issues probing sparse files when using the nfs-ganesha NFS server."
  • Win32 Alternate Data Streams (ADS): Mapped to NFS named attributes, allowing Windows-specific metadata storage on Linux exports (if the server supports named attributes).
  • ARM64 Support: Native aarch64 kernel modules and userland utilities are now included for Windows 11 ARM64.
  • Bug Fixes: Specific bugfixes were applied for FreeBSD NFS servers, but general stability improvements may benefit Linux interoperability as well.
  • Security & Compatibility: Binaries are now signed with a WDK test signature to mitigate false positives from Windows Defender. Support for sec=none was added.

Conclusion

This announcement serves as a call for cross-platform testing. For the Linux NFS community, the relevance lies in validating that modern Linux kernels (6.6 LTS through 7.0+) correctly handle the advanced NFSv4.2 features—particularly server-side copy, block cloning, and sparse file operations—when accessed by this Windows client driver. There were no replies or further technical discussions on the linux-nfs list within this week's window; the thread consists solely of this forwarded announcement.
