NFSd: Add CB_NOTIFY Support for Directory Delegations (v2)

Summary

This week's thread focuses on a significant new feature: adding support for CB_NOTIFY callbacks in directory delegations. Jeff Layton submitted a 28-patch series (PATCH v2 00/28) that enables NFS servers to notify clients of directory changes (creates, unlinks, renames) without recalling the delegation. This enhancement improves caching efficiency and reduces overhead for NFS clients.

Key Technical Arguments and Evolution

New Feature: CB_NOTIFY for Directory Delegations The series allows the server to send CB_NOTIFY callbacks for specific events, including updated directory attributes. Layton explained:

"With this support, the client can register interest in a directory and get notifications about changes within it without losing its lease."

The implementation involves:

  • Allowing the VFS to ignore certain directory change events for delegations.
  • Setting up fsnotify watches on directories to trigger CB_NOTIFY events.
  • Adding protocol support for CB_NOTIFY as proposed in RFC8881bis, including new NOTIFY4_* flags.

Bug Fixes in v2 Layton highlighted several critical bug fixes from v1:

  • Fixed __break_lease handling with different lease types on the flc_lease list.
  • Recalculated the fsnotify mask after unlocking the lease instead of before.
  • Avoided notifying the client that is making the changes.
  • Properly released nfsd_dir_fsnotify_group on server shutdown.

FSNOTIFY_EVENT_RENAME Data Type A new FSNOTIFY_EVENT_RENAME data type was introduced to handle cross-directory rename events, allowing the fsnotify event to include information about a file unlinked due to a rename. Amir Goldstein reviewed this patch (Re: PATCH v2 07/28), noting:

"It is strange to me that the NFS protocol needs to report the overwritten node in the same event of the rename, but oh well, fine by me."

Layton responded (Re: PATCH v2 07/28):

"Yeah, it's not very useful, but the protocol requires it. Unfortunately RFC5661 was written before anyone had made a real implementation of directory delegations."

Tracepoints and Debugging New tracepoints were added in fsnotify() and at the start of break_lease() to improve visibility into lease breaking and notification events, aiding in debugging and performance analysis.

Final Conclusions

  • The series is targeted for kernel v7.2.
  • Layton noted that while the patches have been tested with pynfs, full client-side implementation is needed before merging:

"I don't think we'll want to merge these until we have a complete client-side implementation to test against."

  • Amir Goldstein provided a Reviewed-by tag for the FSNOTIFY_EVENT_RENAME patch, indicating acceptance of the fsnotify changes.

This thread represents a major advancement in NFS server capabilities, enhancing directory delegation handling and providing a more robust notification mechanism for clients. The inclusion of bug fixes and improved debugging tools also strengthens the overall stability and maintainability of the NFS subsystem.
