NFS pNFS: Cache data server entries for a short grace period

Summary

Patch Series: Cache Data Server Entries for a Short Grace Period

Type: Bug fix / performance optimization in NFS client pNFS data server caching.

Overview

This week, Lei Yin from Lenovo submitted a single-patch series titled "[PATCH 0/1] NFS: pnfs: cache data server entries for a short grace period" introducing the patch. The series addresses a performance issue in the pNFS (parallel NFS) client's data server cache management, specifically targeting open/close-heavy workloads.

Problem Description

The existing behavior of the NFS pNFS client was to destroy data server cache entries immediately upon the last reference being dropped. As Lei Yin explained:

"Today, a data server cache entry is destroyed immediately when the last reference goes away. In open/close-heavy workloads, that can lead to repeated teardown and re-creation of the same data server cache entry when the same data server is reused again shortly afterwards."

This churn — repeatedly tearing down and recreating cache entries for the same data server — introduced measurable latency overhead in workloads with frequent file open/close cycles.

Proposed Solution

The patch introduces a short grace period during which a data server cache entry remains alive after its last reference is dropped. If the same data server is looked up again before the timeout expires, the existing entry is reused rather than being recreated from scratch. Additionally, since destruction is deferred, the patch also handles reaping of scheduled destroy work during network namespace (netns) teardown.

Performance Impact

Lei Yin reported significant improvements in testing:

"In testing with workloads that repeatedly open and close files, the additional read/write latency associated with repeated data server cache churn dropped from a few milliseconds, and in some runs tens of milliseconds, to under 100 microseconds."

This represents an order-of-magnitude improvement in scenarios where pNFS data servers are frequently accessed in rapid succession.

Discussion Status

As of the end of this week's window (2026-04-17), no replies or further discussion had been recorded on this thread. The patch series remains pending review by the NFS maintainer community.

Key Takeaway

This is a focused client-side optimization that reduces unnecessary cache churn in pNFS deployments, particularly benefiting workloads characterized by rapid file open/close cycles. The change is backward-compatible and introduces only a short deferred-destruction mechanism with proper cleanup during netns teardown.
