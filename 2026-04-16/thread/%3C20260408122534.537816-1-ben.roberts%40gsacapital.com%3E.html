pNFS: Maintainer Questions Upstream Validity of Deadlock Fix

Summary

pNFS: Deadlock fix in pnfs_send_layoutreturn — Maintainer Questions Upstream Validity

Overview

This thread concerns a bug fix proposed by Ben Roberts of GSA Capital to address recurring deadlocks in the Parallel NFS (pNFS) client's layout return path. The patch, submitted as v2 on April 8, was met with maintainer skepticism this week regarding its applicability to upstream code.

Prior Context

As summarized last week, Roberts reported that his HPC cluster running Red Hat Enterprise Linux 9 kernel 5.14.0-611.9.1.el9.x86_64 experienced regular deadlocks within pnfs_send_layoutreturn(), causing userspace processes to become stuck in uninterruptible sleep:

"On a HPC cluster running 5.14.0-611.9.1.el9.x86_64, regular deadlocks were seen within pnfs_send_layoutreturn leading to userspace processes stuck in uninterruptible sleep, ultimately requiring reboots to clear."

The proposed fix was a single-line change clearing the NFS_LAYOUT_RETURN_REQUESTED flag in the memory allocation failure path. Roberts noted the patch had been running in production for over three months without recurrence.

This Week's Activity

This week saw one message from NFS maintainer Benjamin Coddington, who raised fundamental questions about whether the issue was diagnosed against upstream code:

"Did you reproduce and diagnose this problem on a recent upstream kernel version? If not, you probably want to report the issue to your Red Hat support channel directly instead of sending fixes upstream because the maintainers will want to see patches and fixes against the upstream code." Benjamin Coddington

Coddington emphasized that the code in the EL9 kernel 5.14.0-611.9.1.el9 may exhibit different behaviors than current upstream, making it difficult for maintainers to validate the fix without an upstream reproduction.

Status

The patch remains under review, but no acceptance has occurred. The discussion underscores a recurring challenge in NFS client development: diagnosing race conditions on production systems running older, distribution-specific kernels that diverge from upstream. Roberts has indicated he will withdraw the patch and pursue further diagnostics (as confirmed in messages outside this week's window).

Conclusion

No code changes were merged this week. The thread highlights the importance of validating pNFS fixes against upstream kernels before submission, particularly when dealing with subtle race conditions in the layout return path.
