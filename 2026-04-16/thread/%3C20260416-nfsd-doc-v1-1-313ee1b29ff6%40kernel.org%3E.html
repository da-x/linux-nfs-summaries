NFSd: Fix missing kerneldoc function name for nfsd_nl_parse_one_export

Summary

NFS Server: Trivial Kerneldoc Fix for Export Netlink Parser

Classification

Bug Fix (Documentation) – A minor correction to a kernel-doc comment in the NFS server (nfsd) subsystem. This is not a protocol change or new feature, but rather a maintenance patch to silence compiler warnings during strict builds.

Discussion Summary

This thread consists of a single trivial patch submitted by Jeff Layton and promptly accepted by NFS maintainer Chuck Lever. The fix addresses kerneldoc warnings generated when building the kernel with Clang and the W=1 warning level enabled.

The Issue

Jeff Layton reported that Anna Schumaker encountered documentation warnings in fs/nfsd/export.c. Specifically, the compiler could not identify the function associated with a kerneldoc comment block because the function name was missing from the comment header. This resulted in errors such as:

"Warning: fs/nfsd/export.c:845 Cannot find identifier on line" "This comment starts with '/**', but isn't a kernel-doc comment."

The problematic comment block belonged to the function nfsd_nl_parse_one_export, which was introduced in a previous patch adding netlink upcall support for the svc_export cache.

The Fix

Layton submitted a one-line patch to add the missing function name to the kerneldoc comment, thereby resolving the warnings. He noted:

"Trivial doc fix. Feel free to fold into the Fixes patch if you get this before the sending the PR to Linus."

The patch references the original commit that introduced the issue: 9d2c4bbf7435 ("nfsd: add netlink upcall for the svc_export cache").

Resolution

Chuck Lever applied the patch to the nfsd-testing tree without further discussion, confirming:

"Applied to nfsd-testing, thanks!"

Key Technical Points

  • Subsystem: NFS Server (nfsd)
  • File Modified: fs/nfsd/export.c
  • Impact: Silences Clang W=1 kerneldoc warnings; no functional code change.
  • Context: Part of ongoing maintenance to ensure clean builds and accurate documentation for the netlink export cache infrastructure.

Conclusion

The discussion was brief and administrative, focusing solely on correcting a documentation formatting error. The fix ensures that automated documentation tools and strict compiler checks do not flag the nfsd_nl_parse_one_export function as malformed. This reflects the community's attention to build hygiene and documentation accuracy in the NFS subsystem.
