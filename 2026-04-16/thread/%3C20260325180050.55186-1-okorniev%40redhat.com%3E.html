NFS: Maintainer ACKs writeback error-loop fix with minor nitpick

Summary

NFS: Review feedback on writeback error-loop fix — minor nitpick, otherwise ACK

Classification

This is a bug fix targeting the NFS client's page cache writeback subsystem. The discussion this week centers on maintainer review of a patch that prevents infinite writeback retry loops when the server returns ENOSPC errors during unstable writes.

Prior Context (Brief)

In March, Olga Kornievskaia submitted v2 of her patch "NFS: fix writeback in presence of errors" 20260325180050.55186-1-okorniev@redhat.com, following an earlier RFC from March 12. The patch addresses two failure patterns discovered while running xfstest generic/751, where writeback I/O can become stuck in an infinite retry loop when the NFS server returns ENOSPC (out of space) errors during unstable writes.

The v2 approach stores a synchronous-writeback flag in the persistent nfs_open_context structure (rather than the transient nfs_page) and extends the fix to cover the LocalIO code path. The prior week's summary detailed the bug, the two failure patterns, and the architectural refinements from RFC to v2.

This Week's Activity

On April 13, Linux NFS client maintainer Trond Myklebust posted his review of the v2 patch 3f2666aec2649cc8cf2fc0524612b73936b3b17b.camel@kernel.org.

Maintainer Feedback: One Nitpick, Otherwise Approved

Myklebust's review is concise and largely positive. He raises a single code-quality concern regarding redundant function calls:

"Can we please do something to avoid 2 calls to iov_iter_count() here?"

This refers to a section in the patch where iov_iter_count() is invoked twice in close proximity — a minor inefficiency that Myklebust flags for cleanup. Beyond this nitpick, he gives the patch his approval:

"Otherwise, the rest looks good to me."

Significance for NFS Client Development

This review represents a critical milestone for the patch:

  1. Maintainer ACK: Trond Myklebust's positive assessment ("the rest looks good to me") effectively serves as an ACK from the Linux NFS client maintainer. The patch is now very close to being merged, pending only the minor iov_iter_count() cleanup.
  2. Bug Fix Maturity: The progression from RFC (March 12) → v2 (March 25) → maintainer review (April 13) demonstrates a thoughtful, iterative development process. The architectural shift from transient nfs_page state to persistent nfs_open_context state was validated by the maintainer without objection.
  3. Data Integrity Protection: Once merged, this fix will prevent application stalls and potential I/O deadlocks caused by infinite writeback loops under server-side ENOSPC conditions — a real-world scenario that xfstest generic/751 successfully exposed.

Conclusion

The discussion this week was brief but decisive: the NFS client maintainer approved Olga Kornievskaia's v2 patch with one minor code-efficiency request. The fix addresses a genuine reliability bug in the NFS client writeback path and is expected to be merged after the trivial iov_iter_count() duplication is addressed. This represents a successful example of test-driven bug discovery (via xfstest) leading to a well-reviewed, architecturally sound patch for the Linux NFS client.
