ext4 IS_ERR_OR_NULL Patch Applied by Theodore Ts'o

Summary

This week, ext4 maintainer Theodore Ts'o confirmed the application of [PATCH 04/61] from Philipp Hahn's 61-patch series to replace manual IS_ERR() + NULL checks with IS_ERR_OR_NULL(). This is a code cleanup / refactoring effort—not a new feature, protocol change, or NFS-specific bug fix.

Bridge from Prior Weeks

The broader series was submitted on March 10th by Philipp Hahn. The sole NFS-relevant patch in the series, [PATCH 30/61] net/sunrpc, was accepted in March with Reviewed-by tags from Jeff Layton and Chuck Lever. Subsequent weeks saw mounting criticism: Robin Murphy questioned the mechanical approach, Al Viro condemned the macro's proliferation as "crap," and Krzysztof Kozlowski identified a concrete bug introduced by one of the patches ([PATCH 55/61] interconnect) and rejected the Coccinelle script driving the automation. See the parent series summary for details on that evolving debate.

This Week's Activity: Application Confirmation

Theodore Ts'o posted a single message on April 10th, confirming that the ext4 patch was accepted:

"Applied, thanks!" Theodore Ts'o

The patch was committed as 1d749e110277ce4103f27bd60d6181e52c0cc1e3.

Key Technical Arguments

There were no technical arguments raised in this specific thread this week. The ext4 maintainer accepted the patch without controversy, contrasting with the heated debate surrounding other patches in the same series (particularly the interconnect and Coccinelle script patches).

This acceptance is notable because it demonstrates a divergence in maintainer attitudes: while some maintainers (like Ts'o for ext4) are comfortable accepting these mechanical cleanups, others (like Kozlowski and Viro) argue that IS_ERR_OR_NULL() obscures semantic distinctions between error pointers and NULL, potentially introducing bugs.

NFS Client Development Impact

No direct NFS impact this week. The NFS/sunrpc patch from this series was already accepted in March. This thread concerns only the ext4 filesystem subsystem. However, the broader discussion serves as a cautionary tale for NFS developers: mechanical refactoring of error-checking idioms can alter program semantics in subtle ways, particularly when WARN_ON() or other diagnostic macros are involved.

Final Conclusions

  • Patch Status: Applied to ext4 by Theodore Ts'o on April 10th.
  • NFS Relevance: None directly; the NFS/sunrpc patch was accepted weeks earlier.
  • Broader Context: This acceptance occurs against a backdrop of growing criticism of the IS_ERR_OR_NULL() macro and the Coccinelle script used to propagate it. The series remains controversial, with at least one confirmed bug introduced by mechanical replacement.
