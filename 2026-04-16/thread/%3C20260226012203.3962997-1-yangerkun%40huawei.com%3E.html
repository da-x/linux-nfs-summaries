Summary

NFS file-lock list UAF fix: ping for merge after Reviewed-by

Classification

This is a bug fix on the NFS client side, not a new feature or protocol change. It addresses a use-after-free (UAF) hazard during traversal of the per-inode file-lock list in delegation-claim and lock-reclaim paths.

Bridge from prior weeks

As summarized in February, Huawei's Yang Erkun opened this thread with an RFC patch to protect NFS file-lock list traversal using nfsi->rwsem instead of flc_lock. The bug — originally identified by Li Lingfeng — stems from the fact that functions like nfs_delegation_claim_locks and nfs4_reclaim_locks must release flc_lock to call blocking RPC code, creating a UAF window.

In March, maintainer Jeff Layton reviewed the patch and awarded it a Reviewed-by, noting:

"Nice work!"
"Reviewed-by: Jeff Layton jlayton@kernel.org"

Layton also ran an independent AI-assisted review, confirming no regressions. Erkun thanked him on March 10. Since then, the patch has been awaiting merge by the NFS subsystem maintainers.

This week's activity

This week saw a single message — a polite follow-up from Yang Erkun addressed to Anna Schumaker and Trond Myklebust:

"Could you please help check if there are any issues with this patch, and if there are none, could you help merge it in?" [id://163aebb3-4233-4aaa-872c-c36aa3fcb3af@huawei.com]

This is a straightforward request for the maintainers to take the final step and integrate the patch, now that it carries Jeff Layton's endorsement.

Key technical arguments (recap)

The fix rests on two pillars:

  1. Per-inode protection via nfsi->rwsem. The previous guard (so_delegreturn_mutex) is per-state-owner, but a single inode can carry multiple nfs4_state objects, allowing races between state owners on the same inode. Switching to nfsi->rwsem aligns with the already-established pattern in nfs4_reclaim_locks.

  2. Relocation of locks_lock_inode_wait. The call was moved out of async RPC callbacks (nfs4_lock_done, nfs4_locku_done) into the synchronous caller _nfs4_proc_setlk, so it can execute under nfsi->rwsem without risking deadlocks. Erkun argued this does not regress the original atomicity bug fixed by commit c69899a17ca4, because later commits (notably 0460253913e5) drain slots before reclaim, and the delegation-claim path sets the stateid only once.

Current status

The patch remains unmerged as of this week's close. With Jeff Layton's Reviewed-by secured in March and no objections raised over the intervening seven weeks, Erkun's April 16 ping is a gentle nudge to Anna Schumaker and Trond Myklebust to complete the merge. The discussion itself has reached a quiet conclusion — the technical arguments are settled, and the ball rests with the maintainers.
