NFS vmstat folio accounting cleanup

Summary

NFS vmstat folio accounting cleanup

This week saw a minor but welcome code quality improvement in the NFS client’s interaction with the memory management subsystem. The discussion centered on a patch series that modernizes how node statistics are updated when dealing with folios, specifically within fs/nfs/.

Technical Context: A Bug Fix / Cleanup?

While not fixing a runtime bug per se, this is a code cleanup and refactoring effort aimed at improving readability and correctness guarantees. The change replaces generic node_stat_mod_folio() calls with more specific node_stat_add_folio() and node_stat_sub_folio() helpers.

Evolution of the Discussion

The thread began with Ye Liu submitting [PATCH 1/4] mm/vmstat: use node_stat_add_folio/sub_folio for folio_nr_pages operations. The patch targets several memory management files, including fs/nfs/internal.h and fs/nfs/write.c, replacing verbose patterns like node_stat_mod_folio(..., folio_nr_pages(folio)) with the cleaner node_stat_add_folio(...).

Ye Liu explained the motivation:

"This makes the code more readable and reduces the number of arguments passed to these functions."

David Hildenbrand (Arm) responded with a significant technical insight, noting that the refactoring also provides semantic clarity regarding atomicity and scope of accounting:

"Also, that makes it clearer that we always account the full folio, never parts of it."

This remark highlights an important aspect of NFS client development: ensuring that memory accounting operations are unambiguous. By using dedicated add/sub functions, the code explicitly documents that entire folios are being accounted for, reducing the risk of future bugs where partial accounting might be mistakenly implemented.

Ye Liu acknowledged this point:

"Thank you, David, for your support. I agree that the new functions make the intent more explicit."

Final Conclusions

The discussion concluded with consensus on the value of the change. The patch series (of which this was part 1/4) improves the NFS client's codebase by:

  1. Enhancing Readability: Reducing argument clutter in vmstat calls.
  2. Improving Correctness Guarantees: Making it explicit that full folios are accounted for, which is critical for accurate memory statistics in the NFS writeback path.

This cleanup contributes to the long-term maintainability of the NFS client's interaction with the kernel's memory management subsystem.
