nfsd: Fix PNFS flag handling in netlink export path

Summary

This thread addresses a critical bug fix in the NFS server (nfsd) regarding the handling of Parallel NFS (pNFS) exports via the netlink interface.

Issue Identification

Jeff Layton identified a regression introduced by a previous rework of block layout checks. The issue was that the check for the NFSEXP_PNFS flag had been moved out of nfsd4_setup_layout_type() into its callers, but a new call site within nfsd4_setup_layout_type() itself was missed.

Layton explained the consequence clearly:

"That patch didn't account for the new call in nfsd4_setup_layout_type()."

He emphasized the severity of the oversight, noting that without this fix:

"pnfs is enabled on every xfs export discovered via netlink."

This was reported by Olga Kornievskaia, who likely encountered unexpected pNFS behavior on XFS exports.

Resolution

The patch, submitted as a single-line fix, restores the necessary check for NFSEXP_PNFS in the netlink codepath. Layton suggested it be folded into the original patch it fixes, but Chuck Lever applied it separately to his nfsd-testing branch:

"Applied to nfsd-testing, thanks! ... For the moment Christoph's series is still in my tree."

Christoph Hellwig, who authored the original rework, reviewed and approved the fix:

"Looks good"

Conclusion

This was a quick-turnaround bug fix for a significant configuration issue in NFS server exports. The patch ensures that pNFS is only enabled on XFS exports when explicitly requested via the NFSEXP_PNFS flag, preventing unintended behavior for administrators using netlink to manage exports. The fix has been applied to the nfsd-testing tree and reviewed by the original author of the problematic rework.
