NFSv4: Retry GETATTR on Directory Delegation Failure

Summary

Bug Fix: Resilient GETATTR When Directory Delegation Fails

This week, Olga Kornievskaia from Red Hat submitted a bug fix addressing an issue in the NFSv4 client where opportunistic directory delegation requests could cause otherwise valid GETATTR operations to fail unexpectedly. The patch was posted on April 10 as version 1, and a revised version (v2) followed on April 15 here.

The Problem

The NFS client attempts to acquire directory delegations opportunistically by piggybacking the request onto existing GETATTR calls. However, if the server rejects the delegation request, the entire GETATTR operation fails, propagating an error to the user even though the attribute retrieval itself was legitimate.

As Olga explained in the patch description:

"Currently, getting a directory delegation is opportinistic and gets added to an existing GETATTR that's trying to retrieve some needed attributes. However, GET_DIRDELEGATION can fail and that currently causes a GETATTR to fail and an error is propagated to the user."

This behavior was introduced by commit 156b09482933, which enabled directory delegation requests on ACCESS, CREATE, and UNLINK operations.

The Fix

The patch modifies fs/nfs/nfs4proc.c to retry the original GETATTR without requesting a directory delegation if the initial attempt fails due to delegation issues. Additionally, it clears the flag asking for a directory delegation for that specific inode to prevent repeated failures.

Olga noted an alternative approach in her comments:

"Note: instead of clearing NFS_INO_REQ_DIR_DELEG perhaps turning off directory delegations for the whole server is appropriate but I wasn't sure."

Version 2 Update

In the v2 submission, Olga addressed a specific edge case involving BSD servers:

"BSD server can return NFS4ERR_NOFILEHANDLE when requesting directory delegations on "/" that isn't exported."

This refinement ensures the client handles cases where the root directory is not exported by the server, avoiding spurious errors.

Conclusion

This is a bug fix focused on improving the robustness of the NFSv4 client. By decoupling the success of GETATTR from the opportunistic delegation request, users will no longer encounter unexpected errors when servers decline directory delegations. The patch represents a targeted improvement to NFS client development, enhancing compatibility with diverse server implementations.
