pNFS: Deadlock fix in pnfs_send_layoutreturn — second build error report (m68k)

Summary

pNFS: Deadlock Fix in pnfs_send_layoutreturn — Continued Build Error Reports

Classification: Bug Fix

This thread concerns a bug fix for a critical deadlock in the Parallel NFS (pNFS) client subsystem. The patch, originally submitted by Ben Roberts last week, addresses production-observed hangs on HPC clusters where pnfs_send_layoutreturn() enters a recursive loop under memory allocation failure conditions.

Bridge to Prior Week

Last week (summary), Ben Roberts submitted the patch and received an initial build error report from the kernel test robot on April 8, identifying a missing semicolon after pnfs_clear_layoutreturn_info(lo) in fs/nfs/pnfs.c. The prior summary concluded that the patch was logically sound but required a trivial syntax fix before integration.

"The fix ensures that NFS_LAYOUT_RETURN_REQUESTED is cleared in the allocation failure path before calling pnfs_put_layout_hdr(). This prevents pnfs_layoutreturn_before_put_layout_hdr() from attempting another layout return, breaking the recursion cycle." — Ben Roberts

This Week's Activity

This week saw a second automated build error report from the kernel test robot on April 10, this time targeting a different architecture: m68k. The error is the same underlying syntax issue — a missing semicolon — but surfaced on a distinct defconfig and compiler toolchain.

The kernel test robot reported:

">> fs/nfs/pnfs.c:1364:49: error: expected ';' before 'pnfs_clear_layoutreturn_waitbit' 1364 | pnfs_clear_layoutreturn_info(lo) | ^ | ;"

The failure was reproduced on m68k-defconfig using m68k-linux-gcc (GCC) 15.2.0, with the build also failing against trondmy-nfs/linux-next, linus/master v7.0-rc7, and next-20260407. The robot noted:

"[auto build test ERROR on trondmy-nfs/linux-next] [also build test ERROR on linus/master v7.0-rc7 next-20260407]"

The error occurs in the memory-allocation-failure path of pnfs_send_layoutreturn(), where the patch adds a call to pnfs_clear_layoutreturn_info(lo) but omits the terminating semicolon before the subsequent call to pnfs_clear_layoutreturn_waitbit(lo).

Technical Context: The Deadlock Being Fixed

The underlying bug is significant for NFS client development. In production HPC environments running kernel 5.14.0-611.9.1.el9.x86_64, the deadlock manifested as follows:

  1. pnfs_send_layoutreturn() allocates a nfs4_layoutreturn structure via kzalloc().
  2. On allocation failure (-ENOMEM), the error path calls pnfs_put_layout_hdr(lo).
  3. If NFS_LAYOUT_RETURN_REQUESTED is still set, pnfs_layoutreturn_before_put_layout_hdr() triggers another layout return attempt.
  4. This creates a recursive deadlock, leaving processes stuck in uninterruptible sleep (D-state).

Roberts reported that the patch had been running successfully in production for over three months prior to submission. The fix clears the NFS_LAYOUT_RETURN_REQUESTED flag and associated wait bits before releasing the layout header, breaking the recursion cycle.

Current Status

As of the end of this week's window, no v2 patch has been submitted. The same syntax error (missing semicolon) persists across multiple architectures and kernel trees. The patch remains pending a corrected submission from Ben Roberts or adoption by the NFS maintainer.

The kernel test robot advised:

"If you fix the issue in a separate patch/commit (i.e. not just a new version of the same patch/commit), kindly add following tags | Reported-by: kernel test robot lkp@intel.com | Closes: https://lore.kernel.org/oe-kbuild-all/202604101309.6eRanxOC-lkp@intel.com/"

Key Takeaways for NFS Client Development

  • Deadlocks in pNFS layout return paths remain a critical reliability concern, particularly under memory pressure on HPC workloads where layout returns are frequent.
  • The automated 0-day CI testing infrastructure continues to catch even trivial syntax errors across diverse architectures (x86 last week, m68k this week), underscoring the value of broad cross-architecture build coverage for NFS client patches.
  • This fix, once corrected and merged, will improve the robustness of the pNFS client's error handling during memory-constrained scenarios.
