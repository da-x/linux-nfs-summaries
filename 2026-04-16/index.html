Week ending 2026-04-16

Critical Client Bug Fixes

Writeback Infinite-Loop Fix (v3 Submitted)

Olga Kornievskaia submitted v3 of her fix for an infinite writeback retry loop in the NFS client when servers return ENOSPC during unstable writes (thread). The bug — discovered via xfstest generic/751 — causes application stalls under two failure patterns: (1) ENOSPC at an offset smaller than file size, and (2) a short write followed by ENOSPC. The fix marks affected requests for synchronous writeback using a persistent flag in nfs_open_context, covering both traditional NFS and LocalIO paths. Trond Myklebust ACKed v2 last week; v3 addresses a minor nit about redundant iov_iter_count() calls and appears merge-ready.

RCU Safety Fix in Super Block Comparison (v1 Reviewed)

Sean Chang's two-patch series fixing RCU safety in nfs_compare_super_address received detailed review from Benjamin Coddington (thread). The first patch guards against use-after-free when dereferencing the __rcu-marked cl_xprt pointer during transport switches. Coddington suggested narrowing the RCU critical section and adding an XPRT_CONNECTED check for robustness. The second patch corrects a Sparse warning in the nfs_page_class tracepoint by removing an incorrect __private annotation while preserving kernel pointer obfuscation via %p formatting. A v2 series is expected shortly.

Inode Size Corruption Under Write Delegations — Reproduction Provided

Dai Ngo's patch preventing the NFS client from blindly trusting server-reported inode sizes while holding a write delegation (thread) progressed this week. After Trond Myklebust questioned whether the existing nfs_writeback_check_extend() already covered the scenario, Dai provided a concrete reproduction: file corruption when running Git's test suite on NFSv4.2 with pNFS SCSI layouts. This confirms the bug is real and not theoretical, though the thread awaits further analysis of why existing safeguards are insufficient.

File-Lock List UAF Fix — Ping for Merge

Yang Erkun followed up on his long-standing use-after-free fix for file-lock list traversal during delegation claim and lock reclaim (thread). The patch, which received Jeff Layton's Reviewed-by in March, replaces per-state-owner locking with nfsi->rwsem to protect against races between multiple state owners on the same inode. After seven weeks of quiet acceptance, Erkun pinged maintainers for merge consideration.

GETATTR Retry on Directory Delegation Failure (v2)

Olga Kornievskaia submitted v2 of a fix ensuring GETATTR operations don't fail when an opportunistic GET_DIR_DELEGATION request is declined by the server (thread). The client now retries without the delegation request and suppresses future delegation requests for that inode. v2 adds handling for BSD servers returning NFS4ERR_NOFILEHANDLE on unexported root paths.

pNFS Deadlock Fix — Maintainer Questions Upstream Validity

Ben Roberts' fix for a deadlock in pnfs_send_layoutreturn() under memory pressure (thread) hit a roadblock. Benjamin Coddington asked whether the bug was reproduced on a recent upstream kernel, noting the patch targets RHEL 9's 5.14 LTS tree which diverges from upstream. The patch also has an unresolved missing-semicolon syntax error flagged by the kernel test robot across multiple architectures (thread). Roberts indicated he would withdraw and pursue further diagnostics.

Major Feature: Directory Delegations with CB_NOTIFY

Server-Side Implementation (v2, 28 Patches)

Jeff Layton submitted a 28-patch series adding CB_NOTIFY callback support to the NFS server for directory delegations (thread). This allows servers to notify clients of creates, unlinks, and renames without recalling the delegation — a major efficiency improvement. The series introduces FSNOTIFY_EVENT_RENAME in the VFS layer (reviewed by Amir Goldstein), fsnotify watches on directories, and full protocol support per RFC 8881bis. Layton noted the patches won't be merged until client-side implementation is complete for testing.

pynfs Test Suite (v2, 25 Patches)

In parallel, Layton submitted a 25-patch test suite for directory delegations in pynfs (thread). Tests cover recall-only behavior (passing on current mainline) and full CB_NOTIFY scenarios including ADD, REMOVE, RENAME notifications, cross-directory renames, rename-over semantics, and self-inflicted change suppression.

NFS Server Fixes

CLONE/COPY Timestamp Regression Fixed (Applied)

Olga Kornievskaia's v4 series fixing mtime/ctime updates for NFSv4.2 CLONE and COPY operations when delegated attributes are present was applied to nfsd-testing by Chuck Lever (thread). The server-side fix complements the client-side COPY timestamp fix also submitted this week (thread).

sunrpc Cache Seqno Fix (Applied)

Jeff Layton's one-line fix initializing next_seqno at 1 instead of 0 resolved persistent mountd hangs caused by the first cache request being silently skipped during netlink GET_REQS dumps (thread). Applied to nfsd-testing.

NFSEXP_PNFS Netlink Flag Fix (Applied)

Jeff Layton fixed a regression where pNFS was incorrectly enabled on every XFS export discovered via netlink due to a missed call site in nfsd4_setup_layout_type() (thread). Applied to nfsd-testing.

Replay Buffer Underflow Fix Rejected

Xiaobo Liu's proposed fix for a replay buffer length underflow in nfsd4_encode_operation was rejected by Chuck Lever as the reported condition is structurally unreachable — truncation and replay-cache paths are mutually exclusive (thread).

pNFS Data Server Grace-Period Caching Rejected

Lei Yin's proposal to defer destruction of pNFS data server cache entries via a timer-based grace period was NACKed by Trond Myklebust for violating RFC 8881 §12.2.10 — caching entries without holding a layout requires active deviceinfo notification subscriptions (thread).

Ongoing Debates and Discussions

P2PDMA Capability Detection Architecture

Pranjal Shrivastava's RFC for PCI P2PDMA support in NFS Direct I/O continued to evolve (thread). Chuck Lever argued that NFS_CAP_P2PDMA is a transport-level property, not a server capability, and must be re-evaluated per I/O since the underlying RPC transport can change during retransmission. Christoph Hellwig pushed for separating the critical iov_iter_extract_pages() migration (a bug fix affecting XFS) from the P2PDMA feature, and recommended adopting folios/bvecs for Direct I/O to match buffered I/O efficiency.

Possible Cache Race: Stale Zero-Fill Beyond EOF

Nikolay Amiantov reported a potential race condition where readers can see stale zero-fill when a file grows remotely between page cache lookup and inode size read (thread). He argues the window between filemap_get_pages() and i_size_read() cannot be closed without locking pages and inode size simultaneously. No replies received yet; includes reproducible test cases for both NFS and FUSE.

exportfs State Release (Committed)

Chuck Lever's patch to release NFSv4 state when the last client is unexported was committed to nfs-utils (thread), allowing clean filesystem unmounts after export removal.
