NFS client: flexfiles v4.0 DS NULL-deref fix, folio DIO debate resolves; NFSD UAF audit series lands in testing

Week ending 2026-07-09

Week ending 2026-07-09

A heavy week for NFS client correctness work — a long-dormant flexfiles v4.0 data-server crash fix, the resolution of the three-week folio-based direct I/O debate, and a batch of client-side lifetime/accounting fixes — alongside a big server-side milestone: Chuck Lever's NFSD use-after-free audit series reaching v4 and landing in nfsd-testing, plus the long-running sunrpc pool_mode rework being applied.

Critical bugs & fixes

NFS client

  • Flexfiles: NULL deref for NFSv4.0 data servers + loosely coupled DS support — Jeuk Kim (Samsung) posted a two-patch series (thread) that fixes a latent crash (Fixes: a7878ca14008) where nfs4_init_ds_session() and ff_layout_async_handle_error_v4() dereference clp->cl_session on a v4.0 DS (no session), leaving cl_lease_time at 0 and busy-looping the renew state manager. The second patch implements RFC 8435 loosely-coupled DS support, which the client had been silently ignoring. Awaiting review; likely Cc: stable candidate.
  • NFSv3 O_WRONLY|O_CREAT EACCES regression — Tian Lan (Jane Street) reported that 6.12's atomic_open change now issues an unconditional CREATE RPC, which a non-conformant server answers with EACCES when the user lacks directory write permission on a pre-existing file (thread). Trond Myklebust pushed back that NFSv3 CREATE must ignore directory permissions on existing files and asked which server is in use — the thread is a live regression investigation, no patch yet.
  • nfs4_listxattr NULL deref + size undercount — Achilles Gaikwad's fix for the security_inode_listsecurity() interface change (v2) was reviewed by Paul Moore and routed through the NFS tree by Anna Schumaker (thread). Side note: Paul is separately bisecting an unrelated NFS regression that appeared between v7.1 and v7.2-rc1 while testing this fix.
  • NFSv4 superblock pin for active state owners — Jia Zhu (ByteDance) proposed pinning the superblock while a state owner is active to close a production umount/reclaim race that oopses in nfs_zap_acl_cache() (thread). No review yet; expect scrutiny on the pin granularity.
  • Delayed delegation return list — Guangshuo Li's one-line fix restores the retry path that Christoph Hellwig's January rework left inert: nfs_end_delegation_return() was moving delayed delegations to delegations_return instead of delegations_delayed, so the clear helper always returned false (thread).
  • Unstable-write accounting inflation — Benjamin Coddington (Hammerspace) flagged that nfs_folio_mark_unstable()/clear_commit() charge the whole folio per request, so a 2 MiB folio split into 512 4 KiB requests inflates writeback counters by up to 512× and can hard-throttle every buffered writer on the host (including nfsd). Fixes: 0c493b5cf16e (2022), Cc: stable (thread).
  • Symlink target cache hardening — ZhangGuoDong (KylinOS) proposed a 6-line check that the instantiated inode is actually a symlink before caching the target folio, backed by a vmcore showing nfs_readdir_clear_array() misinterpreting the data as a readdir array on unmount (thread).
  • sunrpc pipefs UAF — Luxiao Xu's patch keeps clnt->pipefs_sb honest across late mount/remount events so rpc_clnt_remove_pipedir() doesn't skip cleanup and leave dentries pointing at a freed rpc_clnt (Fixes: bfca5fb4e97c, stable) (thread).
  • fhandle detached-mount NULL deref — Guangshuo Li's 3-line fix treats a concurrently-detached mount as not capable in capable_wrt_mount() (thread).
  • rpc.gssd resource leaks — Thiago Becker (Red Hat) fixed a clnt_info refcount leak and a missing pthread_attr_destroy() in start_upcall_thread, both found by Claude Sonnet 4.5 (thread).
  • nfs-utils mountd netlink — Scott Mayhew's three-patch series fixes a nfsstat build break, documents the --no-netlink option in nfs.conf, and disables netlink when falling back to /proc (avoiding indefinite mount hangs on SELinux systems lacking CAP_NET_ADMIN). Reviewed-by Jeff Layton (thread).

NFS server (nfsd / lockd)

  • NFSD UAF audit series — v4 in nfsd-testing — Chuck Lever's nine-patch series fixing a family of use-after-free races in nfs4state.c client teardown and state revocation reached v4 on July 9 with Reviewed-by from Jeff Layton on the new patches, and was pushed to nfsd-testing (v2 thread, v4 thread). The series fixes seven UAF/NULL-deref races plus one svc_export leak, all rooted in the same architectural pattern: raw pointers to nfs4_client that rely on lock discipline rather than reference counting. This is the direct payoff of Wolfgang Walter's 6.18.37 production crash — Chuck exonerated the export-cache revert commit on July 3 and re-scoped the bug as a latent upstream nfs4state.c defect present in both 6.18.36 and 6.18.37. The original RFC patch was the first single-crash fix; v2 expanded it into a six-patch audit, and v4 added blocked-lock reaping, close_lru reaping, and the export-leak fixes.
  • nfsd copy offload lifetime bugs (v2) — Jeff Layton posted a ten-patch series fixing publish races, async-copy UAFs, stale IDR entries, an ownership hole allowing any authenticated client to cancel another's copy-notify stateid, and revoke-path UAFs in NFSv4.2 inter-server COPY (thread). Chuck Lever flagged two new issues in patch 03/10 (missing nfs4_free_copy_state() and uninitialized cb_stateid), so a v3 is expected. Notably, the bugs were found via LLM inspection (kres + agentic review).
  • pynfs copy offload test suite — Layton also posted a 13-patch pynfs series adding real COPY/OFFLOAD_STATUS/OFFLOAD_CANCEL/COPY_NOTIFY tests including inter-server copy, plus a fix for a misnamed XDR union arm that made op.copy_notify() raise TypeError (thread). One test is explicitly designed to catch an inverted TTL check in the kernel's async-copy reaper.
  • lockd NLM_SHARE bitmap fix merged — Oscar Ou (Synology) v3, using a u16 bitmap instead of refcounts for idempotency under UDP retransmit, was applied to nfsd-testing on July 4 (bitmap thread, refcount rejection).
  • nfsd nfs4_create_file() refactor (v2) — NeilBrown's 14-patch series preparing nfsd for a new VFS lookup_open() interface received full review from Jeff Layton, including a genuine bug fix for silently dropped client attributes on NFS4_CREATE_EXCLUSIVE4_1 and a resolved delegation-recall debate (thread).
  • Stable backports — A wave of nfsd fixes landed in stable queues this week: write-verifier reset on deferred writeback errors (silent data loss, 5.10.y/5.15.y), layout stid release on setlease failure (UAF, 5.10.y/5.15.y/6.1.y/6.6.y/6.12.y/6.18.y), mtime/ctime on CLONE with delegated attributes (6.18.y), and CB_GETATTR change-detection fix (6.12.y). See write verifier 5.10, layout stid 5.10, 6.18.y series, 6.12.y series.

Major trends & ongoing debates

NFS client direct I/O folio debate resolves

The three-week argument over whether page_folio() is safe in the new iov_iter_extract_pages() path reached a concrete resolution. Christoph Hellwig confirmed that kernel-side direct I/O users exist (loop, zloop, nvmet, scsi target, nfsd), making the kvec-iterator concern real rather than theoretical. The agreed path forward: NFS should reuse the block layer's get_contig_folio_len() helper rather than hand-rolling folio grouping or relying on the "every page is a folio" invariant. Hellwig endorsed splitting the folio patch out as a standalone prerequisite to unblock the rest of Pranjal Shrivastava's modernization series (thread). A v3 is expected.

sunrpc pool_mode: applied to nfsd-testing

After five revisions and a month-plus of review, Jeff Layton's series hardcoding pool_mode to pernode and fixing the empty-pool connection-starvation bug was applied to nfsd-testing on July 6. The series eliminates indefinite client connection hangs on multi-NUMA servers with fewer nfsd threads than NUMA nodes, and removes a modulus from the svc_pool_for_cpu() hotpath. A brief interface-design debate about whether to make the new accessor static-inline was resolved on module-boundary hygiene grounds (Layton kept struct svc_pool_map private to sunrpc.ko). A follow-on patch dropping a dead if check was folded in within an hour.

netfslib bvecq refactor (v5)

David Howells posted v5 of his 21-patch series replacing netfslib's folio_queue/rolling_buffer with segmented bio_vec[] chains, touching NFS, AFS, CIFS, and cachefiles. The series carries two direct NFS client fixes (nfs_netfs_issue_read() ENOMEM and double-terminate) and is aimed at the VFS tree via Christian Brauner (thread). No review replies yet in-window.

NFS/localio: inline IO + tracepoint fix

Mike Snitzer posted a three-patch series making LOCALIO issue IO inline when not in a memory-reclaim context, eliminating an unnecessary workqueue hop for O_DIRECT and fsync-driven commits (thread). He also fixed a misleading offset in the nfs_local_dio_misaligned tracepoint (cut-n-paste bug reporting start_len instead of middle_offset) (thread). Both await review.

AI-assisted development becomes routine

Multiple patches this week carry Assisted-by: tags for LLM tools: Chris Mason's layout-stid fix (kres/claude-opus-4-7), Jia Zhu's superblock pin (Codex:GPT-5), Luxiao Xu's pipefs UAF (Codex:gpt-5.4), Thiago Becker's rpc.gssd leaks (Claude Sonnet 4.5), Benjamin Coddington's writeback accounting fix (Claude Sonnet 5), and Jeff Layton's copy offload series (kres + agentic review). The pattern is now standard on the list, with human developers filtering false positives before submission.
