Bridge to Prior Week (July 2)

The substantive technical discussion occurred in the prior week when Lever posted the three-patch series. For completeness, here is a brief recap of what was queued:

Patches 1 & 2 — mtime/ctime on CLONE and COPY with delegated attributes (by Olga Kornievskaia): When a client holds delegated attributes, the server opens files with NOCMTIME to avoid drifting from the client's view. However, COPY and CLONE modify the destination file server-side without the client holding a delegation on it, so mtime/ctime must still be updated. As Lever explained in the cover letter:

"When delegated attributes are given on open, the file is opened with NOCMTIME and modifying operations do not update mtime/ctime as to not get out-of-sync with the client's delegated view. However, for COPY operation, the server should update its view of mtime/ctime and reflect that in any GETATTR queries."

Both patches carry Fixes: e5e9b24ab8fa identifying the commit that introduced the over-broad suppression.

Patch 3 — Release layout stid on setlease failure (by Chris Mason, reviewed by Jeff Layton): A use-after-free / dangling-pointer bug in the pNFS layout stateid teardown path. When nfsd4_layout_setlease() fails, the error path freed the stateid via kmem_cache_free() without calling idr_remove(), leaving the IDR slot pointing at freed slab memory. The fix replaces this with a proper nfs4_put_stid(stp) call. Lever described the hazard:

"Any subsequent IDR walker (states_show, client teardown) dereferences the dangling pointer."

Notably, this patch carries an Assisted-by: kres (claude-opus-4-7) tag — one of the first instances of AI-assisted development attribution on a mainline/stable NFS server patch.

Significance

All three patches are now in the 6.18.y stable queue and will ship with the next stable release:

  • Delegated-attribute correctness: The COPY/CLONE fixes close a gap where server-side file modifications could leave stale timestamps visible to other clients, violating POSIX attribute coherence expectations.
  • pNFS robustness: The layout stid leak fix eliminates a potential kernel crash (dangling pointer dereference) triggered by a failed lease acquisition on a pNFS layout — a rare but serious reliability bug.
  • Stable-tree hygiene: Lever's bracketed annotations documenting which upstream commits are missing from 6.18.y exemplify careful backport engineering, ensuring the stable patches remain self-contained and correct in isolation.

The thread is now complete with no further discussion expected.
