nfsd 6.12.y: CB_GETATTR change-detection fix and layout stid leak fix — queued

This week's activity in the thread is brief but conclusive: stable maintainer Sasha Levin confirmed that Chuck Lever's two-patch backport series for the 6.12.y kernel has been accepted and queued. In a single reply, Levin wrote:

"Queued the series for 6.12.y, with the author of 2/2 fixed up to Chris Mason per your follow-up. Thanks!"

The rapid turnaround — from posting at 20:27 UTC on July 2 to confirmation at 02:05 UTC on July 4 — reflects the well-oiled workflow between nfsd maintainers and the stable tree.

Context: what the series fixes (from prior week)

Both patches are bug fixes for the Linux NFS server (nfsd), not new features or protocol changes.

Patch 1/2 — Fix file change detection in CB_GETATTR (protocol compliance)

Authored by Scott Mayhew, this patch corrects how nfsd determines whether a client holding a write delegation has modified a file when the server issues a CB_GETATTR callback. The root cause was a protocol-compliance bug: the code compared a cached file size (stored in the delegation record) against the client-reported size, rather than the current on-disk size as required by RFC 8881, section 10.4.3.

"What section 10.4.3 of RFC 8881 does say is that the server should compare the current file size with the size reported by the client holding the delegation in the CB_GETATTR reply, and if they differ to treat it as a modification regardless of the change attribute retrieved via the CB_GETATTR."

The consequence was spurious mtime/ctime/change-attribute updates on every subsequent CB_GETATTR even when no actual writes occurred. The fix modifies nfsd4_deleg_getattr_conflict() to obtain the current file size via i_size_read() rather than relying on the stale cached value.

Patch 2/2 — Release layout stid on setlease failure (use-after-free)

Authored by Chris Mason, this patch fixes a dangling-pointer bug in the pNFS layout stateid error path:

"nfs4_alloc_stid() publishes the new stid into cl->cl_stateids via idr_alloc_cyclic() under cl_lock before returning to nfsd4_alloc_layout_stateid(). When nfsd4_layout_setlease() then fails, the error path frees the layout stateid directly with kmem_cache_free() without ever calling idr_remove(), leaving the IDR slot pointing at freed slab memory."

The fix replaces manual cleanup with a single nfs4_put_stid(stp) call, which properly removes the IDR slot under cl_lock. A three-line change in fs/nfsd/nfs4layouts.c.

Assessment

This thread is now resolved. Both fixes are queued for the 6.12.y stable kernel and will land in the next stable release. The CB_GETATTR fix addresses a protocol-compliance issue affecting any NFSv4.2 deployment using write delegations, while the layout stid fix plugs a memory-safety hole (use-after-free via dangling IDR pointer) in the pNFS layout recall path. No further discussion is expected on this thread.
