Why this matters (and why it's quiet)

The question sits at an awkward intersection of two long-standing Linux topics:

  1. Swap over NFS has historically been discouraged — and in many configurations explicitly refused — because the kernel's swap subsystem demands reliable, low-latency I/O that a network file system cannot guarantee. A server hiccup or a stale NFS handle can wedge page-in/page-out and take down the whole machine.
  2. NFS/RDMA (the rdma transport for NFSv4) was added to cut latency and CPU cost on high-speed fabrics, but it does not by itself change the reliability semantics of the underlying protocol; swap still goes through the same page-cache / VFS paths.

So the practical answer Nishimura is fishing for — "can I swapon an NFS file on a mount that uses rdma as its transport?" — remains unanswered in-thread. His lone "?" this week reads less like a technical follow-up and more like a polite nudge to the list, aimed at whatever maintainer or RDMA-NFS developer has been sitting on the question since mid-June.
