rpc.gssd: Two resource leaks fixed by AI-assisted audit

Summary

rpc.gssd: Two resource leaks (Thiago Becker, 2026-07-03)

Overview

On Friday, July 3, Red Hat's Thiago Becker posted a small two-patch series to the linux-nfs list addressing two resource leaks in rpc.gssd, the user-space daemon that handles GSS/Kerberos upcalls for NFS clients. The series is a straightforward bug-fix submission — no new feature and no protocol change — touching only utils/gssd/gssd_proc.c with four added lines in total.

The Patches

Patch 1/2 — "Decrement client reference count on error paths" (PATCH 1/2) fixes a leak of a clnt_info reference when alloc_upcall_info fails. As Becker described in the cover letter:

"Patch 1 drops a reference to clnt_info when alloc_upcall_info fails."

The fix adds three lines that ensure the client's reference count is decremented on the error path, preventing a slow accumulation of stale references in long-running gssd processes.

Patch 2/2 — "Call pthread_attr_destroy before returning from start_upcall_thread" (PATCH 2/2) adds a single pthread_attr_destroy() call so that thread attributes are freed before start_upcall_thread returns:

"Patch 2 frees the thread attributes before returning from start_upcall_thread."

A Notable Provenance Detail

The most newsworthy element of this thread is not the code but its origin. In the cover letter (PATCH 0/2), Becker disclosed that both leaks were discovered by an AI assistant:

"Both leaks were identified by claude sonnet 4.5, among some amount of false positives that were hand filtered."

Each patch also carries an Assisted-by: Claude:claude-sonnet-4-5 trailer alongside the standard Signed-off-by. This is a visible example of LLM-assisted code auditing making its way into the NFS user-space tooling, with the human developer explicitly filtering out false positives before submission.

Discussion Status

Within the current week's window (through 2026-07-10), the thread received no replies — it is a quiet, uncontested bug-fix posting. A reply from Steve Dickson (the nfs-utils maintainer) arrived on 2026-07-11, just outside this week's boundary, so its content falls into next week's coverage.

Significance for NFS Client Development

While small in scope, the series is relevant to anyone running Kerberos-authenticated NFS clients: leaked clnt_info references and thread attributes in rpc.gssd would accumulate over time on busy clusters, degrading the very daemon that brokers secure upcalls between the kernel NFS client and the KDC. The fixes are low-risk (four added lines, no behavioral change on success paths) and well suited for stable backporting.
