Petr Pavlu's kmod.h/umh.h include cleanup touches NFS client and server files

Summary

Bring includes in linux/kmod.h up to date (NFS-relevant hunks)

Type: Header-hygiene / build-system cleanup — not a protocol change, not a runtime bug fix. The series is motivated by reducing the preprocessed size of linux/module.h (which pulls in linux/kmod.h) for every *.mod.c file in the tree.

What landed on the list this week

On Wednesday 2026-07-08, SUSE's Petr Pavlu posted a two-patch series titled "Bring includes in linux/kmod.h up to date", apologizing upfront for the wide distribution:

"Apologies for the wide distribution."

The cover letter explains the motivation in detail:

"This cleanup is motivated by trying to reduce the preprocessed size of linux/module.h, which includes linux/kmod.h. The linux/module.h header is included by every *.mod.c file to provide struct module and other related definitions, so it should avoid pulling in unnecessary dependencies."

He also candidly notes that the win is deferred:

"Note that this series doesn't immediately improve the situation, since most of the files included by linux/kmod.h are, for now, also included by linux/module.h through other paths."

Patch 1/2 — treewide linux/umh.h include fix

The first patch adds explicit #include <linux/umh.h> to every file that actually uses usermode helpers, and removes the now-redundant linux/kmod.h include where it was only being used as a proxy for umh declarations. Pavlu traces the original split back to a 2017 commit:

"The usermode helper declarations were previously provided by linux/kmod.h but commit c1f3fa2a4fde ("kmod: split off umh headers into its own file") moved them to linux/umh.h in 2017."

NFS-relevant hunks. The diffstat shows three files under fs/nfs and fs/nfsd:

  • fs/nfs/cache_lib.c — the NFS client's cache library (used by the upcall machinery for nfsdcltrack, rpc_pipefs lookups, etc.) is being switched from linux/kmod.h to linux/umh.h.
  • fs/nfsd/nfs4layouts.c — server-side layout code.
  • fs/nfsd/nfs4recover.c — server-side state-recovery code (adds the umh include).

For NFS-client readers, the change is purely mechanical: cache_lib.c already calls call_usermodehelper_*(), so it now includes the header that actually declares those functions. No behavioural change to the client's upcall path is expected — this is a "include what you use" fix rather than a bug fix.

Patch 2/2 — slim down linux/kmod.h itself

The second patch reduces include/linux/kmod.h to only the headers it truly needs:

"Including linux/kmod.h alone results in 1.5 MB of preprocessed output, even though it provides only a few functions and macros."

Pavlu itemises the real dependencies:

"The header currently depends on:

  • __printf() -> linux/compiler_attributes.h,
  • ENOSYS -> linux/errno.h,
  • bool -> linux/types.h. Include only these files, reducing the preprocessed output to 10 kB."

That is a ~150× reduction in preprocessed size for what is effectively a small function-declaration header — a meaningful win for out-of-tree module builds and make -k parallelism once the other paths through linux/module.h are also cleaned up.

Review exchange (Wed–Thu)

Michal Koutný (also SUSE, long-time cgroup maintainer) replied on 2026-07-08 flagging a missed file. The body of his review was trimmed in the archive copy available here, but the substance is clear from Petr's reply: Koutný pointed out that kernel/cgroup/cgroup-v1.c does not actually use usermode helpers, so adding linux/umh.h there (and removing linux/kmod.h) was wrong.

Pavlu accepted the correction on 2026-07-09:

"You're right. I'll remove the kmod.h include from kernel/cgroup/cgroup-v1.c. I went through all the files again and it seems this was the only place I missed."

So the series is heading toward a v2 that drops the cgroup-v1.c hunk; no other files were affected by the review. No NFS-specific objections were raised — the NFS client/server hunks (fs/nfs/cache_lib.c, fs/nfsd/nfs4layouts.c, fs/nfsd/nfs4recover.c) appear uncontroversial.

Bottom line for NFS readers

  • No protocol change, no runtime bug fix. The NFS-client impact is limited to fs/nfs/cache_lib.c swapping one header include for the correct one; the NFS server picks up two analogous hunks in nfs4layouts.c and nfs4recover.c.
  • Build-time benefit only, and indirect: the real payoff is a much smaller linux/kmod.h, which shrinks every *.mod.c preprocessed output once the redundant paths through linux/module.h are also pruned. Pavlu himself concedes the series "doesn't immediately improve the situation."
  • Status as of end of week: v1 posted, one review comment (cgroup-v1.c hunk to be dropped), no other objections; a v2 is expected but not yet posted within this window.
