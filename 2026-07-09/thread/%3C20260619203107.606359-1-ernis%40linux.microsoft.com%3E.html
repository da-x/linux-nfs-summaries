RDMA ib_device_attr int→u32 — v8 follow-up: v9 promised for the final INT_MIN fix

This week at a glance

One message landed in this window, and it is the natural closing beat of the exchange that began on July 2 (just outside this window's start): Erni Sri Satya Vennela's July 3 reply to Andy Shevchenko is a two-line acknowledgment that commits Microsoft to a ninth revision.

"Thankyou for the confirmation, Andy. I'll add this change in the next version."

That's it — no new technical argument, no scope expansion, no maintainer merge decision. The thread has entered its final wind-down: v8 is posted and reviewed, one residual low-priority item (the INT_MIN / 0x80000000 edge case Shevchenko confirmed on July 2) is now formally queued for v9, and the rdma-next merge decision remains pending.

Bridge from prior weeks

As summarized last week, the July 2 pair of messages — Vennela's friendly follow-up referencing the Sashiko automated review, and Shevchenko's confirmation that the INT_MIN scenario "needs to be fixed" — set up this week's single reply. And as the v8 posting summary from June 19 established, this is a bug fix / type-correctness cleanup (not a new feature or protocol change): capability counter fields in struct ib_device_attr are declared as signed int despite being inherently non-negative, so drivers caching caps as u32 can implicitly narrow values above INT_MAX into negative numbers visible to the IB core.

The substantive correctness work — including the NFS/RDMA-relevant hunks — has been stable since v5–v7:

  • frwr_ops.c unsigned underflow guard (NFS client): reorders the check before the subtraction so a device reporting zero max_sge_rd cannot produce an SGE count of UINT_MAX − 1 and break RDMA transport negotiation for NFS-over-RDMA clients.
  • svc_rdma_transport.c min_t(int, …) → plain min(): the type-mismatch cleanup that was one of v5's headline items.
  • verbs.c / svc_rdma.h: sc_max_send_sges to unsigned int, inline_sge_count to u32, and %d → %u in diagnostic prints.

This week's INT_MIN discussion does not touch those hunks; it concerns a residual signed-int field that Sashiko flagged as low-priority. The NFS/RDMA consumers are already safe under the unsigned semantics Vennela confirmed in earlier revisions ("Yes I have checked that for all the variables I updated").

Assessment

The thread is converging on closure. Seven revisions became eight, and now a ninth is promised for a single remaining edge case. Shevchenko's July 2 confirmation — while noting the scenario is unlikely "IRL" (in real life) — removed any ambiguity: the fix is warranted, the change is small, and v9 should be the final revision before rdma-next maintainer pickup. No new technical objections or scope expansions emerged this week; the only forward-looking commitment in the window is Vennela's one-line promise to fold the INT_MIN fix into the next version.
