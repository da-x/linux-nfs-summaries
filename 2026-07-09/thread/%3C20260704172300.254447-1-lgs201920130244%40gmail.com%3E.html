nfsd: dentry refcount leak fix in nfsd_set_fh_dentry() — already queued upstream

Summary

A short but consequential bug-fix thread landed this week on the NFS list, centered on a dentry reference-count leak in the server-side filehandle-to-dentry path.

The report

Guangshuo Li opened the thread with a patch titled "nfsd: Fix dentry refcount leak in nfsd_set_fh_dentry()". The problem, as he described it:

"nfsd_set_fh_dentry() gets a dentry reference before checking whether an NFSv2 or NFSv3 filehandle resolves to a V4ROOT export. Such filehandles are rejected, but the rejection path jumps to out before the dentry is stored in fhp->fh_dentry."

The consequence is subtle but real: because the dentry never makes it into fhp->fh_dentry, the later fh_put() call never sees it, and the existing out: label only drops the export reference. The dentry reference obtained via dget() or exportfs_decode_fh_raw() is therefore leaked on every V4ROOT-rejected v2/v3 filehandle lookup. His fix adds a dedicated error path that drops the dentry before dropping the export, and it carries a Fixes: tag pointing at 8a7348a9ed70 ("nfsd: fix refcount leak in nfsd_set_fh_dentry()") — i.e., this is a follow-on to an earlier leak fix that itself left this corner unhandled.

The review

NeilBrown responded quickly the same evening with a Reviewed-by:

"Thanks for finding and reporting that."

Reviewed-by: NeilBrown neil@brown.name

The twist: already fixed upstream

The discussion took a turn the next morning when NFS maintainer Chuck Lever replied with a note that no new patch was needed after all:

"Thanks for the report. It appears that there is already a fix for this issue queued in nfsd-next,"

linking to commit ce7d3cc59012382bad5946b4cfc2cdcaabb81163 in his nfsd-next tree. In other words, the leak Guangshuo Li independently diagnosed had already been addressed by an upstream fix sitting in the nfsd-next branch awaiting merge — a common but satisfying outcome where an external reporter's analysis effectively validates an in-flight patch rather than duplicating it.

Bottom line

  • Category: Bug fix (memory/reference-count leak), not a feature or protocol change.
  • Area: fs/nfsd/nfsfh.c, specifically the V4ROOT-rejection path of nfsd_set_fh_dentry() for NFSv2/v3 filehandles.
  • Outcome: NeilBrown's Reviewed-by on the reporter's patch, followed by Chuck Lever confirming an equivalent fix is already queued in nfsd-next — so the leak will be resolved through the existing upstream commit rather than this new submission.

This thread is a nice example of the list's self-correcting nature: an independently found refcount bug in NFS server filehandle handling was reported, reviewed, and then deduplicated against work already in flight within two days.
