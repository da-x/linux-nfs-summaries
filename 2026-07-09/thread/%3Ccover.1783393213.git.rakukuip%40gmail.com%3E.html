sunrpc: fix use-after-free in __rpc_clnt_handle_event and __rpc_clnt_remove_pipedir

Summary

sunrpc: Fixing a Use-After-Free in the Pipefs Mount/Unmount Path

This week's activity on this thread consisted of a single, focused bug-fix patch that landed in the inbox on July 7th. The discussion is squarely about client-side memory safety in the SUNRPC layer — the plumbing that underpins NFS client connections — rather than any new feature or protocol change.

The Patch

Luxiao Xu's patch, reviewed by Ren Wei, targets a subtle lifetime bug in how the RPC client tracks its pipefs superblock across mount and unmount events.

The core problem, as described in the commit message:

"Normal client creation goes through rpc_setup_pipedir(), which records clnt->pipefs_sb, but the mount-event path in __rpc_clnt_handle_event() calls rpc_setup_pipedir_sb() directly and never refreshes that field. The umount path also removes the directory without clearing clnt->pipefs_sb."

In other words, there are two code paths that interact with pipefs — the normal client-creation path and the late mount-event path — and only one of them keeps the pipefs_sb pointer in sync. When a pipefs mount happens late (or after a remount), the stale pointer causes rpc_clnt_remove_pipedir() to skip its cleanup logic entirely:

"After a late pipefs mount or any remount, rpc_clnt_remove_pipedir() compares the current superblock against a stale pipefs_sb pointer and skips cleanup, leaving pipefs dentries whose inode private data still points at a freed rpc_clnt, leading to a potential use-after-free during subsequent rpc_info_open() or rpc_show_info() calls."

The Fix

The remedy is straightforward in principle: keep the pipefs_sb field honest. The patch (17 insertions, 5 deletions in net/sunrpc/clnt.c) updates clnt->pipefs_sb upon mount events and clears it during unmount or failure paths. As the commit message summarizes:

"Fix this by properly updating clnt->pipefs_sb upon mount events and clearing it during unmount or failure paths."

Context and Significance

This is a follow-up to an earlier fix, as noted in the Fixes: tag:

"Fixes: bfca5fb4e97c ("SUNRPC: Fix RPC client cleaned up the freed pipefs dentries")"

The original commit addressed a related but distinct cleanup issue; this patch closes a gap that remained when the mount-event path diverged from the normal creation path. The bug is tagged for stable@vger.kernel.org, indicating it affects released kernels and warrants backporting.

Two external reporters — Yuan Tan and Xin Liu — are credited with identifying the issue, and the patch carries an "Assisted-by: Codex:gpt-5.4" tag, reflecting the growing presence of AI-assisted development in kernel bug fixes.

Status

As of the end of this week's window, no replies or review comments have appeared on the thread. The patch sits awaiting maintainer triage and potential stable backport. Given its narrow scope (a single file, a handful of lines) and clear Fixes: tag, it appears to be a candidate for relatively quick acceptance if the maintainers agree with the diagnosis.
