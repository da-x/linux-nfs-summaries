nfs-utils mountd netlink fixes: configure check, no-netlink option, and /proc fallback hardening

Summary

nfs-utils mountd netlink fixes (3-patch series)

Type: Bug fix series for the NFS client/userspace tooling (nfs-utils), specifically targeting mountd/exportd netlink handling and build configuration.

Overview

On Tuesday, 2026-07-07, Red Hat's Scott Mayhew posted a three-patch series titled mountd netlink fixes to the linux-nfs mailing list, describing them as "a handful of fixes for some issues I ran into on Fedora Rawhide." The series touches configure.ac, nfs.conf, and the export cache code in nfs-utils, with a total footprint of 13 insertions and 2 deletions across four files.

Patch-by-patch breakdown

PATCH 1/3 — configure: update check of system netlink headers

The first patch addresses a build break in nfsstat. Mayhew explains that commit e1401387 ("nfsstat: add netlink support for fetching server statistics") introduced new symbols into support/include/nfsd_netlink.h that "have not yet been added to the kernel headers." Without updating the configure check that defines USE_SYSTEM_NFSD_NETLINK_H, nfs-stat would fail to compile against system headers. The fix is a two-line change in configure.ac to correct the header detection logic.

PATCH 2/3 — nfs.conf: add no-netlink option to exportd and mountd stanzas

The second patch is a documentation/configuration gap-filler. The --no-netlink command-line option was previously added by commit 60c38383 ("mountd/exportd/exportfs: add --no-netlink option to disable netlink"), but the nfs.conf man page and configuration file were never updated to document or support the option in the [exportd] and [mountd] stanzas. This patch adds three lines to nfs.conf to close that gap, allowing administrators to persistently disable netlink via configuration rather than relying solely on a command-line flag.

PATCH 3/3 — mountd/exportd: disable netlink when falling back to /proc

The third and most substantive patch hardens the runtime fallback path in cache_flush(). Mayhew's reasoning is practical: "If cache_flush() has to fall back to the /proc interface, then there's a good chance that the netlink interface isn't going to work, so go ahead and disable it."

The patch addresses a particularly nasty failure mode related to SELinux. As Mayhew notes:

"The netlink interface requires CAP_NET_ADMIN, which requires a policy update on systems running SELinux. If SELinux blocks mountd from using the netlink interface and there's no fallback, then mount requests just hang."

In other words, on SELinux-enforced systems where the mountd domain has not been granted CAP_NET_ADMIN, the netlink socket silently fails, and without a proper fallback the NFS mount process hangs indefinitely rather than degrading gracefully. The patch ensures that when the /proc-based fallback is triggered, both the sunrpc and nfsd netlink sockets are closed, preventing any further attempts to use the broken interface.

Review and outcome

Jeff Layton (kernel.org), a long-time NFS maintainer, responded within 15 minutes of the posting:

"These all look good to me. Nice work, Scott."

He attached a Reviewed-by tag for the entire series in his reply. With Layton's review, the series is in good shape for inclusion in the next nfs-utils release.

Significance for NFS client users

While this series targets the server-side tooling (mountd/exportd) rather than the kernel NFS client directly, it has direct practical impact on NFS client experience: a hung mountd on the server translates into stalled or failed mount operations on every connected client. The SELinux-related hang fix in particular is important for enterprise and RHEL/Fedora deployments where mandatory access control is standard. The configure fix prevents a regression that would have broken nfsstat builds, and the nfs.conf option gives sysadmins a clean, persistent way to work around netlink issues without modifying service unit files.
