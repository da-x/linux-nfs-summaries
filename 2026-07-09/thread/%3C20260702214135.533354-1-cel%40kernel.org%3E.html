Bridge to prior week (brief)

As summarized last week, the series comprised two independent nfsd bug fixes:

  1. Patch 1/2 — release layout stid on setlease failure (authored by Chris Mason, Meta): a use-after-free / dangling IDR slot in the pNFS layout stateid path. When nfsd4_layout_setlease() failed, the error path freed the layout stateid with kmem_cache_free() without calling idr_remove(), leaving the IDR slot pointing at freed slab memory. The fix switches the error path to nfs4_put_stid(stp). For 6.6.y the delta is minimal (1 insertion, 3 deletions in fs/nfsd/nfs4layouts.c) because ls_fence_work does not exist in that tree — Chuck's adaptation note: "[ cel: no ls_fence_work in 6.6.y; dropped INIT_DELAYED_WORK hunk ]".

  2. Patch 2/2 — reset write verifier on deferred writeback errors (authored by Jeff Layton, reported by Chris Mason): a silent data-loss path violating the UNSTABLE+COMMIT durability contract (RFC 1813 §3.3.7 / RFC 8881 §18.32). nfsd_vfs_write() and nfsd_commit() called filemap_check_wb_err() but did not rotate nn->writeverf on failure, so clients holding UNSTABLE write data would COMMIT, receive the unchanged verifier, and conclude their data was durable — silently dropping it. The fix adds verifier rotation at both error sites (open-coded for 6.6.y since the v6.7 helper is absent).

Client impact

Both fixes matter to NFS clients:

  • Patch 2 (write verifier) is the higher-severity one — it closes a silent data-loss path on any client issuing UNSTABLE writes followed by COMMIT against a 6.6.y server with deferred writeback errors. After the fix, the rotated verifier lets the client correctly detect that data was not durably committed and retry or surface the error.
  • Patch 1 (layout stid) prevents server-side dangling-pointer dereferences in states_show / client teardown on pNFS layout setlease failures — which can otherwise surface as spurious NFSv4 stateid errors to clients mid-session.

Final conclusions
