nfsd: stable backport — release layout stid on setlease failure (5.10.y)

Summary

nfsd: release layout stid on setlease failure — 5.10.y stable backport

What happened this week

This thread is a short, single-exchange stable-tree item: a backported bug fix for the NFS server (nfsd) was queued by Sasha Levin for the 5.10.y LTS series. It is squarely a bug fix — specifically a use-after-free / dangling-pointer fix in the pNFS layout stateid teardown path — rather than a new feature or protocol change.

The patch and its technical argument

Chuck Lever posted the 5.10.y backport of Chris Mason's commit 30d55c8aabb2 ("nfsd: release layout stid on setlease failure"). The submission lays out a precise two-part defect:

"nfs4_alloc_stid() publishes the new stid into cl->cl_stateids via idr_alloc_cyclic() under cl_lock before returning to nfsd4_alloc_layout_stateid(). When nfsd4_layout_setlease() then fails, the error path frees the layout stateid directly with kmem_cache_free() without ever calling idr_remove(), leaving the IDR slot pointing at freed slab memory. Any subsequent IDR walker (states_show, client teardown) dereferences the dangling pointer."

In other words, the failure path was bypassing the proper IDR bookkeeping and leaving a stale slot that later readers (states_show, client teardown) would dereference against freed slab memory — a classic use-after-free on the NFS server side.

The fix replaces the ad-hoc cleanup with the canonical teardown:

"The correct teardown for an IDR-published stid is nfs4_put_stid(), which removes the IDR slot under cl_lock, dispatches sc_free (nfsd4_free_layout_stateid) to release ls->ls_file via nfsd4_close_layout(), and drops the nfs4_file reference in its tail."

A second, subtler obstacle was identified: nfsd4_free_layout_stateid() inspects ls->ls_fence_work via delayed_work_pending(), but INIT_DELAYED_WORK() only ran after the setlease call — so on the failure path the destructor would touch an uninitialized delayed_work. The upstream fix hoisted the ls_fenced / ls_fence_delay / INIT_DELAYED_WORK initialization above the nfsd4_layout_setlease() call and collapsed the manual nfsd_file_put + put_nfs4_file + kmem_cache_free cleanup into a single nfs4_put_stid(stp).

The 5.10.y adaptation (key detail for LTS readers)

The backport is not verbatim. Chuck Lever's changelog notes the important divergence:

"[ cel: no ls_fence_work in 5.10.y; dropped INIT_DELAYED_WORK hunk ]"

Because the 5.10.y tree predates the ls_fence_work delayed-work machinery, only the IDR-release portion of the fix applies — the patch shrinks to a one-line change (fs/nfsd/nfs4layouts.c | 4 +---, 1 insertion, 3 deletions). The bug being fixed traces back to:

"Fixes: c5c707f96fc9 ("nfsd: implement pNFS layout recalls")"

The patch carries Reviewed-by: Jeff Layton <jlayton@kernel.org> and is marked Cc: stable@vger.kernel.org. (Notably, the commit also credits an AI assistant via Assisted-by: kres (claude-opus-4-7).)

Conclusion / status

Sasha Levin confirmed acceptance the same day:

"Queued for 5.10.y, thanks!" — Sasha Levin

The thread is therefore closed and resolved: the dangling-IDR-slot use-after-free in the nfsd pNFS layout setlease failure path is fixed upstream and now queued for the 5.10.y stable release. No further discussion, objections, or follow-up patches occurred this week.
