nfsd dangling layout-stid UAF fix backported to 5.15.y stable

Summary

nfsd: release layout stid on setlease failure — backported to 5.15.y

This week's activity (2026-07-03 → 2026-07-09)

This thread's only in-window message is a stable-tree backport of the NFS server (nfsd) pNFS layout use-after-free fix that Chris Mason posted to mainline on May 18. Chuck Lever submitted the 5.15.y backport on July 3, replying to Greg Kroah-Hartman's stable queue request (thread root <2026070228-deny-tattered-d0df@gregkh>). Sasha Levin confirmed the patch was queued for the 5.15.y release cycle in his reply:

"Queued for 5.15.y, thanks!"

The backport is a single-file change to fs/nfsd/nfs4layouts.c (net +1/−3 lines) and carries the upstream commit hash 30d55c8aabb261bc3f427d6b9aae7ef6206063f9.

Classification

  • Type: Bug fix — a use-after-free / dangling IDR pointer in the NFS server (nfsd) pNFS layout stateid teardown path. Not a new feature or wire-protocol change.
  • Subtree: fs/nfsd/nfs4layouts.c (nfsd). Client-visible impact: any subsequent walk of the client's stateid table (e.g., /proc/fs/nfsd/clients/*/states via states_show, or client teardown) could dereference freed slab memory and crash the server.
  • Severity: High — a latent UAF reachable from a rare error path, present since layout recalls were first implemented (Fixes: c5c707f96fc9).

Bridging prior weeks (brief)

The original fix was posted by Chris Mason on May 18 in the mainline thread, reviewed the same day by Jeff Layton, and applied to nfsd-testing by Chuck Lever within an hour (commit 9e93f8c13374d21254f8dcd0010103da346bc1f3). Mason's original description of the bug:

"nfs4_alloc_stid() publishes the new stid into cl->cl_stateids via idr_alloc_cyclic() under cl_lock before returning to nfsd4_alloc_layout_stateid(). When nfsd4_layout_setlease() then fails, the error path frees the layout stateid directly with kmem_cache_free() without ever calling idr_remove(), leaving the IDR slot pointing at freed slab memory. Any subsequent IDR walker (states_show, client teardown) dereferences the dangling pointer."

The correct teardown for an IDR-published stid is nfs4_put_stid(), which removes the IDR slot under cl_lock and dispatches the proper destructor (nfsd4_free_layout_stateid). But a second wrinkle blocked a naive switch:

"nfsd4_free_layout_stateid() unconditionally inspects ls->ls_fence_work via delayed_work_pending() under ls_lock, but INIT_DELAYED_WORK(&ls->ls_fence_work, ...) currently runs only after the setlease call. On the setlease-failure path the destructor would touch an uninitialized delayed_work."

The mainline fix therefore did two things: hoisted the ls_fenced / ls_fence_delay / INIT_DELAYED_WORK() initialization above the nfsd4_layout_setlease() call, and replaced the manual nfsd_file_put + put_nfs4_file + kmem_cache_free cleanup with a single nfs4_put_stid(stp).

This week's adaptation for 5.15.y

The 5.15.y stable tree predates the ls_fence_work delayed-work machinery, so Lever trimmed the backport accordingly:

"[ cel: no ls_fence_work in 5.15.y; dropped INIT_DELAYED_WORK hunk ]"

That leaves a minimal one-line insertion / three-line deletion change that simply swaps the broken manual cleanup for the canonical nfs4_put_stid(stp) call on the setlease-failure path. The patch carries:

  • Fixes: c5c707f96fc9 ("nfsd: implement pNFS layout recalls")
  • Upstream commit: 30d55c8aabb261bc3f427d6b9aae7ef6206063f9
  • Cc: stable@vger.kernel.org
  • Assisted-by: kres (claude-opus-4-7) — AI-assisted development, now routine on this list
  • Reviewed-by: Jeff Layton jlayton@kernel.org

Status

Queued for 5.15.y by Sasha Levin on July 4. No further discussion in this window. This is one of several nfsd stable backports Lever posted to the linux-nfs list on July 3 (sibling threads cover 5.10.y, 6.1.y, 6.6.y, and 6.12.y variants of the same fix), so operators running any of those LTS kernels with pNFS layout recalls enabled should expect this UAF to be patched in the next stable release cycle.
