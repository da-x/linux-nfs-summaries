tip ack for jiffies sysctl include in kmod.h cleanup

Summary

This week’s traffic on Petr Pavlu’s treewide linux/kmod.h include-hygiene series is not an NFS protocol change and not a client bug fix. It is a two-message review of patch 2/3 — the one-line linux/sysctl.h include in kernel/time/jiffies.c — from tip maintainer Thomas Gleixner. The only NFS client hunk in the series (fs/nfs/cache_lib.c swapping kmod.h for umh.h) was posted last week and drew no new comments in this window.

Brief bridge from last week

On 21 July Pavlu posted v2 of “Bring includes in linux/kmod.h up to date”, a preparatory cleanup so linux/kmod.h can stop re-exporting linux/umh.h and linux/sysctl.h. The NFS-relevant change is in patch 1/3: fs/nfs/cache_lib.c will include the header that has actually declared call_usermodehelper() since 2017. Patch 2/3 exists only so shrinking kmod.h does not break the time code that currently gets proc_int_u2k_conv_uop() and friends through linux/module.h → linux/kmod.h. Last week’s recap left Gleixner’s later comments for this window.

What landed this week

On 25 July, Gleixner replied to patch 2/3 with an ack and a style request, not a technical objection. He first tightened the changelog’s opening clause:

"jiffies.c uses ..."

then asked Pavlu to break up the single long sentence that listed five proc_* converters, the indirect include path, and the reason for the new include:

"Can you please split that spaghetti sentence into paragraphs?"

He pointed at the tip changelog rules (https://docs.kernel.org/process/maintainer-tip.html#changelog) and then, with the code itself unchallenged, wrote:

"Other than that."

"Acked-by: Thomas Gleixner tglx@kernel.org"

Two days later Pavlu accepted the rewrite and posted the replacement text he intends to use:

"jiffies.c uses proc_int_u2k_conv_uop(), proc_int_k2u_conv_kop(), proc_int_conv(), proc_dointvec_conv() and proc_doulongvec_minmax_conv(), which are declared in linux/sysctl.h. It currently gets that header indirectly through linux/module.h -> linux/kmod.h, but the latter no longer needs to include linux/sysctl.h."

"Include linux/sysctl.h directly in jiffies.c ahead of removing the unnecessary include from linux/kmod.h."

That is the entire in-window discussion: a changelog-paragraph request, an ack from the time/tip maintainer, and an author commitment to respin the commit message. No v3 series landed this week.

NFS client development

There is none in this week’s messages. The client-facing work remains last week’s one-line include swap in fs/nfs/cache_lib.c (the cache-upcall path that launches idmap and DNS helpers). Nobody from linux-nfs commented, acked, or objected. Patch 2/3 does not touch NFS, NFSD, or the RPC layer; it only keeps kernel/time/jiffies.c compiling once kmod.h stops pulling in sysctl.h. The eventual kmod.h shrink (patch 3/3) will make linux/module.h cheaper for every *.mod.c, including the NFS client and server modules, but Pavlu already warned that this series does not deliver that win by itself.

Status

This remains include hygiene, not a client bug fix and not a protocol change. Patch 2/3 now has Gleixner’s Acked-by pending a changelog resplit. The series is still waiting on the wide Acked-by sweep Pavlu requested; no linux-nfs maintainer has spoken on the cache_lib.c hunk.
