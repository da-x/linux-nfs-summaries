SUNRPC strlcat() cleanup still awaiting review

Summary

SUNRPC: strlcat() removal in rpc_sockaddr2uaddr() still waiting on review

What happened this week

This is a code-cleanup / deprecation patch, not a protocol change and not a functional NFS client feature. The only in-window traffic is a polite ping from the original author.

On 29 July, Ian Bridges followed up on his 27 June one-file change to net/sunrpc/addr.c after more than a month of silence:

"Gentle ping. This patch has had no response since it was posted on June 27. The code it converts is unchanged on mainline as of this week, and the patch still applies cleanly. Happy to resend if that is easier."

No maintainer, reviewer, or other list participant replied in the 24–30 July window. A list search for strlcat / rpc_sockaddr2uaddr in that window turns up only this ping. The thread remains in the same “posted, awaiting review” state it entered in late June.

Brief bridge from prior weeks

The original v1 patch (posted 27 June) is a small, behavior-preserving conversion of the last strlcat() use in the SUNRPC address-formatting path. Bridges framed it as part of the Kernel Self Protection Project campaign to retire the deprecated helper:

"In preparation for removing the deprecated strlcat() API[1], replace the snprintf()/strlcat() pair in rpc_sockaddr2uaddr() with a single snprintf() that appends the port suffix directly to the address buffer."

The technical claim is that rpc_ntop4() / rpc_ntop6_noscopeid() already leave a NUL-terminated presentation address in addrbuf, so the port suffix ".p1.p2" can be written at addrbuf + strlen(addrbuf) with snprintf(). That collapses the two-step snprintf() + strlcat() sequence, deletes the intermediate portbuf, and keeps the existing truncation contract:

"snprintf() returns the length it would have written excluding the NUL, so comparing it against the remaining buffer space preserves the existing truncation check that returns NULL."

The diff is 11 lines in net/sunrpc/addr.c (5 insertions, 6 deletions). No one has yet Acked, Nacked, or requested a respin.

Relevance to NFS client development

rpc_sockaddr2uaddr() is shared SUNRPC plumbing used by the NFSv3/v4 client (and the server) to turn a sockaddr into a universal-address string for RPC connection bookkeeping, XDR of addresses, and diagnostics. Because the patch is intended to be behavior-preserving — same output, same NULL-on-truncation — it is low-risk for client regressions, but it still sits on a core client-side path. Until a maintainer reviews it, the last strlcat() in this formatter remains on mainline, which is exactly the status Bridges is highlighting.

Bottom line

A one-month-old, still-clean deprecation cleanup in the NFS/SUNRPC client address formatter got a ping and nothing else. The conversion of rpc_sockaddr2uaddr() from strlcat() to snprintf() is unchanged, still applies, and is still waiting for review.
