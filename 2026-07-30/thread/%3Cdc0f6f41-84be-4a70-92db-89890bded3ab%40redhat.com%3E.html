nfs-utils 2.9.2 released; git tag restored

Summary

Steve Dickson announced nfs-utils 2.9.2 on 29 July, describing it as “a fairly large release” of the userspace NFS utilities that sit alongside the kernel client (mount.nfs, nfsstat/nfs-iostat) and server (exportfs, netlink helpers). Tarballs and the changelog are on kernel.org and SourceForge; the git tree remains git://linux-nfs.org/~steved/nfs-utils.

The headline items in the announcement are bug-fix and hygiene work rather than a protocol change:

  • “A number of memory leaks fixed (from AI)”
  • netlink fixes and enhancements
  • exportfs fixes and enhancements
  • a new nfs-iostat option (the client-visible stats tool)
  • gcc/warning cleanups

Dickson asked that comments and bugs go to linux-nfs@vger.kernel.org.

Mike Owen replied the same day that the release was not tagged on the public git web view (https://git.linux-nfs.org/?p=steved/nfs-utils.git;a=summary) and asked, “Forgot to tag?” Dickson confirmed the omission and that the tag is now present: “I did... It is there now! Thank you for pointing this out!”

No further technical debate, client-kernel patches, or protocol discussion followed this week. The thread is a userspace release announcement plus a packaging/tagging correction; the new nfs-iostat option is the most directly client-facing feature called out in the announcement, while the leak, netlink, exportfs, and warning work is presented as maintenance rather than a new NFS protocol feature.
