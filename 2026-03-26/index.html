NFS client writeback loop fixes, netfs bvecq overhaul, and NFSD netlink modernization dominate this week

Week ending 2026-03-26

Critical NFS Client Bug Fixes

This week's most impactful activity centers on three separate writeback infinite-loop bugs in the NFS client, each discovered through different failure scenarios:

  • ENOSPC writeback loops — Olga Kornievskaia (Red Hat) submitted v2 of a fix for infinite writeback retries when the server returns ENOSPC during unstable writes. The v2 refines the RFC by storing the synchronous-writeback flag in the persistent nfs_open_context rather than the transient nfs_page, and extends coverage to the LocalIO path. Discovered via xfstest generic/751.

  • -EBADF infinite loop after state recovery failure — Li Lingfeng (Huawei) submitted a one-line fix: when nfs_writepages encounters -EBADF (set by NFS_CONTEXT_BAD after a failed state recovery), it now exits the loop instead of retrying indefinitely. This prevents hung processes and CPU spin after server restarts that return -ESTALE.

  • D-state unkillable processes during writeback — Rushil Patel (GSA Capital) proposed an RFC to make __filemap_fdatawait_range() killable, addressing a production problem where cancelled Slurm jobs with dirty NFS pages become permanently stuck in D-state. Matthew Wilcox engaged positively, suggesting the fix be placed at the NFS client's nfs_wb_all() level rather than in generic filemap code.

Additionally, delegated attribute ctime bugs were fixed by Jeff Layton (v2): utimensat() with atime-only updates and removexattr() now correctly update ctime on the server, resolving xfstest failures generic/221 and generic/728.

A bug report from UCloud describes an NFSv4.1 client hang in the OPEN reclaim path on kernel 5.15, where stale stateids cause NFS4ERR_EXPIRED/NFS4ERR_OLD_STATEID loops despite active SEQUENCE traffic. No maintainer response yet this week.

Major Infrastructure: netfslib bvecq Refactoring

David Howells submitted a 26-patch series replacing folio_queue, rolling_buffer, and ITER_FOLIOQ with a unified segmented bio_vec[] chain (bvecq) across netfslib, cachefiles, AFS, CIFS, 9P, and NFS fscache integration (thread). This supersedes last week's RFC and resolves the FIEMAP controversy by using SEEK_DATA/SEEK_HOLE instead. The series embeds several critical bug fixes: a NULL deref in unbuffered write retry (Deepanshu Kartikey), a kernel BUG for ITER_KVEC iterators, a VM_BUG_ON_FOLIO race in netfs_write_begin() (Viacheslav Dubeyko), and an excess dput() in cachefiles. NFS client developers should note the fscache integration changes will affect cached I/O paths.

NFSD: Netlink Modernization and State Revocation

Two large series advance the migration of nfsd's userspace interfaces from /proc to generic netlink:

  • Netlink upcalls for mountd/exportd (v2, 13 patches) — Jeff Layton replaces the decades-old cache pipe mechanism for auth.unix.ip, auth.unix.gid, svc_export, and nfsd.fh with netlink notifications and dump operations. This enables containerized NFS server deployments and simplifies adding new export options.

  • Automatic NFSv4 state revocation on unmount (v5, 7 patches) — Chuck Lever adds three netlink commands (UNLOCK_IP, UNLOCK_FILESYSTEM, UNLOCK_EXPORT) allowing exportfs -u and administrators to revoke client-held state before unmounting underlying filesystems. The series pivoted from VFS-level hooks (v1–v3) to a pure netlink design in v4/v5.

Both series complement each other and await review outside this window.

NFSD Server-Side Bug Fixes and Optimizations

  • Delegation reference leak — Chuck Lever fixed a memory leak in nfsd4_revoke_states where an extra stid reference was dropped on the failure path, permanently pinning state IDs and inflating cl_admin_revoked. Reviewed-by Jeff Layton.

  • No-op transport enqueues — Chuck Lever submitted a 3-patch optimization reducing wasted svc_xprt_enqueue() calls (85% idle for RDMA, ~195K per workload for TCP). Measurable IOPS and latency improvements. Reviewed-by Jeff Layton.

  • lockd TEST handling regression — Neil Brown submitted v2 of a fix for -ENOLCK on read-only files when querying lock status. The bug existed since early git history but was masked until commit 4cc9b9f2bf4d. Reviewed-by Jeff Layton; backporting strategy discussed with Chuck Lever and Ben Hutchings.

pNFS Block Layouts: Multi-Device Support

Christoph Hellwig submitted a 7-patch series enabling multiple block devices per filesystem for pNFS block-style layouts, targeting XFS Real-Time device support (thread). Chuck Lever's review uncovered three issues: a NULL pointer deref for non-XFS filesystems, a critical fencing logic error where PR revocation targets the wrong device, and an mtime regression in LAYOUTCOMMIT. Hellwig agreed to fix all three, with the fencing issue requiring a broader redesign to track all accessed devices per client.

NFS Server IOMode Debate

Jeff Layton published benchmarking of new nfsd iomodes, finding RWF_DONTCACHE performs "absolutely terrible" for concurrent streaming writes due to aggressive full-file flushes (thread). He proposed an experimental DONTCACHE_LAZY mode with skip-if-busy and proportional caps. Mike Snitzer questioned whether the test scale was sufficient to expose MM bottlenecks, while Chuck Lever corrected an AI-generated analysis error about splice reads.

Other Notable Activity

  • Debug macro cleanup (v5) — Sean Chang's series refactors dprintk/nfs_errorf macros across sunrpc, nfsd, lockd, and the NFS client. Chuck Lever raised concerns about backport safety; Jeff Layton provided Reviewed-by. Awaiting Acked-by from NFS client maintainers for the client-side patch.
  • simple_strto* replacement in sunrpc — Yufan Chen's v3 series replaces deprecated simple_strtol() with kstrtouint() in sunrpc sysctl paths, hardening NFS client debug interfaces against malformed input.
  • generic/551 OOM debate — Christoph Hellwig rejected a test-level workaround for NFS OOM on swapless VMs, calling instead for the NFS client to reduce large memory allocations during AIO-DIO writes.
  • pNFS filelayout op_status handling — Robert Milkowski acknowledged Trond Myklebust's request for evidence and testing before resubmitting a parity fix with the flexfiles driver's data server error handling.
  • NFSv4.0 disabled by default — Salvatore Bonaccorso updated nfs.conf documentation to reflect the security-driven default disablement of NFSv4.0. Reviewed-by Jeff Layton.
