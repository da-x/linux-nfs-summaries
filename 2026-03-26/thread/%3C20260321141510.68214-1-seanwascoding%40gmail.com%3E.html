NFS/SunRPC Debug Macro Cleanup and Refactoring (v5)

Summary

NFS/SunRPC Debug Macro Cleanup and Refactoring (v5)

This week, Sean Chang submitted version 5 of a patch series titled "sunrpc/nfs: cleanup redundant debug checks and refactor macros" to the linux-nfs mailing list. The series targets code hygiene in the SunRPC subsystem, NFS server (nfsd), lockd, and the NFS client, focusing on removing redundant debugging guards and fixing macro expansion issues that trigger Sparse warnings.

Key Technical Arguments and Evolution

The discussion centered on three main technical points: the correctness of do-while(0) wrapping for macros, the safety of removing IS_ENABLED guards via compiler dead-code elimination, and the proper attribution of NFS client changes.

1. Fixing dprintk Type Mismatch (Patch 1/5)

Sean Chang proposed simplifying the dfprintk macro definitions in include/linux/sunrpc/debug.h. The goal was to remove a redundant fmt argument and use no_printk(__VA_ARGS__) directly.

Chuck Lever critiqued the commit message structure, noting that it led with "what" was done rather than "why." More critically, he pointed out a discrepancy in the technical claims:

"The non-debug definitions in the diff below are... not wrapped in do { ... } while (0), and no_printk() evaluates to int (0), not void. The do-while(0) wrapping that was discussed on the list and fixes the Sparse warning appears to be in a later patch in this series... Should the commit message second paragraph be removed or revised to reflect what this patch actually does?"

Sean Chang acknowledged the error on March 25, stating:

"I notice that the commit messages are wrong because the current situation is not the same as when I first sent it, so I will fix this message to the correct one."

He proposed a revised explanation focusing on the efficiency of passing arguments directly through __VA_ARGS__ since no_printk() handles format string validation internally.

2. Removing Redundant Debug Guards (Patches 2/5 and 3/5)

Patches 2/5 and 3/5 removed explicit IS_ENABLED(CONFIG_SUNRPC_DEBUG) checks in nfsd, lockd, and svcrdma. Sean Chang argued that the compiler performs effective dead-code elimination, optimizing out variables declared outside of #ifdef blocks if they are only used within no_printk() calls.

"Verification with .lst files under -O2 confirms that the compiler successfully performs 'dead code elimination'... no stack allocation, no symbol references in the final executable."

Jeff Layton provided a Reviewed-by tag for the entire series on March 23, stating:

"This all looks pretty sane to me."

3. NFS Client Macro Refactoring (Patch 4/5)

Patch 4/5 refactored nfs_errorf and nfs_ferrorf macros in fs/nfs/internal.h to use the standard do-while(0) pattern, addressing a Sparse warning about inconsistent types (void vs int) in ternary operations. It also removed unused nfs_warnf macros.

Chuck Lever requested an Acked-by from NFS client maintainers:

"I need an Acked-by: from the NFS client maintainers on this one."

Sean Chang followed up directly with Trond Myklebust and Anna Schumaker on March 25, highlighting that Andy Shevchenko had already reviewed and tested the change:

"I'd appreciate your feedback or an Acked-by if this looks good to you."

4. Reverting __maybe_unused (Patch 5/5)

The final patch reverted a previous commit that added __maybe_unused attributes to variables in fs/nfsd/export.c. Sean Chang argued these were no longer needed because no_printk() ensures arguments are referenced by the compiler for type checking even when debugging is disabled.

Chuck Lever raised a significant concern about backporting safety:

"This revert is safe only because... [Patch 1/5] already changed the non-debug dfprintk path to use no_printk(VA_ARGS). The commit message doesn't reference that enabling commit by SHA or subject. If this revert is cherry-picked or backported without that pre-requisite, the W=1 build warning returns silently."

He also corrected the technical description:

"The commit message says 'dprintk() now uses no_printk()', but this is true only for the !CONFIG_SUNRPC_DEBUG path. When CONFIG_SUNRPC_DEBUG is enabled, dfprintk expands inode directly via __sunrpc_printk, not through no_printk."

Sean Chang agreed to update the commit message to explicitly state the dependency on Patch 1/5 and clarify that the change applies only to the !CONFIG_SUNRPC_DEBUG case.

Final Conclusions

  • Status: The series received a Reviewed-by from Jeff Layton for the overall approach but requires revised commit messages for Patches 1/5 and 5/5 to accurately reflect technical dependencies and macro behavior.
  • NFS Client Impact: Patch 4/5 is critical for NFS client development as it fixes Sparse warnings in fs/nfs/internal.h. It awaits an Acked-by from the NFS client maintainers (Trond Myklebust or Anna Schumaker).
  • Bug Fix vs. Cleanup: While primarily a cleanup series, Patch 1/5 and Patch 4/5 address specific Sparse warnings (type mismatches), making them bug fixes in the context of static analysis compliance. The removal of redundant guards is a maintenance improvement that relies on compiler optimization guarantees.
  • Next Steps: Sean Chang indicated he would update the commit messages to address Chuck Lever's concerns regarding clarity, dependency tracking for backports, and accurate technical descriptions of macro expansion paths.
