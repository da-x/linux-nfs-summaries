nfs.conf: Update vers4.0 default comment to reflect disabled state

Summary

nfs.conf: Align Documentation with NFSv4.0 Default Disablement

This week saw a brief but important documentation alignment patch concerning the NFS server (nfsd) configuration. The discussion focused on ensuring that the nfs.conf man page and default configuration file accurately reflected recent kernel changes regarding NFS version 4.0 support.

Context: The Shift Away from NFSv4.0

As established in prior weeks, the Linux NFS subsystem has moved to disable NFSv4.0 by default due to its lack of security features (specifically, it lacks strong authentication and encryption capabilities compared to NFSv4.1+). Previous patches, such as bb3f98c848a0 ("nfsd: disable v4.0 by default") and 27b9d85dbc30 ("nfsdctl: disable v4.0 by default"), implemented this change in the kernel code and the nfsdctl utility, respectively.

The Patch: Documentation Consistency

Salvatore Bonaccorso submitted a patch to update the commented-out entry for vers4.0 in the nfsd section of the nfs.conf configuration file 1.

"For consistency reflect as well the 'default off' change in the commented entry for vers4.0 in the nfsd section of the nfs.conf configuration file."

This is a documentation/configuration fix rather than a code bug fix, but it is critical for system administrators who rely on nfs.conf to understand default behaviors. Without this update, the configuration file might misleadingly suggest that NFSv4.0 is enabled by default or require explicit disabling, contradicting the actual kernel behavior.

Review and Acceptance

Jeff Layton, a key maintainer of the Linux NFS subsystem, quickly reviewed the patch. His response was concise and affirmative:

"Reviewed-by: Jeff Layton jlayton@kernel.org" 2

Conclusion

This patch represents the final piece of a multi-component effort to deprecate NFSv4.0 by default across the Linux NFS stack. By updating nfs.conf, the documentation now accurately reflects the security-conscious defaults enforced in the kernel and user-space tools. This ensures that administrators are not surprised by the disabled state of NFSv4.0 and can explicitly enable it only if necessary for legacy compatibility, with full awareness of the implications.

The discussion was straightforward, highlighting the importance of keeping configuration documentation in sync with code changes to maintain system reliability and security transparency.
