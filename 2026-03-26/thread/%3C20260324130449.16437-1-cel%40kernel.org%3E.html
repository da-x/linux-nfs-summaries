sunrpc: Avoid no-op transport enqueues to improve NFS server performance

Summary

Chuck Lever submitted a three-patch series this week targeting the SunRPC service thread scheduler, aiming to eliminate wasted work caused by "no-op" transport enqueues. The changes are focused on the NFS server-side RPC transport layer (net/sunrpc/svc_xprt.c) and represent an optimization effort rather than a bug fix or new feature.

Technical Context and Problem Statement

The core issue identified by Lever is that svc_xprt_enqueue() is called frequently in scenarios where no actual work can be scheduled, causing the system to execute unnecessary memory barriers, flag reads, and tracepoints.

In his cover letter PATCH 0/3, Lever states:

"Reduce the amount of wasted work the svc thread scheduler has to do when no work can be scheduled... I've also measured a slight uptick in IOPS and data throughput as well as a drop in 50th percentile latency for simple workloads on fast storage."

Patch Breakdown

Patch 1: Skip enqueue when no work is pending PATCH 1/3 addresses calls from svc_reserve() and svc_xprt_release_slot(). Lever notes that trace data from a 256KB NFSv3 WRITE workload over RDMA showed:

"11.2 svc_xprt_enqueue() calls per RPC. Of these, 6.9 per RPC lack XPT_DATA and exit svc_xprt_ready() immediately after executing the smp_rmb(), READ_ONCE(), and tracepoint."

The patch introduces a helper svc_xprt_resource_released() that checks for XPT_DATA | XPT_DEFERRED flags before enqueuing. It also upgrades smp_wmb() barriers to smp_mb() to ensure visibility of concurrent flag sets.

Patch 2: Skip enqueue in svc_xprt_received when idle PATCH 2/3 targets svc_xprt_received(), which unconditionally calls svc_xprt_enqueue() after clearing the XPT_BUSY flag. Lever highlights significant inefficiency here:

"Trace data from a 256KB NFSv3 workload over RDMA shows 85% of svc_xprt_received() invocations reach svc_xprt_enqueue() with no pending work flags."

The patch adds a pre-check for work flags between clearing XPT_BUSY and calling the enqueue function.

Patch 3: Skip enqueue when transport is busy PATCH 3/3 handles cases where svc_xprt_resource_released() is called while the transport is still marked as BUSY (e.g., during RPC processing when svc_reserve_auth() reduces the reservation counter). Lever notes:

"Trace data from a 256KB NFSv3 WRITE workload over TCP shows this pattern generates roughly 195,000 wasted enqueue calls -- approximately one per RPC -- each paying the full svc_xprt_ready() cost for no benefit."

The patch adds a BUSY check to prevent these redundant enqueues, relying on the fact that the thread holding XPT_BUSY will call svc_xprt_received() upon completion.

Conclusion

This series represents a targeted performance optimization for the NFS server's RPC transport layer. By avoiding unnecessary enqueue operations when no work is pending, when the transport is idle, or when it is busy, the patches reduce CPU overhead and improve latency metrics. With Jeff Layton's reviews, the series is well-positioned for inclusion in the mainline kernel.
