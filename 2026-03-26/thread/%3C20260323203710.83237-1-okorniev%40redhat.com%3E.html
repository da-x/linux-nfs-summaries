nfsdctl: Improve error messaging when threads are started without listeners

Summary

nfsdctl: Check for Listeners Before Starting Threads

Overview

This week, Olga Kornievskaia submitted a bug fix patch (v2) to improve the user experience of nfsdctl, the NFS server control utility. The patch addresses a confusing error condition that occurs when administrators attempt to start NFS daemon threads before any network listeners have been configured.

The Problem

When an administrator executes a thread command via nfsdctl without first adding any listeners, the tool previously failed with a generic EIO (Input/Output error) — an uninformative and misleading error code that does not help diagnose the actual root cause: the absence of listener sockets.

"When a thread command is executed and yet no listeners have been added prior to it, instead of failing with EIO error print an informative error." — Olga Kornievskaia

Additionally, the "thread 0" command (used to stop all threads) was incorrectly returning an error even when no listeners were present, which is unnecessary since stopping threads should be a safe no-op in that state.

"Also, 'thread 0' command should not error regardless of the listener status." — Olga Kornievskaia

The Fix

The patch modifies utils/nfsdctl/nfsdctl.c, adding 22 lines of code that introduce a pre-flight check for listener availability before threads are spawned. If no listeners exist, the tool now emits a clear, actionable error message instead of the opaque EIO. The "thread 0" path was also corrected to succeed unconditionally.

Classification

This is a bug fix targeting NFS server-side tooling (nfsdctl), not the kernel NFS client or server itself. While it does not directly affect NFS client development, it improves the reliability and diagnosability of NFS server administration — an important consideration for sysadmins managing NFS infrastructure that NFS clients depend upon.

Discussion

The thread contained only this single submission within the current week's window. A reply from Steve Dickson arrived after the window closed (March 29), indicating ongoing review activity but no substantive debate or controversy around the change.

Conclusion

This is a small but practical improvement to nfsdctl's error handling. By replacing a cryptic EIO with an informative message and correcting the behavior of "thread 0", the patch reduces friction for administrators configuring NFS servers — particularly in automated or scripted deployment scenarios where listener setup and thread management may be decoupled.
