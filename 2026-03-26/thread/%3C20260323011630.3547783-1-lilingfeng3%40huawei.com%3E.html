NFS: Fix infinite writeback loop on -EBADF after state recovery failure

Summary

NFS: Stop infinite writeback loop on -EBADF after state recovery failure

Classification

Bug fix — NFS client writeback subsystem.

Overview

Li Lingfeng reported and patched a critical infinite loop in nfs_writepages that can occur when the NFS client encounters a stale file handle during state recovery after a server restart. The patch, submitted on 2026-03-23, modifies the error handling logic to exit the writeback loop when -EBADF is returned, rather than treating it as a non-fatal retryable error.

Technical Background and Bug Description

The bug manifests through the following call chain:

  1. After a server restart, the server may fail to recognize file handles sent by the client, returning -ESTALE.
  2. During state recovery (nfs4_do_reclaim → nfs4_reclaim_open_state → __nfs4_reclaim_open_state), the -ESTALE error triggers nfs4_state_mark_recovery_failed, which in turn calls nfs4_state_mark_open_context_bad.
  3. This sets the NFS_CONTEXT_BAD bit on the nfs_open_context.
  4. During subsequent writeback (wb_workfn → writeback_sb_inodes → do_writepages → nfs_writepages), the presence of NFS_CONTEXT_BAD causes nfs_page_create to return -EBADF.
  5. Critical flaw: Since NFS_CONTEXT_BAD is never cleared and -EBADF was treated as a non-fatal error, nfs_writepages() kept retrying indefinitely, resulting in an infinite loop.

"After a server restart, it may fail to recognize file handles sent by the client and return -ESTALE. As a result, the client sets NFS_CONTEXT_BAD in nfs_open_context."

"During the writeback of dirty pages, the presence of NFS_CONTEXT_BAD causes -EBADF to be returned. Since NFS_CONTEXT_BAD is not cleared and -EBADF is treated as a non-fatal error, nfs_writepages() keeps retrying and eventually falls into an infinite loop."

The Fix

The patch modifies fs/nfs/write.c with a single-line change: when -EBADF is encountered during page writeback, the loop now exits immediately rather than continuing to retry.

"Exit the loop when -EBADF is encountered to avoid this issue."

The fix references commit c6fd3511c339 ("NFS: Further fixes to the writeback error handling") as the original source of the problematic behavior, and links to a prior discussion on lore.kernel.org for additional context.

Significance

This is an important NFS client stability fix. An infinite loop in nfs_writepages can cause:

  • Hung processes attempting to flush dirty pages
  • Potential CPU spin and system responsiveness issues
  • Data writeback stalls after server failover scenarios

The patch ensures that when the NFS context is marked as bad (indicating an unrecoverable state for that open context), the client stops futilely retrying writes and instead exits cleanly, allowing higher-level error handling or application-level recovery to take over.
