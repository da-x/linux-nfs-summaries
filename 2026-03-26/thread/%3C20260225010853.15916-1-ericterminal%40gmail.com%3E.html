Summary

sunrpc sysctl: Series ping and splitting advice for kstrto* migration

Classification: Bug Fix / Code Hardening (NFS Client Subsystem — sunrpc)

This week's activity on Yufan Chen's four-patch series to replace deprecated simple_strto* parsers with modern kstrto* equivalents consisted of a gentle ping from the author and structural review advice from 9p maintainer Dominique Martinet. Only Patch 4/4 touches NFS-relevant code (net/sunrpc/sysctl.c), hardening the sunrpc debug interface by replacing simple_strtol() with kstrtouint().

Prior Context (Brief)

The series was originally submitted on February 25. In prior weeks, network maintainer Simon Horman requested detailed testing evidence, distinguishing between patches motivated as bug fixes versus mere clean-ups. Yufan Chen responded on March 4 with thorough testing details using virtme-ng and a userspace mock harness, emphasizing that the migration to kstrto* enforces strict parsing — rejecting malformed input such as "1abc" with -EINVAL rather than silently accepting partial values.

Evolution of Discussion This Week

Author's Ping (March 24)

Yufan Chen followed up on his March 4 response, seeking confirmation that the provided testing information addressed Horman's concerns:

"Just a gentle ping on this patch series." Re: PATCH v2 0/4

"Does the provided testing information address the concerns? Please let me know if there's anything else I should clarify, or if a v3 is needed to move this forward." Re: PATCH v2 0/4

Maintainer Advice on Series Splitting (March 24)

Dominique Martinet, the 9p maintainer, provided actionable guidance on how to unblock the review process. He identified that mixing a "semi-complex" 9p patch with other networking patches was complicating acceptance:

"Part of the problem is that you've mixed a semi-complex 9p patch with other net patches, I think it'd be easiser to move forward if you'd split this (I can't take non-9p patches, and I'm not sure the -net tree wants the 9p patches as we're a small world appart sometimes...)" Re: PATCH v2 0/4

Martinet also noted his limited ability to test the Xen transport portion and requested that any resend include Stefano Stabellini in CCs:

"For 9p, I can't (easily) test xen, so I'd appreciate if you could resend with Stefano Stabellini stefano.stabellini@amd.com in Ccs as he has been looking after this transport; I can have a quick look but don't have the time for a proper review." Re: PATCH v2 0/4

Significance for NFS Client Development

The NFS-relevant portion of this series (Patch 4/4) hardens proc_dodebug() in net/sunrpc/sysctl.c, which handles sysctl debug parameters for the sunrpc layer underpinning NFS client RPC operations. The key benefits are:

  1. Prevents silent misconfiguration: Malformed input such as "1abc" is now rejected with -EINVAL rather than being silently parsed as "1".
  2. Aligns with kernel best practices: Migrating from deprecated simple_strto* helpers to modern kstrto* functions brings the NFS client's RPC layer in line with current kernel coding standards.

Final Status

The series remains pending acceptance. The path forward, as suggested by Dominique Martinet, involves splitting the multi-subsystem patch set so that individual subsystem maintainers can review their respective portions independently. No further maintainer feedback was received within this week's window beyond Martinet's structural advice. A v3 with split patches and expanded CCs (including Stefano Stabellini for the Xen transport) appears to be the next logical step.
