NFS/blocklayout: Add device usage printing for SCSI layouts

Summary

This week, Christoph Hellwig submitted a small but useful diagnostic improvement to the NFS client's block layout driver. The patch addresses an inconsistency in how device usage is reported between different layout types.

Overview

The discussion centers on a single-patch submission aimed at improving observability into the NFS block layout client's operation. Specifically, it focuses on SCSI layouts, which previously lacked the detailed device usage logging that was already available for standard block layouts.

Technical Argument

Christoph Hellwig noted in his commit message:

"We already print device uses for block layouts, do the same for SCSI layouts as that greatly helps understanding the operation of the client." As mentioned by Christoph Hellwig

The patch modifies fs/nfs/blocklayout/dev.c, adding 5 lines while removing 2, to ensure that SCSI layouts report each device used in the same manner as block layouts do. This is categorized as a bug fix / diagnostic improvement rather than a new feature or protocol change. The existing infrastructure for printing device usage was already present; the patch simply extends this capability to cover SCSI layouts, which had been overlooked.

Evolution and Conclusion

As this was a single-message submission with no replies recorded within the week's window, there was no extended debate. The rationale is straightforward: consistent diagnostic output across layout types aids developers and system administrators in troubleshooting and understanding client behavior. The change is minimal and non-invasive, targeting only the logging/debugging path of the NFS blocklayout driver.

This patch represents ongoing maintenance work on the NFS client's pNFS (parallel NFS) block layout support, ensuring that all layout variants provide equally useful diagnostic information.
