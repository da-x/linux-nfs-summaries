NFS/SunRPC Debug Macro Cleanup and Refactoring (v4)

Summary

This week, Sean Chang submitted version 4 of a five-patch series titled "sunrpc/nfs: cleanup redundant debug checks and refactor macros" to the linux-nfs mailing list. The series targets code hygiene across the SunRPC subsystem, NFS server (nfsd), lock manager (lockd), RDMA transport (svcrdma), and the NFS client.

The primary goals of the series are twofold: first, to remove redundant IS_ENABLED(CONFIG_SUNRPC_DEBUG) guards that are already handled internally by the dprintk() macros; and second, to fix macro expansion issues—specifically type mismatches flagged by Sparse—by adopting safer do-while(0) patterns. While primarily a cleanup effort, the series includes important bug fixes for static analysis warnings in the NFS client codebase.

Key Technical Arguments and Evolution

The v4 iteration incorporated significant feedback from Andy Shevchenko, who provided both Reviewed-by and Tested-by tags for the series. The discussion focused on macro safety, compiler optimization guarantees, and proper commit hygiene.

1. Fixing dprintk Type Mismatch (Patch 1/5)

Sean Chang proposed simplifying the dfprintk macro definitions in include/linux/sunrpc/debug.h. Following a suggestion from David Laight, the patch removes an unnecessary fmt argument and uses no_printk(__VA_ARGS__) directly.

Crucially, to resolve a Sparse warning regarding a void vs int type mismatch when dfprintk is used in conditional statements, Sean wrapped the non-debug definition in a do-while(0) block. As explained in the patch:

"To resolve a Sparse warning (void vs int mismatch) when dfprintk is used in conditional statements, wrap the non-debug definition in a do-while(0) block. This ensures the macro always evaluates to a void expression."

2. Removing Redundant Debug Guards (Patches 2/5 and 3/5)

Patches 2/5 and 3/5 removed explicit IS_ENABLED(CONFIG_SUNRPC_DEBUG) checks in nfsd, lockd, and svcrdma. Sean Chang argued that modern compilers perform effective dead-code elimination, optimizing out variables declared outside of #ifdef blocks if they are only referenced within no_printk() calls.

He provided empirical verification to support this claim:

"Verification with .lst files under -O2 confirms that the compiler successfully performs 'dead code elimination'. Even when variables... or static helper functions... are declared without #ifdef, they are completely optimized out (no stack allocation, no symbol references in the final executable) as they are only referenced within no_printk()."

3. NFS Client Macro Refactoring (Patch 4/5)

From an NFS client development perspective, Patch 4/5 is significant as it addresses specific static analysis warnings in fs/nfs/internal.h. The patch refactored nfs_errorf() and nfs_ferrorf() to the standard do-while(0) pattern for safer macro expansion and kernel style compliance. Additionally, it removed unused nfs_warnf() and nfs_fwarnf() macros.

This change was prompted by a report from the kernel test robot:

"Reported-by: kernel test robot lkp@intel.com"

Andy Shevchenko reviewed this patch and added historical context regarding the unused macros, noting:

"You can also add that they were never actually used from the day of introduction by the commit ce8866f0913f ('NFS: Attach supplementary error information to fs_context.')."

4. Reverting Obsolete __maybe_unused Attributes (Patch 5/5)

The final patch removed __maybe_unused attributes from variables in fs/nfsd/export.c. These attributes had been added in a previous commit to avoid W=1 build breaks, but Sean Chang argued they were no longer necessary because the refactored no_printk() ensures arguments are referenced by the compiler for type checking even when debugging is disabled.

Andy Shevchenko provided feedback on the commit structure, suggesting it be formatted as a proper revert:

"Just make it a revert: proper Subject like 'Revert: "..."' and the Git added line 'This reverts ...'."

Sean Chang incorporated this suggestion in v4, reverting the specific commit (ebae102897e7) as recommended.

Final Conclusions

  • Status: The v4 series successfully integrated feedback from Andy Shevchenko, earning Reviewed-by and Tested-by tags. The changes are technically sound, relying on well-established compiler behaviors for dead-code elimination and standard kernel macro practices for type safety.
  • NFS Client Impact: Patch 4/5 is a direct bug fix for the NFS client, resolving Sparse warnings in fs/nfs/internal.h and cleaning up dead code (nfs_warnf). This improves the maintainability and static analysis compliance of the NFS client subsystem.
  • Bug Fix vs. Cleanup: The series blends cleanup with bug fixes. Patches 1/5 and 4/5 address specific Sparse warnings (type mismatches), making them necessary fixes for W=1 build configurations. The removal of redundant guards in patches 2/5 and 3/5 is a maintenance improvement that simplifies the codebase without altering runtime behavior.
  • Next Steps: With positive reviews from Andy Shevchenko, the series was poised for further review by subsystem maintainers (such as Chuck Lever and Jeff Layton) in subsequent versions. As seen in later iterations (v5), the series continued to evolve with additional feedback on commit message clarity and backporting safety.
