NFSD: Fix delegation reference leak in nfsd4_revoke_states

Summary

NFSD: Fix delegation reference leak in nfsd4_revoke_states

This thread addresses a critical bug fix in the NFS server (NFSD) state management code, specifically concerning a memory leak and counter inflation issue related to delegation revocation.

Classification

Bug Fix: This is not a new feature or protocol change, but a correction of a resource leak introduced by a previous patch.

Technical Summary

Chuck Lever identified a reference counting error in nfsd4_revoke_states(). The function takes an extra reference on the state ID (stid) before calling unhash_delegation_locked().

The bug occurs when unhash_delegation_locked() returns false, indicating that the delegation was already unhashed by a concurrent path. In this failure path:

  1. The pointer dp is set to NULL.
  2. The call to revoke_delegation() is skipped.
  3. The extra reference taken earlier is never released.

Lever explained the consequences of this leak:

"Each occurrence permanently pins the stid in memory. The leaked reference also prevents nfs4_put_stid() from decrementing cl_admin_revoked, leaving the counter permanently inflated."

This issue was traced back to a previous fix for a race condition between the laundromat and free_stateid, with the commit hash 8dd91e8d31fe cited in the Fixes tag.

Discussion Evolution

The discussion was brief, consisting of two messages within the same day (March 24, 2026):

  1. Patch Submission: Chuck Lever submitted the patch to drop the extra reference in the failure path, preventing the permanent pinning of the state ID and correcting the cl_admin_revoked counter.

  2. Review: Jeff Layton reviewed the patch and provided a quick endorsement:

"Good catch! Reviewed-by: Jeff Layton jlayton@kernel.org"

Conclusion

The patch was accepted with a Reviewed-by from Jeff Layton. This fix is important for NFS server stability, as it prevents memory leaks associated with state IDs and ensures that administrative counters accurately reflect the state of revoked delegations. Without this fix, servers under load with concurrent delegation revocations could experience gradual memory exhaustion and incorrect internal accounting.
