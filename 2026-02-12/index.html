NFS Client 7.0 Pull: LRU Delegation Returns, v4.1 Default; Server-Side Scalability Push with TCP Lock-Free Redesign and Signed Filehandles

Week ending 2026-02-12

NFS Client: Linux 7.0 Pull Request Submitted

Anna Schumaker submitted the [GIT PULL] Please Pull NFS Client Updates for Linux 7.0 on February 12, encompassing 41 files with significant architectural changes (thread).

Key Client Features

  • LRU-Based Delegation Return: Christoph Hellwig's 31-patch series overhauls delegation handling, introducing an LRU list for reclaiming stale delegations rather than scanning all of them. This reduces unnecessary network traffic and improves cache hit rates. The series also removes obsolete helper functions and simplifies reference counting throughout delegation.c.
  • NFS v4.1 Becomes Default: Anna Schumaker's 14-patch restructuring splits NFS v4.0-specific operations into dedicated files (nfs40client.c, nfs40proc.c) and introduces a KConfig option to disable v4.0 entirely, reflecting the community's move away from legacy protocol support.

Critical Client Bug Fixes

  • NFS/localio Deadlock Prevention: Mike Snitzer and Trond Myklebust contributed six patches hardening the local I/O path — preventing direct reclaim recursion into NFS via nfs_writepages, using GFP_NOIO in nfs_local_commit, handling short writes by retrying, and removing erroneous -EAGAIN handling. These address real-world deadlock scenarios on systems with NFS over local storage backends.
  • SUNRPC GSS kref Leak: Daniel Hodges fixed a reference-counting leak in the GSS authentication error path (gss_alloc_msg) introduced by a prior rebalancing commit, preventing memory exhaustion on Kerberos-secured NFS mounts (thread).
  • pNFS Wake-Up Fix: Olga Kornievskaia addressed a missing wake-up call when waiting on NFS_LAYOUT_DRAIN, preventing tasks from sleeping indefinitely during layout state transitions.
  • Readdir Slow-Start Regression: Sagi Grimberg resubmitted his fix for a performance regression in directory reading where READDIR requests started with small sizes and ramped up exponentially (thread).

Client Refactoring

  • Writeback Internal Decoupling: Kundan Kumar's series introduces helper APIs to stop filesystems (including NFS) from directly accessing writeback accounting internals, improving modularity (thread).
  • nfsrahead Event-Driven Monitoring: Aaron Tomlin replaced the brittle polling loop in nfsrahead with libmount event-driven monitoring, fixing failures on slow-boot systems (thread).

NFS Server (NFSD): Major Scalability and Security Push

NFSD 7.0 Pull Merged

Chuck Lever's [GIT PULL] NFSD changes for v7.0 was successfully merged, delivering dynamic thread pool sizing, POSIX ACL extension support, and extensive xdrgen tool improvements (thread).

TCP Lock Contention Reduction (v2)

Chuck Lever posted an 8-patch v2 series reducing NFSD TCP lock contention through dedicated receiver kthreads per connection and flat combining for socket sends. This eliminates serialization on the socket lock during receives and amortizes mutex acquisition across batched sends — profiling showed ~15% of cycles were spent in spin-wait paths (thread).

svcrdma Scalability Enhancements (RFC)

A 15-patch RFC series targets RPC/RDMA scalability with lock-free completion queues, per-transport kthreads replacing the global workqueue, WR chaining for Write chunks, and fair queuing for Send Queue access (thread).

Signed Filehandles Applied

Benjamin Coddington's kNFSD signed filehandle series (v6) was applied to nfsd-testing, adding a SipHash-based MAC to filehandles for client-side integrity verification (thread).

pNFS Layout Recall Timeout (v11)

Dai Ngo posted version 11 of the layout recall timeout patch after an extensive review cycle. This critical reliability fix prevents nfsd thread starvation when unresponsive pNFS clients hold block layouts, integrating SCSI PR fencing with lease manager callbacks. v11 also fixes a latent __break_lease timestamp wrap-around bug that could hang uniprocessor systems (thread).

Ongoing Investigations

refcount_t Underflow in Re-export (v6.18)

Daire Byrne reported mixed results testing a candidate fix for the NFSD re-export crash. The busiest server stabilized, but a lower-load server continued crashing — suggesting multiple trigger paths remain (thread).

knfsd Read IOPS Ceiling

After confirming xpt_mutex flat-combining patches were effective, Daire Byrne and Chuck Lever identified two new bottlenecks: the lwq spinlock in the SunRPC thread dispatcher and group sorting in nfsd_setuser (significant for AD-integrated environments with large group memberships). Patches are promised (thread).

Debates and Future Work

xattr Caching Infrastructure

Miklos Szeredi proposed a common xattr caching layer for network filesystems (NFS, FUSE) at LSF/MM/BPF. The current nfs4_xattr_cache was criticized for its per-inode table design. Amir Goldstein cited Samba workloads fetching user.DOSATTRIB on every readdir as a concrete beneficiary (thread).

Stable Backports

Jianqiang Kang submitted backports for the svc_proc_register() return-code fix to 6.1.y and 6.6.y stable trees, addressing syzbot-reported kernel warnings during nfsd teardown (thread).

nfs-utils 2.8.5

The release was announced last week; Debian maintainers inquired about missing git tags (thread).
