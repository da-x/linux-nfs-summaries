NFSD: Layout Recall Timeout and Fencing Integration (v10)

Summary

NFSD: Enforcing Layout Recall Timeouts and Integrating Lease Fencing

This week, the Linux NFS community reviewed v10 of a significant server-side patch by Dai Ngo (Oracle) titled "[PATCH v10 1/1] NFSD: Enforce timeout on layout recall and integrate lease manager fencing" [id://20260210181632.1161855-1-dai.ngo@oracle.com]. While primarily an NFSD (server) change, this work is critical for the stability of environments using Parallel NFS (PNFS) layouts, ensuring that misbehaving or stalled clients do not block server resources indefinitely.

Key Technical Arguments

The patch addresses a scenario where a layout conflict triggers a recall. Without a timeout, nfsd threads can become blocked in __break_lease, degrading server performance for all clients.

"When a layout conflict triggers a recall, enforcing a timeout is necessary to prevent excessive nfsd threads from being blocked in __break_lease ensuring the server continues servicing incoming requests efficiently." [id://20260210181632.1161855-1-dai.ngo@oracle.com]

The solution introduces a new callback, lm_breaker_timedout, within lease_manager_operations. If a layout recall times out and the client has not released the layout, the server initiates a "fencing" operation (using SCSI Persistent Reserve PREEMPT) to revoke the client's access to the underlying block device. This fencing occurs asynchronously via a system workqueue with exponential backoff, ensuring the conflicting lease remains active until the fence is complete, thereby preventing other clients from accessing the file prematurely.

Evolution of Discussion and Bug Discovery

The review process uncovered both administrative improvements and a critical latent bug in the kernel's lease management code.

Administrative and Logging Feedback

Jeff Layton [id://eb1757d7f2409ffb792d800166daff8a8c63b09e.camel@kernel.org] raised concerns about log verbosity, noting that the current implementation might "fire too often." He suggested:

"It'd be better to do it just once. This may mean tracking a per-client flag of some sort."

Layton also emphasized the need for better administrative visibility, particularly in containerized environments where dmesg access is restricted, and requested documentation updates in Documentation/admin-guide/nfs/pnfs-scsi-server.rst.

Critical Bug: Tight Spin in Lease Breaking

Chuck Lever identified a severe bug in the interaction between the new timeout logic and the existing __break_lease function [id://a06f4c17-8227-4c04-b270-5c064b7de79c@app.fastmail.com].

When lm_breaker_timedout returns false (indicating the lease should remain on the list for fencing), __break_lease loops and recomputes the wait timeout. However, because the original timeout has already expired, fl_break_time is in the past. The calculation break_time -= jiffies results in a large unsigned value that wraps to a negative signed long when passed to wait_event_interruptible_timeout().

"schedule_timeout() treats negative values as a bug: it prints a KERN_ERR message with dump_stack() and returns immediately without sleeping... On a uniprocessor system the fence worker workqueue thread never gets scheduled because the spinning task never calls schedule(), so the system hangs." [id://a06f4c17-8227-4c04-b270-5c064b7de79c@app.fastmail.com]

Lever suggested that lm_breaker_timedout should extend fl_break_time before returning false to allow the server thread to sleep properly.

Final Conclusions and Next Steps

Dai Ngo acknowledged all feedback in two separate responses [id://88bdf658-19c3-4203-8948-5aaa64718b47@oracle.com], [id://1677f1ed-27db-4525-ae3e-5e4d12a9f5a9@oracle.com].

Regarding the critical spin-lock bug, Dai proposed a more robust fix within __break_lease itself, rather than patching it specifically for layouts. This approach would also protect against similar issues with timed-out delegations:

"I think this issue should be addressed by __break_lease since we can have the same problem with timed out delegation... if (break_time < jiffies) break_time = jiffies + lease_break_time * HZ;" [id://1677f1ed-27db-4525-ae3e-5e4d12a9f5a9@oracle.com]

Dai confirmed that v11 of the patch will include:

  1. Per-client logging flags to reduce spam.
  2. Inclusion of client IDs in logs for easier administration.
  3. Documentation updates for PNFS SCSI server fencing.
  4. The generalized fix for __break_lease timestamp wrap-around.
  5. Code cleanups (removing unused variables, fixing backoff logic).

This discussion highlights the rigorous review process ensuring that new NFS features like layout fencing do not introduce regressions in core kernel subsystems like file locking, ultimately safeguarding the reliability of NFS storage for all clients.
