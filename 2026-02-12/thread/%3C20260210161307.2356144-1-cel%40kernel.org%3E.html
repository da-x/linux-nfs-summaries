NFSD 7.0 Pull Merged: Dynamic Thread Pooling, POSIX ACLs, and xdrgen Overhaul

Summary

NFSD 7.0 Pull Request Merged: Dynamic Thread Pooling, POSIX ACL Support, and xdrgen Improvements

Classification

Merge window pull request / feature delivery. This thread documents the submission and successful merge of the NFSD (NFS server daemon) changes for the Linux v7.0 merge window.

Overview

On February 10, Chuck Lever submitted the [GIT PULL] NFSD changes for the v7.0 merge window 2026-02-10, aggregating 68 files with 2,267 insertions and 372 deletions across 10 contributors. Two days later, the pr-tracker-bot confirmed that the pull request was merged into torvalds/linux.git:

Key Technical Deliverables

1. Dynamic Thread Pool Sizing for NFSD (Bug Fix / Performance Optimization)

Neil Brown and Jeff Layton contributed a significant architectural improvement: dynamic thread pool sizing for the NFS server. The sunrpc layer now tracks minimum and maximum thread counts per pool, with NFSD adjusting running thread counts based on workload pressure.

As Chuck Lever summarized in his pull request notes:

"idle threads exit after a timeout when the pool exceeds its minimum, and new threads spawn automatically when all threads are busy. Administrators control this behavior via the nfsdctl netlink interface."

This addresses a long-standing operational challenge where administrators had to manually tune the number of nfsd threads — over-provisioning wastes CPU resources while under-provisioning degrades throughput. The implementation includes:

  • Splitting svc_set_num_threads() into two functions for finer control
  • Introducing minimum thread tracking per pool
  • Allowing svc_recv() to return -ETIMEDOUT and -EBUSY to signal thread pressure
  • Admin controls via the netlink interface to set minimum threads per pool

2. POSIX ACL Extension Support (New Feature)

Rick Macklem, FreeBSD NFS maintainer, contributed server-side support for the POSIX ACL extension to NFSv4, as specified in draft-ietf-nfsv4-posix-acls. This is a notable protocol enhancement that allows NFSv4 clients to get and set POSIX access and default ACLs using native NFSv4 operations:

"This extension allows NFSv4 clients to get and set POSIX access and default ACLs using native NFSv4 operations, eliminating the need for sideband protocols." Chuck Lever

The feature is gated by a Kconfig option (CONFIG_NFSD_V4_POSIX_ACL) since the IETF draft has not yet been ratified. The implementation includes:

  • XDR encoding/decoding for POSIX ACL trueform attributes
  • Support for file creation with POSIX ACLs
  • Integration into the NFSv4 SETATTR operation
  • Updated SUPPATTR bitmasks to advertise POSIX ACL support

3. xdrgen Tool Improvements (Infrastructure Enhancement)

Chuck Lever delivered 20 patches including extensive improvements to the xdrgen tool, which generates C code from XDR specifications:

  • Enhanced error reporting covering parsing, AST transformation, and invalid declarations
  • Enum decoders now validate incoming values against valid enumerator lists
  • New support for pass-through lines (embedding C directives in XDR specs)
  • 16-bit integer type support
  • Program number definitions
  • Fix for a memory leak in auth_gss XDR decoding error paths

4. Bug Fixes and Reliability Improvements

Several important bug fixes were included:

Async COPY cancellation on state revocation: When an administrator revokes NFSv4 state via the unlock_fs interface, ongoing async COPY operations referencing that filesystem are now properly cancelled with CB_OFFLOAD callbacks notifying affected clients. This prevents stale operations from continuing after administrative intervention.

Anthony Iliopoulos contributed two fixes:

  • Preventing request deferral during idmap lookup (avoiding potential deadlocks)
  • Fixing the return error code for nfsd_map_name_to_[ug]id

Olga Kornievskaia fixed FMODE_NOCMTIME setting in delegation opens, ensuring correct mtime behavior for delegated files.

Neil Brown ensured vfs_test_lock() never returns FILE_LOCK_DEFERRED, addressing a locking semantics issue that could cause problems in the lock manager.

Bridge from Prior Weeks

This pull request represents the culmination of development work spanning the entire v7.0 cycle. Several related threads from prior weeks fed into this merge:

  • The dynamic thread pool patches built on earlier sunrpc infrastructure work
  • The POSIX ACL implementation required extensive XDR generation improvements via xdrgen
  • The case folding series (targeting v7.1) was intentionally held back from this pull, as noted in prior summaries

Notably, the pNFS layout recall timeout patch by Dai Ngo (v9 posted Feb 10) was not included in this pull request, as it remained under review at the time of submission. That work continues separately and targets a future merge window.

Significance for NFS Client Development

While this pull request is server-focused, several changes have direct implications for NFS client developers:

  1. POSIX ACL support: Clients implementing the draft POSIX ACL extension can now interact with Linux servers using native NFSv4 operations rather than sideband protocols like utimes or sysfs access. This simplifies client implementations and improves interoperability.

  2. Dynamic thread pooling: Server-side performance improvements indirectly benefit clients by reducing latency under variable workloads, as the server can scale its thread count to match demand.

  3. xdrgen improvements: Better error reporting and enum validation in generated code improve reliability for both server and client XDR processing paths.

  4. Async COPY cancellation: Clients performing offload copy operations receive proper CB_OFFLOAD callbacks when the server administrator revokes filesystem state, enabling clients to handle interruptions gracefully.

Final Conclusions

The NFSD v7.0 pull request has been successfully merged into the mainline kernel. The delivery represents a substantial release with:

  • A new dynamic thread pool sizing mechanism for improved server resource management
  • First-class POSIX ACL support via the NFSv4 protocol extension
  • Significant infrastructure improvements to the xdrgen toolchain
  • Multiple bug fixes enhancing reliability and correctness

The merge closes the v7.0 NFSD development cycle, with ongoing work on pNFS layout recall timeouts and case folding targeting future windows.
