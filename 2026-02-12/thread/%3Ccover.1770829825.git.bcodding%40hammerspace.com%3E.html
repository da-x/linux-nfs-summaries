nfs-utils: Signed Filehandle Support (v6)

Summary

nfs-utils: Signed Filehandle Support (v6)

Type: New Feature / Userspace Enhancement
Status: Patch series submitted; no discussion this week.

Overview

Benjamin Coddington from Hammerspace submitted version 6 of a two-patch series adding support for signed NFS filehandles in nfs-utils. This userspace work corresponds to a parallel kernel patch series (also v6) that enables the Linux NFS server (kNFSD) to append a Message Authentication Code (MAC) to filehandles, thereby preventing clients from forging or tampering with filehandle values.

Technical Details

The patch series introduces two key capabilities:

1. Export Option sign_fh

Patch 1/2 adds the sign_fh export option to exportfs. When this option is set for an export, the server is signaled to sign filehandles for that export. As Coddington explains:

"If configured with 'sign_fh', exports will be flagged to signal that filehandles should be signed with a Message Authentication Code (MAC)." As described in patch 1/2

2. Filehandle Key Management

Patch 2/2 adds support for passing a secret key from userspace to the kernel via netlink. The key is derived as follows:

"The secret key passed to the server is the first 128 bits of a sha1 hash of the contents of a file configured via the nfs.conf server section 'fh_key_file'. Exports that have the option 'sign_fh' set will cause the server to use this key to append an 8-byte siphash of the filehandle onto each filehandle." Cover letter

The implementation allows administrators to configure the key file via:

  • The fh-key-file=<path> option in the [nfsd] section of nfs.conf, which is processed by nfsdctl autostart.
  • A new -k, --fh-key-file=<path> command-line argument for nfsdctl threads.

Evolution from Previous Versions

This is the sixth version of the userspace patches. Key changes noted since v5 include:

"Changes on v5:

  • add -k,--fh-key_file= argument to 'nfsdctl threads' command (Jeff Layton)
  • fail if 'nfsdctl threads -k' unsuported by kernel (Jeff Layton)" Cover letter

And for v6:

"Changes on v6:

  • fix a premature exit from fh-key-file hashing routine" Cover letter

The series builds upon several prerequisite patches, including Jeff Layton's work on min-threads and handling of netlink attributes for kernels that may not support the most recent features, as well as Coddington's own patch for automatic module loading.

Conclusion

No replies or discussions occurred during this week's window. The patch series was submitted on February 11, 2026, with the cover letter inviting:

"Comments and critique welcomed." Cover letter

This work represents an important security enhancement for NFS server deployments, allowing administrators to protect against filehandle forgery attacks through cryptographic signing. The feature requires coordination between userspace (nfs-utils) and kernel-space (kNFSD), with both components needing to be updated simultaneously.
