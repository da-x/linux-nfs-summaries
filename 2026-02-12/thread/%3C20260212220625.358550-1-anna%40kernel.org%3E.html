NFS Client Updates for Linux 7.0: Pull Request Summary

Overview

Discussion type: Feature additions, bug fixes, and cleanups for the NFS client subsystem targeting the Linux 7.0 merge window.

On February 12, Anna Schumaker submitted the **[GIT PULL] Please Pull NFS Client Updates for Linux 7.0](https://lore.kernel.org/linux-nfs/20260212220625.358550-1-anna@kernel.org/), requesting that Linus Torvalds pull a substantial batch of changes from the nfs-for-7.0-1 tag in the linux-nfs.git repository. The update encompasses 41 files, with 1,372 insertions and 1,588 deletions — a net reduction of over 200 lines driven largely by refactoring and cleanup work.

Anna summarized the package as:

"NFS Client Updates for Linux 7.0"

The changes build upon commit 24d479d26b25bce5faea3ddd9fa8f3a6c3129ea7 (Linux 6.19-rc6) and extend through the final commit dd2fdc3504592d85e549c523b054898a036a6afe, which addresses a SUNRPC reference-counting leak.

New Features

1. LRU-Based Delegation Return Mechanism

Christoph Hellwig contributed an extensive series of 31 patches that overhaul delegation handling in the NFS client. A centerpiece of this work is:

"Use an LRU list for returning unused delegations"

This introduces a more intelligent strategy for reclaiming stale or unreferenced delegations. Rather than aggressively scanning all delegations, the client now tracks them on a Least Recently Used (LRU) list and returns delegations from the end of the list when over a watermark threshold. This reduces unnecessary network traffic and improves cache hit rates for active files.

2. KConfig Option to Disable NFS v4.0; NFS v4.1 Becomes Default

Anna Schumaker contributed 14 patches that restructure the NFS v4.0 codebase and introduce a configuration option:

"Introduce a KConfig option to disable NFS v4.0 and make NFS v4.1 the default"

This is a significant architectural shift. The changes include:

  • Splitting NFS v4.0-specific operations into dedicated files (nfs40client.c, nfs40proc.c, and a new header nfs40.h)
  • Making various NFS v4.0 operations static to improve encapsulation
  • Merging CONFIG_NFS_V4_1 with CONFIG_NFS_V4
  • Adding a way to disable NFS v4.0 entirely via KConfig

This reflects the community's recognition that NFS v4.0 is increasingly legacy, while v4.1 and later versions provide essential features like state renewal, migration recovery, and session management.

Bugfixes

The pull request addresses several important bugs, with particular emphasis on NFS/localio (local I/O optimization) and pNFS reliability:

NFS/localio Fixes (Mike Snitzer, Trond Myklebust)

Four patches from Mike Snitzer and two from Trond Myklebust address critical issues in the local I/O path:

  1. Handle short writes by retrying — Ensures data integrity when underlying storage returns partial write completions.
  2. Prevent direct reclaim recursion into NFS via nfs_writepages — Fixes a potential deadlock scenario where memory reclaim could recurse back into the NFS layer.
  3. Use GFP_NOIO and non-memreclaim workqueue in nfs_local_commit — Prevents I/O-triggered memory reclaim from causing recursive lockups.
  4. Remove -EAGAIN handling in nfs_local_doio() — Simplifies error handling by removing unnecessary retry logic for transient failures.

These fixes collectively harden the local I/O path against resource exhaustion and deadlock scenarios that could affect systems using NFS with local storage backends.

pNFS Wake-Up Fix (Olga Kornievskaia)

"pNFS: fix a missing wake up while waiting on NFS_LAYOUT_DRAIN"

This patch addresses a subtle concurrency bug where tasks waiting for layout drain completion could be left sleeping indefinitely due to a missing wake-up call. This is critical for pNFS clients that rely on proper layout state transitions.

Readdir Slow-Start Regression (Sagi Grimberg)

"fs/nfs: Fix a readdir slow-start regression"

A performance regression in directory reading was identified and corrected, restoring expected readdir throughput after previous changes inadvertently introduced latency.

SUNRPC GSS Authentication Reference Leak (Daniel Hodges)

"SUNRPC: fix gss_auth kref leak in gss_alloc_msg error path"

This patch fixes a kernel reference-counting leak in the GSS authentication subsystem's error handling path, preventing memory leaks during failed RPC authentication attempts. This is the final commit in the pull request, underscoring its importance as a last-minute stability fix.

Other Cleanups and Improvements

Christoph Hellwig's Delegation Handling Overhaul

Hellwig's 31-patch series goes far beyond the LRU feature. It includes:

  • Removal of obsolete delegation helper functions (__nfs_client_for_each_server, nfs_inode_detach_delegation, nfs_start_delegation_return, etc.)
  • Simplification of delegation reference counting using refcount_inc_not_zero
  • Proper RCU critical section handling in delegation return paths
  • Fix for delayed delegation return handling (a bug fix embedded within the cleanup)

This represents one of the largest single-contributor refactorings in this pull request, touching 594 lines in delegation.c alone.

NFSv4 Lease Handling Improvements (Sergey Shtylyov)

Two patches improve lease period handling:

  • Pass lease period in seconds to nfs4_set_lease_period()
  • Limit the lease period to prevent unreasonably long values

Security and Debug Cleanups

  • Stephen Smalley: Unified security_inode_listsecurity() calls for consistency.
  • Ben Dooks: Fixed SUNRPC debug field definitions when CONFIG_SUNRPC_DEBUG is unset.
  • Chenguang Zhao: Changed list definition method in SUNRPC for better code clarity.
  • Chen Ni: Converted a comma to semicolon in nfs4proc.c (syntax fix).

Significance for NFS Client Development

This pull request represents a maturation of the NFS client subsystem in three key dimensions:

  1. Architectural Modernization: The split of NFS v4.0 into dedicated files and the introduction of a KConfig toggle to disable it reflect a deliberate move away from legacy protocol support. As Anna Schumaker noted through her 14-patch restructuring effort, the codebase is being organized around minor-version operations rather than monolithic version handling.

  2. Reliability Hardening: The NFS/localio fixes address real-world deadlock and resource exhaustion scenarios that could affect production systems. The pNFS wake-up fix and SUNRPC reference leak fix further improve stability.

  3. Code Quality: The net line reduction (−216 lines) despite adding new features demonstrates a strong emphasis on code simplification. Christoph Hellwig's delegation overhaul is particularly noteworthy for removing dead code paths and simplifying complex reference-counting logic.

Relation to Concurrent Server-Side Work

While this pull request focuses on the NFS client, it is worth noting that significant server-side (NFSD) work was also active during this week, including Dai Ngo's multi-version patch series for enforcing layout recall timeouts with lease manager fencing integration (versions 6–9). That server-side work complements these client updates by improving pNFS reliability from both ends of the protocol stack. See related summaries for those threads.

Conclusion

The NFS Client Updates for Linux 7.0 represent a well-rounded release comprising new features, critical bug fixes, and extensive code cleanup. The pull request is ready for integration into the mainline kernel, bringing improved delegation management, modernized version handling, and hardened local I/O support to NFS clients worldwide.
