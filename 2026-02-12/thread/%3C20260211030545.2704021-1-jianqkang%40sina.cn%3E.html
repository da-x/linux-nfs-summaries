Summary

nfsd: Fix Ignored Return Code from svc_proc_register()

Overview

This week, a backport patch was submitted to the 6.1.y stable tree addressing a bug in the NFS server (nfsd) initialization code where error returns from procfs registration were being silently ignored. This fix ensures that failures during nfsd network namespace initialization are properly detected and handled, preventing kernel warnings during teardown.

Technical Details

The issue was originally reported by syzbot, indicating that nfsd_proc_stat_init() was ignoring the return value of svc_proc_register(). As explained in the patch description:

"If the procfile creation fails, then the kernel will WARN when it tries to remove the entry later."

The root cause is that svc_proc_register() can fail under two conditions: if the dentry cannot be allocated, or if an identical dentry already exists. While the second case is deemed unlikely in the nfsd_net construction codepath, ignoring the return value entirely meant that memory allocation failures would go undetected until teardown, at which point a kernel warning would be triggered.

The Fix

The patch, originally authored by Jeff Layton and upstreamed as commit 930b64ca0c511521f0abdd1d57ce52b2a6e3476b, modifies three files:

  • fs/nfsd/stats.c and fs/nfsd/stats.h: Updated nfsd_proc_stat_init() to return the same pointer type as svc_proc_register(), allowing callers to check for errors.
  • fs/nfsd/nfsctl.c: Modified nfsd_net_init() to check the return value and fail nfsd_net construction if registration fails, returning -ENOMEM in such cases.

An additional adjustment was made by Jianqiang Kang to ensure proper cleanup pairing:

"Update the cleanup path to use nfsd_stat_counters_destroy. This ensures the teardown logic is correctly paired with nfsd_stat_counters_init, as required by the current NFSD implementation."

Classification

This is a bug fix, not a new feature or protocol change. It addresses a resource management error that could lead to kernel warnings and potential instability during nfsd initialization failure scenarios. The fix is marked for stable backport to v6.9 and later kernels, with this submission targeting the 6.1.y LTS branch.

Conclusion

The patch was submitted as a single-message thread with no further discussion this week. It represents a straightforward defensive programming improvement, ensuring that error conditions during nfsd procfs registration are properly propagated rather than silently ignored. The fix closes the syzbot-reported issue and improves the robustness of NFS server initialization.
