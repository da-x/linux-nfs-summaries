NFS readdir slow-start regression fix resent

Summary

Overview

This thread consists of a single message this week: a resend of a previously submitted bug-fix patch for the NFS client. The patch addresses a performance regression in directory reading (readdir) operations, an important area of NFS client development.

Background (Prior Weeks)

The discussion originated in late December 2025 when Sagi Grimberg first posted PATCH v1, followed by PATCH v2 on December 27, 2025. On January 5, 2026, Sagi followed up asking:

"Anna, Trond, any feedback on this patch?"

No further discussion or review comments were recorded in the prior thread before this week's resend.

This Week's Activity

On February 7, 2026, Sagi Grimberg resubmitted PATCH v2 with the subject line [PATCH v2 RESEND] fs/nfs: Fix readdir slow-start regression. The resend appears to be a nudge for review attention after the lack of response in prior weeks.

Technical Details

This is a bug fix targeting a performance regression introduced by commit 580f236737d1 ("NFS: Adjust the amount of readahead performed by NFS readdir"). That earlier commit reduced the amount of readahead name caching done by the NFS client, which had efficiency benefits but introduced an unintended side effect.

Sagi describes the problem as follows:

"The downside of this approach is READDIR now may suffer from a slow-start issue, where initially it will fetch names that fit in a single page, then in 2, 4, 8 until the maximum supported transfer size (usually 1M)."

In other words, directory reads start with small request sizes and gradually ramp up exponentially — a classic "slow-start" pattern that degrades initial readdir performance. The patch aims to strike a compromise:

"This patch tries to take a balanced approach between mitigating the slow-start issue still maintaining some efficiency gains."

The fix is minimal, modifying only fs/nfs/dir.c with 2 insertions and 2 deletions. Changes from v1 included minor phrasing adjustments and the addition of a Fixes: tag.

Conclusions

  • No review feedback was received this week or in the prior weeks since the patch's initial submission.
  • The patch remains pending review by NFS client maintainers (Anna Schumaker and Trond Myklebust).
  • This is a targeted bug fix for an NFS client performance regression, not a new feature or protocol change.
  • The resend strategy suggests the patch may require additional visibility to move forward in the kernel development cycle.
