sunrpc/NFS: Post-application validation of make W=1 build fixes

Summary

This week's activity on this thread was limited to a single follow-up message from Andy Shevchenko, providing post-application validation for the three-patch series that was applied in the prior week. The series addressed compiler warnings that surfaced when building with make W=1 (warnings-as-errors mode) in the sunrpc and NFS blocklayout subsystems.

Key Event: LKP Success Report

Andy Shevchenko confirmed that the Linux Kernel Lab (LKP) automated testing infrastructure reported no regressions after Chuck Lever applied the patches to the nfsd-testing tree:

"FWIW, I have got a success report from LKP." As stated by Andy Shevchenko

This validation is significant because it confirms that the build hygiene fixes did not introduce any functional regressions in NFS client or server codepaths.

Background (Prior Week)

The three-patch series, applied last week, addressed:

  1. Patch 1/3: Removal of an unused-but-set variable count in bl_write_pagelist() in the NFS blocklayout driver, which Clang flagged as an error under -Werror,-Wunused-but-set-variable.
  2. Patch 2/3: Elimination of the RPC_IFDEBUG() macro, replacing it with inline conditional logic to simplify the debug infrastructure.
  3. Patch 3/3: Fixing unused variables when dprintk() is compiled as a no-op by forwarding parameters to no_printk(), which also enabled format-string checking even in non-debug builds.

These changes are classified as bug fixes focused on build robustness rather than runtime behavior or protocol modifications. The successful LKP report closes the loop on this series, confirming its safe integration into the NFS development tree.
