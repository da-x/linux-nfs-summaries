Case Folding v6: Target Kernel Clarification — v7.1 Confirmed

Type: New feature / protocol enhancement (continued from prior weeks)

Prior Weeks Recap

Chuck Lever's 16-patch series "Exposing case folding behavior" (v6, posted January 20th) introduces a kernel-wide fileattr_get mechanism for filesystems to report case sensitivity and case preservation characteristics. The series enables NFSD, ksmbd, and NFS clients to accurately convey filename semantics across protocol boundaries. Key review items included a UAPI flag collision with Andrey's fsverity xflag patch (noted by Darrick J. Wong) and an initialization bug in ioctl_getflags() flagged by Jan Kara, where relocated struct zeroing could clear the flags_valid hint before the filesystem callback reads it. See last week's summary for full details on the v6 series, including NFS client fileattr_get support for re-export scenarios and NFSD enhancements for dynamic case sensitivity reporting via NFSv3 PATHCONF and NFSv4 FATTR4 attributes.

In the week ending January 29th, Christian Brauner confirmed that the series would target the v7.1 merge window, not v6.19, noting:

"We're starting to cut it close even with the announced -rc8. So my current preference would be to wait for the 7.1 merge window." Christian Brauner

Brauner further revealed that he had already incorporated the series into his development tree:

"It's usually most helpful if people resend after -rc1 is out because then I can just pull it without having to worry about merge conflicts. But fwiw, I have you series in vfs-7.1.casefolding already. Let me push it out so you can see it." Christian Brauner

Chuck Lever concluded that week by outlining plans for version 7:

"There will be at least one more revision of this series (and it can happen in a few weeks) to split 1/16 as Darrick requested, and address the nit that Jan noted." Chuck Lever

This Week's Activity: Target Kernel Clarification

This week saw a single message from Cedric Blancher (Institut Pasteur), who previously advocated for earlier inclusion in 6.x LTS kernels citing downstream distribution needs. On February 10th, Blancher followed up on Lever's statement about the upcoming v7 revision, seeking explicit confirmation of the target kernel:

"Are you targeting LInux 7.0 or Linux 7.1?" Cedric Blancher

This question, while brief, reflects the ongoing tension between kernel development process discipline and downstream distribution requirements. Blancher's earlier advocacy for 6.x LTS inclusion — citing Bosch's interest in having case folding support available in long-term stable kernels — underscores the practical importance of this feature for enterprise deployments where Linux NFS servers interact with Windows/macOS clients that expect accurate FATTR4_CASE_INSENSITIVE reporting.

The question remains unanswered at week's end, though Christian Brauner's prior statement that the series is already queued in his vfs-7.1.casefolding branch makes v7.1 the de facto target. No further patches were posted or reviewed during this period; all activity was meta-discussion about merge timing.

NFS Client Development Significance

While no code changes occurred this week, the implications for NFS client development remain substantial:

  1. Target kernel confirmed: The case folding feature will land in v7.1, giving NFS client developers a clear timeline for integration planning. The fileattr_get implementation in the NFS client (patch 10/16 from January) enables re-export scenarios where an NFS server accurately reports the case sensitivity of underlying NFS mounts to its clients.

  2. Downstream relevance confirmed: Cedric Blancher's continued engagement highlights real-world demand for case folding support, particularly for environments where Windows-based NFS clients such as ms-nfs41-client require servers to report FATTR4_WORD0_CASE_INSENSITIVE = TRUE for proper operation.

  3. No code changes this week: No patches were posted or reviewed during this period; all activity was process coordination.

Final Conclusions

  • Target kernel: v7.1 merge window (confirmed by Brauner's vfs-7.1.casefolding branch)
  • Series status: Queued in Christian Brauner's VFS tree, awaiting v7 revision
  • Open items for v7: Split patch 1/16 per Darrick J. Wong's request; address Jan Kara's initialization bug in ioctl_getflags()
  • Unanswered question: Cedric Blancher asked whether the target is Linux 7.0 or 7.1, but no response was recorded this week

The case folding series remains on a strong trajectory toward eventual merge in v7.1, with broad support from filesystem maintainers established across six prior versions and two remaining review items clearly identified for resolution.
