SUNRPC: Fix gss_auth kref Leak in GSS Authentication Error Path

Overview

This week, a targeted bug fix was submitted to address a reference counting leak in the Linux NFS client's Secure RPC (SUNRPC) Generic Security Services (GSS) authentication code. The patch, authored by Daniel Hodges, corrects an error path omission introduced by a previous rebalancing commit.

Technical Details

The Bug

The issue stems from commit 5940d1cf9f42, titled "SUNRPC: Rebalance a kref in auth_gss.c," which added a kref_get(&gss_auth->kref) call to balance the gss_put_auth() performed in gss_release_msg(). However, this change inadvertently created a leak on a specific error path.

As Daniel Hodges explained:

"Commit 5940d1cf9f42 ("SUNRPC: Rebalance a kref in auth_gss.c") added a kref_get(&gss_auth->kref) call to balance the gss_put_auth() done in gss_release_msg(), but forgot to add a corresponding kref_put() on the error path when kstrdup_const() fails."

The leak occurs under the following conditions:

  1. The service_name parameter is non-NULL.
  2. The kstrdup_const() allocation fails.

In this scenario, the function jumps to the err_put_pipe_version label, which calls put_pipe_version() and kfree(gss_msg), but critically omits releasing the gss_auth reference that was acquired earlier. This results in a kernel reference count leak where the gss_auth structure is never freed, potentially leading to memory exhaustion over time in systems heavily utilizing GSS-secured NFS mounts.

The Fix

The patch introduces a forward declaration for gss_free_callback() and adds a kref_put() call within the err_put_pipe_version error path to properly release the reference. This ensures that the reference count is correctly balanced regardless of whether the allocation succeeds or fails.

The fix is marked for stable kernel backporting:

"Cc: stable@vger.kernel.org"

Significance for NFS Client Development

This fix highlights the ongoing maintenance burden of reference counting in complex subsystems like SUNRPC, particularly when rebalancing changes are made to existing code paths. GSS authentication is critical for secure NFS deployments (e.g., Kerberos-based authentication), and memory leaks in this path can have significant operational impacts on production systems.

The patch represents a classic "error path cleanup" bug fix, ensuring that all resources acquired before a potential failure point are correctly released. This type of fix is essential for the stability and reliability of the NFS client infrastructure.

Conclusion

Daniel Hodges' patch provides a straightforward and necessary correction to prevent a memory leak in the SUNRPC GSS authentication module. With no further discussion or review comments recorded in this window, the patch stands as a clean bug fix ready for integration and stable backporting.
