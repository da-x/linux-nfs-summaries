kNFSD Signed Filehandles Patch Series Applied

Summary

kNFSD Signed Filehandles: Patch Series Applied to nfsd-testing

This week concluded a significant development effort in the Linux NFS server (kNFSD) with the acceptance of Benjamin Coddington’s patch series introducing signed filehandles. This feature represents a new security enhancement for the NFS protocol implementation, allowing the server to append a Message Authentication Code (MAC) to filehandles provided to clients.

Discussion Overview

The thread centered on the final review and application of the "v6" iteration of the patch series titled "[PATCH RESEND v6 0/3] kNFSD Signed Filehandles." The series aims to enable the Linux NFS server to cryptographically sign filehandles, thereby providing integrity verification for clients.

Key Technical Arguments and Evolution

The discussion this week was brief but conclusive, marking the transition from review to integration.

Chuck Lever, the maintainer responsible for the nfsd-testing tree, applied the series after making some cosmetic adjustments. He noted:

"Applied to nfsd-testing, thanks!

Cosmetic changes were made. Please review the patches in branch."

The applied commits are as follows:

  1. 622534d4910f: NFSD: Add a key for signing filehandles
  2. 482e15caec14: NFSD/export: Add sign_fh export option
  3. b4169318a0af: NFSD: Sign filehandles

Benjamin Coddington responded positively to the application, highlighting a specific technical improvement made by Lever during the cosmetic cleanup. He noted that Lever had refined the netlink attribute policy usage:

"Looks good - you even noticed NLA_POLICY_EXACT_LEN(16) and trimmed out the

if (nla_len(attr) != sizeof(siphash_key_t))

Thanks for all the time you took helping this get trimmed up."

Conclusion

The patch series has been successfully merged into the nfsd-testing branch. The discussion confirmed that the code had been cleaned up, specifically regarding the validation of the SipHash key length using netlink attribute policies. This marks a successful integration of a new security feature for kNFSD, moving it closer to eventual inclusion in the mainline kernel.
