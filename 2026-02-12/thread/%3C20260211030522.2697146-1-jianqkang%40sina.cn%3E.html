nfsd: Fix ignored return code in svc_proc_register()

Summary

nfsd: Fix Ignored Return Code in svc_proc_register() (Backport to 6.6.y)

Overview

This week, a backport patch was submitted to the stable kernel tree (specifically for the 6.6.y branch) addressing a bug in the NFS server (nfsd) subsystem. The issue involves the improper handling of return codes from svc_proc_register(), which could lead to kernel warnings during cleanup if procfile creation fails.

Technical Details

The discussion centers on a bug fix originally upstreamed by Jeff Layton and backported by Jianqiang Kang.

The Bug

In the original code, nfsd_proc_stat_init() ignored the return value of svc_proc_register(). As Jeff Layton explained in the upstream commit:

"If the procfile creation fails, then the kernel will WARN when it tries to remove the entry later."

The failure of svc_proc_register() can occur if:

  1. The dentry cannot be allocated (memory exhaustion).
  2. An identical dentry already exists (unlikely in the nfsd_net construction path).

The Fix

The patch modifies nfsd_proc_stat_init() to return the same pointer type as svc_proc_register(). Consequently, nfsd_net_init() is updated to check this return value. If registration fails, the nfsd_net construction is aborted with -ENOMEM.

Additionally, the backport includes an update to the cleanup path:

"[Update the cleanup path to use nfsd_stat_counters_destroy. This ensures the teardown logic is correctly paired with nfsd_stat_counters_init, as required by the current NFSD implementation.]" — Jianqiang Kang [id://20260211030522.2697146-1-jianqkang@sina.cn]

Impact

This fix prevents kernel warnings and potential instability during NFS server initialization failures. It was reported by syzbot, indicating it was caught via automated fuzzing.

Conclusion

This is a critical stability fix for the NFS server subsystem, ensuring proper error handling during network namespace initialization. The patch has been signed off by Jeff Layton, Chuck Lever, and Jianqiang Kang, and is marked for stable kernels starting from v6.9.
