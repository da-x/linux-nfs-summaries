NFS Client Cleanup: Decoupling from Writeback Internals

This week saw a brief but significant code cleanup effort affecting the NFS client, as well as f2fs and GFS2. The patch series **[PATCH 0/4] Avoid filesystem references to writeback internals](https://lore.kernel.org/linux-nfs/20260211070057.22001-1-kundan.kumar@samsung.com/), submitted by Kundan Kumar of Samsung, aims to improve kernel code hygiene by removing direct dependencies on writeback subsystem internals from filesystem code.

Technical Context and Arguments

The discussion centers on a refactoring initiative originally suggested by Christoph Hellwig. The goal is to introduce dedicated helper APIs for dirty-limit checks and writeback accounting, thereby encapsulating the complexities of the writeback subsystem.

Kundan Kumar noted that the series implements this suggestion:

"As suggested by Christoph [1], filesystem code that directly accesses writeback internals is split out"

The series explicitly states there are "No functional changes intended," highlighting its nature as a maintenance and cleanup patch rather than a feature addition or bug fix. For the NFS client specifically, the changes involve updating fs/nfs/internal.h and fs/nfs/write.c to stop using writeback internals for WB_WRITEBACK accounting.

Evolution of the Discussion

The thread progressed rapidly with broad support from key maintainers:

  1. Jeff Layton, a primary NFS maintainer, endorsed the changes immediately:

    "Seems sensible."

    He provided his Reviewed-by tag, indicating that the NFS-specific portions of the patch are acceptable for inclusion.

  2. Andreas Gruenbacher, representing GFS2 interests, also approved the series:

    "Sure, that won't hurt."

  3. Christoph Hellwig, who initiated the refactoring idea, reviewed the final implementation. While he agreed with the approach, he raised an important technical caveat regarding cgroup writeback support:

    "Looks fine as a cleanup, but maybe add comments that these functions must not be used by file systems that support cgroup writeback and thus can have multiple bdi_writeback structures per bdi?"

Conclusion

The thread concluded with general approval for the cleanup. The NFS client will benefit from reduced coupling to internal writeback structures, simplifying its codebase. The primary action item remaining is for the author to add clarifying comments regarding cgroup writeback limitations, as requested by Hellwig, before the patches are merged into the mainline kernel. This change represents a positive step toward better abstraction in the VFS/writeback layer, ensuring that filesystems like NFS rely on stable helper APIs rather than internal implementation details.
