NFS Weekly Summaries

  1. Summaries

POSIX ACL support lands, lease opt-in architecture shifts VFS, critical migration and refcount bugs surface

Week ending 2026-01-08

Critical Bugs

  • NFSv4.1 Migration Use-After-Free — Wonju Ka (Kakao Corp.) reported a kernel panic during transparent state migration when in-flight RPCs are retried with stale session credentials from the source server against the target. The mismatch causes refcount_t: addition on 0; use-after-free panics under heavy I/O (all 16 slots utilized). No fix posted yet. (thread/20260107074430.84482-1-dylan.ka@kakaocorp.com.md)

  • NFSD refcount_t Underflow on v6.18 Re-export — Daire Byrne's high-throughput (50 Gbit) NFS re-export server continues to crash in nfsd4_sequence_done. Chuck Lever narrowed the regression window to session slot xarray/shrinker commits from v6.13/v6.14 and suggested a candidate unmerged fix (cbfd91d22776). Improved ftrace/kprobe debugging methodology was shared. (thread/CAPt2mGPafo29KgjW9Rb17OhBDLnB-3fZn18zFQEhYk7Eitf6BA@mail.gmail.com.md)

  • EOF Page Pollution Fix Regresses ext4 in Nested VMs — NVIDIA bisected intermittent ext4 checksum errors during nested-VM boot to Trond Myklebust's "Protect against eof page pollution" commit. Reverting the fix eliminates corruption. Investigation into interactions with NFS discard/unmap on qcow2 images is ongoing. (thread/447f41f0-f3ab-462a-8b59-e27bb2dfcbc0@nvidia.com.md)

  • NFSv4.1 Slot Table Draining + Memory Reclaim Deadlock — Wang Zhaolong reported a permanent hang when nfs_release_folio() performs synchronous commits during reclaim while the session slot table is draining. Trond Myklebust proposed an async-only nfs_wb_folio_reclaim() fix, conceptually approved and awaiting formal posting. (thread/20251230071744.9762-1-wangzhaolong@huaweicloud.com.md)

NFS Client Focus

  • NFSv4.2 POSIX ACL Client Support — Rick Macklem posted v1 (7-patch) and v2 (8-patch) series implementing client-side support for the IETF draft POSIX ACL extension, enabling lossless getfacl/setfacl over NFSv4.2. A key architectural decision from Trond Myklebust: check server->attr_bitmask[] directly rather than adding new NFS_CAP_xxx bits, avoiding capability-bit exhaustion. (thread/20260102232934.1560-1-rick.macklem@gmail.com.md, thread/CAM5tNy7QEoa1iE6Cu6Q-aOSzEodQoHF9z2AUwdq7sSnUS5XamA@mail.gmail.com.md)

  • LRU-Based Delegation Eviction — Christoph Hellwig posted a 24-patch series replacing the NFS client's inefficient "return-on-close" delegation policy with an LRU-based eviction strategy. Reported 97% reduction in on-the-wire operations and ~40% speedup for Python module-import workloads. Discussion covered LFU alternatives, RECALL_ANY support, and server-vs-client recall interests. (thread/20260107072720.1744129-1-hch@lst.de.md)

  • IOCB_NOWAIT Writes v5/v6 — Christoph Hellwig's series to restore non-blocking writes for io_uring reached v6, including an NFS-specific refactor splitting nfs_update_timestamps into atime and ctime/mtime paths. Reviewed-by from Jan Kara and Jeff Layton. (thread/20260106074628.1609575-1-hch@lst.de.md)

  • LOCALIO Deadlock Fixes — Mike Snitzer submitted a 4-patch series preventing direct reclaim recursion into NFS via nfs_writepages in LOCALIO, using GFP_NOFS allocations and non-memreclaim workqueues. (thread/20260107160858.6847-1-snitzer@kernel.org.md)

NFS Server (NFSD) Highlights

  • NFSv4.2 POSIX ACL Server Support (v2) — Chuck Lever posted a 12-patch series implementing server-side POSIX draft ACL support, gated behind CONFIG_NFSD_V4_POSIX_ACLS. Jeff Layton: "This all looks pretty reasonable. Nice work!" (thread/20260104161019.3404489-1-cel@kernel.org.md)

  • ACL/SELinux Bug Fixes Backported to 6.6.y — v2 of a 4-patch stable backport fixing: (1) POSIX ACLs silently dropped during NFSv4 file creation, (2) security labels not applied on create, (3) NFSv3 atomicity races in nfsd_setattr(). CI and LLM review clean. (thread/2025122941-civic-revered-b250@gregkh.md)

  • Automatic NFSv4 State Revocation on Unmount (v2) — Chuck Lever's 6-patch series auto-revokes opens, locks, delegations, async COPYs, and cached files when an exported filesystem is unmounted, eliminating the need for manual /proc/fs/nfsd/unlock_fs. Jeff Layton suggested a future redesign using SRCU notifiers instead of fs_pin. (thread/20260108004016.3907158-1-cel@kernel.org.md)

  • Dynamic NFSD Thread Pool (v2 Applied) — Jeff Layton's 8-patch series enabling nfsd to scale threads up/down based on workload demand was applied to nfsd-testing. Backward-compatible: defaults to static behavior. (thread/20260106-nfsd-dynathread-v2-0-416e5f27b2b6@kernel.org.md)

  • SCSI Persistent Registration Fencing Fix (v6 Applied) — After six revisions, the xarray-based per-client fencing tracker for pNFS block layouts was applied. Prevents redundant fence operations when multiple layout recalls target the same device. (thread/20260108144421.3955020-1-cel@kernel.org.md)

Major Trends and Ongoing Debates

  • VFS Lease Architecture Overhaul — Jeff Layton posted a 24-patch series (targeting v7.0) requiring filesystems to explicitly opt-in to lease support, reversing the decades-old implicit-default model. A companion 6-patch fix for v6.19 properly denies directory leases on NFS, Ceph, SMB, and other network filesystems. Christoph Hellwig agreed leases should be opt-in long-term; discussion covered FUSE and kernfs edge cases. (thread/20260108-setlease-6-20-v1-0-ea4dec9b67fa@kernel.org.md, thread/20260107-setlease-6-19-v1-0-85f034abcc57@kernel.org.md)

  • NFS_CAP Bit Exhaustion — With all NFS_CAP_xxx bits consumed, Trond Myklebust established a precedent: new NFSv4 features implemented via attribute types should be detected through server->attr_bitmask[], avoiding redundant capability-tracking sources of truth. (thread/CAM5tNy7QEoa1iE6Cu6Q-aOSzEodQoHF9z2AUwdq7sSnUS5XamA@mail.gmail.com.md)

  • Delegation Recall Strategy — The LRU delegation series sparked debate on whether servers (via RECALL_ANY) or clients should drive delegation reclamation. Consensus: server and client have "orthogonal interests" — servers care about resource utilization, clients know which delegations applications are actively using.
