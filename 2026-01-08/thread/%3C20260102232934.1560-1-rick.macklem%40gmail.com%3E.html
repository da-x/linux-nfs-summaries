NFSv4.2 POSIX ACL Client Support Patch Series

Summary

NFSv4.2 POSIX ACL Client Support — Initial Patch Series

Classification: New feature (protocol extension implementation)

Rick Macklem posted a seven-patch series introducing client-side support for the NFSv4.2 POSIX draft ACL extension, based on the IETF Internet Draft "POSIX Draft ACL support for Network File System Version 4, Minor Version 2". The series was submitted on January 2, 2026, and as of the end of this reporting week, no review replies had been posted.

Overview

The patch series implements a sideband protocol for NFSv4.2 that allows POSIX draft ACLs to be acquired and set directly — bypassing the existing "loosey" NFSv4-to-POSIX ACL mapping algorithm. As Rick Macklem explains in the cover letter:

"The Internet draft 'POSIX Draft ACL support for Network File System Version 4, Minor Version 2' describes an extension to NFSv4.2 so that POSIX draft ACLs can get acquired and set directly, without using the loosey NFSv4->POSIX draft mapping algorithm. It extends the protocol with four new attributes."

This approach is analogous to the NFSACL sideband protocol used for NFSv3, enabling getfacl(1)/setfacl(1) to work transparently over NFSv4.2 mounts when both client and server support the extension.

Patch Breakdown

Patch 1/7: Predefined Client Operations Enum

Adds entries to the predefined Linux client operations enum for getting and setting POSIX draft ACLs, extending include/linux/nfs4.h.

Patch 2/7: POSIX Draft ACL Structures

Introduces new structures and definitions for handling POSIX draft ACLs in the NFS client, adding 49 lines to include/linux/nfs_xdr.h.

Patch 3/7: Global Accessor Function

Makes posix_acl_from_nfsacl() global so it can be called from the NFSv4.2 client code handling POSIX draft ACL extensions.

Patch 4/7: Shared ACL Helper Functions

Refactors three functions — nfs3_prepare_get_acl(), nfs3_complete_get_acl(), and nfs3_abort_get_acl() — by moving them to a new shared file fs/nfs/nfs34acl.c and renaming them to nfs34_XXX(). This enables reuse from both NFSv3 and the new NFSv4.2 POSIX ACL code paths.

Patch 5/7: Server Capability Check

Makes nfs4_server_supports_acls() global and extends it to check for POSIX draft ACL support, allowing the capability to be verified in nfs4proc.c.

Patch 6/7: Superblock Flag

Sets SB_POSIXACL on the superblock when both POSIX draft default ACL and POSIX draft access ACL attributes are supported by the server, enabling proper VFS-level ACL semantics.

Patch 7/7: Core Implementation

The largest patch adds the full procedure implementations and XDR encoding/decoding for the four new NFSv4.2 POSIX draft ACL attributes. It touches fs/nfs/nfs42proc.c (304 lines), fs/nfs/nfs42xdr.c (642 lines), and several other files, totaling 965 insertions. Rick Macklem notes:

"The last patch is rather large, but I would get either build failures or build warnings when I broke it up into smaller chunks."

Known Limitations

Rick Macklem calls out an important caveat regarding the "per file" scope mode:

"The current implementation may not handle the 'per file' scope, where individual file objects store/use either an NFSv4 ACL or a POSIX draft ACL. The only known file system that implements this is IBM's GPFS, and only if the 'all' option is set for ACLs on it. Until a server implements this case, it will be difficult to implement correct client semantics for this case."

Dependencies

The series requires "patch 0001 from the server series to be applied first," indicating a companion server-side implementation is expected.
