NFSD v2: ACL, Security Label, and Atomicity Bug Fixes Backported to 6.6.y Stable Tree

Summary

NFSD: v2 Backport Series for ACL, Security Label, and Atomicity Bug Fixes to 6.6.y Stable Tree

Overview

This week, Chuck Lever submitted version 2 of a four-patch series targeting the Linux 6.6 stable tree to address multiple bugs in the NFS server (NFSD). This is classified as a bug fix backport effort, not a new feature or protocol change. The v1 series was posted last week (prior summary); this v2 iteration refines the approach based on automated feedback.

Evolution from v1 to v2

The v1 series, posted on January 3rd, encountered an automated report indicating that the primary fix patch failed to apply cleanly to the 6.6-stable tree. In response, Chuck Lever reworked the series for v2:

"I received an automated report that patch 'NFSD: NFSv4 file creation neglects setting ACL' failed to apply to the 6.6-stable tree. This series is my attempt to address that failure." Chuck Lever

The key change in v2:

"Changes since v1: Replace 1/4 with the upstreamed version of that commit" Chuck Lever

The series again underwent automated quality assurance:

"LLM agent review for possible regressions reported no issues" "CI testing reported no regressions" Chuck Lever

Patch Series Breakdown

The four-patch series touches 10 files across the fs/nfsd/ directory, with a net result of 45 insertions and 30 deletions:

Patch 1/4: nfsd: convert to new timestamp accessors Jeff Layton

A preparatory change updating the NFS server code to use newer kernel inode timestamp accessor functions (upstream commit 11fec9b9fb04). This patch serves as a dependency for the subsequent atomicity fix:

"Stable-dep-of: 24d92de9186e ('nfsd: Fix NFSv3 atomicity bugs in nfsd_setattr()')" Chuck Lever

Patch 2/4: nfsd: Fix NFSv3 atomicity bugs in nfsd_setattr() Trond Myklebust

This patch addresses critical race conditions in NFSv3 attribute-setting operations. The core issue is that the guarded SETATTR mechanism — designed to prevent races with concurrent WRITE and SETATTR calls — was checking the guard time against the inode ctime before acquiring the inode lock, defeating its purpose:

"The main point of the guarded SETATTR is to prevent races with other WRITE and SETATTR calls. That requires that the check of the guard time against the inode ctime be done after taking the inode lock." Trond Myklebust

Additionally, the fix accounts for NFSv3's 32-bit timestamp limitations:

"Furthermore, we need to take into account the 32-bit nature of timestamps in NFSv3, and the possibility that files may change at a faster rate than once a second." Trond Myklebust

This patch is reviewed by Jeff Layton and NeilBrown, and serves as a dependency for the security label fix.

Patch 3/4: nfsd: set security label during create operations Stephen Smalley

This patch fixes a bug where security labels passed by NFSv4 clients during file creation were received by nfsd but never actually applied to the new inode. The root cause: nfsd_create_setattr() passes the label down, but nfsd_setattr() is never invoked for the label-setting step:

"When security labeling is enabled, the client can pass a file security label as part of a create operation for the new file, similar to mode and other attributes. At present, the security label is received by nfsd and passed down to nfsd_create_setattr(), but nfsd_setattr() is never called and therefore the label is never set on the new file." Stephen Smalley

Smalley also raises an important observation about ACLs:

"Looking at nfsd_setattr() I am uncertain as to whether the same issue presents for file ACLs and therefore requires a similar fix for those." Stephen Smalley

This concern is directly addressed by patch 4/4. The patch includes a detailed SELinux reproducer demonstrating the bug — files created via NFSv4 receive incorrect security contexts (test_file_t instead of the expected test_filesystem_filetranscon_t).

Patch 4/4: NFSD: NFSv4 file creation neglects setting ACL Chuck Lever

This is the primary bug fix driving the entire series. When an NFSv4 client creates a file with a POSIX ACL containing named principals, the ACL is silently dropped:

"An NFSv4 client that sets an ACL with a named principal during file creation retrieves the ACL afterwards, and finds that it is only a default ACL (based on the mode bits) and not the ACL that was requested during file creation. This violates RFC 8881 section 6.4.1.3: 'the ACL attribute is set as given'." Chuck Lever

The root cause lies in nfsd_create_setattr(), which calls nfsd_attrs_valid() to determine whether to invoke nfsd_setattr(). However, this validation function checks only for standard iattr changes and security labels — not POSIX ACLs:

"However, nfsd_attrs_valid() checks only for iattr changes and security labels, but not POSIX ACLs. When only an ACL is present, the function returns false, nfsd_setattr() is skipped, and the POSIX ACL is never applied to the inode." Chuck Lever

The bug was originally reported by Aurélien Couderc and traces back to commit c0cbe70742f4 ("NFSD: add posix ACLs to struct nfsd_attrs"). The fix is a minimal one-line change in fs/nfsd/vfs.h to include POSIX ACLs in the validity check.

Significance for NFS Client and Server Development

While this series targets the NFS server (NFSD), it has direct implications for NFS clients:

  1. ACL enforcement gap: Clients creating files with named-principal ACLs via NFSv4 would experience silent security policy violations, as the requested ACLs were never applied. The server would return a default ACL derived from mode bits instead — a compliance violation against RFC 8881.

  2. SELinux label misapplication: Clients using NFSv4.2 with security labeling (e.g., SELinux) would see files created with incorrect security contexts, potentially breaking mandatory access control policies.

  3. NFSv3 atomicity races: The nfsd_setattr() fix prevents data consistency issues when clients perform concurrent attribute updates (e.g., via chmod or chown) over NFSv3 mounts.

  4. Stable tree importance: These fixes target the 6.6 LTS kernel, which is widely deployed in production environments. The backport ensures that enterprise NFS deployments benefit from these security and correctness improvements without requiring a full kernel upgrade.

Conclusion

This week's v2 submission represents a refined stable-tree backport effort resolving three distinct but related bugs in the Linux NFS server: POSIX ACL omission during file creation, SELinux security label omission during create operations, and NFSv3 atomicity race conditions in attribute setting. The series incorporates prerequisite patches from multiple contributors (Jeff Layton, Trond Myklebust, Stephen Smalley) and passes both LLM-based review and CI testing with no reported regressions. Chuck Lever added his sign-off to the timestamp accessor patch in a follow-up message, completing the series for integration into the 6.6.y stable kernel.
