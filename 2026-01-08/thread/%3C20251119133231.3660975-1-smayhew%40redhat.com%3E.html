SUNRPC GSS Slack Estimate Recalculation — Patch Status Update

Summary

SUNRPC: Check if we need to recalculate slack estimates

Summary

Classification: Bug fix (GSS/Kerberos authentication slack size calculation)

This thread concerns a patch originally submitted by Scott Mayhew on November 19, 2025, addressing an issue with GSS (Kerberos) authentication in the SUNRPC layer — specifically around recalculating "slack estimates" when the incoming GSS verifier is larger than previously recorded. This week, Debian maintainer Salvatore Bonaccorso followed up on the status of the patch, and Chuck Lever explained why it had not been merged.

Background: The Original Patch

Scott Mayhew's original patch addressed a scenario where the GSS credential/context used for an RPC call employs a different encryption type (enctype) than the one used by the machine credential/context. When this happens, the incoming GSS verifier can be larger than what was previously recorded on the gss_auth structure, necessitating a recalculation of slack variables to maintain proper XDR payload alignment.

The patch referenced Debian bug #1120598 and added logic to check:

if (cred->cr_auth->au_verfsize < (XDR_QUADLEN(len) + 2))

This would trigger a slack size update when the verifier exceeded expectations.

Initial Review (November 2025)

Chuck Lever reviewed the patch on the same day, offering a minor comment improvement suggestion:

"No quibble with the code change, but IMO the comment should work a little harder to explain why the increase is needed."

He suggested expanding the inline comment to clarify that when the incoming verifier is larger than expected, it indicates the GSS context is using a different enctype than the one used initially by the machine credential, and thus a slack size update is needed to maintain good payload alignment.

Despite this positive review, the patch was not merged into mainline.

This Week's Activity (January 2–8, 2026)

Debian Maintainer Follow-Up

Salvatore Bonaccorso, a Debian developer, reached out on January 2 to inquire about the patch's status:

"I was looking in Debian for the state of this and noticed this was later on never applied/submitted to mainline, is this correct? Did it fell through the cracks or is it considered not to be a problem to further tackle?"

Chuck Lever's Response

Chuck Lever responded the same day, providing clarity on why the patch had not been merged:

"After further consideration, we concluded the above change is not an adequate repair for this issue."

He indicated that while the winter holidays had delayed progress, Scott Mayhew was expected to continue working on a better fix. This suggests the original approach — checking only whether the verifier size exceeded expectations — was insufficient to fully address the underlying problem with slack estimation in GSS-protected NFS sessions.

Technical Significance

This issue pertains to the SUNRPC layer's handling of GSS/Kerberos authentication, which is critical for secure NFS deployments. The "slack" variables control buffer sizing and XDR payload alignment in RPC messages. When different encryption types produce verifiers of varying sizes, incorrect slack estimates can lead to:

  • Buffer overflow or underflow conditions
  • Misaligned XDR payloads causing protocol errors
  • Performance degradation from excessive reallocations

The fact that the initial fix was deemed "not an adequate repair" suggests the problem is more nuanced than a simple size comparison — likely involving edge cases in how slack estimates are initialized, updated, or propagated across credential and context lifecycle events.

Status

Unresolved. The patch has not been merged. Scott Mayhew is expected to continue investigating a more comprehensive fix after the winter holiday break. Debian users tracking this issue (bug #1120598) should monitor for an updated patch submission.
