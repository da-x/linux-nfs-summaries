NFS/localio: Deadlock Prevention and Code Cleanup Improvements

Summary

NFS/localio: Various Improvements to Prevent Deadlocks and Clean Up Code

Type: Bug fixes and code cleanup for NFS LOCALIO support.

Mike Snitzer submitted a four-patch series on January 7th, rebased on Trond Myklebust's recent NFS patchset, addressing several issues in the NFS LOCALIO subsystem — an optimization that avoids network I/O when the NFS client and server reside on the same system. The patches focus heavily on preventing deadlocks related to direct memory reclaim recursion and cleaning up now-unnecessary error handling paths.

"This series has been rebased on Trond's recent patchset... but the first 2 patches were developed while chasing a particularly nasty deadlock that was reproducible when putting LOCALIO under heavy load on systems with smaller amounts of memory (16G)." — Mike Snitzer

Patch 1: Prevent Direct Reclaim Recursion via GFP_NOFS

The most critical patch addresses a direct reclaim deadlock scenario where LOCALIO operations could recurse back into NFS through nfs_writepages. Snitzer documented the problematic stack traces observed under heavy load on memory-constrained systems (16 GB), showing tasks such as khugepaged and nfsd stuck in commit waits:

"LOCALIO is an NFS loopback mount optimization that avoids using the network for READ, WRITE and COMMIT if the NFS client and server are determined to be on the same system. But because LOCALIO is still fundamentally 'just NFS loopback mount' it is susceptible to recursion deadlock via direct reclaim, e.g.: NFS LOCALIO down to XFS and then back into NFS via nfs_writepages." — Mike Snitzer

The fix ensures all page cache allocations in LOCALIO are performed from GFP_NOFS context, preventing filesystem recursion during memory reclaim. This approach was inspired by a similar XFS fix (commit ad22c7a043c2), with credit given to Ben Coddington for the suggestion.

Patch 2: Use GFP_NOIO and Non-Memreclaim Workqueue in nfs_local_commit

The second patch corrects the workqueue used for LOCALIO's SYNC operations. Snitzer notes that nfslocaliod_workqueue is already a non-memreclaim workqueue, but it was not being used consistently for SYNC work:

"nfslocaliod_workqueue is a non-memreclaim workqueue (it isn't initialized with WQ_MEM_RECLAIM)... Use nfslocaliod_workqueue for LOCALIO's SYNC work." — Mike Snitzer

The patch also sets PF_LOCAL_THROTTLE | PF_MEMALLOC_NOIO flags in nfs_local_fsync_work, further hardening the code against reclaim-related deadlocks.

Patch 3: Remove Dead -EAGAIN Handling in nfs_local_doio()

This cleanup patch removes obsolete -EAGAIN handling code from nfs_local_doio(). The error path, which would call nfs_localio_disable_client(), was introduced in an earlier commit but has since become unreachable due to a subsequent refactoring of iocb initialization:

"Handling -EAGAIN in nfs_local_doio() was introduced with commit 0978e5b85fc08... but commit e43e9a3a3d66 since eliminated the possibility for this -EAGAIN early return. So remove nfs_local_doio()'s -EAGAIN handling that calls nfs_localio_disable_client() -- while it should never happen from nfs_do_local_{read,write} this particular -EAGAIN handling is now 'dead' and so it has become a liability." — Mike Snitzer

Patch 4: Simplify Return Types to void

The final patch is a minor cleanup, converting nfs_local_do_read and nfs_local_do_write to return void since they only ever return 0. This simplifies the code without changing behavior.

Context: Related Deadlock Fix

Snitzer notes that the deadlock he was chasing was also addressed by a separate fix from Trond Myklebust (commit cce0be6eb497) for nfs_release_folio(), which resolved tasks getting stuck in commit waits during page migration and memory compaction. However, Snitzer's series remains valuable as standalone improvements to LOCALIO's robustness.

"Ultimately that deadlock happens to also be fixed by Trond's recent commit... Anyway, I think this LOCALIO series is worthwhile on its own and ready for wider review and hopeful inclusion." — Mike Snitzer

Summary

This patch series represents important bug fixes for NFS LOCALIO client development, addressing:

  • Direct reclaim recursion deadlocks via GFP_NOFS allocation context (Patch 1)
  • Workqueue and memory allocation flag corrections for SYNC operations (Patch 2)
  • Removal of dead error-handling code that could become a liability (Patch 3)
  • Minor code cleanup simplifying return types (Patch 4)

The patches were reported based on real-world testing by John Cagle and verified by Allen Lu at Hammerspace. As of the end of this week, no replies or reviews had been posted to the thread.
