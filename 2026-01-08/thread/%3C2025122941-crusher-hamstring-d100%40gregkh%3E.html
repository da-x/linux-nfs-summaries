NFSD: NFSv4 File Creation ACL Bug Fix Backported to 6.1.y Stable Tree

Overview

This week, Chuck Lever submitted a single-patch backport targeting the Linux 6.1 stable tree to address a bug in the NFS server (NFSD) where POSIX Access Control Lists (ACLs) are neglected during NFSv4 file creation. This is classified as a bug fix, not a new feature or protocol change.

The same underlying issue was previously backported to the 6.6.y stable tree earlier this week (see prior summaries), which required a four-patch series due to additional prerequisite changes. The 6.1.y backport, by contrast, is a standalone one-line fix.

The Bug

On January 5th, Chuck Lever posted the patch with the following description:

"An NFSv4 client that sets an ACL with a named principal during file creation retrieves the ACL afterwards, and finds that it is only a default ACL (based on the mode bits) and not the ACL that was requested during file creation. This violates RFC 8881 section 6.4.1.3: 'the ACL attribute is set as given'." Chuck Lever

The root cause lies in nfsd_create_setattr(). On the 6.1.y branch, the check to determine whether nfsd_setattr() should be called is simply "iap->ia_valid", which only accounts for standard iattr changes:

"When only an ACL is present (and no iattr fields are set), nfsd_setattr() is skipped and the POSIX ACL is never applied to the inode." Chuck Lever

As a result, when the client later retrieves the ACL, the server returns one generated from the file's mode bits rather than the originally-specified ACL — a silent security policy violation.

The Fix

The patch is a minimal one-line change in fs/nfsd/vfs.c. Chuck Lever notes that he deliberately chose to adjust nfsd_create_setattr() directly rather than modifying nfsd_attrs_valid():

"[ cel: Adjust nfsd_create_setattr() instead of nfsd_attrs_valid() ]" Chuck Lever

The fix is backported from upstream commit 913f7cf77bf14c13cfea70e89bcb6d0b22239562 and traces the original bug to commit c0cbe70742f4 ("NFSD: add posix ACLs to struct nfsd_attrs"). The bug was originally reported by Aurélien Couderc.

Significance for NFS Client Development

While this patch targets the NFS server (NFSD), it has direct implications for NFS clients and their security posture:

  • ACL enforcement gap: Clients creating files with named-principal ACLs via NFSv4 would experience silent security policy violations, as the requested ACLs were never applied on the server. The server instead returns a default ACL derived from mode bits — a compliance violation against RFC 8881.
  • Stable tree importance: The 6.1 LTS kernel is widely deployed in production environments. This backport ensures that enterprise NFS deployments relying on POSIX ACLs for fine-grained permission management benefit from this correctness fix without requiring a full kernel upgrade.

Conclusion

This week's activity represents a targeted, minimal stable-tree backport to resolve an ACL enforcement gap in the Linux NFS server for the 6.1.y branch. Unlike the more complex 6.6.y backport (which required four patches including timestamp accessor updates and atomicity fixes), the 6.1.y fix is a straightforward one-line change, reflecting differences in code structure between the two stable branches. The patch is marked for Cc: stable@vger.kernel.org and is positioned for integration into the 6.1 stable kernel.
