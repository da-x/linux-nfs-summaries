re-enable IOCB_NOWAIT writes to files v5 — NFS timestamp refactoring for non-blocking writes

Summary

re-enable IOCB_NOWAIT writes to files v5 (with NFS timestamp refactoring)

Overview

Christoph Hellwig posted version 5 of his series to re-enable IOCB_NOWAIT writes to files on January 6, 2026. This is a long-running effort (now in its sixth iteration since November 2025) to restore non-blocking write support for io_uring workloads that was effectively disabled by commit 66fa3cedf16a ("fs: Add async write file modification handling.").

Problem Statement

The core issue is that timestamp updates during writes currently always require blocking operations, and modern timestamp resolution means timestamps are updated on every write. This has a significant performance impact for io_uring applications:

"This leads to a lot of context switches from applications using io_uring to submit file writes, making it often worse than using the legacy aio code that is not using IOCB_NOWAIT."

— Christoph Hellwig

Series Classification

This is a feature restoration / performance fix spanning the VFS layer and multiple filesystems, with particular relevance to NFS client development through timestamp handling refactoring. The series enables non-blocking timestamp updates for lazytime-capable filesystems (starting with XFS), thereby allowing IOCB_NOWAIT writes to function without forced blocking on metadata operations.

Thread Structure and Evolution

The thread root <20260106074628.1609575-1-hch@lst.de> contains only the cover letter and the first four patches of an 11-patch series, followed by a note from Hellwig:

"Sorry, sending this got interrupted by the broken train wifi. Please look at the immediately following full series instead."

— Christoph Hellwig

The complete v5 series (with all 11 patches) was posted under a separate thread root <20260106075008.1610195-1-hch@lst.de>, where the substantive review discussion occurred. A refined v6 was then posted on January 8, incorporating feedback from Jan Kara and Jeff Layton.

Key Patches Relevant to NFS Client Development

[PATCH 03/11] nfs: split nfs_update_timestamps

This is the most significant NFS-specific change in the series. Hellwig refactored nfs_update_timestamps in fs/nfs/inode.c to separate atime updates from ctime/mtime updates, aligning the NFS client with VFS calling conventions:

"The VFS paths update either the atime or ctime and mtime but never mix between atime and the others. Split nfs_update_timestamps to match this to prepare for cleaning up the VFS interfaces."

— Christoph Hellwig

The patch received positive reviews from both NFS maintainers and VFS experts:

"Looks good. Feel free to add: Reviewed-by: Jan Kara jack@suse.cz"

— Jan Kara

"Reviewed-by: Jeff Layton jlayton@kernel.org"

— Jeff Layton

The refactoring splits the monolithic nfs_update_timestamps into two distinct code paths — one for atime-only updates and another for ctime/mtime updates — which is a prerequisite for enabling non-blocking timestamp operations in future iterations. The diff touches 15 insertions and 16 deletions in fs/nfs/inode.c.

[PATCH 02/11] fs: allow error returns from generic_update_time

This preparatory patch changes the return convention of generic_update_time to return 0 or a negative errno, matching the ->update_time method signature. This is essential for enabling -EAGAIN returns when non-blocking timestamp updates cannot be completed immediately:

"Now that no caller looks at the updated flags, switch generic_update_time to the same calling convention as the ->update_time method and return 0 or a negative errno. This prepares for adding non-blocking timestamp updates that could return -EAGAIN."

— Christoph Hellwig

This change also touches fs/nfs/inode.c (alongside gfs2, ubifs, and xfs), adapting the NFS client's update_time implementation to the new convention.

Broader VFS Changes

The series includes 16 files with 182 insertions and 111 deletions across:

  • VFS core: fs/inode.c, fs/fs-writeback.c, include/linux/fs.h
  • Filesystems: btrfs, gfs2, nfs, orangefs, overlayfs, ubifs, xfs, fat

Key VFS innovations include:

  1. Removal of the now-unused inode_update_time helper (PATCH 01/11)
  2. Introduction of a new ->sync_lazytime filesystem method for deferred timestamp synchronization
  3. Support for non-blocking timestamp updates when lazytime is enabled

Changes Across Versions

The evolution from v4 to v6 highlights iterative refinement:

v5 changes (from v4):

  • Replaced fragile S_* flags with an enum indicating access vs. modification time updates, fixing a bug in the previous version

v6 changes (from v5):

  • "sample ctime before calling inode_set_ctime_current"
  • "fix a mild bisection hazard in fat"

Conclusion

This series represents a significant infrastructure investment to restore IOCB_NOWAIT write performance for io_uring workloads. For NFS clients, the immediate impact is a clean-up of timestamp update paths that better aligns with VFS conventions and sets the stage for future non-blocking timestamp support. The patch received unanimous positive reviews from both Jan Kara (VFS) and Jeff Layton (NFS), indicating broad consensus on the approach. The series was quickly iterated to v6 within the same week, incorporating reviewer feedback on edge cases in FAT and ctime sampling order.
