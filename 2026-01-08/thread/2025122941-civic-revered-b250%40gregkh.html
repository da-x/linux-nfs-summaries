NFSD: NFSv4 File Creation ACL Bug Backport to 6.6.y Stable Tree

Overview

This week, Chuck Lever submitted a four-patch series targeting the Linux 6.6 stable tree to address a bug in the NFS server (NFSD) where NFSv4 file creation operations neglect to set Access Control Lists (ACLs). This is classified as a bug fix, not a new feature or protocol change.

The Issue and Patch Series

On January 3rd, Chuck Lever posted a cover letter explaining the motivation for this backport effort:

"I received an automated report that patch 'NFSD: NFSv4 file creation neglects setting ACL' failed to apply to the 6.6-stable tree. This series is my attempt to address that failure." Chuck Lever

The patch series consists of four commits:

  1. nfsd: convert to new timestamp accessors — A preparatory change updating the NFS server code to use newer kernel timestamp accessor APIs.
  2. nfsd: Fix NFSv3 atomicity bugs in nfsd_setattr() — Addresses atomicity issues in NFSv3 attribute setting operations.
  3. nfsd: set security label during create operations — Ensures security labels are properly applied when files are created.
  4. NFSD: NFSv4 file creation neglects setting ACL — The primary bug fix, correcting the omission of ACL settings during NFSv4 file creation.

The changes touch nine files across the fs/nfsd/ directory, with a net result of 42 insertions and 29 deletions, affecting core NFSD processing code (nfs3proc.c, nfs4proc.c, nfs4state.c), VFS interaction layer (vfs.c, vfs.h), XDR helpers (nfs3xdr.c, xdr3.h), and control interfaces (nfsctl.c).

Validation

Chuck Lever noted that the series underwent automated quality assurance:

"LLM agent review for possible regressions reported no issues" "CI testing reported no regressions" Chuck Lever

Significance for NFS Client and Server Development

While this patch series targets the NFS server (NFSD) side, it has direct implications for NFS clients. The bug in question — ACLs not being set during NFSv4 file creation — would cause security policy violations on the client side, as newly created files would lack the intended access controls. This is particularly important for enterprise environments relying on POSIX ACLs for fine-grained permission management over network-mounted filesystems.

The inclusion of a fix for NFSv3 atomicity bugs in nfsd_setattr() also addresses potential data consistency issues that could affect clients performing attribute updates (e.g., via chmod or chown).

Conclusion

This week's activity represents a targeted stable-tree backport effort to resolve an ACL enforcement gap in the Linux NFS server. The patch series was prepared after an automated failure report indicated the original fix did not cleanly apply to the 6.6.y branch. With prerequisite patches included and both LLM-based review and CI testing reporting no regressions, this series is positioned for integration into the 6.6 stable kernel.
