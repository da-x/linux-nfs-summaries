Re-enable IOCB_NOWAIT Writes to Files v6: Final Polish for Non-Blocking Timestamp Updates

Summary

Re-enable IOCB_NOWAIT Writes to Files v6: Final Polish Before Merge

Summary

Christoph Hellwig posted version 6 of his series to re-enable IOCB_NOWAIT writes to files on January 8, 2026 — just two days after v5 was posted and reviewed. This is the sixth iteration of a long-running effort (since November 2025) to restore non-blocking write support for io_uring workloads that was effectively disabled by commit 66fa3cedf16a.

Background: The IOCB_NOWAIT Problem

As Hellwig explained in the cover letter:

"commit 66fa3cedf16a ("fs: Add async write file modification handling.") effectively disabled IOCB_NOWAIT writes as timestamp updates currently always require blocking, and the modern timestamp resolution means we always update timestamps. This leads to a lot of context switches from applications using io_uring to submit file writes, making it often worse than using the legacy aio code that is not using IOCB_NOWAIT."

The series enables non-blocking timestamp updates for lazytime-capable filesystems (starting with XFS), thereby allowing IOCB_NOWAIT writes to function without forced blocking on metadata operations. The final patch carries a Fixes: tag:

"Fixes: 66fa3cedf16a ("fs: Add async write file modification handling.")"

— Christoph Hellwig

Classification

This is a feature restoration / performance fix spanning the VFS layer and multiple filesystems. It addresses a regression in io_uring write performance by introducing non-blocking lazytime timestamp updates, with XFS as the first implementing filesystem. For NFS clients, the series provides important preparatory refactoring to align timestamp update paths with new VFS conventions.

Changes Since v5

The v6 iteration incorporates two targeted fixes based on feedback from the v5 review cycle:

"Changes since v5:

  • sample ctime before calling inode_set_ctime_current
  • fix a mild bisection hazard in fat"

— Christoph Hellwig

The ctime sampling order bug was identified by Jan Kara during v5 review, and the FAT bisectability concern was raised by OGAWA Hirofumi — both issues were addressed in this final iteration.

Series Structure (11 patches)

The series progresses through several stages:

  1. Patches 01–03: Preparatory VFS cleanup — removing inode_update_time, allowing error returns from generic_update_time, and splitting NFS's nfs_update_timestamps.
  2. Patch 04: FAT-specific flag cleanup for fat_truncate_time.
  3. Patches 05–07: Core refactoring of ->update_time handling, factoring out a sync_lazytime helper, and adding a new ->sync_lazytime filesystem method.
  4. Patch 08: The key feature — adding support for non-blocking timestamp updates by passing IOCB_NOWAIT to ->update_time.
  5. Patches 09–11: Further refactoring of file_update_time_flags, and XFS-specific implementations of ->sync_lazytime and non-blocking timestamp updates.

The diffstat shows 16 files changed, with 182 insertions and 111 deletions across VFS core and filesystems including btrfs, gfs2, nfs, orangefs, overlayfs, ubifs, xfs, and fat.

NFS Client Development: Timestamp Refactoring

[PATCH 03/11] nfs: split nfs_update_timestamps

The most significant NFS-specific change splits nfs_update_timestamps in fs/nfs/inode.c into separate paths for atime updates versus ctime/mtime updates:

"The VFS paths update either the atime or ctime and mtime but never mix between atime and the others. Split nfs_update_timestamps to match this to prepare for cleaning up the VFS interfaces."

— Christoph Hellwig

This patch received positive reviews from both NFS and VFS maintainers:

"Reviewed-by: Jan Kara jack@suse.cz" "Reviewed-by: Jeff Layton jlayton@kernel.org"

— Christoph Hellwig (citing reviewer endorsements)

The refactoring aligns the NFS client's timestamp update behavior with VFS calling conventions — a prerequisite for enabling non-blocking timestamp operations in future iterations. The diff touches 15 insertions and 16 deletions in fs/nfs/inode.c.

[PATCH 02/11] fs: allow error returns from generic_update_time

This preparatory patch changes the return convention of generic_update_time to return 0 or a negative errno, matching the ->update_time method signature:

"Now that no caller looks at the updated flags, switch generic_update_time to the same calling convention as the ->update_time method and return 0 or a negative errno. This prepares for adding non-blocking timestamp updates that could return -EAGAIN."

— Christoph Hellwig

This change also touches fs/nfs/inode.c, adapting the NFS client's update_time implementation to the new convention.

[PATCH 05/11] fs: refactor ->update_time handling

The NFS client's nfs_update_timestamps is further updated in this patch to use the new enum-based update type interface instead of the legacy S_* flags, aligning it with the broader VFS refactoring. The patch description notes:

"Pass the type of update (atime vs c/mtime plus version) as an enum instead of a set of flags that caused all kinds of confusion."

— Christoph Hellwig

Key VFS Innovations

The series introduces several important infrastructure changes:

  1. Removal of inode_update_time (PATCH 01/11): The only external user is gone; the function is now open-coded in its two VFS callers.

  2. New ->sync_lazytime filesystem method (PATCH 07/11): Allows filesystems to explicitly implement lazytime syncing instead of relying on generic inode dirtying:

"Allow the file system to explicitly implement lazytime syncing instead of pigging back on generic inode dirtying. This allows to simplify the XFS implementation and prepares for non-blocking lazytime timestamp updates."

— Christoph Hellwig

  1. Non-blocking timestamp updates (PATCH 08/11): The centerpiece of the series:

"Currently file_update_time_flags unconditionally returns -EAGAIN if any timestamp needs to be updated and IOCB_NOWAIT is passed. This makes non-blocking direct writes impossible on file systems with granular enough timestamps."

— Christoph Hellwig

XFS Implementation

The series concludes with XFS-specific patches that implement ->sync_lazytime and enable non-blocking timestamp updates:

"The lazytime path using the generic helpers can never block in XFS because there is no ->dirty_inode method that could block. Allow non-blocking timestamp updates for this case by replacing generic_update_time with the open coded version without the S_NOWAIT check."

— Christoph Hellwig

Conclusion

This v6 series represents the final polish of a significant infrastructure investment to restore IOCB_NOWAIT write performance for io_uring workloads. For NFS clients, the immediate impact is a clean-up of timestamp update paths that better aligns with VFS conventions and sets the stage for future non-blocking timestamp support on NFS — though NFS itself does not yet implement non-blocking timestamp updates in this series; that remains future work. The rapid iteration from v5 to v6 within two days, incorporating all reviewer feedback, signals strong momentum toward merging this long-awaited fix.
