IOCB_NOWAIT writes v4: Series Rejected for Fixes; Revised Version Expected

Summary

re-enable IOCB_NOWAIT writes to files v4 – Post-Holiday Status Check

Background (Prior Weeks)

Christoph Hellwig's patch series "re-enable IOCB_NOWAIT writes to files v4" was originally posted on December 23, 2025. The series addresses a performance regression: commit 66fa3cedf16a ("fs: Add async write file modification handling") effectively disabled IOCB_NOWAIT writes because timestamp updates always required blocking operations, and modern timestamp resolution means timestamps are always updated. This caused excessive context switches for applications using io_uring to submit file writes, making them "often worse than using the legacy aio code that is not using IOCB_NOWAIT."

The 11-patch series introduced non-blocking timestamp updates for lazytime (when supported by the filesystem), with implementations added for XFS and FAT. On December 24, Christian Brauner applied the series to the vfs-7.0.nonblocking_timestamps branch of vfs/vfs.git, noting that patches would appear in linux-next soon.

However, before the holiday break, Hellwig flagged an issue: "Julia found a nice little typo in the new changes, which really wants me to split the atime from c/mtime update path badly" As noted by Christoph Hellwig. He indicated there would be a revised version soon.

This Week's Activity (Jan 6–7, 2026)

Three messages were exchanged this week as Hellwig returned from vacation and coordinated with Brauner on the status of the applied-but-buggy series.

Hellwig Requests Series Rejection. On January 6, Christoph Hellwig followed up on Brauner's application notice, explaining that Julia Lawall had discovered issues using static type checking tools:

"Umm, as in my self reply just before heading out for vacation, Julia found issues in it using static type checking tools. I have a new version that fixes that and sorts out the S_* mess. So please drop it again for now, I'll resend the fixed version ASAP." Christoph Hellwig

The identified problems included static type-checking errors and what Hellwig described as an "S_* mess" — referring to inode state flag handling (S_* flags) that needed cleanup in the revised version.

Brauner Clarifies: Series Was Never Actually Pushed. Christian Brauner responded later that same day, clarifying that despite his earlier application notice being sent, the patches had not actually been merged into any tree:

"It has never been pushed nor applied as I saw your mail right before all of that." Christian Brauner

Brauner explained that he had seen Hellwig's self-reply flagging the issues before completing any actual merge or push operations, so no buggy code entered linux-next.

Hellwig Suggests Process Improvement. On January 7, Hellwig acknowledged Brauner's clarification and proposed a procedural improvement to avoid future confusion:

"Thanks. But maybe you can fix up the applied messages to be more specific? We had various issues in the past with them, where they were sent, but things did not end up in the tree for various reasons." Christoph Hellwig

Hellwig noted that ambiguous "applied" notifications had caused problems in prior instances — where such messages were sent but the patches never actually landed in the tree. He suggested making these status messages more precise to avoid downstream confusion among reviewers and maintainers.

Nature of the Discussion

This thread concerns a new feature / performance fix rather than a bug fix per se. The series aims to re-enable IOCB_NOWAIT writes by introducing non-blocking timestamp updates — a capability that was effectively broken by prior VFS changes. This is particularly relevant for NFS client development because:

  • The diffstat in the original cover letter shows modifications to fs/nfs/inode.c (4 lines removed), indicating NFS filesystem integration with the new timestamp update infrastructure.
  • Restoring IOCB_NOWAIT functionality directly impacts io_uring-based NFS write performance, reducing unnecessary context switches for asynchronous I/O workloads.

Conclusions

  • The v4 series has not been merged into any mainline tree; Brauner confirmed it was never pushed despite an earlier application notice.
  • A revised version (v5) is expected from Hellwig, addressing static type-checking issues found by Julia Lawall and cleaning up the S_* inode flag handling.
  • The discussion also surfaced a process concern about ambiguous "applied" notifications, with Hellwig suggesting more specific messaging to prevent future confusion.
