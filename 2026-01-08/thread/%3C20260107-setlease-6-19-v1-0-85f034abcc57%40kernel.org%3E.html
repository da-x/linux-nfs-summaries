VFS: Properly Deny Directory Leases on NFS, Ceph, and Other Filesystems

Summary

VFS: Properly Deny Directory Leases on Filesystems with Special Lease Handling

Overview

Jeff Layton submitted a six-patch series this week targeting the NFS client and several other network/distributed filesystems to address a correctness issue in how directory leases and delegations are handled. The series is classified as a bug fix, correcting improper lease denial mechanisms introduced by a prior VFS refactoring.

Background and Motivation

The root cause traces back to commit e6d28ebc17eb ("filelock: push the S_ISREG check down to ->setlease handlers"), which moved the regular-file-only check for leases from the generic VFS layer into individual filesystem ->setlease() handlers. With the advent of directory delegations in NFSv4.2, this change exposed a subtle bug: several filesystems were checking S_ISREG() inside their file-level ->setlease() handlers, but that handler is never invoked for directories. As a result, lease requests on directories were not being properly denied on these filesystems.

"Checking for S_ISREG() in nfs4_setlease() is incorrect, since that op is never called for directories. The right way to deny lease requests on directories is to set the ->setlease() operation to simple_nosetlease() in the directory file_operations." — Jeff Layton

The practical impact, as noted by Layton, is primarily in test infrastructure:

"There should be no noticeable change in behavior, other than fixing the support detection in xfstests, allowing lease/delegation tests to be properly skipped on these filesystems." — Jeff Layton

Patch Series Breakdown

The six patches target the following filesystems, each adding simple_nosetlease() to directory file_operations and, where applicable, removing incorrect S_ISREG() checks from file-level handlers:

  1. NFS (PATCH 1/6): Adds simple_nosetlease() to NFS directory operations and removes the now-redundant S_ISREG() check from nfs4_setlease().
  2. SMB/client (PATCH 2/6): Similar fix for CIFS/SMB client.
  3. 9p (PATCH 3/6: Adds directory lease denial.
  4. GFS2 (PATCH 4/6: Adds directory lease denial, with a noted exception for the "nolock" case where denial is unnecessary.
  5. Ceph (PATCH 5/6: Adds directory lease denial.
  6. VBoxSF (PATCH 6/6: Adds directory lease denial.

Discussion and Review

Christoph Hellwig's Feedback

Christoph Hellwig, who originally reported the issue, provided a Tested-by tag for the NFS patch:

"This fixes generic/786 on NFSv4.2 for me, so: Tested-by: Christoph Hellwig hch@lst.de" — Christoph Hellwig

Hellwig also weighed in on Layton's long-term vision for lease handling. Layton proposed that leases/delegations should become an opt-in feature, denied by default when ->setlease() is not set:

"Long term, I think it would be best to change leases/delegations to be an opt-in thing, such that leases are always denied by default if the method isn't set." — Jeff Layton

Hellwig agreed in principle:

"Agreed." — Christoph Hellwig

However, he cautioned against wiring up simple_nosetlease() everywhere indiscriminately:

"Initially you can just wire them up everywhere. But I guess that would be overkill." — Christoph Hellwig

Layton elaborated on the scope of such a change, noting there are "literally thousands of file_operations structures," many in driver code with no legitimate need for lease support. He proposed a pragmatic approach:

"I think what we probably want to do is wire them up in most filesystems under fs/. Basically, in anything that might reasonably be exportable via NFS or SMB, and have the rest deny them." — Jeff Layton

Ceph Review

Viacheslav Dubeyko provided a Reviewed-by tag for the Ceph patch:

"Looks good. Reviewed-by: Viacheslav Dubeyko Slava.Dubeyko@ibm.com" — Viacheslav Dubeyko

Key Technical Arguments

  • Correctness over convenience: The series prioritizes correct VFS semantics — directory lease denial must happen at the directory file_operations level, not inside file-level handlers that are never invoked for directories.
  • Test infrastructure impact: The immediate benefit is enabling xfstests to properly detect and skip unsupported lease/delegation scenarios on these filesystems.
  • Long-term VFS design: The discussion surfaced a broader architectural question about whether leases should be opt-in (denied by default) rather than opt-out, with consensus that this is desirable but requires careful auditing across thousands of file_operations structures.

Final Conclusions

The patch series received positive review feedback, including a Tested-by from Christoph Hellwig confirming the fix resolves xfstest generic/786 on NFSv4.2, and a Reviewed-by from Viacheslav Dubeyko for the Ceph component. Layton suggested merging all six patches together via Christian Brauner's tree (vfs), targeting kernel v6.19. The immediate bug fix is straightforward and well-supported; the longer-term discussion about making leases opt-in by default remains an open architectural consideration for future work.
