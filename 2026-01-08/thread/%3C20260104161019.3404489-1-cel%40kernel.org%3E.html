NFSD: v2 Series for NFSv4.2 POSIX ACL Support — Reviewed-by from Jeff Layton

Summary

NFSD: v2 Series for NFSv4.2 POSIX ACL Support — Reviewed-by from Jeff Layton

Overview

This week, Chuck Lever posted version 2 of a twelve-patch series that implements the server-side support for the IETF draft "POSIX Draft ACL support for Network File System Version 4, Minor Version 2" in the Linux NFS server (knfsd). This is classified as a new protocol feature, not a bug fix — it adds four new file attributes to NFSv4.2 enabling POSIX draft ACLs to be retrieved and set directly, bypassing the lossy NFSv4-to-POSIX mapping algorithm.

The series received a positive review from Jeff Layton:

"This all looks pretty reasonable. Nice work!" Jeff Layton

"Reviewed-by: Jeff Layton jlayton@kernel.org" Jeff Layton

Context: Relation to Prior Week's ACL Bug Fix Thread

This feature series is closely related to the bug-fix backport effort discussed in a parallel thread this week (see related summary), where Chuck Lever submitted patches to fix an existing ACL omission bug during NFSv4 file creation. That backport addressed the fact that POSIX ACLs with named principals were silently dropped during file creation — a compliance violation against RFC 8881. The current v2 series builds on top of those fixes and extends NFSD with full native POSIX ACL support as defined by the new IETF draft.

Patch Series Breakdown (v2)

The twelve-patch series, posted on January 4th, is co-authored by Chuck Lever and Rick Macklem. Key changes from v1 include folding fixes into earlier patches, ensuring bisect-ability, adding a Kconfig gate for experimental features, using xdrgen for XDR code generation where practical, and refactoring SETATTR/CREATE integration.

Patch 01/12: Kconfig Gate for Experimental POSIX ACL Support

A new build-time option CONFIG_NFSD_V4_POSIX_ACLS is introduced to gate this experimental feature:

"This draft has not yet been ratified. A build-time configuration option allows developers and distributors to decide whether to expose this experimental protocol extension to NFSv4 clients. The option is disabled by default to prevent unintended deployment of potentially unstable protocol features in production environments." Chuck Lever

This mirrors the existing NFSD_V4_DELEG_TIMESTAMPS option for another unratified extension.

Patch 02/12: RPC Language Definition from IETF Draft

The XDR language definition is extracted directly from draft-ietf-nfsv4-posix-acls, ensuring alignment between the specification and kernel source code, and bringing in basic XDR utilities via xdrgen.

Patches 03–06/12: Encoding New File Attributes (Rick Macklem)

These four patches implement XDR encoders for the four new protocol attributes:

  • FATTR4_ACL_TRUEFORM — Reports whether a file stores permissions using NFSv4 ACLs or POSIX ACLs. Linux reports ACL_MODEL_POSIX_DRAFT for filesystems with the SB_POSIXACL flag, and ACL_MODEL_NONE otherwise. As noted in the patch:

"Mapping between NFSv4 ACLs and POSIX ACLs is semantically imprecise: a client that sets an NFSv4 ACL and reads it back may see a different ACL than it wrote." Rick Macklem

  • FATTR4_ACL_TRUEFORM_SCOPE — Indicates the granularity at which the ACL model can vary. Linux reports ACL_SCOPE_FILE_SYSTEM, reflecting that the SB_POSIXACL flag applies uniformly to all files within a filesystem:

"In Linux, the ACL model is determined by the SB_POSIXACL superblock flag, which applies uniformly to all files within a file system." Rick Macklem

  • FATTR4_POSIX_DEFAULT_ACL — Encodes a directory's default ACL, retrieved via get_inode_acl() and encoded as posixace4 entries with tag type, permission bits, and principal names (resolved via idmapping for USER/GROUP entries).

  • FATTR4_POSIX_ACCESS_ACL — Encodes the access ACL for any inode. If no explicit ACL exists, one is synthesized from the file mode via posix_acl_from_mode().

Patch 07/12: Prohibit POSIX ACL Attributes in VERIFY/NVERIFY

Per section 9.3 of the IETF draft, the server must reject attempts to use POSIX ACL attributes with VERIFY or NVERIFY operations:

"Section 9.3 of draft-ietf-nfsv4-posix-acls-00 prohibits use of the POSIX ACL attributes with VERIFY and NVERIFY operations: the server MUST reply NFS4ERR_INVAL when a client attempts this." Rick Macklem

The patch also notes an implementation concern:

"Clients are not required to order the ACEs within a POSIX ACL in any particular way, making reliable attribute comparison impractical." Rick Macklem

Patch 08/12: Refactor SETATTR ACL Error Reporting

This patch introduces separate error fields (na_paclerr for access ACLs, na_dpaclerr for default ACLs) to handle independent success/failure of each ACL type during SETATTR and file creation. It also adds validation logic:

"Default ACL processing rejects non-directory targets with EINVAL and passes NULL to set_posix_acl() when a_count is zero to delete the ACL." Rick Macklem

Patch 09/12: XDR Decoding of POSIX Draft ACLs

Adds decoders for FATTR4_POSIX_ACCESS_ACL and FATTR4_POSIX_DEFAULT_ACL, enabling clients to set POSIX ACLs during CREATE, OPEN, and SETATTR operations. The nfsd4_decode_fattr4() function gains two additional parameters for receiving decoded POSIX ACLs.

Remaining Patches (10–12/12)

The cover letter indicates patches covering POSIX ACL support for file creation, SETATTR integration, and SUPPATTR bitmask updates, completing the server-side implementation.

Significance for NFS Client Development

Although this series targets the NFS server, it has direct implications for NFS clients:

  1. Lossless ACL round-tripping: Clients using getfacl(1) and setfacl(1) over NFSv4.2 mounts will be able to manipulate POSIX ACLs directly without lossy translation through the NFSv4 ACL format — a long-standing pain point for administrators managing fine-grained access controls over NFS.

  2. Protocol extension mechanism: The Kconfig-gated approach provides a safe path for testing experimental IETF drafts before ratification, allowing developers and distributors to opt-in without risking production stability.

  3. Compliance with RFC 8881: Combined with the ACL bug fix backport discussed in the parallel thread, this series ensures that NFSv4 file creation properly honors requested POSIX ACLs — resolving a compliance violation where named-principal ACLs were silently dropped.

Conclusion

This v2 series received a positive review from Jeff Layton and represents significant progress toward native POSIX ACL support in the Linux NFS server. The implementation is carefully gated behind a Kconfig option, uses xdrgen for XDR code generation, and addresses protocol compliance requirements including VERIFY/NVERIFY restrictions. With 822 lines added across 14 files, this is a substantial feature addition that will enable lossless POSIX ACL management over NFSv4.2 once the IETF draft is ratified and the patches are merged upstream.
