NFSD: POSIX Draft ACL Support for SETATTR and File Creation (v2 patches 10–12/12)

Summary

NFSD: POSIX Draft ACL Support for SETATTR, File Creation, and SUPPATTR Advertising (v2)

Overview

This week, Chuck Lever posted three patches from the [PATCH v2 00/12] Add NFSv4.2 POSIX ACL support series (cover letter), implementing the server-side of the IETF draft extension "POSIX Draft ACL support for Network File System Version 4, Minor Version 2" (draft-ietf-nfsv4-posix-acls). This is classified as a new feature — not a bug fix or protocol change — extending the NFS server (NFSD) to support POSIX draft ACLs directly over NFSv4.2, bypassing the lossy NFSv4-to-POSIX mapping algorithm.

The three patches in this thread (10/12, 11/12, and 12/12) complete the NFSD implementation by wiring POSIX ACL support into file creation, attribute modification (SETATTR), and capability advertising (SUPPATTR bitmasks).

Context: The Larger v2 Series

The v2 series comprises 12 patches authored by Chuck Lever and Rick Macklem. As explained in the cover letter by Chuck Lever:

"The extension adds four new attributes to the protocol."

The implementation enables POSIX draft ACLs to be manipulated directly by getfacl(1) and setfacl(1) over NFSv4.2, analogous to the NFS_ACL sideband protocol used with NFSv2/v3. Key design decisions include:

  • The feature is gated behind CONFIG_NFSD_V4_POSIX_ACLS, marking it as experimental.
  • POSIX ACL support applies at the file system level (not per-file), assuming all objects on a given file system use POSIX draft ACLs when the feature is enabled.
  • Mutual exclusion between NFSv4 ACLs and POSIX ACLs is enforced — setting both simultaneously returns nfserr_inval.

Changes since v1 included folding fixes into earlier patches, ensuring bisectability, adding the Kconfig option, deferring SUPPATTR bit advertisement to the final patch, using xdrgen for XDR code generation, and refactoring SETATTR/CREATE integration.

Patch Breakdown

Patch 10/12: Add support for POSIX draft ACLs for file creation

Authored by Rick Macklem, this patch extends nfsd4_create() and nfsd4_create_file() to handle POSIX ACLs during file creation via OPEN(CREATE) and CREATE operations as described in the commit message:

"NFSv4.2 clients can specify POSIX draft ACLs when creating file objects via OPEN(CREATE) and CREATE operations. The previous patch added POSIX ACL support to the NFSv4 SETATTR operation for modifying existing objects, but file creation follows different code paths that also require POSIX ACL handling."

Key technical details:

  • Ownership of decoded ACL pointers (op_dpacl, op_pacl, cr_dpacl, cr_pacl) transfers to the nfsd_attrs structure immediately, with original fields cleared to NULL. This ensures nfsd_attrs_free() releases the ACLs upon completion and prevents double-free on error paths.
  • Mutual exclusion between NFSv4 ACLs and POSIX ACLs is enforced: setting both simultaneously returns nfserr_inval.
  • Errors during ACL application clear the corresponding bits in the result bitmask (fattr->bmval), signaling partial completion to the client.

Patch 11/12: Add POSIX draft ACL support to the NFSv4 SETATTR operation

Also authored by Rick Macklem, this patch connects the na_pacl and na_dpacl fields in nfsd_attrs to the decoded ACL pointers from the NFSv4 SETATTR decoder as explained:

"The POSIX ACL extension to NFSv4 enables clients to set access and default ACLs via FATTR4_POSIX_ACCESS_ACL and FATTR4_POSIX_DEFAULT_ACL attributes. Integration of these attributes into SETATTR processing requires wiring them through the nfsd_attrs structure and ensuring proper cleanup on all code paths."

Notable implementation details:

  • Ownership of ACL references transfers to attrs immediately after initialization, with decoder pointers cleared to NULL. This ensures nfsd_attrs_free() releases the ACLs on normal completion.
  • New error paths call posix_acl_release() directly when cleanup occurs before nfsd_attrs_free() runs.
  • Early returns in nfsd4_setattr() are converted to goto statements branching to proper cleanup handlers — paths before fh_want_write() branch to out_err for ACL release only; paths after use the existing out label for full cleanup.
  • Mutual exclusion between NFSv4 ACLs (sa_acl) and POSIX ACLs is enforced, returning nfserr_inval when both types are set simultaneously.

Patch 12/12: Add POSIX ACL file attributes to SUPPATTR bitmasks

Authored by Chuck Lever, this final patch advertises POSIX ACL support to NFS clients as noted:

"Now that infrastructure for NFSv4 POSIX draft ACL has been added to NFSD, it should be safe to advertise support to NFS clients."

The patch adds the new POSIX ACL attributes to NFSD_SUPPATTR_EXCLCREAT_WORD2, which includes NFSv4.2-only attributes. Version filtering via nfsd_suppattrs[] ensures that pre-4.2 clients never see unsupported attributes.

Significance for NFS Client and Server Development

While this series targets the NFS server (NFSD), it has direct implications for NFS clients:

  1. Lossless ACL transport: Clients can now set and retrieve POSIX draft ACLs without the lossy conversion inherent in the traditional NFSv4-to-POSIX mapping algorithm. This is critical for enterprise environments relying on fine-grained access controls with named principals.

  2. Tool compatibility: The mechanism enables getfacl(1) and setfacl(1) to operate directly over NFSv4.2 mounts, providing a familiar POSIX ACL management interface without requiring special client-side tooling.

  3. Complementary to recent bug fixes: Earlier this week, a separate backport effort addressed the bug where NFSv4 file creation neglected to set ACLs entirely (see related summary). This new feature series builds upon that corrected foundation, extending ACL support to the POSIX draft model.

  4. Experimental gating: The CONFIG_NFSD_V4_POSIX_ACLS option allows administrators to opt in cautiously, providing a safe path for production evaluation.

Conclusion

This thread represents the final three patches of a 12-patch v2 series implementing NFSv4.2 POSIX draft ACL support in the Linux NFS server. The patches complete the implementation by handling POSIX ACLs during file creation (patch 10/12), integrating them into SETATTR processing (patch 11/12), and advertising support to clients via SUPPATTR bitmasks (patch 12/12). With Jeff Layton's positive review, the series is well-positioned for eventual upstream integration. The feature provides a significant enhancement for NFS deployments requiring POSIX-compliant ACL management over network mounts.
