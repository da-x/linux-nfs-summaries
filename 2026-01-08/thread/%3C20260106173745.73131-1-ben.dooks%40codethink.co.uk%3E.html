sunrpc: Fix Sparse Warnings for Debug Symbols When CONFIG_SUNRPC_DEBUG Unset

Summary

sunrpc: Fix Sparse Warnings for Debug Symbols When CONFIG_SUNRPC_DEBUG Is Unset

Type: Bug fix (sparse warning cleanup)

Overview

Ben Dooks submitted a small but targeted patch addressing sparse warnings in the SunRPC subsystem that arise when CONFIG_SUNRPC_DEBUG is not enabled. The issue centers on debug-related symbols being exported even when debug functionality is disabled at compile time, leading to undeclared symbol warnings from the sparse static analysis tool.

Technical Details

The patch targets the file include/linux/sunrpc/debug.h, removing two lines that were causing the problem. As Ben Dooks explained in the commit message:

"The rpc_debug, nfs_debug, nfsd_debug and nlm_debug are exported even if CONFIG_SUNRPC_DEBUG is not set. This means that the debug header should also define these to remove the following sparse warnings"

The specific warnings being addressed were:

  • net/sunrpc/sysctl.c:29:17: warning: symbol 'rpc_debug' was not declared. Should it be static?
  • net/sunrpc/sysctl.c:32:17: warning: symbol 'nfs_debug' was not declared. Should it be static?
  • net/sunrpc/sysctl.c:35:17: warning: symbol 'nfsd_debug' was not declared. Should it be static?
  • net/sunrpc/sysctl.c:38:17: warning: symbol 'nlm_debug' was not declared. Should it be static?

Significance for NFS Client Development

While this is a relatively minor fix, it touches the core SunRPC debug infrastructure that underpins both the NFS client and NFS server subsystems. The rpc_debug, nfs_debug, nfsd_debug, and nlm_debug symbols are used for runtime debugging of RPC operations — a critical tool for diagnosing NFS connectivity and protocol issues. Ensuring these symbols are properly declared regardless of the CONFIG_SUNRPC_DEBUG configuration option helps maintain clean builds across different kernel configurations, which is important for developers working on embedded or production kernels where debug options may be disabled.

Status

As of this week's window, the patch was submitted by Ben Dooks on January 6, 2026 but has not yet received replies or acknowledgments from the NFS subsystem maintainers.
