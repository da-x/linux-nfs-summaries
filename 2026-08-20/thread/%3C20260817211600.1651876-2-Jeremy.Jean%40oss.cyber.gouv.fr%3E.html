NFSv4.1 CB_SEQUENCE empty referring-call kfree bug

Summary

This week's discussion is a client-side bug fix in NFSv4.1 callback XDR, not a protocol change or new feature. Jérémy Jean posted a one-line patch for fs/nfs/callback_xdr.c after KASAN flagged a double-free when the client decoded a valid CB_SEQUENCE referring-call list that contained zero referring calls.

The failure path is in the NFS client's callback decoder. decode_cb_sequence_args() allocates csa_rclists with kmalloc_objs(), so each referring_call_list starts with uninitialized members. decode_rc_list() only writes rcl_refcalls when rcl_nrefcalls is nonzero. Jean wrote:

"A valid list with zero referring calls therefore leaves the pointer uninitialized, and nfs4_callback_sequence() later passes it to kfree(). KASAN reports a double free in nfs_cb_sequence_empty_refcalls_test()."

That is a long-standing hole: the patch carries Fixes: 4aece6a19cf7 ("nfs41: cb_sequence xdr implementation"). The v1 change itself was a single assignment in decode_rc_list():

rc_list->rcl_refcalls = NULL;

placed before the session-id decode, so an empty-but-valid list would still hand a NULL pointer to the later kfree() in nfs4_callback_sequence().

Anna Schumaker accepted the diagnosis but rejected the placement. She asked that the lists be zeroed at allocation time rather than patched one field at a time during decode:

"I think I would rather have this initialized to NULL from the beginning. Could you instead update decode_cb_sequence_args() to use kzalloc_objs() when allocating the referring_call_lists?"

That is the state of this thread at week close: the bug is agreed, the v1 one-liner is not the preferred fix, and no merge decision was recorded here. Later the same day Jean posted a separate v2 ([PATCH v2] NFSv4.1: zero referring call lists before decoding) that switches csa_rclists from kmalloc_objs() to kzalloc_objs(), exactly as Schumaker requested. That follow-up is a new thread and is not reviewed in this one.

Bottom line for NFS client development: empty referring-call lists on CB_SEQUENCE can leak slab garbage into kfree(), which KASAN already hits in nfs_cb_sequence_empty_refcalls_test(). The intended client fix is zeroed allocation of csa_rclists, not a per-list NULL store in decode_rc_list().
