SUNRPC pipefs_sb UAF on late rpc_pipefs mounts

Summary

A short but consequential NFS-client bug-fix thread landed this week: Shigeru Yoshida posted a one-file SUNRPC patch to close a use-after-free that surfaces when RPC clients are created before rpc_pipefs is mounted, and Jeff Layton signed off the same day.

This is a bug fix, not a protocol change. It repairs a hole left by commit bfca5fb4e97c ("SUNRPC: Fix RPC client cleaned up the freed pipefs dentries"), which added clnt->pipefs_sb and a superblock-consistency check in rpc_clnt_remove_pipedir() so pipedir teardown is skipped when the live pipefs superblock no longer matches the one recorded on the client. Yoshida’s diagnosis is that the matching update was never wired into the pipefs notifier path:

"__rpc_clnt_handle_event() never updates clnt->pipefs_sb when it creates or removes pipedirs in response to RPC_PIPEFS_MOUNT and RPC_PIPEFS_UMOUNT notifications."

The practical NFS-client failure mode is clients that exist before pipefs comes up — during boot, or after an unmount. At registration, rpc_get_sb_net() returns NULL, so clnt->pipefs_sb stays NULL. A later RPC_PIPEFS_MOUNT event still creates the pipedir, but leaves that field NULL. When the client is destroyed, rpc_clnt_remove_pipedir() compares the now-live superblock against the NULL recorded pointer, skips cleanup, and leaves orphaned dentries whose RPC_I(inode)->private pointers still point at freed rpc_clnt memory. Opening those leftover info files then trips KASAN in rpc_info_open().

The KASAN report Yoshida included is squarely on the NFS client clone path, not a generic RPC-only workload. Allocation is:

  • nfs_do_submount → nfs4_clone_server → nfs_clone_server → nfs_init_server_rpcclient → rpc_clone_client_set_auth → __rpc_clone_client → rpc_new_client

The free is the usual deferred client teardown (rpc_free_client_work via the workqueue). The user-visible trigger is a later cat of the leftover pipefs info file.

The fix is small and local: in __rpc_clnt_handle_event(), set clnt->pipefs_sb on MOUNT and clear it on UMOUNT, mirroring what rpc_setup_pipedir() already does at client registration. The patch is eight lines in net/sunrpc/clnt.c (Fixes: bfca5fb4e97c). Yoshida noted AI assistance (Assisted-by: Claude:claude-opus-4-6).

Layton’s review was brief and affirmative:

"Looks right."

Reviewed-by: Jeff Layton <jlayton@kernel.org>

No counter-proposals, no requested respin, and no further comments appeared in-window. As of 2026-08-17 the patch has a maintainer Reviewed-by and is waiting on merge; there is no in-thread indication yet that it has been applied. The client-side takeaway is that the earlier pipefs-dentry safety check was incomplete for NFS clones that race (or simply precede) rpc_pipefs mount, and this notifier-side pipefs_sb update is what actually lets rpc_clnt_remove_pipedir() clean up those dentries instead of leaking UAF-prone info files.
