NFS nfsroot: replacing deprecated strlcat() with snprintf()

Summary

This week’s discussion is a cleanup of deprecated string helpers in the NFS client’s nfsroot path, not a protocol change and not a functional NFS bug fix. Mariia Nikitash posted a one-file patch against fs/nfs/nfsroot.c that retires strlcat() from root_nfs_cat() in favor of snprintf(), as part of the Kernel Self Protection Project’s campaign to remove the deprecated strlcat() API.

The change is small: eight lines, four insertions and four deletions. root_nfs_cat() concatenates a comma separator and a source string onto a destination buffer used while assembling nfsroot mount options. Nikitash’s approach builds both pieces in a single snprintf() into the remaining space, then compares the return value (the length that would have been written, excluding the terminating NUL) against that remaining space so the existing truncation check is preserved:

"Build the separator and source string in a single call using the remaining space in the destination buffer. snprintf() returns the length it would have written excluding the terminating NUL, so comparing the return value against the remaining buffer space preserves the existing truncation check."

Google colleagues quickly lined up behind the patch. Justin Stitt supplied a Reviewed-by, and Bill Wendling followed with an Acked-by.

The technical debate opened when David Laight sketched a different rewrite: compute strlen(dest), optionally insert a comma in place, then strscpy() the source into the tail. He also argued the helper should really be an add_option() function, that root_nfs_copy() is “a pointless wrapper on strscpy()”, and that a more valuable target sits nearby:

"I suspect the it used to be just strcat()."

"Much more worth while would be fixing the sprintf() for NFS_ROOT."

Kees Cook accepted that Laight’s sketch was valid, but preferred Nikitash’s %s%s form on readability grounds. He noted that Laight’s version open-codes the first %s and that “the ++len’s interaction between the logic and the argument to strscpy is subtle.” Because root_nfs_cat() is not a fast path, Cook argued for keeping the proposed snprintf():

"Since this isn't fast-path, let's use what Mariia has proposed."

On the add_option() suggestion, Cook was similarly unmoved: the helper is used in too few places to justify a new abstraction. He added his own Reviewed-by.

Nikitash replied that she had considered an approach similar to Laight’s and was “open to any path forward based on what maintainers want,” leaving the choice with NFS maintainers rather than pushing a v2.

Stitt then flagged a potential size_t underflow in Laight’s counter-proposal: if len == destlen, the ++len could make strscpy() see destlen - (len + 1) wrap to SIZE_MAX. Laight dismissed the underflow — len can only be less than destlen, so strscpy() would at worst see a zero-length destination, which is fine — and then went further, arguing the whole helper could drop strlen() entirely. root_nfs_cat() is used only twice against a single static string; tweaking initialization would let sizeof() set the initial length, the comma is always needed, and the second call currently snprintf()s into a temporary buffer that could instead be written directly into the destination.

Status at week’s end: the patch has Reviewed-by from Stitt and Cook plus Wendling’s Acked-by. Cook’s preference for the snprintf() form is the clearest technical conclusion so far. No NFS maintainer Acked-by or merge decision appeared in-window, and Laight’s broader nfsroot string-handling rewrite (including the sprintf() for NFS_ROOT) remains an unaddressed follow-on rather than a blocking objection. The discussion is a hardening/cleanup of NFS client boot-time nfsroot option assembly, not a protocol change.
