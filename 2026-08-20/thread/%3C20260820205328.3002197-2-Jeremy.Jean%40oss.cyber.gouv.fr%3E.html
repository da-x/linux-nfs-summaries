NFSv4.1 CB_SEQUENCE kzalloc_objs referring-call fix

Summary

Summary

This week's traffic is a client-side bug fix, not a protocol change or a new feature. On 20 August, Jérémy Jean posted v2 of a one-line patch to fs/nfs/callback_xdr.c that closes a long-standing hole in NFSv4.1 CB_SEQUENCE referring-call decoding.

The failure is in the NFS client's callback XDR path. decode_cb_sequence_args() currently allocates csa_rclists with kmalloc_objs(), so each referring_call_list starts with uninitialized members. decode_rc_list() writes rcl_refcalls only when rcl_nrefcalls is nonzero. Jean's diagnosis:

"A valid list with zero referring calls therefore leaves the pointer uninitialized, and nfs4_callback_sequence() later passes stale slab contents to kfree()."

That is the same KASAN double-free that v1 already tied to nfs_cb_sequence_empty_refcalls_test(). The patch still carries Fixes: 4aece6a19cf7 ("nfs41: cb_sequence xdr implementation").

Evolution from v1

v1 (posted 17 August in a separate thread, [PATCH] NFSv4.1: initialize referring call pointers before decoding) nulled rcl_refcalls inside decode_rc_list() before session-id decode. Anna Schumaker accepted the bug but rejected that placement:

"I think I would rather have this initialized to NULL from the beginning. Could you instead update decode_cb_sequence_args() to use kzalloc_objs() when allocating the referring_call_lists?"

Jean's v2 changelog records the change of approach:

"On Anna's suggestion, use kzalloc_objs() for csa_rclists instead of initializing each list in decode_rc_list()."

The actual delta is a single allocator swap: csa_rclists is now obtained with kzalloc_objs() so every rcl_refcalls member is NULL from allocation, including valid empty referring-call lists.

Status this week

This thread contains only the v2 posting. There is no Acked-by, Reviewed-by, or merge decision in-window. The technical argument, however, is already settled from the v1 review: empty referring-call lists on CB_SEQUENCE can feed slab garbage into kfree(), and the preferred client fix is zeroed allocation of the whole csa_rclists array rather than a per-list NULL store during decode.

Bottom line for NFS client development: v2 implements Schumaker's requested kzalloc_objs() fix for the CB_SEQUENCE empty referring-call kfree() bug. Reviewers now have the patch they asked for; it still awaits an in-thread ack.
