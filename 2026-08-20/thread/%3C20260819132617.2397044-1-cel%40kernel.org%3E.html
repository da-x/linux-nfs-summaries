NFSD v7.3 pull: CB_NOTIFY directory delegations land in mainline

Summary

Chuck Lever posted the NFSD updates for v7.3 on 19 August, and the kernel.org pr-tracker bot confirmed the next day that Linus merged tag nfsd-7.3 as d141ec2825b4d3ec52f27c43bdd864090159273a. There was no on-list review of the pull itself: two messages, a merge, and a cycle closed.

The pull is a feature drop plus a large bug-fix harvest, not a wire-protocol rewrite. The headline for NFS client development is Jeff Layton’s CB_NOTIFY work on NFSv4.1 directory delegations. knfsd used to recall a directory delegation the moment the directory changed. It now watches delegated directories through fsnotify and pushes adds, removes, renames, and directory attribute changes — with the filehandle and attributes of the affected entry — so a client that implements directory delegations can keep its dcache instead of throwing it away. Some of the NOTIFY4_* flags come from RFC 8881bis and live in nfs_common, so the client tree already has the constants.

The rest of the tag is netlink stats that continue the v7.2 work, a hard-coded SUNRPC pernode thread pool, an async COPY offload rework, a long list of NFSv4 state-revocation use-after-free fixes, and Chris Mason’s SUNRPC/svcrdma hardening. One patch in the pile is an actual fs/nfs client fix: a localio ref leak on nfs_uuid_add_file failure.

Classification

  • New feature: CB_NOTIFY for NFSv4.1 directory delegations; netlink server-stats-get plus per-netns callback counters.
  • Protocol surface: RFC 8881bis NOTIFY4_* flags in nfs_common; CB_NOTIFY encode/decode on the server callback path. Clients that do not speak CB_NOTIFY still see the old recall-on-change behaviour only if they never asked for notifications.
  • Bug fixes / hardening: NFSv4 client-unpin UAFs on revoke/teardown, async COPY stateid races, DRC/IO percpu-counter contention, GSS/RDMA length checks, lockd NLMv4 GRANTED_MSG and SHARE-grant bugs, and a localio ref leak on the client.

What clients actually get from CB_NOTIFY

Lever’s release notes put the client-cache story first:

"Jeff Layton contributed CB_NOTIFY support to NFSD's NFSv4.1 directory delegations. The server used to recall a delegation as soon as the directory changed. NFSD now watches delegated directories through fsnotify and reports adds, removes, renames, and directory attribute changes, carrying the filehandle and attributes of the affected entry, so clients can keep their caches. Some of the NOTIFY4 flags come from RFC 8881bis."

That is the operational change. A Linux NFS client that holds a directory delegation no longer has to treat every mkdir/unlink/rename on that directory as “delegation is dead, revalidate everything.” The server:

  • takes a directory lease with an ignore mask,
  • updates the fsnotify mark when the delegation is set or dropped,
  • applies the client’s notify mask to the delegation,
  • marshals a fattr4 (and the filehandle) from completed args without needing a svc_fh or even an export for fattr4_change,
  • sends child attributes, directory attribute changes, and the filehandle in the CB_NOTIFY payload,
  • tracks requested child and directory attributes separately so GET_DIR_DELEGATION’s reply-size estimate is honest.

The callback ops prepare hook is now a bool return, fi_deleg_file is RCU-protected, and there are dedicated CB_NOTIFY data structures plus encode/decode linkages in nfs4callback.c / xdr4cb.h. fs/nfs/callback.c and callback_xdr.c move a few lines in this tag; the heavy lifting is server-side, but the shared NOTIFY4_* flags in nfs_common are what a client implementation will compile against.

This is the server half of a multi-week directory-delegation push. Earlier in the same week Lever’s CB_RECALL_ANY series named RCA4_TYPE_MASK_DIR_DLG so clients that do implement directory delegations can return them under recall-any pressure. CB_NOTIFY is the complementary piece: keep the cache when the directory is still delegated, instead of only teaching clients how to give the delegation back.

Netlink stats, and why nfsstat on a client host cares

Layton also finished the v7.2 netlink stats work:

"A new server-stats-get operation reports what /proc/net/rpc/nfsd publishes, plus NFSv4 callback counts, and SUNRPC now keeps its per-procedure call counts per network namespace, so a container sees its own numbers. nfsstat reads all of this over netlink, with a procfs fallback for older kernels."

SUNRPC drops the unused svc_version.vs_count field and counts NFSv4 callback operations per netns, exported through the same genetlink family. That is a server ABI, but it is the ABI nfsstat on a client-and-server host (or a container that runs both) will use. The procfs fallback keeps older userland working.

Thread pools: pernode or nothing

"SUNRPC's service thread pool mode selection is gone. Pernode is the right choice on any host we run today, so the auto, global, and percpu modes have been removed. A single-node host still gets one pool. A multi-NUMA host now gets a pool per node. sunrpc.pool_mode accepts the old names but no longer selects anything."

svc_pool_for_cpu() now routes to a populated pool; auto-distribution guarantees a thread per pool; pool counters are torn down before the pool-map reference is dropped; the pool count is derived instead of cached in sv_nrpools. Ameer Hamza’s one-liner restores NUMA_NO_NODE for svc thread allocations in the vestigial global path. Client mounts do not see a mount-option change; they see more predictable nfsd thread placement on multi-node servers.

Bug fixes that matter to clients

The release notes call the remainder “bug fixes, clean-ups, and small optimizations,” then name the ones that have been eating client workloads:

"an async COPY offload rework from Jeff Layton, more use-after-free fixes in the NFSv4 state revocation paths, percpu counter contention removed from the reply cache and IO accounting, and a long list of hardening fixes from Chris Mason."

State-revocation UAFs. Lever’s series is a client-lifetime audit of every walk that can race with nfs4_client teardown: lock-owner free during client teardown, delegation revoke, admin state revocation, export state revocation, NFSv4.0 revoked-state cleanup, blocked-lock reaping, close_lru reaping, plus a consolidated revocation-path client unpin and a released export ref when reaping open stateids. Walkers are annotated with caller preconditions and gated on NFSD_NET_UP. Zhenghang Xiao sets SC_STATUS_FREED in nfsd4_drop_revoked_stid for delegations. From the client’s point of view these are the “server oopsed while recalling my state” class of bugs.

Async COPY. Layton splits nfsd4_copy into transient vs durable async copy objects, makes the copy-offload stateid a first-class nfs4_stid, fixes UAF in copy cancel/shutdown, a stale s2s_cp_stateids IDR entry, copy-notify stateid publish-before-init, client-ownership checks on cancel, and revoke-before-drop of copy-notify stateids. Lever resets the write verifier when async COPY writeback fails and samples the writeback-error cursor before the COPY loop. Inter-server COPY clients should no longer see a server crash or a ghost stateid after cancel.

Session / DRC / filecache. Slot 0 now counts in nfsd_total_target_slots; on-demand DRC growth is bounded by the thread ceiling; an off-by-one in DRC bucket pruning is gone; percpu counters are out of DRC memory accounting, reply-cache stats, and IO byte accounting. Session slots in use are no longer freed; NFSD4_CALLBACK_RUNNING is deferred in deleg_reaper and cleared on a failed recall queue. Filecache shutdown no longer races shrinker/GC/fsnotify; nfsd_file_do_acquire() will not use a non-opened file (NeilBrown); inter-server COPY setup failure no longer leaks an nfsd_file.

Callback and compound robustness. cl_cb_session is RCU-protected so session teardown cannot UAF the callback path. Compound arg release clears opcnt to stop an OOB read. rpc_status dumpit gets a read barrier and real error handling. SUNRPC defers rq_argp/rq_resp free until after an RCU grace period. Backchannel is closed before the callback service is destroyed.

Client-visible protocol nits. nfsd4_delegreturn() now matches the filehandle. nseconds in TIME_DELEG decode paths are validated. Reclaim LOCK after RECLAIM_COMPLETE is rejected. FL_SLEEP is no longer set for every LOCK type. Unsupported netloc4 types return NFS4ERR_NOTSUPP. Nikol Kuklev fixes a NULL deref in nfsd4_setattr for delegated timestamp attributes — the server half of the delegated-timestamp work that has been on the list since last year.

The one in-tree NFS client fix. Chris Mason’s NFS/localio: fix ref leak on nfs_uuid_add_file failure is in fs/nfs_common/nfslocalio.c. Localio is the client/server shortcut; a failed UUID insert no longer leaks a file ref on the client side of that handshake. Adjacent nfsd localio patches hold RCU across the cmpxchg retry and size the fh_verify server sockaddr slot by xpt_locallen.

lockd. Olga Kornievskaia fixes NLMv4 GRANTED_MSG handling. Oscar Ou unswaps arguments in nlmsvc_match_ip() and preserves multiple NLM_SHARE grants from the same owner. Michael Bommarito pins the next file across nlm_inspect_file lock-drop. NLM clients (NFSv3, and anyone still using lockd) are the audience.

Hardening. Mason’s 23 patches clamp GSS/krb5 token lengths, reject short MIC/wrap tokens, fix svcrdma chunk arithmetic and empty Write/Reply chunks, reject oversized Read segments, and close gssx option-array error paths. Lever adds more svcrdma position/budget checks and rejects inline replies that overflow the pull-up buffer. These are not client code changes; they are why a hostile or truncated RPC no longer takes the server — and the client’s outstanding requests — down with it.

Same-week client context (not in this pull)

This tag does not contain the in-window NFS client patches that were still on the list the same days:

  • Jimmy Zuber’s restore d_drop() on failed nfs_mkdir() (stale negative after the 6.15 mkdir-returns-dentry conversion) is unreviewed and not in nfsd-7.3.
  • NeilBrown’s negative-dentry RFC v2 only touches nfs_clear_verifier_directory() so the client can use a common child iterator; it is VFS, not this pull.
  • Petr Vorel’s nfs-utils getport FTBFS fix is userspace.

Directory-delegation clients that want CB_NOTIFY from v7.3 knfsd still need their own client-side CB_NOTIFY consumer; this pull ships the server and the shared flags.

Final conclusions

  • Disposition: merged to torvalds/linux.git on 20 August. No maintainer debate on the pull thread.
  • Headline for NFS client development: knfsd can now notify instead of recall on delegated directories. A client that implements NFSv4.1 directory delegations plus CB_NOTIFY can keep child dentries and attributes across mkdir/unlink/rename. RFC 8881bis notify flags are in nfs_common.
  • Stability: the revocation-path client-unpin series and the async COPY stateid rework are the important bug fixes for long-lived NFSv4.1/4.2 clients. The localio ref-leak fix is the only fs/nfs code change in the tag.
  • Ops: sunrpc.pool_mode is a no-op selector; pernode is mandatory. nfsstat grows a netlink path with procfs fallback. Containers see their own RPC procedure counts.
  • Lever closed the notes with thanks, not a remaining-work list:

"Sincere thanks to all contributors, reviewers, testers, and bug reporters who participated in the v7.3 NFSD development cycle."
