nfs-utils getport FTBFS fix for pre-C23 compilers

Summary

This week brought a one-patch bug fix for an nfs-utils FTBFS, not a protocol change or a new NFS client feature. Petr Vorel posted [FTBFS,PATCH,nfs-utils 1/1] getport: Fix switch case on old compilers, a three-line change to support/nfs/getport.c that restores builds of the user-space NFS client utilities on compilers that still default to C11.

The regression is in nfs_sockaddr2universal(), the helper that turns a sockaddr into a universal address string for NFS port mapping. A recent warning-cleanup commit, 1a6dcd74 ("Removed warnings in nfs_sockaddr2universal()"), introduced a declaration immediately after a switch case label:

size_t path_len = len - offsetof(struct sockaddr_un, sun_path);

That construct is a C23-ism. On older language modes a label must be followed by a statement, and a declaration is not a statement. Buildroot still ships GCC 6.3.0 (Buildroot 2017.05) for aarch64, which fails the file with:

"getport.c:460:3: error: a label can only be part of a statement and a declaration is not a statement"

Vorel’s workaround is the classic C11-compatible one: wrap the case body in a compound statement { ... } so the declaration lives inside a block. He flagged an equally valid alternative for maintainer Steve Dickson:

"Steve, other option would be to use ';'. Not sure which one you prefer."

The patch is a single hunk (2 insertions, 1 deletion) and carries Fixes: 1a6dcd74. It is squarely about keeping nfs-utils — the user-space side of Linux NFS client tooling, including mount helpers and portmap/getport code — buildable on conservative embedded toolchains. There were no replies in this window; the thread is a lone, unacked FTBFS patch awaiting maintainer preference between braces and a null statement after the case label.
