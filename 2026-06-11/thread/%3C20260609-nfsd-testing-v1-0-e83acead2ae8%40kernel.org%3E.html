Jeff Layton's 19-patch nfsd bugfix series for v7.3; Chuck Lever reviews the localio ref leak

Summary

Jeff Layton posts a 19-patch "nfsd: more bugfixes" series targeting v7.3

On Tuesday, June 9, Jeff Layton posted a 19-patch series titled "nfsd: more bugfixes" to linux-nfs, aimed at the v7.3 merge window. The cover letter is refreshingly candid about provenance:

"This is a pile of bugfixes found via LLM inspection. Most of these don't seem to be easily triggerable or require specific conditions, but they're still bugs nonetheless. Please consider these for v7.3."

Every patch in the series carries an Assisted-by: Claude:claude-opus-4-8 tag, making this one of the more prominent examples yet of LLM-assisted kernel auditing landing on a major subsystem list. The series touches 19 files with 182 insertions and 46 deletions, spanning nfsd, lockd, sunrpc, and (in patch 01) the client-side fs/nfs/localio.c.

Highlights of the bugfixes

The series is a grab-bag of correctness fixes rather than a single feature, but several stand out for their severity:

  • Reference-count leak in LOCALIO (PATCH 01/19): Two early-return paths in nfs_local_doio() fail to drop the nfsd_file reference, which "pins the associated net namespace reference, blocking network namespace teardown, and holds a reference on the exported filesystem, preventing unmount." This is the only patch that touches client-side code (fs/nfs/localio.c).

  • Out-of-bounds read via netlink (PATCH 02/19): nfsd4_release_compoundargs() leaves opcnt stale after freeing the dynamic ops buffer, so the RPC status dumpit handler can read up to 16 entries from an 8-element inline array and "leak[s] it to userspace via netlink."

  • Use-after-free in sunrpc (PATCH 05/19): svc_rqst_free() frees rq_argp and rq_resp synchronously while the svc_rqst itself is freed via kfree_rcu(), leaving a window where RCU readers (e.g. nfsd_nl_rpc_status_get_dumpit()) can dereference already-freed buffers.

  • Grace-period denial-of-service (PATCH 13/19): clients_still_reclaiming() mixes CLOCK_REALTIME and CLOCK_BOOTTIME, so the deadline comparison "is always false — it would take ~54 years of uptime for BOOTTIME to exceed the REALTIME-derived deadline." As Layton puts it: "any client can hold the server in grace indefinitely by sending CLAIM_PREVIOUS OPEN requests, blocking all non-reclaim operations for all other clients."

  • RCU protection for lockd ops (PATCH 17/19): nlmsvc_ops is published/cleared with plain stores while lockd dereferences it unguarded, so "a stale load after rmmod nfsd results in either a NULL deref or a module-text use-after-free."

Other fixes cover missing memory barriers in the rpc_status seqcount retry (PATCH 03), netlink dumpit error handling (PATCH 04), unchecked nfsd4_acl_to_attr() return in CREATE (PATCH 06), missing filehandle validation in DELEGRETURN (PATCH 07), unvalidated nseconds in TIME_DELEG decode paths (PATCH 08), premature NFS4_OO_CONFIRMED on failed CLAIM_PREVIOUS opens (PATCH 09), a version-mismatch loop bug in nfsd_acl_init_request() (PATCH 10), an unconditional FL_SLEEP for all lock types (PATCH 11), missing fh_want_write() in the early-verified SETATTR path (PATCH 12), atomicity of somebody_reclaimed (PATCH 14), reclaim LOCK after RECLAIM_COMPLETE (PATCH 15), sockaddr length validation in listener_set (PATCH 16), debugfs init ordering (PATCH 18), and DRC shrinker initialization order (PATCH 19).

Chuck Lever's review of the localio patch

The only reply this week came from NFS maintainer Chuck Lever on Wednesday, June 10, who focused exclusively on PATCH 01/19. In his reply, he raised two practical points:

"I don't seem to have commit e77c464c31b3 in my tree. Should this be Fixes: 70ba381e1a43 ("nfs: add LOCALIO support")?"

And, noting the patch only modifies a client-side file:

"This updates only a client-side source file. Should it go through Anna/Trond's trees? Or were you thinking that, since the leak impacts only NFS server behavior, I should take it?"

Layton responded confirming the corrected Fixes tag — "Yeah, that introduced the first of the leaks, I think" — and was accommodating on the routing question: "I'm fine if Anna or Trond want to take this one."

Status

As of the end of this week's window, only patch 01 has received review; the remaining 18 patches are awaiting maintainer attention. The series is explicitly a bugfix collection (no new features, no protocol changes), and the discussion so far has been limited to the localio reference leak and its routing through the correct maintainer tree.
