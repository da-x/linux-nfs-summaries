NFS: fix CONFIG_NFS_V4 typo in #endif comment

Summary

NFS: correct CONFIG_NFS_V4 macro name in #endif comment

A small but tidy patch landed on the linux-nfs list this week, addressing a long-standing typo in an #endif comment in the NFS client's directory code. The thread consists of a single message — the original patch submission — with no replies or discussion recorded as of the end of the window.

What was submitted

Ethan Nelson-Moore posted a one-line fix on Tuesday, June 9:

"A comment in fs/nfs/dir.c incorrectly refers to CONFIG_NFSV4 instead of CONFIG_NFS_V4. Correct it."

The patch touches fs/nfs/dir.c (1 file changed, 1 insertion(+), 1 deletion(-)) and corrects the preprocessor guard comment so that it matches the actual Kconfig symbol name. This is purely a cosmetic/comment fix — no functional change to the NFS client, no protocol change, and no behavioral bug fix.

How the typo was found

The author explained the discovery context:

"Discovered while searching for CONFIG_* symbols referenced in code but not defined in any Kconfig file."

This is a common cleanup pattern: grep the tree for CONFIG_ identifiers, cross-reference against Kconfig, and flag any that don't resolve. In this case the mismatch was only in a comment, so the fix is trivially safe.

Status

As of the end of the reporting window (2026-06-12), no maintainer has replied with an acknowledgment or applied the patch. Given the trivial nature of the change, it is likely to be picked up during the next merge-window cleanup pass without further discussion.
