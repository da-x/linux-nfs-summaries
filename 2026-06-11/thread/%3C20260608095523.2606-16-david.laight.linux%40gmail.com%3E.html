NFS svcauth_unix: strcpy() replaced with strscpy() for buffer safety

Summary

NFS svcauth_unix: strcpy() → strscpy() hardening patch applied

This week's activity in this thread is brief but noteworthy as part of a broader kernel-wide effort to eliminate unbounded string copies. The discussion centers on a bug fix / hardening change rather than a new feature or protocol modification.

The Patch

On June 8, David Laight submitted a patch targeting net/sunrpc/svcauth_unix.c, replacing two instances of strcpy() with the safer strscpy(). The commit message is direct:

"Replacing strcpy() with strscpy() ensures that overflow of the target buffer cannot happen."

The patch touches only two lines in a single file (net/sunrpc/svcauth_unix.c), making it a minimal, low-risk change.

Context: Part of ~100 Patches

Laight provided important context about the scope of this work. The patch is one of roughly 100 individual submissions across the kernel aimed at removing potentially unbounded strcpy() calls:

"This is one of a group of patches that remove potentially unbounded strcpy() calls. They are mostly replaced by strscpy() or, when strlen() has just been called, with memcpy() (usually including the '\0')."

He noted the methodology—compiler-assisted detection followed by manual fixes—and flagged an important caveat:

"Note that all the changes are only compile tested."

The patches were sent individually to avoid unwieldy cc lists, and some Makefiles were adjusted to allow strcpy() in files where it was deemed acceptable (e.g., sysfs "show" functions that should use sysfs_emit() or seq_printf()).

Quick Acceptance

NFS maintainer Chuck Lever picked up the patch within ~15 hours, applying it to the nfsd-testing tree on June 9:

"Applied to nfsd-testing, thanks!"

commit: cea9ba4f71e82766d782ed423c99bbdf0

No technical objections or discussion arose—the change was straightforward and uncontroversial.

Significance for NFS Client/Server Development

While this particular patch touches the server-side Unix authentication path (svcauth_unix), it is part of a systematic hardening sweep that reduces the attack surface of the RPC/NFS subsystem. The strscpy() replacement eliminates any theoretical risk of buffer overflow in credential string handling, which could otherwise be exploited by a malicious local peer presenting an overlong username or group name. The quick acceptance underscores the community's comfort with this class of mechanical safety improvement.
