NFS client 7.1 bugfix: use-after-free in nfs_write_completion pulled into mainline

This week's activity on this thread is brief but consequential: a one-line, high-severity bug fix for the Linux NFS client was requested and merged into Linus's tree within roughly an hour and twenty minutes of the pull request going out.

The bugfix in detail

On Friday, 2026-06-05, Trond Myklebust — the Linux NFS client maintainer at Hammerspace — sent a pull request to Linus Torvalds for the nfs-for-7.1-2 tag, built on top of Linux 7.1-rc6 (commit e43ffb69e0438cddd72aaa30898b4dc446f664f8). The pull request description is unambiguous about what it contains:

Bugfixes:

  • Fix a use after free in nfs_write_completion

The single commit, authored by Dave Jones, carries the telling title:

NFS: write_completion: dereference loop-local req, not hdr->req

It touches exactly one file — fs/nfs/write.c — with a minimal 1 insertion(+), 1 deletion(-) diff. The fix corrects a use-after-free in the NFS client's write completion path by ensuring the code dereferences the loop-local req pointer rather than the (potentially already freed) hdr->req member.

Why this matters for NFS client development

Use-after-free bugs in kernel memory paths are among the most dangerous class of defects: they can lead to data corruption, privilege escalation, or system crashes under load — and the write completion path is exercised on every NFS write operation, making it a hot code path. A one-line fix like this is the kind of surgical patch that maintainers value highly; it addresses a real memory-safety issue without introducing any behavioral change or new API surface.

The fact that this was delivered as a standalone bugfix pull (tag nfs-for-7.1-2) rather than being bundled with larger feature work signals that the maintainer considered it important enough to warrant its own merge window entry during the 7.1 release cycle.

Rapid merge into mainline

The turnaround was swift. Just over an hour after Trond's pull request, pr-tracker-bot confirmed:

The pull request you sent on Fri, 05 Jun 2026 12:14:01 -0400: git://git.linux-nfs.org/projects/trondmy/linux-nfs.git tags/nfs-for-7.1-2 has been merged into torvalds/linux.git

The merge commit is available at a8dc5f60d127 in the mainline tree.

Broader context for the week

This pull request sits alongside a busy week of NFS development activity on the list, including ongoing work on directory delegation patches (v4/v5/v6 series), NFS server testing submissions, and local I/O improvements — all tracked in other thread summaries for this week. The nfs_write_completion fix is a clean, self-contained bugfix that closes out an important memory-safety issue in the client's write path ahead of the 7.1 release.
