nfs-utils: Fix EIO when setting NFS thread count to 0 without active listeners

Summary

nfsd: Don't assume service is running when setting thread count to 0

Type: Bug fix (nfs-utils userspace)

Overview

This week, Red Hat engineer Scott Mayhew submitted a small but important patch to the nfs-utils project addressing a regression in how the nfsd init script interacts with newer Linux kernels. The issue: when the NFS server has no active listeners (i.e., it is effectively stopped), writing to /proc/fs/nfsd/threads now returns -EIO on recent kernels, which could cause spurious errors during service shutdown or thread-count management.

Key Technical Argument

The core problem is a behavioral change in the kernel's NFS server (nfsd) code path. As Mayhew explained in his patch cover letter posted June 8:

"Newer kernels return -EIO if you try to write to /proc/fs/nfsd/threads and there are no active listeners."

The fix, contained in utils/nfsd/nfsd.c (10 insertions, 6 deletions), ensures the userspace tool does not blindly assume the service is running before attempting to set the thread count to zero. Rather than failing with an unhandled I/O error, the script now gracefully handles the case where no listeners are active.

Discussion and Outcome

The patch drew a quick response from Steve Dickson, the nfs-utils maintainer, who confirmed it was accepted:

"Committed..." — Steve Dickson, June 16

Dickson's one-word verdict (plus ellipsis) is characteristic of his review style on the list, signaling a clean, uncontroversial fix that needed no further discussion.

Significance for NFS Client/Server Ecosystem

While this is a server-side userspace fix rather than a client change, it matters to administrators running NFS servers on modern kernels (likely 6.x+). Without this patch, stopping or restarting the nfsd service on systems with no active exports could produce confusing error messages in logs or fail systemd unit transitions. The fix tightens the userspace contract between the init script and the kernel's procfs interface, a common area of friction as kernel behavior evolves.

Status

  • Patch: Committed to nfs-utils by Steve Dickson.
  • Upstream impact: None on the kernel; purely a userspace robustness improvement.
