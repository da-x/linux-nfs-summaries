Context for readers

The question sits at an interesting intersection of two long-standing Linux topics:

  1. Swap over NFS has historically been discouraged (and in some configurations explicitly refused) because the kernel's swap subsystem demands reliable, low-latency I/O that a network file system cannot guarantee — a server hiccup or a stale NFS handle can wedge page-in/page-out and take down the whole machine.
  2. NFS/RDMA (the rdma transport for NFSv4) was added to cut latency and CPU cost on high-speed fabrics, but it does not by itself change the reliability semantics of the underlying protocol; swap still goes through the same page-cache / VFS paths.

So the practical answer Nishimura is fishing for — "can I swapon an NFS file on a mount that uses rdma as its transport?" — has no in-thread discussion yet this week, and no prior-week summary files exist for this thread (it appears to be a fresh topic).
