nfsd/sunrpc: Convert nfsstat Server-Side Statistics to Netlink (PATCH v3)

Overview

This week's activity in the thread is a single event: on 2026-06-09, Red Hat's Jeff Layton posted the third revision of his four-patch kernel series, "[PATCH v3 0/4] nfsd/sunrpc: convert nfsstat server-side interfaces to use netlink". As with the prior v2 posting in late May, no replies or review comments landed within this week's window — the thread consists solely of the five messages (cover letter plus four patches) that Layton posted in quick succession. The series is a new feature / interface modernization rather than a bug fix, though it does include a deliberate behavior change to the procfs statistics output and touches NFS client code (fs/nfs/callback_xdr.c) during cleanup.

Motivation and Key Technical Arguments

The cover letter restates the three concrete limitations of the current mechanism, in which the nfsstat tool scrapes /proc/net/rpc/nfsd:

"The nfsstat tool currently scrapes /proc/net/rpc/nfsd for server statistics. This procfs interface has several limitations: the counters are global (not network-namespace-aware), the format is fragile to parse, and it cannot be extended without breaking existing parsers."

The proposed solution adds per-network-namespace procedure call counts to the sunrpc layer and exposes them through a new netlink handler in the nfsd generic netlink family, with a procfs fallback retained for older kernels.

The Four Patches (v3)

Patch 1/4 — sunrpc: add per-netns per-procedure call counts to svc_stat The foundational change. Layton adds a vs_count pointer array to struct svc_stat, plus svc_stat_alloc_counts() / svc_stat_free_counts() helpers to manage per-version percpu count arrays tied to the nfsd_net lifecycle:

"Add a vs_count pointer array to struct svc_stat, along with svc_stat_alloc_counts() and svc_stat_free_counts() helpers to manage per-version percpu call count arrays. Increment the per-net counter alongside the global one in svc_generic_init_request()."

Patch 2/4 — sunrpc: use per-net counts in svc_seq_show() A small but consequential change that switches svc_seq_show() to read from the per-netns arrays instead of the global ones:

"This makes /proc/net/rpc/nfsd report per-network-namespace procedure call counts."

Layton is candid about the impact in the cover letter:

"Note that this is a behavior change, but I think it's a desirable one."

Patch 3/4 — nfsd: implement server-stats-get netlink handler The core of the new feature. It implements nfsd_nl_server_stats_get_dumpit(), a dump operation that streams statistics across multiple netlink messages:

"First message: all scalar stats (reply cache, filehandle, IO, network, RPC) plus per-version procedure counts (proc2/3/4-ops) using per-netns vs_count arrays. Subsequent messages: NFSv4 per-operation counts (proc4ops-ops), one entry per message, using cb->args[0] to track the current operation index across dump calls."

This patch also adds a netlink spec (Documentation/netlink/specs/nfsd.yaml, +105 lines) and new UAPI definitions in include/uapi/linux/nfsd_netlink.h (+35 lines).

Patch 4/4 — sunrpc: remove unused svc_version vs_count field A cleanup that removes the now-dead global per-version vs_count percpu counters from nfsd, lockd, and the NFS client callback service (fs/nfs/callback_xdr.c). This is a notable touch to NFS client code — the callback service's unused counter array is dropped as part of the deprecation:

"Now that svc_seq_show() and the nfsd netlink stats handler both use the per-netns svc_stat vs_count arrays, the global per-version vs_count percpu counters are no longer read by anything."

What Changed in v3 (vs. v2)

The only explicit change noted between v2 and v3 is a refinement to the counting logic:

"Changes in v3: Only increment per-net stats for the 'primary' program"

This addresses a potential double-counting issue where non-primary programs sharing an RPC service could inflate per-namespace counters. The link back to v2 is provided in the cover letter.

Evolution and Context (Bridging Prior Weeks)

The v3 revision continues a multi-round effort that began in mid-March 2026 (change-id: 20260316-exportd-netlink-...). The v2 posting on 2026-05-25 was the immediately prior revision, also posted without in-window review feedback. This kernel-side work is the natural companion to the user-space netlink upcall/downcall series Layton sent to nfs-utils back in March, which moved mountd/exportd/exportfs off the legacy /proc cache interfaces. This series extends the same netlink-based philosophy to server statistics collection.

NFS Client Relevance

While this is primarily a server-side (nfsd/sunrpc) change, Patch 4 touches fs/nfs/callback_xdr.c, removing the NFS client callback service's now-unused global vs_count percpu array. This is a minor but notable cleanup in NFS client code that removes dead counter infrastructure as part of the broader sunrpc stats modernization.

Final Conclusions

As of the end of this week's window, the v3 series has been posted but no review feedback or maintainer response had landed on this thread — it is awaiting discussion. Layton tees up the follow-on user-space work:

"I'll also be sending an nfs-utils patch to convert nfsstat to use the new interfaces."

The net effect, if accepted, would be a namespace-aware, extensible, binary statistics interface for NFS server monitoring — completing the migration of nfsd's user-space tooling off fragile procfs scraping. (Subsequent revisions v4–v7 of this series were posted in later weeks.)
