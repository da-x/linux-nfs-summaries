nfsd: Coccinelle-driven error-handling cleanup in svc_export_alloc() rejected on style grounds

Summary

nfsd: Use common error handling code in svc_export_alloc()

Type: Bug fix / code cleanup (refactoring) — not a new feature or protocol change. Status: Rejected by maintainer; no further activity this week.

Overview

This is a short, two-message thread that opened and closed on 2026-06-11. It concerns a small refactoring patch to the NFS server (nfsd) export code rather than the client, but it touches the shared svc_export_alloc() allocation path in fs/nfsd/export.c.

The Patch

Markus Elfring submitted a one-file patch (3 insertions, 4 deletions in fs/nfsd/export.c) aimed at consolidating exception handling. The stated goal:

"Use an additional label so that a bit of exception handling can be better reused at the end of an if branch."

Elfring noted the change was machine-driven rather than hand-written:

"This issue was detected by using the Coccinelle software."

The patch adds a goto label inside an if block so that duplicate cleanup/teardown code at the tail of the branch can be folded into a single shared path — a classic Coccinelle "use common error handling" semantic match.

The Review

NFS maintainer Jeff Layton replied within ~17 minutes and pushed back. While conceding the change is technically valid, he objected to the readability cost:

"I'm not a fan of this patch. I mean, it's legal and all, but sticking a goto label in the middle of a if block makes for messy-looking and hard to reason about code."

Layton's objection is stylistic rather than functional — the concern is that embedding a goto label mid-block obscures control flow and makes the function harder to follow, even though it reduces a few lines.

Evolution & Conclusion

The discussion did not progress beyond this single exchange within the reporting window; there was no author rebuttal or revised patch posted by the end of the week. The practical outcome is that the cleanup, while mechanically sound, was turned down on maintainability grounds — a recurring theme for Coccinelle-generated refactors that trade clarity for line-count reduction.

Note on Scope

This thread sits among a busy week of nfsd activity (directory delegation rework, nfsd testing infrastructure, and localio changes summarized elsewhere), but it is an isolated micro-refactor with no bearing on the client-side work dominating this week's list traffic.
