Dan Shelton asks how NFSv4.2 read/write latency compares to iSCSI and P9FS on Linux

Summary

A cross-posted latency question lands on linux-nfs

This week's activity in this thread is limited to a single message: a fresh inquiry from Dan Shelton, who ported an ongoing FreeBSD-hackers discussion over to the Linux NFS list. The thread has not yet drawn any replies from kernel developers within the reporting window (the only follow-up, also from Shelton himself, landed on 2026-06-12 — just outside this week's half-open interval).

What was posted

Shelton opened the thread on 2026-06-05 by quoting a FreeBSD-hackers exchange in which Bakul Shah had offered an explanation for why NFS latency looks worse than 9P:

"p9fs doesn't cache but nfs does, so anything cached is served much faster."

Shelton then turned the question toward Linux:

"How is the situation on Linux? How is read/write latency NFSv4.2 compared to iSCSI and P9FS?"

Nature of the discussion

This is a performance/behavior question, not a bug report, patch, or protocol change. No code, no patches, and no client-side fix are involved in this week's activity. The implicit technical framing — that NFS's caching layer (and its associated state management, delegation handling, and RPC round-trips) can inflate observed per-I/O latency relative to block-level iSCSI or the cacheless 9P protocol — is the kind of question typically answered by maintainers with measurement caveats (page-cache hit vs. miss, server proximity, NFSv4 session/compound behavior) rather than by a code change.

Status and outlook

  • In-window activity: one message (the original post).
  • No developer responses were posted during the week ending 2026-06-11.
  • A self-reply from Shelton dated 2026-06-12 exists in the thread but falls outside this week's window, so it is not summarized here; it may contain additional data points or a follow-up question worth watching next week.

Bottom line

The thread currently reads as an open call for Linux NFS maintainers to put numbers on the NFSv4.2-vs-iSCSI-vs-P9FS latency comparison. Until a maintainer responds, there is no technical conclusion to report — just the question itself, framed by the FreeBSD-side observation that "p9fs doesn't cache but nfs does."
