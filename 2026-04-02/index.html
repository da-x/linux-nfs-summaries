NFS client delegation bug fixes, netlink upcall integration, and state revocation on unmount dominate this week's activity

Week ending 2026-04-02

NFS Client: Wave of Delegation Attribute Bug Fixes

This week saw a concentrated burst of important correctness fixes for the NFS client, primarily authored by Olga Kornievskaia (Red Hat) and Dai Ngo (Oracle), addressing subtle metadata staleness issues that arise when delegated attributes are active. These bugs were exposed by xfstest regressions and represent the ongoing challenge of balancing delegation-based performance optimizations with strict POSIX semantics.

  • CLONE/COPY attribute staleness: Two patches fix stale mtime/ctime values after NFSv4.2 CLONE and COPY operations when delegated attributes are present on the client. The client was ignoring server-provided timestamps in favor of cached delegation data, causing xfstest generic/407 to fail. See CLONE fix and COPY fix.
  • RENAME attribute staleness with directory delegations: A regression introduced by a prior delegation verifier optimization caused mtime/ctime to remain unchanged after rename operations when directory delegations were active, failing xfstest generic/309. Fix.
  • Inode size trust during write delegations: Dai Ngo submitted a fix preventing the client from overwriting its locally cached file size with stale server-reported values while holding a write delegation. Fix.
  • removexattr ctime update: Jeff Layton's patch to add a trailing GETATTR to the REMOVEXATTR compound operation sparked an extended debate on delegated timestamp semantics. The consensus: synchronous metadata operations like SETXATTR/REMOVEXATTR must bypass delegation caching because they cannot be deferred and have no mechanism for updating only ctime. Discussion.

NFSD: Netlink Upcalls and Automatic State Revocation

Two major infrastructure projects reached significant milestones this week, modernizing how NFS server userspace tools communicate with the kernel.

  • Netlink upcalls applied: Jeff Layton's 13-patch series replacing /proc-based pipe interfaces with generic netlink for mountd and exportd was reviewed and applied to the nfsd-testing tree by Chuck Lever. The companion nfs-utils v2 series (16 patches) was committed to nfs-utils-2.9.1-rc3. This eliminates the /proc dependency, enabling containerized NFS deployments and simplifying future export option extensibility. See kernel series.
  • Automatic state revocation on unmount (v7): Chuck Lever submitted v7 of his 7-patch series introducing three netlink commands (NFSD_CMD_UNLOCK_IP, NFSD_CMD_UNLOCK_FILESYSTEM, NFSD_CMD_UNLOCK_EXPORT) to revoke NFSv4 client state when filesystems or exports are unmounted. This resolves the long-standing EBUSY problem preventing clean unmounts. All patches carry Reviewed-by: Jeff Layton. Lever also submitted a companion exportfs patch to trigger state revocation when the last client for an export path is removed. See v7 series.

NFSD: Bug Fixes and Performance Work

  • nfsd_file reference leak on shutdown: Wolfgang Walter reported a BUG: Objects remaining on __kmem_cache_shutdown() during NFS server teardown. Chuck Lever identified the root cause as a missing fix for an nfsd_file reference leak in nfsd4_add_rdaccess_to_wrdeleg(), now available in stable kernel 6.18.20. Discussion.
  • lockd TEST permission fix: Neil Brown's patch fixing F_GETLK to work with read-only file descriptors is accepted, but Chuck Lever flagged that the NLMv4 xdrgen rewrite in nfsd-testing prevents automated stable backporting. A manual backport for LTS kernels will be needed. Discussion.
  • Fuzzer report dismissed: A fuzzer team reported an alleged refcount_t underflow in nfs3svc_release_getacl(). Chuck Lever dismissed it, noting that SunRPC zero-initializes response buffers and fh_put() guards against NULL pointers. Discussion.
  • RWF_DONTCACHE write performance: Jeff Layton submitted a 4-patch series to fix severe throughput collapse with RWF_DONTCACHE under concurrent writers by introducing rate-limited writeback and an atomic flush guard. Christoph Hellwig and Ritesh Harjani raised design concerns about in-caller writeback vs. the writeback daemon. Discussion. This continues the broader nfsd iomode benchmarking debate.

Infrastructure and New Features

  • netfs bvecq refactoring: David Howells' 26-patch series replacing folio_queue with segmented bio_vec[] chains in netfslib received extensive Reviewed-by tags from Paulo Alcantara. Stefan Metzmacher flagged integration conflicts with the ksmbd tree over shared RDMA iterator code. The series embeds several important bug fixes for NFS fscache operations. Discussion.
  • P2PDMA support RFC: Pranjal Shrivastava submitted an RFC to enable PCI Peer-to-Peer DMA in NFS client Direct I/O, allowing data movement between NVMe and NIC without traversing system memory. Christoph Hellwig and Chuck Lever requested separation of the API migration, dynamic capability checking for RDMA reconnections, and pNFS layout driver integration. Discussion.
  • OPENAT2_REGULAR flag: v6 of the openat2() security flag series received a Reviewed-by from Jeff Layton, including NFS client support. Discussion.
  • max_block_size increase: Mike Snitzer followed up requesting Anna Schumaker to post her Linux NFS client patch enabling support for block sizes greater than 1MB, a prerequisite for increasing the default max_block_size to 4MB. Discussion.

Ongoing Issues

  • FS-Cache PG_WB_END warning: Mike Owen posted a follow-up on the WARNING in nfs_free_request: PG_WB_END stale bug with FS-Cache, but no new diagnostic details or maintainer response were received. Discussion.
