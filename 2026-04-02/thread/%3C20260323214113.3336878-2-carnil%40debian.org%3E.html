nfs.conf: Commitment of vers4.0 default comment update

Summary

This week concluded a brief documentation alignment effort regarding the NFS server (nfsd) configuration in nfs-utils. The thread focused on updating the nfs.conf file to accurately reflect that NFSv4.0 is disabled by default, following previous kernel and utility changes.

Prior Context (Brief)

Last week, Salvatore Bonaccorso submitted a patch 1 to update the commented entry for vers4.0 in the nfsd section of nfs.conf. This was done to maintain consistency with prior patches (bb3f98c848a0 and 27b9d85dbc30) that disabled NFSv4.0 by default in the kernel and nfsdctl, respectively, due to security concerns (lack of strong authentication/encryption). Jeff Layton provided a quick review-by 2.

This Week's Activity

The thread concluded with Steve Dickson, the nfs-utils maintainer, committing the patch. He confirmed the inclusion in the upcoming release:

"Committed.. (tag: nfs-utils-2-9-1-rc2)" 3

Conclusion

This was a documentation/configuration fix ensuring that system administrators see the correct default state for NFSv4.0 in nfs.conf. The patch is now part of the nfs-utils-2-9-1-rc2 release candidate, completing the alignment of user-space configuration documentation with the security-driven defaults in the kernel and nfsdctl.
