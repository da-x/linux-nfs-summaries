Summary

netfs: bvecq Transition — Resolving Integration Conflicts with CIFS/SMB Direct

Overview

This thread addresses integration challenges between David Howells' major 26-patch series to replace folio_queue and rolling_buffer with a segmented bio_vec[] chain (bvecq) in netfslib, and Stefan Metzmacher's ongoing work on the ksmbd-for-next branch. The discussion this week focused on resolving patch conflicts related to CIFS RDMA support and determining the best integration strategy.

Background

David Howells' patch series introduced a substantial refactoring of netfslib, replacing the folio_queue construct with a new bvecq (bio_vec queue) structure. The series aims to:

  1. Consolidate kernel file I/O on bio_vec arrays
  2. Reduce buffering schemes in netfslib to a single unified approach
  3. Enable sending entire filesystem RPC requests via a single kernel_sendmsg() call for improved TCP efficiency

Key changes include switching CIFS to use bvecq instead of folio_queue, adding ITER_BVECQ support to smb_extract_iter_to_rdma(), and removing support for ITER_KVEC/BVEC/FOLIOQ.

This Week's Discussion

Stefan Metzmacher raised a conflict issue on March 29, noting that the patch series conflicts with ksmbd-for-next, a branch that is "typically rebased every few days." He proposed several resolution strategies:

"Maybe we should have a fixed non rebased branch for the smbdirect.ko patches in ksmbd-for-next, so that David can rebase on that. Or should Steve put this also into ksmbd-for-next?"

Metzmacher suggested an alternative approach:

"Another possible way would be to skip this for now cifs: Remove support for ITER_KVEC/BVEC/FOLIOQ from smb_extract_iter_to_rdma() and I rebase my changes on top of Davids patches assuming they will be stable commits (at least up to cifs: Support ITER_BVECQ in smb_extract_iter_to_rdma())"

David Howells responded on March 30, offering flexibility:

"I could certainly split my removal patch. I want to remove FOLIOQ support, but I can leave KVEC and/or BVEC if they're still needed."

Metzmacher agreed with this approach:

"Yes, please keep them, I guess we can removed unused stuff at the end of the merge window."

However, Metzmacher noted that the actual conflict resolution remained open:

"Any idea on how to resolve the actual conflict?"

Technical Significance

This discussion highlights the coordination challenges between subsystem maintainers during major infrastructure refactoring. The bvecq transition affects multiple network filesystems (NFS, AFS, CIFS/SMB) and the cachefiles layer. For NFS client development specifically, the series touches fs/nfs/fscache.c and introduces new Kconfig dependencies, though the core NFS I/O paths are not directly modified in this series.

The patch series also includes several bug fixes:

  • Fix for NULL pointer dereference in netfs_unbuffered_write() on retry (Deepanshu Kartikey)
  • Fix for kernel BUG in netfs_limit_iter() for ITER_KVEC iterators (Deepanshu Kartikey)
  • Fix for error handling in netfs_extract_user_iter() (Paulo Alcantara)
  • Fix for VM_BUG_ON_FOLIO() issue in netfs_write_begin() (Viacheslav Dubeyko)

Status

As of the end of this week, no definitive resolution was reached regarding the conflict between David Howells' netfs patches and the ksmbd-for-next branch. The participants agreed that retaining ITER_KVEC/BVEC support temporarily would ease integration, but the broader question of how to coordinate patch submission between the VFS tree and ksmbd-for-next remains open.
