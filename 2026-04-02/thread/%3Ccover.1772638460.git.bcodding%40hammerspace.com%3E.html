nfs-utils: Signed Filehandle Patches Committed (v7)

Summary

This week, the long-running signed filehandle support patch series for nfs-utils reached its final milestone: the two-patch v7 series was committed to the upstream repository. This is a new feature — a security enhancement that prevents NFS filehandle guessing attacks by appending an 8-byte SipHash MAC to filehandles on selected exports.

Background (Prior Weeks)

The signed filehandle feature has been under development since January 2026, with the kernel-side patches applied to nfsd-testing in early March and the userspace series progressing through seven versions. The core motivation, as Benjamin Coddington explained, is that NFS filehandles are trivially guessable:

"Filehandles are easy to guess because they are well-formed... You can simply insert inode numbers and iterate on the generation number. Eventually you'll be able to access the file using open_by_handle_at(2)."

The v7 userspace series, posted on 2026-03-04, added the sign_fh export option to exportfs and implemented key management infrastructure in nfsdctl, deriving a secret signing key from a configurable file via SHA-1 hashing. See the prior week's summary (2026-03-05) for full details of the patch series and its evolution through v1–v7.

This Week's Activity

On 2026-03-29, nfs-utils maintainer Steve Dickson confirmed that the v7 series had been merged:

"Committed... (tag: nfs-utils-2-9-1-rc2)"

Steve Dickson acknowledged the original cover letter from Coddington and noted the commit target: the nfs-utils-2.9.1-rc2 release tag. This marks the completion of the end-to-end development cycle for signed filehandle support, pairing the previously merged kernel-side implementation with its userspace configuration tools.

Conclusion

The signed filehandle feature is now fully implemented and available in both the Linux kernel (via nfsd-testing) and nfs-utils. Administrators can opt in to hardened exports by:

  1. Configuring a secret key file via fh_key_file in the nfs.conf server section
  2. Adding the sign_fh export option to individual exports in /etc/exports

This provides an effective defense against filehandle guessing attacks while maintaining backward compatibility with existing NFS clients that do not understand signed filehandles. The feature will be part of the upcoming nfs-utils-2.9.1 release.
