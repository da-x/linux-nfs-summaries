Belated RISC-V Ack for Rejected rest_of_page() Macro Series

Summary

Belated Acknowledgment for Previously Rejected Macro Globalization

Overview

This week saw a single late response to Yury Norov's eight-patch series from March, which proposed globalizing the rest_of_page() macro across the kernel tree. The series, originally submitted on March 4th and discussed extensively that same day, had already been effectively rejected by maintainers who argued against obscuring simple arithmetic with abstractions. Paul Walmsley provided a belated "Acked-by" for the RISC-V architecture portion of the series on April 2nd.

Prior Context (March 2026)

The patch series aimed to move the rest_of_page() helper from the net/9p driver into core/mm and apply it tree-wide, including changes to the NFS client in fs/nfs/pagelist.c (Patch 2/8). The proposal faced immediate and strong opposition:

"The thing is, now I have to go lookup what on earth rest_of_page() does, whereas PAGE_SIZE - offset_in_page(page) is immediately obvious. It's a classic case of 'oh let's add this helper to simplify things' which really just makes it worse... IOW, just no." Jens Axboe

Peter Zijlstra echoed this sentiment:

"I hate these pointless helpers that obscure perfectly sensible and obvious code -- and for me that includes things like rounddown() and DIV_ROUND_UP(). It just makes the code harder to read." Peter Zijlstra

This Week's Activity

The sole message this week was Paul Walmsley's acknowledgment for Patch 8/8, which targeted architecture-specific code:

"Acked-by: Paul Walmsley pjw@kernel.org # arch/riscv" Paul Walmsley

This ack arrived approximately one month after the original submission and well after the broader maintainership community had expressed clear opposition to the series. The acknowledgment appears to be a belated response rather than an indication of renewed support for the patch set.

Classification

This discussion concerns a cosmetic code cleanup (not a bug fix, new feature, or protocol change). The proposed changes were described as having "no functional changes intended."

NFS Client Impact

The NFS client was affected by Patch 2/8 of the original series, which would have modified fs/nfs/pagelist.c to use the rest_of_page() macro. Given the strong opposition from maintainers and the lack of any indication that the series will be resubmitted or accepted, the NFS client code is expected to retain its current implementation using explicit arithmetic (PAGE_SIZE - offset_in_page(ptr)).

Conclusion

The thread remains effectively closed following the March rejection. Paul Walmsley's late ack for the RISC-V portion does not signal renewed momentum for the series, particularly given the clear consensus against the abstraction from key subsystem maintainers. No further activity related to NFS client development or bug fixes emerged this week from this thread.
