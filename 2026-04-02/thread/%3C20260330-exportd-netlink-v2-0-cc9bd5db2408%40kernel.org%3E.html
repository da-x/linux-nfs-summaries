Summary

nfs-utils v2: Netlink Support for mountd, exportd, and exportfs

Classification

This is a new feature / infrastructure change in nfs-utils, introducing netlink-based upcall and downcall support for the NFS server-side daemons (mountd, exportd) and the exportfs utility. It replaces the legacy /proc-based pipe interface with generic netlink, enabling containerized NFS deployments and future export option extensibility. The series also includes a few bug fixes and documentation cleanups.

Overview

On March 30, Jeff Layton submitted v2 of a 16-patch series for nfs-utils, adding netlink support to mountd, exportd, and exportfs. This userspace work is the companion to a corresponding 13-patch kernel series that was applied to the nfsd-testing tree earlier this week by Chuck Lever.

In the cover letter, Layton stated:

"This adds support for the new netlink-based upcalls and downcalls in mountd, exportd and exportfs. With this, mountd is no longer reliant on /proc for sunrpc cache upcalls."

The v2 changes were minor compared to v1 (submitted March 16):

"Changes in v2: Consolidate UAPI header updates into one patch; Rebase onto nfs-utils-2-9-1-rc2."

Key Technical Arguments and Design Decisions

Netlink as Primary, /proc as Fallback

The series introduces a dual-mode architecture where netlink is the preferred communication channel between the kernel and userspace daemons, with /proc retained as a fallback for older kernels. As described in patch 11/16:

"Now that all of the exportd upcalls are converted to use netlink, don't bother opening /proc channel files if that succeeds."

The fallback mechanism is designed to be transparent: if the kernel does not support the nfsd or sunrpc generic netlink families, the daemons silently fall back to /proc-only operation. Both mechanisms can coexist safely because the kernel's CACHE_PENDING check prevents duplicate processing.

Coverage of All Cache Types

The series adds netlink handlers for four distinct cache types across two generic netlink families:

  1. svc_export (nfsd.export) — via the nfsd genl family (patch 07/16)
  2. expkey (nfsd.fh) — via the nfsd genl family (patch 08/16)
  3. auth.unix.ip (ip_map) — via the sunrpc genl family (patch 09/16)
  4. auth.unix.gid (unix_gid) — via the sunrpc genl family (patch 10/16)

Each handler uses a two-socket design: a non-blocking notification socket that joins the multicast group and integrates into the existing select() loop, and a blocking command socket for issuing GET_REQS dumps and SET_REQS responses.

Targeted Cache Scanning

patch 13/16 adds an optimization to avoid unnecessary netlink round-trips:

"Parse the NFSD_A_CACHE_NOTIFY_CACHE_TYPE and SUNRPC_A_CACHE_NOTIFY_CACHE_TYPE attributes from netlink multicast notifications to determine which specific caches have pending requests. Only issue GET_REQS for the caches that actually need servicing, avoiding unnecessary netlink round-trips."

Pending Request Handling at Startup

patch 12/16 addresses a race condition where requests may queue before the daemon comes online:

"It's possible for there to be requests queued before mountd comes online. Always check for already-pending requests after opening netlink sockets."

exportfs Enhancements

The series also modernizes exportfs:

  • patch 14/16 adds netlink-based cache flushing with /proc fallback, maintaining the correct dependency order (sunrpc caches flushed before nfsd caches).
  • patch 15/16 uses netlink to probe kernel support and skips the advisory export_test() probe when netlink is available:

"If successful, the kernel supports the new netlink-based cache interfaces and we can skip the advisory export_test() probe -- mountd and exportd will validate exports at cache-fill time via check_export()."

  • patch 16/16 adds a --no-netlink (-L) command-line option and no-netlink= config file setting for debugging or working around kernel netlink issues.

Bug Fixes and Cleanups

The series includes two notable bug fixes:

  1. patch 02/16 removes unnecessary static variables in the nfsd_fh expkey lookup, converting them to local variables scoped to the inner loop. This prevents state leakage across function calls during CROSSMOUNT submount iteration.

  2. patch 03/16 removes obsolete documentation about "legacy mode" for 2.4-era kernels from the exportfs manpage, noting that the nfsservctl() syscall was removed in Linux 3.1 and the corresponding code was dropped long ago.

Evolution of the Discussion

This series is the userspace counterpart to Jeff Layton's kernel-side netlink upcall series (v2), which was reviewed by Chuck Lever and applied to nfsd-testing on April 2. The kernel series introduced the nfsd and sunrpc generic netlink families, cache notification mechanisms, and flush commands. This nfs-utils series implements the corresponding userspace consumers.

The v1 of this nfs-utils series (submitted March 16) was linked from the cover letter. The v2 rebased onto nfs-utils-2-9-1-rc2 and consolidated UAPI header updates into a single patch, simplifying the review surface.

Final Conclusion: Series Committed

On April 3, nfs-utils maintainer Steve Dickson confirmed that the entire series was accepted:

"Committed... (tag: nfs-utils-2.9.1-rc3)" — Steve Dickson

The 16-patch series touched 20 files with approximately 2,350 insertions and 411 deletions. The bulk of the changes (1,892 lines added to support/export/cache.c) implement the netlink cache handlers, while new bundled UAPI headers (nfsd_netlink.h and sunrpc_netlink.h) ensure compatibility with kernels that may not yet carry the latest system headers.

Significance for NFS Development

This series marks a major architectural shift in how NFS server-side userspace tools communicate with the kernel:

  1. Container Compatibility: By eliminating the /proc dependency, mountd and exportd can now run in containers where /proc access may be restricted or undesirable.
  2. Extensibility: Future export options will only need to be added to netlink headers, avoiding the need to synchronize multiple pipe protocols. As Layton noted in the kernel series:

"The intent is that future export options will only be added to the netlink headers, which should eliminate the need to keep so much in sync."

  1. Performance: Targeted cache scanning and elimination of /proc polling reduce overhead in high-load NFS server deployments.
  2. Backward Compatibility: The graceful fallback to /proc ensures that older kernels remain supported during the transition period.
