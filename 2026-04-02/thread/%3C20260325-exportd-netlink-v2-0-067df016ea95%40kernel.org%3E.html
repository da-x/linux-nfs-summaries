nfsd/sunrpc: Netlink upcall series v2 reviewed and applied to nfsd-testing

Summary

nfsd/sunrpc: Netlink Upcall Series v2 — Review and Application

Classification

This is a new feature / protocol interface change affecting the NFS server (nfsd) and SunRPC subsystem. The series introduces generic netlink-based communication channels to replace antiquated /proc-based pipe interfaces used by mountd and exportd. While primarily an nfsd/userspace tooling concern, it has implications for containerized NFS deployments and future export option extensibility.

Overview

Following the v2 submission of Jeff Layton's 13-patch series last week (see prior summary), this week saw targeted review from Chuck Lever and, ultimately, the application of the entire series to the nfsd-testing tree.

Key Technical Discussion: svc_export Netlink Attribute Cleanup

The substantive technical exchange centered on Patch 10/13, which adds netlink upcall support for the svc_export (nfsd.export) cache. On March 30, Chuck Lever flagged an unused attribute set in the YAML specification:

"Is the svc-export-req attribute set used for anything?" — Chuck Lever

Jeff Layton confirmed this was a vestige from an earlier design iteration:

"No, good catch. That's a holdover from an earlier version that had a separate attribute set for the up and downcalls. It's not needed in the latest version." — Jeff Layton

Layton further clarified that removing the attribute set and regenerating the headers would not break the build:

"It should be fine to remove it and regenerate the headers. The result builds fine without it. I've pushed a fixed patch to the 'exportd-nl' branch in my tree." — Jeff Layton

Chuck Lever opted to hold off on immediate action, preferring to see if additional review comments emerged:

"Thanks for jumping on that. Let's wait to see if there are other review comments." — Chuck Lever

Final Conclusion: Series Applied to nfsd-testing

On April 2, Chuck Lever announced that the entire 13-patch series had been applied to the nfsd-testing tree. The cover letter noted that v2 addressed most of Chuck's prior review comments and that the netdev mailing list had been added for broader netlink expertise:

"This version should address most of Chuck's review comments. The userland patch series is unchanged. I've added the netdev folks this time." — Jeff Layton

The application confirmation listed all 13 commits:

"Applied to nfsd-testing, thanks!" — Chuck Lever

The applied patches include:

  • Patches 01/13–04/13: Preparatory renames removing "pipe" terminology from sunrpc cache functions.
  • Patches 05/13–06/13: Core infrastructure adding cache_notify callbacks and request snapshot helpers.
  • Patch 07/13: A new "sunrpc" generic netlink family for cache upcalls.
  • Patches 08/13–09/13: Netlink upcall support for the auth.unix.ip and auth.unix.gid caches.
  • Patches 10/13–11/13: Netlink upcall support for the svc_export (nfsd.export) and nfsd.fh (expkey) caches.
  • Patches 12/13–13/13: Cache flush commands (SUNRPC_CMD_CACHE_FLUSH and NFSD_CMD_CACHE_FLUSH) allowing userspace to clear auth and export caches via netlink.

Significance for NFS Development

Although this series targets the NFS server side rather than the NFS client, it is highly relevant to NFS infrastructure:

  1. Container Support: Eliminating the /proc dependency enables NFS server daemons (mountd, exportd) to run in containers where /proc access may be restricted or undesirable.
  2. Extensibility: The netlink-based interface simplifies adding new export options without modifying pipe protocols — a long-standing pain point for nfsd developers. Layton noted:

"Note that the export-flags and xprtsec-mode enums are organized to match their counterparts in include/uapi/linux/nfsd/export.h. The intent is that future export options will only be added to the netlink headers, which should eliminate the need to keep so much in sync." — Jeff Layton

  1. Companion Userspace Work: A companion patchset for nfs-utils adds support in mountd, exportd, and exportfs, with /proc fallback for older kernels.
