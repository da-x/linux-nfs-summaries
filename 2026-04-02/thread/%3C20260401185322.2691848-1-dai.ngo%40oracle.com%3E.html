NFS Client Fix: Don't Trust Server Inode Size During Write Delegations

Summary

NFS Client: Fix Inode Size Trust During Write Delegations

Overview

This week, Oracle engineer Dai Ngo submitted a targeted bug fix addressing a subtle correctness issue in the NFS client's handling of inode metadata when holding write delegations. The patch resolves a scenario where the client incorrectly overwrites its locally cached file size with stale server-reported values.

Technical Context: Write Delegations and Metadata Caching

NFSv4 write delegations allow a client to buffer writes and associated metadata updates—including file size changes—locally, deferring propagation to the server. This optimization reduces network round-trips but introduces a window during which the server's view of the file's state is inherently stale.

As Dai Ngo explained in the patch description:

"With a write delegation, the server permits the client to buffer writes and associated metadata updates (including file size changes) locally and defer propagating them to the server. As a result, the server-reported GETATTR size may legitimately lag behind the client's cached size for the duration of the delegation, so it must not be treated as authoritative."

The Bug

The issue resides in nfs_wcc_update_inode, which is responsible for updating cached inode attributes based on Weak Cache Consistency (WCC) data returned by the server after operations. Previously, this function unconditionally updated the cached inode size from server-reported values, even when the client held an active write delegation. This could cause the client to overwrite its correct, locally-updated file size with a stale value from the server, leading to inconsistent metadata visible to user-space applications.

The Fix

The patch modifies nfs_wcc_update_inode in fs/nfs/inode.c to add a guard condition: the cached inode size is updated from server data only when either:

  1. The client does not hold a write delegation on the file, or
  2. The cache_validity flags of the nfs_inode have the NFS_INO_INVALID_SIZE bit set (indicating that the cached size is already known to be invalid and must be refreshed).

This ensures that while a write delegation is active, the client trusts its own locally-maintained size unless it has explicitly invalidated that cache entry.

Classification

  • Type: Bug fix
  • Component: NFS client (fs/nfs/inode.c)
  • Impact: Prevents incorrect inode size metadata when write delegations are active
