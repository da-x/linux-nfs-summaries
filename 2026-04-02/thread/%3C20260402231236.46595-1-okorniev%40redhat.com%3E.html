NFS client fix: RENAME attribute staleness with directory delegations

Summary

NFS Client Bug Fix: RENAME Attribute Staleness Under Directory Delegations

Overview

This week, Olga Kornievskaia submitted a targeted bug fix for the NFS client addressing a regression introduced by a prior directory delegation verifier improvement. The patch resolves a test failure in xfstest generic/309 caused by stale inode timestamps after rename operations when directory delegations are active.

Classification

This is a bug fix targeting the NFS client's handling of file attribute updates during RENAME operations in the presence of directory delegations. It does not introduce new features or protocol changes.

Background

The root cause traces back to commit 6f9bda2337f8 ("NFS: Fix directory delegation verifier checks"), originally submitted by Anna Schumaker in December 2025. That patch optimized lookup revalidation by treating directory delegations equivalently to having a delegated verifier, reducing unnecessary wire traffic during lookups. However, as Olga Kornievskaia explains in her submission:

"Since commit 6f9bda2337f8 ("NFS: Fix directory delegation verifier checks") xfstest generic/309 is failing because after the rename (mv) operation, client's mtime/ctime is the same." — Olga Kornievskaia

The issue manifests when a directory holds a delegation: after a RENAME (mv) operation, the client's cached mtime and ctime attributes for the affected directory are not updated, leading to stale metadata. This causes xfstest generic/309 — a filesystem test exercising rename behavior — to fail.

The Fix

Olga's patch addresses the issue by ensuring that the delegated mtime is updated during RENAME operations when directory delegations are present:

"Update the delegated mtime when directory delegations are present in rename." — Olga Kornievskaia

The change touches two files:

  • fs/nfs/inode.c (3 lines changed)
  • fs/nfs/nfs4proc.c (1 line added)

Discussion and Review

The thread saw a single message this week — Olga's patch submission. The only response came after the weekly window, when Benjamin Coddington of Hammerspace provided a review acknowledgment:

"Reviewed-by: Benjamin Coddington bcodding@hammerspace.com" — Benjamin Coddington

No further debate or discussion occurred. The fix is straightforward and narrowly scoped, addressing a clear regression with minimal code changes.

Significance for NFS Client Development

This patch highlights the ongoing challenges in maintaining correctness of the NFS client's delegation handling. Directory delegations are a performance-critical feature that allows clients to cache directory metadata locally, reducing server round-trips. However, as this thread demonstrates, ensuring attribute consistency during mutating operations like RENAME requires careful attention. The interplay between verifier checks (optimized by Anna Schumaker's earlier patch) and attribute updates represents a subtle but important correctness boundary in the NFS client codebase.

Conclusion

The patch has been submitted with a Fixes: tag pointing to the offending commit and carries a single Reviewed-by from Benjamin Coddington. It is expected to be merged into the mainline kernel to restore correct behavior for rename operations under directory delegations and to pass the xfstest generic/309 regression test.
