netfs bvecq Series: Reviews and CIFS/kSMBD Integration Conflicts

Overview

Following the submission of David Howells' 26-patch series last week to replace folio_queue with segmented bio_vec[] chains (bvecq) in netfslib, this week's activity focused on two fronts: (1) formal reviews from Paulo Alcantara, and (2) integration conflict reports from Stefan Metzmacher regarding the CIFS/ksmbd tree.

This discussion centers on a major feature/refactoring of the network filesystem library with embedded bug fixes. While the NFS client itself is not directly modified in these patches, the changes to netfslib and cachefiles affect all network filesystems (including NFS) that leverage this infrastructure for buffered I/O and fscache operations.

Stefan Metzmacher's Integration Concerns

Stefan Metzmacher raised critical integration issues on March 29 regarding conflicts between Howells' CIFS patches and the ksmbd-for-next tree, which is maintained separately and rebased frequently.

Conflict with ITER_KVEC Removal

Regarding Patch 19/26, which removes support for ITER_KVEC/BVEC/FOLIOQ from smb_extract_iter_to_rdma(), Metzmacher pointed out that the ksmbd server still requires ITER_KVEC:

"in ksmbd-for-next smbdirect_map_sges_from_iter is also called in the server from smb_direct_writev() => smbdirect_connection_send_iter() => smbdirect_connection_send_single_iter(). So we still need ITER_KVEC." — Stefan Metzmacher

This highlights a tension between the CIFS client's migration away from legacy iterator types and the ksmbd server's continued reliance on them for SMB Direct RDMA operations.

Code Sharing and Rebasing Challenges

For Patch 17/26, which adds ITER_BVECQ support to the CIFS RDMA extraction, Metzmacher noted:

"this conflicts with my patches in ksmbd-for-next where we have this as smbdirect_map_sges_from_iter and shared between client and server. Can you rebase on ksmbd-for-next?" — Stefan Metzmacher

Proposed Resolution Paths

In his overview response, Metzmacher outlined several potential strategies to resolve the integration conflict:

"Maybe we should have a fixed non rebased branch for the smbdirect.ko patches in ksmbd-for-next, so that David can rebase on that. Or should Steve put this also into ksmbd-for-next? Another possible way would be to skip this for now cifs: Remove support for ITER_KVEC/BVEC/FOLIOQ from smb_extract_iter_to_rdma() and I rebase my changes on top of Davids patches assuming they will be stable commits."

This remains an open discussion point, with no definitive resolution reached within this week's window.

Key Bug Fixes Reviewed This Week

The reviewed patches address several important correctness issues:

  1. NULL pointer dereference in unbuffered write retry (Patch 01/26): Fixed a crash when stream->prepare_write is NULL on retry, affecting filesystems like 9P.
  2. Kernel BUG for ITER_KVEC iterators (Patch 02/26): Resolved a crash during core dump writes to 9P by adding proper handling for ITER_KVEC in netfs_limit_iter().
  3. VM_BUG_ON_FOLIO race condition (Patch 03/26): Fixed an unconditional folio_unlock() that triggered assertions when folios were already unlocked, reproducible via xfstests generic/013.
  4. Read abandonment during retry (Patch 05/26): Corrected a stale pointer issue causing all remaining subrequests to be abandoned.
  5. Excess dput() in cachefiles (Patch 07/26): Fixed a reference counting bug that could lead to use-after-free on directory entries.

Conclusion

This week's activity confirmed broad support for the bvecq refactoring through Paulo Alcantara's comprehensive reviews, while surfacing a practical integration challenge with the ksmbd tree raised by Stefan Metzmacher. The core tension revolves around whether CIFS and ksmbd should share RDMA iterator code, and how to manage the transition away from legacy iterator types (ITER_KVEC, ITER_BVEC, ITER_FOLIOQ) when the server-side ksmbd still depends on them.

For NFS client developers, the most immediate takeaway is that the embedded bug fixes in this series strengthen the reliability of netfslib and cachefiles, which underpin NFS fscache operations. The resolution of the CIFS/ksmbd integration conflict will determine whether the series can be merged as-is or requires adjustments to preserve backward compatibility for shared SMB Direct code paths.
