libtirpc: Fix bindresvport build with clang-22/C23

libtirpc: Fix bindresvport Build with clang-22/C23

Classification

Bug fix / Build compatibility patch

Summary

This week, Khem Raj submitted a minimal but targeted patch to address a build failure in libtirpc when compiled with modern toolchains. The issue arises from legacy C code syntax that is no longer accepted by clang-22 when operating in GNU23 (C23) mode.

Technical Details

The root cause of the build breakage was identified in the bindresvport() function, which was defined using old K&R-style function syntax. This pre-ANSI C style, where parameter types are declared after the argument list, has been deprecated for decades and is explicitly rejected by stricter modern compilers.

Khem Raj's patch converts the function definition to a modern prototype-style definition, restoring compatibility without altering any runtime behavior. As Khem Raj noted in the commit message:

"Convert it to a prototype-style definition. This is a no-op change intended only to restore compatibility with modern C compilers." As mentioned by Khem Raj

The patch modifies a single file (src/bindresvport.c), removing three lines and adding one, reflecting the straightforward nature of the fix.

Context for NFS Development

While this thread is brief and contains only a single message with no further discussion this week, it highlights an ongoing maintenance burden for NFS infrastructure components. libtirpc (Transport Independent RPC library) is a critical dependency for NFS clients and servers in userspace. Ensuring that such foundational libraries compile cleanly with the latest compiler versions (clang-22) and language standards (C23) is essential for distribution maintainers and embedded Linux developers who rely on up-to-date toolchains.

This type of "build hygiene" fix, while small, prevents downstream breakages in Yocto, Buildroot, and other build systems that are increasingly adopting newer compiler defaults.
