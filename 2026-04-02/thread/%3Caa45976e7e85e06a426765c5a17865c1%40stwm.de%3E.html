nfsd: Diagnosing nfsd_file Slab Cache Leak on Shutdown

Summary

This week, Wolfgang Walter reported a kernel BUG occurring during the shutdown of an NFS server running vanilla stable kernel 6.18.19. The issue manifests as a slab cache error when nfsd attempts to destroy its file cache, indicating that objects were not properly released.

The Bug Report

Wolfgang Walter described encountering the following BUG almost every time he rebooted his NFS server:

"BUG nfsd_file (Not tainted): Objects remaining on __kmem_cache_shutdown()"

The stack trace pointed directly to nfsd_file_cache_shutdown calling kmem_cache_destroy, which failed because the nfsd_file slab cache still contained allocated objects. This is a critical resource leak in the NFS server (nfsd) subsystem, where file references are not being dropped before module unload or service termination.

Diagnosis and Root Cause

NFS maintainer Chuck Lever quickly identified the likely culprit. He suggested that Wolfgang's kernel might be missing a specific fix for a reference counting leak:

"Perhaps your kernel is missing commit 8072e34e1387 ("nfsd: fix nfsd_file reference leak in nfsd4_add_rdaccess_to_wrdeleg()")." Chuck Lever

Resolution and Context

Wolfgang confirmed that the patch in question is included in stable kernel 6.18.20 (as commit c07dc84ed67c). He provided the full commit message, which details the technical root cause:

The bug originates in nfsd4_add_rdaccess_to_wrdeleg(). This function unconditionally overwrites fp->fi_fds[O_RDONLY] with a newly acquired nfsd_file. However, if the client already had a SHARE_ACCESS_READ open from a previous operation, this overwrite discarded the existing pointer without releasing its reference, effectively orphaning it.

Furthermore, the interaction between delegation cleanup (put_deleg_file) and access counting (nfs4_file_put_access) meant that if another READ open existed on the file, the reference counter would remain elevated. Consequently, the nfsd_file reference from the delegation was never released.

"Then, on server shutdown, these leaks cause __nfsd_file_cache_purge() to encounter files with an elevated reference count that cannot be cleaned up, ultimately triggering a BUG() in kmem_cache_destroy() because there are still nfsd_file objects allocated in that cache." Wolfgang Walter

Conclusion

This thread highlights a significant bug fix for NFS server stability. The leak of nfsd_file references prevents clean shutdowns and triggers kernel warnings/BUGs due to slab cache inconsistencies. Users running kernels prior to the inclusion of commit 8072e34e1387 (upstream) or its stable backports are advised to upgrade to avoid this issue, particularly in environments where write delegations and read accesses coexist on the same files.
