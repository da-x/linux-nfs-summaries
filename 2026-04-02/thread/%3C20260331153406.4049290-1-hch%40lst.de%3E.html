Cleanup of block-style layout exports in preparation for multi-device support

Summary

Christoph Hellwig posted a four-patch series titled "cleanup block-style layouts exports" to refactor the exportfs support for pNFS block-style layouts. The primary motivation is to prepare the kernel for supporting exports of more than one device per filesystem, while also improving code layering and clarity.

Patch 1: Ignore loca_time_modify in Block Layouts

The first patch explicitly ignores the client-provided loca_time_modify timestamp in NFSv4 block layout commits. Christoph Hellwig noted that RFC 8881 Section 18.42 defines this as a "may" condition, and clients requiring specific timestamps should use a separate SETATTR. Since XFS (the only filesystem currently supporting block layout exports) uses multi-grain timestamps and ignores ia_mtime from setattr_copy, the patch makes this behavior explicit in NFSD.

Jeff Layton reviewed the patch, noting:

"Technically, these fields are completely ignored by notify_change, unless their counterpart ATTR_?TIME_SET flag is set, so you could just leave them unset."

Christoph later clarified that for non-multi-grain timestamp filesystems, the assignment remains necessary because the path does not go through notify_change. He also raised a broader question about time sampling:

"Btw, shouldn't we move the actual time sampling from notify_change into ->setattr for non-mgtime file systems to avoid the extra sampling in notify_change for the mgtime fast path?"

Patch 2: Split Block Layout Operations

This patch separates block layout operations into a new exportfs_block_ops structure and a dedicated header (include/linux/exportfs_block.h). This improves layering by preventing exportfs.h from pulling in unnecessary includes for block layout inline helpers.

Jeff Layton offered a measured review:

"Meh, ok. Almost doesn't seem worthwhile, but I guess the result is a bit cleaner layering-wise."

Chuck Lever suggested that the xfs_export_block_ops structure should be declared const, to which Christoph agreed:

"Probably. If something doesn't support that right now I'll need to fix it."

Patch 3: Simplify commit_blocks Interface

The third patch simplifies the ->commit_blocks callback by removing the struct iattr argument, passing only the new size (with a magic value indicating no change). This reduces complexity in the block layout commit path.

Jeff Layton suggested folding Patch 1 into this one, arguing that Patch 3 makes the timestamp handling in Patch 1 moot. Chuck Lever disagreed:

"Disagree: I think the change in the first patch needs its own patch description and motivation."

Christoph Hellwig defended keeping them separate, emphasizing documentation value:

"The big fat comment is still left. The first patch is mostly intended as clearly documenting what we're doing. There is no behavior except for sampling the current time more often in it anyway."

Patch 4: Rework Layout Support Checks

The final patch moves the checks for block layout support from hardcoded NFSD logic into filesystem helpers and a new exportfs-level helper. This abstraction facilitates future multi-device export support.

Jeff Layton praised the change:

"Much cleaner."

Chuck Lever identified a typo in the patch (exporfs_layouts_supported instead of exportfs_layouts_supported), which Christoph acknowledged would be fixed.

Merge Path Discussion

Chuck Lever asked how the series should be merged, given its cross-subsystem nature (NFS and VFS/exportfs):

"How do you see this getting merged? Do you want all of these patches to go through the NFS tree? Or do you want this to go through VFS?"

Christoph Hellwig responded:

"I don't really care. But I traditionally see exportfs as a nfsd domain, even despite the added other uses of it."

Chuck Lever noted that recent exportfs changes had gone through Christian Brauner's trees but confirmed he was willing to take the series via the NFS tree if preferred.

Conclusion

The series received Reviewed-by from Jeff Layton on all four patches. The discussion concluded with agreement on the technical approach, with minor adjustments (const correctness, typo fixes) expected in the final submission. The series is poised for merge via the NFS tree, continuing the cleanup of pNFS block layout infrastructure.
