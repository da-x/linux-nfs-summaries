lockd TEST fix: Backporting strategy clarified for nfsd-testing and LTS kernels

Summary

lockd TEST Fix: Backporting Strategy Clarified for nfsd-testing and LTS Kernels

Classification: Bug Fix (NFS Server / lockd Permission Checks) — Maintenance Discussion

Bridge from Prior Weeks

This thread continues the resolution of a regression in the NFS server's lockd subsystem, originally reported as a failure of F_GETLK (lock testing/querying) for read-only file descriptors after commit 4cc9b9f2bf4d ("nfsd: refine and rename NFSD_MAY_LOCK"). Neil Brown submitted Patch v2 to fix the bug by introducing O_RDWR as a mode for nlm_do_fopen(), allowing lock tests to succeed with either read or write access. The patch received positive reviews and was accepted in principle.

Last week, Chuck Lever raised a logistical concern: the patch, as written for upstream, would not apply cleanly to the nfsd-testing branch due to an NLMv4 XDR generation rewrite that altered code structure. This created a two-track maintenance challenge, as the rewrite is unlikely to be backported to LTS kernels, meaning automated backporting tools could not handle the fix for kernels v6.19 and earlier.

This Week's Activity: Clarified Backporting Path

This week saw two messages resolving the ambiguity around how to proceed with the backporting process.

Uwe Kleine-König's Acknowledgment

Uwe Kleine-König replied to Chuck Lever's previous message, acknowledging the situation. While the full body of his message was largely a quote of Chuck's prior concerns, he concluded with:

"helps."

This indicates agreement or understanding of the backporting complications outlined last week.

Chuck Lever's Clarified Request

Chuck Lever followed up to explicitly clarify what action is needed from Neil Brown:

"Sorry I wasn't clear. Neil and I have also been down this road before so I wasn't explicit about my request."

"I'd like Neil to provide a patch for upstream against nfsd-testing. Once that is merged, he can present the patch from this thread to the stable/LTS maintainers."

This message establishes a clear two-step path forward:

  1. Upstream Merge: Neil Brown should submit a version of the fix against the nfsd-testing branch for upstream inclusion.
  2. Stable/LTS Submission: After the upstream merge, Neil can present the patch from this thread (the version applicable to pre-nfsd-testing kernels) directly to the stable and LTS maintainers.

Key Technical Arguments

  1. Two-Track Maintenance Due to Code Divergence: The NLMv4 xdrgen rewrite in nfsd-testing creates a structural mismatch that prevents mechanical backporting. This necessitates separate patch variants for upstream and LTS kernels.

  2. Manual Stable Submission Required: Chuck Lever emphasizes that automation cannot handle this backport, requiring Neil Brown to manually coordinate the submission process after the upstream merge.

  3. Precedent Exists: Chuck notes, "Neil and I have also been down this road before," indicating this is a recurring pattern in NFS server development where testing branch divergences complicate stable backporting.

Final Conclusions

  • Backporting Strategy Established: The path forward is now clear: upstream merge via nfsd-testing first, followed by a direct submission to stable/LTS maintainers for older kernels.
  • No Changes to Patch Content Indicated: The technical fix itself remains sound; the discussion focused solely on the logistical process of getting it into the appropriate kernel trees.
  • Action Item for Neil Brown: Neil is expected to prepare and submit the nfsd-testing-compatible patch for upstream merge, after which he will handle the stable tree submission.
