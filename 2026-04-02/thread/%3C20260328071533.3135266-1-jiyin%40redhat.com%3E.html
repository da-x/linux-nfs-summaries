pynfs: Python 3 Compatibility Fixes and NFSv4.2 Mount Support

Summary

pynfs Test Framework: Python 3 Compatibility and NFSv4.2 Support Fixes

This week, Jianhong Yin submitted a four-patch series (v3) to modernize the pynfs test framework — the user-space NFS server implementation used for regression testing of Linux NFS client behavior. The patches address long-standing Python 2/3 compatibility issues, fix runtime errors on newer Python versions, and enable NFSv4.2 protocol support in the test harness. This is primarily a bug-fix and maintenance effort for the testing infrastructure rather than kernel code changes, but it directly impacts the reliability of NFS client validation.

Patch 1: Broad Python 3 String/Bytes Fixes in nfs4server.py PATCH v3 1/4

The largest patch, originally authored by Scott Mayhew and carried forward by Jianhong Yin, addresses the fundamental type mismatch between Python 2 str (which was bytes) and Python 3 str (which is Unicode). As the commit message explains:

"Most of the strings in pynfs are not str but rather 'bytes' objects."

The patch systematically converts across eight files (config.py, dataserver.py, fs.py, nfs4client.py, nfs4server.py, nfs4state.py, ds_exports.py, and server_exports.py), making the following key changes:

  • Replacing plain string literals "string" with byte-string literals b"string"
  • Adding .encode("utf-8") calls where appropriate
  • Swapping StringIO for BytesIO
  • Correcting nfsstat4 references to use the proper module path const4.nfsstat4
  • Fixing Python 3 exception syntax
  • Replacing the deprecated d.itervalues() with d.values()

This patch touches 129 insertions and 120 deletions, representing a significant cleanup of the test framework's codebase.

Patch 2: Resolving SQLite Threading Error on Python 3.12+ PATCH v3 2/4

This patch addresses a specific runtime failure encountered with Python 3.12 and later, where the shelve module's default SQLite backend throws a threading error:

"sqlite3.ProgrammingError: SQLite objects created in a thread can only be used in that same thread."

The fix forces the use of gdbm as the backend for the shelve module, avoiding the multi-threading incompatibility. The patch notes that it has been tested and passes on RHEL-9, RHEL-10, and Fedora-43.

Patch 3: Enabling NFSv4.2 Mount Support PATCH v3 3/4

A minimal one-line change that allows the pynfs test server to accept NFSv4.2 mounts, expanding the protocol coverage of the test harness beyond v4.1. This is a small but meaningful enhancement for testing newer NFS client features.

Patch 4: Fixing Type Errors in nfs4proxy.py PATCH v3 4/4

This final patch applies similar byte-string fixes to the NFS proxy test component (nfs4proxy.py), addressing:

  • String literal conversions from "string" to b"string"
  • Python 3 identity comparison corrections (replacing is with ==)

The patch confirms successful testing on RHEL-9, RHEL-10, and Fedora-43.

Discussion Evolution and Conclusions

This thread consisted solely of the initial v3 patch submission — there were no replies or further discussion within this week's window. The series represents a matured effort (having progressed through at least two prior versions) to ensure the pynfs test framework remains functional on modern Python 3 environments, particularly Python 3.12+.

The key takeaway is that these are critical infrastructure fixes: without them, the NFS client regression test suite would fail on contemporary distributions shipping Python 3.12+, undermining confidence in NFS client development and validation. The inclusion of NFSv4.2 mount support also extends the testing surface for newer protocol features.
