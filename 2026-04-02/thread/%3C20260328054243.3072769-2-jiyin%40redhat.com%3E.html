pynfs: Python 3 Compatibility and NFSv4.2 Mount Fixes (PATCH v3)

Overview

This week, Jianhong Yin submitted a four-patch series ([PATCH v3]) targeting the pynfs test infrastructure — specifically the NFSv4.1 server implementation (nfs4.1/nfs4server.py and related modules). The series is primarily focused on bug fixes to restore Python 3 compatibility, resolve threading issues with newer Python versions, and enable NFSv4.2 mounts in the pynfs test harness. These changes are critical for maintaining a functional NFS client/server testing environment on modern Linux distributions such as RHEL-9, RHEL-10, and Fedora-43.

Patch Breakdown

Patch 1/4: Core Python 3 String and Syntax Fixes PATCH v3 1/4

Authored originally by Scott Mayhew, this patch addresses widespread Python 2 vs. Python 3 incompatibilities across eight files in the pynfs nfs4.1/ directory. The core issue is that NFS protocol data uses byte strings rather than Unicode strings:

"Most of the strings in pynfs are not str but rather 'bytes' objects."

Key changes include:

  • Converting string literals from "string" to b"string" and adding .encode("utf-8") where needed.
  • Replacing StringIO with BytesIO.
  • Updating nfsstat4 references to use the proper module path const4.nfsstat4.
  • Fixing Python 3 exception handling syntax.
  • Replacing deprecated d.itervalues() with d.values().

This patch touches 8 files with 129 insertions and 120 deletions, making it the most substantial change in the series.

Patch 2/4: Resolving SQLite Threading Error on Python 3.12+ PATCH v3 2/4

This patch forces the use of gdbm as the backend for Python's shelve module to avoid a threading-related error introduced in newer Python versions:

"sqlite3.ProgrammingError: SQLite objects created in a thread can only be used in that same thread."

The fix modifies nfs4.1/fs.py and has been verified to pass tests on RHEL-9, RHEL-10, and Fedora-43.

Patch 3/4: Enabling NFSv4.2 Mounts PATCH v3 3/4

A minimal one-line change to nfs4.1/nfs4server.py that allows the pynfs server to accept NFSv4.2 mount requests, expanding the test coverage to include newer protocol features.

Patch 4/4: Proxy Module Fixes PATCH v3 4/4

This patch applies similar Python 3 compatibility fixes to nfs4.1/nfs4proxy.py:

  • Converting string literals to byte strings ("string" → b"string").
  • Replacing identity comparisons (is) with equality checks (==).

Tests were confirmed passing on RHEL-9, RHEL-10, and Fedora-43.

Testing Evidence

In a follow-up message Re: PATCH v3 1/4, Jianhong Yin provided detailed test logs demonstrating a successful NFSv4.2 mount with pNFS enabled:

mount.nfs: trying text-based options 'vers=4.2,addr=127.0.0.1,clientaddr=127.0.0.1'
127.0.0.1:/ on /mnt/nfsmp type nfs4 (rw,relatime,vers=4.2,...)
nfsv4: ... pnfs=LAYOUT_NFSV4_1_FILES,lease_time=60,lease_expired=0

The test script launches both a metadata server (MDS) and a data server (DS) via tmux, mounts the share with vers=4.2, writes and reads files across both pnfs-managed and non-pnfs paths, and verifies correct behavior — confirming that the pynfs infrastructure now functions correctly under modern Python 3 environments.

Conclusion

This patch series represents essential maintenance work for the pynfs NFS testing framework. By resolving Python 3 compatibility issues, fixing a critical threading bug on Python 3.12+, and enabling NFSv4.2 mounts, these changes ensure that the Linux NFS community can continue to rely on pynfs for validating client and server behavior across current and future kernel releases. The discussion is purely focused on bug fixes with no new feature introductions or protocol changes.
