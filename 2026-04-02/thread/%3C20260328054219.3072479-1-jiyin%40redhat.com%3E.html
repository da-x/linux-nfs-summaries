Summary

pynfs: Python 3 Compatibility Fixes for NFSv4.1 Test Infrastructure

This week, a patch series landed on the list aimed at modernizing the pynfs test framework — specifically the NFSv4.1 server components — to ensure compatibility with Python 3. The effort is classified as a bug fix / maintenance update rather than a new feature or protocol change.

Patch Overview

Jianhong Yin submitted PATCH 1/4, authored by Scott Mayhew, which addresses several Python 3 incompatibilities in the pynfs NFSv4.1 server codebase. The commit message outlines the core issues:

"Most of the strings in pynfs are not str but rather 'bytes' objects."

The patch series resolves this by:

  • Converting default string literals from "string" to b"string" (byte strings)
  • Applying .encode("utf-8") where appropriate
  • Replacing StringIO with BytesIO
  • Correcting namespace references such as nfsstat4 → const4.nfsstat4
  • Fixing Python 3 exception handling syntax
  • Updating deprecated iterator methods: d.itervalues() → d.values()

Eight files were modified across the NFSv4.1 test infrastructure, including config.py, dataserver.py, fs.py, nfs4client.py, nfs4server.py, nfs4state.py, and export-related modules. The net change was 129 insertions and 120 deletions.

Significance for NFS Client Development

While this patch does not directly modify the Linux NFS client kernel code, it is critical for the test infrastructure used to validate NFS client behavior. The pynfs framework serves as a reference NFSv4.1 server implementation against which Linux NFS clients are tested. Ensuring its Python 3 compatibility is essential for maintaining reliable regression testing and protocol conformance verification.

Current Status

As of this week's window, only the first patch in the four-patch series was posted. No replies or further discussion occurred within the current timeframe. The remaining three patches in the series have not yet appeared on the list.
