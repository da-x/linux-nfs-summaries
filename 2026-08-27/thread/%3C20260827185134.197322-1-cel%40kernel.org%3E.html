NFSD drops shared NFS trace helpers to unblock xdrgen nfserr.h

Summary

This is a header-hygiene / preparatory refactor, not a protocol change and not a runtime bug fix. Chuck Lever posted a one-patch series on 27 August that stops NFSD tracing from including include/trace/misc/nfs.h. The goal is to keep upcoming xdrgen-generated NFSD status headers from colliding with the client-oriented NFS enumerators that header currently drags in. There were no replies in this window.

Why the shared trace header is a problem

Today fs/nfsd/trace.h pulls in include/trace/misc/nfs.h only because it wants two TRACE_DEFINE_ENUM helpers: show_nfs4_seq4_status() and show_rca_mask(). Lever’s cover letter is blunt about the collateral damage:

"That header pulls in linux/nfs.h, so every NFSD translation unit that reads trace.h also sees the NFS_OK, NFSERR_*, and file-type enumerators."

Those names live in the mixed UAPI enum nfs_stat / file-type tables that both the in-kernel NFS client and server have historically treated as a convenient soup of on-the-wire constants. That is the client-development angle this week: the shared tracing helper is a client-side header (include/trace/misc/nfs.h) that NFSD has been using as a shortcut, and that shortcut leaks client UAPI enumerators into every NFSD C file that includes tracing.

The leak is about to become a hard compile failure. Lever is staging an xdrgen conversion of fs/nfsd/nfserr.h:

"I'm about to switch fs/nfsd/nfserr.h to an xdrgen-generated header, which defines enum nfsstat and enum ftype with those same names. Any translation unit that includes both headers then fails to build with enumerator redefinition errors."

That conversion is the next step after yesterday’s nfserr respell, which already stopped wrapping version-agnostic NFSERR_* names and imported a dedicated NFS3ERR_* table into the shared linux/nfs3.h. This patch is the tracing counterpart: isolate NFSD’s TRACE_DEFINE_ENUM helpers so the generated enum nfsstat / enum ftype can land without fighting linux/nfs.h.

What the patch actually does

NFSD: Replace the use of include/trace/misc/nfs.h is a 67-line diff with a concentrated footprint:

  • fs/nfsd/trace.h: +44 lines. The two helpers that used to come from the shared header are copied into the NFSD-private tracing header, so server TUs no longer need trace/misc/nfs.h at all.
  • include/trace/misc/nfs.h: −22 lines. The NFSD-only show_nfs4_seq4_status() and show_rca_mask() definitions are removed from the shared file.

Lever’s operational conclusion is a one-liner:

"To address this, stop including trace/misc/nfs.h in fs/nfsd/trace.h."

There is no change to NFS wire format, no change to NFSD’s on-the-wire status numbers, and no change to client I/O paths. The TRACE_DEFINE_ENUM pretty-printers that ftrace/perf already use for NFSv4 sequence status bits and recallable-state masks stay available; they just live next to the NFSD events that consume them instead of in a client-shared header that also #includes linux/nfs.h.

Client vs. server, and what is not in this patch

  • Kind of change: preparatory compile-time isolation for xdrgen. No NFS protocol change. No functional bug fix. No client or server I/O path change.
  • Client impact this week: indirect but real. include/trace/misc/nfs.h is a client-facing tracing helper. Removing the two NFSD-only macros from it shrinks the shared surface and, more importantly, stops NFSD from transitively including linux/nfs.h via tracing. Client TUs that still include trace/misc/nfs.h for their own events are unaffected; they already wanted those UAPI enumerators. What goes away is the accidental coupling that made every NFSD file that enabled tracing also see NFS_OK / NFSERR_* / file-type names.
  • Server impact: fs/nfsd/trace.h becomes self-contained for the two pretty-printers. After this lands, NFSD tracing no longer depends on the client UAPI header, which is the prerequisite for swapping nfserr.h onto an xdrgen-generated enum nfsstat / enum ftype without enumerator-redefinition build breaks.
  • Not included: the actual xdrgen-generated nfserr.h. Lever only announces that conversion (“I’m about to switch…”). This patch is the tracing unblocker, not the generator change itself.
  • Review status: Lever is the only participant. No Reviewed-by, Acked-by, or nits this window.

Until reviewers weigh in, the patch sits as unacked infrastructure on the same xdrgen runway as the 26 August nfserr respell: peel NFSD off the mixed linux/nfs.h namespace so generated, spec-based status and file-type enums can replace it without colliding with client tracing helpers.
