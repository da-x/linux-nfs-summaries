Chuck Lever splits two NFSD COMPOUND teardown bugs for different LTS paths

Summary

Summary

This is a bug-fix series, not a protocol change and not NFS client code. On 24 August, Chuck Lever posted two NFSD patches that repair COMPOUND argument teardown: an unprivileged out-of-bounds read in the rpc_status netlink dump, and a POSIX ACL leak when a decoded NFSv4 operation never runs. Both defects were originally reported by Prabhakar Pujeri of Dell in a single combined patch; Lever split them because they need different stable routing. There were no replies in this window.

The client-visible angle is indirect but real. A remote NFSv4 client can force the ACL leak by repeating an aborting COMPOUND, and a local unprivileged user can race the netlink dump against a busy server. Neither patch touches fs/nfs/; both sit in fs/nfsd/.

Why they were split

Lever’s cover letter is explicit about LTS policy:

"They are split here because they need different LTS routing. The rpc_status dump requires no privilege and is present in a default build. NFSv4 POSIX ACL support is experimental and disabled by default, so the ACL-related fix is mainline-only."

He also rejected two pieces of Pujeri’s original approach after review. On the leak:

"In the original proposed fix, the decoder leaves the only reference to a decoded ACL in the operation's argument structure, and the executing operation transfers that reference to struct nfsd_attrs. This is the root cause of leak, so my proposal is to address that instead."

On the OOB:

"After close review, I determined that the argp->opcnt assignments address a problem that is currently unreachable. Instead, my fix is to block the OOB buffer read during the rpc_status dump."

That is the whole discussion this week: a maintainer rewrite of a reporter’s combined patch, with no Acked-by or review comments yet.

Patch 1/2: unprivileged OOB in rpc_status dump

Patch 1 is the one that wants stable. nfsd_nl_rpc_status_get_dumpit() loads args->opcnt and args->ops separately, then walks ops[] before rechecking rq_status_counter. If a COMPOUND finishes between those two loads, nfsd4_release_compoundargs() zeroes opcnt and points ops back at the eight-entry inline array. A dump that already sampled an opcnt of 200 clamps it to the sixteen slots in rq_opnum and then indexes iops[0..15]. Because iops is the last member of struct nfsd4_compoundargs and rq_argp is allocated at exactly that size, the walk runs off the end of the allocation. The trailing counter recheck discards the sampled data, but the read has already happened.

The security note is the reason this is not mainline-only:

"NFSD_CMD_RPC_STATUS_GET carries no GENL_ADMIN_PERM, so an unprivileged local user can repeat the dump against a busy server until it lands in the window."

Lever’s fix samples opcnt and ops into locals, then finishes the counter recheck before dereferencing ops. An unchanged counter means both values came from the same COMPOUND, where opcnt cannot exceed what ops holds. That is a TOCTOU close, not a change to how COMPOUNDs are decoded. Fixes bd9d6a3efa97 ("NFSD: add rpc_status netlink support"). One file: fs/nfsd/nfsctl.c.

Patch 2/2: POSIX ACL leak on unexecuted COMPOUND ops

Patch 2 is the experimental-feature leak. nfsd4_decode_fattr4() allocates POSIX ACLs while decoding OP_OPEN, OP_CREATE, and OP_SETATTR, and leaves the only reference in the operation’s argument structure. Execution hands that reference to struct nfsd_attrs, which drops it. If the op is decoded but never executed, the ACLs leak. Lever’s commit message states the client-triggered DoS plainly:

"A client can repeat an aborting compound to force the server to leak memory."

His ownership model is the opposite of “transfer the only pointer”:

"Give struct nfsd_attrs its own reference with posix_acl_dup() so nfsd_attrs_free() still balances the reference the operation took."

The decoder now records each ACL on the compound’s temporary allocation chain, and each chained item gets an optional release callback. The chain holds a reference for the life of the compound, so OP_OPEN no longer needs an op_release method. Fixes 5fc51dfc2eb1 ("NFSD: Add support for XDR decoding POSIX draft ACLs"). Tagged Cc: stable+noautosel@kernel.org with the comment “experimental, disabled by default.” Files: fs/nfsd/nfs4proc.c, fs/nfsd/nfs4xdr.c, fs/nfsd/xdr4.h.

Client impact, without client patches

There is no NFS client development in this thread. The client still matters as the attacker and as the party that sees the fallout:

  • A malicious or buggy NFSv4 client that aborts COMPOUNDs after XDR decode (OPEN/CREATE/SETATTR with POSIX draft ACLs) can grow server memory until the export is unusable. That path is off unless the experimental NFSv4 POSIX ACL decoder is enabled.
  • A local unprivileged process on the server can spray NFSD_CMD_RPC_STATUS_GET against a busy nfsd and hit the OOB window. That path is on in a default build and needs no CAP_SYS_ADMIN.
  • Ordinary NFS mounts do not change protocol, mount options, or client recovery. The client-side takeaway is “do not expect a client workaround”; the server must own teardown.

Where things stand

  • Kind of change: two NFSD bug fixes for COMPOUND argument teardown. No protocol change. No fs/nfs/ patches.
  • No review this window. Lever posted the cover letter and both patches; nobody replied.
  • Routing is already decided by the author: patch 1 is the LTS candidate (unprivileged, default-on netlink dump); patch 2 is mainline-only because POSIX draft ACL decode is experimental and off by default.
  • Pujeri’s combined patch is superseded, not merged. Lever kept the reports (Reported-by / Closes) and replaced both proposed fixes with root-cause changes: snapshot-then-recheck for the dump, and a compound-lifetime ACL chain plus posix_acl_dup() for the leak.
  • Until this lands, a busy nfsd remains theoretically OOB-readable via rpc_status, and an aborting client can leak POSIX ACLs on servers that enabled the experimental decoder.

Until reviewers show up, this is a maintainer-posted split of a reporter’s findings, not a concluded merge.
