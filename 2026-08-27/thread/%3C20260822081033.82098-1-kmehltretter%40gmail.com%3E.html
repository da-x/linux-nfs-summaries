NFSD docs: pNFS SCSI Kconfig symbol corrected

Summary

This week's linux-nfs traffic included a small but overdue documentation bug fix for the pNFS SCSI layout server, not a protocol change and not a new feature. The patch landed quickly, with maintainers treating the Kconfig mismatch as an unambiguous documentation error rather than a design debate.

The bug

On 22 August, Karl Mehltretter posted [PATCH] NFSD: docs: Fix pNFS SCSI Kconfig symbol. The change is a one-line edit to Documentation/admin-guide/nfs/pnfs-scsi-server.rst: the admin guide had been telling operators to enable NFSD_SCSI, a symbol that was never present in Kconfig. The real gate for the pNFS SCSI layout server is NFSD_SCSILAYOUT.

Mehltretter's commit message was blunt:

"The pNFS SCSI layout server is controlled by NFSD_SCSILAYOUT. NFSD_SCSI has never existed."

The patch carries Fixes: f99d4fbdae67 ("nfsd: add SCSI layout support"), pinning the stale name all the way back to the original SCSI layout server work. In other words, the documentation has been pointing at a phantom config option since SCSI layouts first appeared in nfsd. The surrounding howto still tells client operators to enable CONFIG_PNFS_BLOCK on the NFS client, so the client-side half of the pNFS SCSI recipe was already named correctly; only the server-side Kconfig token was wrong.

This is documentation hygiene, not a runtime bug in the NFS client. Still, it matters for anyone trying to stand up a pNFS SCSI layout path: a kernel configured with the names in the old guide would never actually build the SCSI layout server, and operators would have no CONFIG symbol matching the documented one.

Review and merge

The thread did not linger. Later the same day, Randy Dunlap — a regular documentation and Kconfig reviewer — signed off without requesting changes:

"LGTM. Thanks. Acked-by: Randy Dunlap rdunlap@infradead.org"

On 23 August, nfsd maintainer Chuck Lever applied the patch to nfsd-testing:

"Applied to nfsd-testing, thanks!"

He recorded it as commit 55a29a459f1a6f9f70fddb8c5a6c94ce02e8d566. That is the effective conclusion of the discussion: the correction is in the nfsd testing tree and queued toward mainline with the rest of the NFSD documentation updates.

A day later, Jeff Layton added a post-merge Reviewed-by. There was no further technical argument, no request for a v2, and no debate about whether the client docs needed a matching change.

Takeaway for NFS client work

For client developers, this is a reminder rather than a code change. pNFS SCSI still depends on CONFIG_PNFS_BLOCK on the client and CONFIG_NFSD_SCSILAYOUT on the server; anyone following the admin guide before this week would have been looking for a server option that never shipped. The client code path is untouched. The practical outcome is that the documented server/client Kconfig pair now matches the symbols that actually exist, which should reduce false starts when bringing up SCSI layouts against a current nfsd.

No follow-ups remain in this thread. The patch is applied; the only outstanding step is the usual promotion from nfsd-testing into the next nfsd pull.
