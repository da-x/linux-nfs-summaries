NFS sysfs kobject UAF fix awaits merge

Summary

This week’s linux-nfs traffic on this thread is a status ping, not new code. The underlying change remains a tightly scoped NFS client bug fix: a use-after-free in the per-netns sysfs kobject lifetime for struct nfs_netns_client. It is not a protocol change and not a feature.

On 27 August, Vasileios Almpanis bounced the 3 August v1 after three weeks of silence:

"Hello everyone, just checking on this patch. It has received required review. Is there anything else needed before it can be merged?"

No maintainer replied in this window. The patch still sits at v1 with a single Reviewed-by.

Brief recap of the bug (week of 3 August)

Almpanis’s original patch targets fs/nfs/sysfs.c. struct nfs_netns_client embeds two kobjects and is freed from nfs_netns_object_release(), the release callback of nfs_net_kobj. The sibling p->kobject lives in the same slab, but nothing pins the allocation until that second kobject has finished releasing:

"struct nfs_netns_client embeds two kobjects and is freed by nfs_netns_object_release(), the release function of nfs_net_kobj. Despite that the first one, p->kobject lives in the same allocation. Nothing keeps the allocation from being freed before p->kobject has been released."

With CONFIG_DEBUG_KOBJECT_RELEASE=y the two releases are deferred independently. nfs_net_kobj can free the object first; p->kobject’s delayed work then fires from freed memory, and KASAN reports a write in __run_timers. The repro is client-side netns churn (unshare -n), not the NFS server. The Fixes: tag points at e96f9268eea6 (NFS: Make all of /sys/fs/nfs network-namespace unique).

The eight-line fix is the classic nested-kobject pattern: take a reference on nfs_net_kobj for the lifetime of p->kobject and drop it from nfs_netns_client_release(), so the allocation is always freed last:

"Give p->kobject a reference on nfs_net_kobj for its whole lifetime and drop it from nfs_netns_client_release(), so the allocation is always freed after p->kobject has been released."

Benjamin Coddington reviewed it the next day with no requested changes:

"Reviewed-by: Benjamin Coddington bcodding@hammerspace.com"

There was no debate over the diagnosis and no v2.

Why the ping matters for NFS client development

The hole is in the client’s /sys/fs/nfs netns glue. Namespace create/destroy is a hot path for containers and test harnesses, and the UAF is real timer-wheel memory corruption; CONFIG_DEBUG_KOBJECT_RELEASE only makes the race deterministic. That makes the patch a candidate for stable once it lands.

This week adds no technical argument and no alternative design. Almpanis’s claim that the patch “has received required review” matches the on-list record (Coddington’s Reviewed-by on v1). What is still missing is maintainer pickup. Until someone queues it, the client sysfs UAF remains unfixed upstream.
