rpcctl Python 3.14 finally-block SyntaxWarning

Summary

Debian kernel team member Salvatore Bonaccorso posted a one-line-class userspace bug fix for tools/rpcctl/rpcctl.py, the RPC control helper that sits alongside the NFS client tooling. The thread is a bug fix, not a protocol change or a new client feature: Python 3.14 now warns on control-flow statements inside finally blocks (PEP 765), and rpcctl tripped that warning.

The report

Bonaccorso's patch credits Trent W. Buck with the original observation:

"Trent W. Buck reported that when using rpcctl with Python 3.14 version, a SyntaxWarning warning is issued on the use of return in the finally block in the read_info_file function."

The warning is not a runtime crash today, but it is a compatibility landmine. Python 3.14 documents the new policy at PEP 765; returning from finally can swallow or rewrite an in-flight exception, which is why the interpreter now flags it. The same issue is tracked as Debian bug 1144982.

The code change

The offending site is read_info_file. Bonaccorso's approach is deliberately small:

"Replace the finally clause with an except BaseException, and dedent the return by one level up."

The patch is five lines in tools/rpcctl/rpcctl.py (3 insertions, 2 deletions). Catching BaseException preserves the original intent of running the cleanup path for any unwind, including KeyboardInterrupt and SystemExit, while moving the return out of a finally so Python 3.14 no longer emits SyntaxWarning. That keeps rpcctl usable as distributions start shipping 3.14 without changing the tool's RPC-pipefs inspection behavior.

This is not an NFS client kernel path, but it does matter for client-side diagnosis: rpcctl is the userspace counterpart that reads RPC pipefs info files. A warning on every invocation is noise that will only get louder as Python 3.14 becomes the default interpreter.

Follow-up and status

About half an hour later, Bonaccorso resent the same patch with a wider To: list:

"Including Anna's oracle.com address."

That is the only evolution this week: the original mail went to linux-nfs, and the follow-up explicitly added Anna Schumaker (NFS maintainer at Oracle) so the userspace tool would not stall in the list's general traffic.

No Acked-by, Reviewed-by, or merge confirmation appeared in-window. The discussion therefore ends as an unacked, Debian-originated compatibility fix waiting on maintainer review. There is no disagreement on the diagnosis; the remaining question is simply whether the except BaseException rewrite is the preferred shape versus a more conservative restructure of read_info_file.

Takeaway for NFS client work

  • Class: userspace bug fix / Python 3.14 compatibility, not a kernel NFS client change.
  • Impact: silences a PEP 765 SyntaxWarning in rpcctl's read_info_file so the helper remains clean on current Python.
  • Open item: maintainer ACK (explicitly pinged via Schumaker's oracle.com address) has not landed this week.
