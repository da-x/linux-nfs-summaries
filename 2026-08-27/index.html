7.3 client pull lands as RDMA READ corruption, xprtrdma hangs, and pNFS decoder bugs pile up

Week ending 2026-08-27

The merge window closed with a real NFS client drop in Linus’s tree, then the list spent the rest of the week on data-integrity and hang bugs that did not make that tag. Trond Myklebust’s 7.3 client pull is in torvalds/linux.git as 73e3f0710014. Same week: silent NFSv3/RDMA READ corruption on a legal short header, an FRWR unmap hang that stalls rpciod, a sleep-in-atomic on the NFSv4 setattr path, and a pair of pNFS GETDEVICEINFO decoder holes (one of them a KASAN SIZE_MAX memcpy).

7.3 client pull: stable bugs plus three features

Trond asked Linus to fetch tags/nfs-for-7.3-1 (34 files, +534/−146 across fs/nfs/, fs/lockd/, net/sunrpc/). Linus merged it and rebuked the tag message as a stable-cc-sorted shortlog: drop the redundant SunRPC: / NFSv4: prefixes, give an overview of what matters, and leave “misc fixes” for the rest.

What actually shipped for the client:

  • Stable-class: SunRPC UAF in __rpc_clnt_handle_event / pipedir teardown; TLS handshake completion race; NFSv4 delegation hash leak on nfs4_server_common_setup() failure; lockd NULL deref on lockowner allocation failure; Tim Menninger’s pNFS layoutreturn sign error (pnfs_layout_need_return() compared against unsigned EBUSY); Junrui Luo’s layout-segment leak on the pnfs_layout_process() forget path.
  • Other correctness: delegation return-on-record-failure; state-manager vs umount; flexfiles clora_changed so an unchanged recall does not cancel in-flight I/O; NFSv4.0 data-server NULL cl_session busy-loop; NFSv3 symlink ENXIO / verify-before-cache.
  • Features that rode along: NFSv4.2 UNCACHEABLE_FILE_DATA (open O_DIRECT when the server marks data uncacheable); NFS/localio inline I/O outside reclaim; flexfiles loosely coupled data servers plus version-keying the DS cache.

Same-week client work that missed the tag: Menninger’s xprtrdma unmap hang, FAN YE’s blocklayout lost wakeup, NeilBrown’s negative-dentry verifier walk, and the RDMA READ corruption fix below.

Critical: NFSv3/RDMA READ prepends 84 bytes of junk

Rakesh Bhargava (NetApp) reported silent payload corruption on a legal NFSv3 READ3resok with attributes_follow = FALSE. The server’s RDMA Write of the file data is correct. The client then smears 84 bytes of recycled receive-buffer contents onto the front of those pages — exactly sizeof(fattr3). Ordinary NFSv3/RDMA mounts typically lose only the first READ (nfs3_read_done() learns read_hdrsize). FlexFiles NFSv3 data servers corrupt every READ, because the layout driver installs its own completion callback and that bookkeeping never runs.

Chuck Lever answered with an RFC then a tightened v2 in rpcrdma_inline_fixup(): shrink the head iovec only when a Write chunk carried the payload, to the inline header bytes received, excluding the responder’s implicit XDR roundup. That leaves the krb5p repair in cb0ae1fbb2f5 alone. Compile-tested; no Reviewed-by yet. Until it lands, NFSv3-over-RDMA — especially FlexFiles DS READs — remains a data-integrity bug.

xprtrdma hang: unmap_sync vs disconnect

Tim Menninger’s FRWR race — frwr_unmap_sync() posts LOCAL_INV after rpcrdma_xprt_disconnect() has drained the QP, then sleeps forever on a CQE — went from v2 nits through v3 (Chuck Lever Reviewed-by) to a v4 kdoc polish. One transport-wide rx_unmap_rwsem, existing request/endpoint objects for lifetime, no inflight counter. Seen on v6.8, v6.18.34, and v7.2-rc6 under pNFS data-server restarts. Not in the 7.3 pull.

A separate, uglier client hang landed late Thursday: Kris Globtrotter reported a NULL indirect call in xs_read_stream_request() on xprtiod. The worker oopses while copying a reply, then exits still holding lock_sock(). Every later RPC piles up in xs_tcp_send_request(); nfs: server not responding against a live server; only a reboot recovers. Five hits in three weeks on a hard NFSv4.2 mount. Untriaged.

Negative dentries: v3 drops i_lock on the NFS verifier walk

Chuck Lever’s xfstests run against NeilBrown’s v2 RFC produced BUG: sleeping function called from invalid context at nfs_clear_verifier_delegated() — the NFSv4 setattr / delegation-return path still held i_lock across the now-might_sleep() d_for_each_positive_child() iterator (v2 thread). Neil posted v3, 11 patches the next day: libfs dropped, fsnotify recalc more conservative, and 08/11 takes i_lock only where needed via d_find_alias(). He hopes this is the last RFC and wants to submit in a couple of weeks. No in-thread review yet. The parallel fsnotify update_children fight is unchanged: Neil will not replace his caller-owned walk with Amir Goldstein’s narrower mark.c tweak.

pNFS client: decoder hardening, SCSI OOB, blocklayout hang, wide stripes

Four independent client pNFS threads, none merged:

  • Dell GETDEVICEINFO hardening (Prabhakar Pujeri, 4 patches, Cc: stable): kstrtou8() for universal-address port octets; bound file-layout and flexfiles multipath loops by remaining XDR so a U32_MAX count cannot spin the decoder for billions of iterations once the stream is exhausted; KUnit suites because no pNFS server was available. Unreviewed.
  • SCSI designator OOB (Jérémy Jean): a GETDEVICEINFO designator_len of 0xffffffff stored as signed becomes −1, bypasses the size check, and turns into SIZE_MAX for xdr_inline_decode() / memcpy(). KASAN on a file read against a hostile NFSv4.1+ MDS. Store as u32, reject before decode. Fixes: the original 2016 SCSI layout client. Unacked.
  • blocklayout lost wakeup (FAN YE): v1 reordered set_current_state() and then hit DEBUG_ATOMIC_SLEEP because rpc_queue_upcall() can dput(). v2 switches bl_wq to a completion (the __cld_pipe_upcall() pattern) and resets stale bl_mount_reply on pipe abort. Synthetic repro only. Same day, Scott Mayhew split Kconfig so SCSI layout can build without block layout / device-mapper — which would compile the pipefs waiter out of SCSI-only kernels.
  • flexfiles device notifications v2 (Benjamin Coddington, 23 patches): live-layout CB_NOTIFY_DEVICEID CHANGE/DELETE, RFC 8881 deletion-race recovery, device-cache scaling to 1024 DSes, plus six stable-bound striped-layout fixes (32-bit stripe_unit truncation, 32-bit read offset, coalescing past stripe boundaries, CB_NOTIFY decoder alignment). Anna Schumaker asked whether stripe_unit should be promoted to u64 rather than rejected. Rest of the stack unreviewed.

Late Thursday, Farhad Alemi reported a syzkaller KASAN hit: NFSD’s cld upcall leaves a stack-allocated rpc_pipe_msg queued. That is the “safe” completion waiter FAN YE just copied. Client idmap/gssd/blocklayout paths that stack-allocate the same struct are in the blast radius.

Directory delegations: CB_NOTIFY v2, and d_drop vs negative

Anna Schumaker’s v2 teaches the client to consume CB_NOTIFY — the missing half of directory delegations. Conservative policy: treat notifications as “refresh,” not a directory journal. ADD instantiates via an nfs_prime_dcache()-shaped path; REMOVE d_drop()s; RENAME is remove-plus-add. Jeff Layton asked whether REMOVE should leave a negative dentry instead: d_drop() throws away the information the callback just delivered and forces a LOOKUP that a directory-delegation holder should not need. Unanswered. Nothing merged.

Other client bugs still in flight

  • SUNRPC xdr_inline_pages() OOB (Paula Moutafian): unsigned wrap on a legal NFSv3 AUTH_SYS GARBAGE_ARGS retry; peer-controlled slab write. Anna asked whether the patch was even compiled; Paula retracted the “untested” note. Still no code review of the three-line clamp.
  • NFS sysfs kobject UAF (Vasileios Almpanis): nested kobjects in nfs_netns_client, real with CONFIG_DEBUG_KOBJECT_RELEASE. Coddington Reviewed-by three weeks ago; this week is a merge ping. No maintainer pickup.
  • NetFS v10 (David Howells, 35 patches): bvecq replaces folio_queue; NFS still selects deprecated PG_private_2 and must follow the combined prepare/issue fscache hooks. Howells told Aurélien Couderc that read-abandonment is not a READ_PLUS sparse-read hook — netfslib still has no hole model.
  • READ_PLUS holes remain a server policy fight: Couderc says Linux 7.2 NFSD still reports only data; Chuck Lever says that is spec-compliant because there is no race-free VFS hole API. No client code change.
  • launder_folio removal (Matthew Wilcox): NFS conversion to bulk filemap_invalidate_pages() is still unreviewed. Miklos Szeredi argues writeback and unmap are no longer atomic under the folio lock — a distributed-cache window that looks like NFS mmap vs server INVALIDATE. Jan Kara asked launder users (NFS included) to say whether they need that locked writeout-to-release guarantee.

Userspace: Olga Kornievskaia clamped snprintf offsets in mount.nfs and fixed a one-byte GSS principal overflow in libtirpc. Salvatore Bonaccorso silenced a Python 3.14 return-in-finally warning in rpcctl.

Server-side, in brief

The nfsd control plane is still wedged on nfsd_mutex × synchronous rpcbind. Jeff Layton dropped the “make kernel rpcbind async” plan after talking to Chuck: move SET/UNSET to userland and rev the netlink protocol, no timeline. syzbot then hung svc_export_get_reqs dumpit and nfsd_nrthreads / write_ports the same day, plus a TCP svc_tcp_state_change stack overflow from double-attaching a portlist socket.

Fixes that did move: Ameer Hamza’s session-slot replay race (NULL deref in same_creds when a client pipelines two copies of a cached SEQUENCE) is in nfsd-testing. Chuck split Dell’s POSIX ACL leak into an unprivileged rpc_status OOB (stable) and a mainline-only ACL ownership rewrite. Duplicate fsnotify ACCESS on iterator READs is now a VFS vfs_splice_direct_to_actor() wrapper (Amir Goldstein Reviewed-by; Christoph Hellwig wants it renamed). lockd v3 drops the B_DEAD misfire and splits UAF vs host-leak. NeilBrown’s nfsd lookup-open series is held for v7.4 after extra linux-next soak.

Observability and performance proposals, unreviewed: Dell’s nfsd Netlink client dump (v2 will report locks_in_grace(), and Chuck asked the ABI not to freeze grace as server-wide) plus matching nfsdctl clients; Chuck’s implied-ACK DRC eviction (halved nfsd_cache_lookup CPU on NFSv3/RDMA writes); svcsock TCP receive via ->read_sock after netdev rejected a generic proto op — xprtsock still on the broken mixed-buffer kTLS path.

What to watch next week

  1. Whether Lever’s xprtrdma short-header v2 and Menninger’s unmap v4 get a Tested-by / queue slot — both are client data-integrity / hang fixes sitting outside 7.3.
  2. Review of Pujeri’s GETDEVICEINFO bounds and Jean’s SCSI designator u32 conversion; both are Cc: stable client XDR holes.
  3. Neil’s v3 negative-dentry RFC: a re-run of Chuck’s setattr/delegation xfstests, and whether Al Viro’s d_walk objection still blocks.
  4. Schumaker’s answer to Layton on CB_NOTIFY REMOVE (d_drop vs negative), and Coddington’s answer on 64-bit stripe_unit.
  5. The Globtrotter xs_read_stream_request oops: RIP-at-0x8 plus leaked lock_sock() is a reboot-only client outage until someone maps the freed object.
