NFS Mailing List — Week of 2026-01-15

Critical Bugs & Fixes

NFS Client Bugfixes Pulled for Linux 6.19

Trond Myklebust submitted and Linus merged a second batch of NFS client fixes for the 6.19 release cycle (GIT PULL). The pull includes 12 patches covering:

  • Deadlock fixes: A second nfs_release_folio() deadlock and a pNFS delegation-return deadlock during open.
  • Size read race conditions: Races in truncate, fallocate, and copy-offload operations that could corrupt data — directly addressing the regression reported by NVIDIA (see below).
  • Directory delegation hardening: Five patches from Anna Schumaker fixing verifier checks, premature slot freeing, and incorrect state-recovery assumptions for delegated directories.
  • pNFS memory leaks: Fixes in FlexFiles device ID allocation and Block Layout SCSI parsing error paths.
  • LocalIO fixes: Proper I/O shutdown on fatal errors and handling of page offsets exceeding PAGE_SIZE.

fscache/NFS Re-export Server Lockup — Fix Identified

The ongoing investigation into production server deadlocks in NFS/fscache re-export deployments reached a breakthrough (thread). Mike Snitzer identified Trond Myklebust's commit cce0be6eb497 (fixing the nfs_release_folio() synchronous-wait deadlock) as the likely cure. The fix converts nfs_release_folio() to use asynchronous writeback kicks, breaking a circular dependency between memory compaction and NFS I/O. Mike Owen plans to test against 6.19-rc5; Red Hat and Ubuntu backporting efforts are underway.

refcount_t Underflow on v6.18 Re-export — Debugging Stalls

Daire Byrne's investigation into refcount_t underflows in nfsd4_sequence_done on high-throughput re-export servers hit a wall this week (thread). Despite refined ftrace configuration, the crash produced an empty trace buffer and the refcount_warn_saturate kprobe failed to register (the function is compiled notrace). The candidate fix (cbfd91d22776, "nfsd: never defer requests during idmap lookup") remains untested.

NFS EOF Page Pollution Fix — Race Condition Patch Proposed

NVIDIA reported ext4 checksum corruption in nested VMs caused by the NFS client's eof page pollution protection commit (thread). Trond Myklebust identified a race condition where file size was read before locking the inode in NFSv4.2 fallocate and copy-offload operations, causing nfs_truncate_last_folio() to overwrite valid data. A targeted patch was submitted for NVIDIA's testing team.

New Client Hang Report — fscache Re-export Topology

Mike Owen opened a new bug report (thread) describing silent NFS client hangs in a multi-tier fscache re-export deployment. Clients lose their NFS socket with no logging, revivable only by forced unmount. No responses this week.

Major Trends & Architecture

VFS Lease Opt-In and Stable-Handle Export Enforcement

Two landmark series landed this week that reshape how filesystems interact with NFS infrastructure:

  1. VFS lease opt-in (discussion): Christian Brauner's 24-patch series requiring filesystems to explicitly opt-in to lease support was applied to vfs-7.0.leases. This prevents future regressions where new filesystems inadvertently support leases without proper implementation, which would break NFS delegation correctness.

  2. Stable-handle export enforcement (thread): Jeff Layton posted a 29-patch series introducing EXPORT_OP_STABLE_HANDLES, requiring filesystems to declare that their file handles are stable for NFS export. This prevents kernfs-based filesystems (cgroupfs, pidfs, nsfs) — which have export_operations for open_by_handle_at() but non-persistent handles — from being incorrectly exported via nfsd. The series sparked a lively debate on terminology ("stable" vs. "persistent"), with Chuck Lever arguing that "stable" avoids confusion with NFSv4's VOLATILE handle concept. FUSE and overlayfs edge cases were flagged for correction.

NFSD/SunRPC Layering Cleanup

Jeff Layton's two-patch series (thread) added a generic rq_private pointer to svc_rqst, allowing NFSD to attach per-thread state without polluting the SunRPC layer. The NFSv4-specific rq_lease_breaker and rq_cachetype fields were migrated into a new struct nfsd_thread_local_info. Applied to nfsd-testing after debate over stack vs. heap allocation.

New Features & Protocol Extensions

Case Folding Behavior Exposure (v4)

Chuck Lever posted v4 of his 16-patch series (thread) adding case_insensitive and case_nonpreserving fields to struct file_kattr, implemented across 12 filesystems (FAT, exFAT, NTFS3, HFS/HFS+, ext4, XFS, CIFS, NFS client, f2fs, vboxsf, ISO9660). NFSD patches replace hard-coded case-sensitivity assumptions with dynamic filesystem queries, enabling accurate reporting to Windows/macOS NFS clients. v4 fixed UAPI exposure and flag naming from v3; the remaining open item is struct layout (dedicated field vs. packing into fa_xflags).

NFSv4.2 POSIX ACL Server Support (v3)

Chuck Lever and Rick Macklem submitted v3 of a 13-patch series (thread) implementing server-side NFSv4.2 POSIX ACL support per the IETF draft. The extension introduces four new file attributes (FATTR4_ACL_TRUEFORM, FATTR4_ACL_TRUEFORM_SCOPE, FATTR4_POSIX_ACCESS_ACL, FATTR4_POSIX_DEFAULT_ACL) enabling lossless POSIX ACL manipulation over NFSv4.2, gated behind CONFIG_NFSD_V4_POSIX_ACLS. No replies this week.

kNFSD Encrypted Filehandles — Threat Model Debate

Benjamin Coddington (Hammerspace) resumed his encrypted filehandle series (thread). Chuck Lever pushed back on the threat model and cryptographic approach, arguing that signing (siphash) rather than full AES encryption may suffice to prevent file handle fabrication. Coddington committed to a v2 using siphash with concrete attack-scenario examples. The discussion also exposed layering concerns in svc_rqst, addressed separately by Layton's rq_private series.

NFS Client Delegation LRU

Christoph Hellwig's 24-patch series adding an LRU-based eviction policy for NFS client delegations received explicit endorsement from Sagi Grimberg (thread). A debate emerged on whether delegation recall should be client-driven or server-driven, with Trond Myklebust cautioning that excessive delegation retention harms workloads like rm -rf. A latent bug was identified: the NFS client ignores the "keep" parameter in RECALL_ANY operations.

NFSD Asynchronous Write Throttling (RFC)

Chuck Lever's RFC to throttle UNSTABLE WRITEs under memory pressure (thread) drew skepticism from Neil Brown, who questioned whether balance_dirty_pages_ratelimited_flags() works correctly across NFSD's multi-threaded architecture. The underlying problem — server memory exhaustion under heavy UNSTABLE WRITE traffic observed by Hammerspace — is acknowledged as real. No consensus reached.

bio_vec-Based RDMA API for svcrdma

Chuck Lever posted a 4-patch series (thread) adding bio_vec-based RDMA read/write APIs, eliminating scatterlist conversions in svcrdma and reducing the context structure from ~4KB to ~100 bytes. Christoph Hellwig raised concerns about API duplication, IOVA mapping correctness, and dynamic allocation trade-offs.

NFS Client Focus

Directory Delegation Fix

Anna Schumaker submitted a one-line fix (thread) preventing deadlock when the nodirdeleg module option triggers synchronous delegation return under lock. The patch defers eviction to the state manager and was included in the 6.19 bugfix pull.

NFS Client Case Sensitivity Reporting

The case folding series includes an NFS client patch implementing fileattr_get to propagate case-sensitivity information received from servers during mount, enabling accurate re-export via NFSD.
