nfsdctl: Adding Userland Support for NFSD Dynamic Threading (v1)

Summary

Type: New feature — userland tooling to complement kernel-side NFSD dynamic threadpool support.

On Monday, January 12th, Jeff Layton posted the initial version of a patch adding min-threads parameter support to nfsdctl, the userspace management utility for the NFS server. This is the long-awaited userland companion to the kernel-side dynamic threadpool feature that was merged into nfsd-testing the prior week (see: NFSD/SUNRPC dynamically-sized threadpool).

Background and Context

The preceding week saw the successful merge of Layton's eight-patch kernel series introducing dynamic thread pool sizing to NFSD and SUNRPC. That series enabled the NFS server to automatically scale its thread count between a configurable minimum and maximum based on workload demand, using -ETIMEDOUT and -EBUSY feedback signals from svc_recv(). At the time of that merge, Layton noted:

"I'll plan to post the nfs-utils patches for this in the near future too (they need a bit more work)." Jeff Layton

This patch delivers on that commitment, providing the userspace interface needed to configure and manage the new dynamic threading capability.

Core Functionality

The patch adds proper support to nfsdctl for managing NFSD's new dynamic threading when NFSD_A_SERVER_MIN_THREADS is defined in the kernel header. The behavior is as follows:

  • If the user sets min-threads on a sufficiently new kernel, the traditional threads parameter represents the maximum number of threads.
  • The min-threads value represents the minimum number of threads to run in each pool.
  • The kernel starts at the minimum thread count and dynamically fluctuates between min and max based on load.

Configuration File Support

The autostart subcommand can now read the min-threads parameter from nfs.conf and set it via the netlink call appropriately. If not set, it defaults to 0, which disables dynamic threading (preserving backward-compatible static behavior).

Command-Line Interface

For the threads subcommand, a new command-line option is added. If not specified, the value is omitted from the netlink command entirely, allowing the kernel's existing setting to remain unchanged unless explicitly overridden.

Documentation

The patch updates both nfs.conf.man and nfsdctl.8 with documentation about the new min-threads parameter.

Design Considerations Raised by Author

Layton framed this as a starting point for discussion, noting that the userland interface could differ from the kernel's internal interface. He proposed an alternative approach:

"We could just expose dynamic threading in the config file and command-line interface as a bool. If enabled, we'd set min-threads to 1. If disabled, set it to 0."

He also acknowledged a hybrid possibility:

"I guess we could also do both as well..."

This suggests openness to feedback on whether administrators would prefer explicit numeric control over min-threads, a simple boolean toggle for enabling/disabling dynamic threading, or both options.

Discussion Status

No replies were received during this week's window. The patch stands as an initial proposal awaiting community review and feedback on the interface design choices outlined above.

Significance for NFS Development

This patch is essential infrastructure work that bridges the gap between kernel capability and administrator usability:

  1. Completes the dynamic threading story: Without userland tooling, the kernel-side feature would be inaccessible to administrators using standard NFS management tools.
  2. Backward-compatible by design: Defaulting min-threads to 0 preserves existing static thread behavior, ensuring safe deployment across mixed kernel environments — consistent with Layton's earlier assurance:

"This control scheme should allow us to sanely switch between kernels that do and do not support dynamic threading." Jeff Layton

  1. Opens the door to resource-efficient NFS server deployments: Once merged, administrators can configure NFSD to start with minimal thread overhead and scale up only when demand warrants it.
