NFSD: Fix net ref data memory leak on startup failure (6.12 backport)

Summary

NFSD Memory Leak Fix: Net Ref Data Cleanup on Startup Failure

Classification: Bug Fix (Backport to Stable)

This thread addresses a memory leak in the NFS server (NFSD) subsystem, triggered when an NFSD instance fails to start up. The fix was submitted as a backport to Linux 6.12 stable.

Problem Description

Jay Wang submitted a patch on behalf of Edward Adam Davis that resolves a memory leak reported by the kernel fuzzer syzbot. The issue occurs when NFSD initialization fails before the network namespace is fully set up:

"When the NFSD instance doesn't to startup, the net ref data memory is not properly reclaimed, which triggers the memory leak issue reported by syzbot."

The syzbot report identified an unreferenced object of 64 bytes, with the backtrace pointing to percpu_ref_init called from nfsd_create_serv:

unreferenced object 0xffff88812a39dfc0 (size 64):
  backtrace (crc a2262fc6):
    percpu_ref_init+0x94/0x1e0 lib/percpu-refcount.c:76
    nfsd_create_serv+0xbe/0x260 fs/nfsd/nfssvc.c:605

The root cause is that the net reference data memory reclamation was placed inside nfsd_net_up, meaning it would only execute if the network namespace successfully came up. When startup failed, this cleanup path was never reached.

Technical Fix

The patch moves the net ref data memory reclamation outside of nfsd_net_up so that cleanup occurs even when the network namespace fails to start. The change modifies fs/nfsd/nfssvc.c with 15 insertions and 15 deletions, restructuring the error handling path.

The patch carries the following metadata:

  • Fixes: 39972494e318 ("nfsd: update percpu_ref to manage references on nfsd_net")
  • Cc: stable@vger.kernel.org
  • Reported-by: syzbot+6ee3b889bdeada0a6226@syzkaller.appspotmail.com

Review Feedback

Harshit Mogalapalli from Oracle reviewed the backport submission and provided two key pieces of feedback regarding stable kernel backport conventions:

"You need to mention the upstream commit while cherry-picking/backporting a commit to stable/lts kernels."

Harshit noted that the upstream mainline commit is 0b88bfa42e54 from v6.19-rc5, and suggested adding either [Upstream commit 0b88bfa42e5468baff71909c2f324a495318532b] or commit 0b88bfa42e54 upstream. to the patch header.

Additionally, Harshit emphasized the importance of ensuring broad stable-tree coverage:

"Also, while backporting to a long-term-stable kernel also please ensure the backport is present in all higher/newer stable/LTS version, so we don't let our stable tree consumers run into regressions when they update to newer releases. So in this case, 6.18.y also needs to be patched."

Conclusion

This thread represents a straightforward bug fix addressing a memory leak in NFSD's error handling path. The technical fix itself is clean — restructuring cleanup logic to ensure resources are freed regardless of startup success. The discussion centered on proper backport hygiene for stable kernel submissions, with Harshit Mogalapalli reminding contributors of the standard practices for documenting upstream commit provenance and ensuring comprehensive coverage across all affected stable/LTS branches.
