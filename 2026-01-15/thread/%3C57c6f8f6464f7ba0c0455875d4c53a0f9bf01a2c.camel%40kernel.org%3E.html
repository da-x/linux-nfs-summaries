NFS Client Bugfixes Pulled for Linux 6.19

Overview

This thread is a bug-fix pull request from NFS client maintainer Trond Myklebust, targeting the Linux 6.19 release cycle. The pull request was submitted on January 15, 2026, and was promptly merged into Linus Torvalds' mainline tree the same day.

Pull Request Details

Trond Myklebust submitted a GIT PULL request for the tag nfs-for-6.19-2, available at:

git://git.linux-nfs.org/projects/trondmy/linux-nfs.git tags/nfs-for-6.19-2

The changes build on top of commit 3609fa95fb0f and reach up to commit d5811e6297f3, with the final commit titled "NFS: Fix size read races in truncate, fallocate and copy offload".

Bugfixes Summary

The pull request bundles 12 individual bug fixes across three contributors — Anna Schumaker (2 patches), Trond Myklebust (8 patches), and Zilin Guan (2 patches) — touching 16 source files with a net change of +239 / -101 lines. The fixes address several critical categories:

Deadlock Fixes

  • NFS: Fix another deadlock involving nfs_release_folio() — A second instance of a deadlock in the folio release path was resolved.
  • pNFS: Fix a pNFS-related deadlock when returning delegations during open — Addressed a deadlock scenario specific to parallel NFS delegation return paths during file open operations.

NFS/LocalIO Fixes

  • NFS/localio: Stop I/O upon hitting a fatal error — Ensures that local I/O is properly halted when a fatal error condition is encountered, preventing further potentially corrupting operations.
  • NFS/localio: Deal with page offsets that are > PAGE_SIZE — Fixed handling of page bases exceeding PAGE_SIZE, correcting an edge case in the LocalIO subsystem.

NFS Size Read Race Conditions

  • NFS: Fix size read races in truncate, fallocate and copy offload — Resolved race conditions around file size reads during truncate, fallocate, and copy-offload operations, which could lead to inconsistent state or data corruption.

NFSv4 Directory Delegation Fixes

  • NFS: Fix directory delegation verifier checks (Anna Schumaker)
  • NFS: Don't immediately return directory delegations when disabled (Anna Schumaker)
  • NFSv4: Fix nfs_clear_verifier_delegated() for delegated directories
  • NFSv4: Don't free slots prematurely if requesting a directory delegation
  • NFSv4.x: Directory delegations don't require any state recovery

These five patches collectively harden the NFSv4 directory delegation client code, addressing verifier checks, premature slot freeing, and incorrect state recovery assumptions.

Memory Leak Fixes (pNFS)

  • pnfs/flexfiles: Fix memory leak in nfs4_ff_alloc_deviceid_node() (Zilin Guan)
  • pnfs/blocklayout: Fix memory leak in bl_parse_scsi() (Zilin Guan)

Two memory leaks in pNFS error paths were identified and fixed, one in the FlexFiles layout driver and another in the Block Layout SCSI parsing code.

Merge Confirmation

The pr-tracker-bot confirmed that the pull request was merged into torvalds/linux.git at commit 603c05a1639f.

Conclusion

This was a straightforward bug-fix pull with no discussion or debate. The fixes address important stability and correctness issues in the NFS client, particularly around deadlocks, race conditions, and memory leaks — all critical for production reliability. The rapid merge confirms these were accepted as essential corrections for the 6.19 release.
