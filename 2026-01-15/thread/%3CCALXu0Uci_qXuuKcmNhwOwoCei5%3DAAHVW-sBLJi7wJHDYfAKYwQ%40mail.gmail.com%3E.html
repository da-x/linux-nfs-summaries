Proposal: Mount Option to Enforce Case-Sensitivity Expectations on NFS Shares

Summary

Mount Option to Reject Non Case-Insensitive NFS Shares

Overview

This thread, initiated by Cedric Blancher from the Institute Pasteur, proposes a new mount option for the Linux NFS client that would allow administrators to enforce case-sensitivity expectations at mount time. This is a feature request rather than a bug fix or protocol change.

The Proposal

On January 14, Cedric Blancher opened the discussion by asking:

"Would it make sense to have a mount.nfs(8) option to reject the mount attempt if the NFS server reports that the share is not case-insensitive?"

As described by Blancher, the use case is to prevent accidental misconfiguration where a mount succeeds but with an incorrect case sensitivity flag. This could lead to silent operational issues for software that strictly requires either a case-insensitive or case-sensitive filesystem.

"The use case would be to prevent mounts which have the wrong case sensitive/insensitive flag by accident, ensuring proper operation if software requires a case-insensitive or case-sensitive filesystem."

Technical Context

NFSv4 servers can advertise whether an export is case-insensitive through the case_insensitive attribute in the FSINFO response. The Linux NFS client already supports mounting with the nocase option to indicate that the underlying server filesystem is case-insensitive, which enables proper name lookup behavior on the client side.

The proposed enhancement would add a validation step: if an administrator specifies this new option (e.g., require_case_insensitive or similar), the mount would fail if the server reports the share as case-sensitive — and vice versa for a complementary option requiring case-sensitivity. This acts as a safety net against configuration drift or human error in mount scripts.

Status This Week

Only the initial proposal was posted during this week. No replies were received from NFS client maintainers (such as Chuck Lever) or other developers within the reporting window. The thread remained open, with follow-up messages arriving in mid-February 2026 (outside this summary's scope).

Key Takeaways

  • Type: Feature request — a new mount option for the NFS client utility (mount.nfs(8)).
  • Motivation: Prevent silent misconfiguration when case sensitivity expectations do not match server reality.
  • No conclusions reached within this week; the discussion was just beginning.
