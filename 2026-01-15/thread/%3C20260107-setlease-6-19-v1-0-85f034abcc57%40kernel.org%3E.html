VFS: Directory Lease Denial Fixes Applied to vfs.fixes

Overview

This thread concerns a bug fix series originally submitted last week by Jeff Layton, targeting the NFS client and several other network/distributed filesystems. The six-patch series addresses incorrect lease denial semantics for directories — a correctness issue exposed by a prior VFS refactoring and the advent of directory delegations in NFSv4.2.

This week, Christian Brauner applied all six patches to the vfs.fixes branch, marking the conclusion of this discussion.

Background (from Prior Week)

Last week, Jeff Layton submitted a six-patch series to fix a subtle bug in how directory leases and delegations are handled across multiple filesystems. The root cause traced back to commit e6d28ebc17eb ("filelock: push the S_ISREG check down to ->setlease handlers"), which moved the regular-file-only check for leases from the generic VFS layer into individual filesystem ->setlease() handlers.

The problem: several filesystems were checking S_ISREG() inside their file-level ->setlease() handlers, but that handler is never invoked for directories. As a result, lease requests on directories were not being properly denied.

"Checking for S_ISREG() in nfs4_setlease() is incorrect, since that op is never called for directories. The right way to deny lease requests on directories is to set the ->setlease() operation to simple_nosetlease() in the directory file_operations." — Jeff Layton

The series targeted NFS, SMB/client, 9p, GFS2, Ceph, and VBoxSF, adding simple_nosetlease() to directory file_operations structures and removing now-redundant S_ISREG() checks from file-level handlers.

Christoph Hellwig confirmed the fix resolves xfstest generic/786 on NFSv4.2:

"This fixes generic/786 on NFSv4.2 for me, so: Tested-by: Christoph Hellwig hch@lst.de" — Christoph Hellwig

The prior week's discussion also surfaced a broader architectural question about whether leases should become an opt-in feature (denied by default when ->setlease() is not set), with Hellwig agreeing in principle.

Impact on NFS Client Development

For the NFS client specifically, this fix ensures that:

  1. Directory delegation requests are properly denied via simple_nosetlease() in the directory file_operations, rather than relying on an incorrect S_ISREG() check inside nfs4_setlease() — a handler that is never invoked for directories.
  2. Test infrastructure (xfstests) can correctly detect and skip unsupported lease/delegation scenarios, resolving test generic/786 failures on NFSv4.2.

As Layton noted in the original cover letter:

"There should be no noticeable change in behavior, other than fixing the support detection in xfstests, allowing lease/delegation tests to be properly skipped on these filesystems." — Jeff Layton

Final Conclusions

The series has been fully applied to vfs.fixes and is expected to flow through linux-next into the mainline kernel. The immediate bug fix — correcting directory lease denial semantics across six filesystems including NFS — is complete. The longer-term architectural discussion about making leases opt-in by default remains an open consideration for future VFS development.
