exportfs Kernel-Doc Fixes: Cleaning Up Documentation for struct export_operations

André Almeida submitted a short four-patch series this week addressing kernel-doc warnings and documentation duplication in the VFS exportfs subsystem, which underpins NFS server (nfsd) file export functionality. The discussion was brief and concluded with immediate acceptance into the vfs tree.

Issue Classification: Documentation Bug Fix

The series targets kernel-doc build-time warnings generated for struct export_operations in include/linux/exportfs.h. As André Almeida noted, the following warnings were being emitted:

WARNING: ../include/linux/exportfs.h:289 struct member 'get_uuid' not described in 'export_operations' WARNING: ../include/linux/exportfs.h:289 struct member 'map_blocks' not described in 'export_operations' WARNING: ../include/linux/exportfs.h:289 struct member 'commit_blocks' not described in 'export_operations' WARNING: ../include/linux/exportfs.h:289 struct member 'permission' not described in 'export_operations' WARNING: ../include/linux/exportfs.h:289 struct member 'open' not described in 'export_operations' WARNING: ../include/linux/exportfs.h:289 struct member 'flags' not described in 'export_operations'

Patch Breakdown

Patch 1/4 – Fix kernel-doc output for get_name() [id://20260112-tonyk-fs_uuid-v1-1-acc1889de772@igalia.com]: A minor formatting fix where a missing space between %NAME_MAX and the plus sign caused Sphinx to render an unexpectedly large monospaced string. André explained:

"Without a space between %NAME_MAX and the plus sign, kernel-doc will output NAME_MAX+1, which scapes the last backtick and make Sphinx format a much larger string as monospaced text."

Patch 2/4 – Mark struct export_operations functions at kernel-doc [id://20260112-tonyk-fs_uuid-v1-2-acc1889de772@igalia.com]: Added @ markers before function names in the struct definition so they are properly recognized as kernel-doc entries. André posed a question during development:

"Should I just remove the short descriptions?"

The approach taken was to add detailed @-prefixed definitions alongside existing one-line summaries, with kernel-doc favoring the more detailed version.

Patch 3/4 – Complete kernel-doc for struct export_operations [id://20260112-tonyk-fs_uuid-v1-3-acc1889de772@igalia.com]: Added missing member descriptions for get_uuid, map_blocks, commit_blocks, permission, open, and flags by referencing the original commit messages that introduced these members.

Patch 4/4 – docs: exportfs: Use source code struct documentation [id://20260112-tonyk-fs_uuid-v1-4-acc1889de772@igalia.com]: Eliminated duplicated documentation by replacing the hand-written ReST description of struct export_operations in Documentation/filesystems/nfs/exporting.rst with a reference to the kernel-doc in the source code. This reduced 37 lines of duplicated documentation, as André described:

"Instead of duplicating struct export_operations documentation in both ReST file and in the C source code, just use the kernel-doc in the docs."

Review and Acceptance

The series received rapid positive feedback from key maintainers:

  • Chuck Lever [id://7ac583b8-3480-4a54-bcd7-9b1a8689a7f7@app.fastmail.com] provided a Reviewed-by.
  • Jeff Layton [id://45115f6f2acbe9f498b94b1fbf8133ef0052053a.camel@kernel.org] concurred: "LGTM" and added his Reviewed-by.
  • Randy Dunlap [id://d36eea96-c017-4217-b406-77758cef28c3@infradead.org], the kernel documentation maintainer, provided both Reviewed-by and Tested-by tags for all four patches.

Christian Brauner [id://20260113-gestochen-campen-1d3a663928df@brauner] applied the entire series to the vfs-7.0.misc branch of the vfs/vfs.git tree, noting:

"Patches in the vfs-7.0.misc branch should appear in linux-next soon."

Significance for NFS Development

While this series does not introduce new NFS features or fix runtime bugs, it improves the maintainability and accuracy of kernel documentation for struct export_operations, a central data structure used by filesystems (including NFS server implementations) to expose their export capabilities to the VFS layer. Clean, accurate kernel-doc ensures that developers working on NFS client/server code have reliable reference material for understanding how filesystems integrate with the exportfs subsystem — particularly for operations like UUID handling, block mapping, and permission checks that are relevant to NFSv4 server functionality.
