IOCB_NOWAIT Writes Series v6: Applied to VFS Tree

Summary

Christoph Hellwig's six-iteration series to re-enable IOCB_NOWAIT writes to files has been accepted and applied by VFS maintainer Christian Brauner. This marks the culmination of an effort dating back to November 2025 to restore non-blocking write support for io_uring workloads that was effectively disabled by commit 66fa3cedf16a.

Classification

This is a feature restoration / performance fix spanning the VFS layer and multiple filesystems. The series introduces non-blocking lazytime timestamp updates, with XFS as the first implementing filesystem. For NFS clients, it provides important preparatory refactoring to align timestamp update paths with new VFS conventions.

Background (Bridged from Prior Week)

As Hellwig explained in the cover letter:

"commit 66fa3cedf16a ("fs: Add async write file modification handling.") effectively disabled IOCB_NOWAIT writes as timestamp updates currently always require blocking, and the modern timestamp resolution means we always update timestamps. This leads to a lot of context switches from applications using io_uring to submit file writes, making it often worse than using the legacy aio code that is not using IOCB_NOWAIT."

The v6 series — posted on January 8 after incorporating feedback from v5 — addressed two issues: sampling ctime before calling inode_set_ctime_current (identified by Jan Kara) and fixing a mild bisection hazard in FAT (raised by OGAWA Hirofumi).

This Week's Activity: Application to VFS Tree

On January 12, VFS maintainer Christian Brauner confirmed the series has been merged:

"Applied to the vfs-7.0.nonblocking_timestamps branch of the vfs/vfs.git tree."

— Christian Brauner

He noted that:

"Patches in the vfs-7.0.nonblocking_timestamps branch should appear in linux-next soon."

— Christian Brauner

Brauner also cautioned:

"Please report any outstanding bugs that were missed during review in a new review to the original patch series allowing us to drop it."

— Christian Brauner

NFS Client Impact: Timestamp Refactoring Applied

The NFS-specific patch, [PATCH 03/11] nfs: split nfs_update_timestamps (now at commit b8b3002fbfef), splits the timestamp update function in fs/nfs/inode.c into separate paths for atime versus ctime/mtime updates. As Hellwig described:

"The VFS paths update either the atime or ctime and mtime but never mix between atime and the others. Split nfs_update_timestamps to match this to prepare for cleaning up the VFS interfaces."

— Christoph Hellwig

This patch received endorsements from both NFS and VFS maintainers:

"Reviewed-by: Jan Kara jack@suse.cz" "Reviewed-by: Jeff Layton jlayton@kernel.org"

The refactoring aligns the NFS client's timestamp update behavior with VFS calling conventions — a prerequisite for enabling non-blocking timestamp operations on NFS in future work. The NFS client itself does not yet implement non-blocking timestamp updates; that remains future development.

Conclusion

The series is now merged into the VFS tree and will appear in linux-next. For NFS developers, the key takeaway is that the client's timestamp update infrastructure has been refactored to match new VFS conventions — setting the stage for future non-blocking timestamp support on NFS. The final patch carries a Fixes: tag pointing to the original regression:

"Fixes: 66fa3cedf16a ("fs: Add async write file modification handling.")"

— Christoph Hellwig
