NFS Client: Fix Synchronous Directory Delegation Return Under Lock

Summary

NFS Client: Fix for Directory Delegation Return Under Lock

Overview

This week, Anna Schumaker submitted a bug fix patch addressing a locking correctness issue in the NFS client's directory delegation handling. The single-message thread introduces a targeted correction to how directory delegations are returned when the nodirdeleg module option is used to disable them.

Classification

This is a bug fix for the NFS client, correcting a potential deadlock scenario introduced by a prior commit that added a module option to disable directory delegations.

The Bug: Synchronous Delegation Return Under Lock

The patch submitted on January 9 addresses a subtle concurrency issue in the NFS client's delegation management code. Anna Schumaker explained the problem:

"The function nfs_inode_evict_delegation() immediately and synchronously returns a delegation when called. This means we can't call it from nfs4_have_delegation(), since that function could be called under a lock."

The root cause traces back to commit b6d2a520f463 ("NFS: Add a module option to disable directory delegations"), which introduced the nodirdeleg module parameter. When this option is set, the NFS client should refuse directory delegations. The implementation in nfs4_have_delegation() — a function that checks whether a delegation can be held for a given inode — was calling nfs_inode_evict_delegation() directly to immediately return any existing directory delegation.

The problem: nfs4_have_delegation() can be invoked while holding locks (e.g., the inode's state lock). Calling nfs_inode_evict_delegation() synchronously under a lock risks deadlock, as the eviction path may attempt to acquire the same or related locks during the delegation recall process.

The Fix: Asynchronous Delegation Return via State Manager

The fix is minimal — a one-line change in fs/nfs/delegation.c — but architecturally significant. Instead of immediately evicting the delegation, the code now marks the delegation for return and lets the NFS state manager handle the actual recall asynchronously:

"Instead we should mark the delegation for return and let the state manager handle it for us." — Anna Schumaker

This approach follows the established NFS client pattern of deferring potentially blocking operations to the state manager thread, which runs outside of user-context lock domains and can safely perform delegation recall RPCs without risking deadlocks.

Context: Broader Lease and Delegation Work This Week

This fix arrives in the context of significant VFS-level work on lease semantics this week. As documented in related summaries, Jeff Layton's 24-patch series to make VFS lease support an explicit opt-in feature was applied to vfs-7.0.leases, and a separate six-patch series fixing directory lease denial semantics was applied to vfs.fixes. Both series directly impact NFS client delegation behavior:

  1. The directory lease denial fix (applied to vfs.fixes) ensures that simple_nosetlease() is properly set in NFS directory file_operations, preventing incorrect lease grants on directories — a prerequisite for correct directory delegation handling.
  2. The lease opt-in series (applied to vfs-7.0.leases) prevents future regressions where new filesystems inadvertently support leases without proper implementation, which could break NFS delegation correctness.

Schumaker's patch complements this work by fixing a locking bug in the NFS client's own handling of directory delegations when they are explicitly disabled via module option.

Impact on NFS Client Development

This fix has several implications for NFS client development:

  1. Locking correctness: The nodirdeleg module option can now be safely used without risk of deadlock during delegation checks. This is particularly important in environments where directory delegations cause issues (e.g., certain server implementations or workloads).
  2. State manager pattern reinforcement: The fix reinforces the established pattern of deferring delegation eviction to the state manager, a design principle that NFS client developers should follow when modifying delegation-related code paths.
  3. Directory delegation reliability: Combined with the VFS-level lease fixes applied this week, directory delegation handling in the NFS client is now more robust and correct across all code paths.

Final Conclusions

This is a single-patch bug fix with no further discussion this week. The patch:

  • Fixes a potential deadlock when nfs_inode_evict_delegation() was called synchronously from under a lock in nfs4_have_delegation().
  • Uses the established state manager pattern for asynchronous delegation return.
  • Addresses a regression introduced by commit b6d2a520f463 ("NFS: Add a module option to disable directory delegations").

The patch is signed off by Anna Schumaker and includes a proper Fixes: tag, indicating it is intended for the stable kernel backport process. No reviews or objections were recorded in this thread during the current week.
