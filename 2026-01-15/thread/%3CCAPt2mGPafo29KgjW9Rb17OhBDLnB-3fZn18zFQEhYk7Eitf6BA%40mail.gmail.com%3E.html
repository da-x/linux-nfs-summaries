NFS Server refcount_t Underflow: Empty ftrace Buffer on v6.18 Re-export Crash

Summary

NFS Server refcount_t Underflow Debugging: Empty ftrace Buffer on v6.18 Re-export Crash

Classification: Bug fix (ongoing investigation)

Background

This thread, initiated in late December 2025, tracks an ongoing investigation into a kernel crash affecting NFS server (NFSD) re-export deployments running Linux v6.18. The bug manifests as a refcount_t underflow in the NFSv4.1+ session sequence completion path (nfsd4_sequence_done), leading to use-after-free warnings and system instability. Daire Byrne reported intermittent crashes after upgrading from v6.4 to v6.18.0, occurring roughly once every two weeks on high-throughput (50 Gbps) re-export servers where NetApp NFSv3 mounts are re-exported as NFSv4 to Linux clients.

Last week, Chuck Lever provided refined debugging guidance after initial ftrace data proved too voluminous — the nfsd_slot_seqid_sequence tracepoint fires on every compound operation, saturating buffers at 50 Gbps throughput. He recommended increasing buffer sizes, disabling noisy tracepoints, using kprobes for direct refcount underflow capture, and extending panic timeouts.

This Week's Activity (January 9, 2026)

Empty ftrace Buffer on Crash

On January 9, Daire Byrne reported that the first crash under the new debugging configuration occurred quickly — but yielded no useful trace data:

"Well, my first crash with the latest debug params was quick, but the ftrace buffer was empty..." Daire Byrne

The kernel oops output confirmed an empty trace buffer:

[22183.614070] Dumping ftrace buffer:
[22183.615747]    (ftrace buffer empty)
[22183.617613] CR2: ffd6eb25124a0a08

Debug Configuration Issues Identified

Daire Byrne shared the exact commands he used to implement Chuck Lever's suggestions, revealing two problems:

1. The kprobe for refcount_warn_saturate failed to register:

"I couldn't add the refcount_warn_saturate kprobe though: trace_kprobe: Could not probe notrace function refcount_warn_saturate" Daire Byrne

This indicates the function was compiled with the notrace attribute, preventing kprobe instrumentation — a common issue with core kernel functions where tracing could cause recursion.

2. The ftrace buffer remained empty despite tracepoint configuration:

Daire confirmed he saw the expected NFSd trace events available in /sys/kernel/debug/tracing/trace, but they were not captured during the oops dump:

"I definitely see the requested nfsd trace stuff in /sys/kernel/debug/tracing/trace now, so not sure why it didn't dump on the oops last time around." Daire Byrne

This suggests either a configuration issue with ftrace_dump_on_oops or that the tracepoints were not actually enabled at crash time.

Next Steps

Daire Byrne indicated he would retry the debugging approach and then test the candidate fix patch:

"I'll try it again and then try the suggested patch." Daire Byrne

The candidate fix in question is cbfd91d22776 ("nfsd: never defer requests during idmap lookup") from Chuck Lever's nfsd-testing branch, which was identified last week as potentially relevant to the refcount underflow issue.

Technical Significance

This week highlights the practical challenges of debugging intermittent kernel crashes in production NFS server environments at scale:

  1. Notrace functions block kprobes: Core kernel functions like refcount_warn_saturate may be compiled with notrace, preventing direct instrumentation via kprobes — requiring alternative approaches such as kernel recompilation with different debug options or using hardware-based tracing (e.g., perf, ftrace dynamic events).

  2. ftrace_dump_on_oops reliability: Even with correct tracepoint configuration, the dump mechanism may fail to capture data, possibly due to timing issues during oops handling or incorrect buffer state management.

  3. The debugging path remains open: Despite setbacks in trace data collection, the investigation continues with refined methodology and a candidate patch under evaluation.

Status

Open — under investigation. No root cause has been identified or fix merged. The candidate fix (cbfd91d22776) has not yet been tested by Daire Byrne. Debugging infrastructure issues (empty ftrace buffer, failed kprobe registration) need to be resolved before useful crash data can be captured.
