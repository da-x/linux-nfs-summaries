nfs-utils: Rename CONFIG_NFSV41 to CONFIG_BLKMAPD and Disable by Default

Summary

Deprecating pNFS Block Layout: Renaming and Disabling blkmapd by Default

This week saw a focused discussion around a configuration change in nfs-utils aimed at cleaning up the build system and reflecting the deprecation of the pNFS block layout driver. The patch, submitted by Scott Mayhew, renames CONFIG_NFSV41 to CONFIG_BLKMAPD and disables it by default.

Background: The Decline of pNFS Block Layout

The impetus for this change is the broader shift in parallel NFS (pNFS) support within the Linux kernel ecosystem. As noted by Scott Mayhew in his initial patch submission on January 14:

"pNFS block layout is deprecated in favor of pNFS SCSI layout, which doesn't require the use of blkmapd."

The blkmapd daemon was historically required to support the older pNFS block layout. However, with the industry moving toward pNFS SCSI layout—which does not depend on blkmapd—the daemon has become largely obsolete for most modern NFS deployments.

The Patch: Renaming and Disabling by Default

The existing configuration option CONFIG_NFSV41 in nfs-utils was misleadingly named, as it did not control NFSv4.1 support itself but rather enabled the build of blkmapd. Mayhew's patch addresses this confusion by:

  1. Renaming CONFIG_NFSV41 to CONFIG_BLKMAPD to accurately reflect its purpose.
  2. Disabling it by default, requiring distributions that still need blkmapd support to explicitly enable it via --enable-blkmapd.

"Since CONFIG_NFSV41 (enabled by default, but can be disabled via --disable-nfsv41) is only used to enable blkmapd, let's rename it to CONFIG_BLKMAPD and change the default to disabled."

This change affects three files in the nfs-utils tree: configure.ac, systemd/Makefile.am, and utils/Makefile.am.

Community Response

The patch received swift and positive feedback from key maintainers and distributors.

Christoph Hellwig, a prominent kernel developer involved in NFS infrastructure, provided an immediate review on January 15:

"Looks good"
Reviewed-by: Christoph Hellwig hch@lst.de

His acknowledgment signals strong support from the kernel side for this cleanup effort.

Salvatore Bonaccorso, representing Debian, also validated the patch by testing it against nfs-utils version 2.8.4:

"Tested it on top of 2.8.4."
Tested-by: Salvatore Bonaccorso carnil@debian.org

His testing confirmation ensures that the change integrates smoothly with distribution packaging workflows.

Conclusion

This thread represents a configuration cleanup and deprecation milestone for nfs-utils. By renaming CONFIG_NFSV41 to CONFIG_BLKMAPD and disabling it by default, the project aligns its build system with current NFS best practices—specifically, the transition away from pNFS block layout toward pNFS SCSI layout. The patch is well-received, with both review and testing approvals indicating readiness for inclusion in upcoming nfs-utils releases.
