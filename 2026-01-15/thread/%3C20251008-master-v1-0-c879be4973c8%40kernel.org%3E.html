Summary

NFS: Progress Toward Deprecating NFSv4.0 Server Support

Overview

This thread concerns a protocol change / deprecation effort targeting the NFS server (nfsd) subsystem. Jeff Layton's two-patch series, originally submitted on October 8, 2025, seeks to disable NFSv4.0 protocol support by default in both the kernel nfsd module and the userspace nfsdctl utility, as a preparatory step toward fully deprecating the legacy NFSv4.0 protocol.

Background (Prior Weeks)

The patch series was first introduced at the NFS Bakeathon [id://20251008-master-v1-0-c879be4973c8@kernel.org], where developers discussed deprecating NFSv4.0. The rationale is that NFSv4.0 lacks many features present in later minor versions (such as stateless operations and improved security), and maintaining it adds unnecessary complexity to the server codebase.

The two patches modify:

  • utils/nfsd/nfsd.c — kernel nfsd module, disabling v4.0 by default
  • utils/nfsdctl/nfsdctl.c — userspace nfsdctl, disabling v4.0 by default

The approach ensures NFSv4.0 is only accepted if explicitly requested via configuration file or command-line options, preserving backward compatibility for deployments that still require it while nudging administrators toward newer protocol versions.

Activity This Week

This week saw a brief but meaningful exchange as the patches awaited review and acknowledgment from key maintainers.

Ping for Review

On January 9, Jeff Layton followed up on the stalled thread [id://d71e37c054c51428f34a51b6a980a62bc07a68e7.camel@kernel.org]:

"Steved, ping?"

He also invited broader community participation:

"Also, if anyone else wants to send an Acked-by for this, I wouldn't complain."

This indicates the patches had been sitting without formal review for several months since their initial submission in October 2025.

Maintainer Response

Steve Dickson, a key NFS maintainer and the primary reviewer for nfsdctl changes, responded on January 10 [id://46742bfa-767b-470d-a123-893f8c574b2e@redhat.com]:

"Working on it..."

While brief, this response signals that the patches are actively under review and moving toward acceptance.

Context Within Broader NFS Server Development

This deprecation effort is part of a larger push to modernize and harden the NFS server stack this week. Notably, Jeff Layton also submitted a 29-patch series requiring filesystems to explicitly opt-in to nfsd export support via EXPORT_OP_STABLE_HANDLES — a complementary hardening measure that prevents unsuitable filesystems from being exported via NFS.

Conclusion

This discussion is about a protocol deprecation change rather than a bug fix or new feature. The key takeaways:

  1. NFSv4.0 server support will be disabled by default, requiring explicit opt-in for continued use.
  2. The patches affect both the kernel nfsd module and the userspace nfsdctl utility, ensuring consistent behavior across the stack.
  3. Steve Dickson confirmed he is reviewing the changes, suggesting the patches are progressing toward acceptance.
  4. No technical objections were raised this week; the discussion was limited to status updates.

The change represents a gradual shift in the NFS ecosystem toward encouraging adoption of newer protocol versions (NFSv4.1 and later), which offer improved security, statelessness, and performance features absent from the original NFSv4.0 specification.
