LTP RPC Tests: Valid FD for libtirpc Validation

Summary

LTP RPC Test Fixes: Valid File Descriptor for libtirpc Validation

Classification: Bug fix (LTP test suite, not kernel code)

This week saw continued discussion of an LTP (Linux Test Project) patch addressing failing RPC test cases that use the libtirpc library. The thread, originally posted to the LTP mailing list and cross-posted to linux-nfs, focuses on ensuring that RPC-related tests pass valid file descriptors to satisfy libtirpc's internal validation checks.

Background and Problem Statement

Liu Jian from Huawei submitted [PATCH v2] titled "rpc: create valid fd to pass libtirpc validation" (original patch). As described in the patch cover letter, several LTP RPC test cases were failing:

"The testcase(rpc_svc_destroy, rpc_svcfd_create, rpc_xprt_register, rpc_xprt_unregister) was failing due to an invalid fd, which caused libtirpc's internal validation to reject the operation."

The fix ensures that a valid socket file descriptor is created before being passed to svcfd_create(), thereby satisfying libtirpc's validation requirements. Version 2 of the patch addressed a compilation error on Alpine Linux.

Review and Feedback from Petr Vorel

Petr Vorel of SUSE provided review feedback on January 13, cross-cc'ing Steve French and the linux-nfs list. His review raised several important questions and suggestions:

Request for Environmental Context:

"I would also like to know more details about the failure (libtirpc version, or do you still use Sun RPC from old glibc, distro, arch, ...)."

Petr noted that while some of these tests have known problems, he was uncertain whether the proposed approach — connecting to 127.0.0.1 — is universally valid:

"Because while we have some problems with some of these tests, I'm not sure if connecting to 127.0.0.1 is a valid approach. And if it is, should it be used in more tests? Also rpc_svc_destroy_stress.c and rpc_svcfd_create_limits.c use svcfd_create()."

Code Quality Suggestions: Petr offered several minor implementation improvements:

  • Suggesting a common header with shared code to reduce duplication across the four affected test files.
  • Recommending fprintf(stderr, ...) or perror() instead of printf("socket creation failed").
  • Proposing struct initialization via {0} rather than memset():

"Maybe just: struct sockaddr_in server_addr = {0}; instead of memset() ?"

He also noted a minor observation about resource cleanup:

"Funny that all testsuites don't close fd, but not closing single fd is not that problematic."

Scope and Relevance to NFS Development

This discussion pertains to the LTP test suite, specifically the rpc-tirpc test pack under testcases/network/rpc/. While not a direct kernel NFS client change, reliable RPC testing infrastructure is foundational for NFS development, as NFS relies heavily on RPC transport mechanisms. The patch modifies four test source files:

  • rpc_svc_destroy.c (+27 lines)
  • rpc_svcfd_create.c (+26 lines)
  • rpc_xprt_register.c (+25 lines)
  • rpc_xprt_unregister.c (+25 lines)

Status

As of the end of this week, the patch remains under review. Petr Vorel's feedback has been incorporated into the discussion, and a follow-up response from Liu Jian was posted on January 17 (outside this week's window). The key open questions revolve around whether the localhost-connection approach is appropriate across all test scenarios and which environments/libtirpc versions trigger the original failures.
