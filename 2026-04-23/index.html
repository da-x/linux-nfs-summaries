NFS client bug fixes: syzbot cache OOB, delegation mtime staleness, pNFS hardening; NFSD v7.1 merge with filehandle signing and netlink state revocation

Week ending 2026-04-23

Critical Bugs & Fixes

SunRPC Cache Slab-Out-of-Bounds Read (syzbot)

syzbot reported a KASAN slab-out-of-bounds read in cache_seq_start_rcu() within the shared SUNRPC cache subsystem (net/sunrpc/cache.c). The bug, reachable via unprivileged user namespaces, was caused by a prior commit removing a bounds-check guard in __cache_seq_start(). Chuck Lever submitted a targeted fix adding symmetric bounds checking, which received positive reviews from Benjamin Coddington and NeilBrown. This affects shared infrastructure used by both NFS client and server caches.

NFSv4 State Recovery Deadlock (Unresolved)

Zhihao Cheng submitted a fix for a critical NFSv4 client deadlock that occurs when a server restarts and misses its grace period, causing the client to loop infinitely in NFS4CLNT_RECLAIM_NOGRACE state. Maintainer Trond Myklebust pushed back on the proposed approach as spec-noncompliant and suggested an alternative, but Cheng reported that neither approach fully resolved the issue. This remains unresolved and requires further investigation into the interaction between NOGRACE reclaim and RECLAIM_COMPLETE.

NFS Client Bug Fixes — Delegation and Attribute Correctness

A significant cluster of client-side fixes this week targeted correctness issues around delegations, timestamps, and metadata:

  • CLONE/COPY attribute staleness with delegated attributes: Olga Kornievskaia submitted PATCH v5 fixing xfstest generic/407 failures where the NFSv4.2 client failed to update mtime/ctime after CLONE/COPY operations when delegated attributes were present. The fix ensures delegated attributes are properly invalidated in nfs42_copy_dest_done().

  • Directory mtime staleness under delegation: Tom Haynes submitted a fix for stale directory mtime returned by stat() after local mutations (rename, create, unlink) when a directory delegation is held. The client's early-exit optimization in __nfs_revalidate_inode() was bypassing GETATTR RPCs even when attributes were flagged stale. Anna Schumaker reviewed and suggested broadening the fix to cover all NFS_INO_INVALID_ATTR flags.

  • nlink drop ordering with delegation returns during REMOVE: Roberto Bergantinos Corpas submitted v2 fixing a regression where the VFS failed to deliver FS_DELETE_SELF inotify notifications because delegation returns during REMOVE interfered with gencount logic. Per Trond Myklebust's guidance, the fix pushes gencount capture into version-specific remove handlers.

  • EOF staleness after fallocate/zero-range with delegation: Dai Ngo submitted a fix for xfstest generic/075 failures where NFSv4.2 fallocate/zero-range operations extended files on the server but left the local inode's i_size stale under a write delegation.

  • RCU and tracing pointer safety: Sean Chang submitted v3 of a two-patch series fixing Sparse warnings — removing a redundant __private attribute from nfs_page_class and adding proper RCU protection for cl_xprt access in nfs_compare_super_address(). Both patches received Reviewed-by from Benjamin Coddington.

pNFS Client Hardening

  • LAYOUTCOMMIT retry loop on OLD_STATEID: Lei Yin submitted a fix for an unbounded retry loop in nfs4_layoutcommit_done() when the server returns NFS4ERR_OLD_STATEID. The patch refreshes the layout stateid before retrying, aligning LAYOUTCOMMIT with other pNFS operations.

  • Blocklayout GETDEVICEINFO parser hardening: Werner Kasselman submitted a two-patch series addressing multiple security vulnerabilities in the pNFS blocklayout volume parser: out-of-bounds reads on unvalidated volume indices, kernel stack overflow via unlimited recursion depth, and resource exhaustion from DAG-shaped topologies. Christoph Hellwig reviewed positively with minor suggestions to reduce max depth and use unsigned types.

  • FlexFiles NULL deref on zero version_count: Junrui Luo submitted a fix for a NULL pointer dereference when a server returns version_count == 0 in GETDEVICEINFO, which bypasses the kzalloc_objs() NULL check via ZERO_SIZE_PTR.

  • pNFS layoutreturn deadlock fix withdrawn: The proposed deadlock fix from Ben Roberts was withdrawn after Benjamin Coddington and Trond Myklebust determined the diagnosed race condition does not exist in upstream code due to existing flag-clearing logic in pnfs_prepare_layoutreturn().

NFS Client Performance & Protocol

  • FMODE_NOWAIT for io_uring: Arik Rinberg submitted a one-line patch flagging NFS files as supporting FMODE_NOWAIT, preventing io_uring from needlessly punting I/O to worker threads.

  • EXCHGID4_FLAG_SUPP_FENCE_OPS: Trond Myklebust explained why the Linux NFS client does not set this flag in NFSv4.2 mode: minor versions cannot make features mandatory, and the server's reply determines fence support regardless of client input.

NFSD (Server) Highlights

v7.1 Merge Window Completed

Chuck Lever's NFSD pull request was merged into torvalds/linux.git, delivering:

  • Filehandle signing (SipHash-2-4 MAC) via Benjamin Coddington's work to defend against filehandle-guessing attacks
  • NLMv4 XDR layer conversion from hand-written C to xdrgen-generated code for improved memory safety
  • pNFS block/SCSI layout robustness improvements including per-client SCSI persistent reservation fencing

Netlink State Revocation on Unmount

Chuck Lever submitted v9 of a 9-patch series introducing netlink commands (NFSD_CMD_UNLOCK_IP, NFSD_CMD_UNLOCK_FILESYSTEM, NFSD_CMD_UNLOCK_EXPORT) for fine-grained NFSv4 state revocation. The series also fixes two critical bugs: an infinite loop in layout state revocation and a memory leak in layout stid cleanup. Christian Brauner approved the architectural direction.

Case Folding Behavior Exposure

Chuck Lever's 17-patch series was applied by Christian Brauner to vfs/vfs.git, adding VFS-level case-sensitivity flags and updating NFSD to correctly report FATTR4_CASE_INSENSITIVE/FATTR4_CASE_PRESERVING attributes. This resolves incorrect hard-coded responses for case-insensitive filesystems like FAT, exFAT, and ext4 with casefold.

sunrpc pool_mode RFC

Jeff Layton proposed hardcoding pool_mode to pernode and removing legacy modes. Chuck Lever agreed with the direction but advocated a gradual deprecation path rather than immediate removal, citing backward compatibility concerns for existing modprobe configurations.
