NFSD v7.1 Merge: Filehandle Signing, XDR Safety, and pNFS Robustness

Summary

NFSD v7.1 Merge Window: Security, Safety, and Scalability

This thread captures the successful merge of the NFSD (NFS Server) changes for the Linux v7.1 kernel. The pull request, submitted by Chuck Lever on April 19th and merged into torvalds/linux.git on April 20th, represents a significant update to the NFS server stack, focusing on security enhancements, memory safety through code generation, and robustness improvements for pNFS layouts.

Key Technical Highlights

1. Filehandle Signing for Security

A major new feature contributed by Benjamin Coddington is filehandle signing, designed to defend against filehandle-guessing attacks.

"The server now appends a SipHash-2-4 MAC to each filehandle when the new 'sign_fh' export option is enabled. NFSD then verifies filehandles received from clients against the expected MAC; mismatches return NFS error STALE."

This addition provides a critical security layer, ensuring that clients cannot fabricate or guess valid filehandles to access unauthorized files.

2. NLMv4 XDR Layer Conversion for Memory Safety

Chuck Lever led a substantial effort to convert the entire NLMv4 server-side XDR (External Data Representation) layer from hand-written C code to xdrgen-generated code. This involved approximately thirty patches.

"XDR functions are generally boilerplate code and are easy to get wrong. The goals of this conversion are improved memory safety, lower maintenance burden, and groundwork for eventual Rust code generation for these functions."

This change reduces the risk of bugs in data serialization/deserialization and simplifies future maintenance.

3. pNFS Block/SCSI Layout Robustness

Dai Ngo contributed two key improvements to enhance the robustness of pNFS block/SCSI layouts:

  • Per-client SCSI persistent reservation fencing: Tracked via an xarray to avoid redundant preempt operations and potential deadlocks.
  • Timeout enforcement on layout recall: Integrated with lease manager fencing to prevent issues when all nfsd threads are waiting for a layout return.

4. Scalability and Infrastructure Improvements

The remaining patches focus on scalability and infrastructure:

  • Jeff Layton contributed changes to convert global locks (like state_lock) to per-net namespace or per-cache-detail locks, improving concurrency.
  • Neil Brown improved RCU safety in cache list walking.
  • Various cleanups and bug fixes were provided by other contributors, including compilation error fixes and documentation updates.

Conclusion

The v7.1 NFSD merge window delivered a comprehensive set of improvements, with a strong emphasis on security (filehandle signing), memory safety (xdrgen conversion), and robustness (pNFS layout handling). The successful integration of these changes underscores the ongoing commitment to enhancing the reliability and security of the Linux NFS server.
