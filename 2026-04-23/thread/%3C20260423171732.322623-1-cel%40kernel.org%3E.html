NFSD: Fix YNL Spec Breakage in Cache Dump Operations

Summary

NFSD: Fixing YNL Spec Breakage in Cache Dump Operations

Type: Bug Fix
Status: Applied to nfsd-next

Overview

A critical build-breaking bug in the NFS server (NFSD) netlink interface specifications was identified and resolved this week. The issue affected the tools/net/ynl code generation when building against the -next tree, stemming from incorrect merge conflict resolution in YAML specification files for sunrpc and nfsd caches.

The Problem

The new "get-reqs dump" operations added to sunrpc_cache.yaml and nfsd.yaml incorrectly placed the "requests" nested attribute under dump.request. As Chuck Lever explained, a netlink dump carries an empty request, with its payload traveling back in the reply. Because the specifications named no reply attributes, the YNL C code generator synthesized forward references to <op>_rsp structs that were never defined, breaking any consumer of these specs.

This first surfaced when Thorsten Leemhuis attempted to build tools/net/ynl:

nfsd-user.h:746: error: field 'obj' has incomplete type
struct nfsd_svc_export_get_reqs_rsp obj ...
nfsd-user.h:826: error: field 'obj' has incomplete type
struct nfsd_expkey_get_reqs_rsp obj ...
nfsd-user.c:1211: error: 'nfsd_svc_export_get_reqs_rsp_parse' undeclared

Leemhuis reported the issue, noting that sunrpc_cache.yaml had the same defect in ip-map-get-reqs and unix-gid-get-reqs, but nfsd.yaml errors out first due to alphabetical build order, hiding the sunrpc failures.

The Fix

Chuck Lever submitted a patch NFSD: Put cache get-reqs dump attrs under reply that corrected the attribute placement in both Documentation/netlink/specs/nfsd.yaml and Documentation/netlink/specs/sunrpc_cache.yaml, along with corresponding changes in fs/nfsd/netlink.c and net/sunrpc/netlink.c.

Lever acknowledged the root cause:

'Twas my own damn fault: it was a merge-resolution-gone-wrong.

Resolution

Thorsten Leemhuis tested the fix and confirmed it resolved the build issues:

Thx for the quick fix, this makes things work.
Tested-by: Thorsten Leemhuis linux@leemhuis.info

Chuck Lever applied the patch to nfsd-next shortly after receiving the test confirmation. Jeff Layton also weighed in, expressing appreciation for the timely resolution:

Many thanks! I was just sitting down to look at Thorsten's mail.

Significance

This fix ensures that the netlink interface specifications for NFSD and sunrpc caches are correctly structured, allowing proper code generation by YNL tools. It highlights the importance of careful merge conflict resolution when maintaining YAML specification files that drive C code generation.
