Summary

Proposal for Eregex Support in nfsmount.conf Server Sections

This week, Lionel Cons initiated a discussion regarding configuration management challenges in large-scale NFS deployments, specifically proposing the addition of POSIX extended regular expression (eregex) support to the [ Server "Server_Name" ] sections of /etc/nfsmount.conf.

The Problem: Configuration Scalability

Cons highlighted that managing NFS client configurations becomes unmanageable when dealing with a massive number of servers, such as in Kubernetes environments or setups with approximately 15,000 NFS server machines. He described the current state of /etc/nfsmount.conf under these conditions as "a great mess."

"It is a great mess with /etc/nfsmount.conf when you have Kubernetes, or just lots of NFS servers, say 15000 NFS server machines." Lionel Cons

The Proposal

Cons asked if it would be possible to implement POSIX extended regular expressions for server name matching within the configuration file. This feature would allow administrators to define a single configuration block that applies to multiple servers matching a pattern, rather than requiring explicit entries for each individual server.

"Would it be possible to support POSIX extended regular expressions for [ Server "Server_Name" ]? ... POSIX eregex matching would reduce the pain a lot." Lionel Cons

Discussion Status

The thread consists of two messages from Lionel Cons: the initial proposal on April 20, and a repost on April 21 due to a forwarding issue with the mailing list. As of the end of this week's window, there were no responses from NFS developers or maintainers recorded in this thread. The discussion remains an open feature request without technical feedback or implementation plans from the core team.
