NFS: Fix RCU and tracing pointer safety warnings

Summary

This thread covers a two-patch series from Sean Chang addressing Sparse static analysis warnings in the NFS client, specifically concerning RCU safety and pointer attributes. The discussion is focused on bug fixes to improve kernel code correctness and suppress false-positive or legitimate static analysis errors.

Patch 1: Tracing Pointer Safety

The first patch addresses a warning in fs/nfs/nfstrace.h related to the nfs_page_class tracepoint. Sean Chang explained that the req field was marked with the __private attribute, which caused Sparse to complain about "dereferencing a private pointer within the trace ring buffer context, specifically during the TP_fast_assign() operation."

The fix involved simply removing the redundant __private attribute. This approach was refined from previous versions; as noted in the cover letter v2 changes, "Instead of changing the 'req' field type to unsigned long (as in v1), simply remove the redundant __private attribute. This resolves the Sparse warning while preserving the original pointer type."

Benjamin Coddington provided a Reviewed-by tag for this patch here.

Patch 2: RCU Dereference Safety

The second, more significant patch fixes an unsafe dereference in fs/nfs/super.c. The function nfs_compare_super_address() was accessing cl_xprt, which is marked as __rcu in struct rpc_clnt, without proper RCU protection. This triggered Sparse warnings and represented a potential race condition, as the transport can be updated via transport switching even while the superblock remains active under sb_lock.

Sean Chang implemented the fix by wrapping the access with rcu_read_lock() and using rcu_dereference(). The evolution of this patch saw significant refinement based on reviewer feedback:

"Following reviewer feedback, the RCU critical section is kept minimal, covering only the transport and network namespace checks." Cover letter

Furthermore, in v3, unnecessary checks were removed:

"Removed the redundant XPRT_CONNECTED and pointer existence checks as suggested by Benjamin Coddington. Since the comparison is performed while holding sb_lock, the transport's existence is guaranteed, and its connection state does not affect the server's identity." Cover letter

Benjamin Coddington reviewed and approved this patch as well, adding his Reviewed-by tag here.

Conclusion

Both patches were accepted with reviews from Benjamin Coddington. The series successfully addresses static analysis warnings while ensuring correct RCU usage in the NFS client, particularly around superblock comparison logic which is critical for mount management across network namespaces.
