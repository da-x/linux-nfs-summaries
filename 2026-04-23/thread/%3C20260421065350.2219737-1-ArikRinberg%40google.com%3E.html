NFS: Flag files as supporting FMODE_NOWAIT for io_uring performance

Summary

Overview

This thread consists of a single initial patch submission by Arik Rinberg from Google, proposing that the NFS client flag opened files as supporting FMODE_NOWAIT. As of the end of this week's window (2026-04-23), no replies or reviews have been posted to this thread.

The Patch: Enabling Non-Blocking I/O Awareness for NFS

On 2026-04-21, Arik Rinberg submitted a minimal one-line change to fs/nfs/file.c that sets the FMODE_NOWAIT flag in filp->f_mode when opening an NFS file. The patch is framed as a performance fix for asynchronous I/O workloads using io_uring.

The Problem

Rinberg explains the motivation clearly:

"Without this flag, asynchronous I/O frameworks like io_uring assume that the file system does not support non-blocking I/O. This causes io_uring to punt all I/O operations to background io-wq worker threads to avoid blocking the main ring. This results in performance degredation."

In other words, without FMODE_NOWAIT, io_uring treats NFS as a filesystem incapable of non-blocking I/O and falls back to offloading all I/O to worker threads — an unnecessary indirection that degrades performance for NFS workloads leveraging io_uring.

The Fix

"By setting FMODE_NOWAIT, we inform the VFS that NFS supports asynchronous I/O natively, keeping execution on the fast path and restoring performance."

The patch is a straightforward one-line modification to the NFS file open path, asserting that NFS files support the FMODE_NOWAIT mode. Rinberg links to a liburing issue for additional context on this problem in the io_uring ecosystem.

Classification

This is a bug fix / performance optimization rather than a new feature or protocol change. The NFS client already supports asynchronous I/O operations at the protocol level; the issue is that the VFS layer was not informed of this capability, causing io_uring to take an unnecessarily slow code path.

Context and Related Work

This patch sits within a broader kernel-wide effort around IOCB_NOWAIT and FMODE_NOWAIT support. Related prior discussions include Christoph Hellwig's multi-version series on "re-enable IOCB_NOWAIT writes to files" (dating back to late 2025), indicating ongoing work across the VFS and filesystem layers to properly expose non-blocking I/O capabilities.

Current Status

As of this week's cutoff, the patch has been submitted but has not yet received any reviews, acknowledgments, or objections from NFS maintainers or the broader community. The discussion remains open for next week's window.
