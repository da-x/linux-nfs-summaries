Exposing Case Folding Behavior to NFS and SMB Servers (v10)

Summary

Overview

Chuck Lever submitted version 10 of a significant patch series, [PATCH v10 00/17] Exposing case folding behavior [id://20260423-case-sensitivity-v10-0-c385d674a6cf@oracle.com], aimed at enabling Linux file services (NFSD and ksmbd) to accurately report the case-folding semantics of underlying local filesystems. This is a new feature implementation that bridges VFS, local filesystems, and network file server protocols.

The series addresses interoperability challenges for NFS clients on non-POSIX systems (Windows, macOS), where filename behavior differs from traditional POSIX semantics. As Chuck Lever explained:

"The Linux NFS community has a growing interest in supporting NFS clients on Windows and MacOS platforms, where file name behavior does not align with traditional POSIX semantics."

Key Technical Arguments

VFS Infrastructure Changes

The series introduces two new flags, FS_XFLAG_CASEFOLD and FS_XFLAG_CASENONPRESERVING, to the file_kattr structure [id://20260423-case-sensitivity-v10-2-c385d674a6cf@oracle.com]. These flags allow filesystems to report:

  • Case-insensitivity: Whether lookups ignore case differences.
  • Case-nonpreserving: Whether the filesystem alters the case of stored filenames.

The default behavior (flags unset) reflects standard POSIX semantics: case-sensitive and case-preserving.

Local Filesystem Implementations

Patches 03/17 through 14/17 implement fileattr_get for case sensitivity across numerous filesystems, including:

  • FAT/exFAT: Case-insensitive by default; FAT respects the nocase mount option.
  • NTFS/HFS/HFS+: Case-insensitive with case preservation.
  • ext4/f2fs: Per-directory case folding support.
  • XFS: Reports case sensitivity based on the ASCIICI feature flag.
  • CIFS/vboxsf/isofs: Report case handling based on mount options and host properties.

NFS Client Development (Patch 11/17)

The NFS client patch [id://20260423-case-sensitivity-v10-11-c385d674a6cf@oracle.com] is critical for re-export scenarios. It enables the NFS client to expose case sensitivity information retrieved from servers via:

  • NFSv3: PATHCONF attributes
  • NFSv4: FATTR4_CASE_INSENSITIVE and FATTR4_CASE_PRESERVING

Chuck Lever highlighted a key behavioral change:

"PATHCONF is now invoked unconditionally for NFSv2 and NFSv3 mounts so the case-sensitivity capabilities are established even when the user pins server->namelen with the namlen= mount option."

This ensures that case-sensitivity capabilities are always probed, regardless of other mount options. The patch also clarifies the polarity of capability bits:

"The two capability bits carry opposite polarity because their POSIX defaults differ... NFS_CAP_CASE_INSENSITIVE is set only when the server affirms case insensitivity, so 'server said no' and 'server did not answer' both collapse to the case-sensitive default."

NFS Server (NFSD) Changes

Patches 15/17 and 16/17 enable NFSD to report case-folding behavior via:

  • NFSv3: PATHCONF responses
  • NFSv4: FATTR4_CASE_INSENSITIVE and FATTR4_CASE_PRESERVING attributes

This allows NFS clients, particularly Windows-based implementations like ms-nfs41-client, to optimize lookups and avoid issuing multiple requests for case variants.

Evolution of the Discussion

Community Feedback

Roland Mainz, maintainer of the ms-nfs41-client project, validated the series:

"Looks good to me. It also works with ms-nfs41-client, therefore: Reviewed-by: Roland Mainz" [id://CAKAoaQnfCVGHPx0RP8C8YkpqtPZZOU98kxKm=Nv0b1bMBWFn8w@mail.gmail.com]

Steve French raised a question regarding the CIFS implementation [id://CAH2r5mu1Wg_9tZCjei-xF357UjKR+h6jQr9zey39v59rx9quZQ@mail.gmail.com]:

"Should this also be checking if the SMB3.1.1 Linux Extensions or SMB POSIX Extensions are negotiated (ie the server supports case sensitivity)?"

This suggests a potential refinement for the CIFS patch in future versions, ensuring that case sensitivity reporting accounts for negotiated SMB extensions.

Final Conclusions

The v10 series represents a mature implementation of case-folding exposure across the Linux VFS stack. Key takeaways include:

  1. Improved Interoperability: Windows and macOS NFS clients can now rely on accurate case-sensitivity reporting from Linux servers, reducing lookup overhead and improving application compatibility.
  2. Re-export Support: The NFS client's new fileattr_get implementation enables transparent re-export of case-folding semantics, critical for multi-protocol environments.
  3. Broad Filesystem Coverage: Over a dozen filesystems now report case sensitivity, ensuring consistent behavior across diverse storage backends.
  4. Pending Refinement: Steve French's question regarding SMB POSIX extensions may lead to adjustments in the CIFS patch before final merge.

This series lays the groundwork for seamless integration of NFS and SMB services in heterogeneous environments, where accurate filename semantics are essential for correct operation.
