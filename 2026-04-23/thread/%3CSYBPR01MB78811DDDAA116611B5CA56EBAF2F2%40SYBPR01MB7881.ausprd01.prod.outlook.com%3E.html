pnfs/flexfiles: Fix NULL deref on zero version_count in GETDEVICEINFO

Summary

pnfs/flexfiles: Reject Zero version_count in GETDEVICEINFO

Classification

Bug fix — NFS client (pNFS FlexFiles layout driver)

Overview

This week, Junrui Luo submitted a targeted bug fix for the Linux NFS client's pNFS FlexFiles layout driver. The patch addresses a NULL pointer dereference vulnerability triggered when a server returns a version_count of zero in a GETDEVICEINFO response. The issue was reported by Yuhao Jiang and is marked for stable kernel backporting.

Technical Details

The bug resides in nfs4_ff_alloc_deviceid_node(), which parses flexfiles device addresses from a GETDEVICEINFO response. As described by Luo:

"nfs4_ff_alloc_deviceid_node() parses the flexfiles device address from a GETDEVICEINFO response and passes version_count to kzalloc_objs() without validating it is non-zero."

When version_count is zero, kzalloc_objs() returns ZERO_SIZE_PTR, which bypasses the subsequent NULL check. This leads to a crash when the layout driver later attempts to access device data:

"This leads to a NULL pointer dereference when nfs4_ff_layout_ds_version() later accesses ds_versions[0] through the ZERO_SIZE_PTR."

The fix is straightforward: reject version_count == 0 before the allocation, preventing the invalid memory state from propagating. The patch adds five lines to fs/nfs/flexfilelayout/flexfilelayoutdev.c.

Key Points

  • Root cause: Missing validation of version_count from server responses in the FlexFiles layout driver.
  • Impact: NULL pointer dereference and potential kernel crash when processing malformed or edge-case GETDEVICEINFO responses.
  • Fix: Early rejection of zero version_count before memory allocation as implemented by Junrui Luo.
  • Stability: The patch includes Cc: stable@vger.kernel.org, indicating it should be backported to maintained stable kernel branches.

Conclusion

This is a classic defensive programming fix: validating input from network responses before using them in memory allocations. By rejecting zero version_count values, the NFS client avoids a subtle but dangerous edge case involving ZERO_SIZE_PTR. The patch is small, well-documented, and addresses a real-world bug reported by Yuhao Jiang, demonstrating ongoing maintenance of the FlexFiles layout driver's robustness.
