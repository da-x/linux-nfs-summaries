fsnotify: Review of CB_NOTIFY Infrastructure Patches

Summary

This week's activity on the directory delegation thread was minimal, consisting of two review messages from SUSE's Jan Kara. These messages provided "Reviewed-by" tags for two infrastructure patches within Jeff Layton's larger 28-patch series to add CB_NOTIFY callback support for NFS directory delegations. The discussion is part of a new feature effort aimed at improving NFS client caching efficiency by allowing servers to notify clients of directory changes without recalling delegations.

Key Technical Arguments and Evolution

As established in the prior week's summary, Layton's series introduces significant VFS and NFSd changes to support RFC8881bis CB_NOTIFY callbacks. This week, Jan Kara reviewed two specific fsnotify-related patches that serve as foundational infrastructure for the feature:

1. New Tracepoint in fsnotify() (PATCH v2 05/28)

Layton added a tracepoint to the fsnotify() function to improve visibility into how notifications are dispatched. This aids in debugging and performance analysis for lease-breaking and notification events. Jan Kara approved the patch without comment on technical merit, stating:

"Looks good. Feel free to add:

Reviewed-by: Jan Kara jack@suse.cz"

2. New FSNOTIFY_EVENT_RENAME Data Type (PATCH v2 07/28)

This patch introduces a new fsnotify_rename_data struct and the FSNOTIFY_EVENT_RENAME data type. This enhancement allows fsnotify events to carry information about both the moved dentry and the inode that was overwritten during a rename operation—a requirement for cross-directory rename events in NFS directory delegations.

Jan Kara similarly approved this patch:

"Looks good. Feel free to add:

Reviewed-by: Jan Kara jack@suse.cz"

Final Conclusions

  • Both patches received Reviewed-by tags from Jan Kara, a key maintainer for fsnotify and VFS-related code. This indicates acceptance of the infrastructure changes required for the CB_NOTIFY feature.
  • No new technical debates or bug fixes emerged this week; the activity was purely review-oriented.
  • The broader series remains pending full client-side implementation before merging, as noted in last week's summary:

"I don't think we'll want to merge these until we have a complete client-side implementation to test against."

These reviews represent incremental progress toward the larger goal of enabling efficient directory delegation notifications in NFSv4.
