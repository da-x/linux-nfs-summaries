NFSD Block Layout Export Cleanup and Netlink Spec Bug Fix

Summary

This week's activity centered on a significant refactoring of the NFS server's (NFSD) block-style layout export infrastructure, alongside a critical bug fix for netlink cache specifications. The discussion was driven by Chuck Lever and Christoph Hellwig, with review from Jeff Layton.

Block-Style Layout Export Cleanup

Chuck Lever submitted v3 of a patch series originally authored by Christoph Hellwig to clean up how NFSD handles block-style layouts, which allow NFS clients to access block devices directly.

"Christian prefers to see them taken through the VFS tree," Chuck Lever noted, indicating that once these patches are merged into the VFS subsystem, they will be rebased and dropped from the NFS trees to avoid duplication.

The series introduced four key changes:

  1. Timestamp Handling: In Patch 1/4, Christoph Hellwig removed the handling of loca_time_modify in NFSD. He justified this by citing the NFSv4.2 specification:

    "RFC 8881 Section 18.42 makes it clear that the client provided timestamp is a 'may' condition, and clients that want to force a specific timestamp should send a separate SETATTR in the compound."

    Since XFS—the only filesystem currently supporting block layout exports—uses multi-grain timestamps and already ignores these values at the VFS layer, Hellwig argued it was cleaner to make this explicit in NFSD.

  2. Architectural Separation: Patch 2/4 split the operations for layout-based block device access into a new header, include/linux/exportfs_block.h. This separates the low-level block layout logic from general export operations, reducing coupling and "bloating" of the superblock structure.

  3. Interface Simplification: Patch 3/4 simplified the ->commit_blocks callback by removing the unnecessary struct iattr argument. Hellwig noted that the callback only ever needs the new file size to extend the underlying block device, making the full attribute structure redundant.

  4. Support Checks: Patch 4/4 reworked how NFSD checks for layout support by lifting hard-coded checks into filesystem helpers and providing a generic exportfs-level helper. This prepares the infrastructure for future support of multiple devices per filesystem.

Netlink Spec Bug Fix

Interwoven with the cleanup series was a standalone bug fix patch titled "[PATCH] NFSD: Put cache get-reqs dump attrs under reply" submitted by Chuck Lever.

This patch addressed a regression that broke the build of tools/net/ynl (the YNL C code generator) when Thorsten Leemhuis attempted to compile it against -next. The error manifested as incomplete type definitions for response structures in nfsd-user.h.

Lever traced the issue to the placement of nested attributes in the netlink specification files (nfsd.yaml and sunrpc_cache.yaml). Because netlink dumps carry payloads in replies rather than requests, the "requests" attribute was incorrectly placed.

"These bugs were introduced by incorrect merge conflict resolution," Lever explained.

The fix moved the attributes under the correct reply structures, resolving the build errors for consumers of these specs. Jeff Layton provided a Reviewed-by tag for this correction in his response.

Conclusion and Status

The thread concluded with a procedural note from Chuck Lever. After realizing an error in his submission (likely related to the cover letter or patch formatting), he asked the list to disregard the current posting:

"Damn it. Ignore this, I will try again," Lever wrote.

While the immediate submission was withdrawn for correction, the technical consensus remains: the block layout exports require architectural separation to support future multi-device scenarios, and the netlink spec definitions must be corrected to ensure developer tooling remains functional.
