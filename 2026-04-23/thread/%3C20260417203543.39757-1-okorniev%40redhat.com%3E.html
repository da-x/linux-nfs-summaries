NFSv4.2: Fix CLONE/COPY Attribute Updates with Delegated Attributes (PATCH v5)

NFSv4.2: Fix CLONE/COPY Attribute Updates with Delegated Attributes (PATCH v5)

Summary

Type: Bug fix in the NFS client for NFSv4.2 CLONE and COPY operations when delegated attributes are present.

Overview

Olga Kornievskaia submitted PATCH v5 1/1 titled "NFSv4.2: fix CLONE/COPY attrs in presence of delegated attributes" on April 17, 2026. This is the fifth and latest iteration of a patch addressing failures in the xfstest generic/407 test suite related to incorrect timestamp handling during NFSv4.2 CLONE and COPY operations when the client holds delegated attributes.

Prior Context

This thread follows directly from PATCH v4, submitted earlier on the same day (April 17). The v5 submission represents a minor but important refinement in the placement of the fix, as noted in the changelog:

"v5 change nfs_update_delegated_mtime() placement" — Olga Kornievskaia in her patch cover letter

The Problem

The issue manifests in two ways, both detected by xfstest generic/407:

  1. Missing mtime/ctime updates after CLONE: When a CLONE operation is performed, the server sends a GETATTR response, and the client calls nfs_post_op_update_inode() based on the returned attributes. However, because delegated attributes are present, the client ignores updating the modification time (mtime).

  2. Stale change_attr values: When delegated attributes are present, the server replies with change_attr values identical to what the client had cached previously, causing the test to flag a discrepancy.

"xfstest generic/407 is failing in 2 ways. It detects that after doing a clone the client does not update it's mtime and it's ctime." — Olga Kornievskaia in her patch cover letter

The Fix

The patch addresses the issue by ensuring that delegated attributes are properly invalidated and updated after CLONE and COPY operations:

"Instead, make sure we invalidate the blocks attr." — Olga Kornievskaia in her patch cover letter

The key technical change involves adding delegated attribute updates in nfs42_copy_dest_done(), which ensures that both COPY and CLONE operations update mtime appropriately:

"By adding updating delegated attributes in nfs42_copy_dest_done() both COPY and CLONE would update mtime appropriately." — Olga Kornievskaia in her patch cover letter

The v5 patch is notably minimal, modifying fs/nfs/nfs42proc.c with just 1 insertion — a significant simplification from the more invasive v4 approach. This consolidation was achieved by:

"v4 this version removes the need for having 'NFSv4.2: fix COPY attrs in presence of delegated timestamps'" — Olga Kornievskaia in her patch cover letter

The patch references commit e12912d94137 ("NFSv4: Add support for delegated atime and mtime attributes") as the original source of the regression, indicating that the introduction of delegated attribute caching inadvertently broke proper timestamp updates after server-side copy operations.

Evolution of the Patch

The patch has evolved through five versions:

  • v4 consolidated CLONE and COPY fixes into a single patch by updating delegated attributes in nfs42_copy_dest_done(), eliminating the need for a separate COPY-specific fix.
  • v5 refined the placement of the nfs_update_delegated_mtime() call, resulting in a cleaner, more minimal change (1 line insertion vs. v4's 9 insertions and 1 deletion).

Conclusion

As of this week's window, no replies or review comments were posted to this thread. The patch is awaiting maintainer review and potential merge into the NFS client tree. This fix is important for ensuring correctness of NFSv4.2 space-efficient cloning and offline copying features when delegation-based caching is active — a common scenario in production NFS deployments.
