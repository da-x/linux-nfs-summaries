OPENAT2_REGULAR flag: awaiting linux-next push and -rc1 merge

Summary

This week marked the quiet final administrative steps for the OPENAT2_REGULAR patch series (v6), which introduces a new UAPI feature allowing applications to explicitly request opening only regular files via openat2(). Last week, VFS maintainer Christian Brauner applied the series to the vfs-7.2.openat.regular branch on April 16. This week's activity consisted of a brief exchange regarding when the patches would become visible in linux-next.

Bridge from Prior Weeks

Over the preceding weeks, the series underwent thorough review. Jeff Layton provided a Reviewed-by tag after clarifying concerns about Ceph and GFS2 atomic open paths. The discussion then shifted to UAPI design details—specifically whether OPENAT2_REGULAR should reside in the legacy 32-bit O_* flag space—and ultimately concluded with Brauner's application of the patches. The NFS client implementation, which includes checks in fs/nfs/dir.c, was part of this accepted patch set, enabling robust support for strict regular-file opens within the nfs_atomic_open codepath.

The message body was empty, indicating that Sarai considered the matter resolved or had no further additions to make.

Conclusion

The OPENAT2_REGULAR patch series has been fully reviewed and applied to the VFS tree, awaiting the standard -rc1 push to become visible in linux-next.

Classification: New Feature (UAPI addition). No bug fixes were discussed this week.

Implications for NFS Client Development: The NFS client benefits from this new feature by gaining VFS-level validation for strict regular-file opens. When an application uses openat2() with OPENAT2_REGULAR on an NFS mount, the kernel will now reliably return -EFTYPE if the target is a directory, device node, or other non-regular file type, enhancing security and correctness for applications relying on atomic open paths.
