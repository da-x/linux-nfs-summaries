nfsd/sunrpc netlink series breaks tools/net/ynl build in -next

Summary

nfsd/sunrpc: Netlink upcall series breaks tools/net/ynl build in -next

Classification

This is a build regression / bug report triggered by the recently applied netlink upcall series for NFS server caches. The issue affects the kernel's tools/net/ynl (YANGL — Yet Another Netlink Generator) user-space tooling, which generates C code from netlink YAML specifications.

Background (Brief)

Jeff Layton's 13-patch series "nfsd/sunrpc: add support for netlink upcalls for mountd/exportd" was submitted as v2 on March 25 and applied to nfsd-testing by Chuck Lever on April 2. The series replaces /proc-based cache pipe interfaces with generic netlink for mountd/exportd communication, covering the auth.unix.ip, auth.unix.gid, svc_export, and nfsd.fh caches. After a minor review fix regarding an unused attribute set in Patch 10/13, the full series landed without further controversy.

This Week: Build Breakage Reported

On April 23, Thorsten Leemhuis reported that the netlink patches had surfaced in -next and broken the build of tools/net/ynl, a kernel self-test tooling suite that generates C bindings from YAML netlink specs:

"This afaics showed up in -next today and seems to have broken compiling tools/net/ynl for me." — Thorsten Leemhuis

The Errors

The compilation failures centered on the nfsd-user.c generated source file, with errors including:

  • Incomplete type errors: Fields named obj in response structures had incomplete types (e.g., struct nfsd_svc_export_get_reqs_rsp obj).
  • Undeclared parser functions: Symbols like nfsd_svc_export_get_reqs_rsp_parse and nfsd_expkey_get_reqs_rsp_parse were missing.
  • Type mismatch errors: Functions returning void * where int was expected (return yds.first;, return NULL;).

These errors appeared across multiple architectures (x86_64, aarch64, ppc64).

Root Cause Hypothesis

Leemhuis identified six commits from the series as culprits and reverted them in reverse order to restore the build:

  1. 257dc1227d07be — "nfsd: add NFSD_CMD_CACHE_FLUSH netlink command"
  2. 22f99c05b145e7 — "sunrpc: add SUNRPC_CMD_CACHE_FLUSH netlink command"
  3. 97fa24739b5566 — "nfsd: add netlink upcall for the nfsd.fh cache"
  4. dd8015e766e639 — "nfsd: add netlink upcall for the svc_export cache"
  5. d1b8115657acdf — "sunrpc: add netlink upcall for the auth.unix.gid cache"
  6. 1045ccf519ce30 — "sunrpc: add netlink upcall for the auth.unix.ip cache"

He noted a key observation about which patches might be safe:

"I reverted all patches that modified Documentation/netlink/specs/ in reverse order, so maybe all except the last one in the list above are fine." — Thorsten Leemhuis

This suggests the issue may lie specifically in how the YAML netlink specifications for the svc_export and nfsd.fh caches define response structures — potentially missing proper dump/response type definitions that ynl requires to generate complete C code.

Significance for NFS Development

While this series targets the NFS server side rather than the client, it is relevant to the broader NFS ecosystem:

  1. Tooling compatibility: The tools/net/ynl suite is used by kernel developers to validate netlink interfaces and generate test tools. A build break here blocks CI testing for any netlink-related changes in the tree.
  2. Container support: The netlink upcall mechanism eliminates /proc dependencies, enabling NFS server daemons in containers — a growing deployment model.
  3. No client-side impact: The NFS client code is unaffected by this series; the changes are confined to nfsd and sunrpc cache management.

Current Status

As of the end of this week's window, no response from Jeff Layton or Chuck Lever has appeared addressing the build breakage. The issue remains open and requires investigation into whether the YAML netlink specs need adjustments for ynl compatibility, or whether ynl itself needs updates to handle the new spec patterns introduced by the series.
