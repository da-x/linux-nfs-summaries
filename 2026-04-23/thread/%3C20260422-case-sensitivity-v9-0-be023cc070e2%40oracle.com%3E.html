Exposing Case Folding Behavior: VFS, NFSD, and ksmbd Updates

Summary

Exposing Case Folding Behavior to File Services

This week, the Linux NFS mailing list saw the successful application of Chuck Lever's nine-patch series [PATCH v9 00/17] Exposing case folding behavior Cover Letter. The series introduces a standardized mechanism for the Linux VFS to expose filesystem case-sensitivity and case-preservation semantics to user-space applications and in-kernel file services like NFSD and ksmbd.

Technical Overview: A New VFS Interface

The core of the patchset adds two new flags, FS_XFLAG_CASEFOLD and FS_XFLAG_CASENONPRESERVING, to the file_kattr structure Patch 02/17. These flags are exposed via the ->fileattr_get() inode operation, allowing upper layers to query whether a filesystem performs case-insensitive lookups and whether it preserves filename casing at rest.

To support this, Lever first refactored the initialization of file_kattr in the VFS layer Patch 01/17, ensuring that filesystem-specific handlers could populate these new flags without them being clobbered by memset operations in generic fill functions.

The series implements ->fileattr_get() for a wide array of local and network filesystems, including FAT, exFAT, NTFS3, HFS/HFS+, ext4, XFS, f2fs, vboxsf, ISO9660, CIFS, and NFS Patches 03-14/17.

Impact on NFS Client and Server Development

For the NFS subsystem, this series addresses a long-standing interoperability gap. Lever noted in the cover letter that Windows-based NFS clients explicitly require servers to report FATTR4_WORD0_CASE_INSENSITIVE = TRUE for proper operation, as Windows applications expect case-insensitive behavior.

NFSD Updates: Previously, NFSD provided hard-coded responses indicating all exported filesystems were case-sensitive and case-preserving. This was incorrect for case-insensitive filesystems (like FAT or exFAT) and ext4 directories with casefold enabled. The series updates NFSD to query the underlying filesystem's actual case sensitivity via nfsd_get_case_info() Patch 15/17 and returns accurate values for both NFSv3 PATHCONF Patch 15/17 and NFSv4 FATTR4_CASE_INSENSITIVE/FATTR4_CASE_PRESERVING attributes Patch 16/17.

NFS Client Updates: The NFS client also receives updates to expose case sensitivity information retrieved from servers during mount (via PATHCONF or GETATTR) through the fileattr_get interface Patch 11/17. This is critical for re-export scenarios, where an NFS server re-exporting an NFS mount point needs to accurately convey the case handling semantics of the underlying filesystem to its own clients. Lever highlighted that this enables multi-protocol environments (serving both NFS and SMB clients) to work more smoothly, as the NFS client can adapt to the case folding behavior SMB users expect.

ksmbd Integration

In parallel, the in-kernel SMB server (ksmbd) was updated to report filesystem case sensitivity via FS_ATTRIBUTE_INFORMATION Patch 17/17. Previously, ksmbd unconditionally reported FILE_CASE_SENSITIVE_SEARCH and FILE_CASE_PRESERVED_NAMES, which was inaccurate for case-insensitive filesystems. The patch now translates the new VFS flags into the corresponding SMB attributes.

Discussion and Review

The series received positive feedback from key maintainers:

  • Darrick J. Wong provided a Reviewed-by for the initial VFS refactoring Reply.
  • Steve French (CIFS maintainer) Acked the CIFS implementation and inquired about xfstest coverage Reply.

Lever responded that while no existing xfstests would flip from "notrun" to "run" solely due to this change, the implementation quiets noise in fsstress by returning success instead of ENOTTY. He noted that enabling the existing case-folding test (generic/556) on CIFS would require a separate generalization of the test infrastructure Reply.

Conclusion

Christian Brauner applied the entire 17-patch series to the vfs/vfs.git tree Reply, marking a significant step forward in Linux's ability to accurately expose filesystem semantics to network protocols. This work resolves incorrect case-sensitivity reporting bugs in NFSD and ksmbd, paving the way for better interoperability with non-POSIX clients like Windows and macOS.
