NFS: Fix RCU and tracing pointer safety issues

Summary

This week, Sean Chang submitted a two-patch series, [PATCH v2 0/2] NFS: fix RCU and tracing pointer safety, addressing Sparse static analysis warnings in the NFS client related to RCU safety and pointer attributes. The discussion focused on correcting unsafe dereferences and redundant attribute annotations, with key feedback from reviewer Benjamin Coddington.

Patch 1: Tracing Pointer Attribute Cleanup

The first patch, [PATCH v2 1/2] NFS: remove redundant __private attribute from nfs_page_class, addressed a Sparse warning regarding the nfs_page_class tracepoint. The req field was marked with the __private attribute, causing Sparse to complain about dereferencing a private pointer within the trace ring buffer context during TP_fast_assign().

Sean Chang explained that this warning was introduced by commit b6ef079fd984 ("nfs: more in-depth tracing of writepage events"). The fix involved simply removing the redundant __private attribute. Benjamin Coddington reviewed and approved this change, stating:

"Reviewed-by: Benjamin Coddington bcodding@hammerspace.com"

Patch 2: RCU Safety in Superblock Comparison

The second patch, [PATCH v2 2/2] NFS: Fix RCU dereference of cl_xprt in nfs_compare_super_address, targeted an unsafe access of the cl_xprt pointer in struct rpc_clnt, which is marked as __rcu. Direct access in nfs_compare_super_address() triggered Sparse warnings.

Sean Chang proposed wrapping the access with rcu_read_lock() and rcu_dereference() to ensure memory safety. Additionally, he included checks for the XPRT_CONNECTED state bit and null pointers, arguing that while RCU guarantees memory validity, these checks ensure the transport is logically active:

"Additionally, add a check for the XPRT_CONNECTED state bit. While RCU guarantees the memory remains valid, checking XPRT_CONNECTED ensures the transport is still logically active, preventing operations on a transport that is already undergoing teardown."

Review and Refinement

Benjamin Coddington acknowledged the RCU fix but questioned the necessity of the additional state checks:

"This is a good fix for the sparse warning, but.. I really don't think this check is necessary. Aren't we only ever comparing with one freshly created, and the other looked up holding sb_lock? I'm doubtful this hunk is fixing a real problem."

Sean Chang agreed with the assessment after tracing the call path. He confirmed that nfs_compare_super() is called by sget_fc() while holding the global sb_lock, which ensures the stability of existing superblocks and their transports during comparison. Consequently, he decided to remove the redundant checks:

"Since the connection state doesn't affect the identity of the server, I'll remove the redundant test_bit and pointer checks and send out v3."

Conclusion

The thread concluded with a consensus on the technical approach:

  1. The tracing attribute fix was accepted as-is.
  2. The RCU dereference fix is valid, but the additional XPRT_CONNECTED checks are unnecessary due to existing locking guarantees. Sean Chang planned to submit a v3 of the patch series reflecting this simplification.

This discussion highlights ongoing efforts in NFS client development to maintain strict compliance with kernel static analysis tools (Sparse) and RCU semantics, ensuring robustness in superblock management and tracing infrastructure.
