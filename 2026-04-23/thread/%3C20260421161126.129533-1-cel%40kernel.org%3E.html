sunrpc: Fix out-of-bounds read in cache sequence iteration

Summary

sunrpc: Prevent Out-of-Bounds Read in __cache_seq_start()

Type: Bug Fix (Memory Safety) Component: NFS/SunRPC Cache Subsystem (net/sunrpc/cache.c) Reporter: syzbot (via Chuck Lever)

Overview

This thread addresses a critical memory safety bug in the SunRPC cache subsystem, specifically an out-of-bounds (OOB) read vulnerability in the sequence file iteration logic. The issue was identified by syzkaller and patched by Chuck Lever, with reviews from Benjamin Coddington and NeilBrown.

Technical Details

The bug was introduced by commit 7b546bd89975 ("sunrpc/cache: improve RCU safety in cache_list walking."), which modified the tail of __cache_seq_start() to unconditionally store a position value:

*pos = ((long long)hash << 32) + 1

This change removed a prior guard that checked if hash >= cd->hash_size. As Chuck Lever explained in his patch submission here:

"When the while loop exits because every remaining bucket was empty, hash equals cd->hash_size, so the stored *pos is one position past the table's last valid bucket."

The vulnerability manifests when seq_read_iter() caches this invalid index in m->index. A subsequent pread(2) at the same file offset skips the traverse() function and passes the stored index back to __cache_seq_start(). This causes the kernel to decode hash = cd->hash_size and dereference cd->hash_table[cd->hash_size], resulting in an eight-byte slab-out-of-bounds read past the end of the allocated hash table.

KASAN reported this issue on the NFSD export cache, where the hash table size is 2048 bytes (EXPORT_HASHMAX * sizeof(struct hlist_head) == 256 * 8).

The Fix

Chuck Lever's patch adds a bounds check at the beginning of __cache_seq_start() to reject input hashes that are out of range before accessing the hash table. He noted:

"cache_seq_next() already bounds-checks its own loop; the start routine needs to be symmetric."

This approach ensures that the sequence iteration logic remains robust against invalid indices, preventing the OOB access.

Community Response

The patch received positive feedback from key NFS developers:

  • Benjamin Coddington acknowledged the fix, stating:

    "Thanks!! We were hunting for this one. You'll probably get a Tested-by shortly."

  • NeilBrown reviewed the patch and commented:

    "We could of course avoid ever storing a too-large pos but adding back a test for hash at the end of __cache_seq_start() but I prefer the approach you took as it is more robust."

Conclusion

This fix resolves a syzkaller-reported out-of-bounds read vulnerability in the SunRPC cache subsystem. The patch is small, targeted, and aligns with existing bounds-checking practices in the codebase. It has been reviewed and approved by multiple NFS maintainers, indicating its readiness for inclusion in the kernel tree.
