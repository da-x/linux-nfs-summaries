Summary

NFS client bug fix: missing ida_free() in nfs_alloc_server() error path

Overview

This week the thread that began last week as a Coccinelle-driven cleanup patch evolved into a genuine bug-fix series for the NFS client. Reviewer Christophe Jaillet spotted a real resource leak in the original v1 patch's context, and author Markus Elfring responded promptly with a two-patch v2 series that both fixes the leak and preserves the original cleanup intent. The discussion is squarely about NFS client development (fs/nfs/client.c) and constitutes an important bug fix — specifically a missing ida_free() call in the error path of nfs_alloc_server(), the function that allocates a struct nfs_server on the mount path.

Bridge from prior week

Last week (week ending 2026-06-11), Elfring posted the initial v1 patch on 2026-06-10, a Coccinelle-detected cleanup to consolidate duplicated error-handling labels at the tail of nfs_alloc_server(). No maintainer review or commit had landed by end of that window.

This week's activity

The bug is spotted

On 2026-06-13, well-known kernel reviewer Christophe Jaillet replied to the v1 patch with a concise but critical observation:

"If an error occurs after a successful ida_alloc(), then ida_free() needs to be called in the error handling path."

Jaillet was pointing at the server->s_sysfs_id = ida_alloc(&s_sysfs_ids, GFP_KERNEL) call site. The original code checked for a negative return and freed the server struct, but if a subsequent allocation (e.g., nfs_alloc_iostats()) failed, the already-allocated sysfs ID would leak — it was never returned to the IDA pool. This turned what had been a purely cosmetic refactor into a real resource-leak fix.

The v2 response: two-patch series

The very next morning (2026-06-14), Elfring posted a v2 cover letter and two patches, crediting Jaillet's review:

"Christophe Jaillet pointed out that ida_free() should be called in the error handling path after a successful ida_alloc() call. Thus corresponding tags were added."

The cover letter also references the kernel source for context:

"See also: https://elixir.bootlin.com/linux/v7.1-rc7/source/lib/idr.c#L549-L595"

Patch 1/2 — "Prevent resource leak in nfs_alloc_server()" (link): This is the actual bug fix. Elfring describes it precisely:

"It was overlooked to call ida_free() after a failed nfs_alloc_iostats() call. Thus add the missed function call in an if branch."

The patch carries significant metadata underscoring its importance:

  • Fixes: 1c7251187dc067a6d460cf33ca67da9c1dd87807 ("NFS: add superblock sysfs entries") — tracing the bug back to the commit that originally introduced the sysfs ID allocation.
  • Cc: stable@vger.kernel.org — flagging it for backport to stable trees.
  • Reported-by: Christophe Jaillet, with a Closes link to his review message.

The change is minimal — one insertion in fs/nfs/client.c — adding the missing ida_free() call in the error branch after nfs_alloc_iostats() fails.

Patch 2/2 — "Use common error handling code in nfs_alloc_server()" (link): This carries forward the original v1 intent, now updated to work correctly with the new ida_free() call. The description is unchanged from v1:

"Use an additional label so that a bit of exception handling can be better reused at the end of this function implementation."

"This issue was detected by using the Coccinelle software."

It also carries Cc: stable@vger.kernel.org, and the diff touches 7 insertions / 6 deletions in fs/nfs/client.c.

Technical significance

The bug is subtle but real. nfs_alloc_server() sits on the NFS mount path — every new NFS mount calls it to create the server representation. The sysfs ID allocated via ida_alloc() is a globally unique identifier used for sysfs entries (introduced in commit 1c7251187dc067a). If any allocation after the ida_alloc() call fails (such as nfs_alloc_iostats()), the error path must unwind all previously acquired resources. The missing ida_free() meant that each such failure would permanently leak one ID from the s_sysfs_ids IDA pool. Over time, repeated mount failures could exhaust the available IDs, potentially causing subsequent successful mounts to fail at the ida_alloc() step.

The fix is a textbook example of why error-path auditing matters in kernel code: a single missing cleanup call in a rarely-taken branch can accumulate into a resource exhaustion bug. The Fixes: tag and stable Cc correctly identify this as a regression from a specific upstream commit, making it suitable for backporting.

Broader context

This thread is part of Elfring's ongoing Coccinelle-driven sweep of duplicated error-handling code across the NFS client and server trees. Sibling patches posted in the same period target nfs_sysfs_init() (client) and svc_export_alloc() (nfsd server). The fact that Jaillet's review elevated this particular patch from cleanup to bug fix underscores the value of careful review even for seemingly mechanical changes.

Status

As of the end of the reporting window (2026-06-18), the v2 series has been posted but no maintainer ack, review, or commit is visible in-thread yet. The patches are small, well-scoped, and carry proper Fixes:/Cc: stable tags, so they appear ready for triage by the NFS client maintainers (Trond Myklebust / Anna Schumaker).
