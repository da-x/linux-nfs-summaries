nfsd/sunrpc: netlink conversion of nfsstat server stats lands as v5, adding NFSv4 callback op counts

Summary

nfsd/sunrpc: Convert nfsstat server-side interfaces to netlink (v5)

Summary

On June 18, Jeff Layton posted version 5 of his patch series converting the NFS server-side statistics interface from procfs scraping to a generic netlink dump handler. This is a new feature / interface conversion (server-side, nfsd/sunrpc), with a small behavioral bug fix along the way: the wdeleg_getattr counter's semantics are reworked so that concurrent delegation conflicts coalesce onto a single in-flight callback rather than being counted once per conflict.

The series grew from 4 patches in v4 to 6, adding two new patches dedicated to tracking and exporting NFSv4 backchannel (callback) operation counts — the direct outcome of last week's review discussion with Chuck Lever.

Bridge to Prior Week (v4)

In the v4 thread, two issues were raised by Chuck Lever: a CONFIG_PROC_FS=n build break in patch 1, and the omission of the wdeleg_getattr counter from the netlink dump. Layton proposed replacing the ad-hoc counter with full server-side callback op counts, and Lever endorsed it ("That sounds ideal"). v5 delivers exactly that agreement.

This Week's Changes (v5)

Layton's cover letter states the delta plainly:

"The main difference in this version is the addition of server callback operation counts. I'll be sending another nfs-utils patch to add support for displaying those in nfsstat."

He reiterates the motivation for the whole series:

"The nfsstat tool currently scrapes /proc/net/rpc/nfsd for server statistics. This procfs interface has several limitations: the counters are global (not network-namespace-aware), the format is fragile to parse, and it cannot be extended without breaking existing parsers."

Patch-by-patch

  1. Patch 1/6 — per-netns per-procedure counts in svc_stat: Adds a vs_count pointer array to struct svc_stat plus svc_stat_alloc_counts()/svc_stat_free_counts() helpers managing per-version percpu count arrays, allocated in nfsd_net_init() and freed in nfsd_net_exit(). The per-net counter is incremented alongside the global one in svc_generic_init_request(). (Per last week's review, the helpers now live where they build for all Kconfig combinations.)

  2. Patch 2/6 — svc_seq_show() uses per-net counts: A one-line change making /proc/net/rpc/nfsd report per-network-namespace procedure call counts. Layton notes the safety argument: "The only caller is nfsd, which always allocates vs_count via svc_stat_alloc_counts() in nfsd_net_init(), so the per-netns arrays are always available."

  3. Patch 3/6 — server-stats-get netlink handler: Implements nfsd_nl_server_stats_get_dumpit() in the nfsd generic netlink family. The dump streams statistics across multiple messages: the first carries all scalar stats (reply cache, filehandle, IO, network, RPC) plus per-version procedure counts; subsequent messages carry one NFSv4 per-operation count each, using cb->args[0] to track the operation index across dump calls. Includes 105 lines of netlink YAML spec and new UAPI definitions in include/uapi/linux/nfsd_netlink.h.

  4. Patch 4/6 — remove unused svc_version vs_count: With both consumers migrated to per-netns arrays, the global vs_count percpu counters are dead. This patch deletes the field and all its DEFINE_PER_CPU_ALIGNED initializers across nfsd, lockd, and the NFS client callback service (fs/nfs/callback_xdr.c) — 39 lines of pure cleanup.

  5. Patch 5/6 — count NFSv4 callback operations per netns: The most substantive new patch. It adds a per-netns array of percpu counters for backchannel operations, indexed by RFC 8881 callback opcode (OP_CB_GETATTR..OP_CB_OFFLOAD), bumped in nfsd4_run_cb() "which is hit exactly once per callback that is actually queued."

    This patch also contains the behavioral fix to the old wdeleg_getattr counter. Layton documents the semantic change carefully:

    "CB_GETATTR is sent when a GETATTR conflicts with an outstanding write delegation, which is roughly what the dedicated wdeleg_getattr counter tracked. The two are not identical: the old counter incremented on every such conflict, whereas the CB_GETATTR counter only counts callbacks that are actually queued, so concurrent conflicts that coalesce onto an already in-flight CB_GETATTR are now counted once rather than once per conflict."

    The procfs wdeleg_getattr line is now reported from the CB_GETATTR counter, and the redundant NFSD_STATS_WDELEG_GETATTR counter, its helper, and its increment site are dropped. This is arguably a small bug fix in the statistics: the old counter overcounted under concurrent delegation conflicts.

  6. Patch 6/6 — export callback op stats via netlink: Adds a proc4cb-ops nested attribute to the server-stats dump, reusing the existing server-proc-entry (op/count) layout. Since the callback opcode set is small, it fits in the first dump message with no extra paging: "This lets nfsstat report NFSv4 backchannel operation counts over netlink, including CB_GETATTR which corresponds to the procfs wdeleg_getattr line."

Review Status

As of the close of this week's window, Layton had just posted v5 (June 18, 16:58 UTC). Two review replies from Chuck Lever landed at the very start of June 19 (00:12 and 00:17 UTC), technically outside this week's half-open window — one on patch 5 and one on patch 6 — so their content is not summarized here. The series has no other in-window discussion; all seven in-window messages are Layton's own submission.

Conclusions

  • v5 cleanly implements the design agreed in last week's review: per-netns procedure counts, a netlink dump handler with procfs fallback for older kernels, removal of dead global counters, and — new — full NFSv4 callback operation accounting.
  • The wdeleg_getattr rework fixes an overcounting behavior (conflicts coalescing onto in-flight callbacks were previously counted multiple times) while preserving the procfs line's meaning.
  • A follow-up nfs-utils patch to display the new callback stats in nfsstat is promised; per Layton, "The nfs-utils patch for that part is already merged" for the base netlink support, with the callback-display piece still to come.
  • This work is entirely server-side (nfsd/sunrpc), though it touches the NFS client's callback service code in the cleanup patch. No client protocol changes or client bug fixes are involved.
