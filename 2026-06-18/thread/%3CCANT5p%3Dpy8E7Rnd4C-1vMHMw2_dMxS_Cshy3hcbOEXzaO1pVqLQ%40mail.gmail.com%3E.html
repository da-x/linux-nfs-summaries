Delegations in the NFSv4 client: production readiness, dir-delegation status, and a real-world vscode hang

Summary

Status of Delegations Feature in the NFSv4 Client

Overview

This short thread is a status/inquiry discussion rather than a patch or protocol-change thread. On June 16, Shyam Prasad N opened a question to Trond Myklebust (addressed by Anna Schumaker) about the production-readiness of file delegations and directory delegations in the Linux NFSv4 client. The exchange is notable for its practical framing — Shyam is evaluating these features for real workloads — and for Charles Hedrick's late-week contribution, which adds a concrete field report on a delegation-related hang that has affected Rutgers University users.

The thread sits in an interesting context this week: the CB_NOTIFY directory-delegation series (Layton's v6) is undergoing deep review by Chuck Lever, with client-side support still pending as the gating dependency for upstream merge. Shyam's question about "gaps that exist today" and his offer to "submit patches to fix those issues" lands squarely on the critical path of that work.

Key Technical Points

File Delegations: Production-Ready

Anna Schumaker gave a clear, confident answer on file delegations:

"Like you've said above, file delegations have been around for a long time and I would expect them to be stable for production environments."

This is consistent with the feature's long history in the Linux client (delegations were introduced in NFSv4.0, well over a decade ago) and its widespread deployment. Shyam confirmed the practical benefit: "We tried running some workloads and file delegations offer really good perf benefits."

Directory Delegations: Newer, Still Maturing

On directory delegations, Anna provided a more nuanced picture:

"Directory delegations are still fairly new, and are used with NFS v4.1 and v4.2. We have recallable directory delegations as of Linux 6.19."

She also flagged the next major piece of client-side work:

"Work is underway for supporting the CB_NOTIFY callback, which will hopefully be upstream soon (I have patches written for client support, but I need to find time to clean them up a bit more before posting them)."

This aligns with the parallel CB_NOTIFY dir-delegation thread, where Jeff Layton's v6 NFSD series is under active review. As summarized in that thread, Layton's gating condition remains:

"I don't think we'll want to merge these until we have a complete client-side implementation to test against."

Anna's comment that she has client patches "written" but needs to "clean them up" suggests the client-side CB_NOTIFY work is in progress but not yet ready for posting — consistent with the server-first, client-gated approach.

Charles Hedrick's Field Report: The vscode Hang

The most practically significant contribution came from Charles Hedrick (Rutgers) on June 18. He added a real-world data point that tempers the "stable for production" assessment of file delegations:

"If there is a problem in NFS, we will see it. Rare events occur several times a semester. Impossible events occur at least once a year."

He then identified a specific, reproducible failure mode:

"The worst case for delegations is heavy use of vscode with an NFS home directory. This will hang an Ubuntu 24.04 client, kernel 6.8."

However, he confirmed that upgrading resolves the issue:

"We have been successful with Ubuntu 24.04 upgraded to kernel 6.17, and a Redhat 9.8 server. I assume a Redhat 9.8 client would also be OK, since they backport things."

This is significant for NFS client development because it identifies a known bug in older kernels (6.8) related to file delegation handling under heavy IDE workload (vscode generates many small file opens/closes and directory reads on home directories), which was fixed by kernel 6.17. Hedrick's institutional experience — "several times a semester" for rare events — provides the kind of long-tail reliability data that is hard to get from synthetic benchmarks.

He also noted: "Our kernels have file delegation but not directory delegation, so I can't comment on the latter." This is an important caveat: Rutgers' production environment has not yet exercised directory delegations, so their experience does not speak to that feature's maturity.

Evolution of the Discussion

The thread follows a simple arc within three days:

  1. June 16 — Shyam opens the inquiry, asking about both file and directory delegation stability, and offering to contribute patches for any gaps.
  2. June 17 — Anna responds with the status assessment: file delegations are production-ready; directory delegations are newer (recallable since 6.19) with CB_NOTIFY client support in progress.
  3. June 18 (morning) — Shyam thanks Anna, closing his part of the exchange.
  4. June 18 (evening) — Charles Hedrick adds the vscode hang report and the kernel-version workaround, providing practical deployment guidance.

The thread has a fifth message from Hedrick on June 29 (outside this week's window), suggesting a follow-up that may provide additional detail or resolution.

Implications for NFS Client Development

  • File delegations are considered stable but the vscode-on-NFS-home-directory hang (fixed by ~6.17) is a reminder that delegation recall paths under heavy concurrent I/O remain a stress point. The fix landed between 6.8 and 6.17, so users on older LTS kernels may still encounter it.

  • Directory delegations are the active frontier. The client-side CB_NOTIFY support (which Anna has patches for) is the missing piece that will unlock full directory delegation functionality. This work is directly tied to Layton's NFSD series and its review cycle. Shyam's offer to contribute patches positions him as a potential collaborator on this effort.

  • The production-readiness question is version-dependent. Hedrick's report underscores that "stable" is relative to kernel version: the same feature set can hang on 6.8 but work correctly on 6.17. Organizations deploying NFS home directories with delegation enabled should ensure they are running sufficiently recent kernels.

Classification

  • Existing feature stability (file delegations)
  • In-progress feature development (directory delegations, CB_NOTIFY client support)
  • A known bug fix (vscode hang, resolved in kernels between 6.8 and 6.17)
