NFSD: Remove flawed WARN_ON_ONCE from nfsd_mode_check (NFS reexport)

Summary

NFSD: Remove flawed WARN_ON_ONCE from nfsd_mode_check

Type: Bug fix (removal of an incorrect warning in the NFS server's file-handle verification path).

Overview

This short thread was opened and resolved within a single day. On Friday, 12 June 2026, Red Hat's Mike Snitzer posted a one-patch series removing a WARN_ON_ONCE() from nfsd_mode_check(), arguing that the warning's underlying assumption is invalid for NFS reexport configurations. NFSD maintainer Chuck Lever applied the patch to nfsd-testing less than an hour later, closing out the discussion with no further debate.

The technical argument

The patch targets a warning introduced by commit e75b23f9e323 ("nfsd: check d_can_lookup in fh_verify of directories"). Snitzer's cover message explains that the original commit's justification assumed nfsd_mode_check() would never see a directory dentry whose inode lacks an i_op->lookup operation. That assumption breaks down when NFSD is itself exporting an NFS filesystem — i.e., the reexport case:

"When NFSD exports an NFS filesystem it is very possible for nfsd_mode_check() to encounter a @dentry that doesn't have i_op->lookup (see nfs_fhget()'s NFS_ATTR_FATTR_MOUNTPOINT and NFS_ATTR_FATTR_V4_REFERRAL handling, and d_flags_for_inode())."

Snitzer points specifically at nfs_fhget()'s handling of NFS_ATTR_FATTR_MOUNTPOINT and NFS_ATTR_FATTR_V4_REFERRAL, where the VFS layer legitimately produces dentries without a lookup operation. In such cases the warning fires spuriously, generating kernel log noise (and a stack dump) on perfectly valid server behaviour rather than indicating an actual bug.

The fix is minimal: drop the WARN_ON_ONCE() from nfsd_mode_check(). The diff touches a single file (fs/nfsd/nfsfh.c), removing three lines and adding one, with no behavioural change to the mode-check logic itself — only the (incorrect) assertion is removed.

Evolution of the discussion

There was no back-and-forth. Chuck Lever's reply, posted just 45 minutes after Snitzer's submission, consisted of an acknowledgement and immediate application:

"Applied to nfsd-testing, thanks!"

The patch landed as commit 4b4af25d320d077102026bf72fa2b73614f2605c in the nfsd-testing tree. The speed of review and merge suggests Lever found the rationale self-evident — a spurious warning in a well-understood code path, with a clear Fixes: tag pointing at the offending commit.

Conclusion

The thread is closed: the flawed WARN_ON_ONCE() has been removed from nfsd_mode_check(), eliminating false-positive warnings that would have plagued administrators running NFSD in reexport (NFS-on-NFS) configurations. The change is a pure cleanup with no functional impact on the mode-checking logic, and it will ride along to mainline via the nfsd-testing tree in the next merge window.
