NFSD v7.2 pull request merged: netlink cache upcalls, 4MB block size, crypto/krb5 conversion, NLMv3 xdrgen migration, and a wave of bug fixes

Summary

NFSD v7.2 pull request merged into mainline

Overview

This week's activity on this thread is the formal [GIT PULL] NFSD changes for v7.2 submitted by Chuck Lever (Oracle) on Wednesday, June 17 Lever's pull request, followed the next day by the pr-tracker-bot confirming that the branch was merged into torvalds/linux.git merge confirmation. The pull aggregates a massive 144-file, +7,338/−6,057 change set spanning NFSD, SunRPC, lockd, svcrdma, and VFS — with Chuck Lever personally contributing 104 of the patches.

This is primarily a feature and refactoring drop (new netlink APIs, crypto library conversion, xdrgen migration) combined with an important batch of bug fixes, many reported by Chris Mason. The thread itself is short — just the pull request and the bot's merge confirmation — but it marks the culmination of weeks of patch review activity on this list.

Key technical highlights

1. Netlink-based cache upcalls (new feature)

The headline architectural change comes from Jeff Layton (27 patches), who "wired up netlink upcalls for the auth.unix.ip and auth.unix.gid caches in SunRPC and the svc_export and nfsd.fh caches in NFSD." As Lever frames it:

"The new kernel-user API is more extensible and lays the groundwork for retiring the old pipe interface."

This introduces a generic netlink family (net/sunrpc/netlink.c, include/uapi/linux/sunrpc_netlink.h) alongside NFSD-specific commands (fs/nfsd/netlink.c, include/uapi/linux/nfsd_netlink.h), plus new YAML specifications in Documentation/netlink/specs/. The old pipe-based upcall mechanism — a decades-old kernel/userspace IPC pattern — is now on a deprecation path.

2. Default r/w block size raised to 4MB (performance)

"The default NFS r/w block size rises to 4MB on hosts with at least 16GB of RAM, reducing per-RPC overhead on fast networks. Smaller machines keep their previously computed default, and the value remains tunable through /proc/fs/nfsd/max_block_size."

This is a significant performance improvement for high-bandwidth NFS deployments, cutting RPC round-trips by a factor of four on large I/O operations without impacting memory-constrained systems.

3. RPCSEC GSS Kerberos conversion to crypto/krb5 (refactoring)

"Chuck Lever converted the server's RPCSEC GSS Kerberos code to the kernel's shared crypto/krb5 library. The conversion retires and removes SunRPC's bespoke implementation of Kerberos v5, but keeps RPCSEC GSS-API."

The diff tells the story: gss_krb5_crypto.c shrinks by over 1,000 lines, while gss_krb5_keys.c (546 lines) and gss_krb5_test.c (1,868 lines) are deleted entirely. The per-enctype Kconfig options are removed in favor of a single CRYPTO_KRB5 dependency. This eliminates a large maintenance burden and aligns NFSD with the kernel's shared crypto infrastructure.

4. NLMv3 xdrgen migration (refactoring, groundwork for Rust)

"Continuing the xdrgen migration that converted the NLMv4 server XDR layer in v7.1, Chuck Lever converted the NLM version 3 server-side XDR layer from hand-written C to xdrgen-generated code. As with the NLMv4 conversion in v7.1, the goals are improved memory safety, lower maintenance burden, and groundwork for generation of Rust code for this layer instead of C."

The new fs/lockd/nlm3xdr_gen.c (714 lines) and include/linux/sunrpc/xdrgen/nlm3.h (210 lines) replace the hand-written fs/lockd/xdr.c (deleted, 354 lines) and fs/lockd/svcxdr.h (deleted, 142 lines). A new RPC language description (Documentation/sunrpc/xdr/nlm3.x) documents the protocol for code generation.

5. NFSv4 state quiescing via netlink (bug fix + new admin tool)

"Chuck Lever fixed an issue where lingering NFSv4 state pins a mounted file system after it is unexported. A new netlink-based mechanism can now release NLM locks and NFSv4 state by client address, by filesystem, and by export. Now an administrator can quiesce an export cleanly before unmounting it."

Three new commands — NFSD_CMD_UNLOCK_IP, NFSD_CMD_UNLOCK_FILESYSTEM, and NFSD_CMD_UNLOCK_EXPORT — give administrators a clean way to drain NFSv4 state and NLM locks before unmounting a filesystem, eliminating a long-standing operational pain point.

6. Case-sensitivity reporting (new feature)

A cross-filesystem effort adds fileattr_get for case sensitivity across fat, exfat, ntfs3, hfs, hfsplus, xfs, cifs, nfs, vboxsf, and isofs. NFSD implements FATTR4_CASE_INSENSITIVE and FATTR4_CASE_PRESERVING for NFSv4 clients, and reports export case-folding via NFSv3 PATHCONF. The NFS client side includes patches to "avoid transient zeroed case capability bits during probe" and to "skip pathconf probe when neither field is consumed."

7. Directory delegations VFS groundwork (new feature)

Christian Brauner's four merge commits bring in "VFS changes for nfsd CB_NOTIFY callbacks in directory delegations," including new fsnotify infrastructure (FSNOTIFY_EVENT_RENAME, fsnotify_modify_mark_mask()) and filelock changes to support ignoring delegation breaks for directory change events.

8. Bug fixes (important)

The pull includes a substantial batch of correctness fixes:

  • ACL/lockd/TLS memory safety: "a batch of memory-leak and use-after-free fixes in the ACL, lockd, and TLS handshake paths, many of them reported by Chris Mason." Specific fixes include nfsd: fix posix_acl leak and ignored error in nfsd4_create_file, nfsd: fix posix_acl leak on SETACL decode failure, sunrpc: pin svc_xprt across the asynchronous TLS handshake callback, and sunrpc: wait for in-flight TLS handshake callback when cancel loses race.
  • Delegation reference leak: NFSD: Fix delegation reference leak in nfsd4_revoke_states.
  • Async copy reaper: nfsd: fix inverted cp_ttl check in async copy reaper — a logic inversion that could cause premature or delayed cleanup of async copy operations.
  • Write verifier: nfsd: reset write verifier on deferred writeback errors — prevents clients from receiving stale verifiers after I/O failures.
  • Open owner leak: nfsd: avoid leaking pre-allocated openowner on unconfirmed retry race.
  • XDR buffer overflow: SUNRPC: Bound-check xdr_buf_to_bvec() stores before writing and SUNRPC: Return an error from xdr_buf_to_bvec() on overflow — hardening against potential out-of-bounds writes.
  • lockd leaks: lockd: Plug nlm_file leak when nlm_do_fopen() fails, lockd: Plug nlm_file refcount leak on cached nlm_do_fopen() failure, and lockd: Avoid hashing uninitialized bytes in nlm4svc_lookup_file().
  • Double-free prevention: sunrpc: harden rq_procinfo lifecycle to prevent double-free (Luxiao Xu).
  • SECINFO_NO_NAME cleanup: NFSD: Fix SECINFO_NO_NAME decode error cleanup (Guannan Wang).
  • svcrdma fixes: svcrdma: wake sq waiters when the transport closes (the final commit in the branch), plus write-chunk resource release and send-context deferral improvements. Two reverts are included: "svcrdma: Use contiguous pages for RDMA Read sink buffers" and "NFSD: Defer sub-object cleanup in export put callbacks."
  • User-space input validation: nfsd: check get_user() return when reading princhashlen (Dominik Woźniak).

9. NFS client changes included in the pull

While this is an NFSD pull, several patches touch the NFS client (fs/nfs/):

  • nfs: Implement fileattr_get for case sensitivity
  • nfs: Avoid transient zeroed case capability bits during probe
  • nfs: Skip pathconf probe when neither field is consumed

These ensure the client correctly probes and reports case-sensitivity capabilities from the server.
