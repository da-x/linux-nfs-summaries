nfsd: sockaddr validation patch lands as standalone v3 after being dropped from bugfix series merge

Summary

On Monday, June 15, Jeff Layton posted a standalone v3 of the "nfsd: validate sockaddr length per family in listener_set" patch to linux-nfs. This is the third revision of what was PATCH 15/21 in his 21-patch "nfsd: more bugfixes" series posted on June 11 — a patch that was explicitly dropped from the v2 merge by Chuck Lever pending this revised version.

Bridge from prior weeks

The original bug was identified during review of Layton's 19-patch v1 series (June 9). In v2 (June 11), the patch addressed a 12-byte out-of-bounds read in the nfsd netlink listener_set command: NFSD_A_SOCK_ADDR was declared as bare NLA_BINARY with no minimum length, so a CAP_NET_ADMIN caller could send a 16-byte address with sa_family=AF_INET6, causing three consumers (rpc_cmp_addr_port, svc_find_listener, kernel_bind) to read beyond the buffer.

When Chuck Lever merged the series on June 13, he noted:

"Dropped 15/21 - will be replaced"

Layton had flagged the issue on June 12:

"Sashiko flagged a problem above that we should probably fix. If we get an invalid address here, we should return an error instead of ignoring it. I'm working on an updated patch now."

This week's activity (June 15)

The v3 posting is the resolution of that open item. The patch description explains what changed:

"This version fixes the error handling so that an invalid address passed from userland will properly cause a -EINVAL return."

Technical details

The fix operates on two levels:

  1. Netlink policy tightening: NFSD_A_SOCK_ADDR is now declared with NLA_POLICY_MIN_LEN(16), so nla_parse_nested() rejects anything shorter than a struct sockaddr. This subsumes the previously open-coded nla_len < sizeof(struct sockaddr) check, which is removed from both attribute-iteration loops.

  2. Per-family length validation: Beyond the generic 16-byte floor, the patch adds family-specific checks in both nlmsg_for_each_attr_type loops to ensure AF_INET6 addresses are at least sizeof(struct sockaddr_in6) (28 bytes). This prevents the original 12-byte OOB read.

  3. Error reporting instead of silent skip: The most significant behavioral change from v2. Previously, an unsupported address family would reach svc_xprt_create_from_sa() and return -EAFNOSUPPORT to userspace. Simply skipping the malformed attribute (as v2 did) would have returned 0 — a silent success. The v3 patch instead sets -EAFNOSUPPORT for unsupported families and -EINVAL for too-short addresses before continuing, so "userspace still sees the failure."

The patch touches three files:

  • Documentation/netlink/specs/nfsd.yaml (+4 lines documenting the new minimum length)
  • fs/nfsd/netlink.c (1 line changed — policy declaration)
  • fs/nfsd/nfsctl.c (+40/-7 lines — per-family validation and error propagation)

Classification

This is a bug fix — specifically an input-validation hardening patch that prevents a kernel OOB read reachable by any CAP_NET_ADMIN user. It carries a Fixes: tag pointing to commit 16a471177496 ("NFSD: add listener-{set,get} netlink command"), the original introduction of the vulnerable netlink interface. The patch also carries an Assisted-by: Claude:claude-opus-4-8 tag, consistent with the rest of Layton's series.

Status

As of this week's close, the v3 patch has been posted but no maintainer reply or merge commit is visible in the thread yet. Given that Chuck Lever already signaled intent to accept it ("will be replaced"), and the fix addresses exactly the concern he raised, acceptance into nfsd-testing appears likely. The patch targets the same v7.3 merge window as the rest of the series.
