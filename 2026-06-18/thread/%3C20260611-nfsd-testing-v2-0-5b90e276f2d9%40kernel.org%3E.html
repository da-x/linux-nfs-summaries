nfsd bugfix series v2 lands in nfsd-testing with two patches dropped and one folded

Summary

Jeff Layton's 21-patch nfsd bugfix series applied to nfsd-testing

Bridge from prior week

On June 11, Jeff Layton posted a 21-patch v2 of his "nfsd: more bugfixes" series to linux-nfs, addressing review comments from Sashiko and adding three new fixes over the 19-patch v1. The series was explicitly targeted at the v7.3 merge window:

"AFAICT, these are garden-variety bugs. Chuck, please consider these for v7.3."

This week's activity (June 12–13)

The thread moved from posting to resolution in just two days. Three messages this week mark the final disposition of the series.

Patch 08/21 dropped — premature NFS4_OO_CONFIRMED

On June 12, Layton announced that he was withdrawing PATCH 08/21 ("nfsd: remove premature NFS4_OO_CONFIRMED in CLAIM_PREVIOUS path") from the series:

"My apologies. I meant to drop this one from the series yesterday."

The patch had addressed a case where nfsd4_open() set NFS4_OO_CONFIRMED on the openowner before calling do_open_fhandle(), which could fail, leaving the openowner permanently confirmed despite the OPEN failing. However, Chuck Lever's merge commit notes it was "rejected in v1" — meaning the fix had already been applied or superseded upstream, making the v2 inclusion a mistake.

Patch 15/21 to be replaced — sockaddr validation

Also on June 12, Layton flagged a remaining issue with PATCH 15/21 ("nfsd: validate sockaddr length per family in listener_set"):

"Sashiko flagged a problem above that we should probably fix. If we get an invalid address here, we should return an error instead of ignoring it. I'm working on an updated patch now."

The original patch added per-family minimum-length checks for NFSD_A_SOCK_ADDR (a bare NLA_BINARY attribute with no minimum length), preventing a 12-byte OOB read when a CAP_NET_ADMIN caller sent a 16-byte address with sa_family=AF_INET6. The follow-up fix to return an error rather than silently ignoring invalid addresses was not included in this merge.

Series merged — 19 of 21 patches applied

On June 13, nfsd maintainer Chuck Lever applied the series to the nfsd-testing tree with three modifications:

"Dropped 08/21 - rejected in v1 Dropped 15/21 - will be replaced Folded 20/21 into 03/21 to avoid a bisect hazard"

Key technical highlights

This is a pure bugfix series — no new features or protocol changes. The most impactful fixes for NFS server correctness:

  • Grace-period DoS (PATCH 12): A clock-domain mismatch between CLOCK_REALTIME and CLOCK_BOOTTIME meant the grace period could never expire naturally, allowing "any client to hold the server in grace indefinitely by sending CLAIM_PREVIOUS OPEN requests."
  • Use-after-free on rmmod (PATCH 16): Plain stores/clears of nlmsvc_ops without RCU protection created a window for module-text UAF after rmmod nfsd.
  • Netlink info leak (PATCH 01): Stale opcnt after compound arg release allowed reading beyond the inline ops array, leaking kernel memory to userspace.
  • RCU safety in sunrpc (PATCH 04): Synchronous kfree() of rq_argp/rq_resp while RCU readers could still traverse the thread list.

The folding of PATCH 20 into PATCH 03 was a practical bisect-safety measure: both touch the same netlink dumpit code path, and keeping them separate would have created an intermediate state where the error handling fix (03) depended on the skip-index fix (20).

Status

As of this week's close, 19 of 21 patches are in nfsd-testing. PATCH 15/21 awaits a revised version that properly returns an error for invalid sockaddr input rather than silently ignoring it. The localio patch (dropped from the series to go through the NFS client tree) is being handled separately.
