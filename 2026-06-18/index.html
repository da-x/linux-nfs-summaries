Week Ending 2026-06-18 — Linux NFS Mailing List

Headline: NFSD v7.2 Pull Request Merged into Mainline

The week's defining event was the formal [GIT PULL] NFSD changes for v7.2 submitted by Chuck Lever on June 17 and confirmed merged into torvalds/linux.git on June 18. The 144-file, +7,338/−6,057 change set delivers netlink cache upcalls (replacing the decades-old pipe interface), a default r/w block size increase to 4 MB on large-RAM hosts, conversion of RPCSEC GSS Kerberos to the kernel's shared crypto/krb5 library, NLMv3 xdrgen migration (groundwork for Rust), and a substantial batch of bug fixes in ACL, lockd, TLS, svcrdma, and XDR paths. See thread summary.

NFS Client Development

Direct I/O Modernization (v2) — Folio-Safety Debate Dominates

Pranjal Shrivastava (Google) posted [PATCH v2 0/7] "nfs: Modernize Direct I/O path" on June 16, migrating the NFS client's O_DIRECT handling from the legacy iov_iter_get_pages_alloc2() API to the modern iov_iter_extract_pages() and moving requests from pages to folios. The series is groundwork for PCI Peer-to-Peer DMA (P2PDMA) and incidentally fixes a data-corruption bug in intra-page offset calculation, a requested_bytes accounting race, and a latent early-unpin lifetime bug.

The review debate centered on patch 6/7 ("Optimize direct I/O to use folios for requests"). Trond Myklebust challenged the core assumption that page_folio() is always valid for user-space memory regions. Christoph Hellwig called the area "a minefield" and advised reusing block-layer extraction code; Matthew Wilcox sharpened the point noting slab pages have no refcount and different flag semantics. The maintainers' consensus guidance: mirror or reuse the block layer's iov_iter_extract_bvecs() logic rather than relying on the fragile "every page is a folio" invariant. The thread remains open and unresolved at week's close. See v2 series and the prior v1 xfstests resolution.

Delegation Return Fix — State-Manager Livelock

Chuck Lever posted [PATCH] NFS: Return a delegation the client fails to record on June 17, fixing three error flows in nfs_inode_set_delegation() that silently drop a server-granted delegation without sending DELEGRETURN. The protocol consequence is severe: the server later recalls the phantom delegation, the client answers CB_RECALL with NFS4ERR_BADHANDLE, and the state manager enters an infinite TEST_STATEID loop via SEQ4_STATUS_RECALLABLE_STATE_REVOKED. Lever notes the race is now routinely reachable because modern servers grant write delegations on any write OPEN. The 14-line fix carries a Fixes: tag and is a strong stable-backport candidate. See thread.

NFSv3 ENXIO on O_CREAT Symlink Open

Michael Nemanov (Vast Data) posted a targeted fix for open(2) with O_CREAT on an existing symlink over NFSv3 returning ENXIO instead of following the link. The root cause: NFSv3 CREATE UNCHECKED returns NFS3_OK with the symlink's file handle, and the client unconditionally calls finish_open() which dispatches to no_open_fops. The 7-line fix verifies the returned inode is regular before calling finish_open(). See thread.

pNFS GETDEVICEINFO Integer-Overflow OOB Read

Michael Bommarito posted a two-patch series fixing an out-of-bounds read in decode_getdeviceinfo() where a 32-bit multiply of the server-supplied notification bitmap length wraps to zero for lengths ≥ 0x40000000, defeating the bounds check. A malicious or compromised pNFS server can drive ~2³⁰ words of OOB read. The fix bounds the length before scaling, and patch 2 adds KUnit coverage (reproduced under KASAN on QEMU). Marked Cc: stable. See thread.

Missing ida_free() in nfs_alloc_server() Error Path

A Coccinelle-driven cleanup patch by Markus Elfring was elevated to a genuine bug fix when Christophe Jaillet spotted a missing ida_free() in the error path after nfs_alloc_iostats() fails. Each such failure permanently leaks one ID from the s_sysfs_ids pool, and repeated mount failures could exhaust available IDs. The v2 series carries Fixes: and Cc: stable tags. See thread.

SUNRPC Shift-Out-of-Bounds (UDP Timeout)

A Huawei contributor re-attempted a fix for a shift-out-of-bounds in xprt_calc_majortimeo() affecting NFS-over-UDP transports. The bug, originally reported by syzbot in December 2020, causes a UBSAN warning and potentially incorrect timeout values when to_retries ≥ BITS_PER_LONG. Prior fix attempts (Randy Dunlap 2020, Kurt Manucredo 2021) apparently never landed. See thread.

Delegations Production Readiness Discussion

Anna Schumaker confirmed file delegations are "stable for production environments" while directory delegations remain newer (recallable since 6.19, CB_NOTIFY client support in progress). Charles Hedrick (Rutgers) added a field report: heavy vscode use on an NFS home directory hangs Ubuntu 24.04 kernel 6.8 clients, resolved by upgrading to kernel 6.17. See thread.

Major Server-Side Trends and Features

CB_NOTIFY Directory Delegation — v7 Accepted into nfsd-testing

The multi-month review cycle on Jeff Layton's 20-patch RFC8881bis CB_NOTIFY directory-delegation series reached resolution. After Chuck Lever's exhaustive June 12 review of v6 (surfacing a refcount race, an order-aware-client spec violation, a queue-overflow livelock, and an export UAF), Layton posted v7 on June 16 incorporating all fixes. Lever applied the entire series to nfsd-testing on June 17. A follow-on three-patch fix series (workqueue livelock, sc_export UAF, silent notification drop) was posted June 17 and awaits review. The gating dependency for upstream merge remains a complete client-side implementation. See v6 review, v7 acceptance, and follow-on fixes.

Netlink Conversion of nfsstat Server Interfaces (v4→v5)

Layton's series converting /proc/net/rpc/nfsd scraping to a generic netlink dump handler advanced from v4 to v5 this week. The v4 review surfaced a CONFIG_PROC_FS=n build break and the omission of the wdeleg_getattr counter. v5 (posted June 18) adds full NFSv4 callback operation counts per netns, fixes an overcounting behavior in the old wdeleg_getattr counter, and removes dead global counters. A companion nfs-utils patch to display the new callback stats in nfsstat was posted the same day. See v4 review, v5 posting, and nfsstat patch.

NFSD Bugfix Series v2 — 19 of 21 Patches Merged

Layton's 21-patch "nfsd: more bugfixes" series was applied to nfsd-testing on June 13 with two patches dropped (one already rejected, one to be replaced) and one folded for bisect safety. Notable fixes include a grace-period DoS (clock-domain mismatch allowing indefinite CLAIM_PREVIOUS), an RCU UAF on nlmsvc_ops after rmmod, and a netlink info leak via stale opcnt. The sockaddr-validation patch (15/21) was reworked through v3→v4→v5 and applied separately on June 15. See bugfix series and sockaddr v5.

Slot-Growth Clamp RFC — Three Reviewed-by, In nfsd-testing

The five-patch RFC capping NFSv4.1 on-demand slot growth at the sunrpc thread ceiling received its third Reviewed-by (Benjamin Coddington) on June 15 and is confirmed in nfsd-testing. Coddington plans to rebase his per-client fair-queue dispatch series on top of this clamp. See thread.

Ongoing Debates and Open Questions

knfsd Per-Client Fair Scheduling (RFC)

The design debate continues. Neil Brown proposed two escape hatches: (1) a "stateless" NFS client mount option using v4 anonymous stateids to let Flexfiles migrate off v3, and (2) per-version net-namespace pools via iptables. Coddington rejected both, insisting on one shared pool fair across all versions: "Per-version pools just relocate the unfairness from 'client with N connections' to 'version with N connections.'" Brown also challenged Lever's DoS framing, arguing the problem is cooperation rather than adversarial attack. No patch has been posted; the thread remains at design stage. See thread.

netfs bvecq v4 — Hellwig Objection to Merge-Window Timing

David Howells posted a 30-patch series replacing folio_queue/rolling_buffer with segmented bio_vec[] chains in netfslib (shared by NFS, AFS, CIFS, 9P, Ceph). The series includes important NFS client fixes: a write-streaming/fscache race, a cachefiles double-fput, and a significant performance improvement via CACHEFILES_CONTENT_ALL. Christoph Hellwig objected to posting during the merge window without full review: "this is gigantic unreviewable series." The series' fate now hinges on whether Howells can address timing and review concerns. See thread.

NFSv4.2 I/O Latency vs iSCSI/9P

Dan Shelton's question about why NFSv4.2 read/write latency is higher than iSCSI and P9FS remains unanswered by kernel developers this week. His follow-up hypothesis — that multiple CPU context switches per NFS I/O (process → workqueue → softirq) are the dominant cost — awaits maintainer engagement. See thread.
