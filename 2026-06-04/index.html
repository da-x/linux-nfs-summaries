Week ending 2026-06-04

Week Ending 2026-06-04

The Big Story: NFS Server Hardening Blitz

The dominant theme this week was an extraordinary burst of NFS server (nfsd) bug fixes, with three separate series from Jeff Layton and Chris Mason landing in nfsd-testing within a four-day window. In total, over 25 patches addressing remotely-triggerable panics, use-after-free vulnerabilities, data corruption bugs, DoS vectors, and locally-triggerable information leaks were posted and (in most cases) merged.

"Grab Bag" v2 — Nine Remote-Triggerable Fixes Merged

Jeff Layton's nine-patch series (v2 of the "random bugs" grab bag) was posted May 30 and merged by Chuck Lever within 12 hours. Highlights include:

  • Delegation revoke BUG_ON fix — a client-reachable kernel panic where two NFS clients could race on layout stateids.
  • RCU-protected cl_cb_session — fixes a use-after-free on session teardown that was also a client-controlled DoS vector (a malicious client replying NFS4ERR_DELAY indefinitely could block teardown).
  • Partial-write detection in nfsd_direct_write — a data corruption bug where short writes between 50% and 99% of a segment were silently misaligned.
  • Append-only TOCTOU fix — closes a race where concurrent appends could bypass the IS_APPEND check during truncation.
  • POSIX ACL count cap — bounds an O(n²) bubble sort that a client could trigger with a crafted u32 entry count.

"Medium-Severity" Series — Six Leaks and a Tracepoint Overrun

The six-patch medium-severity series (May 31) addressed remotely-triggerable memory leaks and a tracepoint buffer overrun. Chuck Lever caught a replay-path ACL leak before merging, spawning a v3 fix that landed June 2 with NeilBrown's single-call-site restructuring. Al Viro contributed an untested cleanup of nfsd_cross_mnt() that was subsequently merged as part of the locally-triggerable series.

"Locally-Triggerable" Series — UAFs, Info Leak, and a Heated Review

The eight-patch v1 (June 1) and nine-patch v2 (June 2) addressed locally-triggerable defects including:

  • An unprivileged IPv6 information leak via the nfsd netlink interface (truncated address + adjacent memory shipped to userspace).
  • A filecache disposal UAF fixed by inlining dispose state into struct nfsd_net.
  • A localio cmpxchg retry UAF with a detailed two-CPU race diagram.

The v2 review produced a notable exchange over PATCH 8/9's net-reference ordering: Chuck Lever (citing consolidated findings from both Claude and Codex) identified a put-ordering race, Layton initially pushed back citing LLM analysis, then conceded after Lever's more precise counter-argument. Eight of nine patches merged June 3; the final patch went through v3 and v4, ultimately abandoning net references entirely in favor of widening nfsd_gc_lock, and was merged June 4.

Notable pattern: Multiple patches carry Assisted-by: tags referencing Claude models, and the cover letter credits "Claude" for classifying the bugs. The review discussion itself involved LLM-generated findings validated by human analysis — a new pattern in kernel development.

NFS Client: Direct I/O Modernization Hits an xfstests Wall

Google's Pranjal Shrivastava posted a seven-patch series to modernize the NFS client's O_DIRECT path (June 3), migrating from iov_iter_get_pages_alloc2() to iov_iter_extract_pages() and from pages to folios, laying groundwork for PCI Peer-to-Peer DMA (P2PDMA). The series includes a genuine bug fix (pages being unpinned immediately after request creation instead of at I/O completion).

However, NFS maintainer Anna Schumaker reported widespread xfstests failures across generic/091, generic/130, generic/240, and many more — on every NFS version from v3 through v4.2 — after applying the folio-grouping patch (6/7). Shrivastava acknowledged he had only run fio, not xfstests, and suspects an offset calculation error in the contiguous grouping logic. A v2 is expected that may split the risky folio migration into a separate series.

FMODE_NOWAIT for O_DIRECT Reads

Dylan Yudaken posted a two-patch series (May 30) to enable FMODE_NOWAIT on NFS O_DIRECT reads, allowing io_uring to complete these requests inline rather than punting to a background worker. The change is small (a non-blocking variant of nfs_start_io_direct that returns -EAGAIN instead of blocking on the inode lock) but awaits maintainer sign-off on the locking-safety argument.

Flexfiles: Fix Unwanted In-Band I/O Fallback

Mike Snitzer posted a two-patch fix (June 4) for the NFSv4 flexfiles client where FF_FLAGS_NO_IO_THRU_MDS was silently ignored on two code paths, causing unwanted in-band I/O to the MDS when data servers were unreachable. A Hammerspace test exposed the bug by widening the window between LAYOUTRETURN and LAYOUTGET. The fix introduces a sticky header-level flag for lseg-less windows.

PG_UPTODATE Stale-Flag Warning Fix

Clark Wang (NXP) reported a long-dormant bug in the NFS client read path (June 2): when a folio's read is split into subrequests and a later subrequest fails, previously accumulated PG_UPTODATE bits are not cleared, tripping a WARNING in nfs_free_request(). The fix introduces a sticky page-group read-failed flag. Reproducible with rsize=1024 and a mid-read disconnect.

sunrpc: Uninitialized Transport Creation Args

Hongling Zeng (KylinOS) fixed an uninitialized stack variable in the sysfs transport-creation path that could cause a kernel panic or information leak when hot-adding RPC transports. Anna Schumaker raised a design question about cloning fidelity; the resolution was that zero-initialization is correct since the relevant fields aren't stored on struct rpc_xprt. Reviewed-by from Layton, Cc'd to stable.

xprtrdma: Eight-Patch Hardening + Follow-ups

Chuck Lever posted an eight-patch series hardening xprtrdma connect and reply handling (June 4), the result of an LLM-assisted audit. Key fixes include:

  • A remote-triggerable Receive queue drain via malformed replies (patches 5, 7).
  • An unbounded credit grant from a well-formed reply with an unknown XID (patch 6).
  • An ep kref underflow on ADDR_CHANGE before ESTABLISHED (patch 1).

Also this week: a single-patch fix for a NULL function-pointer race in rpcrdma_rn_register() (arm rn_done before xa_alloc), and a two-patch cleanup follow-up to the req-recycling decoupling (comment correction + dead assertion removal, picked up by Anna Schumaker).

fhandle UAF Fix Merged Rapidly

Jann Horn's fix for a use-after-free in may_decode_fh() (unlocked ->mnt_ns read during concurrent unmount) went from v1 posting to merge in under 24 hours, with Al Viro providing detailed documentation of the mnt_namespace lifecycle. Cc'd to stable; affects any open_by_handle_at() path including NFS file handle resolution.

Major Design Discussions

Per-Client Fair Scheduling: From RFC to Sparse-Flow Service Floor

The knfsd per-client fair scheduling RFC moved from "is this real?" to "how do we fix it?" This week. Benjamin Coddington (Hammerspace) delivered the promised benchmark data showing that a single-connection interactive client drops to ~1/(K+1) of the pool when a greedy peer opens K connections — a 6× throughput reduction at K=16, identical for v3 and v4.1.

Coddington then posted a four-patch RFC proposing identity-based fair-queue dispatch with hash buckets. The review turned the design inside out: Chuck Lever reframed the problem from "ensuring complete scheduling fairness" to "preventing starvation of any one connection," pointing at fq_codel's sparse-flow optimization as prior art. Coddington embraced the reframe and proposed a burst-sized allowance (grant an idle→active connection ~N RPCs, re-granted each time it returns to idle), which stays identity-free and connection-count-proof. The v3 gap (Flexfiles uses v3 in its data plane) remains the live design tension.

Delegation Recall Debate: Client Pre-emptive Return vs. Server-Side Fix

The delegation-recall thread (Coddington's patch to pre-emptively return a write delegation when SETATTR drops write access) drew substantive pushback from Trond Myklebust and Rick Macklem on May 29. Trond argued v4.1 servers should not recall on mode changes at all; Coddington countered that the recall is about truncate-via-stateid semantics, not cache coherence. The key finding: knfsd already authorizes WRITE from the delegation stateid rather than re-checking current mode. Macklem committed to patching FreeBSD to honor READ/WRITE/SETATTR(size) via delegation stateids — pointing to a server-side fix as the more durable solution.

mTLS Named Client Identities RFC

Chuck Lever posted an RFC for named mTLS client identities (June 2), proposing a per-network-namespace .nfs keyring and a tls_identity= mount option to replace the dead, module-global keyring whose global key_lookup() lets any tlshd read credentials. Hannes Reinecke challenged the netns binding (arguing for user/mount-ns); Lever defended it on the grounds that tlshd is inherently a network-layer service. The keys-subsystem maintainers have not yet weighed in.

NeilBrown's 18-Patch VFS/nfsd RFC

NeilBrown posted an 18-patch RFC to replace dentry_create() with vfs_lookup_open() (June 1), fixing a deadlock class in NFS re-export that his earlier directory-locking series would have introduced. Jori Koolstra granted three Reviewed-by tags on the VFS patches and raised open questions on O_EXCL enforcement and FMODE_CREATED semantics. Patches 06–18 (the nfsd refactoring) await review.

Other Notable Activity

  • ENOSPC/EDQUOT writeback discussion: Piyush Sachdeva reported a concrete dirty-bit bug (June 4): after a failed fsync() with ENOSPC/EDQUOT, pages are not re-dirtied (unlike EIO), making retry-after-capacity-increase impossible and defeating the standard fsync-before-close error detection pattern. Affects both NFS and SMB/NetFS.
  • Windows NFS client binaries: Microsoft announced new NFSv4.1/4.2 client driver binaries for Windows 10/11 and Server 2019/2022/2025 testing (June 1).

Key Takeaways for NFS Client Developers

  1. Server hardening is comprehensive: The three nfsd fix series collectively close a wide range of remotely- and locally-triggerable vulnerabilities. Clients should expect more robust server behavior around delegation revokes, callback teardown, direct I/O short writes, and filecache lifetime in the next mainline release.
  2. Direct I/O modernization is progressing but not ready: The P2PDMA groundwork (pin-aware pages, folio migration) needs to clear xfstests before it can be trusted. The FMODE_NOWAIT patch for io_uring is a smaller, more immediately useful improvement awaiting review.
  3. Flexfiles deployments should watch for the MDS fallback fix: Appliance vendors using FF_FLAGS_NO_IO_THRU_MDS (e.g., Hammerspace) have a correctness fix pending that prevents silent in-band I/O during DS unavailability.
  4. The fair-scheduling reframe has client implications: The sparse-flow service floor design means NFSv3 and v4.0 clients benefit without any protocol change — no new slot negotiation or session identity required.
  5. AI-assisted development is now mainstream on the list: Multiple series this week carry Assisted-by: Claude tags, and LLM-generated review findings (from both Claude and Codex) played a role in the nfsd filecache patch debate.
