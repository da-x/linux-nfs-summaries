nfsd fixes grab bag v2 posted and merged — nine patches land in nfsd-testing

Context from prior week

This thread is the direct successor to the v1 series posted by Jeff Layton on May 28. Last week's review cycle saw substantial back-and-forth across all ten patches: the stable_how patch was self-NAK'd, the callback UAF fix was reworked from a synchronous drain to an RCU approach, the grace-end serialization was redesigned around atomic bit ops, and several other patches received targeted feedback. This week's activity is the resolution of that review: Layton posted the revised v2 series and Chuck Lever merged it within a day.

Key developments this week

v2 series posted (May 30)

Jeff Layton posted the nine-patch v2 series on May 30, describing it as:

"These bugs were categorized as remotely-triggerable panics, UAFs, DoS's, etc., but they aren't reliable. There are also a few protocol fixes in here too, etc. It's a grab bag."

The v2 changelog documents the substantial changes from v1:

  • Dropped "NFSD: Enable return of an updated stable_how to NFS clients" (self-NAK'd after review)
  • Replaced the grace-end serialization with "nfsd: convert nfsd_net boolean flags to unsigned long flags word" using test_and_set_bit
  • Replaced the callback drain with "nfsd: RCU-protect cl_cb_session to fix use-after-free on session teardown" using RCU and kfree_rcu
  • Refined the symlink target length check to use NFS4_MAXPATHLEN instead of PATH_MAX
  • Refined the ACL cap patch to return nfserr_inval (over-limit) and nfserr_jukebox (allocation failure) with an explanatory comment
  • Reworked the reclaim dedup to use an rwsem instead of memory barriers

The series touches 13 files with 299 insertions and 110 deletions, authored by Chris Mason (4 patches), Chuck Lever (1), and Jeff Layton (4).

Patch-by-patch highlights

PATCH 1/9: Delegation revoke BUG_ON — This fix addresses a client-reachable kernel panic. As Layton describes, "two NFS clients can trigger it by having one hold a delegation while another opens the same file to force a recall." The race window is closed by taking rcu_read_lock() around the fi_deleg_file read and replacing the BUG_ON with a graceful error return. This was the fix NeilBrown's prior-week critique prompted.

PATCH 2/9: RCU-protect cl_cb_session — The most architecturally significant change in the series. Chuck Lever had identified that the v1 synchronous drain "potentially introduces a client-controlled DoS vector" because callbacks retrying on NFS4ERR_DELAY could block session teardown indefinitely. The v2 fix converts cl_cb_session to an RCU-protected pointer: all rpciod-side readers use rcu_read_lock()/rcu_dereference(), the session slab is freed via kfree_rcu(), and the callback state machine tolerates a NULL session by requeueing. The commit message includes a detailed race diagram showing how rpc_shutdown_client()'s 1-second timeout could miss tasks stuck in rpc_delay().

PATCH 3/9: nfsd_net boolean flags to unsigned long — Replaces scattered boolean fields with a single unsigned long flags word and an enum. The key fix is using test_and_set_bit() for grace_ended, which prevents two concurrent callers (laundromat kworker and RECLAIM_COMPLETE path) from both entering the grace-done path and double-freeing reclaim records. As Layton noted in the prior week's discussion, this avoids "sub-word cmpxchg issues on architectures like Hexagon that only support word-sized atomic operations."

PATCH 4/9: Dedup nfs4_client_to_reclaim inserts — Fixes a bug where duplicate entries in the reclaim hash table inflated reclaim_str_hashtbl_size to 2N, making the fast end-of-grace path dead (the equality check could never hold). The v2 rework uses an rwsem (reclaim_str_hashtbl_lock) instead of memory barriers for serialization.

PATCH 5/9: Gate nfs3 setacl by argp->mask — A protocol-correctness fix: a SETACL with mask=NFS_ACL was silently dropping the directory's default ACL because set_posix_acl() interprets a NULL pointer as "remove this ACL type." The fix mirrors the existing mask check in nfsd3_proc_getacl().

PATCH 6/9: Check truncate permission under inode lock — Chuck Lever's contribution fixes a TOCTOU window for append-only files. The truncation permission check was performed against an unlocked size sample, but the actual notify_change() runs under inode_lock(). A concurrent append could extend the file between the two, turning what appeared to be a non-truncating setattr into a real truncation that bypasses the IS_APPEND check.

PATCH 7/9: Fix partial-write detection in nfsd_direct_write — Chris Mason's fix for a data corruption bug. The short-write check compared host_err against segments[i].iter.count, but by that point the iterator had already been advanced, so the condition only fired when less than half the segment was written. "Any short write completing between 50% and 99% of the segment slips through; the loop advances to the next segment with kiocb->ki_pos only bumped by the short amount, writing the next segment's payload at the wrong offset." The fix snapshots the original byte count before the write.

PATCH 8/9: Cap decoded POSIX ACL count — Closes a DoS vector where a client-chosen u32 entry count drove an O(n²) bubble sort in the server's compound processing path. The v2 refinement (addressing Chuck Lever's and Rick Macklem's review feedback) returns nfserr_inval for over-limit counts and nfserr_jukebox for allocation failures, with a comment explaining why NFS_ACL_MAX_ENTRIES is the right cap.

PATCH 9/9: Validate symlink target length in NFSv4 CREATE — Binds an unbounded kmalloc that a client could force per COMPOUND op. The v2 change uses NFS4_MAXPATHLEN instead of raw PATH_MAX as Chuck Lever suggested during review.

Applied to nfsd-testing (May 31)

Chuck Lever confirmed the merge on May 31:

"Applied to nfsd-testing, thanks!"

All nine patches were merged with their respective commit hashes listed in the reply. The turnaround from v2 posting to merge was under 12 hours, reflecting that the prior week's review cycle had already resolved all open questions.

Nature of the discussion

This is a bug fix series — not a new feature or protocol change. The nine patches address remotely-triggerable panics (delegation revoke BUG_ON), use-after-free vulnerabilities (callback session teardown), data corruption (partial-write detection, append-only TOCTOU), DoS vectors (unbounded ACL sort, unbounded symlink allocation), and protocol-correctness issues (NFSv3 setacl mask handling).

Significance for NFS client development

While the fixes target the server side, several have direct implications for client behavior:

  • The delegation revoke race (PATCH 1) is explicitly client-reachable — two clients can trigger a kernel panic by racing on layout stateids. Clients using pNFS with delegations are directly affected.
  • The callback UAF fix (PATCH 2) addresses a scenario where a malicious or buggy client can keep replying NFS4ERR_DELAY to trigger a DoS on session teardown — relevant to any NFSv4.1+ client implementation's backchannel handling.
  • The partial-write detection fix (PATCH 7) prevents silent data corruption when the underlying filesystem returns short writes during direct I/O, which matters for NFS re-export scenarios and Ceph/CIFS-backed exports.
  • The append-only TOCTOU fix (PATCH 6) ensures that clients attempting to truncate append-only files via SETATTR are properly rejected even under concurrent modification — a correctness guarantee clients can now rely on.

Conclusion

The v2 series landed cleanly with no further review objections. All the major reworks requested during the prior week's review (RCU for delegation file access, RCU for callback session, atomic bit ops for grace-end, rwsem for reclaim dedup) were incorporated as discussed. The series is now in nfsd-testing and will presumably make its way to mainline with the next merge window.
