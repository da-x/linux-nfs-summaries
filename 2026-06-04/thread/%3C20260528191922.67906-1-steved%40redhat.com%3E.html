nfs_sockaddr2universal() warning fix lands in nfs-utils 2.9.2-rc4

Summary

The nfs_sockaddr2universal() warning fix lands in nfs-utils 2.9.2-rc4

A one-line-class cleanup closes out: the AI-drafted patch is committed

This week's activity on this thread was a single, brief message — and it is the resolution of work that began last week. NFS maintainer Steve Dickson confirmed that his small nfs-utils fix silencing a GCC -Wstringop-overread diagnostic has been merged into the userspace stack.

Bridging the prior week

As covered in last week's summary, Dickson posted a minimal patch to support/nfs/getport.c addressing a warning that surfaces when building nfs-utils with recent GCC:

in function 'nfs_sockaddr2universal', inlined from 'nsm_xmit_getaddr.constprop' at ../../support/nsm/rpc.c:251:17: ../../support/nfs/getport.c:459:24: warning: 'strndup' specified bound 108 exceeds source size 26 [-Wstringop-overread] 459 | return strndup(sun->sun_path, sizeof(sun->sun_path));

The issue was that the code passed sizeof(sun->sun_path) (108 bytes on Linux) as the bound to strndup(), even though the actual Unix-domain socket path buffer in memory is only 26 bytes wide. Not necessarily a runtime bug, but exactly the kind of noise that drowns out real problems in a CI build. Dickson was notably transparent about how the fix was produced:

This is a chatgpt solution to remove the warning... untested (yet)

This week: the commit confirmation

The only message within this reporting window — Dickson's reply on 2026-05-30 — is a terse but decisive close to the thread. Re-quoting his own original post for context, he simply confirmed:

Committed... (tag: nfs-utils-2-9-2-rc4)

That is the entire in-window contribution: no discussion, no pushback, no review round-trip — just the maintainer noting that the patch has landed. The "untested (yet" caveat from last week is effectively retired by the merge into the release candidate.

What this means for NFS client users

For anyone tracking nfs-utils master past the 2.9.2-rc4 tag, the net result is a clean build: the -Wstringop-overread warning in the portmapper/socket helpers (the code path used by rpcinfo/NSM tooling around nsm_xmit_getaddr()) is gone. There is no protocol change and no behavior change — purely a warning-suppression bug fix in the userspace side of the stack.

Classification

  • Type: Bug fix (build-warning suppression), not a new feature or protocol change.
  • Component: nfs-utils userspace (support/nfs/getport.c, function nfs_sockaddr2universal()).
  • Status: Committed, tagged in nfs-utils-2-9-2-rc4.
  • Notable angle: The fix was AI-drafted (ChatGPT), with full disclosure from the maintainer — a small but telling data point for the community's evolving relationship with LLM-assisted development.
