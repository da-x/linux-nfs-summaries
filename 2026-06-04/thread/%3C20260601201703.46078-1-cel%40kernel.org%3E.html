rpcrdma: arm rn_done before publishing the notification

This week's activity in this thread is a single, tightly-scoped bug fix to the NFS/RDMA client (net/sunrpc/xprtrdma/ib_client.c) posted by Chuck Lever on 2026-06-01. No replies or follow-ups landed within the reporting window (2026-05-29 → 2026-06-05), so the discussion has not yet evolved beyond the initial patch; it sits in the queue awaiting review.

The bug

The patch targets a race in rpcrdma_rn_register(), which is part of the generic device-removal machinery introduced earlier by commit 7e86845a0346 ("rpcrdma: Implement generic device removal"). Lever walks through the failure mode in the cover message:

"rpcrdma_rn_register() inserts @rn into rd_xa with xa_alloc() before storing the caller's callback in rn->rn_done. The xarray makes @rn reachable to rpcrdma_remove_one(), which walks rd_xa and invokes rn->rn_done(rn) for every registered notification."

The consequence, as he puts it:

"A device removal that races a fresh registration can therefore observe @rn with rn_done still NULL, because the notification objects are zero allocated by their owners, and call through a NULL function pointer."

In other words, a hot-unplug of the RDMA device arriving just as a new transport is registering its completion notification could crash the client by dereferencing a NULL callback. This is squarely an NFS client bug fix — it affects rpcrdma (the RDMA transport used by the SunRPC/NFS client), not the server or the wire protocol.

The fix and its subtlety

The core change reorders the operations so the callback is armed before the object becomes visible in the xarray:

"Store rn->rn_done before xa_alloc() publishes @rn. The xarray's store-side and load-side ordering then guarantees that any CPU which finds @rn in rd_xa also observes the armed callback."

Lever is careful not to make the naive reorder, because rn_done doubles as a state sentinel:

"rpcrdma_rn_unregister() treats a non-NULL rn_done as the sentinel for a completed registration, so the early store must not survive a failed registration. Clear rn_done again when xa_alloc() fails."

He spells out the secondary hazard of getting that wrong:

"Were it left set, the failed-accept cleanup path would call rpcrdma_rn_unregister() on an @rn that was never inserted, erasing an unrelated rd_xa slot and underflowing rd_kref."

So the patch (19 insertions / 7 deletions in ib_client.c) both fixes the NULL-pointer race and preserves the unregister invariant by clearing rn_done on the xa_alloc() failure path. The commit carries a proper Fixes: tag pointing at 7e86845a0346.
