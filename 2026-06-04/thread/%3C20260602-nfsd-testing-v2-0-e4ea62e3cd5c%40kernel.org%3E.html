Summary

nfsd locally-triggerable bugfixes v2: eight of nine patches merge after a heated review over the netns reference ordering in 8/9

Context from prior weeks

This thread is the v2 of the "locally-triggerable bugs" series that Jeff Layton posted as an eight-patch set on June 1. In v1, Al Viro raised a scalability concern about get_net()/put_net() being called on every nfsd_file_alloc()/nfsd_file_free(), and Layton committed to reworking the patch for v2. This week's v2 (posted June 2) is expanded to nine patches — adding Al Viro's own cleanup of nfsd_cross_mnt() from the adjacent "medium-severity" series — and addresses the scalability feedback by limiting the net reference to files that actually enter the delayed-dispose path.

Series overview (June 2)

Jeff Layton posted the nine-patch v2 on June 2, with a terse cover letter:

"Just some minor changes in this version, plus a cleanup patch from Al."

The v2 changes over v1 are:

  • Rework of the filecache patch (8/9) to only take the net ref at disposal time rather than at allocation.
  • A fix to the ordering of operations in nfsd4_release_compoundargs().
  • Addition of Al Viro's nfsd_cross_mnt() cleanup as patch 9/9.

The series is co-authored by Chris Mason (3 patches), Jeff Layton (5 patches), and Al Viro (1 patch), touching 9 files with 101 insertions and 103 deletions — a net reduction in code.

Patch-by-patch highlights

PATCH 1/9: Defer vfree of compound ops to fix rpc_status UAF — A use-after-free on vmalloc memory in the rpc_status netlink dumpit. The dumpit walks in-flight svc_rqst entries under rcu_read_lock and reads opnums from args->ops[], but that buffer was being freed synchronously via vfree() at compound completion. As Layton explains:

"A concurrent compound completion can therefore free the buffer while the dumpit is reading it — a use-after-free on vmalloc memory."

The fix replaces vfree(args->ops) with kvfree_rcu_mightsleep(), deferring reclamation across one RCU grace period. The tradeoff is modest: "completed compound ops buffers (up to 200 * sizeof(struct nfsd4_op)) persist in memory slightly longer, across one grace period, before being reclaimed."

PATCH 2/9: Hold rcu across localio cmpxchg retry — Chris Mason's fix for a UAF in nfsd_open_local_fh(). The again: retry block loads a pointer with cmpxchg and calls refcount_inc_not_zero() without holding rcu_read_lock, while the slab backing freed nfsd_file objects is not SLAB_TYPESAFE_BY_RCU. The commit message includes a detailed two-CPU race diagram showing how a recycled slab page can contain a non-zero word at the nf_ref offset, making the refcount bump "appear to succeed" before the caller dereferences freed memory. The fix takes rcu_read_lock() immediately before the cmpxchg.

PATCH 3/9: Fix ref leak on nfs_uuid_add_file failure — Another Chris Mason fix. When nfs_uuid_add_file() races with nfs_uuid_put() tearing down the net, it returns -ENXIO without publishing the RCU pointer, and the error path in nfs_open_local_fh() leaks both a caller-owned nfsd_file reference and an entry-time nfsd_net reference. The leak "pins one nfsd_file (and the underlying struct file, dentry, inode) and one nfsd_net_ref per occurrence, which blocks nfsd_net and netns teardown."

PATCH 4/9: Guard nfsd_serv deref in nfsd_file_net_dispose — Chris Mason's fix for a NULL pointer dereference during per-net teardown. The service thread loop calls nfsd_file_net_dispose() which unconditionally calls svc_wake_up(nn->nfsd_serv), but nn->nfsd_serv is cleared before the filecache laundrette shuts down. As Mason notes, "The sibling helper nfsd_file_dispose_list_delayed() already documents this ordering and caches nn->nfsd_serv into a local before testing it for NULL. nfsd_file_net_dispose() was introduced with the same raw svc_wake_up(nn->nfsd_serv) call and never picked up the guard."

PATCH 5/9: Widen nfsd_genl_rqstp address fields to sockaddr_storage — The most security-sensitive patch in the series. struct nfsd_genl_rqstp declared rq_daddr and rq_saddr as plain struct sockaddr (16 bytes), but for IPv6 clients the code casts them to struct sockaddr_in6 * (28 bytes) and reads past the end into adjacent memory. As Layton describes:

"The 16-byte nla_put_in6_addr then ships 8 bytes of truncated IPv6 address followed by 8 bytes of rq_flags to userspace via the NFSD_A_RPC_STATUS_SADDR6/DADDR6 netlink attributes."

This is particularly notable because it's reachable by any unprivileged process: "This is reachable by any unprivileged process in the network namespace because NFSD_CMD_RPC_STATUS_GET uses GENL_CMD_CAP_DUMP without GENL_ADMIN_PERM." The fix widens the fields to struct sockaddr_storage and zero-initializes the stack variable.

PATCH 6/9: Fix refcount leak in nfsd_file_lru_add on insertion failure — A latent bug where nfsd_file_lru_add() unconditionally increments nf_ref before attempting LRU insertion, and never releases it on failure. While "currently unreachable" because the sole caller operates on freshly-allocated objects, it "represents a latent bug that would become exploitable if a future change adds another call site or alters the PENDING protocol." The fix adds a compensating refcount_dec() and changes WARN_ON(1) to WARN_ON_ONCE(1).

PATCH 7/9: Fix fcache_disposal UAF by inlining dispose state into nfsd_net — The first of three patches that together fix a single UAF. The per-net struct nfsd_fcache_disposal (containing the spinlock and freeme list) was separately allocated and freed during net teardown, but "The global shrinker, laundrette, and fsnotify callbacks can still be inside nfsd_file_dispose_list_delayed() dereferencing that pointer, causing a use-after-free." The fix inlines the spinlock and list directly into struct nfsd_net, giving them the same lifetime as the net namespace itself. This eliminates 69 lines of alloc/free boilerplate.

PATCH 8/9: Hold net namespace reference for delayed-dispose nfsd_files — The third patch in the UAF trilogy, and the one that drew significant review attention. Without a net reference held by nfsd_file, "nf_net can dangle for in-flight files whose net namespace is torn down concurrently, causing a use-after-free when nfsd_file_dispose_list_delayed() calls net_generic(nf->nf_net, ...)." The v2 fix takes get_net() in nfsd_file_dispose_list_delayed() (rather than at allocation time, per Al Viro's scalability feedback) and releases it in nfsd_file_free(), with a new NFSD_FILE_NET_HELD flag tracking whether a given file holds the reference. A consequential change to nfsd_file_put_local() moves the nfsd_net_put() call before the nfsd_file_put() that may trigger nfsd_file_free().

PATCH 9/9: Unify cleanups in nfsd_cross_mnt() exits — Al Viro's cleanup, carried over from the "medium-severity" series where he originally proposed it. Instead of having a separate path_put() on each failure exit, all are moved past the point where the codepaths join:

"Instead of having a separate path_put() on each failure exit, as well as on the normal path, let's move all of those past the point where these codepaths join. We want to keep the ordering between path_put() and exp_put(), so move that one as well."

Review discussion: the 8/9 put-ordering debate (June 3)

The bulk of this week's discussion centered on PATCH 8/9, specifically the reordering in nfsd_file_put_local() where nfsd_net_put() now precedes nfsd_file_put().

Chuck Lever opened the review with a consolidated finding from both Claude and Codex:

"It seems that all of the LLM reviewers have difficulty with this patch. This is a consolidated review of the issue from Claude and Codex."

The concern was that the reordering — nfsd_net_put() before nfsd_file_put() — introduces a shutdown race where the I/O completion thread could drop the last nfsd_net_ref (triggering global teardown) before executing the nfsd_file_put() on the next line.

Jeff Layton pushed back, relaying Claude's analysis:

"This is the same concern I just addressed for the previous patch's Finding 3, restated as a critical bug. The answer is the same: this is a false positive."

The rebuttal argued that struct net outlives all pernet exit callbacks, and that the three callers of nfsd_file_dispose_list_delayed() (GC worker, shrinker, fsnotify) isolate items and call the function in a single synchronous execution context — there's no window where a local dispose list sits around while the namespace is torn down.

Chuck Lever responded with a more precise counter-argument, identifying two distinct issues:

  1. Put order in nfsd_file_put_local(): "The question is narrow: after an I/O completion thread executes nfsd_net_put() -- dropping the last nfsd_net_ref and running complete(&nn->nfsd_net_free_done) -- what prevents nfsd_shutdown_net() from continuing through percpu_ref_exit() and nfsd_shutdown_generic() into nfsd_file_cache_shutdown() before that same thread executes the nfsd_file_put() on the next line?" He noted that in the current code, "the caller holds it across nfsd_file_put(), and percpu_ref runs the release callback only after every ref drops, so global teardown strictly follows the file free." The patch removes that ordering.

  2. get_net() placement: "A worker preempted between isolating a file and calling dispose_list_delayed() can resume after cleanup_net() has freed the namespace, at which point get_net(nf->nf_net), net_generic(), and the fcache_dispose_lock all touch freed memory. The get_net() sits at the consuming end of the window it is meant to close."

Lever also noted: "As a process note, I'll note that I haven't found any non-pre-existing issues with the other patches on this series."

Jeff Layton ultimately conceded:

"Ok, I'm convinced, and the fix looks fairly straightforward. If you're ok with merging the rest of the set, I'll plan to resend this one separately."

Nature of the discussion

This is a bug fix series — not a new feature or protocol change. All nine patches address locally-triggerable defects: two use-after-free vulnerabilities (rpc_status netlink dumpit, localio cmpxchg retry), one NULL pointer dereference on net teardown, three patches jointly fixing a filecache disposal UAF, two refcount leaks (localio error path, LRU insertion failure), one unprivileged information disclosure (truncated IPv6 address + adjacent memory leaked via netlink), and one code cleanup.

The series continues the pattern of AI-assisted vulnerability classification: multiple patches carry Assisted-by: tags referencing Claude models (claude-opus-4-6, kres:claude-opus-4-7), and the cover letter credits "Claude" for classifying the bugs. The review discussion itself also involved LLM-generated findings (from both Claude and Codex, as Lever noted), which were then validated or refuted by human analysis — a notable example of AI tools playing a role in both fix generation and code review on the kernel mailing list.

Significance for NFS client development

While all fixes are server-side, several have direct implications for clients:

  • The rpc_status UAF (PATCH 1) is relevant to any deployment using the nfsd netlink interface for monitoring in-flight requests — a common practice in production NFS servers. Clients generating high compound request rates increase the race window.
  • The localio cmpxchg UAF (PATCH 2) affects NFS re-export configurations where the local I/O path is used. A client hammering file opens on an exported filesystem could trigger the race, potentially corrupting server memory.
  • The unprivileged IPv6 info leak (PATCH 5) is the most immediately actionable for security teams: any unprivileged user in a network namespace with an active NFSv4-over-IPv6 connection can read 8 bytes of kernel stack/adjacent struct memory via netlink. Clients connecting over IPv6 to affected servers are the trigger.
  • The filecache disposal UAF (PATCHES 7–9) is relevant to any deployment using network namespaces with NFS exports: tearing down a namespace while files are still in-flight through the GC/shrinker path could corrupt kernel memory, potentially affecting all clients on that server.
  • The refcount leaks (PATCHES 3, 6) are slow-burn DoS vectors: each occurrence pins a file/inode/dentry or inflates a refcount permanently, eventually blocking namespace teardown or preventing LRU eviction.

Final conclusions and open items

  1. Eight of nine patches are merged into nfsd-testing with commit hashes confirmed by Chuck Lever.
  2. PATCH 8/9 needs a v3 resend to fix the put-ordering in nfsd_file_put_local() (file ref first, then net ref) and address the get_net() placement concern. Layton has acknowledged: "I'm convinced, and the fix looks fairly straightforward."
  3. The broader filecache disposal simplification (inlining the dispose state into nfsd_net) is a net reduction in complexity (-69 lines) that eliminates an entire class of lifetime bugs.
  4. Al Viro's nfsd_cross_mnt() cleanup (PATCH 9/9) — originally proposed in the "medium-severity" series thread and noted as "completely untested" by Viro himself — has now been merged into nfsd-testing, completing that follow-up item.
