nfsstat netlink patch committed to nfs-utils (v1)

nfsstat Netlink Patch Committed to nfs-utils

Type: New feature (userspace tooling + kernel API) — now merged
Week ending: 2026-06-04
Status: Committed and tagged in nfs-utils.

This Week's Activity

The thread received its first reply of the week on May 30, when Steve Dickson, the nfs-utils maintainer, confirmed that Jeff Layton's patch adding Generic Netlink support to nfsstat has been merged into the project:

"Committed... (tag: nfs-utils-2-9-2-rc4)" — Steve Dickson

Dickson's reply is terse but definitive: he quoted Layton's original patch description in full and appended the commit confirmation with the release tag. No further technical discussion or review comments were exchanged this week — the patch went in cleanly on its first posting, a testament to the careful design (particularly the graceful fallback to /proc/net/rpc/nfsd for older kernels) that was already baked into v1.

Bridge from Prior Week

The previous reporting week (ending 2026-05-28) covered the initial posting of this patch by Jeff Layton on May 25. That summary detailed the technical design:

  • The new code sends an NFSD_CMD_SERVER_STATS_GET dump command over the nfsd generic netlink family.
  • It populates the same stat arrays used by the proc path: reply cache, filehandle, IO, network, RPC, and per-version procedure call counts.
  • A critical design choice is graceful fallback: if netlink is unavailable (older kernels), nfsstat transparently falls back to parsing /proc/net/rpc/nfsd.

Layton also noted the kernel-side dependency:

"This patch requires the corresponding kernel patches to add netlink support." — Jeff Layton

The companion kernel series (v2, 4 patches) converting nfsd/sunrpc server-side interfaces to netlink was posted the same day and remains in its review phase.

Significance

This is a meaningful milestone for NFS server tooling development:

  1. Modernization of a legacy interface. The procfs-based /proc/net/rpc/nfsd has been the de facto way to read nfsd statistics for years, but its text format is brittle and its global (non-namespaced) counters are inadequate in containerized environments.
  2. Namespace-aware observability. The netlink API makes per-network-namespace statistics available, which is essential for multi-tenant and container workloads.
  3. Backward compatibility preserved. The fallback design means administrators on older kernels see no change in nfsstat behavior — a low-risk merge that the maintainer clearly appreciated given the swift acceptance.

The userspace side is now done; the remaining open question is the kernel-side series, which must land before the netlink path is actually exercised in production. Until then, all deployments will continue to use the procfs fallback silently.
