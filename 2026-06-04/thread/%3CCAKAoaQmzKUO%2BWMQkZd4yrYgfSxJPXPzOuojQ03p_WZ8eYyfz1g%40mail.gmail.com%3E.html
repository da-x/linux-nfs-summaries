ms-nfs41-client June 1 Release: New Idmapper, ADS Support, and Case-Insensitive FS Fixes Announced

Summary

ms-nfs41-client Windows Driver Binaries: June 1, 2026 Test Release Announcement

Overview

This week's activity on this thread was limited to a single message in which Martin Wege forwarded an announcement from Roland Mainz regarding new test binaries for the ms-nfs41-client, an open-source NFSv4.2/NFSv4.1 filesystem client driver for Windows 10/11 (x86, x86-64, ARM64) and Windows Server 2019/2022/2025 Martin Wege, 2026-06-01.

As with prior cycles of this recurring thread (see the January 12 and January 20 announcements), this is not a discussion about Linux kernel NFS client development or bug fixes. It is a cross-post to linux-nfs soliciting interoperability feedback from the Linux community when using their Windows-based NFS client against Linux NFS servers. Wege framed the request clearly:

"The NFSv4.2/4.1 client is for Windows 10/11 ARM64+AMD64+x86 and Windows Server 2019+2022+2025/AMD64, but Interoperability feedback with NFSv4.1/NFSv4.2 servers based on Linux 6.6+ LTS and 6.19+/7.2 would be great."

Key New Features in This Release

The June 1 release (based on commit #474807ac) introduces a substantial set of changes. Wege highlighted the most interesting items:

"New idmapper which maps any NFS user/group to any Windows user/group, support for Linux 7.1 case-insensitive NFS filesystems, Windows Alternate Streams (Win32 streams) support, xcopy.exe/cmd.exe copy/MS Explorer file copy acceleration via NFS server side copies, and copy-by-block-cloning are IMO the most interesting new features."

The full changelog from Roland Mainz's announcement covers:

Identity Mapping Overhaul

  • A completely new idmapper that allows mapping any NFS server {uid, gid, fattr4_owner, fattr4_owner_group} to any Windows user/group account. Mapping is done per mount, so a single Windows user can appear as different identities on different NFS servers.
  • Idmapping is implemented via a shell script (cygwin_idmapper.ksh) for maximum flexibility across complex site configurations, including localized (non-English) Windows account names.
  • New winfsinfo subcommand fsctlnfs41queryidmapinfo as a diagnostic aid for administrators.

Case-Insensitive Filesystem Support

  • More fixes for case-insensitive NFS filesystems, requiring FreeBSD ≥ 16.0, Linux ≥ 7.1, or Windows Server NFS with a case-insensitive filesystem. This is notable given the recent Linux kernel work by Chuck Lever adding case_insensitive/case_nonpreserving fields to struct file_kattr (discussed extensively in January on this list), which was partly motivated by interoperability needs of clients like ms-nfs41-client that "explicitly require servers to report FATTR4_WORD0_CASE_INSENSITIVE = TRUE."

Windows Alternate Data Streams (ADS)

  • Support for Win32 named streams/Alternate Data Streams, leveraging NFSv4.x named attributes (available on Solaris ≥ 11.4, Illumos, FreeBSD ≥ 15.0). Includes NTFS-style renaming and new utilities (winstreamsutil.exe).

File Copy Acceleration

  • Implementation of FSCTL_OFFLOAD_READ/FSCTL_OFFLOAD_WRITE for NFSv4.2 server-side COPY (used by xcopy, Windows Explorer).
  • Support for FSCTL_DUPLICATE_EXTENTS_TO_FILE enabling block-cloning via CopyFile2() on Windows 11, requiring NFSv4.2 server with {CLONE, SEEK, DEALLOCATE} and a cloning-capable filesystem (btrfs, XFS).

Other Notable Changes

  • UNC path format changed to <hostname>@<protocol>@<port> (e.g., ournfsserver@NFS@2049) to support future transports like RDMA and TLS/SSL.
  • Windows 11/ARM64 now supported with native aarch64 kernel module.
  • Sparse file support (requires NFSv4.2 {SEEK, ALLOCATE, DEALLOCATE} and FATTR4_WORD1_SPACE_USED).
  • FreeBSD 16.0 NFS server support added; improved FreeBSD 14.x/15.0 compatibility.
  • Windows Server 2022 NFSv4.1 server support (adds ACL support over WS2019).
  • New nfs_globalmount tool for machine-wide mounts and nfsclientdctl for runtime daemon parameter changes.
  • Executables now signed with WDK test signatures to address rare Windows Defender false positives.
  • Bugfixes enabling ReactOS compilation on an NFSv4.1 filesystem.
  • Fixed issues probing sparse files when using the nfs-ganesha NFS server.

Relevance to Linux NFS Client Development

While this thread does not involve changes to the Linux kernel NFS client, it remains relevant as:

  1. Interoperability testing target: The ms-nfs41-client project exercises NFSv4.2 features (CLONE, COPY, named attributes, case-insensitive filesystems) against Linux servers, providing real-world feedback on protocol implementation correctness.
  2. Feature validation: The client's new support for Linux 7.1 case-insensitive filesystems directly validates the kernel-side work on FATTR4_WORD0_CASE_INSENSITIVE reporting.
  3. Sparse file and block cloning: The client's sparse file and CLONE support provides an external test of Linux NFSv4.2 server-side implementations of these operations.
