nfs-utils: UNUSED() netlink warning fix lands in nfs-utils-2.9.2-rc4

Summary

nfs-utils: netlink handler warning fix committed for 2.9.2-rc4

What happened this week

The thread closed out cleanly this week with a single, decisive message from Red Hat's Steve Dickson confirming that Jeff Layton's small cleanup patch had been merged. On May 30, Dickson posted the maintainer sign-off:

"Committed... (tag: nfs-utils-2-9-2-rc4)" — Steve Dickson

That one line is the whole story for this week's window: a patch that opened last week with no review objections has now landed in the nfs-utils-2.9.2-rc4 release tag, and the discussion is effectively over.

Bridge to prior weeks

The patch itself was posted on May 25 by Jeff Layton, who described it in characteristically understated terms:

"Just some fixes for some new warnings I saw crop up recently."

The change is a bug fix / code-quality cleanup — not a new feature and not a protocol change. It targets the shared support/nfs/nfsdnl.c helper in the userspace nfs-utils tree, using the project's existing UNUSED() macro from nfslib.h to silence -Wunused-parameter warnings on the error_handler, finish_handler, and ack_handler callback parameters. Those parameters are mandated by the libnl callback signatures but go unreferenced in the function bodies.

"Use the project's UNUSED() macro from nfslib.h to suppress -Wunused-parameter warnings on the error_handler, finish_handler, and ack_handler callback parameters that are required by the libnl callback signatures but not referenced in the function bodies." — Jeff Layton

The patch carries a Fixes: tag pointing at commit 3ddc8e81240f ("exportfs: release NFSv4 state when last client is unexported"), the change that introduced the libnl callback scaffolding where the warnings first appeared.

Why it matters for NFS tooling

Although this touches server-side userspace plumbing (exportfs/nfsdctl) rather than the nfs client directly, it sits on the same netlink migration that underpins the modern admin story for both ends of an NFS relationship — clean state revocation on unexport/unmount, cache management, and listener control. The practical value is keeping the build warning-free in a shared helper layer that every netlink-using tool depends on: as more tools exercise these callbacks under stricter compiler flags, -Wunused-parameter noise becomes exactly the kind of clutter that hides real regressions in build logs.

Final conclusion

  • Type: bug fix (compiler-warning cleanup), not a feature or protocol change.
  • Scope: support/nfs/nfsdnl.c in nfs-utils; reuses the existing UNUSED() macro from nfslib.h.
  • Provenance: fixes warnings introduced by commit 3ddc8e81240f.
  • Outcome this week: committed to nfs-utils at tag nfs-utils-2-9-2-rc4 with no review objections raised.
