Client crash fixes land in 7.2-rc; CB_NOTIFY, flexfiles hardening, and a still-open futimens() hole dominate review

Week ending 2026-08-06

Anna Schumaker’s second 7.2-rc client bugfix pull merged the same afternoon it was posted. The tag is three surgical nfs4proc.c corrections: pin struct nfs_server across async FREE_STATEID (Dan Aloni’s use-after-free), drop the matching refs if the allocation fails, and fix NFSv4.2 listxattr size-query accounting so a NULL buffer no longer oopses in _copy_from_pages() or undercounts system.nfs4_acl. The listxattr merge path was settled the same week when Paul Moore pressed for an NFS ACK and Schumaker confirmed the patch was already in a test branch.

That is the only client crash class that actually shipped. The rest of the week is review catching more of them, plus the first client-side CB_NOTIFY decoder.

Critical client bugs

futimens() still succeeds without sending SETATTR. The NFSv4.2 timestamp regression is now independently reproduced on three setups, still live on 7.2-rc5, and newly tied to delegations: Matt Kinni found that fs.leases-enable=0 makes it go away. vers=4.1 updates file mtimes but appears to break directory timestamps. Thorsten Leemhuis asked for a bisection (the window is 6.12.88 good through 6.17 bad); nobody answered, and no maintainer has diagnosed the delegated ->update_time path.

Flexfiles decode can panic or stall the client. Junrui Luo’s five-patch hardening series closes LAYOUTGET / GETDEVICEINFO holes a hostile MDS can trigger: an unbounded multipath-address loop that trips the soft-lockup watchdog, a da_netid leak, stack contents leaked into the data-server port via unchecked sscanf, an fh_count that WARNs the page allocator, and a stripe_unit of 0x100000000 that divides by zero on first I/O. Four of the five are marked for stable. No review landed.

NFSv3 O_CREAT on a cold-cache symlink still returns ENXIO. After two months of silence, Trond Myklebust flagged a dentry refcount underflow in Michael Nemanov’s v1 (finish_no_open(file, dentry) must be NULL). v2 is that one-line correction plus a !S_ISREG() type check so CREATE UNCHECKED of a non-regular object falls back to the VFS instead of no_open(). Unreviewed at week close.

Sysfs dual-kobject UAF. Vasileios Almpanis pinned the parent kobject so nfs_netns_client cannot be freed while p->kobject’s delayed release is still armed. Benjamin Coddington Reviewed-by; the race is deterministic with CONFIG_DEBUG_KOBJECT_RELEASE and a real timer write-after-free otherwise.

Stale setid bits after CLONE. Felix Hoffmann’s three-line GETATTR fix asks for mode after NFSv4.2 CLONE so the client cannot keep 04775 after the server has stripped setuid. Reproduced 10/10 against NFSD-on-Btrfs; no maintainer reply.

DIO extract helper is not merge-ready. Three weeks after v3, Trond walked Pranjal Shrivastava’s nfs_direct_extract_pages() and found an oopsable iov_iter_revert when bytes == PTR_ERR plus a swap-over-NFS put_page() of a page that never took a ref. Shrivastava acked both and sketched v5 (separate err, unpin-only leftover cleanup). Hellwig’s earlier Reviewed-by will have to be re-earned.

Major client trends

Directory delegations finally grow a CB_NOTIFY consumer. Schumaker posted a four-patch decoder that treats CB_NOTIFY as a refresh signal rather than a directory-journal replay: REMOVE_ENTRY invalidates the view, ADD_ENTRY instantiates a dentry, RENAME_ENTRY is remove-plus-add. That tension — cover letter says “refresh,” patch 3 still inserts dentries from callback context — is the obvious review target, especially after last winter’s directory-delegation Oopses. No replies in-window. On the server, Jeff Layton and Chuck Lever argued over host-endian scratch in the CB_NOTIFY encoder; Lever refused to drop the series from nfsd-next and Layton promised a v7.4 cleanup.

pNFS flexfiles is still trusting the wire. Besides Luo’s decode bounds, Jeuk Kim’s loosely coupled DS series (RFC 8435 tightly_coupled plus a v4.0 NULL-deref / lease-renewal busy-loop) sat another month with only an empty DESY ping from Tigran Mkrtchyan. The crash-class v4.0 session-less path remains unacked.

kTLS control records stay on the CMSG path. After netdev NACKed read_sock_rectype, Lever and Sabrina Dubroca agreed ->read_sock has no documented errno contract — today’s -EINVAL mixes “control record queued” with leftover sockmap code. Lever then posted v1 and v2 of eight SUNRPC CMSG fixes; the three xprtsock.c patches (two-octet Alert check, description-based fatal classification, helper fold) still need a client-maintainer Ack. KeyUpdate accounting is server-only in this series; the client still has no rekey path.

netfs buffer tracking is moving to bvecq. David Howells’ v8, 25 patches retires folio_queue / ITER_FOLIOQ. For the NFS fscache path, nfs_netfs_issue_read() must return an error, slice once, and terminate once; server over-read is now -EIO for the whole request. No NFS-maintainer Ack on this revision.

VFS/MM work that brushes the client. NeilBrown’s negative-dentry RFC drops the parent lock between nfs_unset_verifier_delegated() on the parent and its children — he thinks it is safe and wants NFS testers to confirm. Zi Yan’s PG_private RFC only deletes no-op flag ops in fs/nfs/write.c. Christoph Hellwig’s swap_ops v2 picked up Kairui Song’s Ack; the NFS hookup (direct.c → file.c) is still waiting on filesystem review. Stanislav Kinsburskii pinged his freezer RFC with a Mesos failure mode: an admin-frozen NFS requester can hold mount state indefinitely and lock other users — including login — out of the same server.

Server and userspace, briefly

Chuck Lever’s nine-patch NFSD series stops revoking a delegation the client never recorded (NFS4ERR_BAD_STATEID / BADHANDLE on CB_RECALL), completing the recall per RFC 8881 and adding referring calls so a grant/recall race is not mistaken for a missing stateid. That is the server half of the June client DELEGRETURN livelock. A procfs write_unlock_fs() UAF report was closed as already queued (208b023eef24 in nfsd-next). Two syzbot hung-task reports (write_threads) show nfsd_mutex still serializing unmount against portlist / threads writers. Lai Zewei’s legacy reclaim NULL check got a Layton Reviewed-by and a Lever request to recast it as cleanup, not a stable crash fix.

nfs-utils 2.9.2 does not build with --disable-nfsdctl: Lars Wendler and Jaipaul Cheernam independently hit undefined reference to nfsd_nl_cmd_str (Cheernam’s diagnosis is the feature-gate split). Cheernam also posted a musl offsetof include. A conffile unmatched-quote leak and Lever’s MAINTAINERS pointer at nfsd-testing round out userspace. Martin Wege forwarded the 1 August ms-nfs41-client binaries asking Linux nfsd testers to exercise casefold, COPY/CLONE, and the new idmapper.

What to watch

The 7.2-rc client train has the FREE_STATEID and listxattr crashes. It does not have the delegated futimens() hole, the flexfiles panic, the NFSv3 symlink ENXIO, the sysfs UAF, or the CLONE setid refresh. Those are all small, Fixes:-tagged, and mostly waiting on the same two maintainers who spent the week reviewing DIO extract and posting CB_NOTIFY. Directory delegations now have both a client decoder and a server encoder in flight; the encoder’s XDR scratch is accepted debt, the decoder’s add-versus-refresh policy is not yet reviewed, and last winter’s verifier crashes are the reason reviewers will be cautious.
