NFSD MAINTAINERS now points CI at nfsd-testing

Summary

This week Chuck Lever posted a one-line-plus MAINTAINERS cleanup so NFSD contributors and automated CI stop following the wrong git branch. It is a process/tooling fix, not a protocol change and not an NFS client runtime bug.

What changed

Lever explained that MAINTAINERS T: entries are not just human documentation:

"Scripting and automation is sensitive to branch names in the subsystem entries in MAINTAINERS. Rather than pulling from cel.git/master, we really want CI to pull from cel.git/nfsd-testing."

The patch updates the NFSD tree pointer in MAINTAINERS (3 lines: two added, one removed). The intent, matching the subject, is to send both human contributors and sashiko.dev at cel.git/nfsd-testing instead of the repository default (master). Neil Brown’s reply quotes an added T: line that also names nfsd-next on the same git://git.kernel.org/pub/scm/linux/kernel/git/cel/linux.git tree, so the file now carries explicit branch names rather than an unadorned URL.

That is the entire technical delta: no fs/nfs/ client code, no wire-protocol change, and no bug-fix patch to lockd or the server runtime.

Reception

Neil Brown treated the missing branch names as a long-standing oddity that automation had been papering over:

"I wondered how that worked - good to see this fixed."

There was no follow-up in the window: no nits on the extra nfsd-next T: line, no discussion of client trees, and no competing MAINTAINERS layout. Brown’s note is an informal endorsement rather than a formal Reviewed-by/Acked-by.

Conclusion

For NFSD development this week, the practical outcome is that CI (sashiko.dev) and anyone scraping MAINTAINERS for git URLs should now clone Lever’s nfsd-testing (and nfsd-next) branches instead of master. The thread does not touch NFS client development or any functional bug fix; it only aligns the documented integration branches with the trees the subsystem actually wants tested.
