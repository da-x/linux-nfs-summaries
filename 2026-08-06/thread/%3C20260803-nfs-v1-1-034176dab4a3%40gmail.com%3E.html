NFS sysfs kobject UAF on delayed release

Summary

This week’s linux-nfs traffic included a tightly scoped bug fix for the NFS client sysfs layer: a use-after-free that only surfaces when kobject teardown is deliberately delayed. The discussion is not a protocol change and does not add a feature; it restores lifetime ordering between two kobjects that share a single nfs_netns_client allocation.

The report

On 3 August, Vasileios Almpanis posted [PATCH] NFS: sysfs: fix use-after-free on delayed kobject release. The object in question is struct nfs_netns_client, which embeds two kobjects. The allocation is freed from nfs_netns_object_release(), the release callback of nfs_net_kobj. The sibling kobject (p->kobject) lives in that same slab object, but nothing holds the allocation alive until p->kobject itself has finished releasing.

Almpanis put the lifetime hole in plain terms:

"struct nfs_netns_client embeds two kobjects and is freed by nfs_netns_object_release(), the release function of nfs_net_kobj. Despite that the first one, p->kobject lives in the same allocation. Nothing keeps the allocation from being freed before p->kobject has been released."

Under normal production configs the two releases tend to run back-to-back, so the race is easy to miss. With CONFIG_DEBUG_KOBJECT_RELEASE=y, each kobject release is deferred onto a delayed_work embedded in the kobject, with an independent random delay. In that mode nfs_net_kobj can free the slab first. p->kobject’s timer is then left armed inside freed memory, and KASAN fires from the timer wheel:

kobject: 'nfs_client' (...): kobject_release, parent 0000000000000000 (delayed 300)
kobject: 'net' (...): kobject_release, parent 0000000000000000 (delayed 100)

BUG: KASAN: slab-use-after-free in __run_timers+0x932/0x980
Write of size 8 at addr ffff888027fdb868 by task swapper/0/0

The splat is a write of size 8 in __run_timers, which matches a timer callback still sitting in the freed kobject. Almpanis reproduced it on a KASAN kernel with CONFIG_NFS_FS=y and CONFIG_DEBUG_KOBJECT_RELEASE=y by cycling network namespaces:

for i in $(seq 16); do unshare -n true; done; sleep 20

That is a client-side path: creating and destroying netns instances exercises /sys/fs/nfs per-namespace objects, not the NFS server.

The regression is attributed to e96f9268eea6 (NFS: Make all of /sys/fs/nfs network-namespace unique), the commit that made the NFS sysfs tree netns-unique and introduced this dual-kobject layout.

The fix

The patch is eight lines in fs/nfs/sysfs.c. Rather than changing how the structure is allocated, Almpanis pins the parent kobject for the lifetime of the child:

"Give p->kobject a reference on nfs_net_kobj for its whole lifetime and drop it from nfs_netns_client_release(), so the allocation is always freed after p->kobject has been released."

In other words, p->kobject takes a reference on nfs_net_kobj when it is set up, and only drops that reference from nfs_netns_client_release(). Because the slab is freed from nfs_net_kobj’s release function, that extra reference guarantees the allocation outlives the delayed work / timer belonging to p->kobject. The debug-kobject random delay can no longer invert the two releases.

This is the classic kobject pattern for nested objects that share storage: the object that actually kfree()s must be the last one whose release callback runs. The debug option exists precisely to catch cases where that invariant is only accidentally true.

Review and status

The next day, Benjamin Coddington of Hammerspace replied with a one-line review and no requested changes:

"Reviewed-by: Benjamin Coddington bcodding@hammerspace.com"

There was no debate over the diagnosis, no alternative approach (for example splitting the two kobjects into separate allocations), and no follow-up from other NFS client maintainers in this window. The thread therefore ends this week with a Reviewed-by on v1, and no v2 in sight.

Why it matters for the NFS client

The bug is in the client’s sysfs / netns glue, not in RPC, pNFS, or the wire protocol. It is still an important client fix:

  • /sys/fs/nfs is the control plane for per-netns NFS client state. Namespace create/destroy is a hot path for containers and test harnesses (unshare -n is exactly that).
  • The UAF is real memory corruption (timer write after free), not a debug-only warning. CONFIG_DEBUG_KOBJECT_RELEASE only makes the race deterministic; the missing reference is a structural lifetime bug.
  • The Fixes: tag points at the netns-unique sysfs conversion, so this is a candidate for stable backports to every tree that carries that change.

No remaining open questions were raised on-list this week. The practical next step is maintainer pickup of Almpanis’s v1 with Coddington’s Reviewed-by.
