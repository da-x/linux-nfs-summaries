Exposing Case Folding Behavior: v13 Series for NFSD/ksmbd Interoperability

Summary

This week saw the submission of v13 of Chuck Lever's series "[PATCH v13 00/15] Exposing case folding behavior" [id://20260502-case-sensitivity-v13-0-aa853140311f@oracle.com]. This is a new feature development aimed at enabling Linux file servers (NFSD and ksmbd) to accurately report filesystem case-sensitivity semantics to remote clients.

Motivation and Context

The series addresses interoperability issues with non-POSIX clients, particularly Windows-based NFS clients that require explicit advertisement of case-insensitive behavior. Lever notes:

"One example of a Windows-based NFS client is [1]. This client implementation explicitly requires servers to report FATTR4_WORD0_CASE_INSENSITIVE = TRUE for proper operation... When an NFS client knows the server is case-insensitive, it can avoid issuing multiple LOOKUP/READDIR requests to search for case variants."

Additionally, Linux clients benefit from this data for correct caching:

"When a client detects a case-insensitive NFS share, negative dentry caching must be disabled (a lookup for 'FILE.TXT' failing shouldn't cache a negative entry when 'file.txt' exists)..."

Key Technical Changes in v13

  • VFS Infrastructure: Introduces FS_XFLAG_CASEFOLD and FS_XFLAG_CASENONPRESERVING flags [id://20260502-case-sensitivity-v13-2-aa853140311f@oracle.com]. Initialization of file_kattr was moved to callers [id://20260502-case-sensitivity-v13-1-aa853140311f@oracle.com] to prevent clobbering of these flags by memset.
  • Filesystem Support: Implements ->fileattr_get() for FAT, exFAT, NTFS, HFS, HFS+, XFS, CIFS, NFS, vboxsf, and isofs. For instance, CIFS sources flags from cached server replies [id://20260502-case-sensitivity-v13-9-aa853140311f@oracle.com].
  • NFS Client: Patch 10/15 [id://20260502-case-sensitivity-v13-10-aa853140311f@oracle.com] ensures PATHCONF is invoked unconditionally for v2/v3 mounts and clears capability bits before probes to prevent stale state during remounts or TSM.
  • NFSD: Replaces hard-coded checks with dynamic queries via vfs_fileattr_get() for both NFSv3 PATHCONF [id://20260502-case-sensitivity-v13-13-aa853140311f@oracle.com] and NFSv4 GETATTR [id://20260502-case-sensitivity-v13-14-aa853140311f@oracle.com]. Lever details error handling nuances:

    "When an LSM hook denies the case-folding query on the parent, NFS3ERR_STALE is the only correct mapping... A client purging the filehandle on receipt is the desired outcome."

  • ksmbd: Updates FS_ATTRIBUTE_INFORMATION responses to reflect actual filesystem semantics [id://20260502-case-sensitivity-v13-15-aa853140311f@oracle.com].

Conclusion

The series has matured through 12 prior versions, incorporating feedback from Jan Kara, Darrick J. Wong, and Steve French. It provides a robust mechanism for exposing case-folding behavior across the VFS, significantly enhancing cross-platform NFS interoperability and correctness in multi-protocol environments.
