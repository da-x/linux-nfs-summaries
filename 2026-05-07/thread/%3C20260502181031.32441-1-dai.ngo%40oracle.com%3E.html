XFS: Fix Uninitialized imap in pNFS Error Path (Resubmission)

Summary

XFS: Fix Uninitialized imap Usage in pNFS Error Path (Resubmission)

Overview

This thread is a resubmission of a bug fix patch by Dai Ngo from Oracle, correcting the subject line from an earlier posting this week. The patch addresses a critical error-handling flaw in the XFS filesystem's pNFS (parallel NFS) export operations, where an uninitialized variable could be consumed on failure paths. This is classified as a bug fix.

The prior submission (Dai Ngo) covered the same technical content; this resubmission simply corrects the subject line formatting, as noted by the author:

"Correct the Subject line."

Technical Details

The patch targets xfs_fs_map_blocks() in fs/xfs/xfs_pnfs.c, a function central to pNFS block mapping. As Dai Ngo explains:

"xfs_fs_map_blocks() acquires the data map lock and then calls xfs_bmapi_read(). If xfs_bmapi_read() fails, the function currently still falls through to xfs_bmbt_to_iomap(), which consumes an uninitialized imap record and may return invalid data to the caller." Dai Ngo

The Bug

When xfs_bmapi_read() fails, the original code did not abort early. Instead, it fell through to xfs_bmbt_to_iomap(), which expects a properly initialized xfs_bmbt_irec (block map record). Because the earlier failure left this structure uninitialized, the downstream function operated on garbage data — potentially returning invalid block mappings to pNFS clients.

The Fix

The remedy is minimal and surgical: release the data map lock and return immediately upon error from xfs_bmapi_read():

"Fix this by releasing the data map lock and returning immediately when xfs_bmapi_read() reports an error. This prevents xfs_bmbt_to_iomap() from being called with an uninitialized xfs_bmbt_irec." Dai Ngo

The patch is tagged with Fixes: 527851124d10f ("xfs: implement pNFS export operations"), tracing the bug to the original introduction of pNFS export support in XFS.

Significance for NFS Client Development

Although this patch modifies XFS (a filesystem driver), it is directly relevant to pNFS client-server infrastructure. The xfs_fs_map_blocks() function maps file blocks to physical storage locations — a capability that pNFS clients rely on to access data directly from storage devices. A bug in this path risks:

  • Invalid block mappings returned to NFS/pNFS clients
  • Potential data corruption if clients act on incorrect block information
  • Kernel instability due to use of uninitialized memory

Conclusion

This is a targeted, low-risk fix correcting an error-handling oversight in the XFS pNFS implementation. The thread contains only the resubmitted patch with no replies or discussion this week. The fix ensures proper cleanup and early return on error, preventing the consumption of uninitialized data structures. No further evolution of the discussion occurred beyond the subject-line correction from the earlier posting.
