XFS: Fix Uninitialized imap in pNFS Error Path (v2)

Summary

XFS: Fix Uninitialized imap Usage in pNFS Error Path (v2)

Overview

This thread covers the second version of a bug fix patch submitted by Dai Ngo from Oracle, addressing an uninitialized variable use in the XFS filesystem's pNFS (parallel NFS) export operations. This is classified as a bug fix.

The v1 submission was covered in a prior summary (see predecessor thread). The v2 patch refines the original submission by removing redundant code.

Technical Details

The Bug

The issue resides in xfs_fs_map_blocks(), a function central to XFS's pNFS implementation that maps file blocks to physical storage locations. As Dai Ngo explains:

"xfs_fs_map_blocks() acquires the data map lock and then calls xfs_bmapi_read(). If xfs_bmapi_read() fails, the function currently still falls through to xfs_bmbt_to_iomap(), which consumes an uninitialized imap record and may return invalid data to the caller." Dai Ngo

When xfs_bmapi_read() encounters an error, the original code did not immediately exit. Instead, it continued to xfs_bmbt_to_iomap(), which expects a properly initialized xfs_bmbt_irec (imap record). Because the earlier failure left this structure uninitialized, the downstream function would operate on garbage data — potentially returning invalid block mappings to NFS/pNFS clients.

The Fix

The correction is minimal but critical: release the data map lock and return immediately upon error detection. Dai Ngo states:

"Fix this by releasing the data map lock and returning immediately when xfs_bmapi_read() reports an error. This prevents xfs_bmbt_to_iomap() from being called with an uninitialized xfs_bmbt_irec." Dai Ngo

v2 Changes

The v2 iteration includes a small cleanup:

"drop the check for (!error). Already checked above." Dai Ngo

This removes a redundant error check, streamlining the patch without altering its functional behavior.

Significance for NFS Client Development

Although this patch modifies XFS (a filesystem), it is directly relevant to NFS server and pNFS client development. The xfs_fs_map_blocks() function is part of the infrastructure enabling pNFS export operations, which allow clients to access storage blocks directly. A bug in this path could result in:

  • Invalid block mappings returned to pNFS clients
  • Potential data corruption if clients act on incorrect block information
  • Kernel instability due to use of uninitialized memory

The patch is tagged with Fixes: 527851124d10f ("xfs: implement pNFS export operations"), tracing the bug back to the original implementation of pNFS exports for XFS.

Conclusion

This v2 submission is a targeted, low-risk fix that corrects an error-handling oversight in the XFS pNFS code path. No further discussion occurred this week beyond the patch submission itself. The fix ensures proper cleanup and early return on error, safeguarding against the consumption of uninitialized data structures in a critical NFS-related subsystem.
