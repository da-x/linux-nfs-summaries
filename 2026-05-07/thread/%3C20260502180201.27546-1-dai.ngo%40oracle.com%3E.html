XFS: Fix Uninitialized imap Usage in pNFS Error Path

Summary

XFS: Fix Use of Uninitialized imap in xfs_fs_map_blocks Error Path

Overview

This thread consists of a single patch submission by Dai Ngo from Oracle, addressing a critical bug in the XFS filesystem's pNFS (parallel NFS) export operations. The issue involves an uninitialized variable being consumed in an error path, potentially leading to invalid data returns to callers. This is classified as a bug fix.

Technical Details

The patch addresses a flaw in xfs_fs_map_blocks(), which is part of the XFS pNFS implementation. As described by Dai Ngo:

"xfs_fs_map_blocks() acquires the data map lock and then calls xfs_bmapi_read(). If xfs_bmapi_read() fails, the function currently still falls through to xfs_bmbt_to_iomap(), which consumes an uninitialized imap record and may return invalid data to the caller." Dai Ngo

The Bug

The root cause is that when xfs_bmapi_read() fails, the code did not immediately return with an error. Instead, it continued execution and called xfs_bmbt_to_iomap(), which expects a properly initialized xfs_bmbt_irec (imap record). Since this record was never populated due to the earlier failure, the function would operate on uninitialized memory.

The Fix

The solution is straightforward: release the data map lock and return immediately upon detecting an error from xfs_bmapi_read(). This prevents the downstream function from being invoked with invalid data.

"Fix this by releasing the data map lock and returning immediately when xfs_bmapi_read() reports an error. This prevents xfs_bmbt_to_iomap() from being called with an uninitialized xfs_bmbt_irec." Dai Ngo

The patch is tagged with Fixes: 527851124d10f ("xfs: implement pNFS export operations"), indicating that the bug was introduced in the original implementation of pNFS export operations for XFS.

Significance for NFS Client Development

While this patch modifies XFS (a filesystem), it is directly relevant to NFS client/server development because it pertains to pNFS export operations. pNFS allows clients to access data directly from storage devices, bypassing the server in certain scenarios. The xfs_fs_map_blocks() function is part of the infrastructure that enables this capability by mapping file blocks to physical storage locations.

A bug in this path could lead to:

  • Invalid block mappings being returned to NFS/pNFS clients
  • Potential data corruption if clients act on incorrect block information
  • Kernel instability due to use of uninitialized memory

Conclusion

This is a targeted, low-risk fix that corrects an error handling oversight in the XFS pNFS implementation. No further discussion occurred this week, as only the initial patch was submitted. The fix ensures proper cleanup and early return on error, preventing the consumption of uninitialized data structures.
