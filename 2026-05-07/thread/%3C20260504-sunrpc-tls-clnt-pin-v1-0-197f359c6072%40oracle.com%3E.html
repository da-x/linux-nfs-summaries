SUNRPC: Fix memory leaks and use-after-free in RPC-with-TLS

Summary

Chuck Lever submitted a two-patch series this week to address critical memory management bugs in the Linux kernel's RPC-over-TLS implementation. The patches, titled "[PATCH 0/2] Fix a few memory bugs in RPC-with-TLS" [id://20260504-sunrpc-tls-clnt-pin-v1-0-197f359c6072@oracle.com], resolve a resource leak and a use-after-free (UAF) vulnerability that could destabilize NFS mounts secured with mutual TLS (mTLS).

Bug Fix 1: Resource Leak in Lower Client

The first patch [id://20260504-sunrpc-tls-clnt-pin-v1-1-197f359c6072@oracle.com] addresses a leak of the "lower" rpc_clnt structure. During the TLS handshake, xs_tcp_tls_setup_socket() creates a temporary client to drive the inner connection. If this process is interrupted by a signal while waiting for the XPRT_LOCKED state, the code previously jumped to an unlock path without calling rpc_shutdown_client().

Chuck Lever explained the flaw:

"the killed-wait path jumps to out_unlock without calling rpc_shutdown_client(), so the clnt and its xprt leak."

The fix ensures that rpc_shutdown_client() is called on the interrupted wait path, preventing the loss of the client and its underlying transport resources.

Bug Fix 2: Use-After-Free in Upper Client

The second patch [id://20260504-sunrpc-tls-clnt-pin-v1-2-197f359c6072@oracle.com] resolves a more severe use-after-free issue reported by Michael Nemanov. This bug occurred when an mTLS mount failed due to certificate rejection. Because nothing pinned the "upper" rpc_clnt across the delayed connect_worker, the client could be freed by the mount caller before the worker thread executed, leading to dereferences of freed memory.

Lever detailed the race condition:

"When a TLS handshake fails fatally... the upper rpc_clnt is freed before the queued connect_worker fires. xs_tcp_tls_setup_socket() then dereferences the freed clnt, producing the refcount_t underflow Michael Nemanov reported."

To fix this, Lever introduced a new rpc_hold_client() helper that takes a reference on the upper client for TLS transports only, which is released when the worker exits. He noted why this was scoped to TLS:

"The non-TLS connect worker (xs_tcp_setup_socket) never reads sock_xprt::clnt, so leave that path alone and avoid the clnt-holds-xprt-holds-clnt cycle that would otherwise prevent xprt destruction."

Conclusion and Testing

Michael Nemanov, who originally reported the UAF, reviewed and tested both patches. He confirmed that the fixes resolved the instability he observed:

"Reviewed and tested both patches. Confirmed 3-sec delayed work was happening multiple times without UAF. Thank you."

The series is marked as compile-tested by Lever and tested-by Nemanov, addressing bugs introduced in earlier SUNRPC/TLS commits. These fixes are critical for the stability of NFS clients using TLS security, ensuring that resources are properly cleaned up during handshake interruptions and that memory safety is maintained during fatal handshake failures.
