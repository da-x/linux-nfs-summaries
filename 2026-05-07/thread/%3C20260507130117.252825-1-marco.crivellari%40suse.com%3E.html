xprtrdma: Migrate long delayed work to system_dfl_long_wq

Summary

This thread concerns a targeted optimization in the NFS/RDMA transport layer (xprtrdma), specifically regarding how long-running delayed work items are scheduled. The discussion is brief, consisting of a patch submission and an immediate review approval.

Technical Context and Argument

Marco Crivellari submitted [PATCH v2] xprtrdma: Move long delayed work on system_dfl_long_wq here. The patch addresses a suboptimal use of the system_long_wq workqueue within the RPC/RDMA transport code.

Crivellari explains that the existing code uses {queue|mod}_delayed_work(), which relies on system_long_wq. This is a per-CPU workqueue. However, the underlying mechanism sets a global timer that can fire on any CPU, potentially enqueuing work in a way that doesn't align with optimal scheduler placement.

"Unbound works could benefit from scheduler task placement, to optimize performance and power consumption. Long work shouldn't stick to a single CPU."

The patch leverages a recently introduced kernel feature: system_dfl_long_wq, an unbound workqueue designed specifically for long-running tasks (added in commit c116737e972e). Crivellari argues that since the xprtrdma work does not depend on per-CPU variables, there is no justification for using a per-CPU queue.

"Since the workqueue work doesn't rely on per-cpu variables, there is no obvious reason that justify the use of a per-cpu workqueue. So change system_long_wq with system_dfl_long_wq so that the work may benefit from scheduler task placement."

Conclusion and Review

The patch was reviewed and approved by NFS maintainer Chuck Lever on the same day.

"Reviewed-by: Chuck Lever chuck.lever@oracle.com" Chuck Lever

This change is classified as a performance and power optimization rather than a bug fix or new feature. It ensures that long-running RPC/RDMA tasks are handled by an unbound workqueue, allowing the kernel scheduler to place these tasks more efficiently across CPUs, potentially improving latency and reducing power consumption in multi-core systems.

Key Changes

  • File Modified: net/sunrpc/xprtrdma/transport.c
  • Change: Replaced usage of system_long_wq with system_dfl_long_wq for delayed work items.
  • Benefit: Improved scheduler task placement for long-running work, optimizing performance and power efficiency.
