SUNRPC: Fix Use-After-Free in Cache Content Files via Deferred Release

Summary

This week, Chuck Lever submitted a six-patch series to address a persistent Use-After-Free (UAF) bug in the SUNRPC layer, specifically within the cache content files (/proc/net/rpc/<cd>/content). The issue was originally reported by Misbah Anjum on ppc64le and later reproduced on aarch64.

The Bug: Synchronous Teardown vs. RCU Readers

While previous fixes in v7.0 addressed UAFs in the NFSD export path (e_show()), a related fault remained in the generic cache show callback (c_show()). Lever explained that two bugs combined to cause the crash:

  1. Missing Network Reference: The /proc/net/rpc/.../content open path took only a module reference, not a network namespace reference. Consequently, if a file descriptor remained open during a namespace exit, cache_destroy_net() would free the cache_detail and its hash table synchronously. Readers walking this freed memory encountered garbage pointers.
  2. Premature Sub-object Cleanup: In caches like ip_map, sub-objects (e.g., auth_domain) were released via path_put() and auth_domain_put() before the RCU grace period ended. Although the final kfree was deferred, these functions performed synchronous teardown steps (unhashing dentries, clearing d_inode) that left data structures in a "half-dismantled" state while RCU readers were still traversing them.

"The cache_head pointer is plain garbage... c_show() is the generic show callback used by /proc/net/rpc/<cd>/content for every per-net cache_detail."
— Chuck Lever

The Fix: Shared Infrastructure and Deferred Releases

Lever's series replaced narrow fixes with shared infrastructure covering all four cache_detail .put paths. Key changes included:

  • Shared Workqueue: A new sunrpc_cache_wq was introduced to handle deferred releases, replacing the NFSD-specific workqueue.
  • Deferred Cleanup: Patches converted ip_map_put() and unix_gid_put() to use a queue_rcu_work() pattern. This moves sleeping cleanup operations (like path_put()) into a callback that runs after the RCU grace period in process context, ensuring readers see consistent state.
  • Net Reference Holding: Patch 5 added get_net(cd->net) to the open helpers for cache files, preventing namespace teardown while files are open.

"This series replaces the v1 narrow fixes with shared infrastructure that covers all four cache_detail .put paths and all three per-cache file types."
— Chuck Lever

Discussion and Verification

The series received quick positive feedback. Jeff Layton reviewed the code, stating:

"The series looks sane."
— Jeff Layton

Calum Mackay provided testing confirmation:

"With these patches, testing shows no crashes, sosreport no longer hangs, no seq_file errors."
— Calum Mackay

Lever subsequently pushed the series with these acknowledgments.

Technical Clarification: Why the UAF Occurred

Later in the week, yangerkun (Erkun) questioned why the UAF was triggered given that previous code used call_rcu for final frees:

"I'm a little confused why this UAF can be trigged... The auth_domain_put function releases ->name using call_rcu... All of this seems to prevent e_show from causing a UAF."
— yangerkun

Lever clarified that the issue wasn't the final kfree, but the synchronous dismantling performed by path_put() before the RCU callback:

"The problem is the synchronous teardown inside path_put(), which runs before svc_export_put() ever reaches its own call_rcu()... An e_show() that's still inside its cache RCU read section walks into that half-dismantled state through seq_path(), and that's the NULL deref Misbah reported."
— Chuck Lever

He emphasized that the new queue_rcu_work() pattern defers these sleeping operations entirely, closing the window for readers to encounter inconsistent state.
