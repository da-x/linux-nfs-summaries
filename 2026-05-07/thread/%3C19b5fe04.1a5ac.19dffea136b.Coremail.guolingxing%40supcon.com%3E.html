NFSv4.1 Client Hang Against Windows Server: Lease Expiration and Slot Table Drain Bug Investigation

Summary

NFSv4.1 Client Hang Against Windows Server: Diagnostic Data Provided

Summary

This thread concerns a bug report filed by Guo Lingxing regarding an NFSv4.1 client hang in nfs4_drain_slot_tbl under concurrent workload when accessing a Microsoft Windows NFS server. This week, the discussion advanced with Guo providing detailed diagnostic information requested by Lionel Cons, including environment specifics and critical observations about lease expiration behavior.

Key Technical Arguments and Evolution

1. Bug Report Context (Prior Week)

Earlier this week, Guo Lingxing reported that Linux NFSv4.1 clients hang when running concurrent workloads against a Windows NFS server. The clients become stuck in nfs4_drain_slot_tbl with no NFS RPC traffic observed at the time of the hang — only TCP ACKs are seen. Additionally, nfsstat shows retrans=0, and the Windows server reports the NFS session state as "Initialized."

Lionel Cons responded by requesting detailed environment information to help diagnose the issue:

"Which version of WindowsServer do you use, e.g what does the 'ver' command in cmd.exe output? How did you set up the user accounts, and which authentication (AUTH_SYS, GSS, ...) do you use? Which CPU architecture do you use? How much memory do you have on the Linux NFS client?" [id://CAPJSo4Xu8ZRmL8dbhW7PQVV0tpADKLOpfzUL-TgTCR1bgg2fEQ@mail.gmail.com]

2. Diagnostic Data Provided This Week

In response, Guo Lingxing provided comprehensive environment details and additional observations from two independent clients:

Environment Details:

  • Windows Server: Microsoft Windows Server 2022 (Version 10.0.20348.587)
  • Authentication: sec=sys (AUTH_SYS), with no AD, LDAP, or passwd mapping configured; unmapped users are handled by the default "Everyone" account
  • Architecture: Both Linux clients and Windows server are x86_64
  • Memory: Each Linux client VM has 16GB RAM

Critical Lease Expiration Observation:

Guo reported data from two independent clients showing a pattern of lease expiration shortly after mount:

"Client A: age: 498061, lease_time: 120, lease_expired: 497941" "Client B: age: 69598, lease_time: 120, lease_expired: 69478"

Guo noted the significance of this pattern:

"In both cases, lease_expired is approximately equal to (age - lease_time), which suggests that the lease expired shortly after mount and has not been successfully renewed since." [id://66cea4e7.1a5d5.19e00075416.Coremail.guolingxing@supcon.com]

3. Concurrent Hang Behavior

The report highlights several concerning symptoms:

"Both clients hang simultaneously under concurrent workload" "Clients are stuck in nfs4_drain_slot_tbl" "No NFS RPC traffic is observed at hang time (only TCP ACK)" "nfsstat shows retrans=0" "On the Windows server side, the NFS session state is reported as 'Initialized'" [id://66cea4e7.1a5d5.19e00075416.Coremail.guolingxing@supcon.com]

Guo indicated ongoing investigation:

"We are currently tracing the RPC lifecycle to identify which RPC does not complete." [id://66cea4e7.1a5d5.19e00075416.Coremail.guolingxing@supcon.com]

Final Conclusions

  • Bug Classification: This is a bug report concerning NFSv4.1 client interoperability with Windows NFS servers, specifically involving session slot table draining and lease renewal failures.
  • Diagnostic Progress: The key finding this week is the evidence that leases expire shortly after mount and are not successfully renewed, which correlates with the observed hangs in nfs4_drain_slot_tbl.
  • Next Steps: Guo Lingxing is actively tracing the RPC lifecycle to identify the specific RPC that fails to complete. Further diagnostic data may be needed from the community to isolate whether this is a client-side bug, a server-side issue, or an interoperability gap between Linux NFSv4.1 and Windows Server 2022's NFS implementation.

This discussion represents an important bug fix investigation for NFS client development, as it highlights potential interoperability issues with Windows NFS servers that could affect users in mixed-platform environments.
