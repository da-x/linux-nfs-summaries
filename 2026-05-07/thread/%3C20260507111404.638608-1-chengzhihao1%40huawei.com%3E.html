nsfs: Fix Wrong Error Code for pidns ioctls (Superseded by v2)

Summary

This thread consists of a single-patch submission and its immediate retraction by Zhihao Cheng, addressing a bug in the namespace filesystem (nsfs) that was inadvertently touching NFS client code. The discussion is brief but highlights an important interaction between namespace ioctl handling and the NFS client state management layer.

The Bug: Incorrect Error Code from pidns ioctls

Zhihao Cheng submitted a patch to fix a regression in nsfs where executing NS_GET_PID_FROM_PIDNS (or similar pid namespace ioctls) returned ENOTTY instead of the correct ESRCH when the target task could not be found in the corresponding PID namespace.

"When executing NS_GET_PID_FROM_PIDNS (or similar pidns ioctls), if the target task cannot be found in the corresponding pid_ns, the error code should be ESRCH instead of ENOTTY."
— Zhihao Cheng

The bug was introduced by a prior commit that added extensible ioctl handling:

"This bug was introduced when the extensible ioctl handling was added. Without proper return, ret would be overwritten by the default case in the extensible ioctl switch statement."
— Zhihao Cheng

NFS Client Relevance

Notably, the v1 patch touched fs/nfs/nfs4state.c in addition to fs/nsfs.c. This indicates that the NFS client's state management code interacts with namespace ioctls — likely during lease recovery or delegation handling where PID namespace context matters. The fix ensures that error propagation from namespace queries behaves correctly for NFS client operations relying on these ioctls.

Retraction and v2

Shortly after submission, Cheng retracted the v1 patch:

"Ignore this patch, see v2."
— Zhihao Cheng

The corrected version (v2) was posted to the linux-fsdevel list rather than linux-nfs, suggesting the NFS-specific changes in v1 may have been unnecessary or handled differently in the revised submission.

Classification

  • Type: Bug fix
  • Scope: Namespace filesystem (nsfs) with incidental NFS client state code touch
  • Status: Superseded by v2 on linux-fsdevel
