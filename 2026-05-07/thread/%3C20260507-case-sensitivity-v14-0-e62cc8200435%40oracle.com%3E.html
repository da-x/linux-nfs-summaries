Exposing Case Folding Behavior: v14 Series Posted for NFSD/NFS Client Interoperability

Summary

Exposing Case Folding Behavior: v14 Series Posted

This week, Chuck Lever posted v14 of his long-running series "[PATCH v14 00/15] Exposing case folding behavior" [id://20260507-case-sensitivity-v14-0-e62cc8200435@oracle.com]. This is a new feature development (with significant bug-fix implications for caching correctness) aimed at enabling Linux file servers (NFSD and ksmbd) to accurately report filesystem case-sensitivity semantics to remote clients, and allowing the NFS client to expose those semantics to upper layers like NFSD in re-export scenarios.

Context and Motivation

The series addresses interoperability issues with non-POSIX clients, particularly Windows-based NFS clients that require explicit advertisement of case-insensitive behavior. Lever emphasizes:

"One example of a Windows-based NFS client is [1]. This client implementation explicitly requires servers to report FATTR4_WORD0_CASE_INSENSITIVE = TRUE for proper operation... When an NFS client knows the server is case-insensitive, it can avoid issuing multiple LOOKUP/READDIR requests to search for case variants."

For the Linux NFS client, accurate case-sensitivity reporting is critical for correct caching behavior:

"When a client detects a case-insensitive NFS share, negative dentry caching must be disabled (a lookup for 'FILE.TXT' failing shouldn't cache a negative entry when 'file.txt' exists) and directory change invalidation must clear all cached case-folded file name variants."

Evolution from v13 to v14

The series has matured through 13 prior versions. v14 incorporates findings from automated review tools (sashiko/gemini-3.1) and addresses several corner cases in the NFS client and server implementations. Key changes since v13 include:

NFS Client Improvements (Patch 10/15)

  • Stale Capability Prevention: The NFS client now clears NFS_CAP_CASE_INSENSITIVE and NFS_CAP_CASE_NONPRESERVING before each probe. This ensures that a remount, an NFSv4 transparent state migration (TSM) to a server with different case semantics, or a failed probe does not retain stale capabilities from the prior probe.
  • Unconditional PATHCONF: PATHCONF is now invoked unconditionally for NFSv2 and NFSv3 mounts, even when the user pins server->namelen with the namlen= mount option. Lever notes: "That option is orthogonal to case handling, and skipping PATHCONF because namelen was already known would leave the caps unset."
  • Polarity Handling: The capability bits carry opposite polarity to match POSIX defaults (case-sensitive and case-preserving). Silence or a missing attribute from the server defaults to the POSIX behavior.

NFSD Improvements (Patches 13/15 and 14/15)

  • Kernel Credentials for Probes: nfsd_get_case_info() now probes under kernel credentials to avoid spurious NFS4ERR_ACCESS errors caused by per-client MAC policies.
  • Error Handling Nuances: For NFSv3 PATHCONF, if an LSM hook denies the case-folding query on the parent, NFS3ERR_STALE is returned. Lever explains:

    "A client purging the filehandle on receipt is the desired outcome, since the server has refused to read attributes through it. Substituting POSIX defaults instead would let the same handle report casefold=false now and casefold=true once policy permits, opening a silent name-collision window on case-insensitive exports."

  • Parent Resolution: The helper queries the parent dentry for non-directory filehandles because case-folding is a per-directory property. Lever documents inherent corner cases:

    "a single-file export's parent lies outside the exported subtree... a disconnected dentry from fh_verify() has d_parent == itself... and a hardlinked file resolves through the alias the dcache currently holds."

Other Filesystem Adjustments

  • ntfs3: Dropped fileattr_get from symlink and special inode ops.
  • cifs: Restricted case-handling flags to directories per UAPI and wired .fileattr_get on cifs_namespace_inode_operations so DFS referral/automount directories report case handling correctly.
  • xfs/hfsplus: Dropped the FS_CASEFOLD_FL fileattr_get mask, admitting the bit through fileattr_set's allowlist instead to prevent chattr round-trip failures.

Conclusion

With v14, Lever asks Christian Brauner to "lock this one in," indicating the series is nearing merge readiness. The changes provide a robust mechanism for exposing case-folding behavior across the VFS, significantly enhancing cross-platform NFS interoperability and ensuring that both NFS clients and servers handle case-insensitive filesystems correctly in multi-protocol environments.
