NFS Client LSM Interface Update Merged into lsm/dev

Summary

This week, the discussion around the security_inode_listsecurity() interface update concluded with Paul Moore confirming that the patch has been merged into the lsm/dev tree. This represents the final step in a brief but important maintenance cycle affecting the NFS client's interaction with the Linux Security Modules (LSM) subsystem.

Classification: Interface Cleanup Affecting NFS Client

This is an interface cleanup rather than a new feature, protocol change, or bug fix. The patch updates the security_inode_listsecurity() LSM hook interface to simplify implementation across security modules by allowing use of the xattr_list_one() helper. The NFS client code in fs/nfs/nfs4proc.c was among the consumers adapted to the new interface signature.

Evolution of the Discussion

Prior Week (ending 2026-04-30): Paul Moore posted a forward-ported version of Stephen Smalley's original patch, updating it for the Linux v7.1 merge window Patch repost by Paul Moore. He indicated his intent to merge pending no objections:

"If I don't hear anything over the next few days, I'll plan to merge this into lsm/dev later this week."

Current Week (ending 2026-05-07): Moore followed up with a single message confirming the merge was completed Merge confirmation by Paul Moore:

"This has now been merged into lsm/dev, thanks all."

NFS Client Impact and Testing

The NFS client component (fs/nfs/nfs4proc.c) required adaptation to the updated interface. Moore confirmed that the changes do not introduce regressions in NFS-related testing:

"The SELinux test suite runs clean for both local and NFS test runs."

This assurance is notable for NFS developers, as LSM interactions with extended attributes are critical for security-aware NFS deployments, particularly when dealing with label-based access controls over networked filesystems.

Conclusion

The security_inode_listsecurity() interface update has been successfully merged into the lsm/dev tree. The NFS client's interaction with this LSM hook is now updated to match the cleaned-up interface, ensuring compatibility with ongoing security subsystem refactoring in the v7.1 development cycle. No objections were raised during the discussion period, and testing confirmed no regressions for NFS workloads.
