tlshd: Fix keyring cert retrieval offset bug

Summary

tlshd: Fix Keyring Certificate Retrieval Offset Bug

Overview

This week, a critical bug fix was submitted and reviewed for the tlshd (TLS over NFS) subsystem, addressing an issue with certificate retrieval from Linux keyrings. The patch resolves an offset calculation error that occurred when using keyring-based certificates, specifically in the context of dual certificate support (RSA + Post-Quantum).

Technical Details

Type: Bug fix

Root Cause: The tlshd codebase recently gained support for dual certificates (both RSA and Post-Quantum/PQ certificates) as indicated by the Fixes tags referencing commits facd084 ("tlshd: Client-side dual certificate support") and 14f5349 ("tlshd: Server-side dual certificate support"). However, the keyring retrieval mechanism only supports RSA certificates. When a keyring is used, the PQ certificate length fields were not being zeroed out, causing the retrieval callback to calculate incorrect offsets in the tlshd_certs list.

The Fix: Scott Mayhew's patch modifies both client and server code paths (src/tlshd/client.c and src/tlshd/server.c) to explicitly zero out the PQ certificate length fields when a keyring is used for certificate retrieval. This ensures that the offset calculations remain correct even when only RSA certificates are present from the keyring.

"The code that gets certs from keyrings currently only gets RSA certs, so we need to zero out the PQ certs length fields when a keyring is used. Otherwise the retrieval callback will look in the wrong offset in the tlshd_certs list." — Scott Mayhew in his patch submission

Discussion Evolution

The thread was brief, consisting of only two messages:

  1. May 1: Scott Mayhew submitted the patch, noting that the issue was reported by Sagi Grimberg. The patch includes proper Fixes tags to ensure it can be backported to stable kernels.

  2. May 3: Sagi Grimberg, who originally reported the bug, reviewed and approved the fix:

"Reviewed-by: Sagi Grimberg <sagi@grimberg.me>" — Sagi Grimberg

Significance for NFS Client Development

This fix is important for NFS clients using TLS with keyring-based certificate management. Without this patch, systems relying on keyrings for certificate storage could experience failures or undefined behavior when the tlshd subsystem attempts to retrieve certificates, due to incorrect list offset calculations. The bug was introduced alongside the dual certificate support feature, which aims to future-proof NFS/TLS connections against quantum computing threats by supporting both traditional RSA and post-quantum cryptographic algorithms.

The rapid review and approval cycle (two days) reflects the collaborative nature of the NFS development community in addressing security-related bugs promptly.
