NFS Weekly: SUNRPC Cache UAF Fixed, svcrdma OOM Resolved, TLS Memory Bugs Patched, and Client Hangs Investigated

Week ending 2026-05-07

Critical Bug Fixes

SUNRPC Cache Use-After-Free Finally Resolved

The longest-running bug on the list this week reached resolution. A use-after-free in cache_check_rcu() — originally reported on ppc64le in February and confirmed to affect ARM64 as well — was fully addressed by Chuck Lever's six-patch series (thread). The root cause involved two compounding issues: (1) the /proc/net/rpc/.../content open path only took a module reference, not a network namespace reference, allowing cache_destroy_net() to free cache structures while readers were still walking them; and (2) sub-object cleanup in caches like ip_map performed synchronous teardown (path_put(), auth_domain_put()) before the RCU grace period ended, leaving data structures in a half-dismantled state. The fix introduces a shared workqueue (sunrpc_cache_wq), defers all sleeping cleanup past the RCU grace period via queue_rcu_work(), and adds proper net reference holding for cache file lifetimes. Jeff Layton reviewed positively and Calum Mackay confirmed no more crashes with sosreport. The discussion thread (thread) provides additional context on the multi-architecture impact.

svcrdma OOM Under Heavy RDMA Load Fixed

A critical Out-Of-Memory condition in svcrdma was reported by Mike Snitzer and Benjamin Coddington from Hammerspace, affecting large deployments (121 clients, 9 servers) where memory grew from ~12GB to exhaustion within seconds under 16K O_DIRECT read workloads (thread). The root cause was an unbounded sc_send_ctxts cache: send contexts were always returned to a lockless list on release, but workqueue lag caused concurrent allocations during the gap, leading to monotonic cache growth. Chuck Lever submitted a two-patch series (thread) that eliminates the problem at its source: Patch 1 inlines resource release to avoid re-queuing on svcrdma_wq (recovering ~1% CPU), and Patch 2 defers send context release entirely to the nfsd thread via per-transport lock-free lists, removing workqueue contention from the Send completion path. Snitzer confirmed that Patch 1 alone eliminated the OOM in production testing.

RPC-over-TLS Memory Bugs Fixed

Chuck Lever submitted a two-patch series fixing critical memory management bugs in the NFS-over-TLS transport (thread). The first patch fixes a resource leak of the lower rpc_clnt when TLS handshake is interrupted by a signal. The second patch resolves a use-after-free in the upper rpc_clnt originally reported by Michael Nemanov (thread), where a failed mTLS mount caused the client to be freed before the delayed connect_worker fired, leading to refcount underflows. A new rpc_hold_client() helper pins the upper client across the TLS connect worker. Nemanov confirmed both patches resolve the instability.

NFS Client Development

NFSv4.1 Slot Table Hang Against Windows Server

A new bug report from 郭玲兴 describes an NFSv4.1 client hang in nfs4_drain_slot_tbl under concurrent workload when connected to a Windows Server 2022 NFS server (thread, follow-up). The client uses vers=4.1,soft,proto=tcp,timeo=60,retrans=10 with AUTH_SYS and no user mapping. Lionel Cons requested reproduction details; the reporter provided full environment specifics (x86_64, 16GB RAM per client VM, Windows Server 2022 v10.0.20348). The issue remains under investigation and highlights ongoing interoperability edge cases with non-Linux NFS servers.

NFSv4 State Recovery Deadlock — Still Unresolved

Zhihao Cheng pinged the unresolved state recovery deadlock that occurs when an NFS server misses its grace period (thread). The client enters an infinite loop during NFS4CLNT_RECLAIM_NOGRACE when the server repeatedly returns NFS4ERR_GRACE. Maintainer Trond Myklebust's suggested fix did not resolve the problem, and the tension between NFSv4 spec restrictions on reclaim operations during NOGRACE and practical recovery needs remains unresolved.

NFS4ERR_SEQ_MISORDERED Fix Deployed

The long-running investigation into NFS4ERR_SEQ_MISORDERED errors causing severe slowdowns for Rocky 8 clients against RHEL10 servers concluded this week (thread). The root cause was a server-side bug in SEQUENCE replay logic that sent incorrect maxslots values, causing clients to discard slot state. Rik Theys confirmed deployment of the fix on kernel 7.0.3 and is monitoring for recurrence.

ENOSPC/EDQUOT Writeback Error Discussion

Piyush Sachdeva initiated a discussion on preventing silent data loss from ENOSPC/EDQUOT writeback errors on network filesystems (thread). The core issue: buffered writes return success immediately, but if the server runs out of space during writeback, pages are marked clean and can be reclaimed under memory pressure, losing data the application believes was persisted. Jeff Layton emphasized this is a fundamental limitation of delayed writeback and recommended that applications use fallocate() proactively to guarantee server-side space before writing.

TLS/Security Infrastructure

ktls-utils Keyring Regression Fixed

A regression in ktls-utils broke keyring-based NFS client certificate management after dual-certificate support was added (thread). Scott Mayhew submitted a fix, and after debate about whether the feature was "production-ready," Chuck Lever agreed to create a ktls-utils-1.3-fixes branch for a 1.3.1 maintenance release. The discussion also highlighted the need for better documentation of cert_serial and privkey_serial mount options in nfs(5) (thread).

VFS and Performance

d_alloc_parallel() Deadlock Fix for NFS Testing

Neil Brown's 19-patch series to lift directory lookups out of the exclusive inode lock hit a deadlock during NFS testing in generic/467 (thread). The bug was traced to __d_move() waking the wrong dentry in __d_wake_in_lookup_waiters(). Al Viro and Neil Brown agreed to decouple the d_alloc_parallel() fix from the larger series for independent merge.

RWF_DONTCACHE Write Performance (v6)

Jeff Layton posted v6 of his RWF_DONTCACHE writeback improvement series (thread), fixing concurrency bugs found by static analysis. Results: +201% throughput (298→897 MB/s), -99.7% tail latency (8.9s→28ms p99.9), and fair bandwidth sharing with buffered I/O. Jan Kara provided Reviewed-by tags.

Case Folding Behavior Exposure (v13)

Chuck Lever submitted v13 of his 15-patch series exposing filesystem case-folding behavior through VFS fileattr_get() (thread). This enables NFSD to correctly report FATTR4_WORD0_CASE_INSENSITIVE for Windows NFS clients and allows the NFS client to disable negative dentry caching on case-insensitive shares. Support was added for FAT, exFAT, NTFS, HFS, XFS, CIFS, NFS, vboxsf, and isofs.

Other Notable Activity

  • nfs-utils throughput display: Tigran Mkrtchyan proposed an option to display throughput in MB/s (thread).
  • nsfs error code fix: Zhihao Cheng submitted a fix for wrong error codes returned by pidns ioctls (thread).
